# `scripts/neardup/` — train·val ↔ eval 근사 중복의 전수 정량화

여기는 **재현 절차**다. 결과·해석과 문턱의 근거는 별도 기록에 있다(공개 대상이 아니다).

## 원칙

- 동결 매니페스트·분할·봉인 자산·`data/raw/` 는 **읽기만** 한다.
- 출력은 전부 `_workspace/2026-09-21-neardup/` 에 쓴다. 이 경로는 무시 규칙 대상이다 — **실물 식별자가 든 파일은 추적하지 않는다.**
  추적 문서에는 건수·분포·해시만 싣는다.
- 제외 기준은 **화소와 해시로만** 정한다. 정답 라벨과 모델 출력은 기준에 쓰지 않는다(사후 확인용으로만 본다).
- GPU 를 쓰지 않는다. 가장 긴 단계는 디스크 읽기다(전 영상 62,308장을 두 번 읽는다).

## 왜 "안쪽 상자" 인가

테두리 마스킹(`scripts/run_border_mask.py`)이 가장자리 8%(102px · 58px)를 전 영상 공통 상수로 채운다. 화소의 29%다.
전체 프레임으로 차이를 재면 그만큼 작게 나오고 상관도 왜곡된다. 모든 화소 특징은 안쪽 상자(x 102~1178, y 58~662)에서만 잰다.

## 단계 (저장소 루트에서 `uv run python -X utf8 scripts/neardup/<파일>`)

| 순서 | 파일 | 하는 일 |
|---|---|---|
| 1 | `nd_stage1_hamming.py 48` | 256비트 지각 해시의 전 쌍 해밍 거리. 교차(eval↔train·val) 6.2억 쌍 · eval 안쪽 · train·val 안쪽의 히스토그램과 거리 ≤ 48 후보(**생성기 G1**) |
| 1b | `nd_stage1b_recall.py 300` | G1 의 재현율 실험 — 알려진 영상에 재압축·리사이즈·밝기·이동을 가해 해시가 얼마나 움직이는지 잰다 |
| 2a | `nd_stage2a_thumbs.py` | 전 영상의 64×36 그레이 축소본(모델이 보는 판) |
| 2b | `nd_stage2b_thumbpairs.py 4.0` | 축소본 안쪽 영역의 전 쌍 RMS 차이 ≤ 4.0 후보(**생성기 G2**) |
| 2c | `nd_stage2c_v2.py <tag>` | G1 ∪ G2 의 합집합에 전 해상도 기본 특징(평균 절대차·상관·기울기 상관·대역 통과 상관) |
| 2d | `nd_stage2d_refine.py <tag>` | **정밀 특징** — 행·열 평균을 뺀 대역 통과 영상의 교차상관 봉우리와 그 뾰족함(`rd_sharp`), 이동, 정합 뒤 세 규모의 상관. 걸러진 쪽의 무작위 대조 600쌍도 함께 계산한다 |
| 2d′ | `nd_stage2d_direct.py within_trainval` | 규모가 큰 train·val 안쪽은 2c 를 건너뛰고 합집합 전체에 정밀 특징을 단다 |
| 2e | `nd_stage2e_v1stage.py <tag>` | 히스토그램 정합 **이전** 판(`tiles_v1`)에서 정합 뒤 차이 — 정합 판은 저대비 영상의 작은 차이를 3~4배로 키운다 |
| 2f | `nd_stage2f_blocks.py <tag> [워커] [입력 csv]` | 과병합 안전장치 — 정합 뒤 4×6 격자 블록별 상관. 영상의 일부(필름 식별 문자 등)만 같은 경우를 가려낸다 |
| 2g | `nd_stage2g_rest.py <tag>` | 2d 의 사전 거름이 뺀 후보 **전량**에 정밀 특징과 블록 일치. 특징이 없는 쌍에는 어떤 규칙도 적용되지 않으므로, 문턱을 낮출 일이 아니라 전량을 재야 닫힌다 |
| 3a | `nd_stage3a_bpdesc.py` | 밝기 변환에 불변인 거친 구조 기술자(가우시안 차 8~32px · 행열 평균 제거 · 64×36) |
| 3b | `nd_stage3b_bppairs.py` | 기술자 상관의 전 교차 쌍 스캔(**생성기 G3**). G1 ∪ G2 에 없던 새 쌍을 따로 적는다 |
| 3c | `nd_stage3c_refine_new.py` | 새 쌍에 정밀 특징 — **G1 ∪ G2 가 놓친 같은 그림이 몇 쌍인가**가 재현율의 근거다 |
| 3d | `nd_stage3d_shiftscan.py pilot` → `scan <문턱>` | **큰 이동 생성기 G4.** 앞의 셋은 약 32px 을 넘는 이동을 못 본다. 거친 구조 기술자를 푸리에 교차상관으로 **모든 이동에서 한 번에** 맞춰 본다. 100장마다 중간 저장하고, 다시 돌리면 본 곳을 건너뛰고 이어서 한다 |
| 4 | `nd_stage4_rawcause.py <특징 csv> <행 번호들>` | 원인 — 같은 그림 쌍의 **원본 zip 구성원**을 읽어 크기·양자화·밝기 통계·바이트를 비교한다(식별자는 찍지 않는다) |
| 5 | `nd_stage5_lists.py` | 정의별 집계와 eval 쪽 제외 목록. 목록은 미추적 경로에 쓰고 sha256 과 건수만 요약에 적는다 |
| — | `nd_montage.py <특징 csv> <출력 폴더> <이름> <행 번호들>` | 쌍 몽타주 `[A | B | 차이×8]`. 그림에는 행 번호만 적는다 |

`<tag>` 는 `cross_eval_vs_trainval` · `within_eval` · `within_trainval` 가운데 하나다.

## 자원

**병렬도를 올리기 전에 여유 메모리를 먼저 본다. 6GB 아래면 올리지 않는다.** 전 영상을 여는 단계(2c~2g)는 워커 하나가
약 0.7GB 를 쓴다. 3d 는 스레드 2개로 약 1.1GB 다. 오래 도는 단계는 중간 결과를 내리므로 멈췄다 다시 돌려도 이어서 한다.

## 시험

`tests/test_neardup_features.py` 가 정밀 특징의 성질을 합성 영상으로 고정한다 — 같은 그림은 밝기·잡음·작은 이동이 달라도 뾰족하고,
수평 구조만 같은 다른 그림은 뾰족하지 않다. `tests/test_neardup_rules.py` 는 과병합 안전장치(필름 식별 문자만 같은 쌍은
블록에서 걸러진다)와 규칙 식 검사기(정답 라벨·분할 열은 규칙에 못 쓴다)를 고정한다. 둘 다 실데이터를 읽지 않는다.
