# AI허브 창원 용접 데이터 검증

이 문서는 주 실험 자료인 창원 AI허브 71761에서 실제로 제공한 파일·라벨과 데이터 품질 문제를 설명한다. 2026-08-23 라벨 JSON 129,613개를 전수 확인하고 원천 이미지 아카이브의 파일 수를 대조한 기록이다. 라벨 전수 확인과 이미지 표본 판독을 구분하며, 이후의 분할·학습 성능 검증을 대신하지 않는다.

여기서 **실측**은 당시 파일 검사 결과, **기재**는 배포처 설명, **미확인**은 확인하지 못한 항목이다. 현재 실험은 이 배포분을 처리한 62,308장의 동결 분할을 사용한다. 평가셋 12,461장의 분할 사이 중복 의심과 결과 해석은 [사전실험 보고](사전실험_보고.md)를 따른다.

## 1. 조사 범위

| AI허브 자료 | 확인 상태 | 연구와의 관계 |
|---|---|---|
| 127. 창원 지역 특화산업 고도화 및 디지털 전환 촉진을 위한 용접 AI 학습 데이터 (`71761`) | 라벨 전수 확인 완료 | RT가 주 자료 |
| 104. 부품 품질 검사 영상 데이터(선박·해양플랜트 LNG탱크) | 폴더 존재만 확인, 내용 미검증 | 용접 결함 검사 자료인지 판정 필요 |
| 42. 용접로봇 행동 생성 데이터 | 폴더 존재만 확인, 내용 미검증 | 행동 생성과 결함 검사의 관련성 확인 필요 |

확보 기록의 경로는 `<공유 드라이브>/<프로젝트 폴더>/`로만 표시한다. 실제 경로나 원본 데이터는 이 문서에 싣지 않는다. 저장 위치의 기록은 사용·반출 조건을 준수했다는 증명과 구분한다.

## 2. 공개분의 규모와 구조

창원 배포분의 `3.개방데이터/1.데이터/` 아래에는 Training과 Validation이 있으며 각각 원천데이터·라벨링데이터로 나뉜다. Test 폴더는 없다. 아카이브 이름의 T/V는 Training/Validation, S/L은 Source/Label, RT/VT는 방사선/육안 검사, ST/AL은 배포처의 명목 재질 구분이다.

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| RT / AL | 294 | 2,621 | 300 | 1,032 | — | — | 4,698 | 8,945 |
| RT / ST | 2,054 | 24,345 | 2,928 | 1,030 | — | — | 23,696 | 54,053 |
| VT / ST | — | 3,067 | 5,671 | — | 14,562 | 10,975 | 32,340 | 66,615 |
| 합계 | 2,348 | 30,033 | 8,899 | 2,062 | 14,562 | 10,975 | 60,734 | 129,613 |

| 구분 | Training | Validation | 합계 |
|---|---:|---:|---:|

원천 ZIP 30개의 중앙 디렉터리를 읽어 이미지 수를 대조했다. Training 115,213장, Validation 14,400장이 라벨 JSON 수와 일치했고 아카이브별 개수도 모두 맞았다. 이미지와 라벨의 개수 대응을 확인한 것이며 이미지 내용의 전수 육안 검사를 뜻하지 않는다.

원천 용량은 약 40.5 GB다. VT/ST가 32.9 GB(81%)이고 RT는 약 7.6 GB(ST 6.7 GB + AL 0.97 GB)다.

### 배포처 기재와의 차이

| 구분 | 전체 구축량(기재) | 확보 공개분(실측) | 비율 |
|---|---:|---:|---:|
| RT / ST | 60,000 | 54,053 | 90.1% |
| RT / AL | 10,000 | 8,945 | 89.5% |
| VT / ST | 74,019 | 66,615 | 90.0% |
| 합계 | 144,019 | 129,613 | 90.0% |

배포처 FAQ와 소개는 8:1:1 분할 및 Test 10% 비공개를 설명한다. 클래스별 공개분 비율도 88.6~91.2%로 비슷하다. 전체 구축량의 90%인 129,617과 실측의 차이는 4장이다. 데이터 목록에는 기재값 144,019가 아닌 실제 확보분 129,613을 사용한다.

## 3. 라벨에서 얻을 수 있는 정보

JSON 129,613개 모두 같은 22키 스키마이며 파싱 실패는 0건이었다. 주요 경로는 아래와 같다. 실제 파일의 원문 예시와 항목별 ID는 공개 문서에 싣지 않는다.

| 필드 | 내용 | 보유·채움 확인 |
|---|---|---|
| `info.id`, `.type`, `.material` | 숫자 ID, RT/VT, ST/AL | 129,613개 모두 보유·채움 |
| `image_data.file_name`, `.format`, `.width`, `.height`, `.information` | 파일명·jpg·크기·한글 클래스 | 129,613개 모두 보유·채움 |
| `meta.is_crowd`, `.annotation_case`, `.total_case` | 군집 여부와 클래스 목록 | 129,613개 모두 보유·채움 |
| `annotations[].tool`, `.class`, `.coordinate.x`, `.coordinate.y` | 폴리곤 형식·정상/결함·좌표 | 129,613개 모두 보유·채움 |
| `annotations[].case` | 영문 클래스 | 68,879개에서 비어 있지 않음. 정상 인스턴스는 빈 문자열 |

| 파일명 클래스 코드 | 한글 | 영문 라벨 | 주로 제공되는 검사 방식 |
|---|---|---|---|
| `00` | 정상 | 빈 문자열 | RT·VT |
| `01` | 균열 | `crack` | RT |
| `02` | 기공 | `porosity` | RT·VT |
| `03` | 용입부족 | `incomplete penetration` | VT |
| `04` | 융합불량 | `lack of fusion` | RT·VT |
| `05` | 슬래그혼입 | `slag inclusion` | RT |
| `06` | 언더컷 | `undercut` | VT |

RT와 VT는 각 5클래스이며 정상·기공·융합불량을 공유한다. 소수의 예외 라벨은 5절에서 따로 다룬다. 원본 라벨을 통일하는 규칙은 [연합설계 적합성](데이터셋_연합설계_적합성.md)과 사상표에서 관리한다.

폴리곤은 288,097개로 defect 227,207개, normal 60,890개다. `tool=polygon`이 전부였으며 0~1 정규화 소수 좌표는 없었다. 꼭짓점 수는 1~1,780개, 이미지당 인스턴스는 최대 117개다. 한 개만 있는 이미지는 91,496장(70.6%)이었다. bbox는 별도 제공하지 않으므로 폴리곤에서 변환한다.

두께·픽셀-mm 스케일·촬영조건(kV, mA, 노출, 선원거리)·이음형상·용접자세·적용규격·등급 필드는 없다. 회사·사업장·설비·촬영일·작업자·검사원 필드도 관련 키·문자열 전수 검색에서 확인되지 않았다. 일부 파노라마 픽셀에는 납글자가 남아 있지만 결함 크롭에는 활용할 연결 정보가 부족하다. [판정문 생성 가능성](데이터셋_판정생성_가능성.md)에 그 범위를 설명했다.

## 4. 이미지 규격과 ID 묶음

포맷은 라벨 기준 jpg 129,613/129,613이며 해상도는 9,767종이다. 최빈값은 1280×720 71,737장(55.3%)이고, 3840×2160 18,856장, 3640×2048 6,636장, 2160×3840 5,429장, 1920×1080 1,035장이 뒤를 이었다. 비트깊이는 전수 미확인이다. 표본에서는 그레이스케일과 RGB가 섞여 있었다.

| 구분 | 해상도 종수 | ID 연속 구간 수 | 이미지 수 | 묶음 평균 | 최대 |
|---|---:|---:|---:|---:|---:|
| RT / AL | 332 | 956 | 8,945 | 9.4 | 50 |
| RT / ST | 9,635 | 5,372 | 54,053 | 10.1 | 84 |
| VT / ST | 13 | 6,628 | 66,615 | 10.1 | 843 |

동일 검사 방식·명목 재질 안에서 숫자 ID가 이어지는 구간은 총 12,956개였다. 평균 크기 10.0장, 고립 묶음 1,293개, 길이 2 이상 묶음에 속한 이미지 128,320장(99.0%)이다. 1,183개 묶음(9.1%)은 클래스 폴더도 가로질렀다.

이 구간을 분할의 보조 근거로 사용했지만 **실제 동일 용접부나 연속 촬영 세션이라고 확인한 것은 아니다.** 후속 분할은 바이트 해시·ID 연속 구간·지각 해시 일치를 함께 사용했다. ID만으로 중복 탐지를 대체하거나 누수를 모두 막았다고 설명하지 않는다.

## 5. 발견한 품질 문제와 영향

| 문제 | 실측 결과 | 처리·해석에 필요한 주의 |
|---|---|---|
| 검사 방식과 클래스 불일치 | RT의 용입부족 2건, VT의 균열 6건 | 제외·매핑 방침을 기록해야 함 |
| 경계 밖 좌표 | 좌표값 9,562개, 음수 포함 파일 1,280개 | bbox 변환 때 경계 제한 필요. 원본 좌표는 보존 |
| 정상 폴리곤 | 60,890개 | 결함 객체 정답에 포함하지 않음 |
| 퇴화 폴리곤 | 꼭짓점 3개 미만 30개 | 유효성 표시와 제외 정책 필요 |
| ID와 파일명 숫자 불일치 | 10건 | 어떤 값을 묶음 근거로 삼았는지 기록 필요 |

좌표 범위는 x −16~7,951, y −20~4,364였다. 경계 문제의 영향 인스턴스는 RT/AL 753, RT/ST 1,396, VT/ST 105개다. 정상 폴리곤을 그대로 검출 객체로 쓰면 정상 상태를 별도의 결함 객체처럼 학습·채점하게 된다.

### 이미지 크기가 답을 드러내는 편향

RT/ST 결함 클래스 네 종류는 모두 1280×720이었다. 정상의 1280×720 비율은 RT/ST 8.8%(2,090장), RT/AL 24.2%(1,139장), VT/ST 0.3%(102장)다. 정상의 대형 이미지(폭>2500)는 각각 19,371·3,552·25,756장이었다.

결함의 평균 크기는 약 0.92 MP이고 정상은 RT/ST 3.01 MP(최대 36.17), VT/ST 7.86 MP였다. RT/ST에서 크기만으로 정상·결함을 나눈 규칙의 정확도는 96.1%였다. 결함 형상을 배우지 않아도 높은 점수를 받을 수 있다는 뜻이다. 타일링이나 변환만 적용했다고 편향이 제거됐다고 단정할 수 없으며, 내용 없는 대조선과 함께 결과를 읽어야 한다.

### 저자 분할과 중복 의심

Training과 Validation을 가로지르는 ID 묶음은 6,874/12,956개(53.1%)였고 그 묶음에 99,888장(77.1%)이 속했다. 같은 ID 구간이 갈린 것은 확인했지만 이 비율을 실제 촬영 세션 누수율로 부르지는 않는다. 저자 분할을 그대로 사용하지 않고 별도로 분할한 이유다. 새 분할에서도 중복 의심이 남아 있으므로 현재 평가 결과는 탐색적으로 해석한다.

## 6. 이 검증이 뒷받침하는 범위

이 자료에는 결함 종류와 픽셀 위치를 학습·평가할 라벨이 있다. 실치수 기반 합부 판정을 검증할 정답은 없다. ST·AL은 명목 구분이며 실제 재질과 일치하는지는 미확인이다. 개수·스키마 확인, 분할의 독립성, 라벨의 전문가 검증, 자료 사용권은 서로 다른 확인 항목이다.

파일 목록은 확보분 수량으로 만들고, 원본 좌표·이미지는 보존하며, 변환 결과와 제외 이유를 따로 기록한다. 이 보고서의 129,613장 전체나 RT 62,998장을 현재 사용한 62,308장과 혼용하지 않는다. 전체 안내는 [데이터셋 현황](데이터셋_현황.md)에 있다.
