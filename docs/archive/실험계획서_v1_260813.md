# 용접 결함 판정 연구 — 실험 계획

작성 기준일 2026-08-13 (2차 개정) · 목표 마감 10월 20일 (9주)

> 1차 판에서 주 데이터를 특정 공개 데이터셋으로 전제했으나, 확보 상태를 재확인해 **데이터 미확정을 전제로 재작성**했다. 갈래 선택을 데이터 확정 이후로 재배치하고, 3주차 완료 기준을 바꿨다.

## 0. 먼저 확정해야 할 것

이 계획서는 아래 다섯 가지가 정해지지 않은 상태에서 작성되었다.

| # | 결정 사항 | 영향 범위 | 언제 정해지나 |
|---|---|---|---|
| 1 | 주 이미지 데이터를 무엇으로 할 것인가 | 2.1, 일정 | 8/25 시한 |
| 2 | X선에서 통합형이 작동하는가 | 갈래 결정 | 사전 테스트 (반나절) |
| 3 | 주 실험을 어느 갈래로 할 것인가 | 3장, 4장 | **1·2번 이후** |
| 4 | 배경지식 학습 범위 (대상 모델 크기, 추가 사전학습 포함 여부) | 2.4, 3장 | 8/16 회의 |
| 5 | 정답 조항 목록 작성 담당과 전문가 검토 경로 | 5.3, 6.3 | 8/16 회의 |

**순서가 중요하다.** 갈래를 먼저 정하고 데이터를 맞추는 것이 아니라, 확보되는 데이터가 갈래를 결정한다. 3번을 1·2번 뒤로 미룬 이유다.

X선 영상에서는 통합형 모델의 직접 증거가 아직 부족하다는 것이 관련 리뷰의 평가다. 방사선 데이터로 확정될 경우 통합형은 근거가 약해지고 분리형이 사실상 강제된다. 가시광 데이터가 확보되면 두 갈래가 모두 열린다.

**본 계획서는 갈래 2(분리형)를 기본으로 가정한다.** 확보 가능성이 가장 높은 데이터가 방사선이고, 어느 데이터로 확정되든 성립하기 때문이다. 갈래 1로 결정될 경우 달라지는 부분은 각 절에 표기했다.

## 1. 전체 흐름

```
[0] 사전 확인          X선에서 통합형이 작동하는가 → 갈래 결정 근거
       ↓
[A] 데이터 수집        확보된 것으로 8/25 확정 · 한국어 원문 시드
       ↓
[B] 이미지 정제        라벨 체계 통일 → 평가셋 선분리 → 회사별 분할
       ↓
[C] 합성 corpus 생성   지식 서술문 · 질의응답 · 판정 추론 3종
       ↓
[D] 검증 · 버전 고정   규칙 검사 → 조항 대조 → 표본 전문가 검토
       ↓
[E] 배경지식 학습      (선택) 추가 사전학습 → 지시 학습 → 추론 학습
       ↓
[F] 학습 방식 3종      로컬 단독 / 연합 / 중앙집중  ← 유일한 비교 변수
       ↓
[G] RAG 구성           조항 단위 색인 · 정답 조항 목록
       ↓
[H] 평가               검출 · 근거 접지 · 조항 정확도 · 낯선 데이터
```

[A]~[E]는 세 학습 방식에 공통으로 적용된다. 즉 비교 변수가 아니다. [F]만이 갈라지는 지점이며, 이 통제가 무너지면 논문의 주장이 성립하지 않는다.

**회신 시한을 8월 25일로 정한다.** 그 시점까지 도착한 것으로 확정하고 실험에 들어간다. 9월 초에 기준 실험이 끝나야 하므로 더 미룰 수 없다. 메일과 별도로 GitHub Issue에도 같은 문의를 올린다 — 공개 게시물이라 응답 압력이 다르다.

**Intel 신청 시 주의.** 익명 정보로 낸 신청은 거부된다고 명시되어 있다. 기관 메일, 소속, 비상업 연구 목적을 정확히 기재한다. 인용 의무가 있으므로 논문 참고문헌에 반영한다.

**데이터별 성격**

*RIAWELC (X선)* — 즉시 쓸 수 있는 유일한 대규모 데이터다. 다만 X선 영상에서 통합형 모델의 성능 근거가 아직 부족한 영역이라, 이 데이터로 확정되면 분리형이 사실상 강제된다. 검출 모델은 X선에서 잘 작동하므로 분리형에는 문제가 없다.

*Intel (가시광 멀티모달)* — 승인되면 가장 좋은 선택지다. 통합형에 유리하고, 메타데이터에 강종·두께·이음형상·로봇 속도가 들어 있어 **"협력사마다 취급 강종이 다르다"를 데이터에 있는 값으로 구현할 수 있다.** 인위적 분할이 아니라 실제 속성 기반 분할이 되므로 논문의 설득력이 크게 올라간다. 다만 4,000샘플을 3분할하면 클라이언트당 1,300개 남짓으로 다소 적고, 라벨 노이즈가 논문에 명시되어 있다.

*MWDD* — 확보되면 선행 연구와 직접 비교가 가능하다. 다만 두 가지를 감안해야 한다. 첫째, 텍스트 어노테이션이 사실상 템플릿 채우기다. 논문 표현과 달리 규칙 기반 자동 생성물이므로, 이를 정답으로 삼는 텍스트 유사도 평가는 "템플릿을 얼마나 잘 흉내내는가"를 재게 된다. 둘째, 여러 출처를 병합한 것으로 보여 원본을 특정하기 어렵다.

> 이 한계는 오히려 6.3의 조항 정확도 지표를 정당화한다. 기존 텍스트 지표가 못 미더우니 표준 조항에 직접 접지하겠다는 논리가 선다.

```
확인 내용 : 사전학습된 시각-언어 모델의 제로샷 분류가
            X선 영상에서 작동하는가
방법     : RIAWELC과 가시광 데이터에서 각각 측정

```

| 결과 | 해석 | 갈래 |

이 결과 자체가 논문의 근거로 쓰인다. "왜 분리형을 택했는가"에 실측으로 답할 수 있다.

### 2.1b 텍스트 QA 공개 데이터 — 사용하지 않는다

공개된 용접 QA 데이터 4종(약 57,000행)을 검토했으나 후보에서 제외한다.

| 이유 | 내용 |
|---|---|
| 이미지 없음 | 순수 텍스트다. 비전 모달이 빠져 있다 |
| 저작권 | 한 종은 원본이 유료 핸드북임이 문서에 명시되어 있고 라이선스 표기가 없다 |
| 검증 안 됨 | 생성형 모델이 만든 문답이라 사실 확인이 되지 않았다 |
| 순환 위험 | 평가에 쓰면 모델이 만든 데이터로 모델을 평가하는 구조가 된다 |

다만 그중 국제 규격 기반 중국어 질의응답 세트는 **형식 참고용으로만** 본다. 규격 조항을 질의응답으로 바꿀 때 어떤 형태가 되는지 참고할 만하다. 내용을 가져오지는 않는다.

### 2.2 이미지 데이터 정제

**(a) 라벨 체계 정리**

주 데이터가 무엇으로 확정되든 **국제 표준 코드로 사상하는 대응표를 먼저 만든다.** 학습 라벨은 원본 체계를 그대로 쓰고, 조항 검색과 낯선 데이터 평가에서만 표준 코드를 쓴다. 원본 라벨을 바꾸면 선행 연구와 비교가 깨진다.

| 원본 클래스 | 성격 | ISO 6520-1 대응 |
|---|---|---|
| 균열 (Crack, CR) | 결함 유형 | 100번대 |
| 기공 (Porosity, PO) | 결함 유형 | 2011 / 2012 |
| 용입불량 (Lack of Penetration, LP) | 결함 유형 | 402 |
| 과다 덧살 (Excess Reinforcement) | 결함 유형 | 502 |
| 스패터 (Spatters) | 결함 유형 | 602 |
| 용접선 (Welding Line) | 결함 유형 | 판정 보류 — 정상 비드와 경계 모호 |
| 정상 (ND / Good Welding) | 판정 수준 | 해당 없음 |
| 불량 (Bad Welding) | 판정 수준 | 유형 아님 — 계층 분리 필요 |

두 가지를 주의한다.

*판정 수준과 결함 유형이 섞인 체계.* 일부 데이터는 "불량"과 "균열"이 같은 층위에 있다. 둘이 동시에 성립하는 경우의 처리가 불분명하므로 계층을 분리해 둔다.

*RIAWELC은 4종뿐이다.* 표준 6개 그룹 중 3개만, 그것도 방사선에서 잘 보이는 것만 포함한다. 논문에서 이를 한계로 명시하고, 향후 확장 시 라벨 재정의 없이 이어지도록 표준 코드 체계를 유지한다.

*용접선 클래스*는 선행 연구에서도 최저 성능이었다. 하락은 예상된 결과이므로 별도 보고한다.

**(b) 중복 제거**

같은 용접부를 연속 촬영한 프레임이 학습셋과 평가셋에 나뉘어 들어가면 성능이 부풀려진다. 지각 해시(perceptual hash) 기준으로 근접 이미지를 묶고, 같은 묶음은 같은 쪽에만 배정한다.

**(c) 전처리 통일**

입력 해상도 640×640, 정규화 방식, 증강 설정을 세 학습 방식에 동일하게 고정한다. 선행 연구 설정(100 epoch, batch 32, SGD, AMP)을 따른다. 여기서 차이가 나면 "연합학습이 못한 게 아니라 전처리 때문"이라는 반론을 막을 수 없다.

**(d) 평가셋 선분리 — 순서가 중요하다**

```
전체 이미지
  ├─ 글로벌 평가셋 20%   ← 회사별 분할보다 먼저 떼어낸다
  └─ 학습 풀 80%
       ├─ 앵커 조선소   60%
       ├─ 협력사 1      20%
       └─ 협력사 2      20%
```

분할 이후에 평가셋을 만들면 세 방식이 서로 다른 기준으로 채점된다. 반드시 먼저 뗀다.

**(e) 회사별 분할 설계**

두 축으로 불균형을 준다.

- **규모 불균형** — 60 : 20 : 20. 앵커 조선소가 데이터를 많이 가진 현실을 반영한다.
- **클래스 편중** — 디리클레 분포 α = 0.5로 클래스별 배분. α 값은 논문에 명시하고, 분할 시드도 고정해 재현 가능하게 한다.

균등 분할(IID)로 하면 결과가 뻔하고 논문이 재미없어진다. 편중이 있어야 "연합학습이 무엇을 회복했는가"가 드러난다.

**(f) 분할 방식 — 데이터에 따라 갈린다**

| 확보 데이터 | 분할 방식 | 논문 표기 |
|---|---|---|
| Intel 승인 | 강종·두께 등 실제 속성으로 분할 | 속성 기반 이질성 |
| MWDD 확보 | 출처 메타데이터가 있으면 출처 기준 | 자연 발생 이질성 |
| RIAWELC 단독 | 클래스 편중을 인위적으로 부여 | **시뮬레이션 페더레이션** |
| 둘 이상 확보 | 데이터셋 자체를 클라이언트로 | 기관 간 이질성 |

Intel의 메타데이터 기반 분할이 가장 좋다. "협력사마다 취급 강종이 다르다"가 인위적 설정이 아니라 데이터에 실재하는 값이 되기 때문이다.

RIAWELC 단독으로 가더라도 학술적으로 문제없다. 시뮬레이션임을 명시하면 되고, 오히려 분할 조건을 통제할 수 있어 실험이 깔끔해진다.

### 2.3 텍스트 데이터 수집

2.1b에서 공개 QA 데이터를 제외했으므로, 씨앗은 **한국어 원문 중심**으로 새로 모은다.

| 출처 | 언어 | 접근 | 우선순위 |
|---|---|---|---|
| 대한용접접합학회지 논문 | 한 | KCI 무료 | **최우선** |
| KS 규격 용접 관련 | 한 | 표준인증 열람 | 높음 |
| 한국선급 규정 | 한 | 홈페이지 공개 | 높음 |
| IACS Rec. 47 | 영 | 전문 무료 공개 | 높음 — RAG 색인 필수 |
| ISO 6520-1 코드 체계 | — | 코드 번호는 사실 정보 | 라벨 온톨로지 |
| 유료 핸드북류 | 영 | 저작권 애매 | **제외** |
| 중국어 자료 | 중 | — | **제외** — 한국어 성능에 기여 없음 |

**한국어를 우선하는 이유가 셋이다.** 국내 학회 발표라 명분이 서고, 라이선스가 깨끗하며, 최종 판정문 출력이 한국어여야 하기 때문이다.

**PDF 수집·정제가 생각보다 큰 작업이다.** 수백 쪽짜리 문서에서 표와 그림 캡션을 어떻게 처리할지가 관건이다. 허용치 표는 판정 추론 데이터의 핵심 재료이므로 표를 구조화해 추출해야 하고, 이건 본문 텍스트 추출과 다른 작업이다. **담당자를 지정해야 한다.**

**저작권 방침.** 유료 표준 전문은 corpus에 넣지 않는다. 결함 코드 번호와 명칭(401 = 융합불량 등)은 사실 정보이므로 라벨 체계로 쓰는 데 문제없다. RAG 색인은 무료 공개 문서로만 구성한다.

**규모 목표.** 배경지식 학습에 추가 사전학습을 포함할 경우와 아닌 경우가 다르다.

| 범위 | 필요 규모 | 비고 |
|---|---|---|
| 지시 학습 + 추론 학습만 | 수백만 토큰 | 확보 가능한 원문으로 충분 |
| 추가 사전학습 포함 | 5,000만 토큰 이상 | PDF 수집이 필수 전제 |

후자로 가려면 PDF 수집에만 2주가 든다. 3장의 범위 결정과 직결된다.

### 2.4 합성 corpus 생성

세 종류를 만든다. 각각 학습 단계가 다르다.

**(a) 지식 서술문** — 추가 사전학습용

```
입력  : 학회지 초록, 규격 조항, 결함 원리 설명
출력  : 연속된 서술문. 질문·답변 형식 없음
예    : "용접부의 저온균열은 확산성 수소, 구속응력, 경화조직의
         상호작용으로 발생한다. 확산성 수소는 용접 금속이 냉각되며..."
```

목표 분량은 추가 사전학습 포함 여부에 따라 달라진다. 포함하지 않기로 결정되면 이 항목은 만들지 않는다.

**(b) 질의응답** — 지시 학습용

```
Q : 방사선 사진에서 기공과 슬래그 개재물을 어떻게 구분하는가
A : 기공은 원형에 가깝고 경계가 뚜렷하며 밀도가 균일하다.
    슬래그 개재물은 불규칙한 형상이고...
```

결함 유형별로 균형 있게 생성한다. 목표 2만 건.

**(c) 판정 추론 과정** — 추론 학습용. **이 연구의 핵심 자산이다.**

용접 판정은 추론 사슬이 명확하고 정답이 표준 문서에 있다. 이 성질 덕분에 다른 도메인보다 생성과 검증이 모두 유리하다.

```
관찰 : 방사선 사진 중앙부에 직경 약 2 mm의 원형 음영이 관찰된다
분류 : 형상과 밀도로 보아 기공(ISO 6520-1 2011)에 해당한다
조회 : 모재 두께 12 mm, 품질 수준 C 적용
      → 단일 기공 허용 직경은 0.3s (최대 3 mm)
대조 : 관찰값 2 mm ≤ 허용값 3 mm
판정 : 합격. 근거 — ISO 5817 품질수준 C, 항목 2.1
```

목표 1만 건. 결함 유형 × 두께 구간 × 품질 수준 조합으로 생성하되, 실제 존재하는 조합만 만든다.

### 2.5 합성 데이터 검증

생성한 것을 그대로 쓰면 오류가 학습에 그대로 들어간다. 3단계로 거른다.

**1단계 — 규칙 검사 (프로그램)**

- ISO 6520-1 코드가 유효 목록에 있는가
- 조항 번호가 실제 문서에 존재하는가
- 수치 조건이 계산상 맞는가 (`2 mm ≤ 3 mm` 같은 부등식을 파서로 검증)
- 두께와 품질 수준 조합이 표에 존재하는가

정량 조건은 사람이 볼 필요 없이 프로그램으로 잡힌다. 이 단계에서 상당량이 걸러진다.

**2단계 — 조항 대조 (모델)**

생성문이 인용한 조항의 원문을 가져와 내용이 일치하는지 대조한다. 중요한 것은 **생성한 모델이 자기 결과를 판정하지 않는 것**이다. 검증 축을 외부 문서에 걸어야 의미가 있다. 같은 모델이 자기검증하면 통과율만 올라가고 오류는 남는다.

**3단계 — 표본 전문가 검토**

전체의 2~3%를 무작위 추출해 전문가가 확인한다. 통과율을 논문에 보고한다. 외부 도메인 전문가(협의 예정) 연계 가능 여부를 확인한다.

**버전 고정.** 최종 corpus에 스냅샷 해시를 부여하고 논문에 명시한다. 재생성하면 RAG 결과가 바뀌어 재현이 불가능해진다.

## 3. 배경지식 학습 (준비 단계)

세 학습 방식에 **똑같이 적용**한다. 비교 변수가 아니다.

### 3.1 어디에 적용하는가

| | 갈래 1 (통합형) | 갈래 2 (분리형) |
|---|---|---|
| 적용 대상 | 그림·글 통합 모델 전체 | 언어모델 쪽만 |
| 검출 모델 | 별도 없음 | 이미지로만 학습 (텍스트 미적용) |

갈래 2에서는 검출 모델이 텍스트를 보지 않으므로 배경지식 학습 대상이 아니다. 이것이 두 갈래의 첫 번째 분기점이다.

### 3.2 학습 단계

```
기본 모델
   ↓  (선택) 추가 사전학습 — 지식 서술문, QLoRA r=128
   ↓  지시 학습 — 질의응답, QLoRA r=16
   ↓  추론 학습 — 판정 추론 과정, QLoRA r=16
도메인 모델  →  세 학습 방식의 공통 출발점
```

**추가 사전학습을 넣을지는 미정이다.** 넣는다면 조건이 넷이다.

1. 한국어 원문 시드를 2주 안에 확보할 수 있는가 (PDF 수집 담당 지정)
2. 대상 모델 크기를 확정했는가
3. 유무 비교 실험(4회차)을 돌릴 여유가 있는가
4. 주 지표를 이미지 성능 단독이 아니라 조항 정확도와 병렬로 둘 것인가

**모델 크기가 자원을 결정한다.**

| 크기 | 추가 사전학습 필요 사양 | 접근성 |
|---|---|---|
| 0.5B ~ 1B | 24~40GB | 연구실 GPU로 가능 |
| 3B | 80GB급 | 클라우드 또는 기관 노드 |
| 7B 이상 | 다중 노드 | 현실적으로 어려움 |

선행 연구가 3B급을 썼으므로 비교를 생각하면 3B가 자연스럽지만, 자원 확보가 전제된다. 낮은 랭크 어댑터 방식(r=128)으로 하면 24GB에서도 가능하지만, 전체 파라미터 학습보다 지식 주입 효율이 떨어진다는 점을 논문에 밝혀야 한다.

기관 AI 노드를 연구 목적으로 쓸 수 있으면 제약이 사라진다. 사용 가능 여부를 먼저 확인한다.

**전제하지 말고 측정하라.** 넣기로 한다면 유무 비교를 붙인다. 효과가 없어도 그 자체가 결과다 — 텍스트 학습이 이미지 판별에 기여하지 않는다는 실증이 되기 때문이다.

**어댑터 병합.** 배경지식 학습으로 만든 어댑터는 반드시 기본 모델에 병합한 뒤 배포한다. 병합하지 않고 얹으면 이후 연합 집계 대상이 모호해지고, "무엇을 평균했는가"라는 질문에 답하기 어려워진다.

## 4. 학습 방식 3종

### 4.1 절대 건드리면 안 되는 것

| 항목 | 고정값 |
|---|---|
| 기본 모델 | 동일 체크포인트, 버전 명시 |
| 어댑터 설정 | rank, alpha, 대상 레이어, dropout 동일 |
| 최적화 | 학습률 스케줄, 배치 크기, warmup 동일 |
| 전처리 | 해상도, 정규화, 증강 동일 |
| 프롬프트 | 완전 동일 (한 글자도 다르면 안 됨) |
| RAG | 동일 색인 스냅샷, 동일 검색기, 동일 top-k |
| 디코딩 | 온도 0 또는 시드 고정, 최대 토큰 동일 |
| 시드 | 3개 세트, 세 방식에 동일 적용 |

### 4.2 세 방식

**로컬 단독** — 각 클라이언트가 자기 데이터로만 N 에폭 학습. 다른 클라이언트와 아무것도 주고받지 않는다. 세 클라이언트의 평균과 개별값을 모두 보고한다.

**연합** — R 라운드 × E 로컬 에폭. 매 라운드 클라이언트가 학습한 결과를 서버가 평균하고 다시 배포한다.

**중앙집중** — 전체 학습 풀을 한곳에 모아 N 에폭 학습.

### 4.3 학습량 등가 — 심사에서 반드시 나오는 질문

```
R × E = N
예) R = 30, E = 1  ↔  N = 30
```

맞추지 않으면 "연합학습이 진 게 아니라 덜 학습한 것"이 된다. 조기 종료는 쓰지 않고 고정 예산으로 돌린다. 논문에 R, E, N, 총 갱신 횟수를 모두 명시한다.

### 4.4 집계 대상

**갈래 2인 경우 — 2단계로 나눈다.**

```
1단계 : 검출 모델 전체 가중치 집계 (R1 라운드) → 완료 후 동결
2단계 : 판정 쪽 어댑터 집계 (R2 라운드)
```

두 루프를 라운드마다 섞는 것보다 통제가 쉽고, 각 단계의 기여를 분리해 볼 수 있다. R1과 R2의 배분 근거는 논문에 밝힌다.

검출 모델이 2.78M 규모이므로 전체 가중치를 주고받아도 부담이 없다. 판정 쪽은 어댑터만 오간다.

**갈래 1인 경우 —** 어댑터만 집계한다. 단계 구분이 없어 단순하다.

### 4.5 어댑터 평균의 주의점

낮은 랭크 어댑터는 두 행렬의 곱으로 표현된다. 각각을 평균한 것의 곱은 곱을 평균한 것과 다르다.

```
avg(B) · avg(A)  ≠  avg(B · A)
```

실무에서는 각각 평균하는 방식이 널리 쓰이지만, 심사에서 지적될 수 있는 지점이다. 미리 인지하고, 필요하면 갱신량 자체를 평균하는 방식을 대안으로 준비한다.

## 5. RAG 구성

### 5.1 색인

| 항목 | 설정 |
|---|---|
| 문서 | IACS Rec. 47, 한국선급 규정, ISO 6520-1 코드 체계, 합성 판정 사례 |
| 청킹 단위 | **조항 단위** — 고정 길이로 자르면 조항 경계가 깨진다 |
| 메타데이터 | 문서명, 조항 번호, 결함 코드, 적용 두께 범위, 품질 수준 |
| 임베딩 모델 | 고정. 세 학습 방식에서 재학습하지 않는다 |
| 검색 | top-k 고정 (k = 3 권장) |

### 5.2 검색 질의 구성

**결함 코드를 그대로 키로 쓴다.** 자연어 질의를 생성해 검색하면 재현성이 떨어지고, 검색 실패 원인이 질의 생성 탓인지 색인 탓인지 분리되지 않는다.

```
질의 = { 결함 코드, 실측 치수, 모재 두께, 지정 품질 수준 }
```

### 5.3 정답 조항 목록

평가를 위해 결함 유형별 정답 조항을 미리 정해 둔다.

```
결함 유형 × ISO 6520-1 코드 × 해당 조항 번호
```

7종 × 두께 구간 × 품질 수준이므로 규모는 크지 않다. 다만 **전문가 확인이 필수**다. 이 목록의 정당성이 흔들리면 6.3의 지표 전체가 흔들린다. 표준 원문의 조항 번호를 그대로 인용하는 방식으로 방어한다.

### 5.4 연합학습 대상이 아니다

색인은 공개 문서와 합성 corpus로 만들어지며 모든 참여 기관이 동일하게 갖는다. 학습 대상이 아니므로 집계 루프 바깥에 둔다. 아키텍처 그림에서도 경계 밖에 그린다.

## 6. 평가

### 6.1 검출 성능 (주 지표)

| 지표 | 비고 |
|---|---|
| **Macro-F1** | 주 지표. 클래스 불균형에 강하다 |
| mAP@0.5, mAP@0.5:0.95 | 선행 연구와 직접 비교 |
| 클래스별 P / R / F1 | Welding Line 저조는 예상 결과 |
| **결함 recall** | 별도 보고 |
| 혼동 행렬 | 최소한 연합학습 조건은 필수 |

**결함 recall을 따로 떼는 이유.** 현장에서 미검출은 오검출보다 훨씬 위험하다. "정상으로 잘못 판정한 실제 결함의 비율"을 별도 지표로 두면 실용성 논거가 서고, 제작 품질 기준의 관점과도 맞는다.

전체 정확도만 보고하면 다수 클래스 뒤에 실패가 숨는다.

### 6.2 근거 접지 (선행 연구 지표 계승)

| 지표 | 의미 |
|---|---|
| Class-Jaccard | 판정문이 언급한 결함 종류가 실제 검출과 맞는가 |
| BBox-IoU | 판정문이 지목한 위치가 실제 검출 위치와 맞는가 |

선행 연구가 도입한 지표를 그대로 쓴다. 다만 위치 라벨이 있는 데이터에서만 산출 가능하다. RIAWELC은 분류 라벨만 있으므로 이 지표를 낼 수 없고, 그 경우 6.1과 6.3만으로 평가한다.

**좌표는 반드시 정규화한다.** 선행 연구에서 원시 픽셀 좌표를 그대로 넣었을 때 BBox-IoU가 0.055로 붕괴했다. 정규화하면 0.938이다. 17배 차이다.

### 6.3 조항 정확도 (신설)

위 두 지표는 **검출 결과와의 일치**를 잰다. 검출이 맞다는 전제에서만 의미가 있으며, 인용한 규정이 실제 표준과 맞는지는 재지 않는다. 세 번째 축을 추가한다.

| 지표 | 산출 |
|---|---|
| 조항 검색 정확도 | 정답 조항 대비 top-1 / top-3 적중률 |
| 인용 일치율 | 판정문이 인용한 조항 ↔ 정답 조항 |
| 판정 정합성 | 인용 조항의 허용치와 실측값으로 도출한 합부가 최종 판정과 일치하는가 |

세 번째 항목이 특히 중요하다. 조항을 맞게 찾고도 결론을 틀리게 낼 수 있기 때문이다.

### 6.4 생성문 품질

검색이 맞아도 문장이 엉망일 수 있다. 표본 평가를 병행한다.

- 한국어 평가셋(599행)에 전문가 표본 검토
- 평가 항목: 사실 오류 유무, 근거 제시 여부, 실무 적용 가능성

규모가 작으므로 주 지표가 아니라 보조 지표로 둔다.

### 6.5 낯선 데이터

학습 없이 추론만 한다. 비용이 사실상 0이므로 반드시 포함한다.

| 데이터 | 비교 방식 |
|---|---|
| RIAWELC | ISO 코드로 라벨 사상 후 결함 유형 분류 성능 |
| Notre Dame 현장 95장 | 합격 여부 이진 판정만 — 검출 지표와 직접 비교 불가 |
| LoHi-Weld | 표면 결함 검출 성능 |

**결과가 나쁠 가능성이 높다.** 도메인 차이가 크기 때문이다. 주 결과가 아니라 한계 절에 배치하고, "선행 연구가 남긴 일반화 공백의 최초 정량화"로 서술한다. 시간이 부족하면 가장 먼저 잘라도 논문은 성립한다.

### 6.6 헤드라인 숫자

```
회복률 = (연합 - 로컬) / (중앙집중 - 로컬) × 100 %
```

논문의 결론 문장이 된다. 90%를 넘으면 강한 결과이고, 70%대여도 데이터를 내보내지 않는다는 조건을 감안하면 정당화된다.

### 6.7 결과 표 형식

| 학습 방식 | Macro-F1 | 결함 recall | Class-Jac. | BBox-IoU | 조항 top-1 |
|---|---|---|---|---|---|
| 로컬 단독 (3사 평균) | — ± — | — | — | — | — |
| 연합 | — ± — | — | — | — | — |
| 중앙집중 | — ± — | — | — | — | — |

시드 3회 평균과 표준편차를 함께 적는다. 중앙집중 행에는 "현실에서는 데이터 반출 불가"를 각주로 단다.

### 6.8 자주 놓치는 함정

- corpus 스냅샷을 고정하지 않으면 RAG 결과가 바뀌어 재현이 안 된다
- 검색기를 방식별로 재학습하면 통제가 깨진다
- 한국어 평가셋을 학습에도 쓰면 누출이다. 평가 전용으로 격리한다
- AI-Hub 데이터는 이용약관에 성과 보고 의무가 있다. 발표 전 확인한다
