# 개발 규약

이 저장소는 공개 용접 방사선 영상으로 로컬 단독·중앙집중·연합학습을 비교한다. 본실험 대상은 통합형 VLM이며 완료된 분리형 검출기 실험은 사전실험으로 보존한다. 이 문서는 자료를 훼손하지 않고 비교 조건과 증거를 유지하기 위한 작업 규칙이다. 설계 의도는 [실험설계](실험설계.md), 코드의 연결과 검증 범위는 [구현설계](구현설계.md), 정책 변경은 [의사결정로그](의사결정로그.md)에 설명한다.

규칙을 정한 사실, 코드를 구현한 사실, 실제 실행에서 검증한 사실을 구분한다. 2026-10-05 현재 통합형 실행·생성·채점 코드는 있으나 실물 리허설을 통과하지 않았고 본실험 결과도 없다. 과거 기록의 ‘검증 완료’를 다른 판본이나 현재 전체 경로의 보증으로 인용하지 않는다.

## 1. 원본과 분할을 보존한다

1. `data/raw/`는 읽기 전용이다. 원본을 수정·삭제·덮어쓰지 않고 변환 결과는 새 경로에 쓴다.
2. 학습·평가는 매니페스트와 스냅샷을 입력으로 사용한다. 원본 폴더를 임의 순회하거나 분할을 실행 중 다시 만들지 않는다. 매니페스트 변경은 실험 변경이다.
3. 평가셋은 참여자 분할보다 먼저 뗀다. 현행 설계는 20%, 명목 재질×클래스 층화, 묶음 단위 분할이다. 같은 묶음을 train·val·eval에 나누지 않는다.
4. 평가 이미지·정답 조항을 학습, 프롬프트 선택, 전처리 적합, 리허설에 사용하지 않는다. 진단과 리허설은 train·val의 별도 목록을 사용하며 노출 이력을 남긴다.
5. corpus·페어·색인은 sha256으로 동결한다. 변경할 때는 새 이름·경로·계약을 사용하고 기존 산출물과 해시를 보존한다.
6. 허용치 CSV를 골격·RAG 메타데이터·판정 기준의 공통 원천으로 삼는다. 라벨은 코드에 흩어 적지 않고 원본↔ISO 사상표 YAML에서 읽는다.

동결 RT는 62,308장, 공통 eval은 12,461장이다. 학습 풀 49,847장은 train 44,846·val 5,001이고 C1 26,451·C2 16,253·C3 7,143장으로 구성된다. C1·C2는 명목 ST, C3는 명목 AL이다. 회사 정보가 없는 데이터이므로 실제 회사·확인된 재질로 표현하지 않는다.

묶음은 해시와 ID 구간 등의 대용 기준이다. 실제 용접부·촬영 세션을 확인한 식별자가 아니며 분할 간 중복이 남았다. 따라서 ‘누출 방지 완료’나 ‘독립 일반화 검증’으로 쓰지 않는다. 2026-10-01에 현행 분할의 탐색적 비교와 평가 부표본 2,910장을 채택했다. 부표본 목록·가중·재표집 규칙은 사용 전에 등록하고 모든 모델·시드·대조선에 동일하게 적용한다. 2,910장은 기존 설계의 희소층 전수 부분이어서 나머지 층의 포함확률 문제를 해결하기 전에는 전체 eval을 대표하는 확률표본으로 서술하지 않는다.

매니페스트·주석의 기본 판독기는 `data.manifest_io.load_snapshot()`이다. eval 정답을 올리면 안 되는 경로와 본채점은 `data/manifest_view.py`의 제한된 네 판독기를 사용한다. 허용 열, 영수증 검사, 반환 직후 지문 대조와 호출 기록의 상세 규칙은 [구현설계](구현설계.md#2-입력은-동결-스냅샷으로-읽는다)를 따른다. 직접 CSV를 읽어 이 제한을 우회하지 않는다.

## 2. 자료의 이용 범위와 공개 범위를 지킨다

AI허브 71761의 원본·파생 이미지는 해외 스토리지, 해외 리전 클라우드, 외부 API에 업로드하지 않는다. 내국인 신청·성과 보고 의무 등 이용 조건은 발표 전 재확인한다. 유료 GPU를 사용할 경우 국내 사업자·국내 리전으로 한정하고 위탁처리·재해복구(DR) 리전을 서면으로 확인하는 기존 방침을 적용한다.

학습·추론·합성 생성은 로컬 가중치로 수행한다. 원본 이미지를 상용 VLM API에 보내 라벨이나 판정문을 만들지 않는다. 상용 API 생성 응답을 학습에 쓰지 않으며, 학습 투입 여부를 결정하는 합성 검증에도 상용 API를 사용하지 않는 정책이다. 초기 QA 배치 API 검토 기록을 현행 예외 승인으로 읽지 않는다.

실험 추적은 MLflow 로컬 sqlite와 파일 artifact로 한다. 외부 클라우드 로깅은 사용하지 않는다. 자격증명·GPU 계정·개인 절대경로는 추적하지 않는 로컬 파일에 두고 커밋하지 않는다.

유료 표준 전문을 corpus·색인에 넣지 않는다. 무료 열람과 재배포 허용도 구분한다. 조항 코드·사실값·재서술을 사용할 때 출처와 이용 범위를 기록하며, 검토가 끝나지 않은 원문 파생 자산을 공개하지 않는다. `cycle_pilot` 봉인 코퍼스는 규정 원문 연속 일치 문제로 공개하지 않기로 했다. 코드·문서 공개가 이미지·코퍼스·페어 전체 공개를 뜻하지 않는다.

백업은 파일이 있다는 확인과 해시가 같다는 확인을 구분한다. 복사, 파일 수·용량·sha256 대조, 동기화 완료 확인을 마친 후에만 별도 승인된 원본 정리를 검토한다. 연결 경로나 디렉터리 별칭을 통해 동결 자산을 삭제하지 않는다. 계약서가 없으면 봉인 검증 성공으로 처리하지 않는다.

## 3. 비교 조건을 고정한다

같은 구조의 학습 방식 비교에서 기본 모델, 어댑터 rank·alpha·대상 레이어·dropout, 최적화, 전처리, 프롬프트·채팅 템플릿 모드, 디코딩을 고정한다. 프롬프트의 사소한 문구 변경도 판본 변경으로 기록한다. 통합형과 검출기의 백본·입력·검색 제공 여부는 다르므로 두 구조 전체가 같은 조건이라고 쓰지 않는다.

조기 종료와 best 체크포인트 선택을 사용하지 않는다. 고정 예산을 마친 last를 채점한다. `R × E = N`은 원본 이미지 방문 횟수 등가이며 학습 순서·증강·optimizer 갱신 경로의 동치가 아니다. 실제 스텝·표본·감독 토큰·시도 수를 기록한다. AMP 갱신 시도와 실제 적용도 구분한다.

통합형은 Qwen3.5 4B QLoRA, 4bit, `enable_thinking=False`를 채택했다. 시드당 로컬 세 모델·중앙·연합을 모두 비교한다. 최종 학습량·시드 수·생성 한도·대표 지표가 미정이면 임의 기본값으로 본실험을 시작하지 않는다. 검출 사전실험의 N=100·R=50·E=2와 시드 세 개를 통합형의 확정값으로 자동 승계하지 않는다.

디코딩은 greedy 1회다. 파싱 실패나 낮은 점수를 이유로 재시도·재프롬프트하지 않는다. 같은 입력에서 성공한 출력만 골라 바꾸지 않는다. 실패율과 사유를 과업 지표와 별도로 보고한다.

출력은 공통 JSON 규약으로 변환한 뒤 동일한 채점기 판으로 처리한다. `uni_local`은 참여자 식별을 포함한다. 지표가 정의되지 않거나 수행하지 않은 경우 0으로 채우지 않고 상태·사유를 남긴다.

현재 파싱 실패는 빈 예측으로 처리된다. 결함 이미지에서는 미탐이지만 정상의 빈 예측은 오탐을 만들지 않으며 Class-Jaccard 공집합 규칙에서는 1을 얻을 수 있다. 모든 실패가 일률적인 0점이라는 문구를 사용하지 않는다. M1 실패 결합·항목 폐기·민감도 채점의 최종 규칙은 대표 지표 등록 전에 확정한다.

bbox는 원본 픽셀로 저장하고 학습용 변환·채점용 역변환을 함수로 분리한다. 현 저장 규약은 `ABS_ORIG`다. 채택 모델의 실제 생성 좌표 프레임이 일치하는지 본실험 전에 확인한다. 합성 도형 제로샷 시험만으로 미세조정 후 좌표를 검증했다고 쓰지 않는다.

## 4. 합성 자료의 검증 상태를 정확히 기록한다

규칙이 수치·논리·조항 골격을 만들고 생성 모델은 표현을 변주한다. 생성한 모델이 자기 답을 검증하지 않으며 검증기는 다른 계열을 사용한다. 계열 차이만으로 사실성 검증이 완성되지는 않으므로 원문·사람 정답 대조도 필요하다.

합성 검증 실패분은 폐기하고 검증기 이름·판본과 통과율을 기록한다. 재생성해 통과한 사례로 바꾸지 않는다. 허용치 표·코퍼스·정답 조항의 사람 검수가 끝나지 않았으면 미완료를 표시한다. 형식·중복 검사 통과를 사실성 검증으로 부르지 않는다.

페어의 `validated_by`는 현재 `rule`만 허용한다. 사람 검수 기록의 존재만으로 다른 값을 허용하지 않는다. 대상 빌드 해시, 표본 수, 검수자·시각을 양쪽 검사기가 확인하는 계약을 마련한 뒤 확장한다.

실이미지에 없는 두께·실치수·합부 정답을 만들어 채우지 않는다. AL 결함의 `clause_only`·`verdict=null`을 보존한다. 합성 수치를 쓴 규칙 일치는 실제 용접부 합부 정확도와 구분한다. KR 누적 점수제처럼 용접부·촬영 시야 단위가 필요한 규정은 이미지 한 장 자료로 적용하지 않는다.

CPT, 증류, DPO, GRPO는 현재 연구에서 수행하지 않는 정책이다. 불용어 제거·형태소 분석은 dense·LLM 경로에서 하지 않고 패딩은 collator가 처리한다. RAG를 포함한 분리형 판정부는 여유 과업이며 통합형 본실험 완료 범위에 넣지 않는다.

## 5. 실행과 산출물의 신원을 연결한다

생성 설정과 채점 규칙의 내용 해시를 나누고 등록 영수증과 실행 시작 기록으로 순서를 증명한다. 영수증·필수값·해시가 맞지 않으면 생성과 본채점을 거부한다. 첫 예측 뒤 변경은 사후 개정으로 기록한다. 생성 규약이 바뀐 뒤 옛 예측을 새 규약의 결과로 사용하지 않는다.

원장과 체크포인트에는 실행 ID, 시드, 조건, 분할·페어·모델·정책 식별자를 결속한다. 다른 신원의 실행을 같은 원장에 이어 쓰지 않는다. 임시 저장 후 재로드·해시를 확인하고 완료 파일을 원자적으로 교체한다. 기존 결과는 덮지 않고 새 판을 만든다. 재개 기능은 실제 지원·검증된 범위에서만 사용한다.

결과표에는 코드 커밋, 설정·스냅샷 해시, 실행 장비·정밀도, 속도 측정 범위와 외부 점유·워커 차이, 실패·중단·재실행 구간을 남긴다. 계산 등가가 검증되지 않은 재개 결과를 같은 조건으로 합산하지 않는다. 회계의 복원·재구성 셀을 실측 셀로 인용하지 않는다.

모델 교환량은 배열 원소 바이트 합이다. 현재 하향은 상향 복사값이고 양방향 회선 바이트는 미측정이다. 이를 실제 네트워크 비용이나 검증된 통신 절감률로 부르지 않는다.

채점·CI·집계는 파일 이름만으로 연결하지 않는다. 시드·입력 해시·채점기 지문·규약 ID·신뢰수준과 점추정이 일치해야 한다. 기존 사전실험의 구간 규약과 2026-10-01 통합형 규약을 구분하며 과거 값을 소급 덮어쓰지 않는다.

## 6. 검토와 보고

설계가 달라지면 채택·보류·폐기 상태, 이유, 적용 시점과 과거 결과에 대한 영향을 기록한다. 분할·좌표·허용치 경계·LoRA 집계·재개·정밀도처럼 결과를 크게 바꿀 수 있는 부분은 대안과 반례를 확인한다. 합의나 시험 통과 건수만으로 방법론이 옳다고 결론내리지 않는다.

M1 검산은 별도 구현으로 수행하며 공유 정규화 입력과 원시 입력 직접 파싱 두 방식을 모두 대조한다. 같은 작성자가 원 구현과 별도 구현을 작성했다면 그 사실을 결과 보고에 적는다. 별도 구현 요건과 원저자가 아닌 쪽의 코드 검수는 다른 절차다. 필요한 사람 검토는 담당·완료 여부를 따로 표시한다.

주장 범위는 확인한 증거에 맞춘다. 공통 eval의 개선을 실제 회사의 운영 이득으로 바꾸지 않는다. 사진 번호만 읽는 대조선을 넘지 못한 분류 결과로 영상 내용 학습을 주장하지 않는다. AI가 생성·검증한 자료의 방법과 한계도 공개한다. 정한 비교가 성립했다면 낮은 점수·손실·실패 역시 결과로 보고한다.

문서는 처음 읽는 사람이 이해할 수 있게 쓴다. 전문 약어는 처음에 정의하고, 같은 정책을 여러 문서에서 독립적으로 고치지 않는다. 세부 규칙의 정본을 한 곳에 두고 다른 문서는 링크한다. 그림은 흰 배경과 평이한 용어를 사용한다. 공개 독자가 접근할 수 없는 내부 일지 번호에 설명을 맡기지 않는다.
