# 연구 규칙 — 연합학습 기반 용접 결함 판정

데이터를 중앙에 모으기 어려운 제조환경을 가정한다.
통합형 VLM의 로컬 단독·중앙집중·연합학습 성능을 비교한다.

대한산업공학회 2026 추계학술대회에 투고한다(초록 10-20, 논문 전문·발표자료 11-10).

## 상세 문서

[실험 설계](실험설계.md)와 [구현 설계](구현설계.md)를 함께 읽는다.
아래 규칙은 연구의 비교 조건이며 모든 실행이 이를 충족했다는 완료 선언은 아니다.

## 실험 구조

| 구분 | 로컬 단독 | 중앙집중 | 연합학습 |
|---|---|---|---|
| 통합형 본실험 | C1·C2·C3별 모델 | 전체 학습 풀로 학습 | 참여자별 어댑터 집계 |
| 분리형 검출기 사전실험 | 완료 | 완료 | 완료 |

분리형 검출기 사전실험은 세 시드 결과를 보존한다.
분리형 판정부의 완료를 뜻하지 않는다.
YOLO와 언어모델 판정부의 연결은 여유 시 과업으로 둔다.

- RQ1: 통합형 연합학습의 성능을 로컬 단독·중앙집중 기준과 비교한다.
- RQ2: 통합형과 분리형의 구조 비교는 본실험 범위에서 제외한다.
- RQ3: C1·C2·C3 각 참여자 역할의 자체 모델과 공동 모델 사이의 성능 변화를 확인한다.

비교 항목은 결함 검출, 위치, 근거 인용, 처리 속도와 모델 교환량이다.
통합형 대표 지표는 미정이다.
회복률의 대표 채택은 지표와 분모·신뢰구간 검증을 거쳐 판단한다.

### 불변조건의 적용 범위

아래의 공통 조건은 해당 모델 구조 안에서 비교하는 학습 방식들에 적용한다.
데이터 격리·분할·고정 예산·last 채점·공통 채점 원칙은 본실험과 사전실험의 각 비교 조건에 적용한다.
모델·프롬프트·검색 설정의 공통 고정은 같은 구조 안의 학습 방식 비교에 적용한다. 프롬프트의 고정 범위에는 채팅 템플릿 모드를 포함하며, 학습과 생성에 실제로 적용되는 모드를 명시한다.
통합형 시드 정책의 현행 적용 범위는 실험설계 6-4절을 따른다.
과거 실행 조건을 새 정책으로 소급해 서술하지 않는다.

# 프로젝트 불변조건

아래 세 절은 이 저장소에서 작업하는 **모든 사람에게 예외 없이 적용된다.**
위반하면 실험의 타당성이나 데이터 이용 조건을 충족하지 못할 수 있다.

## 1. 데이터 취급 규칙

1. **원본 불변.** `data/raw/` 이하는 읽기 전용이다. 어떤 스크립트도 원본을 수정·삭제·덮어쓰지
   않는다. 변환 결과는 항상 새 경로에 쓴다.
2. **매니페스트가 단일 진실.** 학습·평가 코드는 원본 폴더를 직접 읽지 않고 `manifest.csv`만
   읽는다. 매니페스트가 바뀌면 실험 결과가 바뀐 것이다. 분할 확정 후 읽기 전용으로 잠근다.
3. **평가셋은 회사별 분할보다 먼저 뗀다.** 20%, 재질×클래스 층화, 중복 묶음 단위.
   순서가 바뀌면 다섯 칸이 서로 다른 기준으로 채점된다.
4. **평가 자산은 격리.** 평가셋·정답 조항 목록은 어떤 학습 단계에도
   투입하지 않는다. 누출은 곧 논문 철회 사유다.
5. **중복 묶음 단위 분할.** 같은 용접부 연속 촬영이 학습·평가로 갈리면 성능이 부풀려진다.
   중복 신호(연속 촬영 축·파일명 접두사·지각 해시)로 묶고 묶음 ID를 매니페스트에 기록, 분할은 묶음 단위로 한다.
6. **스냅샷 고정.** corpus·페어·색인은 sha256 부여 후 재생성 금지. 해시는 논문에 싣는다.
7. **허용치 CSV가 단일 소스.** 골격 생성기·RAG 청크 메타데이터·채점기 정답 기준 세 곳이
   모두 이 한 파일에서 파생된다. 여기가 어긋나면 판정 정합성 지표가 통째로 무의미해진다.
8. 라벨 문자열을 코드에 하드코딩하지 않는다. 사상표 YAML(원본 라벨 ↔ ISO 6520-1)을 import한다.

## 2. 보안 레드라인

**연구의 서사 자체가 "데이터를 밖으로 내보내지 않는다"이다.** 아래를 어기면 논문의 전제가
스스로 무너진다. 편의를 이유로 예외를 만들지 않는다.

1. **AI허브(71761) 데이터는 국외 반출 금지.** 내국인 신청 한정이며 이용약관에 성과 보고
   의무가 있다. 해외 호스팅 스토리지·해외 리전 클라우드·외부 API에 원본이나 파생 이미지를
   업로드하지 않는다. 발표 전 약관 재확인은 필수 절차다.
2. **원본 이미지를 외부 상용 API에 전송하지 않는다.** 통합형·판정부 학습과 추론은 전부
   로컬 가중치로 수행한다. 상용 VLM API 호출로 라벨·판정문을 만들지 않는다.
3. **외부 클라우드 실험 로깅 금지.** 추적은 MLflow 로컬(sqlite + 파일 artifact)만 쓴다.
   W&B 등 기본이 클라우드 로깅인 도구는 채택하지 않는다 — 비반출 서사와 충돌한다.
4. **상용 API 출력으로 모델을 학습시키지 않는다.** 벤더 약관 위반이다. 합성 생성은 오픈
   가중치 모델 로컬 추론으로 한다.
5. **유료 표준 전문을 corpus·색인에 넣지 않는다.** RAG 색인은 무료 공개 문서만
   (IACS Rec.47, 한국선급 규정 등). ISO 결함 코드 번호·명칭은 사실 정보이므로 라벨 체계로
   쓰는 데 문제없다.
6. 개인 자격증명·로컬 절대경로·GPU 계정 정보는 추적하지 않는 로컬 파일에 두고 커밋하지 않는다.

## 3. 모델·실험 정책

1. **조기 종료 금지.** 전 단계에서 early stopping·patience 기반 중단을 쓰지 않는다.
   학습량 등가(`R × E = N`)가 논문의 공정성 주장이다. Ultralytics는 기본 patience가
   조기 종료로 작동하므로 epoch 수 이상으로 설정해 끈다.
2. **best 체크포인트 금지. last를 채점한다.** best 선택은 val 기준 암묵적 조기 종료다.
3. **다섯 칸 공통 고정:** 기본 모델 체크포인트, 어댑터 설정(r/alpha/target/dropout),
   최적화, 전처리, 프롬프트(한 글자도 다르면 안 됨)와 채팅 템플릿 모드, 검색 설정·top-k, 디코딩, 시드 3세트.
4. **재시도·재프롬프트 금지.** greedy 1회. 스키마 위반 출력은 오답 처리하고 실패율을 별도 보고.
   현재 구현은 이 규칙의 일률적인 오답 처리와 일부 다르다.
   레코드 파싱 실패는 빈 예측으로 채점된다.
   정상 이미지에서 예측과 정답이 모두 공집합이면 Class-Jaccard는 1.0을 부여한다.
   이미지 수준 F1과 BBox-IoU는 정상 이미지의 빈 예측에 오탐 벌점을 부여하지 않는다.
   M1 기본안에서도 정상 이미지의 빈 예측은 TP·FP·FN을 늘리지 않는다.
   따라서 공집합으로 점수를 얻는 경우와 오탐 벌점을 받지 않는 경우를 구분한다.
   동결 평가셋에서 이 처리가 적용될 수 있는 정상 이미지는 5,375장으로 전체의 43.1%다.
   실패율과 실패 사유는 과업 점수와 별도로 보고한다.
   실패 처리의 결합 범위 기본안과 민감도 M1의 정의는 [실험설계](실험설계.md) 8-5절의 실패 처리 설명을 따른다.
   두 안은 팀 결정 전 기본안이다.
   처리 규칙은 통합형 대표 지표 등록 전에 확정한다(실험설계 8-5절).
5. **생성 모델이 자기 결과를 검증하지 않는다.** 검증기는 반드시 다른 계열 모델.
6. **합성 검증 실패분은 재생성하지 않고 폐기한다.** 통과율을 기록해 논문에 싣는다.
7. **다섯 칸 출력을 공통 JSON 스키마로 변환한 뒤 단일 채점기로 채점한다.** 칸마다 채점
   코드를 따로 짜면 공정성 주장이 무너진다.
8. bbox는 원본 픽셀로 저장하고, 학습용 변환·채점용 역변환을 각각 함수로 둔다. 학습 타깃은
   채택 모델의 네이티브 좌표계를 따른다(0~1000 정규화 통일이 아니다).
9. CPT(추가 사전학습) **미수행** — 원문 규모가 CPT 요구치에 두 자릿수 미달. SFT + RAG 집중.
   현행 본실험에서는 통합형 SFT를 다룬다. RAG를 포함한 분리형 과업은 시간 여유가 있을 때 검토하며, 통합형 본실험에 포함된 것으로 읽지 않는다.
10. 불용어 제거·형태소 분석은 하지 않는다. 패딩은 collator가 처리한다.

## 스택

- Python 3.11 (uv로 고정 — 시스템 PATH의 3.14는 쓰지 않는다) / PyTorch 2.x
- 설정은 YAML + OmegaConf / 시드 전역 고정, cudnn.deterministic
- 검출: YOLO11s (AGPL — 사업화 시 Apache 계열 전환 전제)
- 통합형·판정부: Qwen3.5 4B QLoRA (동일 체크포인트 공유)
- 합성 생성: 오픈 가중치 로컬 추론(transformers; sm_120/cu128 충돌과 Windows 미지원 때문에 이 환경에서는 vLLM을 사용하지 않음) / 검증: Gemma·DeepSeek 등 **다른 계열**
- 연합: Flower 시뮬레이션 (Ray, GPU 1장, VLM은 동시성 1)
- 추적: MLflow 로컬 / 저장: jsonl·parquet + sha256 (RDB 불필요)

## 설계 대안 비교와 반례 확인이 필요한 구간

아래는 한 번에 정답이 나오지 않아 시행착오가 예상되는 구간이다. 착수 전에 해당 여부를
먼저 확인하고, 해당하면 단일 접근으로 밀지 않는다. 서로 다른 설계안을 세운 뒤
서로의 약점과 반례를 짚어 무너뜨려 보고 살아남은 안을 채택한다.

정답이 있는 입력에서 64-bit pHash의 과병합은 28,304쌍 대 112쌍으로 나타났다.
중복 제거 규칙은 여러 설계의 반례와 정답 일치 여부를 비교해야 한다.

| 번호 | 구간 | 확인할 위험 |
|---|---|---|
| 1 | Ultralytics와 Flower 결합 | 자체 저장·재개 로직과 Flower의 매개변수 주입이 충돌하므로 학습기 동작을 조정하는 연결 구현이 필요하다 |
| 2 | 배치 정규화의 연합 평균 | 전역 모델 1개를 공통 평가셋으로 채점하는 설계에서는 FedBN을 사용할 수 없다. 강재와 알루미늄의 분포 차이로 결과가 흔들릴 수 있다 |
| 3 | LoRA 어댑터 집계 | `avg(B)·avg(A) ≠ avg(B·A)`이므로 PEFT 상태 사전의 교환·병합 시점을 확인한다 |
| 4 | 시각언어모델의 경계 상자 좌표계 | Qwen2-VL은 0~1000 정규화, Qwen2.5-VL은 절대 픽셀이다. 학습 정답·생성 출력·채점 좌표계의 일치를 확인한다. `ABS_ORIG` 규약의 근거인 합성 도형 4장 제로샷 검사는 0~1000 정규화 배제까지만 뒷받침한다. 시험한 크기에서는 리사이즈 전후 크기가 같아 원본·리사이즈 좌표 프레임을 구별하지 못했고, 미세조정 후 거동은 미측정이다. 본실험 이미지 62,308장은 모두 1280×720이며 프로세서는 이를 1280×704로 줄인다. 본실험 착수 전에 좌표 프레임을 재확인한다. 선행연구의 0.055→0.938을 생성 좌표계 불일치의 근거로 사용하지 않는다 |
