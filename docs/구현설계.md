# 용접 결함 판정 연구 · 구현 설계

작성 2026-08-14 · 실험 종합 보고서(v2)의 구현 편 · 소요 시간은 배제하고 구현 방안만 다룬다

> **현행 구성.** 본실험은 통합형 시각-언어 모델 하나(Qwen3.5 4B, 4비트 QLoRA)를 로컬 단독(C1 · C2 · C3) ·
> 중앙집중 · 연합의 세 방식으로 학습해 시드마다 모델 다섯을 얻는다. 학습 예산은 N = E = R = 1(연합은 한 번
> 집계), 평가는 동결 평가셋의 묶음 단위 층화 표본(명목 3,000장), 평가 생성 한도는 512 토큰이다. 분리형
> 검출기(YOLO11s)의 세 학습 조건은 마친 사전실험이고, 분리형 판정부(규정 검색)는 여유 시 과업이다.
> 확정 수치의 정본은 `configs/`(`base.yaml` · `train_registration.yaml` · `eval_registration.yaml`)이며 이 문서의
> 수치가 그와 다르면 configs 가 맞다. 옛 설계의 값은 각 절의 "이전 설계 기록"에 남긴다.

이 문서는 설계를 코드로 옮길 때 필요한 결정을 적는다. 각 절은 채택안, 대안과 근거, 선행 사례 순으로 구성했다. 항목별 정리표는 별도 엑셀(구현설계_실무정리_260814.xlsx)에 있다.

# 1. 전체 구성

## 1-1. 언어·환경

| 항목 | 채택 | 비고 |
|---|---|---|
| 언어 | Python 3.11 | 전 구간 단일 언어 |
| 프레임워크 | PyTorch 2.x + CUDA 12.x | 검출·VLM·LLM 공통 |
| 패키지 관리 | uv — Python 3.11 고정, `pyproject.toml` · `uv.lock` | 잠금 파일을 저장소에 커밋 |
| 설정 관리 | YAML 단일 파일 + OmegaConf | 조건별 설정은 base.yaml 상속 + 차이만 override |
| 시드 | random, numpy, torch, cuda 모두 고정. cudnn.deterministic=True | 시드 값은 설정 파일에 기록 |

설정 관리에 Hydra를 쓰는 것이 요즘 연구 코드의 일반형이지만, 비교 조건이 고정되어 있고 스윕이 없으므로 OmegaConf 수준이면 충분하다. 도구를 늘릴 이유가 없다.

│   ├── ingest/         # AI허브 압축 해제·JSON 파싱

│   ├── dedup/          # pHash 중복 묶음

├── corpus/

## 1-3. 단일 진실 소스 원칙

모든 학습·평가 코드는 원본 폴더를 직접 읽지 않고 매니페스트를 읽는다.

- `manifest.csv`: 이미지 경로, sha256, 원본 라벨, ISO 코드, split(train/val/eval), client(C1/C2/C3), 중복 묶음 ID
- 텍스트 자산은 jsonl + 스냅샷 해시 파일(`SNAPSHOT.sha256`)
- 매니페스트가 바뀌면 실험 결과가 바뀐 것이다. 분할 확정 후에는 읽기 전용으로 잠근다

### 평가 정답을 적재하지 않는 판독기

매니페스트와 주석은 검증된 스냅샷 로더(`data.manifest_io.load_snapshot()`)로만 읽는다는 매니페스트 계약(계약 #2)은 그대로다.
`pandas.read_csv` 직접 호출의 **예외는 `data/manifest_view.py`의 네 함수뿐이다.**
넷 다 `verify_snapshot()` 을 먼저 부르고, 로더와 같은 자료형 규칙을 쓴다. 이 절이 그 예외의 정본이고, 동결 스냅샷 폴더의 README 는 이 절을 가리킨다.

| 함수 | 읽는 것 | 막는 것 |
|---|---|---|
| `read_manifest_columns(root, columns, *, split_filter)` | 고른 분할의 행에서 고른 열만 | 평가 행에서는 `image_id` · `split` · `sha256` · `group_id` 넷만 읽는다. 그 밖의 열을 평가 행에 대해 요구하면 파일을 열기 전에 거부한다. 층(`strata_key`)은 train·val 행에서만 읽는다 |
| `read_annotations_view(root, ids)` | 준 `image_id` 집합의 주석 행만 | 집합에 평가 id 나 매니페스트에 없는 id 가 있으면 주석 파일을 열기 전에 거부한다. 흡수 곁파일은 열지 않는다 |
| `read_annotations_view_eval(root, ids, *, receipt)` | **본채점 엄격 경로 전용.** 준 **평가** id 의 주석 행만 | id 집합이 비어 있지 않음 · 영수증(파일 경로)의 종류가 `main`(이 함수가 평가 쪽 파싱보다 먼저 본다) · 그 커밋이 `refs/heads/main` 의 조상 · 그 커밋의 등록이 생성·채점 두 쪽 모두 영수증과 맞고 목적 `main`·기준 분할 `eval` · 등록의 지문과 검증한 지문이 **영수증 커밋의** `configs/base.yaml` 닻(`git show`)과 같음 · id 가 전부 평가 id — 하나라도 어기면 주석 파일을 열기 전에 거부한다. 작업 트리의 설정은 읽지 않는다. 영수증 파일은 한 번 읽고 그 바이트로 해시와 파싱을 함께 한다. 거부든 허용이든 호출마다 `outputs/eval_truth_view/calls.jsonl` 에 한 줄(시각 · 부른 곳 · 영수증 해시 · 집합 해시 · 결과)을 남기고, 허용 호출은 기록을 쓴 뒤에 읽는다 |
| `read_image_paths_eval(root, ids, *, receipt)` | **본실험 export 의 엄격 경로 전용.** 준 **평가** id 의 `image_id` · `rel_path` 만 | 셋째와 **같은 조건 검사**를 지난다 — 하나라도 어기면 경로 열을 읽기 전에 거부한다. 평가 행의 식별자 넷 밖의 다른 열은 여전히 막는다(경로 하나만 연다). 호출 기록은 셋째와 같은 파일에 `view` 칸으로 갈라 남긴다 |

평가 정답에 닿으면 안 되는 쪽(리허설 · 프레임 진단 · 본채점의 탐색 경로)은 앞의 둘로만 읽는다. 평가 정답은 본채점의 엄격 경로가 셋째로만 읽고, 평가 이미지의 경로는 본실험 export 의 엄격 경로가 넷째로만 읽는다. 파일의 바이트는 검증과 칸 나누기로 모두 지나간다 —
막는 것은 평가 행의 금지 칸과 준 집합 밖 주석 행을 **값으로 만드는 것**이다. 어느 지문이 승인된 스냅샷인지는 판독기가 정하지 않는다 —
네 함수는 검증한 지문을 결과(`attrs["snapshot_digest"]`)에 싣고(셋째 · 넷째는 닻과의 대조까지 스스로 한다), 부르는 쪽이 `configs/base.yaml` 의 `fixed_before_main_runs.snapshot_digest` 와
**반환 직후, 프레임에 어떤 연산도 하기 전에** 맞댄다. `attrs` 는 pandas 연산을 지나며 이어진다는 보장이 없다.

이 예외가 지키지 못하는 것도 적는다.

- **정적 시험이 막는 것은 실수다.** 판독기 모듈의 시험은 구문 트리의 이름을 본다 — 전체 로더 함수, 흡수 모듈, 파일을 직접 여는 이름
  (`read_csv` · `read_text` · `open` 등, `open` 은 파일을 여는 세 자리 — CSV · 영수증 · 호출 기록 — 만 허용), 동적 접근(`getattr` · `importlib` · `eval` 등)이 없어야 한다.
  문자열을 조립해 이름을 푸는 **고의의 우회는 이 시험이 보지 못한다** — 그것은 코드 검수의 일이다. 부르는 쪽의 정적 금지도 같은 한계를 갖는다.
- **자료형 규칙은 로더 모듈의 비공개 상수에서 가져온다.** 두 경로가 같은 칸을 같은 값으로 만들게 하는 대가로 결합한다. 그 이름이 바뀌면 판독기는
  import 에서 멈춘다.
- **검증과 읽기 사이에 파일이 바뀌면 검증이 헛돈다.** 로더도 같다. 동결 디렉터리는 읽기 전용이라 실질 위험은 낮다.

# 2. 이미지 파이프라인 (D1)

## 2-1. AI허브 데이터 해제·파싱

AI허브 라벨은 이미지당 JSON이고 결함 영역이 폴리곤 좌표로 들어 있다. 파싱 단계에서 할 일:

1. JSON 스키마를 pydantic 모델로 정의해 필드 누락·좌표 이상(음수, 이미지 밖)을 걸러낸다. 걸러진 건수를 로그로 남긴다
2. 메타데이터(type=VT/RT, material=ST/AL)를 매니페스트 컬럼으로 승격한다
3. 두께·픽셀-mm 스케일 필드의 존재 여부를 이 단계에서 프로그램으로 전수 확인한다 (설명서만 믿지 않는다). 라벨 전수에 두 필드가 없다 — 그래서 치수 기준 판정은 원리적으로 불가하고 수행하지 않는다([판정생성 가능성](데이터셋_판정생성_가능성.md) 2장)

## 2-2. 폴리곤 → bbox·크기 산출

| 산출물 | 방법 | 라이브러리 |
|---|---|---|
| bbox | 폴리곤 x·y의 min/max | numpy |
| 결함 장축 길이 | 최소 외접 사각형의 긴 변 | cv2.minAreaRect |
| 등가 직경 | 폴리곤 면적에서 √(4A/π) | shapely 또는 cv2.contourArea |

- bbox와 크기는 픽셀 단위로 매니페스트에 저장한다 (원본 값을 덮어쓰지 않는다). 화소당 실치수가 자료에 없어 mm 환산 칸은 두지 않는다
- 픽셀 크기는 같은 이미지 안의 상대 비교에만 쓸 수 있고, mm 로 정한 허용치와 대조하는 데는 쓰지 않는다

#### 이전 설계 기록

스케일이 확인되면 mm 환산을 별도 컬럼으로 더하고, 크기 값을 판정 골격 생성기(4-3)와 판정 gold 의 입력으로 쓰기로 했다. 스케일 필드가 없어 이 경로는 쓰지 않는다.

## 2-3. 중복 제거

같은 용접부 연속 촬영이 학습·평가에 갈라져 들어가는 누수를 막는 단계다.

- 묶음은 세 신호로 만든다 — 파일 내용 해시 일치, 라벨 숫자 식별자의 연속 구간, 지각 해시(256비트 pHash)의 완전 일치(거리 0). 연속 구간은 같은 검사 방식 · 명목 재질 라벨 안에서 식별자가 1씩 이어지는 범위이며, 실제 용접부나 촬영 세션을 확인한 단위가 아니라 대용이다
- 지각 해시에는 양수 임계를 쓰지 않는다. 이 자료에서는 해시 거리가 식별자 묶음의 안팎을 가르지 못했다(`configs/base.yaml` 의 `dedup`)
- 묶음은 union-find로 연결하고 묶음 ID를 매니페스트에 기록
- 분할은 이미지 단위가 아니라 묶음 단위로 한다 (sklearn StratifiedGroupKFold의 group 인자에 묶음 ID를 넣는 방식)

#### 이전 설계 기록

imagehash 의 pHash(64비트) 해밍 거리 8 이내를 같은 묶음으로 판정하고, 관례값인 임계 8 을 표본 100쌍의 육안 점검으로 확정하기로 했다. 지각 해시 거리가 식별자 묶음과 맞지 않아 양수 임계는 채택하지 않았다.

## 2-4. 라벨 통일

- 사상표(원본 라벨 ↔ ISO 6520-1 코드)는 YAML 한 파일로 두고 모든 코드가 이 파일을 import한다. 코드 안에 라벨 문자열을 하드코딩하지 않는다
- 학습 라벨은 원본 5클래스(정상 포함 여부는 검출 프레임 관례에 따름: 검출에서 정상 이미지는 "박스 없음"으로 표현)
- 중간 포맷은 COCO JSON으로 통일하고, YOLO txt는 COCO에서 스크립트로 변환한다. COCO를 기준으로 두면 pycocotools 채점(8장)과 바로 연결된다
- RIAWELC 낯선 데이터 평가용 사상(공통 3클래스)도 같은 YAML에 별도 섹션으로 둔다

## 2-5. 전처리·증강

- 공통: 정상 파노라마는 결함 크롭과 같은 1280×720 타일로 자르고(원본 1장당 1장, `configs/base.yaml` 의 `preprocess.tile`), 밝기 히스토그램 정합의 기준 분포는 학습 풀 49,847장에서 낸 256 구간 히스토그램 하나다(동결 스냅샷의 `histmatch_reference.json`)
- 검출: 입력 해상도 640, letterbox 리사이즈 (Ultralytics 기본과 동일)
- 증강은 검출 프레임 기본값(mosaic, HSV, flip)을 세 조건에 동일 적용한다. 사전실험의 학습 고정값은 `detection/round_runner.py` 의 `FIXED_OVERRIDES` 이며, 증강 확률(mosaic · HSV · flip)은 그 목록에 없어 Ultralytics 기본값을 썼다. mosaic 를 끄는 시점만 목록에 `close_mosaic` = 10 으로 고정했고, 연합 조건도 전역 epoch 기준으로 마지막 10 epoch 에 끈다(`detection/fed_trainer.py`)
- 통합형(VLM)은 증강 없이 프로세서의 리사이즈만 한다(최소 65,536 · 최대 16,777,216 화소, `configs/base.yaml` 의 `uni_processor_kwargs`). 검출과 VLM은 입력 구조가 달라 전처리를 완전히 같게 만들 수 없으므로, "구조 내 동일" 원칙(분리형 세 조건끼리 동일, 통합형 다섯 모델끼리 동일)을 논문에 명시한다
- 방사선 이미지 특성상 색 증강(HSV)은 의미가 없거나 해로울 수 있다(영상은 그레이스케일이다). mosaic+flip 만 켠 설정과의 비교는 하지 않았다

## 2-6. 분할 구현

```
절차 (순서 고정)
 1) 중복 묶음 생성 (2-3)
 2) 글로벌 평가셋 20% 선분리: 재질×클래스 층화, 묶음 단위
 3) 남은 80%를 C1/C2/C3로 분할
    - C3 = RT 명목 재질 라벨 AL 전체 (자연 분할 — 데이터셋의 재질 표기이며 실측 재질이 아니다)
    - C1:C2 = RT 명목 ST 를 2:1로 나누되 Dirichlet 분할(농도 벡터 (1/3, 1/6) — α=0.5, 비율 2:1)로 클래스 편중 부여
 4) manifest.csv 확정, sha256 기록, 읽기 전용 전환
 5) 클래스×클라이언트 분포 히트맵 생성 → 논문 그림
```

Dirichlet 분할은 클래스별로 α=0.5의 Dirichlet 분포에서 클라이언트 비율을 뽑아 배정하는 표준 방식(Hsu et al. 2019에서 제안된 이후 연합학습 non-IID 실험의 관례)을 그대로 구현한다. 함수 하나(입력: 라벨 배열, 클라이언트 수, α, 시드 / 출력: 인덱스 리스트)로 짜고 단위 테스트를 붙인다. flwr-datasets 패키지에 DirichletPartitioner가 있으나 우리는 묶음 단위 제약과 자연 분할(C3)이 섞여 있어 자체 구현이 더 단순하다.

non-IID의 관리는 별도 시스템이 아니라 매니페스트로 한다. 분할 결과가 CSV로 남아 있으므로 어떤 실험이든 같은 분할을 재사용하고, 분포 통계(클라이언트별 클래스 수)는 CSV에서 재계산 가능하다.

# 3. 검출 모델 구현 (분리형 검출기 사전실험 — 세 학습 조건)

## 3-1. 프레임 선택

| 후보 | 라이선스 | 판단 |
|---|---|---|
| Ultralytics YOLO11s | AGPL-3.0 | 채택(사전실험, 파일럿은 YOLO11n). 학습·검증·추론이 한 API로 묶여 구현 비용이 가장 낮다 |
| RT-DETR | Apache-2.0 | 대안 1순위. 트랜스포머 검출기, NMS 불필요. 최근 상승세 |
| YOLOX / MMDetection | Apache-2.0 | 대안. MMDetection은 유연하나 설정 비용이 크다 |

Ultralytics는 AGPL-3.0이다. 제품화에는 코드 공개 의무와 라이선스 조건을 확인해야 하며 RT-DETR 계열이나 상용 라이선스 전환을 대안으로 둔다.

선행 사례: AI허브 71761의 참조 모델이 YOLOv5x-seg이므로 같은 계열의 소형 모델을 쓰면 "참조 모델보다 훨씬 작은 모델에서 어느 수준인가"라는 서사가 자연스럽다. 용접 결함 검출 문헌 다수가 YOLO 계열 개조(attention 추가, 소형 결함 대응)를 다루며, 우리는 검출기 자체를 개조하지 않고 표준 모델을 쓰는 쪽이 통제 실험 목적에 맞는다.

#### 이전 설계 기록

처음 채택안은 같은 계열의 Ultralytics YOLOv8n/s 였다. 라이선스 판단(AGPL-3.0)은 같다.

## 3-2. 학습 설정

- 100 epoch, batch 32, SGD(momentum 0.937), AMP, cosine LR (선행 설정 계승, 종합 보고서 6-3)
- **조기 종료 없음.** Ultralytics 기본 patience=100이 조기 종료로 작동하므로 patience를 epoch 수 이상으로 설정해 끈다. 고정 예산 원칙 때문이며, 설정 파일에 주석으로 이유를 남긴다
- best.pt가 아니라 last.pt를 채점 대상으로 한다. best 선택은 val 성능 기준의 암묵적 조기 종료와 같아서 조건 간 공정성을 해친다. last로 통일하고 val 곡선은 참고로만 로깅한다
- 로컬 조건(분리·로컬)은 같은 설정으로 C1/C2/C3 각 1회, 총 3모델

## 3-3. 연합학습에서의 검출 모델

- 교환 단위: model.state_dict() 전체를 ndarray 리스트로 직렬화 (Flower 표준 방식)
- **BatchNorm 주의.** FedAvg로 BN의 running mean/var까지 평균하면 클라이언트 간 입력 분포가 다를 때(강재 vs 알루미늄) 글로벌 모델 성능이 흔들릴 수 있다. FedBN(BN을 로컬에 남기는 방식)이 알려진 처방이지만, 우리는 글로벌 모델 하나를 글로벌 평가셋으로 채점하는 설계라 로컬 BN을 남길 수 없다. 기본은 BN 포함 전체 평균으로 가되, 이 선택과 근거를 논문에 한 문장으로 명시한다. 결과가 크게 흔들리면 BN 통계만 서버에서 다시 추정하는 보정을 부록 실험으로 둔다 — 재추정의 forward 는 학습 분할(train)로만 하고 평가셋은 쓰지 않는다

# 4. 텍스트·합성 데이터 파이프라인 (D2·D3·D4)

## 4-1. 문서 파싱

- Docling으로 PDF·HWP 변환본을 구조화(제목 계층, 표)한다. 표는 DataFrame으로 나오므로 허용치 표를 CSV로 바로 뽑는다
- Docling이 실패하는 문서(스캔본, 한글 특수 조판)는 pdfplumber + 수작업 보정으로 처리하고, 어떤 문서를 어느 경로로 처리했는지 목록을 남긴다
- 산출물: `corpus/parse/` 아래 문서별 markdown + 표 CSV

## 4-2. 텍스트 전처리

계획 수립 중에 "패딩, stopword 등 기본 전처리"가 언급되었는데, 현재 스택에서는 다음이 맞다.

- **불용어 제거·형태소 분석은 하지 않는다.** BERT 계열 이후의 dense 임베딩과 LLM 토크나이저는 원문 그대로를 전제로 학습되어 있어, 불용어를 빼면 오히려 문맥이 깨진다. 이 전처리는 TF-IDF·BM25 시절의 관례다. (BM25를 하이브리드 검색에 보조로 쓸 경우에만 형태소 분석기 기반 토큰화를 그 경로에 한정 적용한다)
- **패딩은 데이터 전처리가 아니라 학습 시 collator가 처리한다.** transformers의 DataCollator가 배치 내 최장 길이에 맞춰 동적 패딩한다. 미리 패딩해 저장하지 않는다
- 실제로 필요한 전처리: 유니코드 정규화(NFC), 공백·개행 정리, 단위 표기 통일(㎜→mm, ℃→°C 등 변환표), 조항 번호 패턴 정규식 추출(`제?\s*(\d+(\.\d+)*)\s*조?항?` 류), 표 셀의 병합 해제

## 4-3. 규칙 기반 판정 골격 생성기 (핵심 자체 구현)

판정 추론 corpus (c)와 이미지-판정문 페어 D4의 골격은 같은 규칙 엔진에서 나온다. D4 의 학습 타깃은 그 골격의 구조화 출력(defects · verdict · cited_clauses)이며 LLM 을 거치지 않는다. (c)에서는 LLM이 문장 표현만 담당하고 수치·논리는 전부 규칙이 만든다.

```
입력 테이블 (허용치 CSV — 공개 규정 문서에서 한 사람이 옮겨 적고 Docling 추출과 대조한 판. 사람의 이중 검수는 거치지 않았다)
  defect_code, thickness_min, thickness_max, quality_level,
  limit_type(길이/직경/비율), limit_value, unit, clause_id, source_doc

생성 절차
 1) 실존 조합 열거: (결함코드 × 두께구간 × 품질수준) 중 표에 행이 있는 것만
 2) 수치 샘플링: 합격 40% / 불합격 40% / 경계(허용치 ±10%) 20%
 3) 골격 JSON 생성:
    {defect_code, size_mm, thickness_mm, quality_level,
     clause_id, limit_value, verdict, margin}
 4) LLM 표현 변주: 골격을 프롬프트에 넣고 "수치와 조항 번호를 바꾸지 말 것"
    제약으로 자연문 생성
 5) 수치 잠금 검증: 생성문에서 정규식으로 수치·조항 번호를 재추출해
    골격과 대조. 불일치는 폐기 (재생성하지 않고 버린다. 통과율 기록)
```

- 경계 사례 20%를 명시적으로 넣는 이유: 무작위 샘플링만 하면 허용치 근처 사례가 희박해져, 모델이 대소 비교를 배우지 못한다
- D4(실이미지 페어)는 수치 샘플링을 하지 않는다. 실제 이미지 라벨의 결함 종류 · 원본 픽셀 상자와 결함 종류별 적용 조항 후보만 쓰고, 두께 · 실치수 · 합부는 만들지 않는다(합부 칸은 "판정불가"). 두께와 화소당 실치수가 자료에 없어 치수 기준 판정은 원리적으로 불가하다. 수치 샘플링과 합부는 실이미지와 묶이지 않는 판정 추론 corpus (c)에만 있다
- 골격 생성기는 순수 함수로 짜고 단위 테스트(부등식 경계, 조합 누락)를 붙인다. 이 코드가 틀리면 corpus 1만 건이 통째로 오염된다

## 4-4. LLM 생성: 실행과 모델

- **실행: 오픈 가중치 모델을 로컬 가중치로 transformers 에서 돌린다.** 국내 리전 클라우드의 GPU 에서 실행하고 외부 API 는 쓰지 않는다. 생성 · 판정 모델과 설정의 정본은 `configs/corpus_production.json` 이다
- **생성 모델: Qwen2.5-7B-Instruct**(같은 파일의 `generation`). 상용 API 출력으로 타 모델을 학습시키는 것을 약관으로 금지하는 벤더가 있어, 오픈 모델 로컬 생성이 라이선스가 깨끗하고 논문에 "생성 모델 명시"가 가능하다
- **판정 모델은 생성 모델과 다른 계열로 둔다 — Phi-4-mini-instruct**(같은 파일의 `judge`). 자기검증 금지 원칙의 구현이다
- 영상 설명문(통합형의 학습 타깃이 아니다)은 정상 행을 고정 템플릿으로 만들어 생성 모델을 부르지 않고, 결함 행만 생성 모델이 관찰 문장을 쓴 뒤 렌더러가 고정 제한 문장을 붙인다
- 프레임워크: (b) 질의응답은 원문의 사용 권리가 정해진 뒤 생성하며, 생성하면 자체 프롬프트 스크립트가 기본이다. distilabel(Argilla)도 파이프라인 관리가 필요해지면 대안이지만, 이 규모에서는 jsonl 스크립트로 충분하다

선행 사례: 도메인 특화 LLM 구축에서 "문서 파싱 → 구절 → LLM 질문 생성 → LLM 심판 필터"가 표준 흐름으로 자리 잡았고(IBM Granite의 Docling 기반 합성 QA, Red Hat SDG Hub 등), 우리 (b)가 정확히 이 형태다. (c)처럼 수치 추론이 걸린 데이터는 규칙 골격 + 표현 변주라는 hybrid가 관례이며, 수학·표 추론 합성 데이터 연구들이 같은 이유(수치 환각 방지)로 이 구조를 쓴다.

#### 이전 설계 기록

처음에는 vLLM 으로 로컬 OpenAI 호환 서버를 띄우고 openai 클라이언트로 부르는 구성, Qwen2.5-32B/72B-Instruct 급 생성 모델, Llama-3.x 계열 검증 모델을 후보로 두었다. vLLM 은 개발 장비(sm_120 · Windows)에서 쓸 수 없어 채택하지 않았다. (b) 질의응답에서는 Docling-SDG 의 표본 100건을 보고 채택 여부를 정하기로 했었다.

# 5. RAG 구현 (분리형 판정부)

> 분리형 판정부는 본실험 범위 밖의 여유 시 과업이다. 통합형 본실험에는 규정 검색이 없다. 실이미지에는 두께가
> 없어 아래 질의의 두께 키는 비고, 판정부를 돌려도 출력은 근거 조항과 기준 서술까지다(합부 없음).

## 5-1. 설계의 성격을 먼저 분명히

우리 검색은 자연어 유사도 검색이 아니라 **메타데이터 필터가 1차, 벡터 유사도는 보조**다. 질의가 구조화 키 {결함 코드, 크기, 두께, 품질 수준}이므로, 조항 청크의 메타데이터(결함 코드, 두께 범위, 품질 수준)와의 정확 매칭·범위 매칭으로 후보를 좁힌 뒤, 후보가 복수일 때만 dense 유사도로 top-3을 정렬한다. 사실상 구조화 lookup에 가깝고, 그래서 조항 top-1 정확도가 높게 나와야 정상이며 낮으면 색인 구축 오류를 먼저 의심한다.

## 5-2. 청크 스키마

```json
{
  "chunk_id": "IACS47-3.2.1",
  "doc": "IACS Rec.47",
  "clause_id": "3.2.1",
  "defect_codes": ["2011", "2012"],
  "thickness_min": 8, "thickness_max": 25,
  "quality_levels": ["B", "C"],
  "text": "...조항 재서술 또는 무료 공개 원문...",
  "source_page": 14
}
```

- 청킹은 Docling의 제목 계층으로 조항 경계를 잡는다. 고정 길이 분할은 쓰지 않는다.
- 메타데이터 필드는 골격 생성기의 허용치 CSV와 같은 소스에서 나온다. 두 곳이 어긋나면 판정 정합성 지표가 무의미해지므로, 허용치 CSV를 단일 소스로 두고 청크 메타데이터를 그로부터 생성한다

## 5-3. 임베딩·벡터 저장

| 항목 | 채택 | 대안 | 판단 근거 |
|---|---|---|---|
| 임베딩 | BGE-M3 | KURE-v1 (BGE-M3 한국어 파인튜닝), multilingual-e5-large, Qwen3-Embedding | BGE-M3는 MIT 라이선스에 dense+sparse 동시 지원, 한국어 벤치마크 상위. KURE-v1은 한국어 실사용 보고가 좋으나 dense 전용. 최종 선택은 자체 검증(아래)으로 |
| 벡터 저장 | FAISS (IndexFlatIP) 또는 Chroma | Qdrant, Milvus, pgvector | 청크가 수백~수천 개 규모라 flat 인덱스 전수 검색으로 충분. 서버형 벡터 DB는 과잉이다. 메타데이터 필터가 필요하므로 Chroma(필터 내장)가 코드가 짧고, FAISS면 필터를 pandas로 선행하면 된다 |
| 하이브리드 | 선택 | rank_bm25 | 구조화 질의라 필요성이 낮다. 임베딩 검증에서 dense 단독 top-1이 기준 미달일 때만 추가 |

임베딩 모델 선택 절차: 정답 조항 목록에서 질의 100건(결함코드+두께+품질수준 → 정답 청크)을 만들어 후보 모델별 top-1/top-3을 직접 잰다. 벤치마크 순위가 아니라 우리 문서에서의 성능으로 정한다. 임베딩은 재학습하지 않고 고정한다.

## 5-4. 판정부 파이프라인

```
검출 결과 JSON → 질의 키 구성 → 메타 필터 → (복수 시) dense top-3
 → 프롬프트: [검출 결과 + 검색 조항 3건] → LLM(기본 모델. 공통 출발점을 두면 그 학습본 · greedy)
 → 판정문 JSON 출력 → 채점기
```

- 프롬프트 템플릿은 파일로 고정하고 스냅샷 해시에 포함한다
- 검색 결과가 0건이면 "해당 조항 없음"을 출력하도록 프롬프트에 명시한다 (환각으로 채우는 것을 방지)

# 6. 미세조정 구현

## 6-1. 스택

| 용도 | 채택 | 대안 | 트렌드 비고 |
|---|---|---|---|
| LLM QLoRA | transformers + PEFT + bitsandbytes + TRL SFTTrainer | LLaMA-Factory (YAML 설정 기반, 재현 관리 편함), Axolotl | 공통 출발점(배경지식 학습)을 둘 때의 스택이다. TRL 직접 사용이 통제력이 가장 높다 |
| VLM QLoRA | transformers + PEFT + bitsandbytes(4비트 nf4) — Qwen3.5 4B(`Qwen/Qwen3.5-4B`, 판 고정) | Unsloth FastVisionModel, LLaMA-Factory VLM 지원 | 통합형 다섯 모델이 같은 스택을 쓴다. Unsloth 는 쓰지 않는다 |
| 추론(평가 시) | transformers generate — 탐욕 생성 1회, 생성 한도 512 토큰 | vLLM | 평가 표본(명목 3,000장) × 다섯 모델. vLLM 은 개발 장비(sm_120 · Windows)에서 쓸 수 없어 채택하지 않았다 |

#### 이전 설계 기록

통합형은 Qwen2.5-VL 공식 예제 경로로 미세조정하고, 평가 추론은 vLLM 으로 판정문 채점 표본 2,000건 × 다섯 칸을 돌리기로 했다.

## 6-2. 하이퍼파라미터

확정값은 configs/에만 존재하고 문서에는 "configs 참조"로 링크한다 (문서와 코드의 이중 관리 방지). 통합형 본학습의 정본은 `configs/train_registration.yaml` 이다.

| 단계 | 대상 | r / alpha | LR | 유효 배치 | epoch | 조기 종료 |
|---|---|---|---|---|---|---|
| 통합형 본학습 (D4 구조화 출력) | VLM | 16 / 32 | 1e-4 | 32 (마이크로 배치 1 × 기울기 누적 32) | 1 (N = E = R = 1) | 없음 |

공통 출발점(배경지식 학습)을 둘지는 정하지 않았다. 둔다면 지시 학습(QA)과 추론 학습(판정)의 값은 아래 이전 설계 기록의 표를 출발점으로 다시 정한다. 추가 사전학습(CPT)은 하지 않는다 — 원문 규모가 요구 수준에 크게 못 미친다.

- **조기 종료는 전 단계에서 쓰지 않는다.** 이유는 검출과 같다: 다섯 모델의 학습량 등가(R×E=N)가 논문의 공정성 주장인데, 조기 종료는 모델마다 다른 학습량을 만든다. val loss는 로깅만 하고 개입하지 않는다
- 대상 모듈: 언어부의 12종 — 전체 어텐션의 q · k · v · o, 선형 어텐션의 in_proj_qkv · in_proj_z · in_proj_a · in_proj_b · out_proj, MLP 의 gate · up · down(감싼 선형층 248개, 어댑터 매개변수 32,464,896개). dropout 0. 시각 인코더는 대상이 아니다(어댑터 크기와 통신량을 줄인다)
- 패킹(sample packing)은 쓰지 않는다. 속도 이점보다 "노출 횟수 등가" 계산의 단순함을 택한다

#### 이전 설계 기록

파일럿 전 초기값으로 둔 표다. 대상 레이어는 attention q,k,v,o + MLP(PEFT `target_modules="all-linear"`)로, max_seq_length 는 QA 1,024 / 추론 · 판정문 2,048(초과 샘플은 폐기 후 건수 보고)로 잡았다.

| 단계 | 대상 | r / alpha | LR | 유효 배치 | epoch | 조기 종료 |
|---|---|---|---|---|---|---|
| (선택) 추가 사전학습 | LLM·VLM 언어부 | 128 / 256 | 1e-5 | 64 | 1 | 없음 |
| 지시 학습 (QA) | 〃 | 16 / 32 | 2e-4 | 64 (grad accum) | 3 | 없음 |
| 추론 학습 (판정) | 〃 | 16 / 32 | 1e-4 | 64 | 3 | 없음 |
| 통합형 본학습 (D4) | VLM | 16 / 32 | 1e-4 | 32 | 3 | 없음 |

## 6-3. 좌표계

모델 계열마다 좌표 형식이 다르다 — **Qwen2-VL은 0~1000 정규화 좌표로 학습되었고 Qwen2.5-VL은 리사이즈된 이미지의 절대 픽셀 좌표를 쓴다.** 모델 네이티브 좌표계와 다른 형식으로 파인튜닝하면 사전학습된 grounding 능력을 버리고 새로 배우는 셈이 되어 손해다.

- 구현 원칙: **학습 타깃 좌표는 채택 모델의 네이티브 형식을 따른다.** 현행 규약은 원본 이미지의 절대 픽셀 좌표(`ABS_ORIG`, `configs/base.yaml` 의 `uni_coord_space`)다. 본실험 영상의 원본(1280×720)과 프로세서 입력(1280×704)의 크기가 달라, 이 규약이 모델의 네이티브 좌표 프레임과 맞는지는 본실험 착수 전 좌표 점검에서 다시 확인한다. 근거와 그 한계는 실험설계 4-3절을 따른다
- 데이터 파일에는 원본 픽셀 좌표를 저장하고, 학습용 변환·채점용 역변환을 각각 함수로 둔다
- 채점은 원본 이미지 좌표계로 역변환한 뒤 IoU를 계산한다

#### 이전 설계 기록

초기 설계 보고서는 bbox 를 0~1000 정규화로 통일하기로 했다. 선행 연구의 IoU 0.055→0.938 사례를 좌표계 불일치의 교훈으로 읽었으나, 그 값은 정렬 모듈 입력 수치 속성의 인코딩 비교라 생성 좌표계를 정하는 근거로 쓰지 않는다.

# 7. 연합학습 구현 (Flower)

## 7-1. Flower 현재 구조

Flower 1.x의 현행 API는 `flwr new`로 프로젝트를 생성하고 ServerApp·ClientApp 두 진입점을 정의한 뒤 `flwr run`으로 실행하는 구조다. 설정(라운드 수, 로컬 epoch, 배치)은 pyproject.toml의 run-config에 두고 실행 시 override할 수 있다. 시뮬레이션은 Ray 백엔드가 클라이언트 프로세스를 관리하며, 클라이언트당 GPU 지분(예: num_gpus=0.33)을 지정할 수 있다. FedAvg를 포함한 표준 전략(FedProx, FedAvgM 등)이 내장되어 있다.

우리 실행 형태는 **1 GPU 위의 시뮬레이션**이다. 3클라이언트가 물리적으로 분산되어 있지 않으므로, 논문에는 "시뮬레이션 환경이며 통신량은 상향 교환 객체 크기 실측 × 라운드 수 × 참여자 수로 산출하고 하향은 같은 크기로 어림한다"임을 명시한다. VLM처럼 클라이언트 하나가 GPU를 다 쓰는 경우 클라이언트를 순차 실행(동시성 1)으로 돌리면 된다. 시뮬레이션이라 가능한 방식이다.

대안 프레임워크: NVFlare(산업·보안 기능 강함, 무거움), FedML, OpenFL. 연구용 표준은 Flower로 수렴한 상태고, LLM 연합 파인튜닝 벤치마크(FlowerTune)도 Flower 생태계에 있다. 바꿀 이유가 없다.

## 7-2. 검출 FL (분리·연합)

```python
# Client 측 핵심 (개념 코드)
get_parameters: model.state_dict() → [ndarray]   # BN 통계 포함
fit: set_parameters → E epoch 로컬 학습 → get_parameters, len(train_set) 반환
# Server 측
strategy = FedAvg(가중 = 클라이언트 표본 수)      # 각 참여자의 학습 표본 수(매니페스트의 train 행)
```

- Ultralytics 결합 지점: trainer를 epoch 단위로 호출할 수 있도록 래핑하거나, model.model(내부 nn.Module)의 state_dict를 직접 다룬다. Ultralytics의 자체 저장·재개 로직과 Flower의 파라미터 주입이 충돌하지 않게, 학습 루프를 커스텀 트레이너로 한 겹 감싼다
- R×E=N: R=50 · E=2 · N=100(`configs/base.yaml` 의 `train_budget`). optimizer 상태(momentum)는 라운드마다 리셋됨을 인지하고 명시 (FedAvg 표준 동작)

## 7-3. VLM FL (통합·연합)

- 교환 단위: PEFT의 `get_peft_model_state_dict()` 결과(LoRA A·B 행렬)만. 기본 모델은 각 클라이언트에 사전 배포된 동일 체크포인트
- 집계: 행렬별 가중 평균 (avg(A), avg(B)). 가중은 참여자 학습 자료의 감독 토큰 총합이다(`configs/base.yaml` 의 `uni_expected_supervised_tokens`) — 학습 손실을 감독 토큰 총합으로 정규화하므로 같은 단위로 가중해야 연합의 목적함수가 중앙집중과 맞는다. avg(B)·avg(A) ≠ avg(B·A) 문제는 논문에 명시하고 집계 라운드에서 상대 오차를 재서 부록에 싣는다. 여유가 있으면 갱신량(ΔW) 평균 방식(FLoRA 계열)과 비교한다
- 라운드 흐름: 서버가 어댑터 배포 → 클라이언트가 기본 모델에 로드 후 로컬 학습 → 어댑터만 반환. 본실험은 한 라운드(R = 1)다. 병합(merge)은 하지 않는다. 평가는 학습과 같은 4비트 기본 모델에 최종 어댑터(`adapter_last.npz`)를 병합하지 않은 채 주입해 생성한다(`vlm/export_model.py`)
- 통신량 실측: 참여자가 올려 보낸 배열 원소의 바이트 합을 라운드마다 로깅한다(직렬화 헤더 · 전송 계층 부가량은 넣지 않는다). 어댑터 한 벌은 fp32 로 129,859,584 바이트(약 130 MB — 매개변수 수에서 계산한 실행 전 어림, 논문 6.6절)이고, 검출 모델 전체 가중치(사전실험 원장의 실측)와의 대비가 결과 표에 들어간다

선행 사례: LoRA 어댑터만 FedAvg로 교환하는 연합 지시 튜닝(FedIT 계열)이 확립된 패턴이고, 4bit 고정 기본 모델 + 어댑터 교환 구성의 구현 보고도 다수다. 우리 통합·연합 모델은 이 패턴의 VLM 적용이다.

#### 이전 설계 기록

어댑터(r=16, 언어부만)를 라운드당 수십 MB 로 어림하고, 검출 쪽은 YOLOv8n fp32 기준 약 12MB 와 견주기로 했다. 최종 라운드 뒤 어댑터를 한 번 병합해 평가용 체크포인트를 만들기로 했으나, 평가는 병합하지 않은 어댑터를 주입해 생성한다.

## 7-4. 라운드 관리

- 라운드마다: 글로벌 파라미터 저장(마일스톤 라운드만 보존, 아래 10-2), **`val` 지표**를
  서버 사이드 evaluate 콜백에서 산출해 MLflow에 round=step으로 로깅
- **`val`은 학습 풀의 10%**(묶음 단위·층화, 로깅 전용)이며 **글로벌 평가셋이 아니다.**
  글로벌 평가셋은 전 실험을 통틀어 **최종 채점 1회만** 접근한다. 조기 종료를 쓰지 않고
  last를 채점하므로 라운드별 곡선에는 선택압이 없다 — 그럼에도 두 집합을 분리해 두는 것은
  "평가셋이 학습·선택에 영향을 주지 않는다"는 주장을 문구 수준에서까지 방어하기 위해서다
- 클라이언트 로컬 체크포인트는 저장하지 않는다 (시드+분할+설정으로 재현 가능)
- **`accept_failures=False`.** Flower FedAvg 기본값(`True`)은 클라이언트가 라운드 중 실패해도
  나머지로 집계를 진행해, 실효 학습량이 줄어든 사실이 지표에 남지 않는다. `R × E = N` 등가가
  조용히 깨지는 경로이므로 금지한다. 실패 시 라운드를 중단하고 사람이 개입한다
- **클라이언트 × 라운드 회계 매트릭스**를 정식 산출물로 남긴다. 라운드별 각 클라이언트의
  참여 여부·로컬 스텝 수·표본 수를 기록하고 종료 시 `R × E = N`을 실측 검증한다.
  총 갱신 횟수는 이 실측치를 논문에 싣는다 — **단 `optimizer_updates` 는 갱신 시도 수다**
  (2026-09-16, 34번 §3-1 8-3). AMP `GradScaler` 가 inf/NaN 기울기에서 `optimizer.step()` 을
  건너뛴 시도도 세기 때문이다. 실제 적용 수(`optimizer_updates_applied`)는 ②③ 의 meta.json 에
  남고 회계 열·원자 로그 지표는 늘리지 않았다(D 계약 조율 뒤 별건). 세 시드 사전실험(분리·연합) 값
  71,202 는 시도 수이며 적용 수는 미계측이다 — 논문은 적용 수가 있는 실행에서만 그 이름을 쓴다
- 실패 복구: 라운드 단위 재시작이 가능하도록 서버가 최신 글로벌 파라미터를 항상 디스크에 남긴다

# 8. 평가 구현

## 8-1. 공통 채점기 원칙

다섯 모델(사전실험은 세 조건)의 출력을 전부 **공통 예측 JSON 스키마로 변환한 뒤 단일 채점기**로 채점한다. 조건마다 채점 코드를 따로 짜면 공정성 주장이 무너진다. 스키마의 정본은 사전실험(분리형 세 조건)이 `evaluation/schema.py`(1.3판), 통합형 본실험 다섯 모델이 `evaluation/schema_v14.py`(1.4판)다. 1.4판은 생성 종료 사유와 좌표 규약을 필수로 싣는다.

```json
{"image_id": "...", "defects": [{"iso_code": "2011", "bbox_px": [x1,y1,x2,y2]}],
  "verdict": "판정불가", "cited_clauses": ["IACS47-3.2.1"], "parse_ok": true}
```

실이미지에는 판 두께와 화소당 실치수가 없어 결함의 `size_mm` 은 비고 `verdict` 는 "판정불가"다.

- 분리형: 검출 출력(판정부를 돌리면 그 출력까지)을 이 스키마로 조립
- 통합형: 생성 텍스트를 파싱한다. JSON 이 읽히지 않거나 잘렸거나 `defects` 가 목록이 아니면 레코드 실패(parse_ok=false)로 기록하고 빈 예측으로 채점한다. 판정 · 인용 칸만 어긋나면 상자는 채점하고 조항 축에서만 실패로 센다(결합 규칙 `decoupled_v2`). 깨진 결함 항목은 그 항목만 버리고 폐기 수를 따로 센다. 레코드 실패의 경우 M1 에서는 결함 이미지의 정답 상자가 모두 미탐이 되고 정상 이미지에는 계수가 생기지 않는다. 파싱 실패가 모든 지표에서 0점이 되지는 않는다 — 정상 이미지에서 예측과 정답이 모두 공집합이면 Class-Jaccard 는 1 을 주고, 이미지 수준 F1 · BBox-IoU 는 정상 이미지의 빈 예측에 오탐 벌점을 주지 않는다(실험설계 8-5). 민감도 채점은 실패 레코드마다 평가 클래스별 오탐 1 을 더한다(`configs/eval_registration.yaml` 의 `sensitivity_variant`). 구현이 등록 규칙과 다르면 등록 규칙이 정본이다. 재시도·재프롬프트 없음 (greedy 1회 원칙). 실패율은 따로 보고한다

## 8-2. 지표별 산출 방법과 자동화 수준

| 지표 | 산출 | 자동화 수준 |
|---|---|---|
| M1 (본실험 대표 지표) | 클래스가 일치하는 상자를 IoU 0.5 로 짝지은 F1 의 네 결함 매크로 평균. 표본의 설계 가중 추정과 가중 없는 표본 값을 함께 낸다 | 완전 자동 |
| Macro-F1, 클래스별 P/R, 혼동행렬 | 이미지 수준 결함 유무·종류로 산출 (sklearn) | 완전 자동 |
| 결함 recall (놓침 비율) | 결함 이미지 중 해당 결함을 하나라도 잡은 비율 | 완전 자동 |
| mAP@0.5, 0.5:0.95 | 사전실험 검출기의 지표. COCO 형식 변환 후 pycocotools. 생성 출력에는 상자별 신뢰도가 없어 통합형에는 산출하지 않는다 | 완전 자동 |
| Class-Jaccard | 예측 `defects` 의 결함 코드 집합 ↔ 라벨 집합의 Jaccard | 완전 자동 (JSON 필드 기준) |
| BBox-IoU | 예측 bbox ↔ 라벨 bbox, 좌표 역변환 후 | 완전 자동 |
| 조항 검색 top-1/3 | 검색 로그 ↔ 정답 조항 CSV 대조. 분리형 판정부(여유 시 과업)에만 정의된다 | 완전 자동 (정답 목록 확정 후) |
| 인용 일치율 | cited_clauses ↔ 정답 조항. 사람이 검수하지 않은 허용치 표와의 내부 일치이며 실제 규정 적합성이 아니다 | 완전 자동 |
| 판정 정합성 | 인용 조항의 허용치 CSV 값 + 크기 값으로 부등식 재계산 ↔ verdict. 실이미지에는 두께 · 실치수가 없어 산출하지 않고, 합성 수치에서만 규칙 적용의 일치율로 낸다 | 규칙 기반 자동 (허용치 CSV가 정답 소스) |
| 무근거 인용률 | 1차: 조항 ID가 색인에 실존하는가 (자동). 2차: 실존하지만 무관한 인용은 정답 매핑 대조 (자동) + 경계 사례만 사람 판정 | 자동 + 표본 검수 |
| latency, VRAM | warmup 10회 후 100장 median, batch=1, 동일 GPU, torch.cuda.max_memory_allocated | 완전 자동 (측정 스크립트 고정) |
| 통신량 | 상향으로 보낸 배열 원소의 바이트 합 실측 × 라운드 × 참여자. 하향은 같은 크기로 어림하고 계측값으로 쓰지 않는다 | 완전 자동 |

## 8-3. 사람이 직접 하는 일 (전체 목록)

1. 정답 조항 목록 확정 (결함×두께×품질수준 → 조항). 전문가 확인 필수, 조항 축(인용 일치율 · 무근거 인용률)의 기준이 됨. 지금의 허용치 표는 한 사람이 옮겨 적었고 사람의 이중 검수 전이다. 대표 지표 M1 은 이 목록을 쓰지 않는다
2. corpus · 페어 · 영상 설명문 표본 검수 (검증 3단계의 마지막. 영상 설명문은 층마다 최소 5행 · 전체의 2% — `configs/corpus_production.json` 의 `quality`)
3. 무근거 인용 중 "실존하나 무관" 경계 사례 판정 (표본)
4. 중복 묶음 규칙 · 증강 설정 등 파일럿 결과 눈 확인
5. 판정문 자연스러움 소표본 평가 (보조 지표, 5점 척도, 논문에는 부록) — 판정문을 내는 분리형 판정부를 돌릴 때만 해당한다. 통합형의 출력은 구조화 출력이다

이 다섯 개 외에는 전부 스크립트다. 사람 검수 결과도 시트로 남겨 통과율을 논문에 쓴다.

# 9. 결과를 읽는 기준

결과를 본 뒤에 해석 기준을 만들지 않도록 기준을 먼저 둔다. 본실험의 기준은 등록 규칙이다 — 대표 지표 M1, 회복률을 대표 수치로 올리는 다섯 조건(분모 안정 · 구간 반폭 · 분모 구간 하한 · 미정의 재표집 비율 · 등록 대조선 초과), 화소를 보지 않는 대조선과의 병기. 최소 의미 차이나 허용 손실 같은 문턱은 두지 않는다. 시드가 하나인 결과에서는 분모 안정성을 판정할 수 없어 대표 채택이 미판정이다. 정본은 실험설계 8-5절과 `configs/eval_registration.yaml` 이다.

미달이 곧 실패가 아니라는 원칙을 공유한다. 비교가 성립하는 한, 어느 조건이 어디서 무너지는지 자체가 결과다.

#### 이전 설계 기록

다섯 칸 설계에서 둔 참조점과 기준선이다. 회복 구간과 유지율의 문턱은 근거 문헌이 확인되지 않아 판정 근거로 쓰지 않는다. 참여자별 이득은 지금 RQ2 의 세 참여자 비교(대표 지표의 차이와 구간)로 보고하며 아래의 +5%p 문턱을 쓰지 않는다. 조항 top-1 기준선은 분리형 판정부를 돌릴 때만 해당한다. 판정 정합성 기준선은 실이미지에 두께 · 실치수가 없어 해당하지 않는다 — 합성 수치에서 규칙 적용의 일치율만 낸다(8-2).

| 항목 | 참조점 | 해석 기준선 |
|---|---|---|
| 분리·중앙 검출 | AI허브 참조 모델(YOLOv5x-seg) 공개 성능치. 데이터 설명서에서 확인, 체급 차이(88M vs 3.2M) 명시 | Macro-F1 0.85 이상이면 파이프라인 정상. 미달 시 결과 해석 전에 라벨·분할 오류 먼저 점검 |
| 분리형 회복률 | non-IID FedAvg 문헌에서 통상 85~95% 회복 보고 | 90% 이상 강한 결과, 80~90% 방어 가능, 80% 미만이면 non-IID 심화 효과로 해석 — 근거 문헌이 확인되지 않아 쓰지 않는다 |
| 통합형 유지율 | 어댑터 FedAvg 문헌상 중앙 대비 소폭 하락이 일반적 | 90% 이상이면 통합형도 연합 가능 — 근거 문헌이 확인되지 않아 쓰지 않는다 |
| 통합형 절대 성능 | 선행 연구(WeldLLM)의 Class-Jaccard·BBox-IoU 보고치. 데이터가 달라 직접 비교 아닌 참조점, 제로샷 실측이 하한선 | 제로샷 대비 유의한 향상이 있으면 학습 효과 성립. 분리형에 밀려도 그 자체가 구조 비교(본실험 제외)의 답 |
| C3 참여 편익 | 없음 (자체 비교) | C3의 결함 recall이 로컬 대비 +5%p 이상이면 참여 편익 주장 성립 |
| 조항 top-1 | 없음 (구조화 lookup) | 95% 이상이 정상. 미달 시 색인·메타데이터 구축 오류부터 의심 |
| 판정 정합성 | 없음 | 95% 이상 기대. 미달분은 오류 유형 분해(조항 오검색 vs 대소 비교 실패)로 보고 |

# 10. 실험·모델 관리

## 10-1. MLflow

- 로컬 tracking 서버(sqlite backend + 파일 artifact store)로 충분하다. W&B는 편하지만 기본이 외부 클라우드 로깅이라 "데이터 비반출" 서사와 어긋나 보일 수 있고, 로컬 서버 모드를 쓸 거면 MLflow 대비 이점이 없다
- run 구조: experiment = "weld-fl", run 명명 `{cell}_{seed}_{yymmdd}` (예: `sep_fed_s0_260910`)
- 필수 로깅: config YAML 전체(artifact), git commit hash, manifest·스냅샷 sha256, 지표(FL은 round를 step으로), 학습 곡선, 최종 결과 JSON
- Flower 결합: 서버 evaluate 콜백 안에서 mlflow.log_metrics(round=step) 호출. 클라이언트 쪽은 로깅하지 않는다 (서버 시점 지표로 통일)
- 결과 표(8-6)는 MLflow에서 스크립트로 추출해 생성한다. 손으로 옮겨 적지 않는다

## 10-2. 체크포인트 규칙

| 항목 | 규칙 |
|---|---|
| 명명 | 가중치는 NPZ 배열 파일이다 — 검출 `sep_local_c{k}.npz` · `sep_central.npz`, 연합 서버 `global_r{라운드 세 자리}.npz` · `latest.npz`, 통합형 어댑터 `adapter_last.npz` |
| 보존 | 로컬·중앙: last만. 연합: 최종 + 마일스톤 라운드(25%, 50%, 75%) 글로벌만 — 통합형 본실험은 한 라운드라 최종만 |
| 동반 저장 | 같은 폴더에 config.yaml, 지표 JSON, 생성 코드 commit hash |
| 공통 출발점 | 둘지 정하지 않았다. 두면 배경지식 학습 완료 체크포인트(병합본)를 별도 디렉터리에 동결하고 해시를 기록해 다섯 모델이 모두 이 해시를 로깅한다. 두지 않아도 기본 모델의 판과 해시를 고정하고 다섯 모델의 초기 어댑터가 같은지 대조한다 |
| 용량 추정 | 기본 모델(Qwen3.5 4B) 가중치 파일 9,319,828,096 바이트(safetensors 두 조각), 어댑터 한 벌 129,859,584 바이트(fp32). 검출 모델은 수십 MB라 무시 가능. 로컬 디스크 수백 GB면 충분, 정리 스크립트로 마일스톤 외 자동 삭제 |

- **재개 파일 정리.** `detection/round_runner.train_round`의
  `clear_resume_on_success` 기본값은 **False** 다(종전 True). 학습 함수가 반환 직전에 지우면,
  최종 가중치를 저장하는 호출자와의 사이에서 죽었을 때 **재개 파일도 최종 산출물도 없다**.
  정리는 산출물을 인계받은 쪽이 한다: ②③ 은 `detection/train_cell` 이 NPZ 를 `tmp→os.replace`
  로 쓰고 **재로드해 배열 수·shape·dtype·값을 대조**한 뒤(`meta.json` 의 `weights_file.sha256`)
  `clear_resume`, ④ 는 `fl/client_det.run_client_round` 가 응답 반환 직전(= 서버 인계 시점).
  ④ 의 실효 범위는 **응답 조립 실패 시 재개 파일 보존**까지다 — 직렬화·전송·집계·서버 저장은
  그 뒤 구간이고, 현재 트리에는 라운드 경계 재개가 없어(R 미착지) 그 구간에서 죽으면 라운드
  1 부터 재실행된다. 서버의 라운드 저장(`_save_round`)을 같은 내구 규약으로 올리는 것은 별건.
  최종 산출물이 이미 있는데 재개 파일이 남아 있으면(저장·정리 사이 사망) 다음 실행이 **학습
  전에 그 잔해를 지운다** — 완주 체크포인트는 `validate_detection_resume` 가 거부하므로 그대로
  두면 사람이 지워야 재기동된다. CLI는 `scripts/main_det.py`의 사용법을 따른다.
  `<tag>.meta.json`은 LF 줄끝을 사용하며 `weights_file` 블록을 포함한다.
- **재개 시 loss CSV 보존·병합 규약.** 재개는 상류 `args.resume`를
  쓰지 않으므로 Ultralytics 가 트레이너를 만들 때 같은 save_dir 의 `results.csv` 를 지운다.
  `train_round` 는 재개 상태로 들어오면 **트레이너를 만들기 전에** 그 파일을
  `results.before_resume_<epoch_done>__<run_id>__<시각>.csv` 로 **이름만** 바꾼다(삭제·덮어쓰기 없음,
  `<epoch_done>` 은 0-기반이라 파일 안의 마지막 epoch 보다 1 작다). 보존은 `validate_detection_resume`
  **뒤**에 한다 — 거부될 재개는 파일을 건드리지 않는다. 합치는 일은 학습 경로가 아니라 읽기 전용
  `detection/results_merge.py` 가 파생 테이블로만 한다: epoch 이 겹치면 뒤 조각(재개 뒤)을 채택하고,
  손상 행·읽을 수 없는 조각은 버리되 보고한다. **구판 F03 짧은 행은 오른쪽으로 패딩하지 않는다** —
  마지막 epoch 행은 `metrics/*`·`val/*` 7 열이 가운데에서 빠진 8 열이고 뒤 3 값이 LR 이라, 앞(epoch·
  time·train/*)·뒤(lr/*) 블록으로 되맞추고 가운데를 NaN 으로 둔다. "조기 종료 부재의 증거는
  `results.csv` 행 수" 라는 주장(회계 문서)은 재개한 런에서 **조각을 합친 뒤에만** 성립한다.

#### 이전 설계 기록

체크포인트 명명은 `{cell}_{stage}_{round|epoch}_{seed}.pt` 로, 용량은 VLM 3B fp16 병합본 약 6~7GB × (출발점 1 + 통합형 산출물)로 어림했다. 학습이 내는 가중치 산출물은 NPZ 로 저장한다(위 표).

## 10-3. 연합학습 특유의 관리 사항

- 글로벌 모델만 관리 대상이다. 클라이언트 로컬 상태는 (시드, manifest, config)로 재현되므로 저장하지 않는다
- 라운드별 지표 CSV(라운드, 손실, F1, 통신 바이트)를 MLflow와 별도로 남겨 그림 생성에 직접 쓴다
- 어댑터 집계 직전·직후 파라미터의 norm을 로깅한다. 집계 버그(순서 뒤섞임, dtype 불일치)를 조기에 잡는 저비용 안전장치다
- **원장(원자 로그) 신원 검사와 run_id 정책 접미.** `atomic_log.csv`는 append 전용이라
  첫 데이터 행이 그 파일의 소유자다. 연합 서버(`fl/server_app.main`)·②③ 진입(`detection/train_cell`)·`AtomicLog` 생성자는
  기존 원장의 `run_id`·`seed`·`cell`·`split_hash` 를 새 실행과 대조해 하나라도 다르면 **그 위에 쓰지 않는다**
  (서버는 초기 가중치를 읽기 전에 `LedgerIdentityMismatch` 로 죽는다 — `SystemExit` 는 flwr 두 런타임이
  받지 못해 실패가 기록되지 않는다). ②③ 은 기존 `<tag>.meta.json` 의 `identity` 블록(신판) 또는
  파생 시드·정책(구판)도 대조한다. 난수 정책(`loader-reseed-per-epoch=true`, F01 opt-in)은 원장 열에 없으므로
  run_id 의 stamp 에 접미 `_rs1` 을 붙여 새긴다(`fl.atomic_log.policy_stamp`) — 클라이언트 재개 신원의 `run_id` 도
  같은 값을 받는다. **정책이 꺼진 실행의 run_id 는 종전과 같다**(`sep_fed_s20260828_main_s1`)이고 접미 없는
  옛 원장·meta 는 고치지 않고 그대로 읽는다. 같은 run_id 의 재기동(라운드 경계 재실행)은 통과한다.
  다른 정책·시드·분할의 실행은 별도 출력 경로(또는 다른 run-stamp)로 돌린다
