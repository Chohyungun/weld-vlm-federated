# 구현 설계

이 문서는 자료를 고정하고 통합형 VLM을 학습한 뒤 같은 기준으로 비교하기 위한 코드 구조와 입출력 규칙을 설명한다. 연구 질문과 지표의 해석은 [실험설계](실험설계.md), 변경의 근거는 [의사결정로그](의사결정로그.md), 작업 중 지켜야 할 조건은 [개발규약](개발규약.md)을 함께 읽는다.

2026-10-05 기준으로 통합형 로컬·중앙·연합의 실행기, 생성 결과 내보내기, M1 채점, 등록 영수증과 구간 계산 코드는 존재한다. 실물 리허설은 아직 통과하지 않았고 통합형 본실험 결과도 없다. 아래의 구현 설명을 본실험 완주나 실제 GPU 동작 보증으로 읽지 않는다. 초기 문서의 ‘다섯 칸’은 통합형 두 조건과 분리형 세 조건을 뜻했지만, 현행 본실험은 통합형 로컬 세 모델·중앙·연합의 다섯 모델이다.

## 1. 구성과 실행 환경

```text
configs/      공통 설정, 구조별 설정, 라벨 대응표
data/         원본 파싱 → 좌표 변환 → 묶음 생성 → 분할 → 동결 스냅샷
corpus/       규정 파싱, 허용치 표, 합성 답안 생성·검증
detection/    검출기 사전실험 학습·저장·재개
vlm/          통합형 학습·생성·리허설
fl/           Flower 서버·클라이언트와 집계
rag/          조항 색인·검색·판정부
evaluation/   공통 예측 규약·채점·등록·신뢰구간
tracking/     로컬 실행 추적과 체크포인트 규칙
scripts/      실행 진입점
```

파트 간 연결은 매니페스트, JSONL, 체크포인트와 해시 파일로 한다. Python 3.11을 uv로 고정하며 시스템 PATH의 3.14를 사용하지 않는다. PyTorch 2.x, YAML·OmegaConf, transformers·PEFT·bitsandbytes, Flower를 사용한다. 추적은 로컬 MLflow(sqlite와 파일 artifact)다.

2026-08-17 실측 장비는 RTX 5060 Ti 16GB, compute capability 12.0(`sm_120`), 드라이버 581.08이었다. 해당 환경에서는 cu128 이상이 필요했고 cu121 계열은 동작하지 않았다. 이 날짜의 디스크 여유 약 226GB나 장비 상태를 현재 가용 자원으로 보장하지 않는다. 초기 vLLM 서빙안은 당시 sm_120/cu128 충돌과 Windows 미지원으로 사용할 수 없어 로컬 transformers 경로로 바뀌었다. Linux GPU에서의 재검토는 별도다.

## 2. 입력은 동결 스냅샷으로 읽는다

`data/raw/`는 원본 보관소다. 변환 결과는 새 경로에 쓰고 학습·평가는 원본 폴더를 임의 순회하지 않는다. 매니페스트가 이미지 경로, sha256, 라벨, split, client, group_id를 정한다. 텍스트 자산은 JSONL과 `SNAPSHOT.sha256`으로 관리한다. 분할·자산을 바꾸면 새 판과 새 실험으로 구분한다.

일반 경로는 검증된 `data.manifest_io.load_snapshot()`만 사용한다. 직접 `pandas.read_csv`로 매니페스트나 주석을 읽는 예외는 `data/manifest_view.py`의 다음 네 함수다. 모두 `verify_snapshot()`을 먼저 부르고 기존 로더와 같은 자료형 규칙을 쓴다.

| 함수 | 허용 범위 |
|---|---|
| `read_manifest_columns(root, columns, *, split_filter)` | 선택한 분할·열. eval에는 `image_id`, `split`, `sha256`, `group_id`만 허용. `strata_key`는 train·val에서만 읽음 |
| `read_annotations_view(root, ids)` | 지정한 train·val ID의 주석. eval 또는 매니페스트 밖 ID가 섞이면 주석 파일을 열기 전에 거부. 흡수 곁파일은 읽지 않음 |
| `read_annotations_view_eval(root, ids, *, receipt)` | 본채점 엄격 경로의 eval 주석. 아래 영수증 검증을 통과한 ID만 허용 |
| `read_image_paths_eval(root, ids, *, receipt)` | 본실험 내보내기 엄격 경로의 eval `image_id`, `rel_path`. 주석용 함수와 같은 영수증 검사 적용 |

eval 접근은 빈 ID 집합을 거부한다. 영수증 종류가 `main`이고 그 커밋이 `refs/heads/main`의 조상이어야 한다. 영수증 커밋의 등록은 생성·채점 양쪽 해시와 맞고 목적 `main`, 기준 분할 `eval`이어야 한다. 등록 지문·검증한 스냅샷 지문은 같은 커밋의 `configs/base.yaml`에 고정한 값과 일치해야 하며 요청 ID는 모두 eval이어야 한다. 작업 트리의 설정으로 대신하지 않는다.

영수증은 한 번 읽은 바이트로 해시와 내용을 확인한다. 허용·거부 호출마다 `outputs/eval_truth_view/calls.jsonl`에 시각, 호출자, 영수증 해시, ID 집합 해시, 결과를 남기고 허용 기록을 쓴 뒤 제한된 열을 읽는다. 주석과 경로 접근은 `view`로 구분한다.

반환된 `attrs["snapshot_digest"]`는 호출자가 프레임 연산 전에 즉시 `fixed_before_main_runs.snapshot_digest`와 대조한다. pandas 연산 후에도 attrs가 보존된다고 가정하지 않는다. 이 경로는 파일 바이트 자체를 읽지 않는 장치가 아니다. 금지된 eval 열과 요청 밖 주석을 값으로 만드는 일을 막는다.

정적 검사는 직접 파일 열기·전체 로더·동적 import 등의 실수를 찾지만 문자열 조립을 이용한 고의 우회까지 보장하지 않는다. 로더의 비공개 자료형 상수 변경과 검증·읽기 사이 파일 변경 위험도 남는다. 코드 검수와 동결 디렉터리 읽기 전용 관리를 함께 적용한다.

## 3. 이미지 변환과 분할

AI허브 JSON의 필드·좌표를 검사하고 검사 방식과 명목 재질을 매니페스트로 옮긴다. 폴리곤의 min/max로 bbox를 만들며 장축은 `cv2.minAreaRect`, 등가 직경은 면적 A에서 `√(4A/π)`로 구하는 설계다. 결과 단위는 픽셀이다. 두께와 스케일이 없는 현 자료에 mm 환산 값을 만들어 넣지 않는다.

학습은 원본 결함 라벨을 유지하며 ISO 6520-1 대응은 YAML에서 읽는다. 검출기의 정상은 박스 없음으로 표현한다. COCO를 중간 형식으로 사용하고 YOLO txt는 변환 결과로 만든다. RIAWELC 외부 평가의 균열·기공·정상 대응도 같은 사상표에서 관리한다.

묶음은 파일 해시, 숫자 ID 구간과 pHash 완전 일치로 만든다. 현행 pHash는 256-bit, 최종 임계 0이다. 초기 해밍 거리 8 안은 채택되지 않았다. 2026-08-26에는 90개 연결을 추가해 묶음이 6,322→6,232개로 바뀌었다. 같은 ID 묶음이 실제 같은 용접부임을 확인한 것은 아니며 근사 중복 누출은 남아 있다.

정상 파노라마에는 원본 한 장당 1280×720 타일 한 장을 대응시킨다. 후보 격자의 가로 간격은 640이고 밴드 중심을 세로 기준으로 삼는다. 검은 패딩은 금지한다. 타일 선택 함수는 split을 받지 않고 이미지 ID와 시드의 해시를 사용한다. 전량 그레이스케일(`L`) 변환과 JPEG quality 74를 고정했다. 전처리 통계는 예비 분할의 학습 풀에서만 구한다.

최종 순서는 묶음 생성, 20% 공통 eval 선분리, 참여자 배정, 각 참여자의 val 분리, 매니페스트 해시 고정이다. C1·C2의 명목 ST에만 Dirichlet α=0.5를 적용하고 C3는 명목 AL로 둔다. C1:C2의 2:1은 사전분포이며 실제 크기는 26,451:16,253이다. 검출과 VLM은 입력 구조가 달라 전처리를 완전히 같게 하지 않으며 같은 구조 안의 학습 방식끼리 고정한다.

## 4. 텍스트·페어·규정 검색

문서 파싱은 Docling을 기본으로 하고 실패한 스캔본·한글 조판은 pdfplumber와 수작업 보정 경로를 기록한다. 필요한 전처리는 NFC, 공백·개행·단위 표기 정리, 조항 번호 추출과 표 셀 정리다. 불용어 제거·형태소 분석은 dense 임베딩·LLM 경로에 적용하지 않는다. BM25를 추가할 경우 해당 경로에서만 별도로 다룬다. 패딩은 저장 단계가 아니라 학습 collator가 처리한다.

허용치 CSV는 골격 생성기, RAG 메타데이터, 정답 조항·판정 기준의 공통 원천이다. 결함 코드, 두께 범위, 품질 수준, 허용치 유형·값·단위, 조항과 출처 외에 `inspection_method`(`RT`/`VT`/`ALL`)를 포함한다. 같은 결함도 표면·내부 검사에서 기준이 달라 이 축을 생략하면 잘못된 행으로도 높은 내부 일치율을 얻을 수 있다.

규칙이 실존 조합을 열거하고 수치·판정·조항 골격을 만든다. 로컬 오픈 가중치 LLM은 문장 표현을 변주하며 수치·조항 재추출 검증에서 어긋난 답은 폐기한다. 초기 합성 수치안의 합격 40%·불합격 40%·경계(허용치 ±10%) 20%는 텍스트 합성용 비율이다. 현 실이미지 페어에 가정 실치수를 넣는 근거로 사용하지 않는다.

본실험 페어는 49,845건으로 봉인됐다. AL 결함 3,372건은 허용치 표에 AL 행이 없어 `clause_only`, `verdict=null`이다. 현재 `validated_by`는 `rule`만 받는다. 사람 검수 등의 표기를 허용하려면 대상 빌드의 스냅샷 지문·표본 수·검수자·시각을 검사하는 공통 규약이 먼저 필요하다. 파일이 존재한다는 이유만으로 사람 검수 완료를 인정하지 않는다.

RAG는 구조화 검색이다. 조항 단위 청크에 문서명, 조항 ID, 결함 코드, 두께 범위, 품질 수준, 본문, 출처 쪽수를 둔다. 메타데이터로 후보를 좁힌 뒤 복수 후보일 때만 dense 유사도로 top-3을 고른다. 검색이 0건이면 해당 조항 없음으로 기록한다. 임베딩은 재학습하지 않고 색인은 집계 루프 바깥에 둔다.

BGE-M3·Qwen3-Embedding-4B의 100질의 비교는 2026-09-01 당시 모든 질의의 후보가 한 개, 청크 네 개의 본문 길이가 0이어서 변별력이 없었다. 임베더 호출도 0회였고 `embedding.model`은 null로 유지했다. BGE-M3를 확정 모델이라고 쓰거나 조항 본문·정답 검증이 끝난 것으로 설명하지 않는다. 본실험의 기본 통합형에는 RAG를 붙이지 않는다.

## 5. 검출기 사전실험

검출기는 YOLO11s(9.4M)다. 초기 문서의 YOLOv8n/s·3.2M 설명은 당시 후보 기록이며 현행 모델이 아니다. Ultralytics AGPL-3.0의 배포 조건은 연구 코드와 제품 배포 상황에 맞춰 확인해야 한다. 제품화 때 Apache 계열이나 상용 라이선스를 검토한다는 기존 방침은 실제 전환 완료를 뜻하지 않는다.

로컬·중앙은 N=100 epoch, 연합은 R=50·E=2로 실행했다. 설정·optimizer·증강을 고정하고 조기 종료를 끈 뒤 last를 채점했다. 검출 연합은 BatchNorm 통계를 포함한 교환 대상 가중치·버퍼를 평균한다. 전역 모델 하나를 공통 평가셋에서 채점하므로 로컬 BN을 유지하는 FedBN을 기본으로 쓰지 않는다. 별도 BN 보정을 하더라도 eval을 학습·보정에 사용할 수 없다.

Flower는 GPU 한 장에서 참여자 역할을 실행하는 시뮬레이션이다. 물리적인 기업 간 배포나 회선 성능을 측정한 것이 아니다. `accept_failures=False`로 참여자 실패를 남은 참여자만의 정상 라운드로 처리하지 않는다. 라운드별 val은 학습 풀에서 뗀 자료이며 eval과 다르다. 기존 eval의 재채점 이력이 있으므로 ‘전 실험에서 최종 한 번만 접근했다’고 서술하지 않는다.

### 검출기의 회계와 재개

클라이언트×라운드 기록에는 참여·표본·스텝을 남긴다. `optimizer_updates`는 갱신 시도 수다. AMP가 inf/NaN에서 실제 적용을 건너뛴 경우도 포함한다. 사전실험 세 시드의 71,202는 시도 수이며 실제 적용 수는 미계측이었다. 적용 수 필드가 있는 실행에서만 `optimizer_updates_applied`를 인용한다. 재구성값 대신 `value_source == measured`인 기록을 사용한다.

`detection/round_runner.train_round`의 `clear_resume_on_success` 기본값은 False다. 로컬·중앙 호출자는 NPZ를 임시 파일에 쓰고 재로드해 배열 수·shape·dtype·값과 sha256을 확인한 뒤 완료 파일로 교체하고 재개 파일을 정리한다. 연합 클라이언트의 응답 반환 전 정리는 응답 조립 실패까지 보호한다. 이후 직렬화·전송·집계·서버 저장까지 내구성을 보장하지 않는다. 검출 연합의 라운드 경계 재개는 조건부 채택 기록과 완료 검증을 구분해야 한다.

재개 전 검증을 통과한 `results.csv`는 트레이너 생성 전에 `results.before_resume_<epoch_done>__<run_id>__<시각>.csv`로 보존한다. 파생 테이블은 `detection/results_merge.py`가 읽기 전용으로 병합한다. 겹치는 epoch는 뒤 조각을 쓰고 손상 행·조각을 보고한다. 구판 F03의 8열 마지막 행은 앞의 epoch·time·train과 뒤의 LR 블록으로 복원하며 중간 metrics·val 일곱 열을 NaN으로 둔다. 단순 오른쪽 패딩은 하지 않는다.

원자 로그의 첫 데이터 행이 `run_id`·seed·cell·split_hash를 정한다. 다른 실행은 같은 원장에 덧쓰지 않는다. epoch별 재시드 정책을 켠 검출 실행은 run_id에 `_rs1`을 붙이며 접미 없는 옛 산출물을 고치지 않는다. 재개 실행의 epoch 증거는 CSV 조각을 합친 뒤 해석한다.

## 6. 통합형 학습·생성

`scripts/main_uni.py`는 시드마다 로컬 C1·C2·C3, 중앙, 연합을 실행한다. `vlm/train_cell.py`가 로컬·중앙을, `fl/`이 연합 경로를 맡는다. 본실험 실행은 저장소 루트에서 시작하며 설정·페어·출력 경로·고의 중단 변수 등을 모델 적재 전에 검사한다. 미완성 필수 설정을 파일럿 기본값으로 채우지 않는다.

각 로컬 모델은 공통 초기 어댑터에서 따로 출발한다. 앞 참여자의 학습 어댑터를 이어 쓰지 않는다. 어댑터 파일이 이미 있으면 신원과 원장 마감을 먼저 대조한다. 같고 원장이 닫혔으면 건너뛰고, 열렸으면 저장 검증을 거친 명시적 마감을 요구하며, 다르면 거부한다. 출력 경로를 덮어써 새 실행을 만들지 않는다.

어댑터 저장은 임시 저장→재로드 대조→sha256→메타데이터→원자 교체 순서다. 완료 어댑터가 저장된 뒤 원장을 닫는다. 중단·재개 신원에는 셔플 정책, 템플릿 모드, 토큰 접두 판본을 결속한다. 통합형 연합 실행기는 현재 같은 원장에 이어 쓰는 라운드 재개를 제공하지 않는다. 남은 실패 출력은 보존하고 새 실행과 구분한다.

통합형의 교환물은 PEFT LoRA A·B 상태다. 4bit 기본 모델은 같게 두고 어댑터 행렬별 평균을 수행하며 가중 단위는 감독 토큰 총합이다. 라운드 중 어댑터를 병합하지 않는다. 초기 설계의 ‘최종 병합본으로 평가’와 달리 현 생성기는 학습과 같은 4bit 기저에 비병합 LoRA를 주입한다. 같은 어댑터를 bf16 기저에 올린 소표본은 4B 초기 어댑터 8장 중 0장, 0.8B 학습 어댑터 8장 중 2장만 토큰 수열이 같았다. bf16의 28% 속도 이점은 동일 출력이 검증된 본실험 결과가 아니다.

`scripts/export_uni.py`와 `vlm/export_*`가 모델·에코 모드의 생성 묶음을 쓴다. 에코는 정해진 출력을 사용해 좌표·입출력 연결을 확인하는 경로다. 실제 모델 생성기는 `vlm/export_model.py`에 구현돼 있다. HF 모델 적재, 어댑터 키·값 확인, 학습과 같은 프롬프트 렌더를 거쳐 `do_sample=False`, `num_beams=1`, batch 1로 생성한다. 실제 GPU 검증은 미완료다.

마지막 새 토큰이 종료 토큰이면 한도에 닿았어도 `eos`, 종료 토큰 없이 한도에 닿으면 `length`로 남긴다. 둘 다 아니면 `stop_undetermined`를 남기고 평가 검증기가 묶음을 거부한다. latency는 CUDA 동기화를 포함한 `model.generate` 구간이며 적재·전처리 전체 시간과 다르다. 파싱과 좌표 역변환은 공통 경로를 사용한다.

생성과 학습에는 같은 프롬프트·템플릿 모드, 모델 판본·프로세서 설정을 전달한다. 2026-10-05에는 모델 revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`와 봉인 페어를 설정에 연결하도록 결정했지만 결정과 배선·실행 확인은 별도다. 계획에 적힌 한도 2,304 토큰 역시 현 본실험의 확정 생성 한도로 자동 승계하지 않는다.

## 7. 공통 채점과 구간 계산

통합형은 `evaluation/schema_v14.py`의 `uni_local`, `uni_central`, `uni_fed`를 사용한다. 로컬은 C1·C2·C3 식별을 포함한다. 박스·인용·실패 정보를 공통 예측 형식으로 바꾼 뒤 같은 채점기를 쓴다. 구판 예시의 `size_mm`·합격 필드는 현 실이미지에서 실측 가능한 필수값이 아니다.

`evaluation/metrics/box_f1.py`는 모델 종류를 받지 않고 예측·정답 박스와 클래스만 받는다. 이미지×클래스 TP·FP·FN 계수표를 만든 뒤 부분집합, 가중 집계, 묶음 재표집에 재사용한다. M1은 최대 짝 수 우선, 동률에서 IoU 합·항목 순서를 사용하는 F1이다. 기존 BBox-IoU의 합 최대화 매칭을 그대로 재사용하지 않는다. binary64의 수학적 `IoU ≥ 1/2` 경계와 유리수 재판정은 [실험설계](실험설계.md)에 설명했다.

현재 파싱 실패의 빈 예측 처리는 정상 이미지의 공집합 점수나 무벌점과 구분해 보고한다. 한 레코드의 결함 필드와 판정·인용 오류를 어떻게 결합할지는 최종 등록이 필요하다. 정상·결함과 N-crop·N-tile별 실패율을 별도 기록한다. 신뢰도 점수가 없는 통합형 mAP는 `NOT_APPLICABLE`이며 0으로 채우지 않는다.

### 통합형의 백분위 규약

`evaluation/recovery_interval.py`가 추첨을 분류하고 `evaluation/percentile_rule.py`가 구간 끝점을 구한다. 2026-10-01 채택한 규약 ID는 `interval-20261001-1`이다. 회복률만이 아니라 통합형 산출물의 분모·대응 차·참여자 보고·출처 진단에 실리는 모든 백분위 구간에 적용한다.

한 시드의 분자 N=`연합−로컬평균`, 분모 D=`중앙−로컬평균`에 대해 D>0이면 N/D다. D≤0이고 N>0이면 +∞, N<0이면 −∞를 추첨값으로 둔다. 이는 음수 분모의 대수적 비율이 아니라 꼬리 순서를 정한 약속이다. D≤0·N==0은 판정 불가이며 `N==0`은 −0.0을 포함한 부동소수 정확 비교다.

| 추첨 분류 순서 | 처리 |
|---|---|
| 고정 평가 클래스의 정답 지지량 소실 | `n_excluded_support`, 구간 집계 제외 |
| 어느 시드든 분모 실패와 분자 0 | `n_indeterminate`, 사유 `numerator_zero` |
| 시드 사이 +∞·−∞ 혼재 | `n_indeterminate`, 사유 `sign_conflict` |
| +∞가 있음 | `n_infinite_pos`, 위쪽 끝값으로 포함 |
| −∞가 있음 | `n_infinite_neg`, 아래쪽 끝값으로 포함 |
| 나머지 | `n_finite`, 시드별 회복률 평균 |

미정의 비율의 분자는 `n_excluded_support + n_indeterminate`다. 분모 실패는 무한으로 구간에 들어가므로 여기에 다시 더하지 않는다. 집계 길이는 `n_finite + n_infinite_pos + n_infinite_neg`이다. 오름차순 추첨값 x의 인덱스는 0부터 센다.

```text
k = ((n − 1) × 25) // 1000       # 95% 구간
하한 = x[k]
상한 = x[(n − 1) − k]
```

보간하지 않고 무한을 양 끝값으로 포함한다. 끝점 상태는 `finite`, `pos_inf`, `neg_inf`, `absent`; 반폭은 `finite`, `infinite`, `undefined`, `absent`다. 같은 부호의 무한끼리 반폭은 미정의다. 수 필드는 유한할 때만 숫자를 담고 나머지는 null과 상태로 표현한다. 점추정은 어느 시드든 D≤0이면 해당 회복률과 평균을 `absent` 및 사유로 보고하며 무한을 적지 않는다.

기존 사전실험의 `evaluation/recovery_ci.py`는 분모 실패를 제외하고 기본 보간을 사용한 동결 규약이다. 규약 ID는 `pre-drop-undefined-numpy-default`로 구분한다. 새 규약의 사후 계산을 하더라도 등록 뒤 별도 산출물에 ‘판정에 쓰지 않음’을 표시하며 기존 값을 덮지 않는다.

## 8. 등록·영수증·산출물 검증

`evaluation/prereg_unified.py`는 생성·채점을 별도 해시로 묶는다. `generation_sha256`에는 목적·분할·동결본·목록·프롬프트·템플릿·디코딩·모델·출발점·학습 설정·좌표·라이브러리 판을 담고, `scoring_sha256`에는 지표·실패 결합·대조선·CI·모집단 설계·기지답 벡터를 담는다.

등록은 값의 존재와 자료형·허용 범위·필드 간 관계를 모두 검사한다. `None`은 미정이지만 False와 0은 값이다. 배경지식 학습을 유지하면 `start_checkpoint_sha256`, 폐지하면 `init_adapter_digest`를 채우고 다른 쪽은 null로 둔다.

| 목적 | 기준 분할 | 용도 |
|---|---|---|
| `main` | eval | 본실험 생성·본채점. 완결된 생성·채점 등록 필요 |
| `rehearsal` | val | 전 구간 연결 확인. 본실험 성능으로 합산하지 않음 |
| `frame_diag` | val | 학습·생성 좌표 프레임 진단. 진단 규칙·학습 행·계획 해시 필요 |

영수증에는 목적, 등록 파일 경로와 바이트 해시, 등록 커밋을 남긴다. 작업 트리 대신 영수증 커밋의 파일을 읽어 해시를 맞춘다. 저장소 이력을 2026-09-17·09-19에 다시 쓴 이력이 있어 커밋 시각만으로 사전등록을 입증하지 않는다. 생성 시작 기록과 내용 해시를 함께 사용한다.

예측·채점·CI·집계는 입력 해시와 등록을 공유해야 한다. CI 파일 이름이나 저장된 통과 플래그만으로 채택하지 않는다. 시드 목록, 채점기 지문, 신뢰수준·구간 방식, 점추정·항등 검사를 다시 확인한다. 기존 파일이 있으면 새 판을 덮지 않고 거부한다.

## 9. 검증 범위와 남은 작업

2026-10-05 점검에서는 모델·페어 설정 연결, 판본 있는 근사 중복 연결 목록, 단계별 제한 시간, 연합 리허설 단계, 좌표 진단 경로와 에코 학습 설정 등 착수 조건이 남았다. 진단의 표본 하한·문턱은 결정 대기이며 본실험 학습량·생성 한도·시드 수·대표 지표도 미정이다. 코드·합성 시험·정책 채택을 실물 리허설 통과로 바꾸어 보고하지 않는다.

재현 확인은 고정 입력·설정·코드 판과 원시 예측에서 시작한다. 제출 전 새 환경 재실행 계획은 매니페스트 해시 대조, 검출 중앙 한 시드의 재학습 오차 확인, 채점 재현이었다. 이 계획 자체가 수행 기록은 아니다. 확인한 항목, 입력·코드 식별자, 실제 실행 여부, 미검증 구간을 결과와 함께 남긴다.
