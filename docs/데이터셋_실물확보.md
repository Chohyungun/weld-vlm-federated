# 데이터 특성

## RIAWELC의 위치 라벨

아카이브 전수 목록(24,424 엔트리, `7z l -slt` 기준)을 뽑아 확장자를 집계했다.

```
24,407.png
     1.rar   (분할 아카이브 자기 참조)
```

JSON·XML·TXT·CSV·MAT 어떤 형태의 어노테이션 파일도 없다. 라벨은 오로지
디렉터리 경로로만 표현된다. 육안 확인한 이미지도 결함이 프레임 전체에 걸쳐 있고
좌표 정보를 담을 사이드카 파일이 없다.

→ RIAWELC은 순수 분류(classification) 데이터셋이다. 백업 시나리오에서
mAP·BBox-IoU·Class-Jaccard 위치 지표는 산출 불가로 확정한다.

> 대안 제시: GDXray Welds는 규모가 작지만 bbox 정답이 있다. RIAWELC 백업
> 시나리오에서 위치 지표를 완전히 포기하는 대신 소규모 보조 평가로 살릴 여지가 있다.
> 실험 입력에는 포함하지 않는다.

## 이미지 규격 — 224×224가 아니라 227×227

해제된 PNG 24,407장 전부의 IHDR 헤더를 프로그램으로 판독했다. 표본이 아니라 전수다.
단 한 장의 예외도 없이 다음과 같다.

```
24,407 / 24,407    227 x 227,  bit depth 8,  color type 0 (grayscale),  PNG 시그니처 정상
```

클래스별로도 전수 일치한다 (Difetto1 7,635 · Difetto2 6,320 · Difetto4 4,452 ·
NoDifetto 6,000, 아카이브 목록 집계와 해제본 실측이 동일).

RIAWELC 공식 README의 기재는 224×224이지만 실물 해상도는 227×227이다.

227은 AlexNet 입력 규격이다. 저자가 AlexNet 계열 학습용으로 패치를 뜬 흔적으로 보인다.

영향: 우리 전처리는 640 letterbox로 리사이즈하므로 학습에 실질 영향은 없다.
다만 "224 가정"으로 하드코딩된 크롭·리사이즈 코드가 있으면 3픽셀이 조용히 잘린다.
ingest 어댑터는 규격을 하드코딩하지 말고 헤더에서 읽어야 한다.
비트깊이 8bit·grayscale 기재는 정확했다.

## 클래스 폴더명이 `LP/PO/CR/ND`가 아니다. 매핑 미공개

실제 디렉터리 구조는 다음과 같다.

```
DB - Copy/
├── training/   {Difetto1, Difetto2, Difetto4, NoDifetto}
├── validation/ {Difetto1, Difetto2, Difetto4, NoDifetto}
└── testing/    {Difetto1, Difetto2, Difetto4, NoDifetto}
```

`Difetto`는 이탈리아어 "결함"이다. `Difetto3`이 결번이고, 어느 번호가
LP·PO·CR 중 무엇인지 저장소·README·논문 어디에도 명시가 없다.

### 매핑 확정: 독립적인 두 방법이 일치

(a) 분포 순위 대조. 실측 전량 분포와, RIAWELC을 쓴 선행 문헌이 보고한
클래스별 표본 수의 순위가 일치한다.

| 실측 폴더 | 실측 장수 | 문헌 보고 클래스 | 문헌 보고 장수 |
|---|---|---|---|
| Difetto1 | 7,635 | crack | 7,008 |
| Difetto2 | 6,320 | porosity | 5,768 |
| NoDifetto | 6,000 | no defect | 5,352 |
| Difetto4 | 4,452 | lack of penetration | 3,712 |

(b) 육안 형태 판독. 클래스별 표본을 직접 열어 방사선 형태학으로 대조했다.

| 폴더 | 관찰된 형태 | 판정 |
|---|---|---|
| Difetto1 | 가늘고 불규칙하게 갈라지며 꺾이는 어두운 선 | CR 균열 |
| Difetto2 | 둥근 어두운 반점과 그 군집 | PO 기공 |
| Difetto4 | 폭이 일정하고 곧게 연속되는 어두운 띠 | LP 용입불량 |
| NoDifetto | 균일한 질감, 특징 없음 | ND 정상 |

### 확정 매핑

```yaml
Difetto1:  CR  # crack               균열
Difetto2:  PO  # porosity            기공
Difetto4:  LP  # lack of penetration 용입불량
NoDifetto: ND  # no defect           정상
```

주의, 직관적 추측이 틀린다. 공식 README는 클래스를 `LP, PO, CR, ND` 순으로
나열한다. 번호 순서대로 읽어 `Difetto1=LP`로 두면 균열과 용입불량이 통째로
뒤바뀐다. 낯선 데이터 평가(공통 3클래스 균열·기공·정상)가 조용히 오염되므로,
클래스 매핑은 사상표 YAML을 기준으로 적용한다.

|---|---|---|---|---|---|
| training | 4,962 | 4,108 | 2,893 | 3,900 | 15,863 |

평가셋은 층화·묶음 단위로 직접 선분리한다. 저자 분할의 중복 사본을 제외한 고유 이미지 풀을 사용하고 클라이언트 분할은 따로 만든다.

## 타일 이름과 묶음 누수 위험

파일명이 타일 좌표를 담고 있다.

```
bam5_Img2_A80_S4_[13][30].png
└─ 모원본 식별 ────────┘ └행┘└열┘
```

파일 이름 접두사의 집계값은 509개이며, ` - Copia` 접미를 함께 처리한 집계값은 479개다. 이 차이는 이름 처리 방법에 따른 것으로, 어느 값도 독립적인 원본 사진 수를 직접 실측한 값으로 해석하지 않는다. 24,407개 파일은 격자 위치를 이름에 담은 타일이다. [메타데이터 설계](메타데이터_설계.md)에 접미 처리와 묶음 식별 규칙을 설명했다.
`bam` 접두사로 보아 BAM(독일 연방재료연구소) 공개 방사선 사진이 원천으로 보인다.

같은 모원본에서 나온 인접 타일이 학습과 평가로 갈리면 성능이 부풀려진다.
같은 모원본 타일이 두 분할에 걸치는 누수를 막기 위해, RIAWELC에서는
pHash를 돌릴 필요도 없이 파일명 접두사가 곧 묶음 ID다.

→ 조치: RIAWELC ingest 어댑터는 `_[행][열]` 정규식을 떼어낸
접두사를 `group_id`로 매니페스트에 기록하고, 분할을 이 묶음 단위로 수행해야 한다.
저자 제공 testing이 training의 복제본이라는 사실은 아래 중복 대조 결과에 포함되어 있다. 따라서 저자 분할을 독립 평가셋으로 사용하지 않는다.

### 바운딩박스 있음 (RIAWELC과 대비되는 지점)

이미지 1장마다 어노테이션 2종이 동봉돼 있다.

- `.yolo`: YOLO 형식 `class_id cx cy w h`, 정규화 좌표
- `.json`: LabelMe v5.1.1 `shape_type: "rectangle"`, 절대 픽셀 좌표

> 두 포맷의 좌표계를 통일해야 한다. 원본 픽셀 좌표로 저장하고 변환과 역변환은 별도 함수로 둔다.

클래스 ID는 저장소 `create_kfold.py`의 소스 코드 확정값이다 (추정 아님).

```yaml
0: pore   1: deposit   2: discontinuity   3: stain
```

| | 이미지 | bbox 계 | pore | deposit | discontinuity | stain | 라벨 없는 이미지 |
|---|---|---|---|---|---|---|---|
| low_resolution | 2,000 | 12,937 | 3,427 | 1,141 | 4,243 | 4,126 | 77 |
| high_resolution | 1,022 | 9,475 | 523 | 1,794 | 2,977 | 4,181 | 0 |
| 계 | 3,022 | 22,412 | 3,950 | 2,935 | 7,220 | 8,307 | 77 |

### 라벨과 해상도의 제약

(a) 저해상 77장은 어노테이션이 비어 있다. `.yolo` 파일은 존재하나 내용이 없다.
정상(무결함) 이미지인지 라벨 누락인지 문서에 설명이 없다.

(b)  이미지 크기가 장마다 다르다. RIAWELC처럼 고정 규격이 아니다. 전량 3,022장 실측:

| | n | 가로 (min~max, 평균) | 세로 (min~max, 평균) | 픽셀 포맷 |
|---|---|---|---|---|
| low_resolution | 2,000 | 85 ~ 215 (155.2) | 30 ~ 56 (40.0) | 24bpp RGB |
| high_resolution | 1,022 | 755 ~ 827 (779.2) | 164 ~ 280 (191.8) | 24bpp RGB |

용접 비드를 가로로 자른 띠라 가로:세로가 약 4:1이다. 두 가지가 걸린다.
크기를 고정값으로 가정한 코드가 깨진다(헤더에서 읽어야 한다). 그리고
640 정사각 letterbox를 그대로 적용하면 세로 패딩이 과도하다. 저해상은 세로가
30~56픽셀뿐이라 640으로 늘리면 원본에 없던 정보를 만드는 셈이다.

(c) 저자 제공 5-fold 분할이 들어 있다. `kfold_low\`·`kfold_high\`가 fold별로 이미지를
복사해 갖고 있어, 해제본 34,489개 중 25,420개가 중복분이다
(kfold_low 16,824 + kfold_high 8,596). 원본은 `low_resolution_welds\` 6,000개 +
`high_resolution_welds\` 3,066개가 전부다. 실험에서는 저자 분할을 쓰지 않는다.

## 고유 이미지 수와 파일 총수

파일 수와 이미지 장수는 다른 값이다. 섞어 읽으면 LoHi가 11배로 잘못 집계된다.

### LoHi-WELD — 원본 이미지는 3,022장. 문서 기재가 옳다

34,489는 이미지·어노테이션·저자 5-fold 사본·캐시·스크립트를 전부 합친 파일 수다.

| 확장자 | 개수 | 용량 | 정체 |
|---|---|---|---|
| `.jpg` | 15,712 | 621.2 MB | 원본 3,022 + kfold 사본 12,690 |
| `.txt` | 12,714 | 4.5 MB | kfold용 YOLO 라벨 사본 |
| `.json` | 3,022 | 5.9 MB | LabelMe 어노테이션 (원본) |
| `.yolo` | 3,022 | 0.85 MB | YOLO 어노테이션 (원본) |
| `.cache` | 14 | 3.4 MB | YOLO 학습 캐시 |
| `.sh` `.py` | 5 | 2.6 MB | 저자 스크립트 |
| 계 | 34,489 | 638.4 MB | |

고유 이미지 파일명 3,022개, 등장 총합 15,712회, 최대 중복 6회.
6회 = 원본 1 + test 1 + fold0~4 각 1로 정확히 맞는다.

| 폴더 | 파일 | 이미지 | 성격 |
|---|---|---|---|
| `low_resolution_welds` | 6,000 | 2,000 | 원본 |
| `high_resolution_welds` | 3,066 | 1,022 | 원본 |
| `kfold_low` | 16,824 | 8,400 | 파생 (쓰지 않는다) |
| `kfold_high` | 8,596 | 4,290 | 파생 (쓰지 않는다) |

학습 대상 = 3,022장. `kfold_*`는 전량 파생본이다.

### RIAWELC — 파일 24,407, 고유 이미지 21,964. `testing`은 복제본이다

라벨 혼입은 없다(전량 `.png`). 그런데 고유 파일명이 21,964개뿐이다.
2,443개 이름이 두 번 나타나고, 전수 sha256 대조 결과는 다음과 같다.

| | 결과 |
|---|---|
| 중복 파일명 | 2,443 |
| 걸친 split 조합 | `testing` ↔ `training` 단 하나 (2,443건 전부) |
| sha256 일치 | 2,443 / 2,443 (100%) |
| sha256 불일치 | 0 |
| 클래스 불일치 | 0 |

```
파일 총수     24,407   ← 파일 총수
고유 이미지   21,964   ← training 15,863 + validation 6,101
중복 사본      2,443   ← testing 전량
```

저자 제공 `testing`은 독립 평가셋이 아니라 `training`에서 바이트 단위로 복사된 것이다.
테스트 누수 100%. 그 분할로 채점하면 학습 데이터로 채점하는 것과 같다.

중복 사본을 제외하면 testing의 바이트 복제로 인한 누수를 막을 수 있다. 같은 모원본의 타일이 두 분할에 걸치는지도 별도로 제한해야 한다. 다만
RIAWELC 백업 시나리오의 유효 표본은 24,407이 아니라 21,964장(−10.0%)이므로 분할
규모 산정을 이 값으로 해야 한다. `testing` 폴더는 원본 불변 원칙에 따라 삭제하지 않고
"중복본, 사용 금지"로 표시한다.

> 창원은 연속 촬영 묶음의 53.1%가 두 분할에 걸쳐 있고, RIAWELC은 test를 train에서 복제했다. 두 저자 분할 모두 독립 평가셋으로 그대로 사용할 수 없다.

## Bacioiu TIG HDR

```
https://www.kaggle.com/datasets/danielbacioiu/tig-aluminium-5083
```

"TIG Aluminium 5083 defect image dataset", D. Bacioiu. 문헌 기재
(약 30,000장 / 800×974 / 55fps / 6클래스 / 전문가 수동 어노테이션)와 문헌 기술이 일치한다.

원 논문: Bacioiu et al., *Automated defect classification of Aluminium 5083 TIG welding
using HDR camera and neural networks*, Journal of Manufacturing Processes (2019).

실험 입력에는 포함하지 않는다. Kaggle 다운로드에는 계정 로그인이 필요하다. 문헌상 프레임 단위 분류 라벨로 보이므로 위치 지표의 산출 가능성은 보장되지 않는다.
