# RIAWELC·LoHi-WELD 실물 확보와 검증

이 문서는 두 보조 이미지 데이터셋을 실제로 받아 확인한 결과를 설명한다. 원본 파일의 규모·형식·중복을 확인한 기록이며, 사용권 전체를 확정하거나 모델 성능을 검증한 보고서는 아니다. 취득일은 2026-08-18이고 공유 드라이브 이전 기록은 2026-08-22다. 후속 정정은 함께 반영했다.

전체 자료의 현재 역할은 [데이터셋 현황](데이터셋_현황.md), 주 자료인 창원 데이터는 [AI허브 전수확인](데이터셋_AI허브_전수확인.md)을 본다.

## 1. 확보 결과

| 자료 | 출처 | 고유 이미지 | 해제본 파일 수 | 원본 아카이브 |
|---|---|---:|---:|---:|
| RIAWELC | [공식 저장소](https://github.com/stefyste/RIAWELC), main | 21,964 | 24,407 | RAR 19파트, 490,670,723 B |
| LoHi-WELD | [공식 저장소](https://github.com/SylvioBlock/LoHi-Weld), main | 3,022 | 34,489 | ZIP 1개, 630,791,890 B |
| Notre Dame 현장 자료 | Khvatskii 외(2025) 논문의 공개 경로 | 0 | — | 링크 만료로 확보 실패 |

두 아카이브는 7-Zip 종료코드 0으로 해제돼 CRC 검사를 통과했다. 해제본은 RIAWELC 483,502,197 B, LoHi-WELD 638,399,972 B였다. LoHi의 아카이브 엔트리 34,570개와 파일 34,489개의 차이는 디렉터리 81개다.

원본 아카이브 20개의 SHA-256과 바이트 수는 내부 확보 기록에 보존한다. 당시 클라우드 확인은 아카이브 20/20의 존재·바이트 수, 마지막 생성 파일 3개, README 3종을 대조했다. 이것은 해당 파일의 업로드 확인 근거이며 해제본 58,919개를 클라우드에서 전수 바이트 대조했다는 뜻은 아니다. 기존 적재 기록의 총 바이트 표기는 서로 달라 이번 개정에서 새 합계로 확정하지 않았다.

## 2. RIAWELC에서 확인한 것

### 이미지와 클래스

PNG 24,407개 전부의 IHDR 헤더를 판독한 결과 **227×227, 8bit, grayscale**였고 예외는 없었다. 공식 README를 포함한 기존 224×224 기재는 실물과 다르다. 파일 크기나 입력 크기는 헤더에서 읽어야 한다.

어노테이션용 JSON·XML·TXT·CSV·MAT 파일은 없었다. 라벨은 폴더명으로만 주어지므로 분류에는 쓸 수 있지만 위치 평가용 bbox 정답은 없다. mAP·BBox-IoU와 bbox 기반 Class-Jaccard를 산출할 수 없다.

| 원본 폴더명 | 해석 | training | validation | testing | 파일 합계 |
|---|---|---:|---:|---:|---:|
| `Difetto1` | CR, 균열 | 4,962 | 1,908 | 765 | 7,635 |
| `Difetto2` | PO, 기공 | 4,108 | 1,580 | 632 | 6,320 |
| `Difetto4` | LP, 용입불량 | 2,893 | 1,113 | 446 | 4,452 |
| `NoDifetto` | ND, 정상 | 3,900 | 1,500 | 600 | 6,000 |
| 합계 | | 15,863 | 6,101 | 2,443 | 24,407 |

번호와 클래스의 대응은 배포처가 명시한 매핑표에서 가져온 것이 아니다. 선행 문헌의 클래스별 분포 순위와 이미지 표본의 방사선 형태 판독이 일치해 위 매핑을 채택했다. 문헌의 장수는 CR 7,008·PO 5,768·ND 5,352·LP 3,712로 실제 파일 합계와 다르므로 순위 대조 근거로만 사용했다. README의 나열 순서 `LP, PO, CR, ND`를 폴더 번호에 그대로 대입하면 균열과 용입불량이 뒤바뀐다.

### 중복과 원판별 묶음

`testing` 2,443개는 모두 `training`에 같은 이름으로 있고, 전수 SHA-256 대조에서도 2,443/2,443개가 일치했다. 클래스 불일치는 0건이다. 따라서 24,407은 파일 수이고, 고유 이미지 수는 21,964다. 원본 폴더를 보존하되 저자 테스트 사본은 학습·평가 표본에서 제외한다.

이미지는 방사선 원판을 격자로 자른 타일이다. 파일명의 `_[행][열]` 앞 접두사를 원판별 묶음의 근거로 사용한다. 2026-08-21 후속 전수 확인은 ` - Copia` 접미까지 처리해 24,407/24,407개를 매칭했고 **479개 접두사**를 얻었다. 이전의 509개 집계는 접미가 있는 30건 처리에서 차이가 생긴 값이다. 엄격한 정규식은 접두사 478개와 패턴 불일치 30건을 남겼다.

접미 파일 표본 8건에는 이름에 대응하는 원본 파일이 없었다. 이름의 `Copia`만으로 삭제할 중복본이라고 판단하지 않는다. 같은 원판의 비겹침 타일은 지각 해시만으로 묶기 어려우므로 원판 접두사를 함께 사용한다. BAM 원천이라는 설명은 파일명에 근거한 추정이며, GDXray와의 원천 중복 가능성도 남아 있다.

## 3. LoHi-WELD에서 확인한 것

원본 이미지는 `low_resolution_welds`의 2,000장과 `high_resolution_welds`의 1,022장이다. 저자 5-fold용 복제본은 추가 이미지로 세지 않는다.

| 확장자·종류 | 파일 수 | 내용 |
|---|---:|---|
| `.jpg` | 15,712 | 원본 3,022 + kfold 사본 12,690 |
| `.txt` | 12,714 | kfold용 라벨 사본 |
| `.json` | 3,022 | 원본 LabelMe 라벨 |
| `.yolo` | 3,022 | 원본 YOLO 라벨 |
| `.cache` | 14 | 학습 캐시 |
| `.sh`, `.py` | 5 | 저자 스크립트 |
| 합계 | 34,489 | 이미지 장수와 구분 |

원본 폴더의 파일 수는 6,000개와 3,066개다. `kfold_low` 16,824개와 `kfold_high` 8,596개는 합계 25,420개 파생 파일이다. 고유 이미지 파일명 3,022개의 등장 총합은 15,712회이며 최대 6회였다.

이미지마다 YOLO의 `class_id cx cy w h` 정규화 좌표와 LabelMe v5.1.1의 `rectangle` 절대 픽셀 좌표를 함께 제공한다. 클래스 ID는 배포 저장소의 `create_kfold.py`에서 확인했다.

| 구분 | 이미지 | bbox | `pore`(0) | `deposit`(1) | `discontinuity`(2) | `stain`(3) | 빈 라벨 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 저해상 | 2,000 | 12,937 | 3,427 | 1,141 | 4,243 | 4,126 | 77 |
| 고해상 | 1,022 | 9,475 | 523 | 1,794 | 2,977 | 4,181 | 0 |
| 합계 | 3,022 | 22,412 | 3,950 | 2,935 | 7,220 | 8,307 | 77 |

빈 `.yolo` 77개가 정상 이미지인지 라벨 누락인지는 문서에서 확인하지 못했다. 정상 정답으로 확정하지 않는다.

이미지는 모두 24bpp RGB JPEG지만 크기는 가변이다. 저해상은 가로 85~215(평균 155.2), 세로 30~56(평균 40.0)픽셀이고, 고해상은 가로 755~827(평균 779.2), 세로 164~280(평균 191.8)픽셀이다. 약 4:1의 띠 모양이므로 정사각 입력으로 변환할 때 확대와 패딩 효과를 확인해야 한다.

`deposit`은 정의 미확인, `discontinuity`는 특정 결함보다 넓은 말, `stain`은 표면 오염이라는 차이가 있다. 창원·RIAWELC의 공통 결함 체계에 무리하게 합치지 않는다. [연합설계 적합성](데이터셋_연합설계_적합성.md)에서 비교 범위를 설명한다.

## 4. 사용 조건과 인용

RIAWELC과 LoHi-WELD 모두 취득 당시 명시적 LICENSE 파일을 찾지 못했다. RIAWELC의 공개 배포 문구와 LoHi-WELD 논문의 공개 데이터셋 설명은 확인했지만, 이를 모든 상업 이용·재배포 허용의 근거로 삼지 않는다. 보유와 사용권 확인은 별개다.

사용 시 반영할 인용은 다음과 같다.

1. Totino, B., Spagnolo, F., Perri, S. (2022). *RIAWELC: A Novel Dataset of Radiographic Images for Automatic Weld Defects Classification*. ICMECE 2022, 6–7 October, Barcelona.
2. Perri, S., Spagnolo, F., Frustaci, F., Corsonello, P. *Welding Defects Classification Through a Convolutional Neural Network*. Manufacturing Letters, Elsevier.
3. Block, S.B., da Silva, R.D., Lazzaretti, A.E., Minetto, R. (2024). *LoHi-WELD: A Novel Industrial Dataset for Weld Defect Detection and Classification, a Deep Learning Study, and Future Perspectives*. IEEE Access 12, 77442–77453. DOI 10.1109/ACCESS.2024.3407019.

실제 논문 제출본에 이 인용과 데이터 가용성 설명이 반영됐는지는 제출 전에 확인해야 한다. AI허브의 성과 보고 절차 역시 별도 확인 사항이다.

## 5. 미확보 후보와 보관 원칙

Notre Dame 자료는 *Do multimodal large language models understand welding?* (Khvatskii 외, 2025, *Information Fusion* 120, 103121; arXiv:2503.16537)의 Real-World Weld Dataset 95장이다. Online Weld Dataset 73장과 구분한다. 전문가 1인이 맥락별 이진 판정과 서술 근거를 붙였으며 RV & Marine 43/52, Aeronautical 12/83, Farming 26/69라는 분포가 기재돼 있다. 공개 경로는 당시 HTTP 410 `repository_expired`였고 미러를 찾지 못해 확보하지 못했다. 이 결과는 영구적인 입수 불가능 판정은 아니다.

Bacioiu TIG HDR·GDXray·KAMP·CMT·INWELD 등의 조사 결과는 중복을 줄이기 위해 [데이터셋 현황](데이터셋_현황.md)에 모았다. 확보 당시 AI허브 승인 여부를 로그인 없이 확인하지 못한 기록도 있었으나, 이후 창원 자료를 확보하고 검증했다. 예전 승인 대기를 현재 미확보 상태로 읽지 않는다.

원본 아카이브와 해제본은 수정하지 않는다. 변환·리사이즈·분할 결과는 별도 파생물로 보관하며, 실제 저장 경로는 공개 문서에 싣지 않는다. 개인 드라이브에서 공유 드라이브로 이전한 뒤 사용한 논리 경로는 `<공유 드라이브>/<프로젝트 폴더>/weld-fl-datasets/`다.

과거 다운로드에서는 파일이 예외 없이 잘리거나 경고 HTML이 압축파일로 저장된 사례가 있었다. 성공 여부는 명령 종료만으로 판단하지 않고 기대 바이트 수·아카이브 형식·CRC를 대조한다. 동기화 폴더의 존재나 계정 전체 사용량만으로 클라우드 업로드를 확정하지 않는다. 한글 경로와 대괄호가 든 파일명은 실제 경로를 그대로 읽는 방식으로 처리해야 한다.
