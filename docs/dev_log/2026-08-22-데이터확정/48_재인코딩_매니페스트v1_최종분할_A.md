## 5. 총괄 판단이 필요한 것

### 5-1. pHash 묶음(E3)이 아직 안 들어갔다

현재 묶음은 연속 id 축 하나로만 만들어져 있다. 원천 이미지가 없던 시점의 v0 방식이
그대로 남아 있다. 타일이 생겼으므로 이제 pHash 를 돌릴 수 있으나, 임계 t\* 는
`configs/base.yaml` 에서 `threshold_final: null` 이고 실데이터 눈 확인으로 정하도록
되어 있다. 임계 결정은 지정 함정 구간이라 단독으로 정하지 않았다.

**이것이 분할에 미치는 영향을 분명히 해 둔다.** 묶음은 합쳐질 뿐 쪼개지지 않으므로,
E3 를 나중에 더하면 지금 서로 다른 split 에 있는 두 묶음이 한 묶음으로 합쳐질 수 있다.
그러면 현재 분할은 묶음 원자성을 잃고 다시 돌려야 한다. **잠그기 전에 E3 를 확정하고
분할을 한 번 더 돌리는 순서가 맞다.**

### 5-2. Dirichlet 재추첨 17회

v0 의 15회에서 17회로 늘었다. 수용 밴드 0.60~0.73 안에 들기까지 17번 다시 뽑았다는
뜻이다. 실현 지분 0.6319 는 밴드 가운데에 가깝다. 재추첨 횟수가 많다는 것은 농도 벡터가
목표 지분과 밴드에 비해 퍼져 있다는 신호이고, 시드를 바꾸면 결과가 크게 달라질 수 있다.
농도 벡터를 조정할지 밴드를 넓힐지는 결정 사항이라 그대로 두고 보고한다.

## 6. 발견: 라벨 id 와 원천 파일명이 어긋난 10건

라벨 JSON 의 `info.id` 로 원천 이미지를 찾으면 10장을 잃는다. `info.id` 와 파일명 꼬리
숫자가 다른 레코드가 10건 있다.

| 13121 | RT_ST_02_62757373 |
| 15353 | RT_ST_02_27230305 |
| 18889 | RT_ST_02_66475738 |
| 41621 | RT_ST_02_36202316 |
| 78192 | RT_ST_02_85910118 |

| 169968 | RT_ST_02_61446442 |
| 171731 | RT_ST_02_59511439 |
| 8304898 | RT_AL_00_43478135 |

원천과 이어지는 키는 `image_data.file_name` 하나다. 전수 대조에서 `file_name` 은
62,998건 모두 원천에 있고 `info.id` 는 충돌이 없다. 따라서 매니페스트 키는 id 로 두고
원천 조회만 파일명으로 한다.

이 종류의 실패는 조용하다. 못 찾은 장을 건너뛰면 폐기 회계가 틀린 채로 맞아 보인다.
원천을 못 찾으면 건수를 세어 보고하고 멈추도록 했다.

## 7. 잠그지 않았다

`split_meta.json` `tile_accounting.json` `encode_progress.jsonl` 이 있다.
