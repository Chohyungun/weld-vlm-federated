## 과제 2 — P9 를 파일럿 필수 산출물로 등록

### 구현

`evaluation/probes/p9_runner.py` — 공통 스키마 출력에서 계산하는 브리지.

- **입력**: 다섯 칸 공통 예측 레코드(계약 #4) + 동결 스냅샷(매니페스트 + `tiles.csv`).
- **오탐의 단일 정의**: `parse_ok` 이고 예측 결함 집합이 비어 있지 않은 정상 이미지.
  파싱 실패는 예측 공집합(스펙 §4-1)이라 오탐이 아니다 — 실패율이 따로 센다.
- **정상 여부는 GT 로 정한다** (매니페스트 `has_defect`). 예측으로 정하면 오탐 많은
  칸일수록 분모가 줄어드는 순환이 생긴다.
- 채점 누락 이미지는 '오탐 아님'으로 채우지 않고 **결측으로 센다.**
- N-band 는 집계에서 제외하되 건수를 보고한다.
- 판정: 묶음 클러스터 부트스트랩 2,000회 + TOST δ=0.10. 검정력 부족은 **판정 불가**
  (통과 아님).
- `p9_all_cells()` 가 (칸, 시드)로 갈라 **같은 함수로** 전 칸을 처리한다. 칸 이름으로
  분기하는 코드는 없다. 칸·시드가 섞인 입력은 거부한다.

시험 16건 (`tests/test_p9_runner.py`). TOST 의 저검정력 방어가 실제로 작동하는 것도
시험으로 고정했다 — FP 율이 같아도 묶음 40개로는 CI 가 δ 를 넘어 동등 판정이 나오지
않으며, 이는 결함이 아니라 성질이다.

### 대상 모집단 (동결 스냅샷 실측)

| 출처 | 평가셋 정상 | 처리 |
|---|---|---|
| N-crop | **654** | 집계 |
| N-tile | **4,697** | 집계 |
| N-band | 24 | 제외, 건수 보고 |
| 합 | 5,375 | |

**지시서의 "N-crop 7,740장"과 다르다.** 7,740 은 평가셋 N-crop **전체**
(결함 7,086 + 정상 654)다. P9 의 정의가 "평가셋 **정상** 이미지의 FP 율"이므로 정상
654 가 맞는 모집단이다. N-tile 4,697·N-band 24 는 지시서와 정확히 일치한다.
654장이면 묶음 수십 개 규모라, 시드·칸별로 검정력이 판정 불가로 떨어질 수 있다 —
그 경우 "동등"이 아니라 "판정 불가"로 보고되며 그것이 설계다.
