# 매니페스트 v0 · 예비 분할 · 타일 규칙 캘리브레이션

2026-08-24 · 실행 순서 40번 4-1 의 ①②③ · 재현 `scripts/build_manifest_v0.py`

> 요약. RT 62,996장으로 매니페스트 v0 을 만들고 예비 분할(잠그지 않음)을 낸 뒤 학습
> 풀에서만 타일 규칙을 캘리브레이션했다. 밴드 높이가 타일을 넘는 4.05% 의 처리를
> **폐기가 아니라 밴드 중심 크롭**으로 정했다. 폐기로 두면 AL 정상 폐기율이 6.415% 로
> 상한 5% 를 넘어 진행이 막힌다.

## 1. 실행 순서를 지킨 방식

```
① 매니페스트 v0   라벨 JSON 전수, 규격은 라벨의 width/height
② 예비 분할       묶음 단위, 재질×클래스 층화 20%, 시드 20260825, 잠그지 않음
③ 캘리브레이션    ②의 학습 풀에서만. 평가셋 행은 읽지 않는다
```

②를 ③보다 먼저 두는 이유는 전처리 상수가 평가셋 통계에서 유도되면 평가 격리가 실질에서
깨지기 때문이다. `calibrate()` 는 `split != "eval"` 로 거른 뒤에만 통계를 집계한다.

**v0 는 스냅샷이 아니다.** 원천 이미지가 로컬에 없어 `sha256` 과 `phash_hex` 가 비어 있다.
잠그지 않았고 스냅샷 디렉터리에도 두지 않았다(`data/interim/manifest_v0/`). 타일링 후
실파일에서 해시와 규격을 다시 읽어 v1 을 만들고 그때 잠근다.

## 2. 매니페스트 v0

| 항목 | 값 |
|---|---|
| 이미지 | 62,996 (라벨 전수 62,998 에서 2장 제외) |
| 결함 인스턴스 | 109,140 |
| 묶음 | 6,328 (연속 id run, 모달×재질 안에서) |

### 제외 2장: 라벨 공간 밖 클래스

RT 라벨의 `case` 값을 전수로 세면 5종이다.

| case | 장수 |
|---|---|
| porosity | 26,987 |
| lack of fusion | 3,327 |
| crack | 2,376 |
| slag inclusion | 2,108 |
| **incomplete penetration** | **2** |

`incomplete penetration`(용입불량)은 계약 #1 의 `sources.aihub71761` 에도,
`eval_spaces.main_rt` 에도 없다. main_rt 는 "AI허브 RT 에 용입불량이 존재하지 않는다"는
전제로 이 클래스를 제외해 두었는데, 실물에 2장 있다. 계약이 동결 상태라 임의로 넓히지
않고 **이미지 단위로 제외**하고 건수를 회계에 남겼다. 폴리곤만 빼면 결함이 있는 이미지가
정상처럼 남으므로 이미지째 뺀다.

판단이 필요하다: 계약 #1 에 용입불량을 더할 것인가, 2장 제외를 유지할 것인가. 2/34,604 =
0.006% 라 제외로 두어도 실험에 영향은 없다.

### 다중 클래스 이미지

한 이미지에 두 종류가 섞인 경우가 180장 이상이다(`lack of fusion` + `porosity` 106,
`porosity` + `slag inclusion` 48, `crack` + `porosity` 26 등). 폴리곤마다 `case` 를 읽어
결함 인스턴스별로 클래스를 매긴다. 이미지 대표값으로 뭉뚱그리면 이 이미지들이 오라벨된다.

### 결함 종류가 없는 폴리곤 1개

id 14520899 에 `case` 가 빈 폴리곤이 하나 있다. 1298×723 으로 이미지(1280×720) 전체를
넘는 크기라 결함 표시가 아니라 이상 어노테이션이다. 그 폴리곤만 건너뛰고 같은 이미지의
기공 결함은 살렸다. **결함 이미지가 밴드 폴리곤을 갖는 사례가 아니다.** RT 전체에서 1건
뿐이고, 밴드 점유율 비대칭을 라벨로 못 잰다는 기존 판단은 그대로다.

## 3. 예비 분할 (잠그지 않음)

| | 값 |
|---|---|
| split | train 45,353 / eval 12,600 / val 5,043 |
| client | C1 26,323 / C2 16,918 / C3 7,155 |
| Dirichlet | 농도 (1/3, 1/6), 채택 시드 20260842, 시도 15회, 실현 C1 지분 0.6088 |

평가셋 12,600 은 62,998 의 20% 기준값과 맞는다.

**Dirichlet 재추첨이 15회 걸렸다.** 수용 밴드 [0.60, 0.73] 의 하단에 겨우 들어왔다
(0.6088). v0 의 묶음이 연속 id run 이라 묶음 하나가 크고(평균 10장) 배분 알갱이가 굵기
때문이다. 타일링 후 v1 에서 pHash 엣지가 더해지면 묶음은 더 커지므로 이 경향은 강해진다.
시도 횟수와 채택 시드를 기록해 두었고, v1 에서 다시 15회 이상 걸리면 밴드 폭을 재검토해야
한다.

## 4. 캘리브레이션 (학습 풀에서만)

`tau_mode: band_containment` 로 확정된 규칙을 학습 풀 정상 이미지 22,669장에 적용했다.

| | 값 |
|---|---|
| 밴드가 타일 안에 들어감 | 21,750 (95.946%) |
| 밴드가 타일보다 큼 | 919 (4.054%) |

### 밴드 초과 4.05% 의 처리: 폐기가 아니라 밴드 중심 크롭

밴드가 타일보다 크면 포함 관계가 뒤집혀 **tile ⊆ band** 가 된다. 이때 타일의 모든 화소가
검사된 용접부 안에 있으므로 정상 승계가 오히려 더 안전하다. 미검사 영역 문제는 반대
방향(tile ⊋ band)에서만 생긴다. 따라서 크롭을 허용하고 폐기하지 않는다.

폐기를 택했다면 이렇게 된다.

| 재질 | 초과 비율 | 4-4 정상 셀 상한 5% |
|---|---|---|
| RT/AL | **6.415%** | **초과. 진행 보류** |
| RT/ST | 3.580% | 이내 |
| 재질 간 차 | 2.835%p | 이내 (상한 5%p) |

AL 이 상한을 넘어 게이트가 막힌다. 다만 **상한을 피하려고 규칙을 고른 것이 아니다.**
포함 방향이 뒤집힌다는 사실이 먼저이고, 상한 충돌은 그 사실의 결과다. 순서를 바꿔 읽으면
결과에 맞춰 규칙을 느슨하게 한 것이 되므로 분명히 해 둔다.

폐기 회계에는 별도 셀 `oversized_band_cropped` 로 잡았다. 폐기가 아니므로 폐기율에
합산되지 않지만, 크롭된 919장은 다른 타일과 생성 경로가 다르므로 건수를 남긴다.
