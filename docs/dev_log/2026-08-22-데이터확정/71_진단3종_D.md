**세 지표가 소수 4자리까지 항등이다.** 유일한 예외인 분리·중앙 Macro-F1 +0.0021 은

빠지면서 균열 정밀도가 0.8750 → 1.0000, 균열 F1 이 0.3415 → 0.3500 으로 오르고,

나머지 여섯 칸은 N-tile 정상 오탐이 0건이라 뺄 것이 없다.

### 왜 항등인가 (산술)

`score_detection` 은 이미지 수준 다중라벨이고 **진음성 항이 없다.** 정상 이미지는 오직
FP 원천으로만 들어가는데, 일곱 칸 중 여섯이 N-tile 정상에서 FP 가 0이다. 따라서 N-tile
정상을 빼도 tp·fp·fn 이 한 자리도 움직이지 않는다. 결함 놓침과 결함 recall 은 아예
결함 이미지에서만 계산되므로 **정의상** 불변이다.

**즉 "채점 모집단을 N-crop 으로 좁힌다"는 조치는 헤드라인 세 지표에 대해 무연산이다.**
승격(①)이든 채점 슬라이스 전환(③)이든 이 표가 같은 답을 준다.

### Class-Jaccard 만 움직이고, 방향이 지름길에 유리하다

| 모집단 | 지름길 규칙 | 최고 칸(통합·중앙) | 격차 |
|---|---|---|---|
| 전량 653 | 0.8267 | 0.7833 | **0.0434** |
| N-crop 431 | 0.7374 | 0.6717 | **0.0657** |

전량에서는 N-tile 정상 222장이 "양쪽 공집합 = 1.0" 규약으로 모든 칸에 공짜 점수를
준다. 그것을 빼면 전 칸이 내려가는데 **규칙이 가장 덜 내려간다**(−0.0893 대 −0.11~−0.30).
규칙은 N-crop 안에서 결함 388장을 전부 맞히므로 잃을 공짜 점수가 애초에 적다.

**결론: 이 조치는 지름길 대비 격차를 1.5배 벌린다.** "슬라이스로 지름길을 통제한다"는
서술은 이 표와 맞지 않는다.

## 2. 과제 2 — 출처 고정 판별력 (헤드라인 보조지표 후보)

### 2-1. 정의 — 승격 전제로 고정한다

    판별력 Δ = (결함 이미지 발화율) − (정상 이미지 발화율)   [출처 고정, 기본 N-crop]

구현 `evaluation/discrimination.py` · 시험 `tests/test_discrimination.py` 15건.

| 항목 | 정의 | 이유 |
|---|---|---|
| 계산 모집단 | 지정 출처(기본 `N-crop`)의 평가셋 이미지 **전량**. 결함·정상 둘 다 | 출처를 상수로 고정하는 것이 존재 이유다 |
| 결함/정상 판정 | 매니페스트 `has_defect`(GT). 예측으로 정하지 않는다 | 예측으로 나누면 분모가 모델마다 달라져 칸 간 비교가 깨진다 |
| 발화 | `parse_ok` 이고 예측 결함 집합이 비어 있지 않다 | **P9 와 같은 함수를 호출한다** — `p9_runner.is_false_positive` 가 `discrimination.fires` 를 부르도록 배선했다. 문서가 아니라 코드가 보증한다 |
| 파싱 실패 | 발화 아님(빈 예측), 분모에는 남는다 | 스펙 §4-1. 실패율은 별도 지표가 이미 센다 |
| 결측 | 레코드 없는 이미지는 **결측으로 세고 분모에서 뺀다** | 채점 누락을 '깨끗함'으로 읽으면 지표가 조용히 좋아진다 |
| CI | 묶음(`group_id`) 클러스터 부트스트랩, **차 자체를 재표집** | 이미지 단위면 CI 가 3배 좁아진다(`stats` 머리말) |
| 층 결측 재표집 | 한쪽 층이 통째로 안 뽑힌 재표집은 **0 으로 대치하지 않고 뺀다**(건수 보고) | 0 대치는 CI 를 0 쪽으로 끌어 "판별 불성립"을 공짜로 만든다 |
| 부호 | 양수 = 결함에서 더 발화 / 0 = 지름길선 / 음수 = **역전** | 0 이 실패선이 아니라 기준선이다 |

### 2-2. 지름길이 정의상 통과할 수 없다 — 증명과 실측

출처만 읽는 예측기는 출처가 상수인 구간에서 **상수 예측기로 퇴화**한다. 상수 예측기는
결함 이미지와 정상 이미지에 같은 값을 내므로 두 발화율이 같고 Δ = 0 이다. 이미지를
보지 않고 0 을 넘을 방법이 없다.

실측: 66번의 규칙("N-crop 이면 기공")을 같은 함수에 넣으면
**Δ = +0.0000, CI [+0.0000, +0.0000]** 이다(발화율 결함 1.0000 / 정상 1.0000).
시험 3건이 이 성질을 못박는다 — 발화하는 규칙·침묵하는 모델·N-tile 혼입 방지.

## 4. 과제 4 — ⑤ 판정부 프로브

### 4-1. 소요·VRAM 실측 (67번 §4-1 프로브 3, "1~7일" 자리값을 닫는다)

**평가셋을 열지 않았다.** 이 프로브의 산출은 그대로 예산·상수의 입력이 되므로 67번 §5-4
규칙을 그대로 적용해 **train 분할에서** 653장을 결정론적으로 뽑았다(시드 20260825).
프롬프트의 결함 목록은 **GT** 다 — 본실험 검출기가 GT 수준으로 검출할 때의 상한
프로파일이며, 미학습 파일럿 검출기(발화 10%)로 재면 본실험 비용을 과소평가한다.
`Qwen/Qwen3.5-0.8B` bf16 · 어댑터 없음 · greedy 1회 · `max_new_tokens` 512.

| 항목 | 실측 |
|---|---|
| 표본 | train 653장 (결함 0개 273장 → 질의 없음 → 무검색) |
| 생성 호출 | **380회** (58.2%). `greedy_once` 검사 통과, 재시도 0 |
| 벽시계 | 1,791초 (29.9분) |
| **이미지당** (무검색 포함) | **2.743초** |
| 생성당 | 4.714초 |
| 지연 p50 / p90 / 최대 | 4,457 / 5,252 / 12,852 ms |
| 프롬프트 토큰 p50 / 최대 | 283 / 659 |
| **출력 토큰 p50 / 최대** | **77 / 135** — 상한 도달 **0건** |
| 파싱 실패율 | **0.0000** |
| VRAM 가중치 / peak(allocated) / peak(reserved) | **1.589 / 1.689 / 1.721 GiB** |

**VRAM 은 병목이 전혀 아니다.** 0.8B bf16 텍스트 전용이라 peak 1.7 GiB 로, 16GB 로컬에서
검출 학습(0.24GB)·통합형 학습(4.97GB)과 나란히 놓아도 여유가 크다. 4B 로 올려도 bf16
가중치가 약 8GB 라 단독 실행은 들어간다.

**출력 토큰 최대 135 는 66번이 최악 형태로 계산한 149 와 같은 자리다.** 상한 도달이
0건이므로 `judge.max_new_tokens: 512` 는 3.8배 여유다(§5-5).

### 4-1-b. 외삽 — 다만 지금 구성에서는 이 비용이 0이다

이미지당 2.743초 × 동결 평가셋 12,461장 = **패스당 9.5시간**(0.8B). 4B 배율 ×3~5 를
곱하면 패스당 1.2~2.0일이다. 67번 §4-4 의 "⑤ 판정부 1~7일" 자리값은 **패스 수를 곱하기
전 값으로는 과대**였고, 패스 5개(분리형 5모델 × 대표 시드 1)를 곱하면 그 범위에 들어온다.

**단, 지금 구성에서 이 비용은 발생하지 않는다.** 66번 §9-1 대로 `verdict_mode:
clause_only` 에서는 두께 결측으로 검색 적중이 0이라 생성이 한 번도 호출되지 않는다.
이 프로브가 380회를 돈 것은 허용치 표 자신의 구간에서 유도한 대표 두께를 넣어 검색
경로를 태웠기 때문이며, **소요 측정 전용이고 지표가 아니다.** 즉 ⑤ 의 GPU 예산은
`conditional` 승격 결정(68번 §9 질문·66번 §12-3)에 종속된다.

한 가지 덧붙인다. 프롬프트의 조항 자리는 여전히 `(본문 미등재)` 다(§4-2). 지금 재고 있는
것은 **배관의 속도**이지 판정의 품질이 아니다.

### 4-2. 임베딩 후보 2종 — 다시 재지 않았다

지시대로 66번 §7 의 "변별 불가" 조건이 그대로인지만 확인했다.

| 조건 | 66번(9/1 오후) | 지금 |
|---|---|---|
| `corpus/derived/chunk_meta.jsonl` 청크 수 | 4 | **4 (변동 없음)** |
| 본문이 빈 청크 | 4 / 4 | **4 / 4 (변동 없음)** |
| dense 정렬이 필요한 질의 | 0 / 100 | 0 / 100 |

**조건이 그대로다.** 임베더 호출 경로에 진입하는 질의가 0건이고 정렬할 본문도 없으므로

## 5. 과제 5 — `max_new_tokens` 최종 권고

### 5-1. train+val 전용으로 다시 역산했다

66번은 파일럿 **생성문(평가셋 추론 결과)** 에서 회귀식을 뽑고 파일럿 표본 전체의 최대
결함 수(31)로 외삽했다. 67번 §5-4 가 그것을 금지한다. 그래서 **동결본 train+val
49,847장의 어노테이션만** 읽어 학습 타깃 JSON 을 그대로 만들고 실토크나이저
(`Qwen/Qwen3.5-0.8B`)로 셌다. **eval 12,461장은 코드 경로에서 걸러진다.**

    출력 토큰 = 26.2 + 29.82 × (결함 수)      (잔차 최대 11.7 · 결함 0개면 19)

66번의 `26 + 30 × N` 과 사실상 같은 식이 **평가셋을 열지 않고** 나왔다. 식 자체는
JSON 직렬화 형식과 토크나이저의 성질이지 표본의 성질이 아니라는 것이 이것으로 확인된다.

### 5-2. 최대 결함 수 — train+val 만으로 50이다

| 출처 | 이미지당 최대 결함 | 비고 |
|---|---|---|
| 파일럿 표본 3,279장 | 31 | 66번이 쓴 값 |
| **동결본 train+val 49,847장** | **50** | 71번 실측. **eval 미열람** |
| 동결본 전수 | 50 (68번) | eval 을 포함해도 같다 — train+val 이 이미 상한을 담고 있다 |

**67번 규칙(train+val 전용)과 68번 관측(전수 50)이 충돌하지 않는다.** 상한이 train+val
안에 있으므로 규칙을 지켜도 같은 수가 나온다. 66번의 31 만 파일럿 표본의 산물이었다.

### 5-3. 예산별 절단 회계 (train+val 49,847장 기준)

| `max_new_tokens` | 감당 결함 수 | 절단 이미지 | 비율 |
|---|---|---|---|
| **256** (C 가 쓴 값) | 7 | 2,041 | **4.09%** |
| 512 | 16 | 240 | 0.48% |
| 1,024 | 33 | 20 | 0.04% |
| **1,536** (66번 권고) | 50 | **0** | 0.00% |
| **2,304** (71번 권고) | 76 | 0 | 0.00% |

256 의 4.09% 는 C 가 평가셋에서 실측한 절단율 4.90% 와 같은 자릿수다 — 고장 7 의
원인 규명이 train+val 만으로도 재현된다.

### 5-4. 권고

**통합형 추론 `MAX_NEW_TOKENS = 2304`** (`scripts/pilot_export_vlm.py`, C 소유 파일).

1,536 은 감당 결함 수가 정확히 50 이라 **여유가 0이다.** 우리는 규칙에 따라 eval 을
열지 않았으므로 평가셋에 51개짜리 이미지가 있는지 모른다. 게다가 생성 모델은 GT 보다
많은 결함을 주장할 수 있고(파일럿 통합·중앙은 정상 이미지에도 평균 1.30개를 냈다),
그 초과분이 절단되면 **결함 놓침이 토큰 예산 인공물로 오른다** — 다섯 칸 전부에서
같은 방향으로 오르므로 이상치로도 드러나지 않는다. 여유 계수 1.5 를 곱한
`ceil(1529 × 1.5 / 64) × 64 = 2304` 를 권고한다.

비용은 거의 오르지 않는다. greedy 는 EOS 에서 멈추므로 긴 예산을 실제로 쓰는 것은
다결함 이미지뿐이고, KV 캐시도 동적 할당이라 VRAM 상수 비용이 아니다.

### 5-5. 판정부 `judge.max_new_tokens` — **512 유지. 승인 경로 불발동**

판정부 출력은 결함 수에 비례하지 않는다(`{verdict, cited_clauses, basis}` 고정 구조).
66번이 최악 형태를 직접 세어 149 토큰, 이번 프로브의 실측 출력 토큰은 아래 §4 표에 있다.
**512 는 그 배수 이상이므로 값을 바꿀 이유가 없다.**

`configs/rag.yaml` 값 변경은 색인 스냅샷 재부여 사유이고 총괄 승인 사항인데,
**변경이 없으므로 그 경로를 발동하지 않는다.** 만약 총괄이 통합형과 판정부의 상수를
하나로 묶기로 하면 그때 승인 경로가 필요하며, 그 경우 판정부 예산이 4.5배 과다해지는
대신 상수 관리가 하나로 준다 — 권고는 **묶지 않는 것**이다(형식이 다르다).

## 6. 과제 6 — 채점 모집단 선택지 비용표

기준: 통합형 이미지 생성 실측 **7.72초/장**(61번 §4, 653장 1.4시간) · ⑤ 판정부 실측
**2.743초/장**(§4-1) · 4B 배율 ×3~5(미실측, 67번 §4-4) · 패스 수는 67번 §2-4
(분리형 5모델 × 시드 + 통합형 2칸 × 1시드).

| 축 | 전량 12,461 × 시드3 | 전량 × 시드1 | 층화 부표본 2,000 × 시드1 |
|---|---|---|---|
| 채점 장수 | 12,461 | 12,461 | **2,108**(실현값) |
| 패스 수 (분리형 ⑤ / 통합형) | 17 (15 / 2) | 7 (5 / 2) | 7 (5 / 2) |
| GPU-일, 지시서 단가 7.72초 일괄 (0.8B) | 18.9 | 7.8 | 1.3 |
| GPU-일, 지시서 단가 (4B ×3~5) | 56.8 ~ 94.6 | 23.4 ~ 39.0 | 4.0 ~ 6.6 |
| **GPU-일, 실측 단가 분리** (0.8B) | **8.2** | **4.2** | **0.7** |
| **GPU-일, 실측 단가 분리** (4B ×3~5) | **24.5 ~ 40.8** | **12.6 ~ 21.0** | **2.1 ~ 3.6** |
| P9 — N-crop 정상 장수 | 654 | 654 | **113** |
| P9 — N-crop 묶음 수 | **248** | **248** | **42** |
| P9 형식 판정(≥20 묶음) | 성립 | 성립 | 성립(42묶음) |
| P9 **실질** 판정 (아래 §6-1) | 12/12 조건 등가 성립 | 12/12 성립 | **상관 조건에서 2/3** |
| 자명하한(전량양성) | 0.2160 | 0.2160 | **0.2127** (−0.0033) |
| 사전등록 상수 | 그대로 | 그대로 | **표본 기준으로 재산출·병기 필요** |
| 심사 방어력 | 최상. 시드 분산까지 보고 | 표준. 시드 1 한계 명시 | **약함** — §6-1·§6-2 |

**⑤ 실측을 넣으면 예산이 절반 이하로 내려간다.** 지시서가 준 7.72초/장은 통합형 이미지
생성 단가인데, 17패스 중 15패스는 분리형의 ⑤(텍스트 전용, 2.743초/장)다. 전량×시드3
조차 4B 기준 24.5~40.8일로, 지시서 단가로 본 56.8~94.6일의 절반 이하다.
**이것이 "값싼 길을 배제한다"는 방침을 값싸게 만든다** — 전량 채점의 가격표가 생각보다 낮다.

두 가지 단서를 붙인다. 첫째, ⑤ 비용은 `verdict_mode` 가 `conditional` 로 승격될 때만
발생한다(§4-1-b). `clause_only` 를 유지하면 분리형 15패스의 생성 비용이 0이고 채점은
검출 출력만으로 끝난다 — 그때 이 표의 GPU-일은 통합형 2패스 몫(4B 기준 6.7~11.2일)만
남는다. 둘째, 4B 배율 ×3~5 는 여전히 미실측이다(67번 프로브 2 의 몫).

부표본은 **묶음 단위 층화 추출**로 시뮬레이션했다(`strata_key` 비율 유지, 시드
20260825). 이미지 단위로 뽑으면 불변조건 1-5 를 어기므로 후보가 아니다. 목표 2,000 에
대해 실현값이 2,108장 · 197묶음인 것은 묶음이 불가분 단위이기 때문이다.

### 6-1. 부표본이 무너지는 지점 — 형식이 아니라 정밀도다

**지시서의 예상("N-crop 정상 약 105장 → 묶음 최소선 미달")과 실측이 다르다.**
묶음 단위로 뽑으면 N-crop 정상 113장이 **42묶음**에 걸쳐 최소선 20 을 넘는다.
형식 판정은 성립한다.

무너지는 곳은 그다음이다. 등가를 주장하려면 차의 CI **전체**가 ±δ(0.10) 안에 들어와야
한다. 실제 묶음 구조 위에 두 출처에 **같은** 오탐률을 얹고(참값 차 0) 오탐 배치 시드를
3개 돌려 CI 반폭과 등가 성립 횟수를 쟀다.

| 오탐률 | 묶음 내 상관 | 전량(248묶음) 반폭 중앙[범위] | 등가 | 부표본(42묶음) 반폭 중앙[범위] | 등가 |
|---|---|---|---|---|---|
| 0.02 | 없음(낙관) | 0.0126 [0.0110, 0.0132] | **3/3** | 0.0267 [0.0244, 0.0268] | 3/3 |
| 0.02 | 완전(보수) | 0.0181 [0.0178, 0.0308] | **3/3** | 0.0455 [0.0303, 0.0601] | **2/3** |
| 0.05 | 없음(낙관) | 0.0186 [0.0172, 0.0196] | **3/3** | 0.0392 [0.0278, 0.0431] | 3/3 |
| 0.05 | 완전(보수) | 0.0376 [0.0308, 0.0564] | **3/3** | 0.0585 [0.0488, 0.0979] | **2/3** |

**전량은 12개 조건 전부 등가가 성립한다. 부표본은 상관 조건에서 세 번 중 한 번 무너진다.**
참값 차가 0인데도 무너지는 이유는 반폭만이 아니다 — 표본이 작으면 점추정 자체가 0에서
밀리고, 밀린 중심에 넓은 반폭이 붙으면 CI 한쪽 끝이 δ 를 넘는다.

**상관 조건이 현실 쪽이다.** 68번 §2-3-(f)가 평가셋 N-crop 정상 654장 중 647장(98.9%)이
결함 이미지와 같은 연속 촬영 묶음에서 나온 프레임임을 실측했다. 같은 묶음의 프레임은
거의 같은 그림이라 모델의 오탐도 함께 움직인다.

즉 부표본을 택하면 P9 는 형식적으로는 돌지만 **참값이 정확히 0인 이상적 상황에서도 세 번
중 한 번은 결론이 안 나는 검정**이 된다. 57번이 P9 를 파일럿 필수 산출물로 승격하며
걸었던 판단(크롭 한정본 승격 여부)이 본실험에서도 미결로 남을 확률이 그만큼이다.

**이미지 단위 추출로 바꿔도 해결되지 않는다.** 묶음을 쪼개면 불변조건 1-5 를 어기고,
같은 묶음의 프레임이 표본 안팎으로 갈려 부표본이 전량 평가셋의 축소판이 아니게 된다.
CI 는 좁아 보이겠지만 그 좁음이 곧 이 문서 §2-1 이 배제한 "이미지 단위로 내면 3배
좁아지는" 인공물이다.

### 6-2. 부표본이 추가로 무너뜨리는 것 둘

1. **사전등록 상수를 전부 다시 산출해야 한다.** 자명하한이 0.2160 → 0.2127 로
   움직인다(작아 보이지만 68번 §5 가 정리를 요구한 상수 7종이 전부 표본 의존이다).
   67번 §5 는 "축소·사전등록 상수는 첫 런 착수 전 확정"을 요구하는데, 부표본을
   9/4 에 정하면 상수 재산출이 그 뒤로 밀린다.
2. **검출 지표와 생성 지표의 모집단이 갈린다.** 67번 §7 질문 2 가 "검출 지표는 전량으로
   내고 생성 기반 지표만 자르는 것이 정합적"이라 적었는데, 그러면 Class-Jaccard 처럼
   두 축에 걸친 지표의 모집단이 무엇인지 표마다 각주가 붙는다. RQ2(구조 비교)는
   통합형과 분리형을 같은 표에서 비교하는 것이 목적이라 이 분기가 직접 걸린다.

### 6-3. 그래서 전량이어야 하는 이유 (총괄 방침과의 정합)

총괄이 값싼 길(통합형 강등·부표본 채점)을 배제했으므로 이 표는 그 판단의 근거표다.
부표본이 사는 것은 GPU-일 하나뿐이고, 실측 단가로 다시 계산하면 그 절감액이
**전량×시드1 대비 4B 기준 10.5~17.4일**로 줄어든다(지시서 단가로는 19~32일로 보였다).
그 대가로 **P9 결론·사전등록 상수·모집단 정합** 셋을 동시에 판다. 값이 안 맞는 거래다.

**전량 × 시드1** 이 현실적 절충이다. 시드3 대비 4B 기준 11.9~19.8일을 아끼면서
P9·상수·모집단을 전부 지킨다. 잃는 것은 시드 분산 보고인데, 그것은 65번·66번이 이미 "시드 1세트에서는
회복률을 헤드라인으로 쓰지 않는다"로 처리해 둔 항목이라 새 손실이 아니다.
다만 **검출 지표는 시드 3세트로 내고 생성 기반 지표만 대표 시드 1로 좁히는** 형태라야
RQ1(주 기여)의 분산 보고가 살아남는다 — 검출 추론은 CPU 로도 653장당 13~18초라
시드 3세트가 예산에 거의 걸리지 않는다(65번 실측).

### 7-1. `iso_codes` 구분자 오류의 영향 범위 — 전수 확인

| 소비처 | 영향 |
|---|---|
| 다섯 칸 지표표(65·66번) | **없음.** `read_gold` 가 `annotations.csv` 의 행별 `iso_code` 를 읽는다 |
| P9 · 발화율 분해 · 지름길 규칙 채점 | **없음.** `has_defect` / `n_defects` 만 쓴다 |
| `evaluation/probes/source_probe.py` | **없음.** 유일한 소비가 `if not r.iso_codes`(공집합 여부)라 다중 라벨도 참으로 남았다. R3 사다리 AUC 는 그대로다 |
| 66번 §9-1 정답 쌍 조회 건수 | 388 → **393** (§7-4) |
| 자명하한 산출 | **있었다.** 처음 계산에서 동결 평가셋 하한이 0.2160 대신 **0.2142** 로 나왔고, 구분자를 고치자 68번 값 0.2160 과 정확히 일치했다 |

마지막 줄이 이 오류를 잡은 경로다 — 68번의 독립 재현값과 어긋나서 찾았다.
**교차 재현이 실제로 오류를 잡았다는 기록으로 남긴다.**

## 9. 총괄이 결정할 것

1. **출처 고정 판별력 Δ 를 헤드라인 보조지표로 승격할지** (§2). 승격하면 결과표에
   칸마다 Δ 와 CI 가 붙고, "지름길선(0) 대비 위/아래"가 판정 문구가 된다.
   정의는 §2-1 에 고정해 두었고 코드·시험이 그것을 강제한다.
2. **채점 모집단** (§6). 권고는 **전량 × 시드1**, 단 검출 지표는 시드 3세트 유지.
   부표본은 P9 결론을 잃는 대가가 GPU-일 절감보다 크다.
3. **`MAX_NEW_TOKENS` 2304 를 C 에 반영할지** (§5-4). D 가 남의 트랙 파일을 고치지 않았다.
   판정부 512 는 변경 없음이므로 색인 스냅샷 재부여 경로는 발동하지 않는다.
4. **A 에 대조 요청**: §5-2 의 train+val 최대 결함 50 은 D 재현값이다. 68번 §7 이
   A 에 배정한 전수 산출과 대조해 한 값으로 확정해야 한다.
