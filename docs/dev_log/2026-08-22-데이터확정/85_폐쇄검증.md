## 3. 깨진 것 전수

### 3-1. 착수 차단 — 3건. 이것이 열려 있는 한 본실험 수치는 무효다

**① FedAvg 가중이 판정 2 를 위반한다 — `fl/client_vlm.py:134-135` 중복 키.**
`WEIGHT_KEY == "num-examples"`(`fl/strategy.py:45`)인데 metrics dict 리터럴이 같은
키를 두 번 쓴다: `{WEIGHT_KEY: 토큰, "num-examples": 페어 수}`. 파이썬은 뒤가
이기므로 **실제 전송 가중은 페어 수**다(실행으로 재현). 그런데
`fedavg_weight_unit`은 `"supervised_tokens"`로 남아 **회계가 단위를 거짓말한다.**
자기 문서 기준으로 C3 비중이 1.52배 어긋난 목적함수로 집계된다 — RQ3 직결.
묶음 3의 1차 검증과 묶음 5의 재검이 서로 모르고 같은 결함을 찾았다.

시험이 못 잡은 이유까지 확인됐다: 판정 2 고정 시험(`tests/test_fl_round_wiring.py:438`)
은 소스 문자열 포함 검사라 깨진 코드에서 통과하고, 스모크는
`fl/pilot_sim.py:82`가 두 키에 같은 값을 실어 원리적으로 충돌을 못 본다.

**처방 경고 — 1차 검증의 처방("135행 키 개명 한 줄")을 그대로 쓰면 안 된다.**
재검이 정정했다: `"num-examples"`는 가중 키이자 페어 수의 의미 키라, 개명만 하면
`fl/round_wiring.py:68`·`:80`, `fl/server_app.py:65`가 토큰을 페어 수 자리에 쓰고
페어 수는 산출물에서 사라진다. 올바른 수정은 **가중 키를 의미 키에서 분리**
(`WEIGHT_KEY="fedavg-weight"` + `fl/strategy.py:45`·`fl/round_wiring.py:104`
`WEIGHT_METRIC`·`fl/client_det.py:78` 동시 변경)하고, 문자열 시험을 행동 시험
(dict 실구성 또는 `fedavg_weight==supervised_tokens` 감사)으로 바꾸는 것이다.
같은 묶음의 부수 결함 3건을 함께 닫는다 — `WEIGHT_METRIC` 동일성 시험 부재,
검출 클라이언트의 weight-unit 미기록(`fl/client_det.py:104-110`), 재개 경로의
`supervised_tokens` 기본값 0(`vlm/pilot_vlm.py:289` — 구판 체크포인트 재개 시
조용한 과소 가중). — **C**

**② `verify_against_prereg`가 낡은 상수 위에 있다 — `evaluation/prereg.py:35`.**
자명하한 0.2081 리터럴 잔존. 76번 재산출(동결 평가셋 기준 0.2160)이 미반영이고,
`RT_TOTAL` 62,998·규격전용 0.3025 도 그대로다. 시험(`tests/test_prereg_probes.py`)도
낡은 리터럴로 호출해 통과하는 짝 — 상수를 갱신할 때 시험 리터럴 3곳(:72·:76·:82)을
함께 갱신해야 한다. §4-6 게이트 판정 자체는 무사하다(CI 하한 0.4934 는 재산출
0.2160 의 2.28배, 규격전용 최적선 0.3025 의 1.63배) — 낡은 것은 판정이 아니라
비교선의 출처다. 다만 본실험 결과표에는 평가셋 기준 재산출값을 병기해야 한다. — **D**

**③ 게이트 함수 4종의 실호출처가 0건.** `verify_against_prereg`·
`recovery_denominator_ok`·`guard_no_cloud_logging`·`require_tags` — 정의와 시험
리터럴 호출뿐, 게이트 레지스트리(`evaluation/gates.py`)도 부재. C 몫 2종
(`deterministic_torch`·`check_cells_identical`)은 배선·산출물 기록까지 확인됐으나
항목 18 은 전체로는 미폐쇄다. 82번이 D 소관으로 명시 이관했으므로 허위 보고는

### 3-2. 본실험 진입점 계열 — Major 3건, 합치면 항목 14 미폐쇄 사유

**④ `flwr run` 진입점(`fl.server_app:app` main)이 어떤 실행에서도 끝까지 돈 적이
없다.** 런타임 스모크는 `run_simulation`(pilot_sim) 진입점만 돈다. server_app 고유
구간(run_config 파싱·`_load_initial`·`_as_list`)은 실행 이력 0 — F1(진입점이 죽은 채
커밋)과 같은 부류의 사각. 게다가 pilot_sim 이 얹힌 `run_simulation`은 flwr 1.33 이
deprecated 로 경고하는 API 다.

**⑤ 등록된 유일한 clientapp(`fl.client_det:app`)의 train 핸들러가 죽어 있다.**
`in_cfg["round"]`(:131)를 읽는데 flwr 1.33 전략은 `config["server-round"]`를 준다 —
`flwr run` 시 라운드 1 KeyError(정적으로 증명 가능). `run_cfg["data-yaml"]`·
`node_cfg["num-examples"]`도 안 오는 키이고, 서버가 보내는 키는 전부 무시한다.
리터럴 금지 시험의 검사 파일 목록에 정작 `client_det.py`만 빠져 있다 — 포함시키면
즉시 실패한다.

**⑥ ⑦(통합·연합)을 `flwr run`으로 띄울 방법 자체가 없다.** pyproject 주석이 말하는
`uni-fed` 페더레이션이 `[tool.flwr.federations]`에 정의돼 있지 않고,
`fl.client_vlm:app`은 어디에도 등록돼 있지 않으며, client_det 에는 cell 분기가 없다.
"두 컴포넌트가 해석된다"(import 성공)와 기동 가능성은 다른 문제였다.

④~⑥ 을 합치면: 본실험 명세가 요구하는 진입점은 실질 부재이고, 지금 도는 것은
deprecated API 위의 시뮬레이션 경로뿐이다. — **C**

### 3-3. 그 밖의 Major — 3건

**⑦ `fl/run_gates.py:93` — 지문이 1개면 `cells_identical: true`로 적는다.**
82번 §8 의 "하나뿐이면 null + 사유" 주장과 다르다(0개일 때만 null). 실호출부

없이 "통과"가 기록된다 — 이 게이트가 잡으려던 무이빨 형태의 재발. — **C**

**⑧ 판정 2·정본 우회 방지 시험이 문자열 수준이다.** ①에서 본 가중 시험 외에도

확인뿐이라 `nn.CrossEntropyLoss()`·`F.nll_loss`·`model(labels=…)`(HF 내부 mean) 우회를
전부 통과시킨다. 현재 코드가 깨끗한 것은 직접 열람으로 성립하는 것이지 이 시험들
때문이 아니다. (재검이 `labels=` 채널을 전수 확인 — 현재 vlm/ 에 해당 호출 없음.) — **C**

**⑨ `tests/test_fl_round_wiring.py:32`의 모듈 수준 `importorskip("flwr")`.**
CLAUDE.md 가 경고하는 `uv sync --extra` 사고로 flwr 가 걷히면 항목 16 이빨 시험
19건 전체가 조용히 skip 되어 초록으로 보인다 — 무이빨 재발의 잔존 경로. — **C**

## 5. 남은 착수 조건

순서대로. ①~③이 코드 수정, ④~⑥이 트랙 보고, ⑦이 재실행이다.

1. **C — 가중 키 분리 수정** (3-1 ①). 처방 경고 준수: 개명 한 줄 금지,
   `WEIGHT_KEY` 신설 + 읽는 쪽 4곳 동시 + 행동 시험 교체 + `WEIGHT_METRIC` 동일성
   시험 + client_det weight-unit + 재개 경로 기본값. 이 수정 전에 ⑦ 재실행을 돌리면
   그 산출물이 또 인용 금지가 된다.
2. **C — flwr run 경로 소생** (3-2). client_det 의 `server-round` 키 정정, ⑦ 기동

   flwr 버전 고정), 리터럴 금지 시험에 client_det.py 포함, 두 진입점 스모크.
3. **C — 소소 3건.** run_gates 지문 1개 처리(⑦), importorskip 방호(⑨), 기준 3 CI
   산출 추가(m1 — `stats.py drop_undefined` 가 이미 있다).
4. **D — 83번 보고.** prereg 상수+시험 리터럴 동시 갱신(②), 게이트 4종 배선 +
