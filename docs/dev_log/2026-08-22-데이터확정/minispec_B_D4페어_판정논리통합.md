# 미니스펙 — D4 페어 판정 논리 통합 (함정 #6)

- 트랙 B · 작성 2026-09-01 · **총괄 게이트 대기. 구현 착수 전이다.**
- 배경: 74번 감사 P4(Critical·절차) · M9(Major) 소급 검토 결과. 상세는 `78_감사수정_B.md`.
- 대상 코드: `corpus/generate/make_pairs_pilot.py` · `corpus/rules/skeleton_gen.py`
  · `corpus/rules/clause_text.py`
- 대상 자산: `data/processed/pairs_pilot_v1/` (동결본, 손대지 않는다) · 본실험 D4 페어

## 1. 왜 미니스펙이 필요한가

지시서가 `skeleton_gen.py` 사용을 명시했는데 `make_pairs_pilot.py` 가 그것을 import 하지
않고 신규 생성기를 썼다. 소급 대조에서 **두 생성기의 판정 논리가 재질 축에서 갈렸고,
동결본 2,625건 중 219건이 그 갈림 위에 있다**(알루미늄 이미지에 강재 전용 조항 인용).

여기서 결정할 것은 "코드를 어떻게 합칠까"가 아니라 **알루미늄 페어를 어떻게 취급할
것인가**다. 그 선택이 C3(알루미늄 클라이언트)의 학습 자산 규모를 바꾸고, 따라서 RQ3
(소규모·특수재질 회사의 연합 참여 이득)이 무엇을 잰 값인지를 바꾼다. 트랙이 단독으로
정할 사안이 아니다.

## 2. 확정된 사실 (게이트 입력)

측정 스크립트와 수치는 78번 §1 에 있다. 결론만 옮긴다.

| # | 사실 | 근거 |
|---|---|---|

| F2 | 스케일·두께를 가정 주입해 강제 통과시키면, **강재 4개 코드의 조항 선택이 두 생성기에서 완전히 일치**한다 (2011→KRA27-T15, 301·401→KRA27-T16, 100→KRA27-3D) | 실측 |
| F3 | **알루미늄은 갈린다.** `applicable_row` 는 재질 축을 보고 해당 행 없음으로 거절하고, `clause_basis` 는 재질을 보지 않아 강재 조항을 그대로 붙인다 | 실측 |
| F4 | 동결본에서 그 영향은 **219건**(train 153 · val 66), 전체 2,625건의 8.3% | 실측 |

| F6 | `clause_basis` 는 `limit_op`·`ratio_basis` 도 읽지 않는다 — "이하"·"모재 두께"가 f-string 상수다 (M9 의 뿌리). 파일럿 12행이 전부 `le`·`t` 라 사고가 안 났을 뿐 | 코드 |

## 3. 제안 — 조항 선택을 정본 한 곳으로 모은다

축(조항 검색 + 기준 서술, 합부 없음)은 그대로 둔다. 바꾸는 것은 **행 선택과 문장화의
소재지**뿐이다.

```
현재  make_pairs_pilot.clause_basis()        ← 자체 필터 (scope·검사방식만)
                                             ← 자체 문장화 ("이하"·"모재 두께" 상수)

제안  corpus.rules.limit_eval.rows_for_clause / applicable_row  ← 행 선택 정본
      corpus.rules.clause_text.criterion_ko / clause_text       ← 문장화 정본
                                             (limit_op·ratio_basis 를 읽는다)
```

`clause_text.py` 는 과제 4 로 이미 들어갔고 `corpus/derived/` 본문이 그것으로 나온다.
즉 **정본은 이미 있다.** 남은 것은 `clause_basis` 를 그쪽으로 갈아끼우는 일이다.

`skeleton_from_label` 을 D4 페어 경로로 쓰지 않는 이유는 F1 이다 — 그 함수는 치수 합부
축의 골격 생성기이고, 스케일·두께 없이는 정의상 아무것도 만들지 못한다. **본실험에서
픽셀→mm 변환이 확보되면(함정 #10, 트랙 F) 그때는 그 경로가 정본이 된다.** 지금의 축
축소는 잠정이며, 그 사실을 코드 도크에 남긴다.

## 4. 게이트 판단 사항 — 알루미늄 페어

셋 중 하나를 골라 달라. 어느 쪽이든 동결본 v1 은 건드리지 않는다.

| 안 | 처리 | 본실험 C3 결함 페어 | 위험 |
|---|---|---|---|
| **A** 격리 | 재질을 덮는 행이 없으면 `no_applicable_row` 로 폐기, 통과율에 기록 | 0 건 (정상 페어만 남음) | C3 가 결함 학습 신호를 잃는다. RQ3 의 "특수재질 참여 이득"이 정상/결함 불균형 이득으로 바뀐다 |
| **B** 조항 없음 서술 | 결함은 서술하되 "적용 가능한 허용치 조항을 특정할 수 없다"로 닫는다. `clauses=[]` | 전량 유지 | 조항 검색 축에서 C3 만 정답이 공집합이다. 채점기가 이 경우를 어떻게 볼지 D 와 합의 필요 |
| **C** KS-AL 확보 대기 | 트랙 F 가 알루미늄 허용치를 확보할 때까지 D4 알루미늄 페어를 만들지 않는다 | 확보 시점까지 0 건 | 일정 위험. 9주 안에 못 받으면 A 와 같아진다 |

**B 를 권한다.** 축이 "조항 검색 + 기준 서술"이고 합부를 말하지 않는 상태에서, 근거가
없다는 것을 명시하는 문장은 지어낸 것이 아니라 사실이다. A 는 C3 결함 페어를 통째로
없애 RQ3 을 인위적으로 만들고, C 는 통제 못 하는 외부 일정에 D4 를 건다. 다만 B 는
D 의 채점기가 "정답 조항 공집합"을 어떻게 세는지에 달려 있어, **D 합의가 선행 조건**이다.

## 5. 함께 처리할 것 (게이트 승인 시)

1. **M9 해소** — `criterion_ko` 가 `limit_op`·`ratio_basis` 를 읽으므로, 부등식 방향
   검사가 생성문과 **CSV 행**을 비교하게 된다. 지금은 생성기가 박은 상수를 생성기가
   다시 찾는 자기참조다. 검사 대상이 바뀌므로 `check_pair` 도 함께 손봐야 한다.
2. **개행 고정** — `make_pairs_pilot` 이 `write_text` 로 써서 `pairs.jsonl` 이 CRLF 다.
   `newline=""` 로 바꾼다. **바꾸면 v1 의 SNAPSHOT.sha256 과 바이트가 달라진다** — v1 은
   그대로 두고 재생성분부터 적용한다(v2 로 이름을 가른다).
3. **M10 해소** — `geom_valid=False` 어노테이션을 기록 없이 스킵해 manifest `n_defects` 와
   4건 어긋났다. 스킵을 폐기 사유로 집계한다.
4. **64번 정정** — 재현 명령이 이제 재질 가드에서 멈춘다. 64번에 정정 블록을 붙였다.

  기록**하고 그대로 둔다. 파일럿 ⑥⑦ 학습은 이미 이 입력으로 끝났고 재실행하지 않는다.
- 축 확대(치수 합부 복원) — 함정 #10 이 풀리기 전에는 불가.
- `skeleton_gen.py` 의 D4 경로 삭제 — 스케일 확보 시 정본이 될 경로다. 손대지 않는다.

## 개정 (2026-09-02, 80번 체크리스트 20 수행 후)

체크리스트 20 을 수행하면서 §4·§5 의 상태가 바뀌었다. 게이트에 묻는 것도 줄었다.

### 이미 반영한 것 — 게이트 없이 진행한 근거

디스패치(체크리스트 20)가 **"재질 축·합계길이 정정, 회계 421건 두 종류 기록,
RQ2·RQ3 을 그 위에서 읽는다"** 로 지시했다. "정정 + 회계 + 페어는 남는다"는 §4 의
**안 B(서술)** 와 같다 — 안 A(격리)면 C3 결함 페어가 0건이 되어 "그 위에서 읽을" 것이
없어진다. 그 독해로 v2 를 만들었고, 총괄 독해가 다르면 되돌린다.

| 항목 | 처리 |
|---|---|
| 재질 축 | `clause_basis(table, material)` 가 재질 축을 본다. 덮는 행이 없으면 조항을 특정하지 않고 그 사실을 문장에 적는다. v2 에서 알루미늄 결함 페어 219건이 조항 미특정으로 나간다 |
| 합계길이 | 원천 표에 기계 표현으로 옮기지 못한 단서가 있는 조항에 **부기**를 단다. "위 기준만으로 합부를 결정하지 않는다" — 불완전한 규칙을 완전한 규칙으로 가르치는 것을 멈춘다 |
| M9 | 문장화가 `clause_text.criterion_ko` 정본을 지난다. `limit_op`·`ratio_basis` 를 읽으므로 부등식 방향 게이트가 더 이상 자기참조가 아니다 |
| 개행 | v2 는 LF 고정. v1 의 CRLF 는 그대로 둔다(동결본 해시가 그 바이트 위에 선다) |
| M10 | `geom_valid=False` 스킵을 레코드가 들고 다닌다(`n_annotations_skipped_geom_invalid`). 표본 전체 5건 |
| 좌표 | `coord_space: "ABS_ORIG"` 를 페어 레코드와 `PAIRS_META.json` 에 명시. 총괄 판정 1 (main 47c4dbc) |
| 회계 | `PAIRS_META.json.known_defects_in_v1` — 219 + 286 − 84(중복) = **421건, 28.16%**. 실측 확인 |

### 새로 올리는 것 — limits CSV 에 집계 기준 축이 없다

합계길이 정정이 **부기까지밖에 못 간 이유**가 이것이다.

`KRA27-T16` 은 원문에서 **합계 길이** 기준인데, `limits.csv` 스키마에는 `limit_type=길이`
로만 실린다. "개별 결함의 길이"인지 "결함 길이의 합"인지를 구분하는 축이 없다. 그래서
파생 문장이 개별 결함 한계처럼 읽히고, 동결본 286건이 그 상태였다.

기계로 말하려면 축이 필요하다. 후보:

```
measure_basis: individual | sum | count | score
```

이것은 **단일 소스 계약 변경**이다 (`EXPECTED_COLUMNS` + `LimitRow` + 로더 V1 검사).
파생 셋(골격·조항 본문·gold_clauses·chunk_meta·D4 기준 서술)이 전부 여기 얹혀 있어
트랙 B 단독으로 열 수 없다. 승인하면:

1. `limits_v0_pilot.csv` 에 컬럼 추가 + 12행 값 기입 (T16 6행 = `sum`, 나머지 `individual`)
2. `clause_text.criterion_ko` 가 축을 읽어 "합계 길이 6 mm 이하" 로 문장화
3. 부기는 남긴다 — 무시 하한·군집 간격은 여전히 미표현이다
4. 본실험 D4·corpus 재파생

원문 표기 필드(`limit_expr`·`source_row_label`·`note`)를 옮기는 방법은 쓰지 않는다.
KR-RULES-P2 가 KS B 0845 계열(유료) 표를 재수록하고 있어 셀 표기를 옮기면 유료 표준
표현이 색인에 들어가는 경로가 생긴다 (규약 2-5).

### 게이트에 묻는 것 (개정)

1. **§4 의 독해가 맞는가** — 체크리스트 20 을 안 B(서술)로 읽고 v2 를 만들었다. 아니면
   되돌린다. D 채점기가 "정답 조항 공집합"을 어떻게 세는지는 여전히 D 합의 사항이다.
2. **`measure_basis` 축 신설을 승인하는가** (위 §새로 올리는 것).
3. **`configs/corpus_validation.yaml` 소관** — 체크리스트 9 가 검증기 설정을 `configs/`
   에 고정하라고 했고 새 파일로 만들었다. A 의 파일은 건드리지 않았다. D 의
   `configs/rag.yaml` 과 같은 형태이며 감사 P13 이 소관 재배정으로 올린 항목이다.
4. **`skeleton_gen` D4 경로** — 스케일 확보(트랙 F) 전까지 여전히 골격 0건이다.
