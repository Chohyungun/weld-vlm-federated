## 1. 한 줄 답

**구라는 없다.** 네 트랙 모두 없는 수치를 지어내거나 불리한 결과를 숨긴 흔적이 없고, 확인 대상 109건 중 대부분이 기계 기록·독립 재계산과 일치했다. 다만 **결론을 바꾸는 오류가 6건 있고 그중 4건은 논문 수치나 실험 설계에 직접 걸린다.** 성격은 조작이 아니라 (가) 자기 산출물의 성질을 과신한 서술과 (나) 검증이 원리적으로 통과할 수밖에 없는 자기검사를 통과 근거로 올린 것이다.

특히 무거운 것 셋을 먼저 적는다.

- **C ⑦(통합·연합) 1라운드분이 사실상 폐기됐다.** LoRA A 초기화가 클라이언트별로 고정되지 않아 r0 집계가 "같은 기저의 평균"이 아니라 "독립 난수의 상쇄"였다. 전체 432스텝 중 144스텝(33%)이 버려진 셈이고, 함정표 #3 그 자체다.
- **A 의 게이트 선 0.3465 는 "content-free 계열의 최댓값"이 아니다.** 화소를 안 보는 메타데이터 규칙을 다르게 세우면 0.5940 까지 나온다. 지금 문구대로 논문에 실으면 게이트가 실제 천장보다 0.25 낮게 등록된다.
- **D 의 다섯 칸 비교에서 분리형만 conf 0.25 로 잘린 뒤 채점된다.** 통합형에는 대응하는 임계가 없다. RQ2 의 핵심 수치(결함 놓침 0.8142 대 0.2646)가 이 비대칭 위에 있다.

## 3. 불일치 전수

### 3-1. Critical — 결론을 바꾼다

**C-1. ⑦ 통합·연합 r0 의 LoRA A 초기화가 클라이언트별로 고정되지 않았다** (61번 §1 ⑦ 행 "함정 #3 3라운드 정상")

`vlm/pilot_vlm.py` 의 `_load_model()`·`train_rounds()` 어디에도 `get_peft_model` 앞 시드 고정이 없다. 저장소 전체에서 `torch.manual_seed` 는 `detection/init_weights.py:64` 한 곳뿐이며 그것은 YOLO 헤드용이다. `scripts/pilot_c.py` 의 `cmd_cell7` r0 에서 세 클라이언트가 모두 `adapter_in=None` 으로 각자 난수 A 를 만든다.

수치가 확증한다. r0 클라이언트 `param_l2` = 31.7405 / 31.6717 / 31.6238 인데 가중 평균 직후 `global_l2` = **20.5755** 다. `adapter_r001.npz` 를 열면 ‖A‖=20.5304, ‖B‖=1.3620. 가중치 w=(1275,656,342)/2273 로 독립 난수 A 를 가중합하면 ‖ΣwA‖ = 31.68 × 0.64852 = 20.55 가 예측되고 실측과 0.1% 차다. A 가 공유 초기값이었다면 ≈31.7 이 나와야 한다.

- 영향: r0 로컬 학습분 144스텝(전체 432의 33%)이 상쇄로 사실상 폐기됐다. r1·r2 는 global 을 주입받아 A 가 공유되므로 정상이다(norm 20.7 대 유지, 관측과 일치). **RQ2 의 통합·연합 칸 결과를 좌우한다.**
- 비대칭도 함께 지적한다 — 검출 칸에는 동일 출발 증명(`initial.npz` + `injection_digest`)이 있는데 VLM 칸에는 대응물이 아예 없고, 61번이 이를 언급하지 않는다.

**A-1. 게이트 선 0.3465 의 근거 진술이 사실과 다르다** (69번 §1 · `wt/A configs/base.yaml:127`)

"게이트는 content-free 계열의 최댓값"이라며 0.3465(통과선 0.3515)를 박았다. 그러나 화소를 보지 않는 메타데이터 규칙을 `image_id` 4분위 축으로만 세워도 Macro-F1 **0.3877**, 출처×재질×id4분위(11셀)면 **0.5940** 이다. 절반 적합·나머지 절반 채점으로도 0.3834 / 0.5958 이라 과적합이 아니다.

- 영향: 정확한 서술은 "출처·재질 두 축에 한정한 최댓값"이다. 지금 문구대로면 게이트가 실제 content-free 천장보다 0.25 낮게 등록된다. 함정표 #12(재질↔어노테이션 시기 교락)가 기준선에 그대로 새는 경로다.

**A-2. 게이트 상수 자체가 동결 평가셋의 정답 라벨 위에서 최적화됐다** (같은 파일, 1차 감사가 "격리 준수"로 통과시킨 항목)

`scripts/recompute_baselines.py` 의 `best_content_free()` 는 해당 모집단의 `gold` 로 만든 `pos_by_cell` 을 받아 클래스별 최적 셀 집합을 고른다. 즉 `material_only_best`·`source_only_best`·`source_x_material_best`(및 N-crop 쌍둥이)는 평가셋 라벨 유도값이고, 게이트 0.3465·통과선 0.3515 가 그 위에 선다.

- 방어 가능한 설계이긴 하다(게이트를 더 엄하게 만든다). 문제는 **문서·설정 어디에도 "평가셋 라벨로 적합했다"는 말이 없고**, 같은 `configs/base.yaml:140-141` 이 상수 박스에 대해서는 "평가셋 화소·통계에서 뽑으면 불변조건 1-4 가 실질에서 깨진다"고 정반대 기준을 적는다는 점이다. 한 파일 안에서 기준이 갈린다.
- 1차 감사의 "전처리 상수 3종 전부 train+val 유도" 확인은 사실이지만, 새로 박힌 6개 상수의 절반을 덮지 못한다.

**A-3. 어블레이션 두 팔이 서로 다른 평가 모집단에서 채점된다** (69번 §5)

구성표 2,097 / 2,098 은 맞다. 그러나 crop_only 의 eval 은 431장(전량 N-crop, 결함 388, 전량양성 자명하한 **0.2930**), scale_control 의 eval 은 418장(N-crop 276·N-tile 141·N-band 1, 결함 250, 자명하한 **0.2197**)이다.

- 영향: 두 팔의 content-free 바닥이 0.073 차이나므로 (크롭 한정 − 대조) 델타에 학습 변화가 아니라 채점 모집단 변화가 섞인다. 지시서가 "델타가 무엇을 잰 것인지 알 수 없다"며 대조 팔을 요구한 바로 그 혼입이고, 69번 §1 이 스스로 증명한 기제(전량양성 0.2160 대 0.3066)다. §5 는 평가셋 "크기"만 맞췄고 구성은 맞추지 않았으며, 어느 평가셋으로 채점할지도 지정하지 않았다.

**D-1. 분리형만 conf 0.25 로 잘린 뒤 채점된다** (65번, `scripts/probe/score_detection_cells.py:38`)

`CONF = 0.25  # Q4 기본값 — 5칸 공통. configs 확정 전 문서 기본값` 이 스크립트 상수로 살아 있고 `configs/*.yaml` 어디에도 conf 키가 없다. 통합형 2칸에는 대응하는 임계 자체가 없다.

- 영향: 단일 채점기라는 사실은 확인됐지만(칸 이름 분기 코드 부재), 그 **앞단**에서 분리형만 저신뢰 박스를 버린 뒤 들어간다. RQ2 의 핵심 대비인 결함 놓침 0.8142(분리·중앙) 대 0.2646(통합·중앙)이 이 비대칭 위에 있다.
- 부수: 확정 하이퍼파라미터가 `configs/` 밖에 있는 것도 개발규약 위반이다.

**C-2. 토큰 예산 처방의 분모가 절단이 만든 순환 관측치다** (61번 §2-7)

"파일럿 표본의 이미지당 최대 결함 수(관측 9개)에서 필요 토큰을 역산한다" — 9는 256토큰에서 끊겨서 나온 물리적 상한이다. 실물 정답은 평가 split 최대 **24**개(10개 이상 18장), 학습 split 최대 **31**개다.

- 영향: 9 기준으로 역산하면 본실험 평가셋의 약 2.8%(12,461장 기준 ~344장)가 여전히 절단된다. 61번이 스스로 "본실험 차단 조건"으로 등급 매긴 항목인데, 처방을 문자 그대로 이행하면 **차단이 해소되지 않는다.** (D 의 66번 §8 이 같은 사실을 독립적으로 잡아 26+30N · 권고 1,536 을 냈으므로, C 가 D 값을 받으면 해소된다.)

## 8. 감사 자체에 대한 기록

- 감사자와 재검자 모두 **저장소를 수정하지 않았다.** 감사 종료 시점에 네 스냅샷 digest 전부 재검증 통과, `git status` 클린, `data/raw` 에 2026-08-26 이후 수정 파일 0건.
- 1차 감사의 판정 중 18건이 재검에서 뒤집혔다. 방향은 반반이다 — 통과시킨 것 중 12건이 불합격이었고, 미검증으로 민 것 중 9건이 검증 가능했다. **합의가 정답의 증거가 아니라는 사례가 또 하나 늘었다**(64-bit pHash 건에 이어).
- 재검이 재현하지 못한 것: A 의 히스토그램 전수 재구축과 JPEG 단조 실측(비용 문제로 1차 감사 결과를 인정), C 의 프로브 산출물 일부. 이 항목들은 절차가 타당해 보여 그대로 받았다.
