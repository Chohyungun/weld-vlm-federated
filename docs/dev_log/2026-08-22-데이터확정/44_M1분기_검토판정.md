# 검토 게이트 — M1 분기 판단 요청 2건

2026-08-24 · 판단 요청 `43_M1분기_총괄판단 요청_A.md` · 근거 `41_`·`42_`

## 판단 요청 1 — 타일 규격: **1280×720 유지. 차선안 발동하지 않는다.**

**수용.** 분기 조건은 참이지만 조건이 가리키는 차선안이 실측상 채택안보다 나쁘다.
3% 결함 절단 상한을 통과하는 유일한 높이가 720 이므로, 차선안은 다른 규격에 도달하지
않고 **더 나쁜 경로로 같은 규격에 온다.**

근거가 된 실측: 결함 개별 폴리곤 높이 중앙값 44px 로 작지만 **이미지당 세로 스팬**이
중앙값 100px · q95 492px 다. 정상 밴드(205px)와 달리 결함은 720 높이를 실제로 쓴다.
40번 4-9 가 "밴드 높이"만 보고 분기를 설계한 것이 부정확했다 — 봐야 할 값은
**결함의 세로 스팬**이었다.

**40번 4-9 의 첫 행을 정정한다.** 조건을 "밴드 높이 중앙값 < 720" 에서
**"결함 세로 스팬 q95 < h_t 이면서 밴드 높이 중앙값 < h_t"** 로 고친다.
조건을 결과에 맞춰 느슨하게 바꾸는 것이 아니라, 원 조건이 잘못된 축을 봤음을 인정하는 정정이다.

## 판단 요청 2 — τ 정의: **`band_containment` 채택.**

**수용.** 205px 밴드가 720px 타일에 들어가면 면적비 상한이 0.285 이므로 τ=1.0 은
물리적으로 달성 불가능하고, 높은 τ 는 정상 타일을 전량 폐기시켜 4-4 폐기율 상한과
정면으로 충돌한다. **워크플로가 못 본 자리다.**

`configs/base.yaml` 의 `tau_mode: "band_containment"` 를 확정하고 `tau: null` 을 유지한다.
`area_ratio` 는 선택지로 남기되 이번 실험에서 쓰지 않는다.

**조건 하나를 붙인다.** 밴드 포함률 99.6% 는 **포함 여부**만 본 값이다. 남는 0.4%(밴드
높이 ≥720)의 처리를 명시하라 — 폐기인지, 밴드 중심 크롭 후 절단 허용인지. 폐기라면
4-4 폐기 회계에 별도 셀로 잡고 상한에 포함시켜라.

## 남는 비대칭 — 트랙 D 이관 수용

정상 타일의 밴드 점유율이 결함 크롭과 같은지는 **결함 이미지에 밴드 폴리곤이 없어
라벨만으로 원리적으로 확인 불가**다. 결함 폴리곤으로 대신 재면 라벨로 전처리를 적합하는
것이라 규약 1-4 위반이다. **D 의 P2(픽셀 기반 프로브) 몫으로 넘긴다는 A 의 판단을 수용한다.**

이 비대칭은 숨기지 않고 40번 5절 증명 절차에 **잔존 위험으로 명시**한다. P2 가 이것을
잡지 못하면 헤드라인 주장 범위를 축소한다(4-5 후퇴 사다리 R3).

## 진행 승인

τ 확정으로 **타일링 착수 가능**하다. 4-1 실행 순서를 지켜라 — 예비 분할 → 학습 풀에서만
캘리브레이션 → 타일링 → 최종 분할. 8/25 전처리 규격 확정 게이트는 예정대로 연다.
