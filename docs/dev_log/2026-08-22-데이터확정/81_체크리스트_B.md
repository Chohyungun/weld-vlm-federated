## 6. 검증기 [자료] 등식 — 닫음

### 무엇이 깨져 있었나

생성 프롬프트는 결함 코드를 "그대로 적으라"고 **의무화**했는데 판정 프롬프트의 [자료]에는
결함 코드가 없었고, 판정 지시는 "자료에 없는 사실은 NG"였다. **지시대로 쓴 문장이
구조적으로 NG 조건을 만족한다.** 178건 중 98건(55.1%)이 그 상태다 (B2·B4).

원인은 두 프롬프트가 각자 f-string 으로 자료를 편 것이다. 한쪽만 필드를 빠뜨려도
아무도 몰랐다.

### 무엇을 했나

`corpus/generate/basis.py` 신설. 자료를 만드는 지점이 하나다.

```
basis.render_basis(골격)  ──┬─→ prompt_generate  (생성)
                            └─→ prompt_judge     (판정)
```

**등식은 시험이 아니라 구성으로 보장된다.** 필드를 빼거나 더하려면 이 파일을 고쳐야 하고,
고치면 양쪽이 함께 움직인다. 시험은 그것을 확인만 한다.

`required_mentions()` 가 stage0 의무 요소의 정본이고, 생성 프롬프트의 "반드시 지킬 것"
목록이 그 함수에서 나온다. **자료 밖 요소는 의무가 될 수 없다** — 구조적으로.

### 시험 (`tests/corpus/test_canonical_wiring.py`)

| 시험 | 내용 |
|---|---|
| 생성과 판정이 같은 자료 문자열을 싣는다 | `render_basis(rec)` 가 두 프롬프트에 **문자 그대로** 들어 있는가 |
| stage0 의무 요소가 전부 자료에 있다 | 의무 라벨 ⊆ 자료 필드, 값까지 일치 (G4-2·G4-3) |
| 의무 요소는 생성 프롬프트에도 그대로 실린다 | 라벨만 맞고 값이 다르면 같은 사고다 |
| clause_only 는 판정을 자료에서 뺀다 | 축이 "합부를 말하지 않는다" 이므로 자료에도 없어야 한다 |
| 자료에 내부 표현이 새지 않는다 | `Unit.`·`None`·아티팩트 0건 |

### 부수로 닫힌 것 — B3

stage0 의 ISO 6520-1 예외가 죽은 코드였다(`STD_REF` 캡처 그룹 때문에 `findall` 이
`['ISO']` 만 돌려줘 마스킹 실패, 폐기 22건 중 18건이 그 인공물). 자체 검사를 걷어내고
정본 `numeric_lock._scan` 을 쓰므로 **그 코드가 아예 없어졌다.**

## 7. 정본 검증기 배선 — 닫음

도 부를 수 없었다 — 그 함수들이 요구하는 §4-5 골격이 아니었기 때문이다. **배선이 안 된

이제 (c) 축은 `skeleton_gen.generate_corpus_skeletons` 가 만든다. 조합 열거·난이도 층화·

```
생성 → check_numeric_lock (0단계)  → run_stage1(asset="c") (1단계) → 다른 계열 판정 (2단계)
```

`check_record` 를 지웠다. 그 안에 있던 것:

### 배선 시험 — 문서로 금지한 것을 시험으로 옮긴다

`skeleton_gen.py:34-38` 이 "재구현 금지"를 주석으로 적어 뒀지만 주석은 아무것도 막지
못했다. AST 로 검사한다.

| 시험 | 내용 |
|---|---|
| 생성 모듈이 수치·판정어 정규식을 재정의하지 않는다 | `corpus/generate/*.py` 최상위 `re.compile` 이름에 NUM·VERDICT·STD_REF·PASS·FAIL·CLAUSE·UNIT 이 있으면 실패 |
| 사이클 실행기가 정본 검사기를 부른다 | `check_numeric_lock`·`run_stage1`·`check_normal_lock`·`find_artifacts`·`find_verdict_implying`·`render_basis` 호출 실재 |
| 사이클 실행기가 자료를 검사기에 넘긴다 | `basis_fn=render_basis` — 안 넘기면 아티팩트 게이트가 꺼진다 |
| 페어 생성기가 정본 어휘 락을 부른다 | `find_defect_tokens` |

**이 시험이 실제로 잡았다.** `make_pairs_pilot.VERDICT_WORD` 가 남아 있는 것을 시험이
먼저 발견했고, 그것을 고쳐서 초록이 됐다.

### 남은 것 — D4 는 `run_stage1(asset="d4")` 를 부르지 못한다

을 필수로 받는다. **표본 전체에서 두께 비결측 0건**이라(함정 #10) 그 경로는 지금 열 수

의사결정로그 미정 항목이고 미니스펙 §게이트에 올렸다.

## 8. 생성문 아티팩트 게이트 — 닫음

### 값 검사로는 원리적으로 안 잡힌다

`4.00` 은 값으로는 `4` 와 같다(§5-4 2단계 후행 0 동치). 그래서 화이트리스트 대조를
통과한다. **틀린 것은 값이 아니라 표기다.** 채택 69건 중 49건(71%)이 그 산물이었다.

`numeric_lock.find_artifacts(text, basis=...)` 신설. 판정 기준은 **[자료]** 다.

- 자료에 그 토큰이 문자 그대로 있으면 아티팩트가 아니다 — 자료가 그렇게 줬으면 옮겨
  적은 것이 맞고, 고칠 곳은 자료 쪽이다.
- 자료에 없는 표기가 생성문에만 있으면 내부 표현이 다른 경로로 샌 흔적이다.

이 구분이 없으면 둘 중 하나가 된다: 자료를 안 보면 정당한 출력이 전량 폐기되고,
표기를 안 보면 71% 오염이 그대로 통과한다.

검출 대상: 내부 enum(`Unit.`·`InspectionMethod.` 등) · 개구간 인코딩 `X.01` ·
후행 0 `X.00` · 파이썬 리터럴(`None`·`Decimal(`) · **수사**(십이·十二·twelve, G2-7).

### 출력 측 회귀 시험 — 실제 오염 문장을 픽스처로 (G3-2)

92eefae 의 회귀 시험이 프롬프트만 보고 출력은 안 봐서 71%가 통과했다. 파일럿 채택분에서
실제로 뽑은 문장을 박았다.

```
clause-0002  "… 크기는 4.00 Unit.MM 이하로 제한된다."
clause-0004  "… 적용 두께 구간은 25.01 mm 이상 50.01 mm 미만이다."
```

### 함께 닫은 것

| # | 내용 |
|---|---|
| B21 | `_PASS_RE = (?<!불)합격` 한 글자 lookbehind 가 "불 합격"에 뚫렸다. 분리자(`\s·ㆍ・-_~`)를 지운 뒤 센다. 실측 확인: `불 합격` → (pass 0, fail 1) |
| G2-6 | 판정 함의 표현(적합하다·허용된다·만족한다 …)을 `clause_only` 에서 폐기 사유로. 낱말을 피해 같은 뜻을 전달하는 경로를 막는다 |
| B16 / G3-4 | `parse_judgement` 를 부분문자열에서 **앵커** 매칭으로. "This LOOKS fine" 이 OK 로 읽히지 않는다 (시험 고정) |
| B17 / G3-3 | 기각 사유가 입력 문장과 최장 공통 부분열 80% 이상 겹치면 "사유 미기재"로 강등하고 `n_reason_is_echo` 를 보고 스키마 필수 필드로 |
| B8 / G6-1 | 축 보고 블록에 `validated_by`·`measures` 필수. `validated_by=none` 인 축은 키가 `pass_rate` 가 아니라 **`format_rate`** 다 — QA 0.94 와 판정추론 0.345 가 같은 이름으로 실리지 못하게 구조로 막는다 |
| G6-2 | 돌지 않은 단계를 "폐기 0건"으로 렌더하지 않는다 (`status: not_run`) |

### 실측 사고 하나 — 수사 검출이 정상 문장을 죽였다

한글은 낱말 경계가 없어 "열"(ten)이 **균**열·배열·나열에 걸린다. D4 페어 89건이
그것으로 폐기됐다. 한글·한자 수사는 **수량 단위와 붙어 있을 때만** 수사로 본다
(개·건·장·번·회·배·mm …). 영문은 `\b` 로 충분하다. 고친 뒤 폐기 0건.

이 사고 자체가 게이트 설계의 교훈이다 — **넓게 잡는 검사는 이빨 시험만으로 부족하고,
실물 전수에 걸어 봐야 한다.**

## 9. 검증기 정본 사전 등록 — 사람 라벨만 남음

### 설정 교락을 닫았다 (G12-4)

파일럿의 56.75pp 차는 **계열 차이가 아니라 계열 + 설정 차이**였다. 한쪽은 사고를
프리필로 억제하고 예산을 32 토큰으로 잘랐고, 다른 쪽은 자유 생성 64 토큰이었다.

`configs/corpus_validation.yaml` 신설. 예산·사고 정책이 **후보별이 아니라 공통 블록**에
있다 — 구조로 교락을 막는다. 시험이 후보 항목에 `max_new_tokens`·`prefill` 이 없는지
확인한다.

```yaml
judges:
  budget: {max_new_tokens: 96, reason_max_new_tokens: 72}   # 두 후보 공통
  thinking_policy: suppress                                  # 두 후보 공통
  candidates: [deepseek(llama 계열), phi(phi 계열)]
  canonical: null            # ← 사람 라벨 비교 전까지 정본 없음
```

산출물은 후보별 결과를 `judge_<id>_*` 키로 따로 담는다. 덮어쓰지 않아야 같은 파일에서
일치도를 잴 수 있다.

### 라벨 하네스 (`corpus/validate/judge_labels.py`)

```
uv run python -m corpus.validate.judge_labels sheet   # 표본지 100건 (축2 × 판정2 층화)
uv run python -m corpus.validate.judge_labels score   # 정밀도·재현율
```

- 층별 균등 배분, 시드 고정. 층이 부족해도 **다른 층에서 채우지 않는다** — 채우면
  층 비율이 무너져 지표가 어느 모집단의 값인지 말할 수 없다. 부족분은 `shortfall` 기록.
- 표본지는 사람에게 **기계 판정을 보여 주지 않는다**. 라벨러가 끌려가면 정답이 아니다.
- 사람이 보는 [자료]도 기계가 본 것과 같은 문자열이다 (G4-1).

### 막힌 것 — 사람 라벨은 트랙이 만들 수 없다

**정본 선정은 사람 라벨 100건 없이 성립하지 않는다.** 표본지는 재실행분으로 생성해 뒀고
(§19), 채우는 것은 사람 몫이다. 그때까지 어느 후보도 정본이 아니고, 보고서는 통과율을
`pass_rate` 가 아니라 후보별 `stage2_judges` 로만 싣는다 — 코드가 그렇게 강제한다.

**총괄에 요청**: 라벨러 배정. 2명이면 kappa 도 함께 싣는다. 다만 재실행분에서
2단계에 도달한 레코드가 25건뿐이라 **표본이 100건이 안 된다** — §19 참조.

### 무엇 때문에 떨어졌나 — 진단

| 결손 | 건수 | 내용 |
|---|---|---|
| `thickness_mm` 미출현 | **82** | 모재 두께를 문장에 안 쓴다. 크기와 한계는 쓴다 |

따라 실측 크기가 3.85 mm인 경우 합격 판정을 받았다."* — 두께 1.73 mm 가 빠졌다.

원인 후보는 프롬프트 설계다. **"2~3문장"** 을 요구하면서 문자 그대로 담을 값을 5~6개
의무화한다. 다만 **여기서 프롬프트를 고쳐 다시 돌리지 않았다** — 통과율을 보고 프롬프트를
손보면 그것이 지표에 맞춘 튜닝이 된다(규약 3-4·3-6). 측정값 그대로 싣고, 본 생성의
문장 길이·의무 항목 구성은 게이트에 올린다.
