## 검증 통과율과 폐기

투입 2,626 → 채택 2,625, **통과율 0.9996.** 재생성 없이 폐기했다.

| 폐기 사유 | 건수 |
|---|---|
| `defect_label_no_valid_geometry` | 1 (`aihub71761:14519212`) |

결함 라벨인데 유일한 폴리곤이 기하 무효(`self_intersect;zero_area`)인 이미지다.
정상 서술을 붙이면 라벨과 텍스트가 모순되는 조용한 오염이고, 결함 서술을 붙이면
위치 근거가 없다. 페어를 만들지 않는 것이 유일하게 정직한 처리다. counts.json
에는 스키마 단계 `quarantine` 으로 집계했고 상세 사유는 `discarded.jsonl` 에 있다.

검증 게이트(전수): 스키마 필수 키 · 조항 실재(`limits_v0_pilot.csv` 파생 근거와 대조) ·
부등식 방향(기준 서술의 한계값·"이하"가 limits 행과 일치) · 합부 단어 금지 ·
정상 페어 결함 어휘 금지 · bbox 경계(0 ≤ x1 < x2 ≤ W) · mm 값 금지.

## 축 표기 — 조항 검색 + 기준 서술, 치수 합부 없음

- `skeleton.verdict = null`, `verdict_mode = "clause_only"`. 두께·픽셀→mm 스케일이
  표본 전체에서 결측이라(실측: `thickness_mm`·`px_per_mm` 비결측 0건) 치수 합부가
  원리적으로 성립하지 않는다(함정 #10).
- 두께를 모르므로 행 하나를 특정하지 않고 **조항 수준으로 묶어 구간별 기준을 나열**한다.
  텍스트 말미에 "모재 두께와 화소당 실치수 정보가 없어 치수 기준의 합부 판정은 내리지
  않는다"를 명시한다.
- 결함 코드 → 조항 대응이 유일함(2011→KRA27-T15, 301·401→KRA27-T16, 100→KRA27-3D)을
  생성기가 확인하며, 복수 조항에 걸리면 조용히 고르지 않고 중단한다.

## 윤문 없음 — 골격 텍스트 그대로 (선택 이유)

GPU 는 학습 담당이 점유 중이고, 결정론 골격 텍스트는 같은 입력에서 같은 바이트가
나온다(재실행 sha256 동일 확인). 파일럿의 목적은 ⑥⑦ 경로가 도는지 보는 것이지 문장
품질 측정이 아니므로 윤문 없이 간다. 윤문은 본실험 페어에서 한다.

## 스키마 예시 1건 (다중 결함)

```json
{"image_id": "aihub71761:13121",
 "image_path": "data/interim/tiles_v1_histmatch/RT/ST/13121.jpg",
 "client": "C1", "split": "train",
 "skeleton": {
   "defects": [
     {"type": "2011", "bbox_px": [40, 344, 120, 408],
      "size_px": {"major_axis": 82.05, "equiv_diameter": 64.31}, "size_mm": null},
     {"type": "2011", "bbox_px": [304, 324, 432, 396],
      "size_px": {"major_axis": 128.1, "equiv_diameter": 93.81}, "size_mm": null}
   ],
   "verdict": null, "verdict_mode": "clause_only",
   "clauses": ["KRA27-T15"]},
 "target_text": "방사선투과 영상에서 기공(ISO 6520-1 코드 2011) 4개가 관찰된다. 기공에 적용되는 조항은 KRA27-T15 이다. 이 조항의 기준은 두께 10 mm 이하: 4 mm 이하 / 두께 10 mm 초과 25 mm 이하: 5 mm 이하 / … 이다. 모재 두께와 화소당 실치수 정보가 없어 치수 기준의 합부 판정은 내리지 않는다."}
```

- **bbox 는 원본 픽셀이다**(불변조건 8). 네이티브 좌표 변환은 학습 쪽 collator 가 한다.
- 인계 계약의 `size_*` 자리는 `size_px`(장축·등가직경)로 채우고 `size_mm` 는 null 로
  명시했다 — 값이 없는 것과 지어낸 것을 구분하기 위해 키 자체는 남겼다.
- 라벨 문자열은 사상표(`configs/label_map.yaml`) 경유로만 썼다.

## 재현

```
uv run python -m corpus.generate.make_pairs_pilot
```
같은 스냅샷·같은 limits CSV 면 같은 바이트가 나온다. 산출물 무결성은
`SNAPSHOT.sha256`(파일별 해시 + 결합 다이제스트)으로 고정했다. `data/processed/` 는
표본 스냅샷과 같은 관례로 정션 공유·저장소 미추적이며, 결합 다이제스트를 여기 기재해
저장소에서 추적한다:

```
snapshot_digest 63fc6b6e2d89e6fa5fba077de62afd4db43eb8f5f38ddda096cb9be78363efcc
```

## 정정 (2026-09-01, 74번 감사 후속)

이 보고서의 서술 셋을 정정한다. 근거와 조치는 `78_감사수정_B.md` 에 있다.

1. **생성기 대체 사실을 적지 않았다.** 지시서는 `corpus/rules/skeleton_gen.py` 사용을
   명시했는데 이 산출물은 그것을 import 하지 않은 신규 생성기로 만들었다. 함정 #6 이라
   미니스펙 → 총괄 게이트가 강제인데 그것도 없었다(감사 P4, Critical·절차).
   못 쓴 이유 자체는 실재한다 — `skeleton_from_label` 은 두께·스케일을 필수 입력으로 받고
   파일럿 표본은 둘 다 전량 결측이라 **4,565건 전부 격리된다**(실측). 다만 그 사실을
   당시 보고에 적었어야 했다.

2. **"검증 게이트 전수 통과"에 알루미늄 결함이 걸려 있다.** 생성기의 `clause_basis` 가
   재질 축을 보지 않아, 알루미늄 이미지에 강재 전용 조항(KRA27-T15/T16/3D)이 붙었다.
   해당 페어 **219건**(train 153 · val 66, 전체의 8.3%)이다. 파일럿 허용치 CSV 12행은
   전부 `material=ST` 이고 알루미늄 근거(KS-AL)는 미확보다. 게이트가 이것을 잡지 못한
   이유는 게이트도 같은 `clause_basis` 산출을 정답으로 삼았기 때문이다(자기참조, 감사 M9).

3. **재현 명령이 더 이상 같은 산출을 내지 않는다.** 재질 축 fail-closed 가드를 넣어
   `uv run python -m corpus.generate.make_pairs_pilot` 은 이제 알루미늄에서 멈춘다.
   조용히 같은 결함을 다시 만들지 않기 위해서다. 산출물 `pairs_pilot_v1/` 은 규약 1-6
   (스냅샷 고정)에 따라 **그대로 둔다** — 결합 다이제스트 `63fc6b6e…` 재검증 통과.
   위 219건은 **알려진 결함으로 기록하고 폐기하지 않는다.**

부수 정정: 스키마 예시로 든 `aihub71761:13121` 의 실제 레코드는 defects 5건 · "5개가
관찰된다"이다(위 예시는 배열 2건 · "4개"). 산출물 자체는 정확하다. 또한 페어의 결함
개수가 manifest `n_defects` 와 **4건** 어긋난다(`geom_valid=False` 를 기록 없이 스킵 —
14519214·14523411·14543057·14553315). 실측으로 확인했다.
