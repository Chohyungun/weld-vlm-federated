## 1. 재산출 상수 (동결 평가셋, 단일 채점기)

전부 `evaluation/score.py` 의 `score_records` 출력이다. 해석식(2·TP/(예측양성+실양성))을
같이 돌려 **전 항목 소수점 이하 완전 일치**를 확인했다. 불일치 표시가 뜬 항목은 없다.

### 모집단 `eval12461` (동결 평가셋 전체)

| 예측기 | Macro-F1 | miss_rate | Class-Jaccard |
|---|---|---|---|
| 전량양성 자명하한 | **0.2160** | 0.0000 | 0.1428 |
| 전량 상수 기공 | 0.1523 | 0.2329 | 0.4369 |
| 출처 조건부 기공 (N-crop→기공) | 0.2068 | 0.2329 | 0.8158 |
| 재질 전용 최적 | **0.2454** | 0.0555 | 0.1902 |
| 출처 전용 최적 | 0.3066 | 0.0000 | 0.5217 |
| **출처×재질 전용 최적** | **0.3465** | 0.0555 | 0.5690 |

### 모집단 `eval_ncrop7740` (N-crop 부분모집단)

| 예측기 | Macro-F1 | miss_rate |
|---|---|---|
| 전량양성 자명하한 | **0.3066** | 0.0000 |
| 전량 상수 기공 = 출처 조건부 기공 | 0.2068 | 0.2329 |
| 재질 전용 최적 = 출처×재질 전용 최적 | **0.3465** | 0.0555 |

두 모집단에서 값이 겹치는 것은 우연이 아니다. **평가셋 결함 이미지 7,086장이 전부
N-crop 이다**(N-tile 4,697·N-band 24 는 전량 정상). 결함 이미지가 타일링을 거치지 않고
원본 규격 그대로 통과했기 때문이고, 그래서 클래스별 실양성 수가 두 모집단에서 같다.
출처 축이 결함 유무를 거의 결정한다는 사실이 상수표에도 그대로 찍힌다.

### 게이트

**게이트는 content-free 계열의 최댓값으로 잡는다.**

| 항목 | 값 |
|---|---|
| content-free 최댓값 (`eval12461`) | 0.3465 |
| 여유 | 0.005 |
| **통과선** | **0.3515** |

자명하한(0.2160) 하나를 선으로 쓰면 출처×재질만 아는 규칙(0.3465)이 통과한다. 66번의
소득이 그것이었는데 하한만 갈아끼우면 같은 상태로 되돌아간다.

### 최적성 검산

"최적"은 탐색이 아니라 **정확해**다. Macro-F1 은 클래스별 F1 의 평균이고 클래스 c 의 F1 은
"어느 셀에서 c 를 주장하는가"에만 의존하므로 **클래스끼리 독립**이다. 클래스마다 셀
부분집합만 전수로 보면 전역 최적이고 셀 조합 16^n 을 뒤질 필요가 없다.

재질 축(셀 2개)은 16² = 256 조합 전수 탐색으로 교차 확인했다 — 최댓값 0.2454, 규칙
`AL → {기공, 슬래그}`, `ST → {균열, 기공, 융합불량}`. 클래스 독립 해와 일치한다.

68번의 재질 전용 0.2434·출처×재질 0.3439 는 각각 0.0020·0.0026 낮다. 이쪽이 증명된
상한이므로 **더 큰 값이 정본**이다. 게이트는 높은 쪽으로 가야 안전하다.

## 2. 0.3066 대 0.3041 — 0.3066 이 맞다

**결론: 0.3066.** 근거 셋이 같은 값을 준다.

1. 채점기 직접 산출 (`score_records`, N-crop 7,740장 전수) = 0.3066
2. 해석식 + **매니페스트 직접 산출** 클래스 수 = 0.3066
3. 해석식 + **58번 표 유도** 클래스 수 = 0.3066

두 갈래가 갈릴 것으로 본 지점이 실제로는 갈리지 않는다. 58번 표의 eval 열
(균열 448 · 융합불량 688 · 기공 5,460 · 슬래그 522)이 N-crop 클래스 수와 **정확히 같기
때문**이다 — 위에서 적었듯 결함 이미지가 전부 N-crop 이라 그렇다.

0.3041 은 동결본의 어떤 모집단에서도 나오지 않는다. 역산하면 `N ≈ 7,830.5` 가 필요한데
스냅샷에 그런 모집단이 없다.

| 모집단 | N | 전량양성 Macro-F1 |
|---|---|---|
| N-crop | 7,740 | **0.3066** |
| N-crop + N-band | 7,764 | 0.3059 |
| 결함 이미지만 | 7,086 | 0.3259 |
| 평가셋 전체 | 12,461 | 0.2160 |
| (0.3041 이 필요로 하는 값) | 7,830.5 | 0.3041 |

클래스 수를 하나씩 흔들어도 자연스러운 후보가 없다(균열 448→405, 기공 5,460→5,347 등
근거 없는 값이 필요하다). **0.3041 은 폐기한다.**

## 3. 놓침 축·위치 축 기준선

지금까지 등록된 것은 Macro-F1 계열뿐이었다. 개발규약의 첫 비교 항목인 놓침·위치에
content-free 기준선을 세운다.

### 놓침 축 — 기준선이 0.0000 이다

| 예측기 | miss_rate |
|---|---|
| 전량양성 | **0.0000** |

전량양성은 모든 이미지에 4코드를 주장하므로 재현율 1.0, 놓침 0 이다. **놓침만으로는
어떤 게이트도 세울 수 없다.** 놓침이 낮다는 보고는 반드시 Macro-F1 계열과 짝으로 읽어야
하고, 단독으로 헤드라인에 올리면 자명한 규칙이 만점을 받는다.

### 위치 축 — 상수 박스

상수 박스는 **train+val GT 중앙값**에서 유도했다(n=86,560). 평가셋 통계에서 예측 상수를
뽑으면 불변조건 1-4 가 실질에서 깨진다.

| 항목 | 값 |
|---|---|
| 박스 (x1,y1,x2,y2) | (589, 335, 666, 383) |
| GT 박스 수 | 22,549 |
| IoU ≥ 0.5 비율 | **5.02%** (1,132개) |
| `bbox_iou` 평균 (미매칭 0 포함, 주 정의) | **0.0796** |
| 이미지당 최대 IoU 평균 | **0.2533** |
| mAP@0.5 | 0.0015 |

68번의 5.69% / 0.2576 과 각각 0.67%p · 0.0043 차다. 상수 박스의 정의(어디서 유도했는지)가
명시되지 않아 재현 조건이 달랐을 수 있다. 위 값은 유도 출처·정의를 못 박은 정본이다.
`bbox_iou` 는 미매칭 GT 를 0 으로 포함하는 주 정의와 매칭쌍 평균 두 벌이 있으므로
표에 병기하지 않으면 같은 이름이 다른 값을 단다.

## 4. `configs/base.yaml` 반영

`preregistered:` 블록을 **폐기하고** `fixed_before_main_runs:` 로 교체했다.

- **키 이름을 바꾼 이유.** 파일럿 채점은 9/1 에 끝났고 상수 확정은 그 뒤다. 사전등록으로
  표기하면 날짜만으로 무너진다. 탐색적 파일럿 → 확증적 본실험으로 쓴다.
- **모집단을 키에 박았다.** `content_free__eval12461`, `content_free__eval_ncrop7740`,
  `constant_box__eval12461`. 옛 값(N=62,998 기준 0.2081·0.3025)은 동결본과 모집단이 달라
  폐기했다.
- 게이트는 `max_macro_f1` + `gate_tolerance` 로 계산된다.

### 남은 소관 밖 정리 — D 에 배분 필요

옛 상수가 **트랙 D 소관 파일**에 남아 있다. 규칙대로 건드리지 않았다.

| 파일 | 내용 |
|---|---|
| `evaluation/prereg.py` | `all_positive_macro_f1=0.2081`, `spec_only_macro_f1=0.3025`, `RT_TOTAL=62_998`, `R1_COUNT=37_814` |
| `evaluation/probes/metadata_probe.py` | 통과선 0.2131 서술 |
| `evaluation/probes/pilot.py` | 같은 상수 서술 |
| `tests/test_prereg_probes.py` · `tests/test_pilot_probes.py` | 위 값 검증 |

`verify_against_prereg(atol=0.001)` 는 지금 동결본 재산출값으로 호출하면 **실패한다**
(0.2160 대 0.2081). 게이트가 자명하한 단일선에서 계열 최댓값으로 바뀌었으므로 함수의
계약 자체를 손봐야 하고, 배분은 총괄 몫이다.

## 5. 승격 어블레이션 표본 두 벌

파일럿 표본(3,279장)에서 파생했다. **동결을 풀지 않았다** — 원본 digest `1f80e98b…` 재검증
통과, 60번 전례와 같다.

| 팔 | 경로 | 장수 | digest |
|---|---|---|---|
| 크롭 한정 | `data/processed/aihub71761_rt_v1_pilot3000_crop_only` | 2,097 | `15a8056437f3de3c…` |
| 규모 대조 | `data/processed/aihub71761_rt_v1_pilot3000_scale_control` | 2,098 | `4fb0423bd52b99d0…` |

| 항목 | 크롭 한정 | 규모 대조 |
|---|---|---|
| split (train/val/eval) | 1,434 / 232 / 431 | 1,454 / 226 / 418 |
| 출처 | N-crop 2,097 | N-crop 1,341 · N-tile 752 · N-band 5 |
| 결함 / 정상 | 1,884 / 213 | 1,206 / 892 |
| **학습 풀 정상 비율** | **10.2%** | **43.1%** |

대조 팔은 **(split × 출처) 9개 층**에서 비례로 뽑았다. 출처만 맞추면 평가셋 크기가 따로
움직여 두 팔이 다른 모집단에서 채점된다. 순서는 `sha256(image_id + seed)`, 시드는
파일럿과 같은 20260828 이다. 장수가 1장(0.05%) 어긋난 것은 9개 층의 반올림 합이다.

**두 팔은 짝으로만 해석한다.** 크롭 한정 단독 델타에는 출처 축 제거·표본 35% 감소·정상
비율 43.1%→10.2% 가 섞여 있다. 대조 팔은 뒤의 둘 중 규모만 재현하므로, (크롭 한정 −
대조)가 출처 축과 정상 비율의 합산 효과이고 (대조 − 파일럿)이 규모 효과다.
각 스냅샷 `capabilities.ablation_arm` 에 이 경고를 박아 두었다.

C 가 검출 3칸을 돌릴 수 있는 상태다.

## 6. 결함 수 상한 — train+val 전수

67번 §5-4 대로 **train+val 에서만** 냈다. 평가셋은 열지 않았다(모집단 49,847 =
train 44,846 + val 5,001, eval 12,461 미접근).

| 모집단 | max | p99 | p99.9 | 평균 |
|---|---|---|---|---|
| 전체 (정상 0 포함) | **50** | 13.0 | 28.0 | 1.74 |
| 결함 이미지만 (27,501장) | **50** | 15.0 | 31.0 | 3.15 |

`26 + 30 × 결함수` 로 환산하면 다음과 같다.

| 기준 | 결함 수 | 토큰 |
|---|---|---|
| 최대 | 50 | **1,526** |
| p99.9 (전체) | 28 | 866 |
| p99 (전체) | 13 | 416 |

파일럿 표본 최대는 31이었고 66번이 1536 을 권고했다. **동결본 train+val 최대는 50 이고
필요 토큰은 1,526 이라 1536 이 여전히 덮는다.** 여유는 10 토큰이다. D 가 이 값으로
예산을 확정하면 된다. 원자료 `data/interim/manifest_v1/defect_count_trainval.json`.
