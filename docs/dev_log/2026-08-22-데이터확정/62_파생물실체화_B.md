# corpus/derived/ 파생물 실체화

작성 2026-08-31 · 대상: 파일럿 ⑤ 판정부의 색인·채점 입력

`limits_v0_pilot.csv` 한 파일에서 D 소비분 둘을 실체화했다. 새 설계 없이 기존
파생 함수(`derive_chunk_meta`, `derive_gold_clauses`)의 실행이다.

## 산출물

| 파일 | 내용 | 건수 |
|---|---|---|
| `corpus/derived/chunk_meta.jsonl` | RAG 청크 메타 필터 축 (`rag/retrieve.py` Chunk 입력) | 청크 **4** (조항 KRA27-3D · T15 · T16 · S) |
| `corpus/derived/gold_clauses.csv` | 채점 정답 조항 목록 (`evaluation/gold.py` 입력) | 행 **12** (원천 12행 전건 — canonical·active 12/12) |
| `corpus/rules/materialize_derived.py` | 재파생 스크립트 (재실행 가능, `--check` 모드 포함) | — |

## 파생 요약

- **거부 0건.** 로더 G0 통과 12행 전건이 파생됐다. 실현성 경보 1건(V10:
  `KRA27-S-01`, t 하단에서 유효 한계 0.1mm 미만)은 경보이지 거부가 아니며,
  해당 행은 VT 축이라 RT 기본 필터에서는 선택되지 않는다.
- 원천 CSV 를 고칠 일은 없었다(fail-closed 거부 없음).
- 입력은 `limits_loader` 공식 로더 경유. v0-pilot 은 `sources.yaml`·조항 목록이 없어
  pilot 모드로 로드된다(V0·V5·V8 면제 — 면제 내역은 로더가 출력). 본 CSV 전환 시
  전체 G0 를 요구한다.

## 신선도 보장 — 원천 sha256 을 산출물에 박았다

원천이 바뀌었는데 파생물이 낡은 채로 남는 것이 최악이다. 세 겹으로 막았다.

1. **산출물마다 원천 sha256 내장.** `chunk_meta.jsonl` 첫 줄 `_meta` 헤더 레코드,
   `gold_clauses.csv` 상단 `#` 주석. 소비처는 자기가 본 원천 해시와 대조할 수 있다.
2. **재파생은 결정론.** 같은 원천이면 같은 바이트가 나온다(타임스탬프를 넣지 않는다).
   재실행·`--check` 로 확인했다.
3. **회귀 테스트 4건** (`tests/corpus/test_materialize_derived.py`): 산출물 존재 +
   해시 일치, 재렌더 바이트 동일, gold 의 `#` 주석이 `pandas comment="#"` 로 읽힘,
   `_meta` 행 스킵 규약. **원천만 바꾸고 재파생을 잊으면 테스트가 실패한다.**

## 파일 형식 규약 (D 와 공유)

- `chunk_meta.jsonl`: 첫 줄은 `{"_meta": …}` 헤더 레코드. 데이터 행은 둘째 줄부터이며
  `derive_chunk_meta()` 항목 그대로다(D 의 `chunk_from_meta` 가 받는 형태).
  소비처는 `_meta` 키가 있는 행을 건너뛴다.
- `gold_clauses.csv`: `#` 시작 줄은 주석. 상단에 **평가 자산(D6) 경고**를 박았다 —
  채점기·검색 결정 절차 외 어떤 학습 단계에도 투입하지 않는다(개발규약 1-4).

## 재파생 절차

```
uv run python -m corpus.rules.materialize_derived           # 재파생 (변경 없으면 무갱신)
uv run python -m corpus.rules.materialize_derived --check   # 신선도 검사만
```
