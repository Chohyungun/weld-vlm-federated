## 1. 인용 금지 표식 (지시 1항, G11-4)

### 1-1. 범위 — 디렉터리 단위로 막으면 안 된다

G11-4 는 "디렉터리에 `DO_NOT_CITE.md` 를 두고 채점·인용 스크립트가 그 파일을 보면 실패"
하라고 했다. 그대로 하면 **`sep_fed` 가 통째로 막힌다.** 그런데 80번 자신이
"sep_fed 는 논문 본체인 분리형 칸"이라며 회계 두 파일만 지목했다. 예측·가중치까지 막으면
써도 되는 것이 막히고, 그러면 다음 사람이 표식을 지운다 — 통제가 통째로 사라진다.

그래서 표식은 디렉터리에 두되 **파일 단위 범위를 기계 판독 가능한 JSON 블록**으로 담았다.

| 표식 위치 | 금지 | 금지가 **아닌** 것 | 사유 |
|---|---|---|---|
| `outputs/pilot_c/uni_central/` | 전부 | — | C3·E3 |
| `outputs/pilot_c/uni_fed/` | 전부 | — | C3·E3·F8 |
| `outputs/pilot_c/predictions/` | `uni_central.generations.jsonl` `uni_fed.generations.jsonl` | 검출 예측 5종 (`sep_*.detections.jsonl`) | C3 파생 |
| `outputs/pilot_c/sep_fed/` | `accounting.csv` `audit.json` | `global_r00{1,2,3}.npz` `latest.npz` `atomic_log.csv` `accounting.json` `runs/` | F7·F8 |

실물 판정 확인:

```
[가능] outputs/pilot_c/sep_fed/latest.npz
[금지] outputs/pilot_c/sep_fed/accounting.csv        ← F7 · F8
[가능] outputs/pilot_c/sep_fed/atomic_log.csv
[가능] outputs/pilot_c/predictions/sep_fed.detections.jsonl
[금지] outputs/pilot_c/predictions/uni_fed.generations.jsonl   ← C3 파생
[금지] outputs/pilot_c/uni_central/adapter_last.npz  ← C3 · E3
[가능] outputs/pilot_c/sep_central/sep_central.npz
```

### 1-2. 사유는 인용이 아니라 실측으로 적었다

표식에 들어간 증거는 전부 **산출물에서 직접 다시 확인**한 것이다. 80번을 옮겨 적지 않았다.

| 산출물 | 실측 |
|---|---|
| `uni_fed/atomic_log.csv` | r0 클라이언트 `param_l2` 31.7405 인데 집계 직후 `global_l2` **20.5755** — 독립 난수 A 가중합의 지문(공유 초기값이면 ≈31.7). 이월 r1 20.7508 · r2 20.8797 |
| `uni_central/adapter_last.meta.json` | 필드가 `optimizer_steps`·`supervised_tokens`·`peak_vram_gb`·`payload_bytes`·`param_l2`·`wall_s`·`seed` **일곱 개뿐.** `init_proof`·`epochs_ran`·`optimizer`·`lr`·`init_seed` 전무. `adapter_initial.npz` 부재 |
| `sep_fed/accounting.csv` | **9행 전부 `stopper_true_count=0`**(리터럴). `stopper_class`·`stopper_calls`·`value_source`·`optimizer_updates`·`resumed_from_epoch` 다섯 열 없음 |
| `sep_fed/audit.json` | `ok`·`failures`·`total_epochs_by_client`·`total_optimizer_steps` **네 필드뿐** |

각 표식에 **언제 풀리는지**도 체크리스트 항 번호로 적었다. 예: `uni_fed` 는 15·16·2 가
닫힌 뒤 재실행하고, **집계 후 norm 이 20.6 대가 아니라 31.7 대로 나오는지**가 수정 확인
지표다.

### 1-3. `outputs/` 가 git 추적 대상이 아닌 문제

`outputs/` 는 `.gitignore:11` 에 걸려 있고 본체와 정션으로 공유된다. **표식 파일 자체는
커밋되지 않으므로 지워지면 근거가 사라진다.** 그래서 스펙을 커밋되는 스크립트에 두고
표식을 생성하게 했다.

```
uv run python scripts/citation_ban.py --write            # 표식 배치·복원
uv run python scripts/citation_ban.py                    # 제자리에 있는지 검사
uv run python scripts/citation_ban.py --check <경로> ...  # 인용 가부 (금지면 종료 1)
```

판정은 상수가 아니라 **디스크의 표식을 읽어서** 한다. 상수만 보면 표식을 지워도 검사가
통과한다고 착각하게 된다. 표식이 깨져서 읽을 수 없으면 **안전하게 금지로 본다** —
그러지 않으면 표식을 망가뜨리는 것이 우회로가 된다.

### 1-4. 남은 배선은 C·D 소관

G11-4 의 "채점·인용 스크립트가 그 파일을 보면 실패"에서 **A 는 표식과 검사기까지**다.
채점기(D)·학습 진입점(C)이 `citation_ban.is_banned()` 를 호출하도록 잇는 것은 그 트랙들
소관이라 손대지 않았다. 호출 한 줄이면 된다.

## 2. 동결 디렉터리 위생 (지시 2항, G11-1)

### 2-1. 격리

`data/interim/manifest_v1/attic/` 로 6벌을 옮기고 전부 읽기 전용으로 잠갔다.
동결 계약 4파일의 sha256 은 **작업 전후 모두 일치**한다(스냅샷 digest `1f80e98b…` 불변).

### 2-2. 여섯 파일의 성격이 셋으로 갈린다 — 80번의 묶음이 거칠었다

80번은 "경쟁 매니페스트 4벌 · 분할 메타 2벌"로 한 묶음으로 적었다. 실측하면 이렇다.

**(가) 위험도 상 — 다른 분할을 담은 완전한 매니페스트 2벌**

| 파일 | 정본 대비 |
|---|---|
| `manifest_e3.csv` | `split` **26,738행** · `client` **36,797행** · `eval_subset` 3,753행 · `strata_key` 129행 · eval 12,462(정본 12,461) · 강재 중 C1 비중 0.6319(정본 0.6194) |
| `manifest_pre_e3.csv` | 위와 동일 + `phash_hex`·`group_id` **전량** 다름, `group_size` 2,960행 |

80번 E16 이 "파일명 하나를 잘못 고르면 26,738장의 평가셋 소속이 뒤집힌다"고 한 것이 이 둘이다.

**(나) 위험도 중 — 같은 분할, 전처리 이전 경로 2벌**

`manifest_pre_histmatch.csv`·`manifest_pre_mask.csv` 는 `split`·`client` 차이가 **0** 이다.
분할이 같아서 덜 위험해 보이지만 `rel_path`·`sha256` 이 **전량** 다르다 — 틀린 이미지
파일을 읽는다.

**네 벌 전부 `rel_path`·`sha256` 이 전량 다르다.** 어느 것을 집어도 동결본이 아닌 화소가
학습에 들어간다. 80번은 분할 차이만 봤는데, 화소 경로 쪽이 더 넓게 걸린다.

**(다) 분할 메타 2벌 — 성격이 정반대다**

| 파일 | `dirichlet` | 판정 |
|---|---|---|
| `split_meta.json` | seed_used **20260844** · attempts **17** · c1_share **0.6319** | **폐기값.** 위 (가)에 대응. 80번 E21 이 지목한 파일 |
| `split_meta_e3.json` | seed_used **20260839** · attempts **12** · c1_share **0.6194** | **폐기가 아니다 — 정본 분할의 유도 원본** |

`data_capabilities.yaml`(해시 잠금)의 `split_meta` 가 정확히 `20260839 / 12 / 0.6194` 이고,
`scripts/freeze_snapshot.py` 가 **`split_meta_e3.json` 을 읽어 그 값을 만들었다.**
즉 값은 이미 잠긴 파일에 흡수됐고 이 파일은 그 유도 근거다. "폐기본"으로 처리했으면
정본의 근거를 잃는다. `attic/README.md` 에 이 구분을 명시했고, 시험으로도 고정했다
(`split_meta_e3` 는 정본과 같아야 하고 `split_meta` 는 **달라야** 통과).

`split_meta.json` 도 지우지 않았다 — `encode` 설정·`discarded 688`·재질×결함 4층
`accounting` 이 이 형태로는 여기에만 있다(74번 §3-3 이 688 의 소재로 지목한 파일이다).

### 2-3. 격리보다 큰 사고 경로를 찾았다 — 스크립트 셋이 정본을 직접 덮어쓴다

지시 범위 밖이지만 같은 디렉터리의 문제라 함께 처리했다.

`run_dedup_v1.py` · `run_hist_match.py` · `run_border_mask.py` 셋은 **`V1/manifest.csv` 를
직접 `open("w")` 로 덮어쓴다.** 동결 전에 쓰인 코드라 스스로 `"SNAPSHOT 은 잠그지 않았다"`
라고 출력한다. 지금은 잠겨 있으므로 **재실행 한 번이 동결본을 지운다.**

넷째가 더 있었다 — `data/convert/encode_runner.py` 는 `--manifest-out` 으로 받은
디렉터리에 매니페스트·`split_meta.json`·`distribution.csv` 를 쓴다. **경로를 인자로 받으므로
동결본을 겨누는 것을 코드가 막지 않는다.** 여기도 두 진입점에 같은 가드를 걸었다.

읽기 전용 속성만으로는 부족하다. `PermissionError` 는 무슨 일이 벌어진 건지 말해 주지
않고, 속성을 푸는 순간 조용히 성공한다. 그래서 **파일 속성이 아니라 계약의 존재로** 막는다.

`data/frozen_guard.py` 를 새로 두고 네 스크립트의 **단계 진입점**에서 부른다
(중간이 아니라 진입에서 — 그래야 비싼 불변조건 검사를 돌리기 전에 멈춘다).

```python
assert_writable(V1, what="동결 매니페스트 디렉터리")
```

메시지에 **무엇을 해야 하는지**를 적었다("재파생이 필요하면 `--outdir` 로 새 경로를 주고
새 스냅샷으로 잠근 뒤 어느 쪽이 정본인지 의사결정로그에 남겨라"). 권한 오류만 던지면
다음 사람이 읽기 전용을 풀고 다시 돌린다 — 그게 정확히 막으려는 사고다.

세 스크립트가 만들던 직전본 파일도 `attic/` 에 쓰도록 경로를 바꿨다. 읽는 쪽 셋
(`measure_hist_match_contrast` · `measure_clamp_feasibility` · `freeze_snapshot`)은
경로를 직접 쓰지 않고 `legacy_path()` 를 부른다. 이 함수는 `attic/` 을 먼저 보고,
본 디렉터리에서 발견되면 **격리가 풀린 것이므로 알린다.**

## 3. 층화 채점의 층 (지시 3항, 총괄 판정 6)

### 3-1. 재실행 가능 여부 — 확인했다

`scripts/recompute_baselines.py` 를 f8518ae 머지 후 다시 돌렸다. **값이 그대로 재현된다.**

```
검산 (출처×재질 6셀): 접두사 0.346486 / 전수열거 0.346486 / 벡터 0.346486 → 일치
감사 재현 idq4                 보고 0.3877 · eval 절단점 0.3875 · train+val 절단점 0.3541
감사 재현 prov3xmaterial2xidq4 보고 0.5940 · eval 절단점 0.5937 · train+val 절단점 0.4912
게이트 = 0.9149 (족 idq512) · 통과선 = 0.9199
```

### 3-2. D 가 소비할 경로 — 명시할 만한 경로가 없어 만들었다

지시는 "경로를 보고에 명시"였다. 그런데 확인해 보니 층 정의가
`scripts/recompute_baselines.py` 의 내부(`Population`·`make_cuts`·`GRANULARITY`)에만 있어
**D 에게 줄 만한 경로가 없었다.** 스크립트 내부를 import 하라고 하면 D 가 결국 채점기에서
다시 구현하고, 그때 **분위 절단점을 어느 모집단에서 뽑느냐**가 어긋난다. 그게 정확히
74번 A-2 의 사고 유형이고, 76번 §1-5 에서 감사 자신도 걸린 지점이다(평가셋 분위 0.3877 대
train+val 분위 0.3541 — 같은 이름으로 다른 것을 잰다).

그래서 최소한으로 소비 지점을 만들었다.

| 경로 | 내용 |
|---|---|
| `data/id_strata.py` | `stratum_of(image_ids, k)` → 층 번호. **절단점은 train+val 에서만** |
| `data/interim/manifest_v1/id_strata_k16.csv` | `image_id,split,stratum` (K=16) |
| `data/interim/manifest_v1/id_strata_k64.csv` | 같음 (K=64) |
| `materialize(k)` | 다른 K 가 필요하면 표를 새로 쓴다 |

`tests/test_id_strata.py` 가 **`recompute_baselines.py` 의 `idq` 축과 층이 비트 단위로
같은지** 확인한다(K=4·64). 갈리면 76번의 천장 수치와 채점기의 층이 서로 다른 것을 가리키게
되므로 그 시험이 정합의 잠금이다. 절단점이 평가셋에서 오지 않는지도 따로 건다.

### 3-3. K 는 A 가 정하지 않았다

층이 잘아질수록 통제는 세지지만 층당 표본이 줄어 분산이 커진다. 그 절충은 채점 설계(D)와
총괄의 판단이라 모듈은 K 를 받기만 한다. 판단 재료만 적는다.

| K | 평가셋 층당 장수(중앙값) | 최소 |
|---|---|---|
| 16 | 약 780 | — |
| 64 | **199** | 57 |

`diagnose_id_axis.py` 의 순도 증거(구간 순도 중앙값 1.000, 무작위 기준선 0.445,
구간 안 train↔eval L1 중앙값 0.0000)는 **K=64 에서 잰 것**이라 K=64 가 서술과 맞는다.
다만 층당 57장짜리 층이 생기므로 부트스트랩 신뢰구간이 넓어진다 — D 판단이다.
