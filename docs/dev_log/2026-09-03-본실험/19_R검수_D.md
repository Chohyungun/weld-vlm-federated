### 1-8. 18번 §5 미결 3건에 대한 판단

1. **실 `Strategy.start` 경로 CPU 시험 부재.** 수용. 오프셋 소비처는 §1-2 대로 소스로 닫히고 T-smoke-resume 가 실기로 덮는다. 다만
   창의 Ray 실기가 무관한 이유(메모리·SuperLink)로 실패하면 배선 검증이 통째로 미뤄지므로, 가짜 `Grid`(`get_node_ids`·`create_message`·
   `send_and_receive`)로 flwr 의 진짜 `start` 를 도는 30줄짜리 CPU 시험을 R 후속에 권한다(Minor 3).
2. **T-eq 중단 시점·kill 대상.** 트리거 `runs/r002_c0/args.yaml` 는 라운드 3 C1 트레이너 `__init__`(`trainer.py:150`)이라 라운드 2 의
   accounting 덤프·npz·index 가 끝난 뒤다 → k=2 보장. 변형 1(액터 kill)은 에러 응답 → RoundFailure → `finally` 실행(audit 있음)
   경로, 변형 2(flwr-simulation kill)는 `finally` 미실행(audit 없음) 경로. **실제 두 번의 사망은 모두 변형 2 의 형태**(SIGINT 자체
   종료·하드킬)이므로 변형 2 를 "시간이 남으면" 이 아니라 **필수**로 두길 권한다 → Important 2. 액터 kill 뒤 Ray 가 액터를 되살려
   무중단 완주하면 `TeqInvalid`(exit 2)로 무효 처리되어 거짓 PASS 는 없다.
3. **`effective_batch` 가드 직접 시험 부재.** 수용(Minor). T7 은 통과 경로만 본다. 두 번째 층 `optimizer_steps == epochs×ceil(n/32)`
   가 이빨 시험이 있고 실물 178 셀에서 성립하므로 가드가 안 울려도 마감이 잡는다. 가짜 트레이너(`train()` 뒤 `batch_size=16`)로
   `train_round` 를 부르는 단위 시험을 R 후속에.
