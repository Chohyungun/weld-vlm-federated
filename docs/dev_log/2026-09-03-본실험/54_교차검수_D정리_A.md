## 1. n-1 — `is_main_output` 경계 찌르기

```python
parts = [p.casefold() for p in Path(os.path.abspath(str(out))).parts]
return any(parts[i:i + 2] == ["outputs", "main_d"] for i in range(len(parts) - 1))
```

스크래치 사본의 함수에 가짜 경로를 넣었다(프로브 스크립트, 실행 디렉터리 = 사본 루트).

| 경로 | 결과 | 기대 |
|---|---|---|
| `<wt_A>/outputs/main_d/seed1` (정션 경로) | True | ○ |
| `<본체>/outputs/main_d/seed1` (정션 대상) | True | ○ |
| `outputs/main_d/seed1` · `./outputs/./main_d/seed1` (상대) | True | ○ — `abspath` 가 작업 디렉터리 아래로 절대화 |
| `outputs/pilot_d/../main_d/seed1` (`..` 로 되돌아옴) | True | ○ |
| `outputs/main_d/../pilot_d` · `outputs/main_d/..` (`..` 로 벗어남) | False | ○ — 정규화 뒤 성분으로 본다 |
| `outputs\main_d\seed1` (역슬래시) | True | ○ |

**Windows 이름 정규화.** `outputs/main_d./seed1`(끝 점)은 파일시스템이 `main_d` 로 접는데 `os.path.abspath` 도 같은 Win32
정규화를 거쳐 `main_d` 가 되므로 **True** — 우회 없음(스크래치에서 실제로 `main_d.` 로 만들면 `main_d` 가 생기는 것을 확인).
`outputs/main_d /seed1`(끝 공백)은 생성 자체가 `WinError 3` 로 실패해 쓸 수 없다. **8.3 짧은 이름:** `outputs`·`main_d` 는
8자 이하라 짧은 이름이 긴 이름과 같다(`GetShortPathName` 이 그대로 돌려줌) — 별칭 경로가 없다.

**그대로인 것.** 파일럿 루트(`outputs/pilot_d`) v1 은 `protected=False` 로 다시 쓴다(`"w"`). `gate` 부명령은 `gate_recheck_*_v1.json`
을 `"w"` 로 쓰며 `artifact_dest` 를 거치지 않는다(958행, 변경 없음). 레코드 파일(`record_path`)은 존재하면 되읽어 대조하고
없을 때만 쓴다(660~672행, 변경 없음). **배타 생성:** 보호 대상(v2 이상 · 본실험 루트 v1)은 `dest.open("x")`, 그 외 `"w"` —
`artifact_dest` 의 존재 확인과 쓰기 사이에 파일이 생겨도 덮지 않는다.
