## 2. 대응 결정

1. **라운드 1 부터 재실행**(R 미착지, G5). 실패 원장은 `sep_fed_failed_20260907_r23/` 로 이동(라운드 1~22 벽시계는 속도 표본으로 유효, 채점 금지), `_resume` 덤프 격리, 로그 이름 변경.
2. **B 를 재실행에 포함.** 근거: (a) 검증 워커 12개의 프리페치(48 배치 × 64 = 3,072장)가 기동 I/O 폭주의 대부분이라 정지를 부른 요인을 직접 줄인다, (b) 커밋 −13.7 GB, (c) 등가는 14번 §B-4 소스 논증 + **재실행 라운드 1 = 오라클**(`global_r001.npz` sha256 `5c0378a1…`, C1/C2/C3 `param_l2` 192.23213244102195 / 194.41977624944028 / 190.76837433025506, `global_l2` 192.23750521425777). 불일치면 감시 스크립트가 체인을 즉시 정지 → B 제거 → B off 재실행 → 총괄 보고. 라운드 2·3 도 09-04 run 과 대조(0c436ad8…, 3b874b53…).
3. **시드 1 안 비대칭(②③ B off / ④ B on)은 예외로 기록.** 계산은 오라클로 동일, 호스트 메모리·기동 시간만 다름. `val_loader_workers` 증빙 필드(②③ meta.json 은 None, ④ 는 0)와 속도 축 각주(트레이너 생성 오버헤드 분해, 14번 §B-5)로 표시한다. 시드 2·3 은 ②③④ 전부 B on.
4. **하트비트 TTL 환경 완화.** 상수를 CLI 나 env 로 바꿀 수 없으니 venv 의 `flwr/common/constant.py` 를 패치(30→300)하고 sha256 전후·패치 diff 를 10번에 기록, 기동 스크립트가 값을 검증(다르면 exit 2). uv sync 가 되돌릴 수 있으므로 착수 전에 검증해야 한다. 계산 경로·집계·클라이언트 코드에 닿지 않는다.
5. **venv 의 SSD 이관(C:)** 은 별건 등록(§4). 기동 I/O 의 나머지(워커 spawn 시 torch·ultralytics 적재)를 없애지만 경로 가정이 넓어 시드 3 창 이후 검토.

## 4. 조건·후속

- **구현 위치.** B 즉시분은 wt/C 작업트리(재실행이 그 트리의 FAB 를 쓴다). 그 커밋 이후 **wt/C 의 추적 코드 경로(`fl/ detection/ scripts/ tests/ pyproject.toml configs/`) 편집 금지** — 시드 2 는 ④ 에 들어갈 때 ④ FAB 를 디스크에서 다시 빌드하기 때문. R 은 별도 worktree(`wt/C-bdr` 브랜치)에서 구현·CPU 시험하고 시드 3 창에서만 wt/C 로 착지.
- **독립 검수.** B 즉시분은 D 가 diff 검수(재실행과 병행, 발견 시 즉시 정지). R 은 착지 전 D 검수 필수(회계·감사 변경의 소비자).
- **오라클 판정 자동화.** C 의 감시 스크립트가 `[ROUND 2/50]` 시점에 sha256·회계 대조 → 불일치면 체인 정지·보고. 라운드 2·3 도 대조.
- **별건 등록.** venv(E: HDD) 의 SSD 이관 — SuperLink 콜드 기동 18 s, 워커 spawn 적재, 이번 정지 가설이 전부 같은 원인을 가리킨다. 시드 3 창 이후 검토(경로 가정·속도 축 비교 가능성 포함).
- 10번에 사망 #2 타임라인·B 착지 커밋/FAB 해시·패치 sha256·오라클 결과를 기록. 의사결정로그는 총괄이 갱신한다.
