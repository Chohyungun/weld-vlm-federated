### 4-3. 구현 방식 변경 — 원숭이 패치 → 공개 훅

설계는 "`optimizer.step` 을 래핑" 이었다. 실측으로 두 결함을 확인해 **`optimizer.register_step_post_hook`** 로 바꿨다.
- torch 2.11 `LRScheduler.__init__` 은 `optimizer.step.__func__` 를 요구한다. 우리 래퍼가 먼저 걸리면 그 뒤 스케줄러 생성이 죽는다. 상류가 스케줄러를 다시 만드는 경로(`args.time`, OOM 자동 축소의 `_build_train_pipeline`)가 있다.
- 래퍼 클로저가 트레이너를 참조해 optimizer↔trainer 순환을 만든다. 라운드마다 트레이너를 새로 만드는 ④ 에서 가중치 한 벌이 gc 패스까지 더 상주한다.

공개 훅은 `optimizer.step` 을 건드리지 않으므로 순서 제약이 없고, `load_state_dict` 뒤에도 남는다. GradScaler 가 inf/NaN 에서 `optimizer.step()` 을 건너뛰면 훅도 불리지 않는다. 훅은 `optimizer_step` 마다 멱등하게 다시 걸어 옵티마이저가 새로 만들어져도 계수가 이어진다. CPU 프로브 실측:
