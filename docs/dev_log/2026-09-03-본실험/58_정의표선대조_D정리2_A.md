## 2. A 의 소스 독해 요약 — D 표를 보기 전에 적은 것

1. `setDetParams`: `iouThrs = linspace(.5,.95,10)`, `recThrs = linspace(0,1,101)`, `maxDets=[1,10,100]`, `areaRng[0]='all'=[0,1e10]`, `useCats=1`.
2. `_prepare`: gt/dt 를 (image_id, category_id) 로 묶는다. `ignore = iscrowd`.
3. `computeIoU`: dt 를 `-score` **mergesort(안정)** 정렬 후 `maxDets[-1]` 로 자른 뒤 `maskUtils.iou(d, g, iscrowd)` — 행 dt(점수순), 열 gt(원본 순).
4. `evaluateImg`: gt 를 무시 플래그로 안정 정렬(무시 0 뿐이면 원본 순), dt 를 점수순 안정 정렬 후 `maxDet` 절단. 문턱마다 dt 순회 —
   `iou = min(t, 1-1e-10)` 에서 시작해 gt 를 순서대로 보며 `ious < iou` 면 건너뛰고 아니면 `iou` 를 갱신하고 `m` 을 그 gt 로 —
   즉 **문턱 이상인 gt 중 IoU 최대, 동률이면 뒤쪽**(`<` 라 같음은 갱신). 이미 매칭된 gt 는 crowd 가 아니면 건너뛴다.
   기록은 `dtm[t,d] = gt[m]['id']`, `gtm[t,m] = d['id']` — **id 의 참/거짓이 곧 매칭 여부**다.
5. `accumulate`: 카테고리·면적·maxDet 마다 이미지들의 결과를 이어 붙여(`p.imgIds` 순) `-score` 안정 정렬, `npig`(무시 아닌 gt 수) 0 이면 건너뜀
   (정밀도 −1). `tps = dtm & ~dtIg`, `fps = ~dtm & ~dtIg`, 누적합, `rc = tp/npig`, `pr = tp/(fp+tp+np.spacing(1))`, 뒤에서부터 포락선,
   `searchsorted(rc, recThrs, side='left')` 로 101점 표본, 범위 밖은 `except: pass` 로 0 유지.
6. `_summarize(1, iouThr=.5, maxDets=100)`: `precision[t=.5][:, :, all, 100]` 에서 `s > -1` 인 값을 **평탄하게 한 번에 평균**.
   정밀도 0 은 포함, 부재 카테고리(−1)는 블록째 제외. 각 카테고리가 101개씩이라 카테고리별 AP 평균과 같다.
7. 함정으로 짚어 둔 것: id 0 은 매칭이 안 된 것으로 보인다(4); ε 때문에 완벽 매칭도 AP 가 1 이 아니다(5); 절단은 세 곳(3·4·5)에서 같은
   규칙으로 반복된다; 문턱 비교는 `≥`; `np.unique(imgIds)` 로 이미지 순서가 정수 정렬이다.

## 5. 수정·보강 목록 (승인 조건이 아니라 구현자에게 넘길 명세 보강)

- **a. #9 문구.** "IoU ≥ 문턱인 것을 고른다" 를 **"문턱 이상인 미매칭 정답 중 IoU 가 최대인 것(동률은 #10: 뒤쪽)"** 으로. 지금 표는 #9 와 #10 을
  합쳐 읽어야 최대값 선택이 드러난다 — 첫 번째 문턱 통과 gt 에서 멈추는 구현을 막기 위해 한 문장으로 적어 달라.
- **b. #18 추가 — id 는 1 부터.** pycocotools 는 매칭을 `dtm = gt['id']`·`gtm = dt['id']` 로 기록하고 `accumulate` 가 그 **참/거짓**으로
  tp 를 센다(§2-4, 실측 §3: gt id 0 → AP 0). 프로젝트 빌더는 gt `ann_id = 1` 부터, 이미지 `i+1`, 카테고리 `i+1`, dt 는 `loadRes` 가 1 부터
  (`localization.py:302-322`) — 지금 채점에는 영향이 없다. 그러나 **시험 2(합성 무작위, pycocotools 비트 대조)의 픽스처와 I 모드의 자기 id 는
  반드시 1 부터** 매겨야 한다. 두 번째 구현은 id 의 진릿값에 기대지 말고 명시적 매칭 표를 써라.
- **c. #4 보강.** ε 때문에 완벽 매칭의 AP 가 `0.9999999999999999` 다(§3). 손계산 픽스처(시험 1)에서 "AP = 1.0" 으로 적으면 1e−12 안이지만
  비트 대조에서는 다르다 — 픽스처 기대값은 pycocotools 실측값으로 적거나 허용 차를 명시해 달라.
- **d. #5 보강.** 절단은 `computeIoU`·`evaluateImg`·`accumulate` 세 곳에서 같은 규칙(점수순 상위 `maxDet`, 이미지·카테고리 단위)으로 반복된다.
  `map_50` 은 `_summarize(1, iouThr=.5, maxDets=maxDets[2]=100)` 조각이다. 프로젝트가 `maxDets` 를 바꾸지 않는다는 것을 `localization.py:240` 이
  못박고 있으니 표에 "기본 `[1,10,100]`, 채점은 100 조각" 을 적어 두면 I 모드가 다른 값을 쓸 여지가 없다.
- **e. #8 보강.** 이미지 목록은 `sorted(gold)` **전체**(정답 없는 정상 이미지 포함)라 검출만 있는 이미지의 FP 가 셈에 든다. 정답·검출 둘 다 없는
  이미지만 `evaluateImg` 가 `None` 을 돌려 빠진다(#17). I 모드가 이미지 목록을 매니페스트 평가셋 전체로 잡아야 같은 결과다.
