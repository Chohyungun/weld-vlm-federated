## 1. 총괄이 직접 검증한 것

### 1-1. F01 — 전면 수용. 독립 재현으로 확정했다

**감사자 주장:** `loader_reseed_per_epoch=False` 가 실제 기본값이고, Ultralytics 가 로더 생성기를
상수 `6148914691236517205 + RANK` 로 시드하므로 라운드마다 새 로더를 만드는 연합은 같은 첫 두
epoch 순열을 반복한다. `R×E=N` 은 원본 이미지 방문 횟수의 등가일 뿐이다.

**총괄 독립 재현.** 감사자 스크립트를 쓰지 않고, Ultralytics 를 import 하지도 않고,
그 코드가 하는 구성(상수 시드 `torch.Generator` + `RandomSampler` + `_RepeatSampler`)을 직접 만들어
확인했다. 재현 스크립트는 총괄 세션 임시 폴더에 있고 본문 아래에 전문을 옮긴다(§4-1).

| 경로 | 100 epoch 동안 본 서로 다른 순열 수 |
|---|---|
| 연합 흉내 — 라운드마다 로더 신규, 각 2 epoch × 50 | **2** |
| 중앙집중 흉내 — 로더 1개로 100 epoch 연속 | **100** |
| 참고: epoch 기반 재시드를 켠 경우 | 100 |

라운드 1·2·9 의 첫 epoch 앞 12개가 `[47, 15, 58, 46, 5, 2, 24, 17, 0, 1, 34, 49]` 로 완전히 같았다.

**코드 확인.** `detection/fed_trainer.py:184`·`detection/round_runner.py:187` 이 기본값 `False` 이고,
`detection/train_cell.py`·`fl/client_det.py`·`scripts/main_det.py`·`configs/` 어디에서도 `True` 로
넘기지 않는다(grep 전수, 호출 0건). **본실험 시드 1·2 전 구간이 재시드 없이 돌았다.**

**이 프로젝트가 이미 알고 있었다는 점을 함께 적는다.** `detection/fed_trainer.py:102-112` 의
`LoaderReseed` docstring 이 바로 이 문제를 "숨은 기본값 #9" 로 서술하고 해결책까지 구현해 두었다.
만들어 놓고 켜지 않았다 — 감사 보고서가 §4 에서 지적한 "선언과 실행의 불일치" 의 전형이다.

**함의 — 우리에게 불리한 방향이다.**
1. `R×E=N` 은 "학습량 등가" 가 아니라 **"원본 이미지 방문 횟수 등가"** 다. 논문의 공정성 주장 문구를 고쳐야 한다.
2. 연합은 데이터 순서 다양성이 낮은 상태로 학습했다. 즉 **지금까지 잰 회복률은 연합을 과소평가한 값일 수 있다.**
   결과를 부풀린 방향이 아니라 깎은 방향이라는 점을 밝혀 둔다 — 그렇다고 설계 결함이 아닌 것은 아니다.
3. F02(연합에만 있는 epoch 91 단절)의 유력한 설명이 된다(§1-2).

**조치(총괄 결정).**
- **시드 3 은 지금 코드 그대로 돌린다.** 시드 사이에 학습 조건을 바꾸지 않는다는 원칙이 우선이다.
  재시드를 켜면 시드 3 만 다른 조건이 되어 3세트 분산 추정이 성립하지 않는다. 감사자 권고("수정 후
  시드 3만 실행해 기존 시드 1·2 와 합치지 않는다")와 결론이 같되, 우리는 **시드 3을 기존 조건으로 돌려
  3세트를 완성하고, 재시드는 별도 통제 실험으로 분리**하는 쪽을 택한다. 이 선택의 근거를 §5 열린 질문 Q1 에 올린다.
- 재시드 통제 실험은 시드 3 완주 후 GPU 여유가 생길 때 별도 프로토콜로. 켜고 끈 두 조건을 **다섯 칸 전부에**
  적용해야 비교가 되므로, 한 칸만 다시 돌리는 것은 답이 되지 않는다.
- 논문 문구 수정을 E 에 배분한다(§3).

### 1-3. F06 — 전면 수용. 총괄 판정을 철회한다

**무엇이 틀렸나.** 총괄은 09-08 판정(22번 §6-2-5)에서 `Δ_AUC` 를 "지름길 면역과 임계 독립을 동시에
만족하는 유일한 축" 이라고 적었다. 근거는 "출처(N-crop)를 상수로 묶은 구간 안에서는 출처만 읽는
예측기가 상수로 퇴화해 정확히 0" 이었다. **그것은 출처 하나에 대한 면역이지 지름길 일반에 대한 면역이 아니다.**
촬영 ID·시기 같은 다른 지름길은 N-crop 구간 안에서도 살아 있다.

감사자 반례(같은 N-crop 모집단, 평가셋 정답으로 규칙을 적합하지 않음):

| 방법 | Δ_AUC |
|---|---|
| **촬영 ID 만 쓰는 빈도 규칙** | **0.6177** |
| 개별 C2(실모델 최고) | 0.5827 |
| 연합 | 0.5722 |
| 중앙 | 0.5324 |

화소를 한 번도 안 보는 규칙이 다섯 모델을 전부 이긴다.

**아픈 지점은 이것이 어제 고친 잘못의 반복이라는 것이다.** 09-08 에 총괄은 macro-AP 를 분류 축 대표로
올리면서 그 축의 무내용 대조선을 함께 옮기지 않았고, 내부 검증이 그것을 잡아 판정을 고쳤다(22번 §5·§6).
그러면서 **같은 문단에서 `Δ_AUC` 를 후보로 올릴 때는 그 축의 대조선을 요구하지 않았다.** 방어선을
지표마다 따라 옮겨야 한다는 교훈을 적어 놓고 바로 옆에서 어겼다.

**조치.**
- 22번 §6-2-5 의 "지름길 면역" 근거를 철회한다. `Δ_AUC` 의 성질은 **"출처 단일 변수의 영향 제거"** 로만 기술한다.
- `Δ_AUC` 후보 지위는 유지하되 **무내용 대조선(촬영 ID 빈도 규칙 포함)을 등록하기 전에는 어떤 문서에도
  대표·보조 지표로 적지 않는다.** D 에 산출을 배분한다(§3).
- "연합이 중앙집중을 넘는다(+0.0398)" 는 관측 자체는 남는다. 다만 그 위에 "그러나 촬영 ID 규칙이 셋 다
  넘는다" 를 반드시 병기한다. 병기 없는 인용을 금지한다.

### 1-4. F07 — 수용. 총괄 논증을 수정한다

총괄은 22번 §2-3 에 "지름길이 다섯 칸 전부에 같은 방향으로 실려 있으므로 칸 사이 비교는 성립하고
절대 점수의 해석만 무너진다" 고 썼다. 감사자 지적대로 **방향이 같아도 의존 강도가 모델마다 다르면
상대 순위와 회복률이 바뀐다.** 실제로 크롭 정상 오탐률이 모델별 18.5~49.4% 로 2.7배 차이가 난다.

이 지적은 09-08 내부 검증에서도 두 번 제기됐다가 3렌즈 반박에서 각각 1/3 로 갈려 기각됐고, 종합자가
"성급한 기각" 목록에 올려 두었다. **총괄이 그 경고를 읽고도 문장을 고치지 않았다.** 외부 감사가 같은
곳을 다시 짚은 것은 그 판단이 틀렸다는 뜻이다.

**조치.** "같은 방향이므로 비교가 성립한다" 는 문장을 판정문·논문·D 보고에서 모두 내린다. 대신
(a) 출처별 지표를 항상 병기하고, (b) 동일 출처 구성비로 재가중한 분석을 추가하며, (c) "현재 혼합
모집단에서의 비교" 와 "현장 일반화" 를 문장 단위로 구분한다. D·E 에 배분한다(§3).

### 1-5. F08 — 수용

통합형과 분리형은 영상 해석기(YOLO11s vs Qwen 시각 인코더)가 다르고 RAG 유무도 다르다. "같은 백본을
공유하므로 구조 효과를 분리했다" 는 서술은 판정부에만 해당한다. 통합형이 아직 미착수라 지금 고치는
것이 비용이 가장 싸다. 주장을 "두 완성 시스템의 비교" 로 한정하고, 구조만의 인과 효과는 별도 대조
없이는 주장하지 않는다. E 에 배분한다(§3).

### 1-6. F15 — 수용(기존 인식과 일치)

실영상의 규정 합부·근거 신뢰도가 미입증이라는 지적은 프로젝트 자체 기록과 어긋나지 않는다.
픽셀→mm 변환 재료 부재는 함정 #10 으로 등록돼 있고 판정 과업을 "조항 검색 + 기준 서술" 로 좁히는
것이 전제였다. 다만 **그 축소가 논문 문안에 충분히 반영됐는지는 별개**이며 E 가 확인한다.
감사자가 제안한 "`clause_only` 에서 조항 선택과 수치 행 선택을 분리" 는 D 가 실현 가능성을 답한다.

## 2. 감사 방법 자체에 대한 총괄 소견

되묻기 위해 적는다. 아래는 반박이 아니라 **확인 요청**이다.

1. **F06 반례의 적합 모집단.** "train+val 에 적합, 평가셋 정답으로 규칙을 적합하지 않았다" 는 서술을
   확인했다. 다만 `fit_idq(512)` 의 512 라는 분위 수는 저장소가 이미 고른 값이고, 그 선택은 과거에
   평가셋 관측을 본 뒤 이뤄졌을 수 있다. 반례의 강도를 낮추지는 않지만, **K 사다리 전 구간(2~512)에서
   같은 반례가 서는지**를 함께 보여 주면 우리 쪽 대조선 등록이 훨씬 단단해진다.
2. **F01 의 정량 함의.** 순열 다양성 2 대 100 은 확정됐다. 그러나 이것이 최종 성능에 얼마나 닿는지는
   통제 실험 전까지 미지다. 감사 보고서가 "R×E=N 은 원본 이미지 방문 횟수의 등가일 뿐" 이라고 한 것에
   동의하며, 우리는 여기에 **"그 차이가 연합에 불리하게 작용했을 가능성이 높다"** 를 덧붙인다.
   이 방향 판단에 이견이 있으면 알려 주기 바란다.
3. **F05 와 현재 완주본의 관계.** 감사자가 "이번 완료본은 재개 이력이 비어 있어 오염을 판정하지 않았다"
   고 명시한 점을 확인했다. 우리 원장도 같다(시드 1·2 `resumed_cells` 0). 이 부분은 서로 일치한다.

## 4. 재현 자료

### 4-1. F01 재현 스크립트

`scripts/probe/verify_f01_loader_permutation.py` 로 저장소에 넣었다 — 감사자가 그대로 돌려 볼 수 있다. Ultralytics 를 import 하지 않고 그 구성만 복제한다.
핵심은 `torch.Generator()` 를 **호출마다 새로 만들어 상수로 시드**하는 것이며, 이것이
`ultralytics/data/build.py:364-365` 가 하는 일이다. 감사자가 이 스크립트를 다시 반박하려면
"실제 학습 경로에서는 로더가 라운드마다 새로 만들어지지 않는다" 를 보이면 된다 —
우리 확인으로는 `detection/round_runner.py:289` 가 라운드마다 `FedDetectionTrainer` 를 새로 만들고
그 안에서 로더가 새로 생성된다.
