# 36. 미니스펙 — 회복률의 묶음 클러스터 부트스트랩 CI (트랙 D, 2026-09-16)

총괄 게이트 대상. 구현은 게이트 통과 뒤에 한다. **값을 보기 전에 판정 규칙을 고정한다** —
17번 §11 이 무내용 대조선에서 그렇게 했고, 그것이 22번 §6 판정을 방어 가능하게 만들었다.

## 0. 무엇을 왜

27번 §3-1 의 판정 ②가 비어 있다. 사전등록 §5-4 는 "분모 D 를 95% CI(묶음 단위 클러스터
부트스트랩 2,000회)와 반드시 병기" 를 요구하고, 41번은 트립와이어 단독의 검정력 부족을 실측해
**회복률 자체의 CI 반폭** 보조 판정을 처방했다. 둘 다 지금 없다. 그래서 `recovery_reportable`
이 `null`(미판정)이고 대표 숫자 +24.8 % 는 "실어도 되는가" 에 답이 없는 상태다.

막힌 이유는 비용이다. 대표 축 `mAP@50` 은 COCO 평가라 재표집 2,000회 × 칸 5 × 시드 3 =
30,000번을 `COCOeval` 로 다시 돌리면 며칠이다. 이 스펙은 그 비용을 **매칭 1회 + 집계 30,000회**
로 바꾸는 설계다.

## 1. 통계량 — 무엇의 CI 인가

| 항목 | 정의 |
|---|---|
| 축 | `mAP@50`, export 하한(conf ≥ 0.01) 레코드. 22번 §6-2-3 의 유일한 확정 대표 축 |
| 칸별 값 | `coco_map()` 과 **같은 규약**(pycocotools 기본, 이미지·카테고리 id 고정 매핑, 정상 이미지 포함) |
| 시드별 회복률 | `R_s = (연합_s − 로컬평균_s) / (중앙_s − 로컬평균_s)` |
| **판정 대상 통계량** | **`R̄ = (R_1 + R_2 + R_3) / 3`** — 27번 §3 의 "회복률의 평균", 대표 숫자 +24.8 % 그 자체 |
| 병기 통계량 | `R_s` 각각 · 분모 `D_s = 중앙_s − 로컬평균_s` 각각 · 칸별 mAP@50 (15개) |
| 재표집 단위 | `group_id` (평가셋 12,461장 → **1,245 묶음**, 크기 중앙값 7 · 최대 90). 이미지 단위는 쓰지 않는다 |
| 짝지음 | **한 번의 묶음 추첨을 15개(칸 5 × 시드 3) 전부에 같이 쓴다.** 그래야 `R_s` 와 `R̄` 의 CI 가 짝지은 대비가 된다(`score_threshold_free` 와 같은 원칙) |
| 횟수·시드·구간 | `BOOTSTRAP_N = 2,000` · `BOOTSTRAP_SEED = 20260825` · 백분위 2.5–97.5 % (기존 `cluster_bootstrap` 과 동일, BCa 아님) |
| 미정의 재표집 | `D_s ≤ 0` 이면 `R_s` 는 `nan`. **버리고 센다**(`drop_undefined=True` 규약). 버린 비율을 산출물에 싣는다 |

## 2. 계산 — 왜 정확히 같은 수가 나오는가

`COCOeval` 은 두 단계다. `evaluate()` 가 이미지×카테고리마다 매칭 결과(`dtMatches`·`dtScores`·
`gtIgnore`·`dtIgnore`)를 `evalImgs` 에 남기고, `accumulate()` 가 그것을 이어 붙여 PR 곡선과
AP 를 낸다. **매칭은 이미지 안에서 닫힌다** — 다른 이미지가 있든 없든 한 이미지의 매칭은 같다.

그래서:

1. (칸, 시드) 15개마다 `evaluate()` 를 **한 번** 돌려 `evalImgs` 의 `areaRng='all'`·`maxDets=100`
   조각을 캐시한다(디스크에 두어 재실행이 싸게).
2. 재표집은 묶음 추첨 → 이미지별 **중복도** `w_i ∈ {0, 1, 2, …}` 로 바뀐다.
3. `accumulate` 를 다시 구현하되, 이미지 `i` 의 검출·GT 항목을 `w_i` 번 **제자리에서 반복**한
   뒤 pycocotools 와 같은 순서로 정렬(`-score`, `mergesort` 안정 정렬)하고 같은 101점 보간으로
   AP 를 낸다. 같은 이미지가 두 번 뽑힌 것과 항목이 두 번 있는 것은 정확히 같은 계산이다.
   `npig`(무시 아닌 GT 수)도 `w_i` 배로 센다. 카테고리 평균은 pycocotools 와 같이 `npig > 0`
   인 카테고리만.

**항등 검사가 이 설계의 전부다.** 중복도가 전부 1 인 "재표집" 은 채점기가 낸 `map_50` 과
**부동소수 마지막 자리까지** 같아야 한다(15개 전부). 하나라도 어긋나면 집계 재구현이 pycocotools
와 다른 것이고, 그때는 **CI 를 내지 않고 멈춘다.** 근사값으로 판정하지 않는다.

비용: 매칭 15회는 일회성(칸당 수십 초). 집계는 numpy 로 검출 ~15만 건 × 카테고리 4 라
회당 수십 ms → 2,000 × 15 ≈ 수십 분. GPU 없음.

## 3. 판정 규칙 — 값을 보기 전에 고정

| # | 규칙 | 출처 | 상태 |
|---|---|---|---|
| ① | 트립와이어 `D ≥ 3·시드 sd` | 사전등록 §5-4 | 이미 판정됨(27번 §3-1, 세 정의 전부 충족) |
| ② | **`R̄` 의 95% CI 반폭 ≤ 0.25** (비율 단위, = 25 pp) | 41번 §4 제안. **미등록 — 이 게이트에서 확정** | 총괄 결정 필요 |
| ③ | **`D_s` 의 95% CI 가 세 시드 모두 0 을 배제** | §5-4 "D 를 CI 와 병기" 의 판정형. 분모가 0 을 품으면 비율은 정의 불가 구간을 지난다 | **신설 제안.** 값 보기 전 등록이라 사후 규칙이 아니다. 총괄이 기각하면 ②만 적용 |
| ④ | 미정의 재표집 비율 > 10 % 면 CI 를 헤드라인 근거로 쓰지 않는다 | 신설 제안 | 총괄 결정 필요 |

`recovery_reportable` = ① ∧ ② ∧ ③ ∧ ④ (채택된 규칙만). 하나라도 미달이면 `false`,
CI 가 안 나오면(항등 검사 실패 등) `null` 유지. `tripwire_only_reportable` 은 그대로.

②의 0.25 는 41번이 §5-4 의 델타법 예(D=0.08 → 반폭 31 pp)에서 "못 쓰는 구간" 경계로 잡은
값이다. 지금 바꾸면 3세트 값을 본 뒤의 변경이 되므로 **그대로 등록하기를 제안**한다. 등록
자리는 `configs/base.yaml` `fixed_before_main_runs`(A 소관) 또는 이 게이트 문서 — 총괄 지정.

## 5. 시험

| # | 무엇 | 어떻게 |
|---|---|---|
| T1 | **항등** | 실측 15개 (칸, 시드) 에서 중복도 전부 1 → `map_50` 과 1e-12 이내 일치. 불일치면 실행 중단 |
| T2 | **중복 = 반복** | 합성 COCO 픽스처에서 이미지를 새 id 로 물리적으로 복제한 데이터를 pycocotools 로 직접 평가한 값 = 원본 + 중복도로 낸 내 집계값. 동점 검출·빈 이미지·GT 0 카테고리 포함 |
| T3 | 결정론 | 같은 입력·같은 시드 → 같은 CI |
| T4 | 미정의 처리 | 분모 ≤ 0 인 재표집이 버려지고 세어진다 |
| T5 | 정책 배선 | CI 반폭이 임계 안/밖인 합성 입력으로 `recovery_reportable` 이 `true`/`false`, 파일 없으면 `null` |

## 6. 위험

- pycocotools 내부(`evalImgs` 구조·정렬 종류)는 비공개 API 다. 버전이 바뀌면 깨질 수 있다 — T1·T2 가 그때 잡는다. 통과 못 하면 구현을 고치지 값을 내지 않는다.
- 동점 검출의 정렬 순서가 AP 에 영향을 준다. 제자리 반복은 pycocotools 의 안정 정렬에서 "같은 이미지가 두 번" 과 같은 순서를 만든다 — T2 가 이것을 본다.
- 묶음 1,245개 중 큰 묶음(최대 90장)이 CI 를 넓힐 수 있다. 그것이 사실이면 넓은 것이 맞다.

## 7. 총괄 결정 요청

1. 규칙 ②의 0.25 를 그대로 등록하는가, 등록 자리는 어디인가.
2. 규칙 ③·④를 채택하는가(둘 다 값 보기 전 신설).
3. 판정 대상 통계량을 `R̄`(3세트 평균)로 두는 것에 동의하는가 — 시드별 `R_s` 는 병기.

셋에 답이 오면 구현에 들어간다. 그 전에는 코드를 쓰지 않는다.
