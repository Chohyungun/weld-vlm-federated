## 1. 과제 1 — 동결 표식과 거부 가드

### 1-1. 저장소가 쓰는 표식은 무엇인가 (먼저 확인하라던 것)

세 종류가 후보였고, **하나만 계약이다.**

| 표식 | 실물 | 판정 |
|---|---|---|
| `SNAPSHOT.sha256` | `cycle_pilot` · `cycle_pilot_v2` · `pairs_pilot_v1` · `pairs_pilot_v2` · `manifest_v1` · `aihub71761_rt_v1_pilot3000` 계열 3개 | **계약이다.** A 트랙이 `data/frozen_guard.py` 로 이미 정의했고 5개 스크립트가 쓴다 |
| `DO_NOT_CITE.md` | `cycle_pilot/` 한 곳 | 계약이 아니다. "이 산출물을 논문에 인용하지 마라"는 **품질** 표식이고, 봉인 여부와 독립이다 |
| 읽기 전용 파일 속성 | 일부 | 계약이 아니다. 누구나 풀 수 있다 — `data/frozen_guard` 의 시험이 이미 이 전제를 고정하고 있다 |

그래서 **판정은 `SNAPSHOT.sha256` 의 존재 하나로 한다.**

### 1-2. 재구현하지 않았다

계약 판정(`is_frozen`)과 예외형(`FrozenDirectoryError`), 계약 파일명 상수(`CONTRACT_NAME`)는
`data.frozen_guard` 것을 **그대로 가져다 쓴다.** 74번 감사 P6(어휘 락 재구현)이 지적한 것이
정확히 이 패턴이라, 로직을 두 벌로 두지 않았다.

새로 만든 `corpus/generate/frozen_out.py` 가 감싸는 것은 **사람이 읽는 문장뿐**이다. 이유는
하나다 — `assert_writable` 의 본문이

> "이 스크립트는 manifest.csv 를 덮어쓰므로 … `--outdir` 로 **새 경로**를 주고"

라고 매니페스트 파이프라인을 지목한다. corpus 사이클에는 `manifest.csv` 도 `--outdir` 도 없어서,
그 문장을 읽은 사람은 **없는 플래그를 찾는다.** 그 함수 자신의 docstring 이 "권한 없음만 던지면
다음 사람이 읽기 전용 속성을 풀고 다시 돌린다"고 경계한 실패와 같은 종류다.

> **총괄 보고(A 소관, 손대지 않음):** `data/frozen_guard.assert_writable` 의 본문은 매니페스트
> 전용 문구로 고정돼 있고 `what=` 만 바꿀 수 있다. `data/convert/encode_runner.py` 도 이미
> `--manifest-out` 을 겨누며 같은 어긋남을 안고 쓴다. 문구를 인자로 받도록 일반화하면 corpus
> 쪽 wrapper 를 지울 수 있다. **A 트랙 파일이라 고치지 않았다 — 배분은 총괄이 한다.**

### 1-3. `--force` 를 두지 않은 이유

지시는 "우회를 **두려면** 무엇을 지우는지 찍고 사람이 확인하게 하라"였다. 두지 않기로 했다.

규약 1-6 이 "sha256 부여 후 재생성 금지"이므로 봉인본을 **제자리에서** 덮어쓸 정당한 사유가
없고, 탈출구는 이미 있다 — `--out` 에 새 경로를 준다. 플래그를 두면 막으려던 사고가 플래그
한 글자 뒤로 옮겨갈 뿐이다.

**예외는 하나**, `snapshot_cycle_pilot --reseal` 이다. 이것은 성격이 다르다 — 자료를 지우지
않고 **기록만** 갱신한다. 그래서 우회가 아니라 절차로 두고, 지시한 대로

1. 현재 `snapshot_digest` 와 기록된 구성원 전체를 화면에 찍고,
2. 사람이 **디렉터리 이름을 그대로 입력**해야 통과하며,
3. 비대화식(파이프·CI·백그라운드)이면 **무조건 거부**한다.

3번을 넣은 이유: 확인을 받을 수 없는 자리에서 통과시키면 그 플래그는 확인 절차가 아니라
그냥 스위치다.

## 2. 과제 2 — `--out` 기본값: 필수 인자로 했다

지시가 "타임스탬프 기본값" 과 "필수 인자" 중 어느 쪽이 저장소 관례에 맞는지 판단해 근거와
함께 보고하라고 했다. **필수 인자**다. 근거 셋.

**(1) 저장소의 판본 이름은 전부 손으로 고른 것이다.** `manifest_v0` · `manifest_v1` ·
`pairs_pilot_v1` · `pairs_pilot_v2` · `cycle_pilot` · `cycle_pilot_v2` — 타임스탬프가 하나도
없다. 타임스탬프 기본값은 이 관례를 깬다.

**(2) 규약 1-6 이 "해시는 논문에 싣는다"고 했다.** 논문이 가리킬 경로는 **부를 수 있는 이름**
이어야 한다. `cycle_pilot_20260908T1934/` 는 부를 수 없다.

**(3) 타임스탬프 기본값은 사고를 막지 못하고 다른 사고를 만든다.** 무인자 실행이 매번 새
디렉터리를 만들면 GPU 몇 시간짜리 산출물이 아무도 안 보는 자리에 조용히 쌓인다. 봉인본은
지켜지지만 "내 산출물이 어디 갔나"가 새 문제가 된다.

**필수 인자는 "생각하지 않음"이 잘못된 대상을 겨눌 수 없는 유일한 선택지다.** 실측:

```
$ uv run python -m corpus.generate.run_cycle_corpus
usage: run_cycle_corpus.py [-h] ... --out OUT
run_cycle_corpus.py: error: the following arguments are required: --out
```

넷 다 같다 (`--out` 셋, `snapshot_cycle_pilot` 은 `--dir`).

옛 기본값 경로는 지우지 않고 `LEGACY_OUT_DIRS` 상수로 남겼다. 장식이 아니라 **회귀 시험이
그것을 읽는다** — 한때 기본값이었던 경로가 지금 실행되면 반드시 막혀야 한다는 시험이다.

## 3. 과제 3 — 시험 (32건, 전부 통과)

`tests/corpus/test_frozen_out.py`. 지시의 "통과가 공허하지 않도록 가드를 빼면 실패하는지
확인하라"를 **시험 자체에 넣었다.** 진입점마다 짝으로 건다.

| 짝 | 막는가 | 그게 가드 때문인가 |
|---|---|---|
| 사이클 | `FrozenDirectoryError` + **디렉터리에 아무것도 안 생김** | `assert_not_frozen` 을 무력화하면 `build_clause_records` 까지 도달 |
| 페어 | 같음 | 무력화하면 `load_snapshot` 까지 도달 |
| 스냅샷 | 종료코드 **4** | `is_frozen` 을 무력화하면 4 가 아니라 2(대상 없음)로 떨어짐 |
| 대조기 | `FrozenDirectoryError` | `--out` 을 딴 데로 주면 본체까지 도달 |

무력화 쪽은 가드 **바로 뒤** 호출을 감시 예외로 갈아 끼워 확인한다 — **GPU 를 쓰지 않는다.**

그 밖에 건 것:

- `test_페어_가드는_이름이_아니라_계약을_본다` — v1·v2 어느 이름도 아닌 디렉터리를 계약만
  붙여 놓고 막히는지. **옛 가드가 놓쳤던 바로 그 구멍**이다.
- `test_옛_기본값_경로는_지금이라면_전부_거부된다` — 보고된 결함 자체에 대한 회귀 시험.
- `test_reseal_은_비대화식에서_거부한다` — 무엇을 지우는지 화면에 찍었는지까지 확인.
- `test_확인은_이름을_정확히_입력해야_통과한다` — 거부만 걸면 **통과할 수 없는 확인**을
  못 잡는다. 사람이 절차를 밟았는데도 막히면 다음 사람은 절차 대신 가드를 지운다.
- `test_corpus_는_계약_이름을_다시_박지_않는다` — 소스에 `"SNAPSHOT.sha256"` 리터럴이 다시
  나타나면 실패한다. (**이 시험이 실제로 물었다** — §5)
- `test_봉인_대상을_쓰는_진입점이_전부_가드를_부른다` — AST 배선 시험(80번 G1-2). 새 진입점이
  늘 때 가드를 빼먹는 것을 막는다.
- 실물 봉인본 넷이 아직 잠겨 있고, 계약 목록과 실물 파일이 어긋나지 않았는지.

### 실물 확인 (봉인본은 건드리지 않았다)

봉인 디렉터리를 **임시 경로에 복사**해 실제 CLI 를 네 번 돌렸다. 원본은 읽기만 했다.

```
before: 5255ad84c8f1da3ce5820a5d4c812f7f3b80f5b1d90ce52b93761703d97bcd9d
        (사본 전체 파일 해시의 해시)
  run_cycle_corpus   --out <사본>  → FrozenDirectoryError
  make_pairs_pilot   --out <사본>  → FrozenDirectoryError
  snapshot_cycle_pilot --dir <사본> → exit 4 (--check / --reseal 안내)
  compare_judges     --dir <사본>  → FrozenDirectoryError
after : 5255ad84c8f1da3ce5820a5d4c812f7f3b80f5b1d90ce52b93761703d97bcd9d   ← 동일
```

거부 메시지 실물 (`run_cycle_corpus`):

```
--out 대상(…/cycle_pilot)는 봉인된 스냅샷이다 — SNAPSHOT.sha256 가 있다.
  봉인 구성원 8개 / snapshot_digest fb316682843cde37906f143e669397338458512581572b55195c928e11277400

  재생성이 필요하면 --out 에 **새 경로**를 줘라 (관례: `..._v3` 처럼 판본 접미).

## 4. 과제 4 — 다른 생성기 훑기

`corpus/` 안에서 `def main` 을 가진 진입점 전부를, 계약 파일이 있는 디렉터리 목록과 교차했다.

**같은 결함이 있어 함께 고친 것 — 3개** (§0 표의 2·3·4).

특히 4번은 성질이 나쁘다. `compare_judges` 는 **인자가 하나도 없었고**, `judge_agreement.json`
을 `cycle_pilot/` 안에 썼다. 그 파일은 v1 SNAPSHOT 의 구성원이다. 한 번 돌리면 봉인이 조용히
깨지고, 다음 `--check` 가 그제서야 알려 준다.

2번은 다른 의미로 나쁘다. **가드가 있었는데 물지 못했다.** `out_dir.resolve() == FROZEN_V1`
이라 이름을 하나 열거한 셈이고, 그 뒤 v2 가 봉인되면서 **기본값이 곧 봉인본**이 됐다. 이름을
열거하는 가드는 자산이 느는 속도를 못 따라간다 — 지금은 넷 다 계약으로 판정한다.

**봉인 디렉터리에 쓰지 않아 손대지 않은 것 — 5개.**

| 진입점 | 쓰기 대상 | 계약 파일 |
|---|---|---|
| `corpus/generate/run_pilot.py` | `corpus/validate/validation_report_pilot.json` | 없음 |
| `corpus/rules/materialize_derived.py` | `corpus/derived/` | 없음. `--check` + 바이트 비교로 이미 멱등 |
| `corpus/parse/extract_candidates.py` | `corpus/parse/extracted*` | 없음 |
| `corpus/parse/survey_docling.py` · `survey_textscan.py` | `corpus/parse/survey/<doc_id>/` | 없음 |
| `corpus/validate/judge_labels.py` | `corpus/validate/judge_labels/` | 없음. 봉인본은 **읽기만** |
| `corpus/validate/compare_pair_generators.py` | (쓰지 않음) | — |

> **주의로 남길 것:** `corpus/derived/` 는 지금 계약이 없어서 가드 대상이 아니다. D5(규정 색인)가
> 여기서 파생되므로, 총괄이 이 디렉터리를 봉인하기로 하면 `materialize_derived` 에도 같은
> 가드를 걸어야 한다. 지금 걸면 규약 1-7(CSV 가 단일 소스, 파생은 재파생 가능)과 충돌한다.

### 부수 발견 — 봉인 무결성 확인 결과

넷 다 **구성원 해시 일치 · 결합 다이제스트 재계산 일치**다 (읽기만 해서 확인).

| 디렉터리 | 구성원 | 일치 | digest 재계산 | 비고 |
|---|---|---|---|---|
| `corpus/generate/cycle_pilot` | 8 | ○ | ○ | |
| `corpus/generate/cycle_pilot_v2` | 6 | ○ | ○ | |
| `data/processed/pairs_pilot_v1` | 3 | ○ | ○ | **계약 파일이 CRLF** |
| `data/processed/pairs_pilot_v2` | 4 | ○ | ○ | |

`pairs_pilot_v1/SNAPSHOT.sha256` 만 줄바꿈이 CRLF 다. 08-31 에 `newline=""` 수정 전 코드로
쓰였기 때문이고, **내용은 온전하다** — 세 구성원의 sha256 을 직접 계산해 기록과 대조했다.
다만 표준 `sha256sum -c` 가 파일명 끝의 `\r` 때문에 이 파일을 검증하지 못한다.

**고치지 않았다.** 지시가 "봉인 자산은 읽기만" 이었고, 계약 파일 자체를 다시 쓰는 것은
`--reseal` 이 관장하는 행위다. `data/processed/` 는 git 미추적이라 저장소에는 영향이 없다.
**총괄 판정 필요** — 지금 상태로 두거나(내용은 온전), `--reseal` 로 LF 정규화하거나.

## 5. 시험이 실제로 문 것 둘

붙이자마자 두 건이 걸렸다. 둘 다 진짜 결함이었다.

**(1)** `snapshot_summary` 가 계약 파일을 읽을 때 `except OSError` 만 잡았다. utf-8 이 아닌
파일은 `UnicodeDecodeError`(= `ValueError`)라 **가드가 예외로 죽었다.** 가드가 죽으면 호출자는
가드를 빼 버린다. `(OSError, ValueError)` 로 넓혔다.

**(2)** `make_pairs_pilot` 이 봉인을 쓸 때 `"SNAPSHOT.sha256"` 을 **다시 박고 있었다.** 계약
이름이 두 벌이면 한쪽만 바뀐다 — P6 이 지적한 그 패턴이다. `CONTRACT_NAME` 으로 돌렸고,

# 부록 A. 게이트 실패 수리 + 봉인 실물 보관처 제안 (09-08 총괄 반려분)

총괄 진단이 맞다 — **내 결함이 아니라 트리 차이**다. 그리고 파고 보니 노출은 보고된
400KB 보다 크다.

## A-1. 왜 만든 자리에서만 통과했나

계약 구성원 일부가 `.gitignore` 로 추적 밖이다.

```
.gitignore:91  # --- 파일럿 합성 산출물 (드라이브·로컬 보관, 저장소는 스크립트·보고서만) ---
.gitignore:92  corpus/generate/cycle_pilot/*.jsonl
.gitignore:93  corpus/generate/cycle_pilot/_raw_generated.json
```

그래서 `corpus/generate/cycle_pilot/` 은 **본체·타 워크트리 6곳에 7개, `wt_B` 에만 12개**다.
계약서는 8개를 적고 있고 그중 5개가 추적 밖이라, main 에서 "계약에 있는데 실물이 없다"가
정확히 걸렸다. 내가 쓴 시험이 **단순 존재 검사**였던 것이 잘못이다 — 만든 자리에서만
통과하는 시험은 통과가 아무것도 보장하지 않는다.

## A-2. 조치 (1) — 트리에 의존하지 않는 대조

가르는 기준을 **"git 이 그 이름을 추적하는가"** 로 바꿨다. 판정을 시험 안이 아니라
`corpus/generate/frozen_out.verify_contract()` 로 올려서, 게이트가 어느 트리에서든
같은 판정을 직접 돌릴 수 있게 했다.

| 판정 | 뜻 | 시험 동작 |
|---|---|---|
| `ok` | 구성원이 전부 이 트리에 있다 | **엄격히 검사** (지금까지와 동일) |
| `incomplete_tree` | 없는 것이 전부 **추적 밖** | 경고 + skip, **이름을 남긴다** |
| `broken` | **추적분**이 없다 | **실패** — 봉인본 훼손 |
| `unverifiable` | git 을 못 물어 판단 불가 | 통과로 떨어뜨리지 않는다 |

조용한 통과를 막는 장치를 셋 뒀다. ① `pytest.skip` 이라 진행 표시가 `.` 이 아니라 `s` 다.
② `IncompleteTreeWarning` 이 **기본 출력의 경고 요약에** 못 본 파일 이름을 전부 찍는다
(`-rs` 없이도 보인다). ③ `uv run python -m corpus.generate.frozen_out` 이 모든 봉인처를
훑어 표로 낸다 — 깨진 것이 있을 때만 종료코드 1.

main 트리 조건을 그대로 재현해(추적분 7개만 복사) 확인했다.

```
. s                                                        [100%]
IncompleteTreeWarning: 계약 구성원 8개 중 5개를 이 트리에서 대조하지 못했다
  (incomplete_tree) — ['_phi_discarded.jsonl', '_phi_reasoning.jsonl',
   'discarded.jsonl', 'qa_accepted.jsonl', 'reasoning_accepted.jsonl']
1 skipped, 1 warning
```

**이빨 시험도 같이 걸었다** — 추적분 하나를 지우면 같은 함수가 `broken` 을 낸다. 트리 차이와
훼손을 안 가르면 한쪽은 매번 깨지고 다른 한쪽은 영영 안 걸린다. 시험 37건 · corpus 496건 통과.

부수로 `tracked_names` 의 잠재 결함 하나를 잡았다. `subprocess.run(text=True)` 가 로캘
(win32 cp949)로 읽는데 git 오류 문구는 한국어 UTF-8 이라, 읽기 스레드가 `UnicodeDecodeError`
로 죽었다. `encoding="utf-8"` 을 명시했다.

## A-3. 조치 (2) — 봉인 실물이 어디에 있나 (실측)

## A-4. 제안 (판정은 총괄)

**자산 등급을 갈라야 한다 — 둘을 같이 다루면 한쪽은 레드라인을 밟고 다른 쪽은 근거 없이
사라진다.** 실측하니 `cycle_pilot*` 의 미추적 10개(1.32 MB)에는 AI허브 데이터가 없다.
레코드 키가 `sample_id·skeleton·text·judge_*·passage_id` 이고, 골격은 허용치 CSV(KR-RULES-P2·
IACS Rec.47 — 규약 2-5 의 무료 공개 허용 목록)에서, 생성문은 로컬 Qwen 추론에서 나온다.
QA 축조차 구절 **원문이 아니라 `passage_id` 참조**를 싣는다(확인함). 즉 이 1.32 MB 는
국외 반출 금지(레드라인 1)에도 유료 표준 전재 금지(규약 2-5)에도 걸리지 않으므로,
**git 추적 전환이 가장 싸고 가장 튼튼하다** — 1.32 MB 는 저장소에 부담이 아니고, origin
복제가 곧 오프사이트 백업이 되며, 무엇보다 **모든 트리에서 봉인이 실제로 검증 가능해져
A-2 의 skip 자체가 불필요해진다**(지금 방식은 "못 봤다"를 정직하게 적을 뿐 검증을
복원하지는 않는다). 다만 `origin` 이 **공개 GitHub 저장소**(`Chohyungun/weld-vlm-federated`)
이므로 추적 전환 전 1회 공개 적합성 검수 — 생성문에 규정 문구가 길게 인용된 레코드가
없는지 — 를 붙여야 하고, 이것은 `numeric_lock` 의 유료 표준 스크린(`PAID_STD`)을 전수
적용하면 자동으로 된다. 반대로 `pairs_pilot_v1|v2` 의 7개(4.29 MB)는 **git 으로 보내면
안 된다.** 레코드가 `image_id: "aihub71761:13121"` · `image_path` · 폴리곤 유래 `bbox_px`
를 담은 AI허브 71761 파생물이고, 공개 GitHub 은 해외 호스팅이라 레드라인 1(국외 반출 금지)
과 정면으로 충돌한다 — 파생 좌표라도 예외가 아니다(규약 2-1 이 "원본이나 파생 이미지"라고
적었고, 라벨 좌표는 그 데이터셋의 핵심 산출이다). 이쪽은 **국내 공유 드라이브 백업**이
유일하게 남는 선택지이고, 정션이라 물리 사본이 하나뿐이므로 최소 2사본(본체 + 공유
드라이브)을 만들고 `SNAPSHOT.sha256` 으로 적재 후 대조까지 마쳐야 한다. 어느 쪽으로
가든 계약서가 **구성원별로 "추적분인지 드라이브 보관분인지"를 스스로 밝히게** 하는 것이
남는 과제다. 지금은 `verify_contract` 가 git 에 물어서 알아내는데, 드라이브 보관분은
git 이 모르므로 "이 트리에 없다"와 "어디에도 없다"를 여전히 구분하지 못한다.

> **정리 — 총괄 판정 요청 3건**
> 1. `cycle_pilot`·`cycle_pilot_v2` 미추적 10개(1.32 MB) **git 추적 전환**? (공개 적합성 검수 선행)
> 2. `pairs_pilot_v1|v2` 7개(4.29 MB) **국내 공유 드라이브 2사본**? (git 은 레드라인 1 로 배제)
> 3. 계약서에 구성원별 보관 등급(`tracked` / `drive`) 필드를 넣을지 — 넣으면 봉인 형식 변경이라

                              부위, 결함이 발생하기 쉬운 부위, 작업조건이 나쁜 부위 및 …
```

길이 분포는 40–59자 418건 · 60–99자 54건 · 100–199자 6건 · **200자 이상 0건**. 문단이나
표를 통째로 옮긴 것은 없고, 최악이 한 문장이다.

### 정제해서 일부만 올리는 선택지는 없다

"걸린 레코드만 빼고 추적" 은 안 된다. 그 파일들은 **봉인 구성원**이라 한 바이트만 바꿔도
`SNAPSHOT.sha256` 이 어긋나고, 그러면 논문에 실을 digest 가 가리키는 실물이 사라진다
(규약 1-6). 봉인과 정제는 양립하지 않는다.

### 그래서 남는 길

`cycle_pilot*` 의 10개(1.32 MB)도 **`pairs_pilot` 과 같이 드라이브 보관**으로 가는 것이
일관된다. 근거 보존은 이미 부분적으로 돼 있다 — `EVIDENCE.jsonl`(추적 중)이 생성문 전문
없이 항목별 판정 플래그와 sha256 만 담으므로, 통과율은 원본 없이도 재계산되고 나중에
원본이 나오면 한 건씩 대조된다. 다만 이 경로를 택하면 A-2 에서 넣은 `incomplete_tree`
skip 이 **영구 상태**가 된다. 그것을 닫는 것이 ③(보관 등급 필드)이다.

> **판정 요청:** cycle_pilot·cycle_pilot_v2 미추적 10개를 ② 와 같은 드라이브 보관으로
> 편입할지. 편입하면 `verify_backup --dirs` 에 두 경로를 더하면 되고 도구 변경은 없다.

## B-2. ② 드라이브 백업 — 목록·절차·검증 스크립트 준비 완료 (실행은 사용자)

`corpus/validate/verify_backup.py` 신설. **복사하지 않는다** — 목적지가 국내인지 판단하는
것은 사람이고, 스크립트가 대신 정하면 레드라인 판단이 코드 안으로 숨는다.

계약 구성원 7개에 **계약서 2개를 더했다.** 계약서를 빼면 사본만으로는 무엇이 있어야
하는지 알 수 없다 — 원본 디스크가 죽는 상황이 바로 이 백업을 쓰는 상황이므로 사본이
자립해야 한다.

### 절차 (사용자 실행)

```bash
# 1) 목록·매니페스트 산출 (봉인 디렉터리에는 아무것도 쓰지 않는다)
uv run python -m corpus.validate.verify_backup plan --out backup_manifest.json

# 2) 사람이 복사한다 — 국내 공유 드라이브로.
#    디렉터리 이름을 그대로 유지해야 대조가 된다 (pairs_pilot_v1/ · pairs_pilot_v2/).
#    원본 경로: E:\Fedvlm_for_welding\data\processed\  (정션 대상 = 실물)

# 3) 적재 후 대조
uv run python -m corpus.validate.verify_backup verify --dest "<드라이브 경로>"
```

3단계는 **두 겹으로 본다** — 원본↔사본, 그리고 계약서↔사본. 원본↔사본만 보면 원본이 이미
틀어져 있어도 같이 틀어진 채 통과하기 때문이다. 종료코드 0 이면 적재 완료, 1 이면 다시
복사한다. 예행 연습으로 사본을 만들어 9/9 일치를 확인했고, 한 파일을 1바이트 변조하고
다른 파일을 지웠더니 `mismatch` · `missing` 으로 각각 잡히고 종료코드 1 이 났다.

> **드라이브는 공유 드라이브다** — 개인 드라이브에 적재하지 않는다. 이동은 복사 → 대조 →
> 확인 순서이고, 원본 삭제는 하지 않는다(2사본이 목적이다).

## B-3. 시험

새 시험 15건 (`tests/corpus/test_release_and_backup.py`). 둘 다 **통과가 곧 승인**이 되는
도구라, "잡는가" 만이 아니라 "안 잡으면 어떻게 되는가" 를 같이 걸었다.

- 검수기: 사유 넷을 각각 잡는지 · 한계 미만 겹침은 안 잡는지(안 그러면 흔한 표현마다 걸려
  검수가 무의미해진다) · **원천 문서가 없으면 통과로 적지 않는지** · 적발이 종료코드에
  반영되는지(그리고 깨끗하면 0 이 나오는지 — 늘 1이면 그것도 게이트가 아니다).
- 대조기: 목록이 계약서 자신을 담는지 · 손상과 누락을 **둘 다** 잡는지 ·
  **원본이 계약과 어긋나면 사본이 원본과 같아도 막는지.**

시험을 붙이자마자 검수기의 결함 둘을 잡았다. 기본 인자에 `SOURCE_DOCS`·`TARGET_DIRS` 를
박아 import 시점에 묶여서 대상을 바꿀 수 없었고(그래서 검수기를 검수하는 시험이 실제
봉인본을 건드릴 뻔했다), 저장소 밖 경로에 `relative_to` 를 걸어 검수 자체가 죽었다.
