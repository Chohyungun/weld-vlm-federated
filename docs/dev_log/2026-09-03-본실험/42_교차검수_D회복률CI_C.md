## 1. `evaluation/recovery_ci.py` — 매칭 캐시 + 중복도 집계

### 1-1. pycocotools `accumulate` 와 같은가 — 코드 대조

pycocotools 2.x `accumulate` 를 한 줄씩 맞대 보았다. 모두 같다.
- 이미지 순서로 검출을 잇고 `-score` 안정 정렬(mergesort)을 한다.
- `npig == 0` 이면 그 카테고리를 건너뛴다(-1). 검출이 0 이면 정밀도 행이 0 이다.
- 우측 포락선은 `pr[i-1] = max(pr[i-1], pr[i])` 와 같다.
- 101점 보간은 `searchsorted(left)` 로 하고, 인덱스를 넘는 칸은 pycocotools 의 `except: pass` 와 같게 0 이다.
- `(T, R, K)` 격자를 C 순서로 펴서 한 번에 평균한다(`_summarize` 와 같은 순서). 그래서 항등 검사의 허용 오차 0 이 성립한다.

**가장 위험한 가정은 캐시의 이미지 순서다.** `EvalCache.image_ids = sorted(gold)` 인데 `evalImgs` 의 i 번째가 그 이미지여야 한다. `build_cocoeval` 이 `sorted(gold)` 순서로 정수 id 1..N 을 매기고 pycocotools 가 `np.unique(imgIds)` 로 정렬하므로 일치한다. 무시 플래그(`dtIgnore`)는 이 구축에서 생기지 않는다(`iscrowd=0`, 면적 범위 `[0, 1e10]`).

## 4. `24a1224` — CI 입력 결속과 규칙 재판정

### 4-1. 설계 대조

외부 지적(codex_reply §18)과 총괄 요구 1~6 을 코드에 대조했다.
- **결속**: 판 번호·산출물 이름·시드 목록·시드별 {원시 sha256, 시드값, 지문 combined·rule·newline_normalized}, CI 실행 지문 = 채점 지문, `stable=true`.
- **재판정**: 기록된 `ci_pass` 를 쓰지 않는다. 재표집 수·난수 시드 등록값, 구간 유한성, 반폭 자기모순, 미정의 수 ≤ 재표집 수를 본 뒤 prereg 상수로 판정한다.

생성기와 집계기가 같은 함수(`read_artifact`·`make_binding`)를 쓰고, 해시와 파싱이 같은 바이트에서 나온다. 설계는 지적을 정확히 겨냥한다.

## 6. 발견

### Important

- **I-1. 재판정이 신뢰수준·구간 방식을 등록값과 대조하지 않는다.** `rejudge_ci_rules` 는 "등록 외 재표집 조건" 으로 재표집 수와 난수 시드를 본다. 그런데 같은 등급의 등록 조건인 `statistic.alpha`(0.05)와 `interval`(백분위)은 보지 않는다. 90 % 구간은 95 % 구간보다 좁아 규칙 ② 를 쉽게 통과한다. 실물 v2 에 `alpha 0.10` 만 적은 CI 가 `recovery_reportable=true` 가 됐다(§4-2 F).
  - 지문 일치는 "채점과 같은 코드로 CI 를 냈다" 까지만 보증한다. 생성기의 `ALPHA` 를 바꾼 트리로 다시 채점하면 지문도 맞는다.
  - **처방**: `alpha == 0.05`·`interval == "백분위"`(또는 등록 상수)를 확인하고 다르면 null, 시험 1건. 가능하면 `ALPHA` 를 prereg/stats 상수로 올려 생성기와 재판정이 같은 값을 읽게 한다.
- **I-2. v3 산출이 보존 대상 v1·v2 파일을 덮는다.** 두 경로다.
  1. `aggregate_seeds.py` 는 `suffix = "v2" if "v2" in args.artifact else "v1"` 로 출력 이름을 정한다. `--artifact score_cells_v3.json` 이면 **`aggregate_v1.json`** 에 쓴다. v2 파일을 `score_cells_v3.json` 이름으로 복사해 스크래치에서 실증했다. 기본 `--dest` 는 공유 `outputs/main_d/seed3set` 이다.
  2. `recovery_bootstrap.py` 는 출력 이름이 **`recovery_ci_v1.json` 고정**이다. v3 CI 를 내면 v2 로 낸 기존 CI 를 덮는다.

  37번 §8-6 이 "v1·v2 파일은 삭제하지 않는다 … 진단 이력으로 보존" 이라고 약속했고, 다음 단계가 바로 v3 산출이다.
  - `score_cells.py` 의 `ARTIFACT_VERSIONS` 에도 v3 가 없어 어차피 코드 수정이 필요하다.
  - **처방**: 산출물 판을 파일명에서 정규식(`_v(\d+)\.json$`)으로 뽑아 `aggregate_v{n}`·`recovery_ci_v{n}` 에 쓰고, 대상 파일이 있으면 덮지 않고 멈춘다. 시험 1건씩을 붙인다.
