# 50. 공개 검수기 픽스처의 로컬 경로 교체 — 트랙 B (2026-09-16)

지시: `dispatch_B_픽스처경로_20260916.md` (총괄 21:15; 보고 번호는 총괄 정정으로 50번).
F 46번 §4 가 올린 ④ 후보 — `tests/corpus/test_release_and_backup.py` 의 `test_로컬_절대경로를_잡는다` 입력이

## 1. 교체

입력을 **존재하지 않는 가짜 경로**로 바꿨다 — `Q:` 드라이브(이 컴퓨터의 드라이브는 C·E·G 뿐이다) +
`Users\example_user\sample_project\corpus`. 드라이브도 폴더 이름도 이 저장소·사용자와 무관하다.
시험의 뜻(검수기가 로컬 절대경로를 `local_path` 로 잡는다)은 그대로이고, 왜 가짜인지를 독스트링에 적었다.

**`Users` 갈래로 시험하는 이유 — 규칙이 폴더 이름 목록에 기대고 있다(보고).**
`screen_public_release.LOCAL_PATH` 는

```
[A-Za-z]:[\\/](?:Users|Fedvlm|Program Files)|/(?:home|Users)/[A-Za-z]
```

이다. Windows 쪽은 드라이브 다음 **첫 폴더가 `Users`·`Program Files`·이 저장소 이름의 접두**일 때만 잡는다.
옛 픽스처는 그중 **저장소 이름 갈래**를 탔다 — 즉 시험이 이 저장소 이름에 기대고 있었다. 가짜 경로로는
그 갈래를 시험할 수 없으므로(저장소 이름을 쓰면 다시 실제 형태가 된다) 어느 저장소에나 있는 `Users` 갈래로 옮겼다.

가짜 입력으로 규칙을 찔러 본 결과(시험 아님, 직접 호출):

| 입력 형태 (전부 가짜) | `local_path` |
|---|---|
| `Q:` + `\Users\example_user\…` (픽스처) | 잡음 |
| `Q:` + `/Users/…` · `Q:` + `\Program Files\…` · `/home/example_user/…` | 잡음 |
| 드라이브 없이 `\Users\example_user\…` | **놓침** (이빨 변이의 근거 — §3) |
| `Q:` + `\sample_project\…` (첫 폴더가 목록 밖) | **놓침** |
| `Q:` + `\공유 드라이브\…` · `Q:` + `\내 드라이브\…` | **놓침** |
| `Q:` + `\\Users\\…` (**JSON 이스케이프**, 역슬래시 2개) | **놓침** |

**규칙 자체는 넓히지 않았다(지시 — 별건, 보고만).** 다만 마지막 줄은 검수기의 실제 용도에 걸린다.
(**§6-1 에서 정정** — 검수기는 JSON 을 먼저 풀어서 보므로 아래 문단은 과장이었다.) 검수 대상
(`TARGET_DIRS` = `cycle_pilot`·`cycle_pilot_v2` 의 미추적 구성원)은 JSON/JSONL 이고, JSON 은 Windows 경로의
역슬래시를 두 개로 적는다. 그 안의 경로는 이 규칙에 **안 잡힌다** — 09-13 위생 정규식이 이스케이프된 경로를
놓친 것(30번 부록 G)과 같은 모양이다. 공유 드라이브·내 드라이브 형태도 총괄·F 의 위생 grep 패턴은 잡지만 이
규칙은 못 잡는다. 넓힌다면 `[\\/]{1,2}` 와 그 두 폴더 이름을 더하고, 저장소 이름 갈래는 빼는 것을 제안한다.

**위생 grep 과의 관계.** 가짜 경로도 `Users` 로 시작하므로 총괄·F 의 위생 패턴
(`[A-Za-z]:[\\/]{1,2}(Users|…)`)에는 이 줄이 **계속 걸린다.** 검수기가 잡는 형태여야 시험이 서므로 피할 수 없다.
다음 정리 목록에서는 "가짜 경로 픽스처(`Q:`·`example_user`)" 로 분류하면 된다.

## 6. 추기 (21:24 총괄) — 검수기 경로 규칙을 넓힌다

별도 커밋이다. 교차 검수는 F 가 `9f5cc8b` 와 함께 본다.

### 6-1. 먼저 정정 — §1 의 "JSON 이라 놓친다" 는 과장이었다

`screen()` 은 파일을 `json.loads` 로 **먼저 풀고** 문자열 값에 규칙을 건다(`iter_texts` → `_walk`). 그래서
JSON 파일에 흔히 있는 이스케이프(`\\`)는 검사 전에 역슬래시 하나로 돌아오고, 옛 규칙도 그 형태는 봤다.
옛 규칙이 실제로 놓치는 이스케이프는 **문자열 안에 JSON 이 한 번 더 들어 있는 경우**(모델 원출력을 문자열로
저장한 것 등)뿐이다. 결함은 맞지만 "검수 대상 전체가 빠진다" 는 수준이 아니었다. 아래 실물 대조가 그것을
수치로 보인다 — 옛 규칙도 새 규칙도 실물에서는 0건이다.

### 6-2. 새 규칙

```
① (?<![A-Za-z0-9])[A-Za-z]:[\\/]{1,2}[^\s\\/:*?"<>|][^\s:*?"<>|]*
② (?<![\\\w])\\\\(?:\\\\)?[\w.$-]{2,}\\{1,2}[\w$][^\s\\/:*?"<>|]*
③ /(?:home|Users)/[A-Za-z]
```

| 갈래 | 무엇 | 설계 |
|---|---|---|
| ① 드라이브 | 문자 + `:` + 구분자 1~2개 + 폴더 이름 첫 글자 | **첫 폴더 이름과 무관.** 저장소 이름 갈래는 뺐다. 드라이브 문자 앞이 영문자·숫자면 잡지 않는다 — `https://` 의 `s:`, YAML 문자열의 `documents:` 뒤 `\n`. 시각·규격 표기는 콜론 앞이 숫자라 애초에 안 걸린다. 증거로 경로를 공백 앞까지 담는다 |
| ② UNC | `\\호스트\공유` | **잡기로 판단했다.** SMB 공유는 사내 NAS 경로로 흔한 형태이고, 드라이브 문자가 없어 ①로는 못 잡는다. 앞이 역슬래시·단어 문자가 아닌 곳에서 역슬래시 2개(한 겹 더 이스케이프된 4개 포함), 호스트는 **두 글자 이상의 `[\w.$-]`** — 이스케이프된 정규식 조각(`\\d+\\s*`)은 호스트 자리에 기호가 와서 안 걸린다 |
| ③ POSIX | `/home/…`·`/Users/…` | 지시대로 **그대로.** 다만 앞 글자 가드가 없어 URL 경로에 `/home/`·`/Users/` 가 들어 있으면 잡힌다(남은 오탐 후보, §6-6) |

가짜 입력 22건(양성 11 · 음성 11)을 직접 호출로 찔러 어긋남 0 을 확인한 뒤 시험으로 옮겼다.

### 6-3. 시험 (+10)

| 시험 | 입력(전부 가짜) |
|---|---|
| `test_폴더_이름_목록과_무관하게_로컬_경로를_잡는다` ×4 | 이스케이프가 한 겹 남은 드라이브 경로 · 목록 밖 첫 폴더 · 공유 드라이브 이름 · UNC |
| `test_경로가_아닌_콜론_표기는_잡지_않는다` ×5 | URL · 시각(`12:30`·ISO 시각) · 규격 표기(`5817:2014`) · YAML 줄바꿈 이스케이프 · 이스케이프된 정규식 조각 |
| `test_경로_규칙은_폴더_이름_목록을_들고_있지_않다` | 규칙 문자열에 `Program Files`·저장소 이름이 없다 |

음성 시험은 `local_path` 만 본다 — 규격 표기 입력은 유료 표준 사유로 따로 걸리는 것이 맞다.

**이빨 (스크래치 사본, 기준 → 변이 → 원복).**

| 변이 | 무너지는 시험 |
|---|---|
| 옛 규칙으로 되돌림 | 양성 4건 전부 + 목록 시험 |
| 드라이브 앞 영숫자 가드 제거 | 음성 2건(URL · YAML 줄바꿈) |
| UNC 호스트 글자 제한을 `[^\s\\/]+` 로 넓힘 | 음성 1건(정규식 조각) |

세 변이 모두 원복하면 통과한다.
