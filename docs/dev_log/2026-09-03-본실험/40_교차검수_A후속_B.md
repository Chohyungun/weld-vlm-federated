## 1. 과제 1 — 봉인 바이트 재커밋 (`4c83520`)

### 1-1. blob ↔ 계약

`corpus/generate/cycle_pilot/SNAPSHOT.sha256`(wt/A 판, main 과 **동일 blob**)의 값과 대조했다.

| 파일 | 계약 | `4c83520` blob | wt/A 팁 blob | CR | main blob |
|---|---|---|---|---|---|
| `_phi_report.json` | `fb1eef4a…` | 일치 | 일치 | 49 | `1609571d…` 불일치 |
| `cycle_corpus_report.json` | `381d4351…` | 일치 | 일치 | 50 | `8cacb1a9…` 불일치 |
| `judge_agreement.json` | `7e19ef0a…` | 일치 | 일치 | 33 | `7f7db7d0…` 불일치 |

`cycle_pilot_v2/cycle_corpus_report.json` 은 main 과 **동일 blob**(LF, 계약 `859501d5…` 와 원래 일치).
계약 파일 두 개(`SNAPSHOT.sha256`)는 손대지 않았다 — blob 동일, 속성도 `text=auto eol=lf` 그대로.

### 1-2. `.gitattributes`

추가는 정확히 네 줄 `-text`(cycle_pilot 3 + v2 report 1)이고 기존 규칙 뒤에 있어 `*.json text eol=lf`
를 이긴다. `git -C wt_A ls-files --eol`:

```
i/crlf  w/crlf  attr/-text   cycle_pilot/_phi_report.json
i/crlf  w/crlf  attr/-text   cycle_pilot/cycle_corpus_report.json
i/crlf  w/crlf  attr/-text   cycle_pilot/judge_agreement.json
i/lf    w/lf    attr/-text   cycle_pilot_v2/cycle_corpus_report.json
i/lf    w/lf    attr/text=auto eol=lf   …/SNAPSHOT.sha256 (둘 다)
```

`check-attr` 에 `eol: lf` 가 남아 보이지만 `text: unset` 이면 변환이 없다 — 아래 clone 이 그 증거다.
다른 추적 파일의 속성은 바뀌지 않았다(diff 가 네 줄 추가뿐).

### 1-3. 새 clone — 이 변경의 존재 이유

`git -c core.autocrlf=<X> clone --branch wt/A <본체 저장소> <임시>` 를 `true`·`false` 로 각각 떴다.

| autocrlf | cycle_pilot 3파일 | v2 report | clone `git status` |
|---|---|---|---|
| true | **3/3 일치** (CR 49·50·33) | 일치 | 0줄 |
| false | **3/3 일치** | 일치 | 0줄 |

30번 부록 E-1 에서 "새 clone 은 3/3 불일치" 였던 것이 닫혔다. A 가 32번 §8-3 에 적은 "4/4" 와 같다.

### 1-4. 짚을 것 (Minor)

이것은 30번 부록 E-2 의 **C 안**(blob 을 CRLF 로 다시 커밋)이다. B 는 A 안(`text eol=crlf`, blob 불변)을
권했고 총괄이 C 를 택했다. C 의 대가는 E-2 에 적은 그대로 — `4c83520` 이전 커밋을 체크아웃하면 세 파일이
다시 LF 라 계약과 안 맞는다. 봉인 구성원 세 개의 blob 이 바뀐 커밋이 이력에 남고, 커밋 메시지가
그 사유("재봉인 아님, 원 바이트 저장")를 담고 있어 감사는 된다. 대신 `git show`·GitHub raw 가 계약
바이트 그대로를 보여 주므로 외부 대조에는 C 가 더 곧다. **판정을 바꿀 사유는 아니다.**
