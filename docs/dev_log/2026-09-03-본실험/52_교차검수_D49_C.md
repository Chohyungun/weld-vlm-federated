## 3. 점추정 독립 재계산 (과제 3)

42번 §0 과 같은 방식이다.
- v3 세 파일의 `threshold_independent.per_tag[*].map_50` 에서 로컬 평균을 합 ÷ 3 으로 낸다(`math.fsum` 변형도 함께).

v3 CI 구간은 재실행하지 않았다. 다만 세 사실이 이어진다.
1. v3 CI 의 입력 캐시가 내 독립 캐시와 같다.
2. v2↔v3 CI 구간이 비트 단위로 같다(§1).
3. v2 CI 구간은 42번 §9-4 의 독립 재실행과 비트 단위로 같다.

따라서 **v3 CI 구간도 독립 재실행 결과와 같다.** 42번 §9-3 에서 루프 이동 전후 20회 비트 일치를 확인했으므로 코드 쪽 차이도 없다.

## 6. 49번 §5 · §7-4 의견 (과제 6)

- **§5(하위 필드 오독 위험) — 동의한다. 다만 범위가 49번 기술보다 한 줄 넓다.**
  - `denominator_sd_df2` 의 `ci_pass: null`·`recovery_reportable: null`·`field_caveat`("지금은 null")에 더해, **`detail` 문장도** "→ 회복률 CI 미산출: 게재 가부 미판정(트립와이어만 통과)" 이라고 적는다.
  - 원인을 코드로 확인했다. 이 블록은 `recovery_denominator_verdict(…, recovery_ci=None)` 의 결과이고, `verdict` 로 가는 것은 `tripwire_pass` 하나뿐이다. v2 집계본에도 같은 블록이 있다(v2↔v3 차 없음).
  - v3 파일은 그대로 둔다. 인용은 최상위 `denominator_gate.recovery_reportable`·`verdict`·`recovery_ci` 로만 하라고 E·총괄 보고에 못박는다.
  - 코드는 D 후속 커밋에서 고친다. 재집계는 필요할 때만 하고, 새 dest 에 쓴다. 판 번호 규칙에는 "같은 입력 판 + 고친 집계기" 자리가 없으므로 폴더로 구분한다.
- **§7-4(`detect_infer.CHECKPOINTS` 연합 경로) — 지금은 조용한 오염 없이 크게 실패하는 상태다.**
  - 본실험 세 시드 트리에 파일럿 경로 `sep_fed/global_r003.npz` 가 없음을 확인했다(`predict` 는 "체크포인트 없음" 으로 멈춘다).
  - 본실험 `predict` 를 다시 쓰기 전에 D 가 표를 프로파일별로 가르거나, adapt 기록의 `export_meta.checkpoint`+sha256 을 입력으로 받게 하면 된다. 프로파일별 경로는 파일럿 R=3 → `sep_fed/global_r003.npz`, 본실험 R=50 → `fl/sep_fed/global_r050.npz` 다.
  - C 규약은 이 검수에서 확인했다. 본실험은 `seed<n>/{sep_central/sep_central.npz, sep_local/sep_local_c{0,1,2}.npz, fl/sep_fed/global_r050.npz}` 이고, 파일럿은 `sep_fed/` 아래에 둔다.
