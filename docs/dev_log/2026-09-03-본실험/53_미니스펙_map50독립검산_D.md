## 1. 범위 — 무엇을 새로 짜고 무엇을 공유하나

`map_50` 은 `score_cells.threshold_independent_block` → `evaluation.score.score_records` →
`evaluation.metrics.localization.coco_map`(pycocotools `COCOeval`)으로 나온다. 입력은 **하한 레코드**
(`seed<n>/sweep/<칸>_raw_s<seed>.jsonl`, export 하한 conf 0.01)뿐이다. 운용점 레코드 15개는 `map_50` 에 쓰이지 않는다.

| 단계 | 두 번째 구현 | 이유 |
|---|---|---|
| ① 이미지·카테고리별 검출 정렬과 100건 절단 | **새로 짠다** | pycocotools `evaluateImg`·`computeIoU` 몫 |
| ② IoU | **새로 짠다** | `maskUtils.iou`(C 구현) 몫 |
| ③ 매칭(점수 순 탐욕) | **새로 짠다** | `evaluateImg` 몫. 지금 어떤 재구현도 거치지 않은 부분이다 |
| ④ 누적·포락선·101점 보간·평균 | **새로 짠다** | `accumulate`·`_summarize` 몫. `recovery_ci` 의 재구현을 import 하지 않는다 |
| 레코드 파싱(`read_records`) · 정답 적재(`read_gold`, `annotations.csv`) · 클래스 목록 · xyxy→xywh 규약(`to_coco_xywh`) | **공유**한다 | 채점 **입력 규약**이지 평가 알고리즘이 아니다. 두 구현이 같은 입력을 받아야 차이가 알고리즘에서만 나온다 |

공유 입력은 따로 싸게 대조한다 — 틀리면 두 구현이 같이 틀리기 때문이다.

- 정답: `annotations.csv` 를 `csv` 모듈로 직접 읽어 평가셋 이미지의 클래스별 박스 수를 센 값(bbox 열이 빈 행 제외) = `read_gold` 결과.
- 레코드: jsonl 을 `json` 으로 직접 읽어 칸별 박스 수를 센 값 = v3 `n_boxes_floor`. 점수가 없는(None) 박스와
  클래스 목록 밖 박스의 수도 센다.

## 3. pycocotools 와 정의가 갈리는 지점

pycocotools 2.0.11 설치본의 동작이다. 매칭 규칙은 설치본 소스(`COCOeval.evaluateImg`·`Params.setDetParams`)를 직접 읽어 적었다.
**두 번째 구현은 전 항목을 pycocotools 쪽에 맞춘다.** 채점 값이 이 정의로 나왔으므로, 정의를 맞춰야 "다른 값" 이 결함인지 가릴 수 있다.

| # | 지점 | pycocotools 2.0.11 (지금 채점) | 흔한 다른 정의 | 맞출 쪽 · 비고 |
|---|---|---|---|---|
| 1 | 보간 | 재현율 격자 101점. 각 점 r 에서 **재현율 ≥ r 인 첫 순위**(`searchsorted(left)`)의 포락선 정밀도, 없으면 0. AP = 101개의 평균(계단) | VOC 전 구간 면적 · 11점 · 사다리꼴(ultralytics) | pycocotools |
| 2 | 격자 값 | `np.linspace(0, 1, 101)` — 부동소수 격자. 재현율이 정확히 k/npig 로 격자점과 같을 때 포함 여부가 이 값에 달린다 | 십진 정확값 | **같은 `linspace`** 를 쓴다 |
| 3 | 포락선 | 뒤에서부터 `pr[i-1] = max(pr[i-1], pr[i])` | 포락선 없음 | pycocotools |
| 4 | 정밀도 분모 | `tp / (tp + fp + np.spacing(1))` | ε 없음 | 같은 ε |
| 5 | 절단 | 이미지·**카테고리마다** 점수 내림차순 **상위 100건**만 IoU·매칭·누적에 쓴다(`maxDets[-1]`). export 는 이미지당 최대 300건이고 실측 절단이 일어난다(C 42번 §1-3: 칸마다 18~162 쌍) | 이미지당 전체 100 · 제한 없음 | 이미지·카테고리당 100 |
| 6 | 이미지 안 정렬·동점 | `-score` **안정 정렬**(mergesort) — 동점은 입력(레코드) 순서를 따른다 | 불안정 정렬 | 같은 규칙. 입력 순서는 `read_records` 가 준 순서 |
| 7 | 전체 누적 정렬·동점 | 이미지 순서로 이어 붙인 뒤 `-score` 안정 정렬. 동점은 (이미지 순서, 이미지 안 순서) | 점수만 | 같은 규칙. 동점 tp·fp 순서가 PR 곡선을 바꾼다(37번 §9 m-5 픽스처) |
| 8 | 이미지 순서 | 정답 id 를 **문자열 정렬**한 순서(1..N 정수로 매핑) | 입력 순서 | 문자열 정렬 |
| 9 | 매칭 | 점수 순 탐욕. 검출마다 아직 매칭 안 된 정답 중 IoU ≥ 문턱인 것을 고른다. 문턱은 `min(t, 1−1e−10)`, 비교는 `IoU < 문턱이면 건너뜀`이라 **같음은 매칭**이다 | 헝가리안 · IoU 전역 정렬 탐욕(ultralytics) · `IoU > t` | pycocotools |
| 10 | IoU 동률 | 문턱을 지난 뒤 문턱을 그 IoU 로 올리고, 다음 정답도 `<` 가 아니면 갱신한다 — **같은 IoU 면 정답 순서상 뒤쪽**에 매칭된다. 정답 순서는 무시 플래그로 안정 정렬한 원본(`annotations.csv`) 순서 | 앞쪽 · 임의 | pycocotools(뒤쪽). 동률 발생 건수를 센다 |
| 11 | IoU 식 | xywh(0-기준 연속, `+1` 없음). 교집합 폭 = `min(x+w) − max(x)`, 합집합 = 면적 합 − 교집합. **오른쪽 끝을 x+w 로 다시 계산**하므로 xyxy 로 바로 계산한 값과 끝자리가 다를 수 있다 | VOC `+1` · xyxy 직접 | 같은 식(xywh 에서 x+w 재계산). **문턱 경계 쌍(\|IoU − 0.5\| < 1e−9) 수**를 따로 센다 |
| 12 | 면적 범위 | 'all' = [0, 1e10]. 정답 면적은 bbox `w·h`(`annotations.csv` 의 `area_px`(다각형 면적)가 아니다). 범위 밖 정답은 무시, 범위 밖 미매칭 검출도 무시 — 'all' 에서는 걸리는 박스가 없다 | 면적 구간별 | 'all' 만. 무시되는 박스가 0 인지 단언한다 |
| 13 | 무시·crowd | 구축이 `iscrowd=0` 만 만든다 → 무시 정답 없음 | crowd 처리 | 무시 없음(단언) |
| 14 | 정답 없는 카테고리 | 그 카테고리 정밀도 −1 → **평균에서 뺀다.** 그 카테고리의 검출은 어디에도 계산되지 않는다 | 0 으로 포함 | 뺀다. 본실험 4클래스는 모두 정답이 있다(§5 실측) — 그래도 픽스처로 고정한다 |
| 15 | 정답은 있는데 검출 0 | 정밀도 0 행 → 평균에 **포함** | 뺀다 | 포함 |
| 16 | 평균 순서 | (T, R, K) 격자에서 −1 이 아닌 값을 C 순서로 펴서 한 번에 `np.mean`. `map_50` 은 T=0 조각(R 우선, 그 안에서 K) | 카테고리별 AP 평균 후 평균 | **둘 다 낸다.** 같은 순서 값은 비트 비교, 카테고리별 평균은 1e−12 비교 |
| 17 | 점수 없음 · 목록 밖 클래스 · 빈 이미지 | 점수 None 은 0.0 으로 대체(`score_records`), 클래스 목록 밖 검출은 버림, 정답·검출이 모두 없는 이미지는 건너뜀 | — | 같은 대체·버림(공유 입력 규약). 각각의 수를 센다 — 본실험 검출 칸은 전부 점수가 있다 |

## 4. 판정 기준 (계산 전 등록)

| 대상 | 허용 차 | 근거 |
|---|---|---|
| 칸 × 시드 15개 `map_50`(평균 순서 #16 을 맞춘 값) | **≤ 1e−12** · 기대는 0 | 37번 §8-3 `POINT_TOLERANCE` 와 같은 근거. 연산 순서까지 맞추면 비트가 같아야 하고, 1e−12 는 부동소수 경로 차이만 허락한다 |
| R_s(시드 3) · R̄ | **≤ 1e−12** | 분모 D≈0.3 으로 나눠도 map_50 차가 0 이면 0 이다 |
| 카테고리별 AP(4 × 15) | ≤ 1e−12 | 불일치 칸을 좁히는 진단용이다 |
| D. ultralytics 참고치 | **판정에 쓰지 않는다** | 정의가 다르다. 칸별 차와 회복률 차의 크기만 보고한다 |

- **전부 허용 안 → "독립 구현 검산 통과".** 대표 채택의 남은 조건이 닫힌다.
- **하나라도 넘으면** 해석하기 전에 원인을 좁힌다. 첫 불일치 칸에서 카테고리별 AP, 경계 IoU 쌍(#11), IoU 동률(#10),
  격자 경계(#2), 동점 묶음(#6·#7), 이미지별 매칭 결과를 덤프한다. 그리고 **총괄에 보고하고 대표 채택을 다시 연다**(총괄 지시).
  두 번째 구현의 결함으로 확인되기 전에는 어느 쪽이 맞다고 적지 않는다.

## 5. 입력 · 출력 · 코드

- **입력**: 하한 레코드 15개 `outputs/main_d/seed<n>/sweep/<칸>_raw_s<seed>.jsonl`. 해시는 v3 `input_records` 에 고정돼 있다.
  실행 전후에 49번 §1-2 와 같은 방식으로 맞댄다(30개 전부 — 운용점 15개는 계산에 쓰지 않지만 같이 확인한다).
  정답은 동결 스냅샷 `data/interim/manifest_v1`(`ensure_verified`)과 평가셋 12,461장이다. 정답 박스는 **22,549개**
  (클래스별 `100` 994 · `2011` 19,562 · `401` 918 · `301` 1,075), 박스가 있는 이미지는 7,086장이다(09-16 `load_population` 실측).
- **출력**: `outputs/main_d/seed3set/map50_independent_v3.json`. 판 번호는 입력(`score_cells_v3.json`)에서 뽑고
  (`provenance.versioned_output`), 이미 있으면 계산 전에 멈추고 배타 생성으로 쓴다. 본문에 `artifact_version`(자기 파일명)을 싣는다.
  내용은 칸 × 시드 map_50(두 구현·두 평균 순서), 차, 카테고리별 AP, #10·#11·#17 계수, R_s·R̄ 와 차,
  입력 해시, 두 구현의 코드 지문, 정의표 판(이 문서 SHA), 실행 시각, 최대 메모리, D 참고치(선택)다.
  **공유 산출물은 덮지 않는다.**
- **코드**:
  - `evaluation/metrics/map_independent.py`(새 모듈) — **pycocotools 를 import 하지 않는다.** 시험이 모듈 소스를 검사한다.
    `evaluation/recovery_ci.py` 도 import 하지 않는다.
  - `scripts/probe/map50_independent.py`(실행기) — v3 산출물·입력 확인·판정·출력.
  - 새 모듈이 `evaluation/**` 에 들어가므로 다음 판 채점기 지문이 바뀐다. v3 산출물과 v3 지문은 그대로다(사실 기록).
- **시험**(`tests/test_map_independent.py`):
  1. 손계산 픽스처 — #7 동점 tp·fp, #5 절단(12위·111위 참검출), #14 정답 없는 카테고리, #15 검출 0, #10 IoU 동률(뒤쪽 매칭),
     #11 IoU = 0.5 정확, #2 재현율이 격자점과 같은 경우.
  2. 합성 무작위 평가셋 여러 벌에서 pycocotools 와 비트 대조. 시험 안에서만 pycocotools 를 기준으로 쓴다.
  3. 모듈 소스에 `pycocotools`·`recovery_ci` import 가 없음.
  4. 실행기의 판 번호·덮어쓰기 거부·입력 해시 대조(기존 방어와 같은 방식).
  5. 변이 — 동률을 앞쪽으로, `>` 문턱, 이미지당 100(카테고리 무관), 사다리꼴 적분, 카테고리 평균 먼저, 불안정 정렬.
     각각을 시험이 잡는지 본다.

## 6. 비용 · 시간 · 자원

- 구현과 시험: 약 1일(모듈 약 200줄, 시험 약 300줄).
- 실행: pycocotools `evaluate()` 가 칸당 7~14초였다(v3 CI `build_seconds`). 순수 numpy·파이썬 루프는 2~10배 느릴 것으로 본다.
  칸당 30초~2분, 15칸에 **10~30분**으로 추정하고, 실측을 보고한다. 메모리는 2 GB 이하로 추정한다(v3 채점 최대 1.54 GB). 실측을 기록한다.
- 새 의존성이 없어 `uv sync` 도 필요 없다. GPU·외부 전송·외부 API 없음. 실행은 게이트와 겹치지 않게 한다.

## 8. 게이트에서 정할 것

1. 추천안 — A 직접 구현 + D 참고치(선택).
2. 구현 트랙 — D 그대로 / 원저자 아닌 트랙(§2 끝).
3. §3 정의표의 "맞출 쪽"(전 항목 pycocotools).
4. §4 판정 기준 — 허용 1e−12, 넘으면 보고하고 대표 채택을 다시 연다.
5. 교차 검수자, 그리고 정의표를 구현 전에 대조할지.

## 9. 하지 않는 것
