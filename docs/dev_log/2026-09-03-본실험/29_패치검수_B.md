## 1. F13 — 정본 검증기가 accepted 선택에 반영되는가

### 1-1. 재현 (`repro_f13.py`)

봉인 v2 의 `reasoning_accepted ∪ remedy_accepted ∪ discarded` 에서 `recs` 200건을 복원해

**패치된 `write_report`** 를 canonical ∈ {null, deepseek, phi} 로 임시 경로에 돌렸다. 봉인
디렉터리는 열지 않았다. 복원이 정확하다는 증거: canonical=null 에서 낸 `discarded.jsonl`
이 봉인본과 **바이트 동일**하다.

| canonical | report `n_accepted` / `n_pending` | `acceptance_status` | `validated_by` · `measures` | `reasoning_accepted.jsonl` | `reasoning_pending.jsonl` | `discarded.jsonl` |
|---|---|---|---|---|---|---|
| **null (현재 설정)** | **0 / 25** | `pending_canonical` | `rule` · `[format]` | **0건** (봉인본 25) | 25건 (새 파일) | 107 = 봉인본과 바이트 동일 |
| deepseek | 18 / 0 | `validated` | `cross_family` · `[format, groundedness]` | 18 | 0 | 114 (= 107 + 판정 기각 7) |
| phi | 7 / 0 | `validated` | 같음 | 7 | 0 | 125 (= 107 + 18) |

**연결은 정확하다.** 감사가 지적한 "canonical 을 읽지만 채택 조건은 stage1_pass 뿐"은
해소됐고, 미지정이면 accepted 가 아니라 pending 으로 남는다(`run_cycle_corpus.py` 패치

phi 의 18건 형식 위반이 accepted 7 에 들어가지 않는다.

### 1-2. 봉인본 소급 경계 — 지시가 특정한 질문

**물리적으로는 바뀌지 않는다.** 패치에는 봉인 디렉터리에 쓰는 경로가 없고, 24번의 가드가
`--out` 봉인본을 막으며, 재현은 임시 경로에서 했다. 재현 전후 봉인 v2 4개 파일의 sha256 이
그대로다 (`봉인본 무결성: True`).

**의미적으로는 바뀐다.** 위 표의 첫 행이 그것이다. 봉인 v2 는 `n_accepted 25 ·
end_to_end_pass_rate 0.2083 · validated_by cross_family · measures [format, groundedness]`
를 기록하고 있고, 같은 입력을 패치 코드로 다시 내면 `0 · null · rule · [format]` 이다.
즉 **봉인본의 "accepted" 는 패치 후 어휘로는 "pending" 이다.** 이 값을 인용하는 문서:

- `81_체크리스트_B.md:230` — `| 조항검색·기준서술 (c) | 120 | **25 (0.2083)** | … | cross_family |`
- `81_체크리스트_B.md:234` — "파일럿의 0.89 가 0.2083 이 됐다"
- `81_체크리스트_B.md:270` — deepseek 18/25 · 0.72 (이쪽은 `judge_agreement` 라 의미 불변)
- 봉인 v2 `EVIDENCE_SUMMARY.json` `recomputed` 블록 (추적 중)

봉인본은 못 고친다(규약 1-6). 그러므로 **재봉인이 아니라 재해석 주석**이 답이다 — 의사결정
로그에 "v2 의 accepted 25 는 정본 미지정 상태의 stage1 통과분이며 패치 후 의미로는 pending
25 다. 종단 통과율 0.2083 은 규칙 통과율이지 검증 통과율이 아니다" 를 남기고 81번에 같은
주석을 단다. **판정은 총괄.** 다음 사이클(v3)부터는 자동으로 새 의미가 적용된다.

### 1-3. 수정 제안 — 머지 차단급 1건

## 2. F14 — 사람 검증 시트에 기계 판정 노출

### 2-1. 재현 (`repro_f14.py`)

패치 전(`wt_B` HEAD)·후(`wt_review`) 의 `build_sheet` 를 **같은 봉인 v2 판정 레코드 120건**에
걸어 비교했다.

| | 패치 전 | 패치 후 |
|---|---|---|
| 행 키 | `…, stratum, …` | `stratum` 없음 |
| `judge_pass`/`judge_fail` 문자열이 든 값 | **25 / 25행** | **0** |
| `judge_*` 키 | 0 | 0 |
| 층 블록 순서 (인접 행의 층 변화 수) | **1** (pass 18행 뒤 fail 7행 — 순서가 곧 판정) | 8 (섞임) |
| 같은 시드 재현 | ○ | ○ |
| **표집된 sample_id 집합** | 25 | **동일** |
| `_shortfall` | 층별 4개 | `{"total": 75}` |

패치된 시험(`test_라벨_표본이_층화되고_기계판정을_보여주지_않는다`)을 **무패치 코드**에 걸면
정확히 그 값으로 실패한다:

```
AssertionError: assert 'stratum' not in {'sample_id': 's101', …,
                'stratum': '조항검색_기준서술|judge_pass', …}
```

패치 코드에서는 통과한다. 감사 지적 그대로 재현됐고 패치가 그것을 닫는다. **수용.**

설계에서 옳은 것 하나를 짚는다. `rng.shuffle` 이 층별 `rng.choice` **뒤**에 오므로 표집
자체는 패치 전과 동일하다(sample_id 집합 일치). 순서만 바꿨지 무엇을 뽑는지는 안 건드렸다.

CLI 경로(`judge_labels sheet --cycle-dir <봉인 v2>`)도 돌렸다 — 봉인 v2 에는
`reasoning_pending.jsonl` 이 없는데 `read_jsonl` 이 빈 목록을 돌려 무사히 25행을 낸다.
쓴 파일에 `judge_pass|judge_fail|stratum` 문자열 0, `judge_` 키 0.

### 2-2. 발견 — 패치 밖, 그러나 같은 사고

**추적 중인 `corpus/validate/judge_labels/sheet_v1.jsonl` 이 패치 전 생성본이라 누설을 그대로
담고 있다.** 25행 전부 `stratum: …|judge_pass/fail` (문자열 26건). 내가 `8ad3885` 에서
커밋한 산출물이다. 패치는 생성기를 고쳤지 산출물을 재생성하지 않았다. `labels_v1.jsonl`
은 아직 없으므로 재생성해도 잃는 라벨은 없다 — 라벨러에게 이 파일이 나가기 전에 머지 직후
`judge_labels sheet` 를 다시 돌려 교체해야 한다 (B 가 한다, 총괄 판정 후).

### 2-3. 수정 제안

**F14-P1. 층별 메타를 분리하지 않고 삭제했다.** `_shortfall` 을 `{"total": n}` 으로 뭉개면서
층별 부족분과 **표집확률(k/N_cell)** 을 낼 근거가 사라진다. 감사 권고는 "표집용 내부 메타데이터와
사람 화면을 **구분**하고, 층별 결과·표집확률을 보고한다" 이지 삭제가 아니다. Codex 도
"표본 가중 정확도 추정은 아직 남아 있다"고 인정하는데, 그러려면 지금 그 정보를 지우면 안 된다.
제안: 사람용 시트는 패치대로 비우고, 내부 메타(`sample_id → 층`, 층별 `N·k·p=k/N`, 부족분)를
라벨러에게 주지 않는 별도 파일(예 `sheet_v1.meta.json`)로 내며, `score()`(`judge_labels.py:124`)
가 그것으로 층 가중 정밀도·재현율을 낸다. 지금 `score()` 는 무가중이라 층별 표집이 들어간
순간 모집단 지표가 아니다 — 감사가 따로 검토하라던 "표집 비율 보정" 이 바로 이것이다.

**F14-P2. 시험이 값 누설을 여전히 안 본다.** 패치 전 시험은 `k.startswith("judge_")` 만
봐서 **값** 안의 `judge_pass` 를 구조적으로 못 잡았다 — 그래서 감사가 잡을 때까지 통과했다.
패치는 `"stratum" not in r` 를 더했을 뿐 같은 구조다. 모든 문자열 값에 `judge_pass|judge_fail`
스캔을 걸고, 순서가 층 블록이 아님(인접 층 변화 > 층 수 − 1)을 함께 걸어야 한다. 이 두 조건은
위 재현표의 "25 → 0"·"1 → 8" 을 그대로 고정하는 것이다.

**F14-P3. 문구 (경미).** `judge_labels.py` 패치 hunk `@@ -184` 의 출력 "…숨깁니다" 는 합쇼체다.
저장소는 해라체다.
