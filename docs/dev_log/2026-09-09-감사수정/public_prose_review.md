사용자 추가 요청: GitHub에 게시한 문서와 커밋 메시지 전체의 문체를 다듬는다. Codex는 GitHub에 직접 연결해 게시하거나 이력을 재작성하지 않는다. 게시 담당자는 기존 절차를 확인한 뒤 별도로 실행한다.

- 상태 `pending_context_review`는 **미검토**다. 원문을 복사해 두었다고 윤문 완료로 세지 않는다.
- `.txt` 중 모델 프롬프트·requirements와 실행 로그 원장은 일반 설명 문서가 아니다. 문체를 이유로 학습·평가 입력이나 기계 판독 형식을 바꾸지 않는다.

## 검토 기준

`humanize-korean` 스킬의 Codex 단일 호출 경로와 `50_공개문서_검수방침.md`의 의미 보존 원칙을 적용한다. 표현상의 과장, 과한 비유, 반복 대조, 불필요한 강조를 문맥에 맞게 다듬는다. 기술 용어와 실행 명령은 유지한다.

연구 사실을 고치는 작업과 문체 작업은 나눈다. 수치·날짜·해시·고유명사·직접 인용을 일괄 치환하지 않는다. 과거 기록에는 당시 판단과 추후 정정의 구분을 남긴다. `게이트`나 `동결`처럼 실제 코드·정책 개념인 용어를 모두 지우는 것도 적절하지 않다.

커밋 메시지는 변경 내용과 중요한 검증 결과를 보존한다. 작성자·날짜·tree·부모 커밋을 바꾸는 작업은 문체 교정의 일부가 아니다. 메시지 매핑을 검토한 뒤에도 이번 Codex 작업에서 ref를 변경하거나 push하지 않는다.

## 작업 상태와 교차 검토 요청

Codex는 연구 본문·실험설계의 오류 교정과 해당 문단 윤문을 먼저 진행했다. **나머지 문서와 커밋 메시지 전체의 문맥별 윤문은 아직 완료되지 않았다.** 단순 정규식 일괄 치환으로 완료 처리하지 않는다.

9/11 역할 정정: 위 JSON의 `proposed` 윤문안은 Codex가 작성하고 Claude가 검토·게시를 맡는다.
초기의 Claude 초안 작성 요청은 이 역할로 대체한다. 아직 실제 윤문하지 않은 항목은 미검토 상태를
유지한다. 새 커밋은 기준 SHA 이후 증분 목록으로 추가한다. 게시·이력 재작성은 윤문안 검토와 구분한다.

문서 전수 작업은 파일별 담당과 완료 여부를 기록해 이어간다. 완료되지 않은 문서를 포함해 “전체 AI 티 제거 완료”라고 보고하지 않는다.
