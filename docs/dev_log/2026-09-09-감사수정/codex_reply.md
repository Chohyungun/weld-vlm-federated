## F05와 `wt/C-bdr`의 T-eq 범위

`wt/C-bdr`의 `scripts/verify_resume_eq.py`를 읽었다. 이 시험은 완료된 서버 라운드 k로 돌아가 미완료 라운드를 다시 실행하는 **라운드 경계 재개**다. `detection/resume.py`의 epoch 체크포인트에서 이어 가는 **라운드 내부 재개**와 다르다. R 구현은 내부 재개 잔해를 격리하므로, T-eq가 통과해도 F05의 내부 재개 결함이 해결됐다는 증거는 아니다.

현재 T-eq는 두 중단 방식, 최종 글로벌 가중치, 일부 원자 로그와 optimizer 갱신 횟수, 클라이언트 실행 순서를 비교한다. F05의 LR 이력 보존, 전역·로컬 epoch 좌표 변환, 완료 epoch 체크포인트의 추가 학습 방지, 누적 gradient·optimizer step 시점 복원까지 전부 시험하지 않는다. 이 항목은 별도 회귀와 실물 재개 시험이 필요하다.

추가 주의: T-eq의 외부 중단 함수는 명령행의 `default_worker` 또는 `flwr-simulation` 문자열만으로 PID를 골라 종료한다. 같은 호스트의 다른 실험 프로세스도 매칭될 수 있다. 전용 유휴 창을 지키고, 가능하면 자신이 기동한 프로세스 트리·실행 식별자까지 확인하도록 좁힌 뒤 실행해야 한다. Codex는 이 GPU·프로세스 종료 시험을 실행하지 않았다.

### C — 다음 재개 실험 전에 확인할 것

1. **이전 loss CSV 삭제 경로.** `round_runner.py`는 같은 출력 경로로 새 trainer를 만들고,
   사용자 정의 재개는 상류 `args.resume=False`다. 설치된 Ultralytics `trainer.py:199–201`은
   이 경우 기존 `results.csv`를 지운다. LR 이력 복원은 과거 loss를 복원하지 못한다. 이전 CSV의
   보존·중복 epoch 방지·미완료 마지막 행 처리까지 시험해 달라.
2. **복구 파일 정리 시점.** `round_runner.py:361–363`은 메모리로 가중치를 내보낸 뒤 복구 파일을
   지우지만, 실제 최종 NPZ는 `train_cell.py:117/171`에서 저장한다. 중간 로그·저장 실패나 전원
   중단을 견디지 못한다. 최종 산출물을 내구성 있게 저장하고 검증한 뒤 정리하는 순서가 필요하다.
   저장 실패를 주입해 복구 파일이 남는지 검증해 달라.
3. **카운터 의미.** `fed_trainer.py`의 `optimizer_updates`는 상류 호출마다 증가한다. AMP의
   `GradScaler.step()`은 비유한 gradient에서 optimizer 갱신을 생략할 수 있다. 현재는 시도 수로
   해석하거나 성공한 갱신 수를 별도로 계측해야 한다. 기존 실행에 실제 skip이 있었다고 단정하지 않는다.
4. **정책과 출력 경로.** 새 loader 정책을 기존 `outputs/main_c` 산출물에 쓸 수 있는 경로가 남아
