### Q3. 연합 과소평가 방향

**방향 판단에는 동의하지 않는다.** 순서 다양성이 낮다는 사실만으로 최종 검증 성능이 낮아졌다고 결론 낼 수 없다. 고정 순서·증강이 최적화, 정규화, 과적합과 상호작용하며, 이 평가셋의 교락까지 있어 영향의 부호를 현재 관측으로 정할 수 없다. 회복률은 중앙·로컬·연합의 세 점수가 모두 들어가는 비율이라 각 점수의 변화 방향만으로도 단순히 판단할 수 없다.

“과소평가했을 수도 있다”를 가능성 하나로 언급하는 것은 가능하지만, “불리한 방향이다”, “결과를 깎았다”, “가능성이 높다”는 우선순위·확률 표현은 근거가 없다. 현재 결론은 **방향과 크기 미확정**으로 남긴다. `claude_response.md`의 해당 서술을 수정해 달라.

## F05와 `wt/C-bdr`의 T-eq 범위

`wt/C-bdr`의 `scripts/verify_resume_eq.py`를 읽었다. 이 시험은 완료된 서버 라운드 k로 돌아가 미완료 라운드를 다시 실행하는 **라운드 경계 재개**다. `detection/resume.py`의 epoch 체크포인트에서 이어 가는 **라운드 내부 재개**와 다르다. R 구현은 내부 재개 잔해를 격리하므로, T-eq가 통과해도 F05의 내부 재개 결함이 해결됐다는 증거는 아니다.

현재 T-eq는 두 중단 방식, 최종 글로벌 가중치, 일부 원자 로그와 optimizer 갱신 횟수, 클라이언트 실행 순서를 비교한다. F05의 LR 이력 보존, 전역·로컬 epoch 좌표 변환, 완료 epoch 체크포인트의 추가 학습 방지, 누적 gradient·optimizer step 시점 복원까지 전부 시험하지 않는다. 이 항목은 별도 회귀와 실물 재개 시험이 필요하다.

추가 주의: T-eq의 외부 중단 함수는 명령행의 `default_worker` 또는 `flwr-simulation` 문자열만으로 PID를 골라 종료한다. 같은 호스트의 다른 실험 프로세스도 매칭될 수 있다. 전용 유휴 창을 지키고, 가능하면 자신이 기동한 프로세스 트리·실행 식별자까지 확인하도록 좁힌 뒤 실행해야 한다. 외부 검토 도구는 이 GPU·프로세스 종료 시험을 실행하지 않았다.

## 게시·윤문 요청에 대한 작업 경계

사용자가 GitHub 직접 연동·게시를 하지 말라고 명시했다. 외부 검토 도구는 로컬 문서와 커밋 메시지 윤문안을 준비하고, 원격 게시·이력 재작성은 실행하지 않는다.

`scripts/publish.sh`와 `50_공개문서_검수방침.md`를 읽었다. 현재 publish 스크립트는 AI 관련 **트레일러 삭제**만 수행하므로 커밋 제목·본문 전체의 윤문 요청을 충족하지 않는다. 이력 변경에는 검토한 메시지 매핑과 SHA 대조 자료가 별도로 필요하다. 또한 reflog 만료·즉시 GC는 복구 수단을 줄이며, 이력 재작성 뒤 일반 push는 non-fast-forward로 거부될 수 있다. 이번에는 이 스크립트를 실행하지 않았다. 게시 전 총괄 세션이 백업·작업 중인 worktree·원격 ref 상태를 확인해야 한다.

과거 검수 방침의 수치 치환표를 현재 정답으로 일괄 적용하지 않는다. 그 표 자체가 과거 시점 기록이다. 문체 수정과 실험 사실 정정을 분리하고, 과거 결정·불일치·기각의 근거를 삭제하지 않는다.

### 우선 수정 요청: 집계 입력과 CI를 결합할 때의 검증

D의 37번 보고와 실제 `recovery_ci_v1.json`·`aggregate_v2.json` 생성을 확인했다.
CI는 이제 미산출이 아니다. 기록된 회복률은 24.7728%, 95% 구간은 [20.8728%, 29.2928%]이고,
T1은 15개 모델의 두 mAP 지표에서 차이 0이다. 이는 이번에 재실행한 시험 결과가 아니라
생성된 산출물의 확인이다. 현재 CI의 시드별 입력 SHA는 실제 v2 세 파일과 일치한다.

다만 `wt_D/scripts/probe/aggregate_seeds.py`의 집계 진입부(현재 804~809행)는 CI의
`artifact_name`만 확인하고, `apply_recovery_ci()`(588~604행)는 저장된 `ci_pass`를 그대로
신뢰한다. 같은 이름의 채점 파일을 갱신하거나 다른 시드를 선택하면 과거 CI로
`recovery_reportable=true`가 될 수 있다. **현재 결과 오염을 발견했다는 뜻은 아니며,
잘못된 입력 조합을 거부하는 방어가 빠졌다는 지적이다.** D가 다음을 보완하고 교차 검수를
받기 전에는 CI를 최종 승인으로 취급하지 말아 달라.

- 선택한 시드 집합, 시드별 실제 파일 SHA, 평가 대상·지표·로컬 평균 정의와 CI 입력의 일치.
- 현재 집계의 점추정과 CI의 점추정 일치, T1 결과의 존재와 통과 여부. 수치 허용오차는 명시한다.
- 누락·불일치·T1 실패를 통과로 바꾸지 않는 시험. 파일명은 같지만 내용이 달라진 경우와
  시드 부분집합이 다른 경우를 포함한다.
- 집계 JSON의 상태를 한 곳에서 결정한다. 현재 `map_50` 아래에는 `ci_pass=null`·"CI 미산출"과
  `recovery_reportable=true`가 함께 남아 있다. "확정 대표 숫자"와 "대표 채택 미결"도 구분한다.

T1은 두 채점 구현의 항등 검사이며 독립 정답 검산은 아니다. 이번 구간은 세 학습 시드를 고정한
평가 묶음 재표집 결과다. 새로운 학습 시드·현장·자료셋의 불확실성까지 포함한다고 쓰지 않는다.
실행 소스와 최종 승인·병합 코드의 일치 확인도 남아 있다. 줄끝 정규화 비교와 원시 파일
해시는 별도 기록하며, v3를 실행하더라도 기존 v1·v2는 진단 이력으로 보존한다. §18-3의
