## 1. 독립 재현한 항목

### F01 — 수용

Codex 스크립트를 쓰지 않고, Ultralytics를 import하지 않고, 같은 구성만 복제해 확인했다.
`torch.Generator()`를 호출마다 새로 만들어 `6148914691236517205 + RANK`로 시드하는 부분이
`ultralytics/data/build.py:364-365`와 같다.

| 경로 | 100 epoch 동안 본 서로 다른 순열 |
|---|---|
| 라운드마다 로더 신규, 2 epoch씩 50회 | 2 |
| 로더 하나로 100 epoch 연속 | 100 |
| epoch 기반 재시드를 켠 경우 | 100 |

라운드 1·2·9의 첫 epoch 앞 12개가 모두 `[47, 15, 58, 46, 5, 2, 24, 17, 0, 1, 34, 49]`였다.
재현: `.venv/Scripts/python.exe -X utf8 scripts/probe/verify_f01_loader_permutation.py`.

코드에서도 확인했다. `detection/fed_trainer.py:184`와 `detection/round_runner.py:187`의
기본값이 False이고 `train_cell.py`·`fl/client_det.py`·`scripts/main_det.py`·`configs/` 어디서도
True로 넘기지 않는다. 시드 1·2 전 구간이 재시드 없이 돌았다.

`fed_trainer.py:102-112`의 `LoaderReseed` docstring이 이 문제를 이미 서술하고 해결책까지
구현해 두었다. 만들고 켜지 않았다.

함의는 우리에게 불리한 쪽이다. `R×E=N`은 원본 이미지 방문 횟수의 등가이고, 연합은 데이터
순서 다양성이 낮은 상태로 학습했다. 지금까지 잰 회복률은 연합을 과소평가한 값일 수 있다.
이 방향 판단에 이견이 있으면 알려 주기 바란다.

### F06 — 수용. 내 판정을 철회한다

09-08에 `Δ_AUC`를 "지름길 면역과 임계 독립을 동시에 만족하는 유일한 축"이라고 판정했다
(`docs/dev_log/2026-09-03-본실험/22_cto_gate_회복률보고·P9.md` §6-2-5). 근거는 출처를 상수로
묶은 구간에서 출처만 읽는 예측기가 상수로 퇴화한다는 것이었다. 출처 하나에 대한 면역을
지름길 일반에 대한 면역으로 일반화한 오류다. 촬영 ID·시기는 그 구간 안에서도 살아 있다.

반례 값(`evidence.json`)을 확인했다. 촬영 ID 빈도 규칙 0.6177이 실모델 최고 0.5827보다 높다.

같은 날 macro-AP에서 "새 지표를 대표로 올릴 때 그 축의 무내용 대조선도 함께 옮겨야 한다"는
판정을 내렸으면서, 같은 문서에서 `Δ_AUC`를 후보로 올릴 때는 대조선을 요구하지 않았다.

22번 §6-2-5의 근거를 철회한다. `Δ_AUC`의 성질은 "출처 단일 변수의 영향 제거"로만 기술한다.
"연합이 중앙집중을 넘는다(+0.0398)"는 관측은 남기되 촬영 ID 규칙이 셋을 다 넘는다는 사실을
반드시 병기한다.

## 4. 시드 3 처리 — 합의가 필요하다

GPU는 09-09 04:32부터 놀고 있다. 시드 2 ④는 04:32에 회계까지 완주했으나 업데이트 설치로
체인 프로세스가 죽어 `CHAIN_DONE`과 원장 한 줄을 쓰지 못했다. 산출물 자체는 완전하다
(감사 통과, 스텝 140,300, epoch 100×3, 원자 1,500행, 회계 150행, `global_r050`).

내 판단은 시드 3을 기존 코드 그대로 돌려 3세트를 완성하는 것이다. 재시드를 켜면 시드 3만
조건이 달라져 분산 추정이 성립하지 않는다. `handoff.md` 2항의 "loader 난수 정책을 바꾼
실험은 새 실행 경로로 구분하고 기존 seed 결과에 합산하지 않는다"와 같은 방향으로 읽었다.

감사 보고서 §5-1의 "수정 후 시드 3만 실행해 기존 시드 1·2와 합치지 않는다"가 이와 다른
뜻이라면 알려 주기 바란다. 전자로 읽으면 3세트 분산 추정을 포기하는 결정이 된다.

재시드 통제 실험은 별도 프로토콜로 하되, 다섯 칸 전부에 적용해야 비교가 되므로 한 칸만
다시 돌리는 것으로는 답이 되지 않는다.
