## 수정과 재계산

회의 자료·상세 보고에서 잘못 특정한 pHash 묶음 설명을 고쳤다. 실제 기준은 파일 SHA256,
라벨 숫자 ID의 연속 구간, pHash 거리 0이다. 숫자 ID는 검증된 연속 촬영 식별자가 아니다.
동결일은 8/31이며 임계값 0.25에서 연합만 상자를 대량 제외한 것처럼 쓴 비교도 고쳤다.
`사전실험_보고_교정기록.md`에 기존 정정의 오류까지 남겼다.

수치 재현은 `outputs/audit_20260915/verify_numbers.py`가 기존 세 시드의 JSON만 읽어 수행했다.
프로젝트 집계 함수는 호출하지 않았다. 결과는 같은 폴더 `numbers_verified.json`에 있다.

- 공개 mAP·로컬 평균·회복률과 원 JSON 3개의 해시가 일치한다. 회복률 평균은 24.77276102857702%다.
- 집계와의 최대 차이는 시드 1·3 회복률의 `3.552713678800501e-15` percentage points다.
  9/11 기록의 `1.42e-14`는 원 연산을 확인하지 못해 철회했다. 집계기와 곱셈·나눗셈 순서를
  같게 하면 차이는 0이다. 부동소수점 끝자리 차이이며 성능 결론을 바꾸지 않는다.
- ΔAUC 최고값은 시드 1에서 0.5826915889625146, 15개 모델 전체에서 0.5843583117332622다.
  K=64 대조선 0.5803453594588459는 둘보다 낮다. K=256·512는 전체 최고값보다 높다.
- 시드 1의 0.25 임계값에서 상자 잔존 비율은 연합 5.844551%, C3 12.410082%다.
  남은 상자 수는 각각 11,041개와 11,024개이므로 '상자 수가 두 배'라고 하면 틀린다.

## CPU 검증

최초 실행은 새 감사 출력 폴더가 없어 pytest의 basetemp 생성에 실패했다. 이를 중단한 뒤
단일 시험에서 `FileNotFoundError`를 확인했다. 부모 폴더를 만들고 새 경로로 다시 실행했으며
코드 실패나 자산 소실로 분류하지 않았다. 이전 임시 폴더를 지우지 않았다.

|---|---|---|
| P3 수정 전 새 비율 시험 | 1 실패 · 2 통과 | 1/3만 반올림하지 않음을 재현 |
| 최신 병합본 전체 CPU | 1,550 통과 · 21 건너뜀 · 5 제외 · 실패 0 | P3 보완 전 |
| P3 보완 후 전체 CPU | 1,553 통과 · 21 건너뜀 · 5 제외 · 실패 0 | 56.66초, 실물 대조 경고 2건 |
| 독립 검토 뒤 봉인 왕복까지 보강한 관련 시험 | 59 통과 | 새 3경우와 기존 채택·소비자 시험 |

건너뜀과 경고를 포함한 전체 검증 완료는 아니다. 두 경고는 main에 없는 cycle 코퍼스 원문
구성원을 전부 대조하지 못했다는 내용이다. GPU 학습·추론, 실제 두 프로세스 재개, 사람 평가는
실행하지 않았다. 비율 보완은 새 보고서만 바꾸며 기존 봉인 자산을 다시 쓰지 않았다.

## 자산과 남은 일

main의 pairs v1은 파일 3개 SHA가 계약과 일치한다. 계약 파일 자체의 SHA도 B30의 복구 기록과
같다. pairs v2와 pilot3000은 현재 main 경로에 없다. pilot3000은 FROZEN_REAL 밖의 자산이며
9/11의 '필수 입력 14개 중 1개 부재'는 이 파일럿 실채점 계약의 점검이다. pairs 구성원 집계가 아니다.

B의 새 사람 시트에는 `judge_pass/fail`·`stratum` 문자열이 없다. 항목별 층 정보는 별도로
취급해야 하며 저장소 이력·기계 판정 근거를 평가자에게 함께 주면 블라인드가 깨질 수 있다.
현재 시트 25건을 목표 100건 달성이나 모집단 정확도 검증으로 보고하지 않는다.

C는 재개 중 과거 loss CSV 삭제, 최종 저장 전 복구 파일 삭제, AMP 카운터 의미, 정책 충돌,
R의 29열 CSV 호환을 수용했으나 구현과 새 시험은 아직이라고 회신했다. 회의 자료에도 미완료로
남겼다. 전환 전후 체크포인트 진단은 제안이며 실행하지 않았다.

문서 재검토와 게시 범위는 `codex_reply.md`의 9/15 회신에 있다. Notion·GitHub 게시 완료는
확인하지 못했다. 이 기록은 이번 세션의 관찰이며 상시 감시 서비스를 기동했다는 뜻은 아니다.
