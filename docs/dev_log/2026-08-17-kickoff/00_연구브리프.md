## 1. 검증된 사실 (ground truth)

아래는 저장소 문서에서 확인한 것이며, 추정이 아니다. 트랙 담당는 이 절을 전제로 삼는다.

### 1-1. 실험 구조 — 5칸 (6칸 아님)

|        | 로컬 단독 | 중앙집중 | 연합학습 |
|--------|----------|---------|---------|
| 통합형 | **제외**  | 통합·중앙 | 통합·연합 |
| 분리형 | 분리·로컬 | 분리·중앙 | 분리·연합 |

통합·로컬 제외 근거: 현실 배포 시나리오가 아니고, RQ3는 분리형 비교로 답하며, 학습 비용이
가장 크다. **제외 사유를 논문에 한 문장으로 명시하는 것까지가 요구사항이다.**

RQ2(통합형 vs 분리형)가 주 기여. KCI·ScienceON 검색(2026-08-03) 0건 — 검색 로그를 각주로 남긴다.

### 1-3. 선행 연구 (WeldLLM, IEEE TII)

순수 VLM이 아니라 전용 검출기(WTDWR-YOLO 2.78M) + ROI-to-token 정렬 + LoRA VLM의 혼합.
공표 수치 mAP@0.5 0.800 / F1 0.773 / BBox-IoU 0.953. 코드는 MIT(github.com/ucassqs/WeldLLM),
데이터셋(MWDD)은 Zenodo Restricted로 잠김.

남긴 공백 3개 = 우리 연구 슬롯: **연합학습 없음 · 규격 준수 미측정 · 미지 현장 이미지 미검증.**

주의: `llm/src/datasets.py`의 텍스트 어노테이션은 150+ 템플릿 채우기다. 논문의 "expert-level"
표현과 실질이 다르므로, 이를 정답으로 삼는 텍스트 유사도 평가는 "템플릿 모사도"를 재게 된다.
→ 이 한계가 오히려 **조항 정확도 축(신설)을 정당화한다.**

## 2. 불변조건 (모든 트랙 상속)

전문은 `docs/개발규약.md`에 있다. 트랙 담당는 세션 시작 시 자동으로 읽으므로 dispatch 파일에
재기술하지 않는다. 총괄이 게이트에서 실제로 검사하는 항목만 여기 요약한다.

**데이터** — 원본 불변 / 매니페스트가 단일 진실 / 평가셋을 회사별 분할보다 먼저 뗀다 /
평가 자산 격리 / 중복 묶음 단위 분할 / 스냅샷 해시 고정 / 허용치 CSV가 단일 소스

**보안 레드라인** — AI허브 국외 반출 금지 / 원본 이미지를 외부 상용 API에 보내지 않는다 /
외부 클라우드 실험 로깅 금지(MLflow 로컬) / 상용 API 출력으로 학습하지 않는다 /
유료 표준 전문을 색인에 넣지 않는다

**모델·실험** — 조기 종료 금지 / best 아닌 **last** 채점 / 5칸 공통 고정 8종 /
재시도·재프롬프트 금지(greedy 1회) / 생성 모델이 자기 결과를 검증하지 않는다 /
검증 실패분은 폐기하고 통과율 기록 / 공통 스키마 + 단일 채점기

이 셋 중 하나라도 어긴 커밋은 **머지 게이트에서 무조건 반려**한다. 성능이나 일정을 이유로
예외를 허용하지 않는다 — 어기는 순간 논문의 주장 자체가 성립하지 않기 때문이다.

## 3. 트랙 구성 — 5트랙 (2026-08-17 사용자 확정)

저장소 구조와 **의존성**을 기준으로 나눈다. 팀원 역할과도 대응한다.

| 트랙 | 범위 | 선행 조건 | worktree / 브랜치 | 팀원 |
|---|---|---|---|---|
| **A 데이터 파이프라인** | `data/` ingest·convert·dedup·split, `configs/` 사상표 | **없음** — RIAWELC으로 즉시 착수 | `_wt_A` / `wt/A` | 박상은 |
| **B 코퍼스·합성** | `corpus/` parse·rules·generate·validate, 허용치 CSV, 판정 골격 생성기 | **없음** — 텍스트 원천만 필요 | `_wt_B` / `wt/B` | 조현건 |
| **C 학습·연합** | `detection/` `vlm/` `fl/` — YOLO11s 래핑, Flower, 집계, 통신량 | A의 manifest **계약**만 (mock 선행) | `_wt_C` / `wt/C` | 조현건 + 김예서 |
| **D 평가·RAG·추적** | `evaluation/` `rag/` `tracking/` — 공통 채점기, 조항 색인, MLflow | **없음** — 예측 스키마 확정 후 즉시 | `_wt_D` / `wt/D` | 박상은 + 조현건 |
| **E 논문·분석** | `docs/paper/` 그림 4종, 결과표, 초록 300자, 선행연구·검색로그 | **없음** — 형식·자리표시자 먼저 | `_wt_E` / `wt/E` | 조현건 |

**5트랙 중 4트랙이 GPU도 AI허브 승인도 기다리지 않고 오늘 착수 가능하다.** 이것이 이 분할의
핵심 이유다. 외부 병목(승인·GPU)이 임계경로에서 빠진다.

**E 트랙의 유휴 위험**은 인지하고 있다. 결과 수치가 나오기 전까지 E가 할 일이 적으므로,
dispatch에 "유휴 방지 — 지금 당장 가치 있는 일" 절을 넣어 선행연구 정리·검색로그 최신화·
그림 명세·서지 검증을 먼저 태웠다. 그래도 비면 총괄이 리뷰 역할(R-적대)을 E에 배분한다.

**D를 별도 트랙으로 세우고 학습보다 먼저 완성시키는 이유:** 채점기가 학습 뒤에 만들어지면
5칸을 각각 채점하는 코드가 갈라지고, 그 순간 공정성 주장이 무너진다. 채점기는 **학습 결과가
나오기 전에 완성돼 있어야 한다.**

**rag/를 C가 아닌 D에 두는 이유:** 판정부 검색은 집계 대상이 아니고 5칸 공통 고정이며,
허용치 CSV·정답 조항 목록을 채점기와 공유한다. C에 붙이면 인터페이스가 늘기만 한다.

### 3-1. 트랙 간 계약 — 명세 작성이 가장 먼저 확정할 것

트랙을 나누는 비용은 전부 이 4개 파일에 몰려 있다. **이것부터 얼리면 병렬이 성립하고,
못 얼리면 4트랙이 서로를 기다린다.**

| # | 계약 | 소유 | 소비 |
|---|---|---|---|
| 1 | `configs/label_map.yaml` 원본 라벨 ↔ ISO 6520-1 | A | B·C·D |
| 2 | `data/manifest.csv` 컬럼 스키마 | A | C·D |
| 3 | `corpus/limits.csv` 허용치 표 | B | B(골격)·D(RAG 메타·채점 정답) |
| 4 | `evaluation/prediction.schema.json` 공통 예측 JSON | D | C(5칸 전부 이 형식으로 출력) |

3번은 특히 위험하다. 골격 생성기·RAG 메타데이터·채점기 정답 기준이 **한 파일에서 파생되지
않으면** 판정 정합성 지표가 통째로 무의미해진다. 세 곳이 각자 표를 읽는 구조를 금지한다.

## 7. 진행 순서

1. **설계 프레이밍** (본 문서) — 트랙 구성·모델 배정 사람 확인 **1회** ← 현재
2. **인프라** — 트랙별 worktree를 고정 경로로 만들고 작업 세션을 분리해 배치한다
3. **명세 작성** — 플래너 분업 단위가 `01_spec_planner.md`. **최우선 산출물은 §3-1 계약 4종**
4. **교차 검토** — 관점 리뷰 병렬. 이 프로젝트에 필요한 패널: **데이터/RDB · 보안 · 배포/재현성 ·
   실험방법론**. (프론트·KG 패널은 해당 없음 — 웹 UI도 지식그래프도 없다)
5. **검토 판정** — 검토 게이트. Critical 전부 해소 후 스펙 v1.1
6. **계획 수립~G** — 계획 → SDD 구현 → 머지. 기능·분석 단위 완료마다 리뷰 2종(재현 검증 /
   방법론·코드 적대 리뷰)을 **원저자가 아닌 트랙**에 배분
7. 마일스톤마다 explain-diff 아티팩트 + 이해도 퀴즈 게시

머지는 총괄만 한다. 머지 전 전체 테스트 + 독립 검수, Critical 해소 전 머지 금지.
