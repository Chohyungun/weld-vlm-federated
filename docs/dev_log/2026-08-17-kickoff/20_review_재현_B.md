## 0. 이 리뷰가 실제로 실행한 것

B는 스펙만 있고 코드가 없다. 그래서 "재실행"의 대상을 **B가 소비하기로 한 계약 #1·#2의
구현본**으로 잡았다. 트랙 A가 그 둘을 구현했으므로 B의 계약이 실제로 맞물리는지를 코드로 확인할
수 있다. 아래 6건은 전부 실측이며, 재현 스크립트는 이 리뷰 말미 §5에 있다.

| # | 검사 | 결과 |
|---|---|---|
| 1 | 계약 #1이 B의 G0 V1(`defect_code ∈ 사상표`)에 필요한 코드 집합 접근자를 주는가 | **없음** → Important-7 |
| 2 | 계약 #2의 `material` 실측값 ↔ B의 `ST\|AL\|ALL` | `ST`,`AL`,**`UNK`** → Important-5 |
| 3 | 계약 #2의 `thickness_source`/`scale_source` 실측값 ↔ B의 `{metadata, assumed}` | 실측 **`none`**, `verdict_mode=clause_only` → Important-3 |
| 4 | 공란=+∞ 를 pandas 기본값으로 읽을 때 V2 검사 거동 | **정상 행과 오염 행의 판정이 뒤바뀐다** → Important-6 |
| 5 | B의 D4 수량 산정 재계산 | 46,165 ≈ "~46,000" **산식 정확** → Minor-3 |
| 6 | ISO 코드 `2011` ↔ 연도 `2011` 동형 | 화이트리스트 충돌 확인 → Important-2 |

**레드라인 스윕 (C4) — 위반 무검출.** `wandb|comet|neptune` 0건, `early.stop|patience|best.pt`
0건, 평가셋 학습 유입 0건. `openai` 1건은 vLLM의 OpenAI **호환 서버**(로컬)이고 상용 API가
아니다 — §5-2가 상용 API 금지를 명시하고 있어 정합하다. `재프롬프트`·`자기검증` 검출분은
전부 금지를 **집행하는** 조항이다.

**함정 구간 (C5) — 충족.** #6·#7 모두 다관점 병렬 검증 수행, 심화 검토 등급 명시, 적대 검증
finding 31건 전건 처리(부록 A). 단독 진행 아님.

**먼저 인정할 것.** 계약 #3을 "파일 + 로더 + 공유 평가기 + **D 소비 파생 함수 3종**"까지
묶어 얼린 §1-4는 브리프 §3-1이 지목한 위험(세 소비처가 각자 표를 읽음)에 대한 정확한 답이다.
C1 항목에서 이 스펙이 가장 잘한 부분이고, 아래 지적은 그 구조를 흔들려는 것이 아니다.

## 1. Critical

```
[Critical] 11_spec_B §5-4 — 수치 잠금이 값-역할 결합을 검사하지 않아, 값을 서로 뒤바꿔
쓴 생성문이 전량 통과한다. "수치·논리는 규칙이 만든다"는 논문 주장이 여기서 무너진다.
```

**실패 시나리오** (구체값)

불합격 골격 하나를 놓는다. `{size_mm: 3.0, limit_value(L): 2.0, margin: -1.0, verdict: 불합격,
clause_id: KR-x, defect_code: 2011, thickness_mm: 12.0}`

LLM이 이렇게 쓴다 — **허용치와 실측을 뒤바꿔서**:

> "모재 두께 12.0 mm, 허용치 **3.0** mm에 대해 실측 **2.0** mm로 확인되어 **불합격**으로 판정한다."

§5-4의 4단계를 순서대로 통과한다.

1. 추출 — 수치 토큰 `{12.0, 3.0, 2.0}`, 코드 `2011`, 조항 `KR-x`
2. 정규화 — 변화 없음
3. **화이트리스트 대조 — 통과.** 허용 집합은 `{size, thickness, L, margin, defect_code,
   clause_id, quality_level}` 의 **값 집합**이고 `3.0`·`2.0`·`12.0` 전부 그 안에 있다.
   필수 출현 집합(§4-4 매트릭스: size, t, L, verdict)도 **값 기준으로는 전부 등장**한다.
4. 판정어 대조 — 생성문 "불합격" = 골격 verdict "불합격". **통과.**

즉 **"2.0 ≤ 3.0 인데 불합격"이라는 부등식이 뒤집힌 문장이 검증을 완주한다.** 그리고 이건
운 나쁜 조합이 아니다. §4-4가 `margin = L − measured`로 세 값을 산술로 묶어놨기 때문에
L·size·margin은 서로 자연스럽게 바꿔 끼울 수 있는 자리에 있고, 판정추론 템플릿(관찰→분류→
조회→대조→판정)의 "조회"와 "대조" 단계가 정확히 그 두 값을 나란히 놓는 자리다.

**어느 층도 이걸 담당하지 않는다.** 스펙이 스스로 그렇게 나눠놨다.

- §5-4는 값의 **집합 소속**만 본다 (역할은 안 본다)
- §6-1 "부등식 재계산"은 `limit_eval`로 **골격에서** verdict를 재도출한다 — 생성문을 보지 않는다
- §6-2 Judge는 §619가 명시한 대로 **"수치는 1단계가 이미 보증"** 이라는 전제로 내용 일치만
  본다. 이진 pass/fail 1회·재프롬프트 금지이므로 잡을 **보증**이 없다
- §6-3 전문가 검토는 2~3% 표본이다

**등급 근거 (루브릭 §1 ①)** — 논문은 "LLM은 표현만 만들고 수치·논리는 전부 규칙이 만든다"를
합성 데이터 정당화의 근거로 쓴다(구현설계 4-3, `docs/개발규약.md` 불변조건 3-6 취지). 이 구멍이 열려
있으면 그 주장이 **정량화되지 않은 비율만큼 거짓**이 된다. 통과율을 보고해도 잡히지 않는다 —
이 오염은 실패로 계수되지 않고 통과분에 섞이기 때문이다. 또한 발견이 생성 이후로 밀리면
(b)(c)·D4 전량 재생성이다(루브릭 ②).

루브릭 §7의 선례를 따랐다: 자리표시자 위반이 문구 문제처럼 보여도 Critical인 이유는
"발견 시점이 아니라 유입 시점부터 오염"이기 때문이다. 검증 관문의 구멍도 같은 성질이다.
**아직 생성 전이라 지금 고치면 비용이 거의 없다는 점이 등급을 낮출 이유는 되지 못한다** —
지금이 유일하게 싼 시점이다.

**제안 (최소 수정, 둘 중 하나로 충분)**

- **(권장) 판정문 JSON에 필드를 동시 출력하게 하고 필드 단위로 대조한다.** §4-5 골격 스키마가
  이미 있으므로, 생성 산출물이 `{"판정문": "...", "fields": {"size_mm":…, "limit_value":…,
  "margin":…, "verdict":…}}` 형태면 §5-4에 **값-대-값 대조 1단계**를 추가하는 것으로 끝난다.
  자연문 파싱이 필요 없다.
- (대안) 문장 내 슬롯 정규식 — 템플릿이 "허용치 {L} mm", "실측 {size} mm" 어형을 강제하고
  슬롯별로 대조. 표현 다양성을 일부 희생한다.

어느 쪽이든 §5-4 3단계를 "집합 소속 + **역할 결합**"으로 고치고, 사유 코드에
`role_swap`을 추가한다.

## 2. Important

```
[Important] 11_spec_B §4-2 — applicable_row 의 "정확히 1행" 보장이 두 경로에서 깨진다.
스펙 자신이 공존을 허용한 조합에서 fail-closed 예외가 난다.
```

시그니처는 `applicable_row(table, defect_code, material, scheme, level, t) -> LimitRow`,
주석은 "정확히 1행, fallback 금지"다. 그런데

**(a) `limit_type` 파라미터가 없다.** §1-2 V3은 그룹 키에 `limit_type`을 **포함**시켰고(D1-8
반영), §4-1은 "같은 조합에 limit_type이 다른 복수 제약(낱개 지름 + 누적 비율)이 공존할 수
있으므로 … 조립 단계에서 AND"라고 **명시적으로 공존을 설계에 넣었다.** 두 서술이 참이면
`applicable_row`의 6개 인자로는 행이 2개 매칭된다.

**(b) `material=ALL`과 `material=ST`가 동시에 매칭된다.** V6 유일성 키에 `material`이 들어
있으므로 `(ST, 100, [8,25), C, 길이)`와 `(ALL, 100, [8,25), C, 길이)`는 **서로 다른 행**이고
V6·V3을 둘 다 통과한다. 그리고 `material="ST"` 질의는 둘 다에 해당한다. 특정성(specificity)
우선순위 규칙이 스펙 어디에도 없다.

**실패 시나리오** — IACS Rec.47에서 균열이 `material=ALL`로 1행 등재되고, KR 규정에서 강재
균열이 `material=ST`로 1행 등재된다(§3-2 초기 배정상 두 문서 모두 경로 D). V9 교차 문서 충돌
검출은 "동치 품질수준 + 한계 파라미터가 다른 행 쌍"을 보므로, 두 행의 한계가 **같으면 충돌로
안 잡힌다.** canonical도 둘 다 true일 수 있다(V6의 "같은 조합에 canonical 2개 이상 = 오류"의
'조합'에 material이 포함되므로 서로 다른 조합이다). 이제 균열 골격 생성 시
`applicable_row(..., material="ST", ...)`가 2행을 받고, fail-closed 원칙(§4-2)에 따라
**(c) 경로는 전체 중단**한다. 균열은 ST 2,277장·AL 332장의 유일한 "전 수준 불허" 유형이라
F4 사례가 통째로 사라진다.

근거: `11_spec_B` §1-2 V3·V6, §4-1, §4-2 / 루브릭 C1
제안: ① `applicable_row`에 `limit_type` 인자를 추가하고, 복수 제약 조회용
`applicable_rows(...) -> tuple[LimitRow, ...]`를 별도로 두어 §4-1의 조립 AND가 쓰게 한다
② `material` 특정성 규칙 1줄 명시 — "구체값(ST/AL) 행이 있으면 그 행, 없을 때만 ALL"
③ V6 유일성 키의 '조합'이 material 특정성 축소 후 기준인지 원본 기준인지 명시

```
[Important] 11_spec_B §5-4 1~2단계 — 수치 토큰 추출·마스킹 우선순위가 미명세여서
양방향으로 실패한다: 조항번호 파편은 폐기율을 폭주시키고, 마스킹하면 우회 통로가 된다.
```

§5-4는 "정규식으로 수치 토큰 전량(숫자+단위), ISO 코드, 조항 번호, 등급, 판정어"를 뽑는다고만
쓰고 **추출 순서와 배타성**을 정하지 않았다.

- 조항 번호 `3.2.1`을 수치로 먼저 뽑으면 `3.2`·`1`이 허용 집합 밖 → **정상 샘플이 폐기**된다.
  판정추론 템플릿의 "조회" 단계는 조항 번호를 반드시 포함하므로 폐기율이 구조적으로 높아진다.
- 반대로 조항 번호를 먼저 마스킹하면 `"조항 5.2 기준 5.2 mm 이하"`에서 두 번째 `5.2`도
  마스킹 규칙에 걸릴 수 있고, 그 순간 **환각 수치의 통로**가 된다.
- **실측 [6]:** 기공 코드 `2011`이 허용 집합에 들어가므로 생성문의 `"2011년 개정판"`이 통과한다.
  거울상으로 `2012`(§4-6에서 D4 배제한 코드)가 연도로 등장하면 허용 집합 밖 → 폐기다.
  ISO 6520-1 4자리 코드와 연도가 같은 자리수·같은 범위라 이건 상시 발생한다.

근거: `11_spec_B` §5-4, §4-6 / 실측 §5-[6]
제안: §5-4에 3줄 — ① 추출은 **배타적 단계순**: 조항번호 → ISO 코드 → 등급 → 연도(4자리 +
`년` 접미) → 수치(숫자+단위 결합 토큰만) ② 앞 단계가 소비한 문자 구간은 뒤 단계에서 제외
③ 단위 없는 맨 숫자는 수치 토큰으로 보지 않는다(대신 **금지 토큰**으로 보고 폐기 — 관대
파싱 금지의 §3-4 원칙과 같은 방향)

```
[Important] 11_spec_B §4-7 — B의 설계는 verdict_mode=conditional 을 전제하는데, 계약 #2의
승인된 기본값은 clause_only 이고 전환은 총괄 승인 사항이다. 아무도 그 전환을 요청하지 않았다.
```

**실측 [3]:** 계약 #2 스냅샷 2벌 모두 `verdict_mode: clause_only`,
`thickness_source = scale_source = 'none'`.

B §4-7의 enum은 `{metadata, assumed}` **2값**이라 실측값 `none`을 표현할 수 없다. 그리고
§4-4는 "verdict는 enum {합격, 불합격} 2종 외 금지"이므로 **합부를 산출하지 않는 상태 자체가
표현 불능**이다. 그런데 `clause_only`의 정의(`10_spec_A` §4-2)가 바로 "합부 미산출, 조항 검색 +
기준 서술까지"다.

**실패 시나리오** — 8/25 `probe_metadata.py`가 두께·스케일 부재를 확정한다. 계약 #2의
`data_capabilities.yaml`은 승인된 안전 기본값대로 `clause_only`를 유지한다. B는 §4-7대로
`configs`의 가정값 t=12mm·`d4_quality_level=iso5817:C`로 **조건부 합부를 46,000건 생성**한다.
D는 전역 플래그가 `clause_only`이므로 판정 정합성을 `N/A`로 채점한다. 결과: 학습 데이터에는
합부 라벨이 46,000건 들어가 있는데 채점은 그것을 재지 않고, 논문은 "판정 과업을 조항 검색과
기준 서술로 좁혔다"고 쓴다. **학습 신호와 평가 서술이 어긋난다.** 이건 과잉 주장 금지 #8
(스케일 미확인 상태에서 합부를 조건부 아닌 것처럼 서술)의 뒷문이다.

정리하면 B의 선택(가정값 명시 채택)은 `10_spec_A` §4-2의 `conditional` 정의와 **정확히 일치**
한다. 틀린 건 설계가 아니라 **누가 그 전환을 승인하는지**다.

근거: `10_spec_A` §4-2 (verdict_mode 3단계, 전환은 총괄 승인) / `11_spec_B` §4-4·§4-7 /
검토 열린질문 Q2 기본값 `clause_only` / 실측 §5-[3]
제안: ① B가 **`verdict_mode=conditional` 채택을 §11 게이트 안건에 명시 등재**한다(현재 §11에
없다) ② `thickness_source`/`scale_source`/`quality_source` enum에 `none`을 추가하고,
널러빌리티 매트릭스에 4번째 행(`clause_only`: verdict·margin·limit_value 전부 null, 수치 잠금
필수 출현 = size·t·clause_id)을 넣어 두 모드가 같은 스키마로 표현되게 한다
③ 승인 전 기본 동작은 `clause_only`
