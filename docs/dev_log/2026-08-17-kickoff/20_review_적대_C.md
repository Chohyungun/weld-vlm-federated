  `16gb.yaml`에만 낮춰 기록 → 이후 유료 전환으로 일부 통합형 run이 48GB 원값으로 실행 →

### [Important] 12_spec_C:§1-3·§2-5 — Flower `accept_failures=True` 기본값: 부분 실패 라운드가 학습량 등가를 조용히 깬다

- **요약**: Flower FedAvg는 기본적으로 클라이언트 실패를 허용(`accept_failures=True`)하고
  나머지 클라이언트만으로 집계를 진행한다. 스펙은 서버 재시작 복구는 다뤘지만 **한 라운드
  안의 부분 실패** 처리를 명시하지 않았고, §2-5 사후 확인 4번("각 라운드 로컬 epoch == E,
  서버 로그로 확인")은 실패 클라이언트가 로그에 아예 없는 경우를 잡는다는 보장이 문면에
  없다. C가 `final_eval()`에서 잡아낸 것과 같은 종류의 "선언과 어긋나는 프레임워크 기본
  동작"이다.
- **실패 시나리오**: 라운드 30에서 C3의 fit이 일시적 OOM으로 실패 → 기본값에 따라 C1·C2만
  집계된 채 라운드 성립 → R=50 완주 → C3의 실제 총 노출 98 epoch ≠ N=100, 해당 라운드
  가중치에서 C3 누락 → R×E=N 공정성 주장과 RQ3(C3 편익) 해석이 동시에 오염되는데 지표
  어디에도 드러나지 않는다.
- **근거**: docs/개발규약.md 모델·실험 정책 1(학습량 등가) / Flower FedAvg 기본 파라미터
  (accept_failures=True, min_fit_clients=2 — 구현 시 소스 재확인 요) / 리뷰 배분 시 지정된
  점검 항목("프레임워크 기본 동작에 같은 종류의 조기 종료류가 숨어 있지 않은지")
  "다른 프레임워크에도 같은 종류의 기본 동작이 숨어 있지 않은지"
- **제안**: ① `accept_failures=False`, `min_fit_clients=min_available_clients=3` 명시 고정
  (검출·VLM 양쪽 전략) ② budget_audit에 **클라이언트×라운드 회계 매트릭스**(R×3 전 셀
  epochs_ran==E, 빈 셀 = run 무효)를 추가해 부재 자체를 실패로 정의한다. VLM 쪽도 동일
  (R×3 전 셀 steps_ran==S_k).

### [Important] 12_spec_C:§3 가정 1·6 — 게이트 #4가 확정한 계약 #2(2파일 + 로더 단일 조인)를 스펙이 아직 반영하지 않음

- **요약**: 가정 1은 "manifest.csv 단일 long format"인데, 게이트 #4는 계약 #2를
  `manifest.csv + annotations.csv` 2파일로 승인하면서 "**조인은 A가 제공하는 로더 함수로만**"
  을 조건으로 걸었다. C의 `dataset_view.py`가 가정 1대로 자체 파싱·조인을 구현하면 이 조건
  위반이다. (스펙이 게이트 #4 이전에 작성된 시차 문제 — 잘못이 아니라 미갱신이다.)
- **실패 시나리오**: C가 annotations를 자체 조인해 data.yaml을 조립 → 이후 A가 로더의 조인
  의미론(예: 정상 이미지 0행 처리, 중복 묶음 필터)을 바꿈 → C와 D의 데이터 뷰가 조용히
  갈라져 "단일 진실" 원칙이 깨진다.
- **근거**: 게이트 기록 게이트 #4 총괄 결정 Q1 조건 2 / docs/개발규약.md 데이터 규칙 2
- **제안**: §3 가정 1·6을 "계약 #2 소비는 A의 로더 API 경유 단일 경로"로 갱신하고,
  `dataset_view.py` 명세에 '자체 조인 금지' 한 줄을 박아라. A의 mock 스냅샷 2벌로 즉시
  맞춰볼 수 있다.

## Minor

1. **[Minor] VLM 라운드당 스텝 공식이 두 문서에서 다르다** — 12_spec Q6은
   `floor(0.5 × ceil(n_i/유효배치))`, 12a 함정#3 §4는 `round(0.5 · n_k / B_eff)`. 값은 거의
   같지만 이 수식이 곧 R×E=N의 정의이므로 한 식으로 통일하고 §2-5 #5 감사도 같은 식을
   쓰게 한다(다르면 감사가 헛돈다).
2. **[Minor] "비트 단위로 동일" 표현** — V2의 실제 합격 기준은 "허용 오차 1e-12"다. 검증
   통과 전 단정이며 기준과 표현이 다르다. "V2 통과 조건으로 epoch 단위 완전 일치"로 완화
   권장. 논문 문장 초안의 "(구현 검증: 100개 값 완전 일치)"도 통과 후 삽입 조건부로.
3. **[Minor] EMA 비활성의 기준선 해석 미반영** — EMA-off는 통상 절대 성능을 소폭 낮춘다.
   구현설계 §9의 "분리·중앙 Macro-F1 0.85 미달 시 라벨·분할 오류 먼저 점검" 기준선을 쓸 때
   EMA-off 효과를 각주로 명시하지 않으면 미달 원인 탐색이 헛돈다. (E가 논문 기준선 절에
   반영할 사항이기도 하다 — E 소관으로 가져간다.)
