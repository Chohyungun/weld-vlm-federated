# 재현 검토: 학습·연합

작성 2026-08-17 · 대상 `12_spec_C_학습연합.md`, `12a_함정구간_판정_C.md`
구현 코드가 아직 없어 문서 검토로 수행한다.
전제: 좌표 규약은 학습 쪽 안으로 확정됐고, 계약 4종은 동결 상태다.

**요약: Critical 0 / Important 2 / Minor 3.** 접점 조정 5건.

핵심 질문은 좌표 규약이 확정안과 일치하게 서술됐는가였고, 답은 그렇다. 서술이
확정문과 문면·취지 모두에서 일치한다(§1). Important 2건은 계약 #4 동결본과 학습 쪽이
가정한 필드 목록의 어긋남, 그리고 평가셋 격리 충돌 지적이 옳아서 채점 명세를 고쳐야 하는
건이다. 후자는 학습 쪽의 결함이 아니라 공적이다.

소유자로 재배치했고(커밋 `7bb24f4`), 계약 #4에서 네이티브 좌표 필드를 제거했다.
**이로써 웨이브 #5 §5-3의 계약 #4 동결 조건이 충족된다.**

### 1-1. 채택안이 원안보다 나은 지점

검토자 편향을 밝히기 위해 적는다. 아래는 채점 쪽 원안보다 학습 쪽 안이 나은 부분이다.

- **999 분모 오용의 판별 경로.** `12a`가 "999는 IoU argmax로 1000과 판별 불가능(0.1% 차이)
  이므로 카나리아가 아니라 **우측·하단 경계 근접 골든 픽스처**로만 잡힌다"고 분리했다.
  D의 원안에는 이 구분이 없었고, D의 분포검사(D1)로도 1~2px 계통 편향은 잡히지 않는다.
- **음성 픽스처.** "xywh로 오해석한 값이 불일치임을 assert"하는 픽스처는 왕복 테스트가
  대수적으로 닫혀 있어 못 잡는 구멍(D 스펙 §3-3 실패경로 #11이 지적한 바로 그 구멍)을
  정면으로 막는다.
- **F3(정변환·역변환이 같은 방향으로 함께 틀림)** 을 식별하고 손계산 골든 픽스처를 처방한
  것. 왕복 테스트만으로는 절대 안 잡히는 실패다.

## 2. Important

```
[Important] 12a §6·§9 ↔ 동결된 계약 #4. C가 예측 스키마에 허용된다고 가정한 메타 필드
4종 중 2종(resized_wh, transformers_version)이 동결본에 없고, additionalProperties:false라
조용히 무시되지 않고 레코드가 통째로 거부된다.
```

**근거.**
- `12a` §6(A·D 트랙 인터페이스 가정): "**D(공통 예측 스키마):** `bbox_px` nullable,
  메타 필드(**convention, resized_wh, coord_cfg_hash, transformers_version**) 허용".
- 동결된 계약 #4(`13_spec_D` §2-1)의 좌표 메타는 **`convention`, `coord_cfg_hash` 2종뿐**이다.
  게이트 §5-3도 이 둘만 명시했다.
- 스키마는 `"additionalProperties": false`다(§2-2에 이유가 적혀 있다. 오타 필드가 조용히
  무시되면 "채웠다고 믿었는데 안 채워진" 사고가 난다).
- `12_spec_C` 가정 9의 추가 요청 3종 중 `cell`·`seed`는 이미 스키마에 있고, `raw_text`는
  `raw_output_ref`(파일:줄번호 포인터)로 대응된다. **이 3종은 충돌하지 않는다.**
  충돌하는 것은 `resized_wh`와 `transformers_version` 둘이다.

**실패 시나리오.** W5~6에 통합·중앙 추론을 완주하고 12,600줄 예측 jsonl을 낸다.
각 레코드에 `resized_wh`, `transformers_version`이 들어 있다. D의 어댑터가 pydantic 검증에서
`additionalProperties` 위반으로 **전 레코드를 `parse_ok=false` 처리**하거나(설계대로면
`schema_violation`), 파일 단위로 즉시 실패한다. 통합형 파싱 실패율이 100%로 찍히고,
결과표의 통합형 행이 전부 오답이 된다. 원인이 모델이 아니라 필드 2개라는 걸 알아내기까지
양쪽이 서로의 로그를 대조해야 하고, 그 시점은 9/16 직후로 일정 여유가 가장 없는 구간이다. 재추론이 필요하지는 않다(어댑터만 고치면 같은 원시 출력으로 다시 조립된다).
그래서 Critical이 아니라 Important다.

**처방(확인 필요).**
1. **`resized_wh`와 `transformers_version`을 예측 스키마에 넣지 않는다.** 이 둘은 §5-1
   판정이 경계를 넘지 않도록 한 바로 그 변환 파라미터다. 넣으면 판정의 취지가 무너지고,
   D가 그 값으로 뭔가를 재계산하고 싶은 유혹이 생긴다(D 스펙 §3-3 실패경로 #3이 금지한 것).
2. 두 값은 **C의 원시 추론 로그**(`outputs/{cell}/{seed}/generations.jsonl`)에 남긴다.
   감사·디버깅에는 그쪽이 맞고, 채점 경로에는 필요 없다.
3. 재현성 추적은 `coord_cfg_hash`가 담당한다. `transformers_version`이 바뀌면 리사이즈
   치수가 바뀌고 `CoordCfg`가 그 버전을 포함하도록 하면 해시가 갈린다. **요청 사항:
   `CoordCfg`에 라이브러리 버전을 포함시켜 해시가 버전 드리프트를 감지하게 할 것.**
   그러면 필드 2개 없이도 D 스펙 §3-3 실패경로 #12(D4 페어 ↔ 학습 시점 버전 드리프트)를
   막을 수 있다.

```
[Important] 12a §(학습 중 평가 제거). C의 지적이 옳고, 그 결과 D 스펙 §8-3
"라운드 r의 글로벌 모델을 글로벌 평가셋으로 채점해 step=r로 로깅"이 격리 원칙과 충돌한다.
```

**근거.** `12a`: "글로벌 평가셋은 학습 중 어떤 코드 경로에서도 접근 금지. 라운드 모니터링은
클라이언트 보고 train loss 집계 + norm 곡선만. 라운드별 지표 곡선은 학습 완주 **후** 보존된
라운드 체크포인트를 D 트랙 채점기가 사후 평가해 생성. 구현설계 7-4의 '글로벌 평가셋 val
지표를 서버 evaluate 콜백에서' 문구는 격리 원칙과 충돌 — 정정을 게이트 안건으로 상정."

D의 `13_spec_D` §8-3은 구현설계 7-4를 그대로 승계해 같은 문제를 갖고 있다.

**실패 시나리오.** 라운드마다 글로벌 평가셋 지표가 콘솔과 MLflow에 찍힌다. 어느 시점에
누군가(사람이든 스크립트든) "라운드 37에서 F1이 꺾였으니 거기서 끊자"고 판단한다. 이는
**평가셋 기준 조기 종료**이며, `docs/개발규약.md`의 불변조건 3-1(조기 종료 금지)과 3-2(best 아닌 last)를
정면으로 어긴다. 실제로 끊지 않더라도, 심사에서 "학습 중에 평가셋 지표를 봤는가"에
**봤다**고 답해야 하고, 그 순간 R×E=N 학습량 등가라는 공정성 주장의 방어선이 약해진다.
논문 주장(①)에 걸리므로 Critical 후보였으나, **아직 아무것도 돌리지 않았고 문서 정정만으로
해소되며 재실험이 불필요**하므로 Important로 둔다. 학습 착수 전에 반드시 닫아야 한다.

**처방(채점 명세를 고친다).**
1. D 스펙 §8-3을 정정한다. 라운드별 서버 사이드 평가를 **val split으로 한정**하고,
   글로벌 평가셋 채점은 **학습 완주 후 사후 1회**로 옮긴다.
2. 라운드별 곡선은 C가 보존한 마일스톤 라운드 체크포인트(25/50/75/100%)를 D 채점기가
   사후 평가해 생성한다. 그림 품질은 점 4개로 충분하다. 곡선이 목적이 아니라 추세가
   목적이다.
3. §1의 평가 자산 격리 자동 검사에 **"학습 러너 프로세스가 `split=='eval'` 행을 로드한
   적이 있는가"** 를 추가한다. 지금은 학습 데이터 소비 ID만 검사하는데, 평가 콜백 경로는
   그 검사를 우회한다.
4. C의 Q7("서버 저장 글로벌 raw state_dict를 D가 로드하는 규약")에 **D가 답한다**: 예.
   `sep_fed_global_r{r}_s{seed}.pt` + config + 해시 동반 규약을 수용하고, D 스펙 §8-5
   체크포인트 규칙의 FL 항목과 일치시킨다.

> 이 항목은 지적이 맞고 채점 명세 쪽이 틀린 경우다. 구현설계 7-4 문구 정정이 함께 필요하다.

## 3. Minor

```
[Minor] 12a §6(골든 픽스처 6종). D 스펙 §3-3(d)가 요구하는 케이스 2종이 목록에 없다.
```

**근거.** C의 6종은 NORM_1000 기본 / 우측·하단 경계 근접 / ABS_RESIZED / 극단 종횡비 /
음성 픽스처 / max_pixels 초과다. D 스펙 §3-3 (d)가 요구한 것 중 **1px·5px 초소형 박스**와
**28 비배수 원본(예: 1234×707)** 이 빠져 있다.

**실패 시나리오.** 슬래그혼입은 실데이터에서 수~수십 px 크기다(강재 1,140장, 최소 클래스).
정수 반올림이 한 번 더 들어가면 초소형 박스에서만 IoU가 떨어지고, **클래스별 지표에서
슬래그만 낮게 나온다.** Macro-F1을 주 지표로 쓰는 설계라 최소 클래스의 왜곡이 헤드라인에
직접 반영된다. 28 비배수 원본은 축별 배율이 미세하게 달라지는 경로로, 정방형·표준 크기
픽스처만으로는 축 스왑이 잠복한다. 어느 쪽도 재실험을 강제하지 않고 픽스처 2종 추가로
끝나므로 Minor.

**처방.** 채점 쪽이 두 케이스를 작성해 되돌린다. 손계산
기대값은 채점 쪽이 만들고 학습 쪽이 검수한다. 생성자와 검증자를 분리하는 원칙이다.

```
[Minor] 12_spec_C 가정 11. 분리형 검출→판정부 인터페이스의 conf 임계가 "5칸 공통 고정"
이라고만 되어 있고 값이 없다. D 스펙 §4-4가 별도로 0.25를 쓰고 있어 같은 손잡이인지 불명확.
```

**근거.** C 가정 11: "conf 임계는 §6 Q4 — 5칸 공통 고정". D 스펙 §4-4: 두 구조를 같은
조건에 놓는 보조 대칭 지표로 "분리형 예측을 conf≥0.25로 자른 뒤의 P/R/F1@IoU0.5".

**실패 시나리오.** C가 판정부 입력용 임계를 0.5로 고정하고 D가 채점용으로 0.25를 쓰면,
**판정부가 본 결함 집합과 채점기가 센 결함 집합이 다르다.** 조항 검색 정확도(§4-8)는
"검출 결과가 맞다는 전제"에서만 의미가 있는데 그 전제의 검출 결과가 두 개가 된다.
결과가 이상해도 원인을 특정하기 어렵다. 값 하나를 configs로 합치면 끝나므로 Minor.

**처방.** `configs/base.yaml`에 `detection.conf_threshold` 단일 키를 두고 C의 판정부 입력과
D의 보조 지표가 **같은 키를 읽는다.** 값 확정은 파일럿 후. D의 주 지표(mAP)는 임계와
무관하므로 이 결정에 종속되지 않는다.

```
[Minor] 12_spec_C 가정 7. FedAvg 가중 n_k를 "클라이언트별 D4 학습 페어 수"로 정의했는데,
분리형(검출) 칸의 n_k는 무엇인지 같은 자리에서 확인되지 않는다.
```

**근거.** 가정 7은 통합형 문맥에서 서술됐고, `12_spec_C` §3에는 "FedAvg 가중은 클라이언트
표본 수 (C1:C2:C3 ≈ 32k:16k:8k)"가 따로 있다. 두 서술이 다른 절에 있어 분리형 검출 칸의
n_k가 **이미지 수인지 결함 인스턴스 수인지**가 한 곳에서 확정되지 않는다.

**실패 시나리오.** 정상 이미지가 44%인 데이터에서 이미지 수 가중과 결함 인스턴스 수 가중은
클라이언트 비율이 눈에 띄게 갈린다. D가 통신량·회복률을 보고할 때 논문에 적을 가중치
숫자를 C의 로그에서 읽어야 하는데, 정의가 두 개면 표에 적는 숫자의 출처가 흔들린다.
논문에 R·E·N과 함께 명시해야 하는 값이므로 확정이 필요하지만, 재실험 사유는 아니다.

**처방.** C 스펙에 한 줄. "분리형 n_k = 클라이언트 학습 이미지 수, 통합형 n_k = 클라이언트
D4 페어 수"처럼 칸별로 명시하고, D가 MLflow params에 `fedavg_weights`로 로깅한다.

## 4. 통과 확인: 지적하지 않은 것들

- **조기 종료 3중 차단**: Ultralytics `final_eval()`의 `best.pt` 로드를 no-op으로 무력화,
  `load_best_model_at_end=False`, EarlyStoppingCallback 미장착, 학습 로그 grep 검증.
  **선언이 아니라 프레임워크 기본 동작을 실제로 건드렸다.** D의 채점기가 파일명에 `best`가
  들어오면 실패시키는 방어와 층이 맞물린다.
- **EMA 발견**: `last.pt`/`best.pt` 가중치가 EMA라는 확인은 연합 집계 대상의 정의에
  직결된다. 총괄이 C에 별도 확인 요청을 걸어 둔 상태이며, D는 결론이 나오면 MLflow
  params에 `fedavg_target: raw|ema`로 로깅해 논문 표에 반영하겠다. **D 쪽 조치 대기 중.**
- **`target_modules="all-linear"` 금지**: 명시 목록 + `named_modules()` 전수 덤프 검증.
  비전 모듈 제외가 통신량 주장의 근거이므로 D의 §4-13(통신량) 산출과 직결된다.
- **집계 오차 실측의 부록 1단 승격**: "E=0.5라 오차가 작다"는 선험 논거를 기각하고 실측
  하기로 한 판단이 옳다. `avg(B)·avg(A) ≠ avg(B·A)`는 심사에서 반드시 나오는 지적이다.
- **`bbox_px` nullable에서 0으로 채우지 않기**: "0으로 채우면 회복률 헤드라인이 오염된다"는
  `12a`의 서술은 D 스펙 §3-5(N/A는 GT가 결정, 오답은 예측이 결정)와 정확히 같은 결론이다.
  양쪽이 독립적으로 같은 결론에 도달했다.
- **VLM 라운드별 서버 평가 없음**: loss·norm만 남기고 곡선은 마일스톤 어댑터로 사후
  산출. §2 Important-2의 처방과 이미 정합한다.
