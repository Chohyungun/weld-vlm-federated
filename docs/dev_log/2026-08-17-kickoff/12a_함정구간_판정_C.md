# 함정 #1

## 채택 결론

함정 #1의 기본안으로 관점 B(DetectionTrainer 서브클래스 + stock resume 경로 재활용)를 채택한다. 근거: (1) warmup·LR 스케줄·close_mosaic이 모두 전역 epoch 변수의 순수 함수임을 소스로 확인했고(scheduler.step은 epoch 시작부, ni=i+nb*epoch, lf(epoch)), `start_epoch=r×E` + `scheduler.last_epoch=start_epoch−1` 오프셋만으로 중앙 칸과 학습률 궤적이 비트 단위로 동일해진다 — A안은 이를 warmup 제거(레시피 변경)와 구간별 선형 근사(중앙=cosine vs 연합=근사라는 구조 내 비대칭)로 우회하는데, 래퍼의 한계 때문에 세 칸 공통 레시피를 바꾸는 것은 본말전도다. (2) 로컬·중앙 칸을 R=1 퇴화 케이스로 같은 train_round를 통과시켜 루프 동일성이 문자 그대로 성립한다. (3) A의 "공개 API만 사용" 주장은 과장 — 주입이 `not resume and self.ckpt and pretrained is not False` 조건에 걸려 조용히 무력화될 수 있고, train() 종료 후 best/last 재로드·EMA 체크포인트 의미론 등 내부 거동에 똑같이 의존한다. B의 내부 접촉점 6곳은 정확 버전 핀(ultralytics==8.4.120) + 계약 테스트 + 행동 등가 테스트(V1~V3)로 방어하며, 진짜 방어선은 핀이 아니라 행동 테스트다. (4) B의 검증은 "LR 100개 값 완전 일치"라는 이진 판정이 가능해 등가성 증명력이 압도적이다. EMA는 검출 3칸 공통 비활성·raw 가중치 교환/집계/채점으로 확정하고, LR은 전역 cosine(N=100) 단일 스케줄을 resume 오프셋으로 이어받는 것으로 확정한다. A의 안전장치(정본 키 sha256, 주입 증빙 로깅, 3중 조기종료 사후 증명, 파생 시드, 스모크 매트릭스)는 전부 흡수한다.


## 2. FedDetectionTrainer — 내부 접촉점 6곳 (이것이 전부이며, 추가 금지)

1. **`_setup_train()` 오버라이드**: `super()._setup_train()` 호출 **후** 순서대로 —
   (a) `weights_in`(정본 키 순서 ndarray 리스트)을 `self.model.load_state_dict(strict=True)` 주입. BN `running_mean/var/num_batches_tracked` 포함.
   (b) 주입 증빙: 대표 텐서 3~5개의 L2 norm 다이제스트를 계산해 RoundResult에 기록 (서버가 보낸 값과 라운드마다 대조).
   (c) `self.start_epoch = round_idx * E` 설정.
   (d) `self.scheduler.last_epoch = self.start_epoch - 1` 재설정 (stock resume과 동일 지점·동일 방식 — super() 안에서 이미 start_epoch=0 기준으로 설정됐으므로 반드시 재설정).
   (e) mosaic 종료 재적용: `if self.start_epoch >= self.epochs - self.args.close_mosaic: self._close_dataloader_mosaic()` — stock의 등호 비교(`epoch == epochs - close_mosaic`)는 라운드 재진입 시 트리거를 지나침 (소스 확인).
   (f) `self.ema.enabled = False` (ModelEMA의 update/update_attr에 enabled 가드 실존 확인).
   (g) `self.stopper`를 스텁으로 교체: `__call__`은 항상 False 반환 + 호출 이력(epoch, fitness) 기록, **`possible_stop=False` 속성 필수** (검증 게이트 조건식 `self.args.val or final_epoch or self.stopper.possible_stop or self.stop`에서 참조됨 — 소스 확인).
2. **`validate()` 오버라이드 → no-op** (`({}, None)` 상당 반환): val=False여도 전역 epoch 99에서 `final_epoch=True`가 검증 게이트를 열어 stock validate()가 발화함을 소스로 확인 — 클라이언트 검증 자체를 차단.
3. **`final_eval()` 오버라이드 → no-op**: stock은 best.pt를 로드·검증 — best 경로 자체를 제거.
4. **`save_model()` 오버라이드 → no-op**: stock 체크포인트는 `"model": None` + EMA만 저장 — EMA off 상태에서 stock last.pt는 초기 가중치 사본이 되는 재앙 차단. 저장은 래퍼·서버 소유.

콜백은 **인스턴스 로컬로만** 등록한다 (`ultralytics.utils.callbacks.default_callbacks` 전역 dict 수정 금지 — 라운드 간 콜백 누적 방지).

## 3. train_round — 3칸 공통 유일 진입점

```
train_round(weights_in: list[np.ndarray], round_idx: int, E: int,
            base_seed: int, client_idx: int, data_yaml: str, cfg) -> RoundResult
```

- **무상태**: 호출마다 FedDetectionTrainer 인스턴스를 새로 만든다 (Flower ClientApp이 ephemeral임을 공식 문서로 확인 — 상태를 액터 수명에 걸지 않는다).
- override 인자 고정: `epochs=100`(전역 N — E가 아님), `patience=10000`(# 조기 종료 금지 — R×E=N 학습량 등가, docs/개발규약.md 모델정책 1), `save=False`, `val=False`, `plots=False`, `optimizer='SGD'`, `lr0=0.01`, `lrf=0.01`, `momentum=0.937`, `cos_lr=True`, `warmup_epochs=3.0`(기본 유지 — 전역 epoch 0~2에서만 발화, 라운드 0·1에 걸쳐 소진), `deterministic=True`, `batch=32`, `imgsz=640`, `seed = base_seed + 10007*round_idx + 101*client_idx`(파생 공식·base_seed 3세트를 configs에 기재 — 고정 시드면 50라운드가 같은 셔플을 반복하는 숨은 비대칭이 생김: init_seeds가 트레이너 init마다 호출됨을 소스 확인), `close_mosaic=10`, 증강 설정은 데이터 담당 확정값 상속.
- **예산 정지**: `on_fit_epoch_end` 콜백에서 `if trainer.epoch + 1 - trainer.start_epoch >= E: trainer.stop = True`. `if self.stop: break`가 이 콜백 직후에 위치함을 소스로 확인 — 즉시 종료된다. 조기 종료가 아니라 예산 도달 정지이며, 스텁 stopper 기록과 예산 콜백 발화 로그로 양자를 구분 가능하게 남긴다.
- 반환 RoundResult: `{ndarrays(정본 순서 fp32), num_examples, epochs_ran, optimizer_steps(콜백 카운터), epoch별 train_loss·lr 로그, stopper_log, key_digest, injection_digest, param_norm}`.
- **로컬·중앙 칸 = R=1 퇴화 케이스**: `train_round(초기 가중치, round_idx=0, E=100)`을 1회 호출. 시작 가중치는 서버(또는 train_cell.py)가 동결 출발 체크포인트에서 serialize.py로 직렬화한 동일 ndarray — 세 칸 모두 같은 주입 경로·같은 다이제스트를 로깅해 "동일 출발 증명"(구현설계 10-2)을 코드로 강제한다.

## 4. serialize.py — 교환 규약

- 실험 시작 시 출발 체크포인트에서 **정본 키 리스트**를 1회 추출·고정, 키 연결 문자열의 sha256을 configs에 기록. 매 라운드 클라이언트·서버 양쪽에서 `list(sd.keys()) == canonical_keys` assert + 텐서별 shape/dtype 대조.
- 와이어 포맷 **fp32** (집계 정밀도 보존 — fp16 왕복은 집계 드리프트 원인. 통신량 표는 fp32 실측 바이트로 채우고 fp16 배포 최적화는 각주).
- `num_batches_tracked`(int64): 교환에는 포함(strict=True 로드 완결성), **집계는 가중 평균 금지 — 클라이언트 간 최대값 통과(pass-through)**. BN momentum≠None이라 이 값은 연산에 미사용임을 주석으로 명시.
- BN `running_mean/var`(float)는 **가중 평균에 포함** (FedBN 불가 — 글로벌 모델 1개를 글로벌 평가셋으로 채점. 세부는 함정 #2에서 다룬다).

## 5. 스케줄 정합성 (이 설계의 존재 이유)

- LR: `lf = one_cycle(1, lrf, epochs=100)` (cos_lr=True, 소스 확인). scheduler.step()이 epoch 시작부 호출 + `last_epoch = r×E − 1` 재개 → 라운드 r 로컬 epoch j의 lr = `lr0·lf(r×E+j)` — 중앙 칸의 전역 epoch r×E+j와 **완전 동일** (off-by-one 없음, V2로 이진 검증).
- warmup: `ni = i + nb*epoch`의 epoch이 전역값이므로 start_epoch ≥ 3 이후 라운드에서는 자동 미발화. 라운드 0·1에서 중앙과 같은 3 epoch warmup이 재현된다. 단 nw는 클라이언트 로컬 배치 수 기준이라 iteration 수는 데이터 규모에 비례해 다름 — 표본 노출 등가(R×E=N) 정의에 부합하며 논문에 한 줄 명시.
- close_mosaic: 전역 epoch ≥ 90(라운드 45~) 진입 시 2-(e)로 강제 재적용.

## 6. EMA·채점 대상 (확정)

**검출 3칸 전부 EMA 비활성. raw fp32 가중치를 교환·집계·채점한다.** stock last.pt(=EMA 가중치, `"model": None` 저장 소스 확인)는 어느 칸에서도 생성·사용하지 않는다. "last 채점" 조항의 구현 = 래퍼/서버가 저장한 **최종 epoch/최종 라운드 raw state_dict** (선택 절차 전무 — last 원칙의 정신 충족). 연합 라운드마다 리셋되는 EMA(2ep×50회)와 중앙의 100ep EMA는 평활 지평이 구조적으로 달라 등가가 깨지므로, 비활성이 유일한 대칭 해법이다. EMA on/off 자체는 세 칸 공통이므로 5칸 고정 조항 유지.

## 7. 조기 종료 3중 방어 + 사후 회계 (budget_audit.py)

1. `patience=10000` (docs/개발규약.md 지시 "epoch 수 이상" 준수. `patience or float("inf")`로 patience=0도 비활성임을 소스 확인했으나 falsy 관용구 회피 — configs 주석 필수).
2. stopper 스텁 (True 반환 구조적 불가 + 이력 기록).
3. 사후 assert: (a) 라운드별 epochs_ran == E, 총합 == N=100 (중앙·로컬은 100). (b) stopper_log에 True 반환 0건. (c) `self.stop=True` 발생 시점 전부가 예산 콜백 발화 기록과 일치. (d) optimizer_steps 총합을 R·E·N과 함께 논문 표에 실측 기재. 전부 통과 시 MLflow `no_early_stop_verified=1` — 채점 스크립트는 이 플래그 없으면 채점 거부.

## 8. Flower 접합

- ClientApp `fit`: manifest(데이터 담당 소유 — `client`, `split`, 이미지 경로 컬럼 가정)에서 파생한 클라이언트 data.yaml로 train_round 호출. data.yaml 조립 시 `split != 'eval'` assert (평가셋 유입 = 논문 철회 사유). `num_examples` = manifest의 클라이언트 train 행 수. 가중치는 이 값에 비례한다.
- ServerApp: FedAvg(num_examples 가중), run-config에 R=50·E=2·batch. 집계 직전·직후 파라미터 L2 norm + 직렬화 바이트를 라운드마다 로깅(MLflow 로컬, round=step). 서버 모듈은 데이터 로딩 코드를 import하지 않는다 — 서버가 받는 것은 ndarray + num_examples + 스칼라뿐 (비반출 서사).
- 자원: `client-resources-num-gpus=1.0` — 검출도 **순차 실행**. Ray 자원 배정이 비강제(초과 사용 시 타 인스턴스 OOM 크래시)임을 공식 문서로 확인. 병렬(0.33)은 VRAM 실측 후 파일럿에서만 시험.
- 체크포인트: 서버가 매 라운드 글로벌 raw state_dict 저장 (`sep_fed_global_r{r}_s{seed}.pt` + config + git hash + manifest sha256). YOLO11s fp32 ≈ 38MB × 50 ≈ 1.9GB — 곡선 생성 완료까지 전 라운드 보존 후 마일스톤(25/50/75%·최종) 외 삭제.
- **학습 중 평가 전면 제거**: 글로벌 평가셋은 학습 중 어떤 코드 경로에서도 접근 금지. 라운드 모니터링은 클라이언트 보고 train loss 집계 + norm 곡선만. 라운드별 지표 곡선은 학습 완주 **후** 보존된 라운드 체크포인트를 평가 담당 채점기가 사후 평가해 생성 (기본 val split, 평가셋 곡선은 게이트 승인 시에만). 구현설계 7-4의 "글로벌 평가셋 val 지표를 서버 evaluate 콜백에서" 문구는 격리 원칙과 충돌 — 정정을 게이트 안건으로 상정.

## 9. 버전 정책

`ultralytics==8.4.120` 정확 핀. 계약 테스트(V9)가 내부 접촉점 6곳의 존재·시그니처를 CI에서 검사하고, 버전 변경 시 V1~V3 행동 테스트 재실행 없이는 업그레이드 금지. flwr는 uv lock 시점 1.33.x 계열로 핀 (sm_120/cu128 Ray 호환은 데이터 담당 함정 #5와 교차 확인).

# 검증 방법 (구현 후)

| # | 테스트 | 방법 | 합격 기준 |
|---|---|---|---|
| V1 | **stock 등가성 (R=1)** | 래퍼 R=1×E=100 vs stock `model.train(epochs=100)` (EMA off·patience·저장 정책을 동일하게 맞춘 stock), 동일 시드, deterministic=True, 소표본 2,000장 | 초반 5 epoch 손실 곡선 오차 ≤ 1e-4, 최종 mAP@0.5 차이 < 0.005 |
| V2 | **LR 궤적 이진 판정 (핵심)** | R=50×E=2로 `on_train_epoch_start`에서 param group lr 로깅, stock 1×100의 lr 시퀀스와 대조 (warmup 3 epoch 구간 포함) | 100개 값 **완전 일치** (허용 오차 1e-12). 불일치 1개라도 있으면 off-by-one/오프셋 버그 |
| V3 | **라운드 경계 격리** | 단일 클라이언트 R=2×E=1 vs R=1×E=2 (집계=항등) | lr·mosaic 상태·epoch 카운트 정확 일치. 잔차는 momentum 리셋 + 파생 시드 효과뿐 — 이 차이가 논문에 명시할 라운드화 비용의 실측 하한 |
| V4 | **주입 왕복** | 임의 노이즈 state_dict 주입 → 최소 학습 → 수확값·주입값 텐서별 근접성 확인, 키 리스트 sha256 서버·클라이언트 대조 | 주입 경로 생존 증명, 다이제스트 일치 |
| V5 | **mosaic 종료** | 라운드 45+(전역 epoch ≥ 90) 진입 직후 dataloader mosaic off assert | 전 라운드 통과 |
| V6 | **조기 종료 부재 사후 회계** | budget_audit.py의 assert 4종 (epochs_ran 합계, stopper_log, stop 발생 시점 대조, optimizer_steps 총합) | 전부 통과 → MLflow `no_early_stop_verified=1`. 실패 시 채점 차단 |
| V7 | **직렬화 왕복** | state_dict → ndarray → state_dict, 텐서별 allclose + BN running_var 양수·유한 + num_batches_tracked dtype 보존 | 완전 일치 |
| V8 | **집계 안전장치** | 라운드별 직전/직후 norm 곡선 불연속·발산 부재, 직렬화 바이트 라운드 불변 | 로그 실존 + 이상치 경보 동작 |
| V9 | **버전 계약 테스트** | 핀 버전 import 후 `_setup_train/_do_train/save_model/final_eval/validate`, `self.lf/self.stopper/self.scheduler/self.start_epoch`, `ModelEMA.enabled` 존재·시그니처 검사 | CI 통과. 실패 = 버전 변경 금지 경보 |
| V10 | **스모크 매트릭스** | 1~2 epoch 초소형 실행으로 {val=False+validate no-op에서 전역 epoch 99 경로 무예외, patience=10000 수용, save=False 부작용, amp 캐파 체크의 외부 다운로드 여부, 콜백 누적 부재} 일괄 확인 | 구현 첫 산출물로 스크립트화 |
| V11 | **평가셋 격리 정적 검사** | 클라이언트 data.yaml 생성 코드에 split=='eval' 경로 유입 시 즉시 실패하는 assert + 생성된 yaml 전수 grep | 위반 0건 |
| V12 | **16GB 실측** | YOLO11s batch=32@640 + Ray 오버헤드 포함 `torch.cuda.max_memory_allocated` 실측 | 파일럿 항목. 초과 시 batch 축소가 아니라(5칸 고정 위반) 48GB 프로파일 이관 판단 |

## 실패 모드

- 주입 무력화: 주입 경로가 조용히 스킵되어 매 라운드 초기 가중치에서 학습 — 그럴듯한 지표로 완주됨 (방어: V4 왕복 + 라운드별 injection_digest 대조)
- stale-EMA last.pt 채점: EMA off 상태에서 stock save가 살아 있으면 last.pt가 초기 가중치 사본 — 랜덤 수준 지표 (방어: save=False + save_model no-op + 래퍼 체크포인트 단일화)
- close_mosaic 등호 비교 미발화: 연합 칸만 마지막 10 epoch에 mosaic 유지 → 증강 스케줄 비대칭 (방어: _setup_train 재적용 + V5)
- scheduler.last_epoch off-by-one: 전 구간 LR 1 epoch 어긋남 (방어: V2 완전 일치 판정)
- 로컬 epoch 번호로 루프: warmup 매 라운드 재발화(3ep×50회), LR 매 라운드 최고치 복귀 (방어: epochs=100 + start_epoch 설계 + V2)
- 조기 종료 몰래 발동: patience 기본값 복원·오타 (방어: 3중 방어 + budget_audit 채점 차단)
- 동일 시드 셔플 반복: init_seeds가 트레이너 init마다 재시드 → 고정 시드면 50라운드가 같은 2-epoch 셔플 반복 (방어: 파생 시드 공식)
- optimizer='auto'가 클라이언트별 데이터 규모에 따라 lr0·momentum 자동 재정 → 5칸 고정 8종 위반 (방어: SGD 명시 고정 + config 스냅샷 로깅)
- 글로벌 평가셋의 클라이언트 유입: data.yaml 조립 실수 — 논문 철회 사유 (방어: V11 정적 검사 + assert)
- 키 순서·dtype 불일치 집계: shape가 우연히 같은 텐서끼리 평균 — 에러 없이 성능만 붕괴 (방어: 정본 키 sha256 + 텐서별 shape/dtype 대조 + norm 로깅)
- num_batches_tracked int64 가중 평균: dtype 오류 또는 무의미 값 (방어: max pass-through 규칙 명문화)
- val=False에서 전역 epoch 99의 final_epoch 검증 발화: validate() 미차단 시 val 데이터 부재로 크래시 또는 의도치 않은 검증 (방어: validate no-op 오버라이드 + V10)
- 버전 드리프트: main 소스로 검증한 거동이 핀 릴리스와 다름 (방어: 8.4.120 정확 핀 + V9 계약 테스트 + 업그레이드 시 V1~V3 재실행 강제)
- Ray 병렬 시 VRAM 경합·라벨 캐시 경합: 자원 배정 비강제 확인됨 (방어: num_gpus=1.0 순차)
- 전역 default_callbacks 수정으로 라운드 간 콜백 누적: 예산 정지 중복 발화 (방어: 인스턴스 로컬 콜백만)
- amp 캐파 체크가 검증용 nano 가중치 자동 다운로드 시도: 재현 환경 비고정 외부 의존 (방어: 가중치 사전 배치 + V10 확인)

## 논문 명시 문장 초안

- 연합 라운드마다 옵티마이저 모멘텀 상태는 리셋된다. 이는 가중치만 교환하는 FedAvg의 표준 동작이며, 중앙집중과의 이 차이는 제거 대상이 아니라 측정 대상인 연합학습의 비용이다.
- 검출 3칸 모두 가중치 지수이동평균(EMA)을 비활성하고 원시 가중치를 채점했다. 프레임워크 기본 체크포인트는 EMA 가중치를 저장하지만, 연합에서는 라운드 경계마다 EMA가 재시작되어 중앙집중의 평활 지평과 구조적으로 달라지므로, 세 칸 대칭을 위해 공통 비활성했다.
- 학습률·워밍업·모자이크 증강 종료는 전역 epoch(N=100) 기준 단일 cosine 스케줄로 정의했고, 연합 칸은 각 라운드를 전역 epoch r×E에서 재개하는 방식으로 이어받아 세 칸의 학습률 궤적이 epoch 단위로 동일하다(구현 검증: 100개 값 완전 일치).
- 워밍업과 스케줄은 epoch 단위로 정의되므로 iteration 수는 클라이언트 데이터 규모에 비례해 다르다. 이는 표본 노출 횟수 등가(R×E=N)의 정의에 부합한다.
- BatchNorm running 통계는 가중치와 함께 표본 수 가중 평균에 포함했다. 글로벌 모델 1개를 글로벌 평가셋으로 채점하는 설계라 로컬 BN을 유지하는 FedBN은 적용할 수 없다.
- 조기 종료는 전 칸에서 비활성했으며, 라운드별 완료 epoch 수·총 optimizer step 실측치를 R·E·N과 함께 보고한다.
- 라운드별 학습 시드는 기본 시드에서 결정적으로 파생했다(공식은 설정 파일에 기재). 고정 시드를 재사용하면 매 라운드 동일한 데이터 순서가 반복되어 중앙집중과의 숨은 비대칭이 생긴다.
- 본 실험은 단일 GPU 위 시뮬레이션이며, 통신량은 직렬화된 교환 객체의 실측 바이트 × 라운드 수로 산출했다(fp32 기준).

## 열린 질문 (안전 기본값)

- **Q:** Q1. EMA 3칸 공통 비활성 + raw 가중치 채점 — 'last.pt 채점' 조항의 구현을 '래퍼가 저장한 최종 epoch raw state_dict'로 해석하는 것을 게이트에서 승인하는가?
  **기본값:** 비활성 + raw 채점으로 진행. stock last.pt는 어느 칸에서도 생성·사용하지 않음 (선택 절차 전무 — last 원칙의 정신 충족)
- **Q:** Q2. 구현설계 7-4의 '글로벌 평가셋 val 지표를 서버 evaluate 콜백에서 산출' 문구 — 평가 자산 격리 원칙과 충돌하므로 '학습 중 평가 전면 제거 + 완주 후 보존 체크포인트 사후 평가'로 문서 정정하는가?
  **기본값:** 학습 중 글로벌 평가셋 접근 0회. 라운드 모니터링은 클라이언트 train loss + norm만, 곡선은 사후에 val split으로 생성 (평가셋 곡선은 게이트 승인 시에만)
- **Q:** Q3. 라운드 곡선용 전 라운드 글로벌 체크포인트 임시 보존(~1.9GB) 후 마일스톤 외 삭제 — 디스크 정책 승인?
  **기본값:** 보존 후 곡선 생성 완료 시점에 마일스톤(25/50/75%·최종) 외 자동 삭제
- **Q:** Q4. 검출 클라이언트 순차 실행(num_gpus=1.0)의 벽시계 증가 수용 여부
  **기본값:** 수용. Ray 자원 배정 비강제 확인 — 병렬(0.33)은 VRAM 실측 후 파일럿에서만 시험
- **Q:** Q5. 교환 와이어 포맷 — fp32 유지 vs fp16 절감(실험설계 6-5는 fp16 언급)?
  **기본값:** fp32. fp16 왕복은 집계 정밀도 드리프트 원인. 통신량 표는 fp32 실측치, fp16 절반 가능성은 배포 최적화 각주로
- **Q:** Q6. 데이터 담당 manifest 인터페이스 가정 — 컬럼 client/split/이미지 경로 실존, per-client data.yaml 생성 책임은 학습 담당 소유로 가정. 게이트에서 계약 #2로 확정?
  **기본값:** 가정대로 진행. data.yaml 생성기는 fl/detection에 두고 split=='eval' 유입 시 즉시 실패
- **Q:** Q7. 평가 담당 채점기 인터페이스 — 서버 저장 글로벌 raw state_dict(`sep_fed_global_r{r}_s{seed}.pt` + config + 해시 동반)를 D가 로드하는 규약으로 확정?
  **기본값:** 가정대로 진행. 채점기는 no_early_stop_verified 플래그 부재 시 채점 거부
- **Q:** Q8. 파생 시드 공식 `seed = base_seed + 10007*round + 101*client_idx` 승인 (base_seed 3세트는 불변)?
  **기본값:** 이 공식으로 진행. configs에 공식·base_seed 기재

## 기각한 설계 요소

- A안 전체 구조(공개 API 반복 호출): '공개 API만 쓰므로 안전' 전제가 과장 — 주입이 `not resume and self.ckpt` 그리고 `pretrained is not False` 조건에 걸려 조용히 무력화 가능(소스 확인), train() 종료 후 best/last 재로드·수확 시점 내부 속성·EMA 체크포인트 의미론에 똑같이 의존. 버전 드리프트 노출은 B와 동급인데 의존이 암묵적이라 오히려 열등
- A의 warmup_epochs=0 공통 고정: 래퍼의 한계(E=2 호출에서 warmup 클립·재실행) 때문에 세 칸 공통 레시피를 바꾸는 본말전도. B의 전역 epoch 방식은 warmup 3.0을 그대로 보존하며 중앙과 정확히 일치
- A1(구간별 lr0/lrf 선형 근사): 중앙=cosine 단일 호출 vs 연합=50구간 선형 근사라는 구조 내 LR 메커니즘 비대칭 + 근사 오차. B는 비트 단위 동일이라 근사 자체가 불필요
- A2(콜백으로 scheduler 교체): resume 경로가 있으므로 불필요한 내부 조작. on_pretrain_routine_end 발화 시점도 미확인 상태였음
- A의 close_mosaic 라운드별 인자 에뮬레이션: A 스스로 발동 조건을 미확인 상태로 설계. 등호 비교임이 확인된 지금, B의 재적용 한 줄이 정확하고 단순
- A의 patience=0: `patience or float("inf")` 소스 확인으로 동작 자체는 사실이나, docs/개발규약.md 명문('epoch 수 이상으로 설정')과 어긋나고 falsy 관용구는 가독성·버전 변동 위험 — patience=10000 + 스텁 + 사후 회계 채택
- A의 num_batches_tracked 교환 제외: strict=True 로드 완결성을 깨뜨림 — 교환 포함 + max pass-through(B) 채택
- A의 raw_sd·ema_sd 동시 수확: EMA 비활성 확정으로 불필요
- A의 '집계는 raw, EMA는 켜둠' 절충: 사용하지 않는 EMA 연산 오버헤드 + stock 저장 경로에 살아 있는 오염 위험을 무이득으로 존치 — 전면 비활성 채택
- EMA 가중치 집계: 중앙 칸에 없는 서버측 평활을 주입하는 비표준 FedAvg 변형
- 칸 간 EMA 비대칭(중앙만 EMA, 연합만 raw): 비교 무효 — 즉시 기각
- 구현설계 7-4 원문대로 라운드마다 글로벌 평가셋 서버 평가: 평가 자산 격리 원칙과 충돌 소지 + 라운드마다 GPU 시간 소모. 사후 체크포인트 평가로 대체 (게이트 안건)
- B의 '서버 evaluate 콜백에서 val split 평가': 방향은 맞으나 학습 중 평가 자체를 제거하는 쪽이 더 단순·안전 — 정보 손실 없음(체크포인트 보존으로 사후 재현 가능)
- 검출 클라이언트 0.33 GPU 지분 병렬을 기본값으로: Ray 자원 배정 비강제 + OOM 경고 문서 확인 — 파일럿 시험 항목으로만 강등

# 함정 #2

## 채택 결론

기본안은 BN buffer(running_mean/running_var) 포함 전체 표본수 가중 FedAvg로 확정한다(Flower 표준 집계 경로 — 소스로 확인). 단 num_batches_tracked는 평균 대상에서 제외하고 서버가 클라이언트 값의 element-wise max로 결정론적으로 덮어쓴다. 메인 런은 관측 전용 진단 계측(누락 분산비 ρ, 클라이언트 간 buffer 거리, 재질별 서브셋 분해, 집계 전후 sanity)만 붙이고 어떤 신호도 런 중 동작을 바꾸지 않는다. 사전 등록 트리거(T1 회복률<80% / T2 AL 서브셋 선택적 격차 / T3 진단 곡선 임계) 발동 시에만 부록 실험을 가동하며, 부록은 (a) buffer-swap 절제(닫힌형 풀링 — '보정'이 아닌 원인 판별기로 재분류)와 (b) 클라이언트 협조 BN 재보정(각 클라이언트가 자기 train 분할로 forward-only 모멘트 수집 → 서버가 표본수 비례로 모멘트 결합)의 2단으로 구성한다. 구현설계.md 3-3의 "글로벌 평가셋의 train 부분으로 BN 재추정"은 평가 자산 격리(docs/개발규약.md 데이터 규칙 4) 위반으로 명시 기각하고 (b)로 교체를 정정을 제안한다. 설계안 B의 "균등 결합이 목적 정합" 주장은 사실 오류로 격추했다 — 층화 추출은 모집단 비율(강재:알루미늄 ≈ 6:1)을 보존하므로 평가 분포에 맞는 기본 가중은 표본수 비례(32:16:8)이고 균등은 부록 변형 행으로 강등한다. 주 결과표는 어떤 경우에도 보정 전 last.pt다.

# 함정 #2 확정 처방 — BatchNorm 연합 평균 (학습·연합 스펙 수록본)

적용 범위: **분리·연합(YOLO11s 전체 가중치 FedAvg) 1칸.** 통합·연합(Qwen 계열)은 RMSNorm 계열로 running 통계 buffer가 없어 무관 — 채택 시점에 `named_buffers()` 열거로 1회 확인해 로그로 남긴다(검증 V10).

## 1. 기본안 (메인 런) — BN 포함 전체 표본수 가중 평균

- Ultralytics는 모델 생성 시 전 BN에 `eps=1e-3, momentum=0.03`을 설정하며(출처 W-1), momentum/eps는 모듈 속성이라 사전학습 가중치 로드로 바뀌지 않는다(출처 W-2 — 종전 미확인 U-3 해소). momentum=0.03 EMA에서 주입된 buffer는 라운드당 로컬 스텝 500(C3)~2,000(C1)회 만에 완전 세척되므로((0.97)^500 ≈ 2×10⁻⁷), 서버가 매 라운드 받는 buffer는 사실상 순수 로컬 분포 통계다. 집계 buffer의 품질은 **오직 글로벌 모델 eval 채점 시의 문제**이고 학습 동역학과 무관하다 — 이 분리가 진단·절제 설계의 인과적 전제다.
- 가중 평균의 수학적 성질: 평균은 정확, 분산은 클라이언트 간 평균 차이 항 Δ = Σwₖ(μₖ−μ_g)² 만큼 **항상 과소추정**(총분산 법칙). 크기는 재질 간 feature shift에 의존해 사전 단정 불가 — 문헌상 우리 국면(저빈도 통신, E=2)은 BN-FedAvg가 GN보다 우수한 영역(출처 W-7)이므로 **사전 보정하지 않고 계측으로 실측**한다.
- **num_batches_tracked 단일 확정:** 평균 대상에서 제외한다. Flower `aggregate`는 모든 ndarray를 일률 가중 평균해(출처 W-4) int64가 float64로 바뀌고, `Tensor.copy_`는 이종 dtype 복사를 허용하므로(출처 W-6) 재적재 시 조용한 절단 경로가 실재한다. 서버 집계 후처리에서 클라이언트 값의 **element-wise max**로 덮어쓴다(단조·정수 유지·결정론). 값 자체는 float momentum 하에서 미사용으로 추정되나 이 세부에 설계가 의존하지 않도록 한다(미확인 항목 참조). 클라이언트 fit 시작 시 `모든 BN momentum==0.03(float) and eps==1e-3` assert 가드를 넣는다.

## 4. 부록 실험 (발동 시에만 · run 명명 `sep_fed_bncal_{seed}_{yymmdd}` · 본 결과와 분리)

### 4-1. 원인 판별 절제 — buffer-swap (통신·데이터 추가 0)

- §2에서 저장한 클라이언트별 buffer로 닫힌형 풀링 v_pooled = Σwₖvₖ + Σwₖ(μₖ−μ_g)² (wₖ=nₖ/Σn)을 계산, last.pt의 buffer만 교체한 대조 체크포인트를 채점.
- 해석: buffer 교체로 격차가 사라지면 BN 통계 기인 확정, 안 사라지면 가중치 발산(client drift) 기인. buffer는 학습 무영향(§1)이므로 인과적으로 깨끗한 절제다.
- **지위 한정(설계안 A 주장 강등):** 클라이언트 buffer는 증강(mosaic/HSV) 분포 하 활성의 EMA(유효 창 ≈ 1/0.03 ≈ 33배치) 추정치다. 닫힌형 풀링은 "EMA 추정치들의 정확한 혼합"일 뿐 모집단 통계가 아니므로 **판별기이지 최종 보정이 아니다**(Precise-BN 논거, 출처 W-5·W-8).

### 4-2. 보정 — 클라이언트 협조 BN 재보정 (federated BN recalibration)

시점: R=50 완주로 last.pt 확정 **후** 1회. 라운드 중 수행 금지(학습 동역학 오염 → 기본안과의 통제 비교 불능).

각 클라이언트 k (C1→C2→C3 순차, 1 GPU 시뮬레이션):
1. 글로벌 last.pt 로드. `@torch.no_grad`, optimizer 미생성, **fuse 전** 내부 nn.Module(함정 #1 래퍼가 노출), `is_fused` assert.
2. BN 입력에 forward hook — 배치별 (mean, sqmean, count) 누적하는 **true-average estimator**(fvcore `update_bn_stats`가 momentum을 1.0으로 바꿔 배치 통계를 얻고 population estimator로 (N1M1+N2M2)/(N1+N2) 결합하는 것과 동등한 방식, 출처 W-5). momentum EMA로 굴리는 방식은 배치 순서 의존이라 금지 — `momentum=None` 경로는 단위 테스트 교차 검증용 참조 구현으로만.
3. 데이터: **자기 로컬 train 분할만**(manifest `client==k & split==train` 필터를 로더 생성부에 assert). B_cal = min(200배치 × batch 32, 클라이언트 train 전량) — fvcore 기본 num_iters=200 계승. 실측 n_k를 기록. 전처리는 letterbox 640만, **증강 전부 off**(buffer는 평가 시 입력 분포에 맞아야 함). `cal_seed` config 고정.
4. 산출·전송: 레이어·채널별 (n_k, μ_k, m_k=E[x²]) float64. 이미지도 파생 이미지도 아닌 수치 요약 — 매 라운드 이미 오가는 buffer와 동일 추상화 수준이라 비반출 정합, 실제 배포에서도 실행 가능한 프로토콜.

서버:
5. 모멘트 결합: μ = Σwₖμₖ, m = Σwₖmₖ, var = m − μ². **기본 가중 wₖ = 클라이언트 학습 표본수 비례(32:16:8).** 근거: 글로벌 평가셋은 재질×클래스 **층화 추출이라 모집단 비율(강재:알루미늄 ≈ 6:1)을 보존**하므로, 평가 입력 분포에 맞는 가중은 비례다 — 설계안 B의 "층화라서 균등이 정합" 논거는 층화의 의미를 뒤집은 사실 오류로 기각. 균등 결합은 부록 표 변형 행 1개로만 병기(AL 상향 여부가 RQ3 진단 재료).
6. `last_bncal.pt`: running_mean/running_var만 교체. num_batches_tracked는 last.pt 값(max 규칙 산출물) 그대로 유지 — 미사용 전제를 §1 가드로 보증. **비-buffer 전 텐서 sha256 동일 assert. 원본 last.pt 불변.**
7. 채점: 동일 채점기·동일 커맨드라인·동일 평가셋으로 last.pt / last_bncal.pt(비례) / last_bncal.pt(균등)를 각각 채점, ST/AL 분해 병기.

### 4-3. 학습량 등가·last 채점 원칙과의 정합

- R×E=N 등가는 gradient 갱신 횟수의 등가다. 본 보정은 forward만 수행(gradient 0회, optimizer 미생성)하고 학습 가능 파라미터 불변을 해시로 증명한다. 보정 데이터는 이미 학습에 소진된 자기 train 분할이라 새 정보가 없다. 심사 지적 대비 카드: 중앙집중 칸에 동일한 forward-only 재보정을 대칭 적용한 행 추가 가능(기본 미적용 — 단일 분포 학습이라 EMA buffer가 이미 정합적).
- **주 결과표(8-6)에는 어떤 경우에도 보정 전 last.pt 수치가 들어간다.** 보정본은 채점 후보가 아니라 진단 산출물이다. 주 결과표 생성 스크립트는 last.pt 경로만 받도록 고정한다.

### 4-4. 통신량 표 오염 방지

본 통신량 표(8-6)는 표준 FedAvg 라운드의 교환 바이트만 집계한다. 재보정 모멘트 업로드 바이트(BN 채널 수 × 2 모멘트 × 8B + 카운트 — 수백 KB 이하 예상)는 실측해 **부록 표 별도 행("보정 추가 통신, 본 표 미산입")**으로만 보고한다. 미발동 시 0.

(a) 글로벌 평가셋(D6)은 20% 전량이 격리 자산이라 'train 부분'이 존재하지 않고, (b) BN buffer는 eval 채점 시 정규화에 직접 쓰이는 모델 상태이므로 평가셋 forward로 buffer를 맞추는 것은 평가 데이터로 모델을 보정하는 누출(docs/개발규약.md 데이터 규칙 4 — 논문 철회 사유), (c) '학습 풀'로 독해해도 서버가 클라이언트 소유 데이터를 읽는 순간 비반출 서사가 깨진다. §4-2 프로토콜로 교체를 제안한다.

## 실패 모드

- 평가셋 이미지가 calibration 로더에 유입 → 누출·논문 철회 사유. 방어: manifest client·split 필터 assert + 소비 image_id ∩ 평가셋 = ∅ 검사(V7)
- running_var 직접 가중 평균 → 클라이언트 간 평균 차 항 누락으로 혼합 분산 과소추정, 보정이 오히려 악화. 방어: 2차 모멘트 결합 고정 + 음성 대조 테스트(V1)
- num_batches_tracked를 float 평균 → int64→float64 변환 후 load_state_dict의 copy_ 경로에서 조용한 절단. 방어: 평균 제외 + element-wise max 덮어쓰기 + 왕복 테스트(V3)
- momentum EMA로 소수 배치 재추정 → 마지막 배치 편중·셔플 순서 의존. 방어: hook 기반 true-average estimator 정본, EMA는 테스트 참조 구현만
- 증강 켠 채 보정 forward → buffer가 증강 분포에 적합, 평가 분포와 불일치 확대. 방어: calibration 전용 config(augment=false) 분리·스냅샷 기록
- fuse된 모델에 buffer 주입 또는 융합 후 보정 forward → BN 부재로 무효/예외. 방어: 융합 전 모듈 접근을 함정 #1 래퍼 인터페이스로 고정 + is_fused assert
- 보정 중 학습 가능 파라미터 변경(train() 부주의, EMA 갱신) → 학습량 등가 훼손. 방어: no_grad + optimizer 미생성 + 전후 sha256 assert(V6)
- '보정 후가 좋으니 주 결과로 승격' → 암묵적 모델 선택으로 best 금지 위반. 방어: 주 결과표 생성 스크립트가 last.pt 경로만 수용, 발동 시 전/후 무조건 병기 명문화
- buffer 키 순서·dtype 불일치로 엉뚱한 레이어 주입 → 조용한 성능 붕괴. 방어: 키 이름 기준 매칭(순서 기반 금지) + 집계 전후 norm·sanity 로깅
- BN 통계 문제와 가중치 발산(client drift)의 오귀속 → 잘못된 처방. 방어: buffer-swap 절제(4-1)로 인과 분리
- 클라이언트가 ModelEMA 사본을 업로드 → 집계 대상이 어긋남. 방어: raw state_dict 업로드를 함정 #1 인터페이스 요구사항으로 명시
- Ultralytics close_mosaic이 라운드 재개마다 오발동 → 말기 라운드 buffer가 다른 증강 분포 반영. 방어: 함정 #1 통합 테스트로 이관 + 라운드별 증강 상태 로깅
- ρ의 EMA 잡음(유효 창 ~33배치)으로 오경보 → 불필요한 부록 가동. 방어: T3에 '5라운드 지속' 조건 + 파일럿 분포로 임계 확정
- 부록 보정 통신·결과를 본 표에 혼입 → 공정성·통신량 최소 주장 붕괴. 방어: 별도 run 명명(sep_fed_bncal_*) + 부록 전용 표 + '본 표 미산입' 각주
- C3 로컬 train < 6,400장 → 클라이언트 간 보정 표본 불균형. 방어: B_cal = min(200배치, 전량) 규칙 + 실측 n_k 기록(결합 가중은 학습 표본수 비례로 불변)

## 논문 명시 문장 초안

- 글로벌 모델 하나를 글로벌 평가셋으로 채점하는 설계상 BN 통계를 로컬에 유지하는 FedBN류(Li et al., ICLR 2021)는 채점에 쓸 단일 BN 상태가 정의되지 않아 적용할 수 없으므로, BN 통계를 포함한 전체 표본수 가중 평균(FedAvg 표준)을 채택했다.
- 평균된 running variance는 클라이언트 간 평균 차이 항 Σwₖ(μₖ−μ_g)²만큼 풀링 분산을 구조적으로 과소추정함을 인지하고, 라운드별 층간 누락 분산비와 클라이언트 간 buffer 거리, 재질별 지표 분해로 감시했다. 저빈도 통신 국면(라운드당 로컬 스텝 500~2,000회)에서는 BN-FedAvg가 GroupNorm 대체보다 우수하다는 보고(Zhong et al., 2023)가 이 선택을 뒷받침한다.
- [트리거 발동 시] 부록 X: 최종 라운드 후 각 클라이언트가 자기 학습 데이터로 forward만 수행해 BN 모멘트를 수집하고 서버가 표본수 비례로 결합하는 클라이언트 협조 재보정을 수행했다. 데이터는 이동하지 않으며 gradient 갱신은 0회로 학습량 등가를 침해하지 않는다. 주 결과표의 수치는 모두 보정 전 last 체크포인트이며, 보정 전후 비교는 부록에만 싣는다.
- [트리거 발동 시] 재보정에 수반된 모멘트 전송량(수백 KB 이하)은 본문 통신량 집계에 산입하지 않고 부록에 별도 보고한다.
- [트리거 미발동 시] 라운드별 BN buffer 발산 곡선에서 불안정 징후는 관찰되지 않았다(부록 그림 X).

## 기각한 설계 요소

- 구현설계.md 3-3 '글로벌 평가셋의 train 부분으로 BN 재추정' — 평가셋(D6)은 전량 격리 자산이라 train 부분이 존재하지 않고, BN buffer는 채점 시 정규화에 쓰이는 모델 상태이므로 평가셋 forward 보정 = 평가 데이터로 모델을 맞추는 누출(docs/개발규약.md 데이터 규칙 4, 논문 철회 사유). '학습 풀' 독해로도 서버가 클라이언트 데이터를 읽어 비반출 서사 훼손
- FedBN·SiloBN (BN 로컬 유지) — BN 파라미터를 집계에서 제외하고 로컬에 남기는 처방이라 글로벌 단일 모델에 채점용 BN 상태가 정의되지 않음. 글로벌 평가셋 채점 설계와 양립 불가 (arXiv:2102.07623 확인)
- GroupNorm 치환 — 표준 YOLO11s 무개조가 통제 실험 원칙(구현설계 3-1)이고, 문헌상 우리 저빈도 통신 국면은 BN이 GN보다 우수한 영역(arXiv:2303.06530)이라 치환 명분도 없음
- FixBN(학습 후반 buffer 동결) 채택 — 라운드 중 프로토콜 개입이고 동결 시점이 추가 하이퍼파라미터가 되어 '표준 FedAvg 기본안' 서사와 등가성 주장을 흐림. 후속 과제로만 언급
- 서버가 제3 데이터(RIAWELC 등)로 BN 재추정: 분포 불일치(227×227 분류 패치 대 RT 640)로 buffer를 엉뚱한 분포에 적합시키고 낯선 데이터 검증(8-4)의 독립성을 오염시킨다
- 설계안 B의 '균등 결합 기본' — '글로벌 평가셋이 재질 층화 추출이므로 균등이 목적 정합'이라는 논거는 사실 오류. 층화 추출은 모집단 비율(강재:알루미늄 ≈ 6:1)을 보존하지 균등화하지 않으므로, 평가 분포 정합 가중은 표본수 비례다. 균등은 부록 변형 행으로 강등
- 설계안 A의 '닫힌형 풀링 = 1차 보정' 지위 — 클라이언트 buffer 자체가 증강(mosaic/HSV) 분포 하 활성의 EMA(유효 창 ~33배치) 추정치라 닫힌형 풀링은 잡음 섞인 추정치들의 정확한 혼합일 뿐 모집단 통계가 아님(Precise-BN 논거). '보정'에서 '원인 판별 절제'로 재분류
- 최대 클라이언트(C1) buffer 채택 — 알루미늄에 체계적 편향, 글로벌 단일 모델 채점 공정성 훼손
- num_batches_tracked의 평균·합·리셋 — 평균은 dtype 사고 경로(Flower 일률 평균 + copy_ 이종 dtype 허용 확인), 합은 이득 없음, 리셋은 재개 시 혼동. element-wise max 덮어쓰기로 단일 확정
- 라운드 중 BN 보정 개입 — 학습 동역학을 바꿔 기본안과의 통제 비교가 불가능해지고, 신호 기반 개입은 암묵적 적응으로 조기 종료 금지 원칙의 취지 위반
- 보정본(last_bncal.pt)의 주 결과 승격 — val/평가 성능을 보고 후보 중 선택하는 순간 best 채점 금지 원칙 위반. 주 결과표는 무조건 보정 전 last.pt

## 웹 출처로 확인한 사실 / 미확인

- Ultralytics initialize_weights가 전 BatchNorm2d에 eps=1e-3, momentum=0.03을 설정 (소스 원문 확인) — https://raw.githubusercontent.com/ultralytics/ultralytics/main/ultralytics/utils/torch_utils.py
- initialize_weights는 DetectionModel.__init__에서 호출되며, BN momentum/eps는 state_dict가 아닌 모듈 속성이라 사전학습 가중치 로드(load_state_dict)로 변하지 않음 — 설계안 A의 미확인 U-3 해소 — https://raw.githubusercontent.com/ultralytics/ultralytics/main/ultralytics/nn/tasks.py
- PyTorch BatchNorm2d: momentum=None이면 누적 평균(단순 평균), running 추정치는 train 모드에서 갱신되고 eval 모드 정규화에 사용. 공식 문서 페이지에는 num_batches_tracked 서술이 없음 — https://docs.pytorch.org/docs/2.13/generated/torch.nn.BatchNorm2d.html
- Flower의 aggregate·aggregate_inplace는 모든 ndarray 층을 일률적으로 표본수 가중 평균하며 정수 dtype·buffer 특별 처리가 없음 (소스 원문 확인: layer×num_examples 합산 후 총수로 나눔) — https://raw.githubusercontent.com/adap/flower/main/framework/py/flwr/server/strategy/aggregate.py
- fvcore update_bn_stats: 기본 num_iters=200, momentum을 1.0으로 바꿔 배치별 통계를 얻고 _PopulationVarianceEstimator가 (N1M1+N2M2)/(N1+N2) 방식의 true average로 결합, 종료 후 momentum 복원. num_batches_tracked는 건드리지 않음 — https://raw.githubusercontent.com/facebookresearch/fvcore/main/fvcore/nn/precise_bn.py
- Tensor.copy_는 이종 dtype 소스 허용('It may be of a different data type') — float64→int64 조용한 변환 경로가 실재하므로 num_batches_tracked를 평균 경로에 태우면 안 되는 근거 — https://docs.pytorch.org/docs/2.13/generated/torch.Tensor.copy_.html
- Zhong, Chen & Chao 2023: BN이 다수 FL 설정에서 GN보다 우수하며 실패 국면은 '고빈도 통신 + 극단 non-IID'. FixBN은 추가 학습·통신 없는 완화책 — 우리 저빈도 국면(E=2, 라운드당 500~2,000 스텝)에서 기본안 방어 근거 — https://arxiv.org/abs/2303.06530
- FedBN(Li et al., ICLR 2021): BN 파라미터를 집계에서 제외하고 로컬에 유지하는 feature-shift 처방 — 글로벌 단일 모델에는 채점용 BN 상태가 정의되지 않아 우리 설계와 양립 불가 — https://arxiv.org/abs/2102.07623
- Flower FedBN how-to는 클라이언트가 'bn' 포함 키를 명시적으로 필터링하도록 요구 — 즉 Flower 기본 경로는 BN buffer 포함 전체 state_dict를 교환·평균 — https://flower.ai/docs/framework/how-to-implement-fedbn.html
- UltraFlwr(MICCAI-AMAI'25, arXiv:2503.15161): Ultralytics YOLO × Flower 통합 선행 사례 존재, YOLO-PA 부분 집계 전략 제안. 단 BN buffer 처리 세부는 저장소 페이지에서 확인 불가 — https://github.com/KCL-BMEIS/UltraFlwr
- 미확인: num_batches_tracked가 float momentum에서 EMA 계산에 전혀 쓰이지 않는다는 세부(설계안 A의 PR #26550 인용)는 공식 문서에 명시가 없어 소스 수준 재확인 필요 — 처방은 이 세부에 의존하지 않도록 평균 제외 + 결정론 덮어쓰기로 설계했고, momentum==0.03 float assert 가드가 전제를 런타임에 못 박음
- 미확인: load_state_dict가 long buffer에 float64 배열을 조용히 절단하는지 예외를 내는지 — copy_의 이종 dtype 허용까지는 확인, 정확한 거동은 왕복 테스트(V3)로 검증
- 미확인: Ultralytics val 경로가 fuse를 강제하는 정확한 지점과 우회 방법 — 함정 #1 커스텀 래퍼 구현 시 소스 추적. 본 처방은 '융합 전 state_dict 주입'만 요구하므로 결론 불변
- 미확인: UltraFlwr의 BN buffer 처리 방식 — 논문에 선행 사례로 인용하기 전 소스 직접 열람 필요
- 미확인: Qwen3.5 4B(채택 후보)의 정규화 계층이 buffer-free(RMSNorm 계열)인지 — 계열 관례상 추정이며 채택 시점 named_buffers 검증(V10)
- 미확인: close_mosaic이 라운드 재개 시 어느 epoch 카운터 기준으로 발동하는지 — 함정 #1 스펙 통합 테스트로 이관
- 미확인: Flower 1.x 현행 API에서 aggregate_fit의 results로 클라이언트별 원시 ndarray에 접근하는 시그니처가 진단 계측(§2)에 충분한지 — strategy 서브클래스 프로토타입으로 확인

## 채택 결론

"행렬별 표본 수 가중 평균(FedIT 패턴) + 서버 1회 어댑터 초기화·배포 + Flower ArrayRecord 키드 교환(wire fp32) + 최종 1회 bf16 비양자화 병합본 단일 평가 경로"를 기본안으로 확정한다. 설계안 A의 수학·프로토콜 골격(서버 초기화, 표본 수 가중, LR 스케줄 오프셋 재개, 2단 부록 구조)과 설계안 B의 배관 명세(ArrayRecord 키드 교환, dtype 체인, 비양자화 베이스 병합, all-linear 금지·명시 목록, modules_to_save 금지, fail-fast assert 군)를 병합하되, 두 안이 정면 충돌한 wire dtype은 Flower arrayrecord 소스 확인(.numpy() 직행 → bf16 불가)으로 B의 fp32로 판정했고, A의 "E=0.5라 집계 오차가 작다"는 선험 논거는 라운드당 수백 스텝(C1 기준 약 400+)이라 정량 근거가 없어 기각 — 대수적 사실(1차항 일치·2차항 유계)만 남기고 집계 오차 실측(부록 1단)을 '여유 시'에서 '필수'로 승격, 이를 위해 마일스톤 라운드의 클라이언트 어댑터 페이로드 보존을 프로토콜에 추가했다. 병합·평가 대안이던 vLLM 어댑터 로드 경로는 멀티모달 LoRA가 언어부 한정·실험적이고 Qwen VL 계열 동적 로드 버그가 보고되어 있어 확정 기각했다.

## 0. 두 설계안 판정 요지

| 쟁점 | 판정 | 근거 |
|---|---|---|
| wire dtype (A: bf16 그대로 / B: fp32 강제) | **B 승** | Flower `ArrayRecord.from_torch_state_dict`가 텐서마다 `.detach().cpu().numpy()` 직행 — numpy에 bfloat16이 없어 bf16 전송은 TypeError. 소스 확인 |
| all-linear 비전 인코더 포함 여부 | **B 승 (소스 확정)** | `_maybe_include_all_linear_layers`는 전 모델 nn.Linear/Conv1D 수집, 제외는 output embeddings·SEQ_CLS 헤드·중첩 tuner뿐. 멀티모달/비전 특례 없음 |
| A의 "E=0.5라 δ 작음 → 오차 작음" | **부분 기각** | "매 라운드 동일 출발점"은 프로토콜 속성이라 E와 무관하게 성립하고, 1차항 일치·2차항 오차라는 대수도 옳다. 그러나 E=0.5는 C1 기준 라운드당 약 400+ 옵티마이저 스텝(페어 약 27k×0.5÷배치32)이라 δ가 "작다"는 선험 보장이 없다. 논거를 "유계 + 실측"으로 교체하고 실측을 필수화 |
| FLoRA 기제 서술 | **A 확인** | 스택 항등식, 다운링크 Σr_k 증가, 가중치 A쪽 단독 적용, 매 라운드 로컬 재초기화 — arXiv HTML 원문 재확인 |

## 1. 교환 객체와 직렬화 (확정)

- **교환물은 `get_peft_model_state_dict(model)` 반환 어댑터 행렬(raw lora_A/lora_B)만.** scaling(α/r)은 LoraConfig 설정값이라 state dict에 없음 — 전 클라이언트 config 동일(§3 동결) 전제에서 상수이므로 평균과 가환. 주입은 `set_peft_model_state_dict`로만 한다(런타임 키 `.default.` 세그먼트와 교환 키가 달라 `model.load_state_dict` 직접 사용 금지).
- **교환 형식: Flower Message API `ArrayRecord`(str→Array 딕셔너리) — 키가 payload에 실려 다녀 "순서 뒤섞임" 실패 모드를 구조적으로 제거.** 집계는 키 기준 매칭. 레거시 NumPyClient(ndarray 리스트)로 강등해야 할 때만 `sorted(keys)` 순서 리스트를 쓰되 키 해시 대조는 유지.
- **canonical key list:** 서버가 라운드 0에 참조 모델에서 `sorted(get_peft_model_state_dict(m).keys())` 확정, `sha256(",".join(keys))`를 run-config로 배포. 클라이언트는 fit 진입 시, 서버는 수신 시 각각 해시 일치 assert — 불일치 즉시 중단.
- **dtype 체인 (캐스트 지점 정확히 2곳):**

| 구간 | dtype |
|---|---|
| 어댑터 학습 | bf16 (`bnb_4bit_compute_dtype=torch.bfloat16`, QLoRA 표준) |
| wire (송신 직전 캐스트) | **fp32** (bf16→fp32 무손실. fp16은 지수 범위 축소로 비무손실이라 배제) |
| 서버 집계 | fp32 누적 (집계 함수는 dtype을 건드리지 않고 fp32 입력 assert) |
| 수신 직후 캐스트 → 주입 | bf16 |
| 마일스톤 저장 | bf16 safetensors |

- **통신량 보고 규칙(칸 간 공통 기준):** 두 연합 칸(분리·연합, 통합·연합) 모두 동일 직렬화 경로의 **wire 실측 바이트(fp32)**로 업링크·다운링크를 라운드마다 로깅해 6-5 공식에 대입한다. 결과표 각주에 "구현 제약으로 fp32 전송이며 bf16/fp16 전송 시 1/2"를 명시. 분리형 검출 가중치도 같은 fp32 wire 기준이므로 상대 비교("분리형이 가장 가볍다")는 오염되지 않는다.

## 2. 집계 규칙 (확정)

- **행렬별 표본 수 가중 평균:** `A_g = Σ p_k A_k`, `B_g = Σ p_k B_k`, `p_k = n_k / Σ n_j`. **n_k = 매니페스트 파생 클라이언트 k의 D4 학습 페어 수**(이미지 수 아님 — A트랙 계약 가정으로 명시). 클라이언트 보고값이 manifest 파생값과 다르면 즉시 실패. E=0.5의 실노출 0.5·n_k가 아니라 n_k로 고정(비율 동일, 로그·논문 수치 일관).
- **서버 1회 초기화 + 라운드 0 배포:** `init_lora_weights=True`(PEFT 기본: A=kaiming_uniform, **B=0** → ΔW=0 no-op 시작, config docstring 확인). 시드는 전역 시드에서 파생·고정. 클라이언트 독립 초기화 금지 — 서로 다른 랜덤 A_k에 결합된 B_k의 평균은 첫 집계부터 구조 파괴. B=0 시작이라 라운드 1 출발 시 다섯 칸 공통 출발점(배경지식 병합 체크포인트)과의 동일성이 보장된다.
- **정당화 논증(스펙·논문 공통 표현):** A_k = A_g+δA_k, B_k = B_g+δB_k 전개에서 행렬별 평균과 참 평균 avg(B_k·A_k)의 **1차항은 완전 일치**하고 오차는 `avg(δB)·avg(δA) − avg(δB_k·δA_k)` — 로컬 드리프트의 2차항. **오차 크기는 선험적으로 '작다'고 주장하지 않고 §7 부록 1단에서 실측한다.** non-IID(특히 C3 알루미늄)가 강할수록 커지는 항이므로 RQ3 해석 시 참조.
- **집계 함수 assert (전부 fail-fast):** ① 키 집합 해시 = canonical ② 입력 전부 fp32 ③ 키별 shape = 라운드 0 동결 shape 테이블 ④ lora_A/lora_B 키 수·이름 짝 완전 대응 ⑤ 정규화 후 가중치 합 = 1.0 (atol 1e-9) ⑥ isfinite 전수 ⑦ 출력 norm ≤ max(입력 norm)×(1+1e-6) — 볼록 결합의 삼각부등식(하한은 상쇄 가능하므로 검사하지 않음).

## 3. LoraConfig 동결 목록 (configs/ 스냅샷, 5칸·3클라이언트 sha256 로깅)

`r=16, lora_alpha=32, lora_dropout=(파일럿 후 고정), bias="none", target_modules=<명시 목록 파일 참조>, exclude_modules=<visual/vision/merger 패턴>, use_rslora=False, use_dora=False, init_lora_weights=True, modules_to_save=None`. 호출부는 `get_peft_model_state_dict(..., save_embedding_layers=False)` 명시 — auto는 target_modules에 임베딩 이름이 있을 때 **그리고 임베딩 resize 시에도** True로 승격됨(소스 확인). 어댑터 이름은 `default` 고정(비-default는 save_pretrained가 하위 디렉터리에 저장해 로드 경로가 어긋남).

## 4. 라운드 프로토콜 (R=6, E=0.5 기본 — 파일럿 후 고정)

```
[사전 1회]
 S0. 배경지식 병합 체크포인트(bf16)를 NF4로 로드하는 공통 기본 모델 3클라 사전 배포
     (시뮬레이션은 동일 경로 공유, sha256 로깅)
 S1. 서버: 시드 고정 어댑터 초기화(A=kaiming, B=0) → 글로벌 어댑터 v0, canonical keys·shape 동결

[라운드 t = 1..R]
 1. 서버→클라: 글로벌 어댑터 ArrayRecord (fp32) + canonical 해시
 2. 클라이언트 k:
    a. NF4 기본 모델 + 동결 LoraConfig 주입 → set_peft_model_state_dict(수신본 bf16 캐스트)
       — 주입 후 norm 변화 assert (0개 로드 조용한 실패 차단)
    b. AdamW 새로 생성 (모멘트 라운드마다 리셋 — FedAvg 표준, 논문 명시)
    c. LR: 자기 총 스텝 예산 T_k = R·S_k 전체에 걸친 단일 cosine을
       전역 스텝 오프셋 (t−1)·S_k 에서 재개 (스케줄 규칙 공통 = "자기 총 예산에 대한 cosine";
       라운드마다 재시작 금지 — 유효 LR 총량이 중앙 칸과 어긋남)
    d. S_k = round(0.5 · n_k / B_eff) 스텝 학습 (B_eff=32, 조기 종료 없음)
    e. bf16→fp32 캐스트 → ArrayRecord + MetricRecord(num_examples=n_k) 반환.
       로컬 체크포인트 저장 안 함
 3. 서버:
    a. §2 집계 → 글로벌 어댑터 v_t
    b. 집계 입력 3개·출력 1개의 전역/lora_A군/lora_B군 L2 norm → MLflow(round=step),
       레이어 블록별 norm 벡터 → jsonl. 업·다운링크 실측 바이트 로깅
    c. latest/ 슬롯 덮어쓰기 저장(재시작용). 마일스톤 라운드(ceil(R×{.25,.5,.75}) = 2,3,5)와
       최종 라운드: PEFT save_pretrained 형식 보존 + **클라이언트 어댑터 페이로드 3개 동반 보존**
       (§7 부록 1단 재료 — 이것이 없으면 집계 오차 실측 불능)
    d. 통합·연합은 라운드 중 글로벌 평가셋 추론 없음(기본): 로컬 학습 loss와 norm만 로깅.
       본 채점은 최종 병합본 1회 (last 채점 원칙·격리 서사·생성 비용 모두 충족.
       구현설계 7-4의 라운드별 평가 로깅은 분리·연합(검출, 저비용)에만 유지)

[종료 후 1회]
 E1. 기본 모델을 양자화 없이 bf16 재로드 → 최종 글로벌 어댑터 PeftModel.from_pretrained
     → merge_and_unload → bf16 safetensors + sha256 = 평가용 체크포인트 → vLLM 서빙
 E2. 병합은 전 과정에서 이 1회뿐. 4bit 베이스 위 merge 금지(dequant→재양자화 손실, PEFT 공식
     경고 — 소스 확인). 병합 전 active_adapter 단수·merged_adapters 빈 리스트 assert
```

- **평가 경로 단일 확정:** bf16 병합본을 vLLM으로 서빙해 채점한다. 대안이던 "NF4+어댑터 로드 평가"는 기각 — vLLM 멀티모달 LoRA는 언어부 한정이 기본이고 비전 타워·커넥터 LoRA는 실험 기능(default False)이며 Qwen VL 계열 동적 LoRA 로드 버그가 보고돼 있다. NF4 학습 어댑터의 bf16 병합은 근사이지만 **통합·중앙과 완전히 동일한 함수(merge_final 공유)를 밟게 해 비교에서 상쇄**한다. 배경지식 단계(5-2)의 어댑터 병합도 같은 함수를 쓴다. CTO 게이트 제안: "병합·평가 체크포인트 생성 절차"를 5칸 공통 고정의 9번째 항목으로 승격.

## 7. 부록 설계 (2단, 주 결과와 분리)

- **1단 (필수, 학습 재실행 없음):** 마일스톤 라운드(2,3,5,최종)에서 `‖avg(B)avg(A) − avg(B·A)‖_F / ‖avg(B·A)‖_F`를 층별 산출해 집계 노이즈의 실측 크기를 표로 보고. §2 논증의 "실측" 부분을 담당하는 심사 방어 자료. A안에서 '비용 0'이라던 전제는 서버가 클라이언트 페이로드를 저장하지 않는 기본 프로토콜과 모순이었으므로, 마일스톤 한정 페이로드 보존(§4 3.c)으로 해소했다.
- **2단 (여유 시만): FLoRA 스택 집계 재학습 1회.** 확인된 기제: `ΣB_kA_k = (B_0⊕…)(A_0⊕…)` (B 가로·A 세로 스택), 가중치는 A쪽에만(제곱 방지), 서버가 스택 어댑터 배포 → 다운링크 Σr_k(3배) 증가, 클라이언트 매 라운드 로컬 어댑터 재초기화 + 4bit 베이스에는 라운드당 dequant→merge→requant 필요. **주 통신량 표(6-5)에 절대 혼입 금지** — 결과표 생성 스크립트에 프로토콜 태그(`agg=matrix_avg` / `agg=flora`)를 두고 주 표는 태그 필터로만 생성. 부록 표에 프로토콜 열 명시.

# 검증 방법 (구현 후)

1. **왕복 동일성:** `sd(bf16) → fp32 캐스트 → ArrayRecord → 직렬화 bytes → 복원 → bf16 캐스트`에서 키·shape 일치, fp32 구간 bit-exact, bf16→fp32→bf16 왕복 bit-exact(무손실이어야 정상). CPU만으로 수행 가능.
2. **집계 단위 테스트 (합성 텐서):** 알려진 3벌 A_k·B_k에 대해 가중 평균 손계산과 `weighted_average` 출력 일치. 입력 딕셔너리 순서를 일부러 뒤섞어 넣어 키 기준 매칭의 순서 무관성 확인. 가중치 합=1, fp32 assert, shape 테이블 대조 각각 작동 확인.
3. **1클라이언트 항등 테스트:** 클라이언트 1개·가중치 1.0·1라운드 → 집계 출력 == 입력 (atol 0). FedAvg 배관의 항등원 검사.
4. **1클라이언트 등가 테스트 (강화판):** (a) 1클라 R라운드 연합 실행 vs (b) 동일 코드 단독 학습에 S_k 스텝마다 수동 옵티마이저 리셋 + 스케줄 연속을 건 대조군 — cudnn.deterministic 하에서 손실 곡선 일치(배관 검증). 별도로 (b) vs (c) 리셋 없는 연속 학습의 차이로 모멘트 리셋 효과를 정량 분리한다. A안의 "허용 오차 내 일치"라는 모호한 기준을 "같은 리셋을 건 대조군과의 일치"로 교체.
5. **의도적 셔플 주입:** 키를 뒤섞거나 1개 누락시킨 페이로드를 보내 assert가 실제로 중단시키는지 확인 — 방어선 작동을 증명하고 넘어간다.
6. **라운드 0 검증:** 배포 어댑터의 모든 lora_B norm=0, lora_A norm>0, 3클라이언트 수신본 sha256 동일.
7. **어댑터 부착 위치 덤프:** lora가 붙은 모듈명 전수 덤프에 visual|vision|merger 0건 (grep + 육안), 목록 sha256을 configs에 기록.
8. **norm 불변식 자동 assert:** 라운드마다 출력 norm ≤ max(입력 norm)×(1+1e-6). 위반 즉시 중단.
9. **wire bytes 게이트:** 라운드당 실측 바이트 = 어댑터 파라미터 수 × 4B ± 5%. 초과 시 임베딩 동봉(F7)·잉여물 혼입 의심. 업링크×3 + 다운링크×3 합계가 6-5 공식 재계산과 일치하는지 대조.
10. **병합 1회성 + 등가 스모크:** 실행 로그의 merge 호출 카운트=1, 병합 전 merged_adapters 빈 리스트. 소형 프롬프트 표본에서 (NF4 베이스+어댑터) vs (bf16 병합본) greedy 출력의 판정 JSON 필드 일치율을 기록 — 완전 일치는 기대하지 않으며(근사), 통합·중앙과 동일 기준으로 보고해 한계 절 재료로 쓴다.
11. **집계 오차 실측 (부록 1단 겸 파이프라인 검증):** 마일스톤 라운드 페이로드로 층별 상대 Frobenius 오차 산출 — 값이 나오는 것 자체가 페이로드 보존·매칭 배관의 검증이고, 값의 크기가 논문 부록 데이터다.
12. **재개 테스트:** latest/ 슬롯에서 서버 강제 재시작 → 1라운드 진행 → norm 궤적·LR 오프셋 연속성 확인.
13. **LR 스케줄 사후 감사:** 라운드별 LR 시작·끝 실측값 로깅이 단일 cosine 곡선 위에 놓이는지 스크립트로 대조 (라운드 재시작 실수 F9의 사후 검출).
14. **GPU 필요 구분:** 1~3·5는 CPU, 4·6~13은 4B 로드 필요 — 공통 16GB 실측 계획에 편입.

## 실패 모드

- 키 순서/A·B 짝 뒤섞임 — 에러 없이 지표만 완만히 오염되는 최악의 조용한 실패 → ArrayRecord 키드 교환 + canonical sha256 assert로 구조 차단, 셔플 주입 테스트로 방어선 작동 증명
- bf16 텐서 .numpy() 직행 → Flower 직렬화에서 TypeError (numpy에 bf16 없음, 소스 확인) → 캐스트 지점 2곳(송신 직전 fp32·수신 직후 bf16)을 adapter_io.py에 유일 소유
- 클라이언트별 독립 어댑터 초기화 → 라운드 1 집계가 랜덤 행렬 평균이 되어 구조 파괴 → 서버 1회 초기화(B=0)+라운드 0 배포, 수신본 해시 3자 대조, lora_B norm=0 검증
- 런타임 키(.default. 포함)와 교환 키 혼용 → load_state_dict strict=False가 조용히 0개 로드, 글로벌이 초기 어댑터 그대로 → set_peft_model_state_dict만 사용 + 주입 후 norm 변화 assert
- 4bit 베이스 위 merge_and_unload → dequant 후 NF4 재양자화로 병합 결과 손실(PEFT 공식 경고) → 병합 함수는 bf16 비양자화 로드 경로만 존재, merge 호출 카운트=1 검증
- all-linear가 visual/merger에 어댑터 부착(비전 특례 없음 — 소스 확정) → 비전 동결 원칙 위반·어댑터 비대·통신량 초과 → 명시 목록 동결 + exclude_modules + 부착 모듈명 assert 0건
- save_embedding_layers auto 오발동(타깃에 임베딩 이름 존재 또는 임베딩 resize 시 — 후자는 두 설계안이 모두 놓친 추가 발동 조건) → 교환물에 fp32 약 1.5GB 임베딩 동봉 → False 명시 + wire bytes ±5% 게이트
- 집계 가중치 미정규화·합≠1 → 출력 norm 폭주·발산 → 합=1 assert(atol 1e-9) + 출력 norm ≤ max(입력) 불변식
- LR 스케줄 라운드마다 재시작 → 유효 LR 총량이 통합·중앙과 어긋나 학습량 등가 주장 훼손 → 전역 스텝 오프셋 재개 + 라운드별 LR 실측 로깅의 cosine 곡선 사후 감사
- num_examples를 실노출 0.5·n_k로 보고 → 가중 비율은 불변이나 로그·논문 수치 불일치 → n_k = manifest 파생 D4 페어 수로 고정, 서버 대조 실패 시 중단
- FLoRA 부록 수치의 주 통신량 표 혼입 → '분리형이 가장 가볍다' 논거의 산출 기준 오염 → 프로토콜 태그(agg=matrix_avg/flora)로 결과표 생성 스크립트에서 분리
- LoraConfig 드리프트(use_rslora/use_dora/rank/alpha) → scaling 상수성·집계 의미 전제 붕괴 → 동결 스냅샷 sha256을 5칸·3클라이언트 전부 로깅, 불일치 시 실행 중단
- 병합·평가 경로가 통합·중앙과 비대칭 → NF4→bf16 병합 근사가 RQ2 비교에 편향으로 유입 → merge_final.py 동일 함수 강제 + 체크포인트 메타에 코드 commit 해시
- 마일스톤 라운드 클라이언트 페이로드 미보존 → 부록 1단(집계 오차 실측) 불능 — A안의 '비용 0' 전제와 기본 프로토콜(클라 상태 미저장)의 모순 지점 → 마일스톤 서버 저장 목록에 클라이언트 어댑터 3벌 명시 포함
- 라운드마다 글로벌 평가셋 생성 평가 수행 → 라운드×2,000건 생성 비용 폭증 + 평가 자산 격리 서사 리스크 → 통합·연합은 라운드 중 loss/norm만, 본 채점은 최종 병합본 1회

## 논문 명시 문장 초안

- 통합·연합의 어댑터 집계는 LoRA 행렬 A·B를 각각 표본 수 가중 평균하는 방식(FedIT 계열의 표준 관례)을 따른다. 저랭크 분해의 비가환성으로 avg(B)·avg(A) ≠ avg(B·A)이며, 모든 클라이언트가 매 라운드 동일한 글로벌 어댑터에서 출발하므로 이 집계 오차는 로컬 갱신의 2차항으로 유계이다. 오차의 실제 크기는 가정하지 않고 마일스톤 라운드에서 상대 Frobenius 오차로 실측해 부록에 보고하며, 노이즈 제거 대안(FLoRA 계열 stacking)과의 비교도 부록에 둔다.
- 옵티마이저 모멘트는 FedAvg 표준 동작에 따라 라운드마다 초기화된다. 학습률 스케줄은 이와 별개로, 각 클라이언트의 총 스텝 예산 전체에 걸친 단일 cosine을 전역 스텝 오프셋으로 이어 가 중앙집중 칸과 유효 학습률 총량을 등가로 유지했다.
- 평가용 체크포인트는 비양자화(bf16) 기본 모델에 최종 글로벌 어댑터를 1회 병합해 생성했다. NF4 양자화 베이스에서 학습된 어댑터를 비양자화 베이스에 병합하는 것은 근사이나, 통합형 두 칸(중앙·연합)에 완전히 동일한 절차를 적용해 비교에서 상쇄되도록 했다.
- 통신량은 직렬화 경로의 실측 바이트로 보고한다. 프레임워크 직렬화 제약으로 fp32 전송이며 bf16/fp16 전송 시 절반이 된다. 분리·연합과 통합·연합에 동일한 직렬화·측정 기준을 적용했다.
- 부록의 FLoRA(스택 집계) 비교는 본문과 다른 프로토콜이므로 본문 통신량 표에 포함하지 않는다. FLoRA는 업링크가 동일하나 다운링크가 참여 랭크 합에 비례해 증가한다.

## 열린 질문 (안전 기본값)

- **Q:** Qwen3.5 4B가 네이티브 멀티모달인가, 비전 모듈 네이밍(visual. 접두, merger)은 실제로 무엇인가? (Qwen3.5-4B 실존은 확인 — 2026-03-02 공개. 멀티모달 여부는 미확인)
  **기본값:** Qwen-VL 관례(visual. 접두 + merger)로 가정하고 §3 명시 목록 절차(채택 시점 named_modules() 전수 덤프)로 흡수한다. 비멀티모달로 판명되면 통합형 백본 재선정을 재검토 안건으로 즉시 올리되, 본 처방의 교환·집계·병합 프로토콜은 백본 무관이므로 그대로 유지한다.
- **Q:** 통합·연합의 라운드별 서버 평가를 구현설계 7-4대로 글로벌 평가셋에 수행할 것인가?
  **기본값:** 하지 않는다. 라운드 중에는 로컬 학습 loss와 norm만 로깅하고 본 채점은 최종 bf16 병합본 1회로 한다(라운드×2,000건 생성 비용 + 격리 서사 보호 + last 채점 원칙 정합). 라운드별 곡선이 그림에 필요하면 보존된 마일스톤 어댑터로 실험 종료 후 오프라인 산출한다. 7-4의 라운드별 평가는 분리·연합(검출, 저비용)에만 유지.
- **Q:** FLoRA 부록 2단(재학습 1회) 착수 여부
  **기본값:** 미착수. 부록은 1단(집계 오차 실측 — 필수 승격)만으로 성립한다. 2단은 G3(9/27) 이후 여유가 확인될 때만, 4bit 베이스의 라운드당 dequant→merge→requant 소형 프로토타입 검증을 선행 조건으로 착수한다.
- **Q:** R=6·E=0.5 확정값 (총 3 epoch 등가)
  **기본값:** R=6, E=0.5 유지. 3주차 파일럿에서 R·E·N과 총 갱신 횟수를 고정하고 논문에 전부 기재한다. 변경 시에도 R×E=3 등가는 불변.
- **Q:** "병합·평가 체크포인트 생성 절차"를 5칸 공통 고정의 9번째 항목으로 승격할 것인가 (CTO 게이트 안건)
  **기본값:** 승격된 것으로 간주하고 진행 — 통합형 두 칸과 배경지식 단계가 merge_final 동일 함수를 쓰도록 강제한다. 기각되더라도 동일 함수 강제 자체는 유지한다.
- **Q:** Flower 서버 초기 어댑터 배포 API의 정확한 형태 (채택 버전의 Message API + Ray + 동시성 1 조합 포함)
  **기본값:** 라운드 0에 서버가 초기 어댑터를 일반 라운드와 같은 ArrayRecord 메시지로 배포하는 자체 흐름으로 설계해 프레임워크 API 세부에 비의존으로 둔다. 세부는 트랩 #1(Ultralytics×Flower) 스펙과 공동으로 버전 고정 후 확정.
- **Q:** FedAvg 가중치 n_k의 정의: 이미지 수인가 D4 페어 수인가 (매니페스트 계약 사항)
  **기본값:** 클라이언트별 D4 학습 페어 수(매니페스트 파생)로 한다 — 실제 학습 표본 수가 FedAvg 정의에 부합한다. manifest에 해당 파생이 불가능하면 이미지 수로 임시 대체하고 게이트에서 계약을 맞춘다.

## 기각한 설계 요소

- [A] wire bf16 전송 — Flower ArrayRecord.from_torch_state_dict가 .detach().cpu().numpy() 직행이라 bf16은 TypeError(소스 확인). fp32 wire로 교체
- [A] sorted ndarray 리스트를 기본 교환 형식으로 — 순서 실패 모드가 잔존하는 암묵 규약. ArrayRecord 키드 교환으로 교체, 리스트는 레거시 강등 경로에서만 해시 대조와 함께 허용
- [A] "E=0.5라 집계 오차가 작다"를 채택 근거로 — E=0.5는 C1 기준 라운드당 약 400+ 스텝이라 δ의 '작음'이 선험 보장되지 않음. 대수적 사실(1차항 일치·2차항 유계)만 남기고 크기는 부록 1단 실측으로 교체, 실측을 필수 승격
- [A] 글로벌 어댑터 전 라운드 디스크 보존 — 구현설계.md 10-2 체크포인트 규칙(FL 칸은 최종+마일스톤만)과 충돌. 마일스톤 ceil(R×p)=2,3,5+최종 + latest/ 덮어쓰기 슬롯으로 교체
- [A U2 열린 질문이던] vLLM에 어댑터 로드로 평가하는 대안 경로 — vLLM 멀티모달 LoRA는 언어부 한정 기본, 비전 타워·커넥터 LoRA는 실험 기능(default False), Qwen VL 계열 동적 로드 버그 보고(issue #28640). bf16 병합본 단일 경로로 확정 기각
- 4bit(NF4) 베이스 위 merge_and_unload — dequantize→가산→Params4bit 재양자화로 병합 결과 손실 + PEFT 공식 rounding 경고(소스 확인)
- target_modules="all-linear" 문자열 사용 — 소스 확정: 전 모델 nn.Linear 수집에 비전 인코더 특례 없음. 전개 후 명시 목록 동결로 교체 (도구 내부에서만 1회 사용)
- modules_to_save(embed_tokens/lm_head) — 모듈당 fp32 약 1.5GB 교환으로 통신량 서사 파괴, vocab 확장 없는 과제라 필요성 부재
- 균등(1/3) 평균 — 표본 수 비례라는 FedAvg 정의 이탈, C3 발언권 3배 부풀림으로 RQ3 해석이 집계 규칙 변경 효과와 분리 불가 (A의 기각 유지)
- 풀 ΔW(m×n) 직접 교환 — 업링크가 언어부 전체 가중치급으로 폭증, 경량·비반출 서사와 정면 충돌 (A의 기각 유지)
- FLoRA를 주 집계 프로토콜로 — 다운링크 Σr_k(3배) 증가 + 4bit 베이스에 라운드당 dequant→merge→requant 필요 + FedIT 대비 관례 이탈로 주 비교 기준 오염. 부록 2단 전용
- fp16 wire — bf16→fp16은 지수 범위 축소(8→5비트)로 무손실 아님. 크기 절반의 이득보다 무손실 보장을 택함
- [B 1-8의 라운드별 평가 전제 조정] 통합·연합 라운드마다 글로벌 평가셋 추론 — 생성 비용 폭증과 격리 서사 리스크로 라운드 중 loss/norm만으로 축소 (분리·연합에는 구현설계 7-4대로 유지, 열린 질문 #2로 확인)

## 웹 출처로 확인한 사실 / 미확인

- Flower ArrayRecord.from_torch_state_dict는 텐서마다 Array.from_numpy_ndarray(v.detach().cpu().numpy())를 호출하며 torch dtype 특례가 없다 — numpy에 bfloat16이 없어 bf16 직행 전송 불가, wire는 fp32 캐스트가 강제된다 (2026-08-17 확인) — https://flower.ai/docs/framework/_modules/flwr/common/record/arrayrecord.html
- PEFT _maybe_include_all_linear_layers(all-linear 전개)는 전 모델의 nn.Linear/Conv1D를 수집하고, 제외는 output embeddings(lm_head)·SEQ_CLS 헤드·중첩 tuner 레이어뿐 — 멀티모달/비전 인코더 특례 없음 (main 브랜치 L2353–2413 소스 직접 확인, 2026-08-17) — https://raw.githubusercontent.com/huggingface/peft/main/src/peft/tuners/tuners_utils.py
- PEFT Linear4bit.merge()는 dequantize_bnb_weight → ΔW 가산 → bnb.nn.Params4bit 재양자화 순서로 동작하며 "Merge lora module to 4-bit linear may get different generations due to rounding errors" 경고를 발생시킨다 — https://raw.githubusercontent.com/huggingface/peft/main/src/peft/tuners/lora/bnb.py
- PEFT get_peft_model_state_dict의 save_embedding_layers="auto"는 target_modules에 임베딩 계열 이름이 있을 때 True로 승격되고, 파인튜닝 중 임베딩이 resize된 경우에도 True로 승격된다 (save_and_load.py L229–263 확인 — 두 설계안 모두 후자 조건은 미언급) — https://raw.githubusercontent.com/huggingface/peft/main/src/peft/utils/save_and_load.py
- PEFT LoraConfig에 exclude_modules 파라미터 존재 (리스트/regex, L450·L629 확인) — https://raw.githubusercontent.com/huggingface/peft/main/src/peft/tuners/lora/config.py
- PEFT init_lora_weights=True(기본)는 Microsoft 참조 구현 초기화로 lora_B=0 — 학습 전 어댑터는 no-op (config docstring L471–475 확인) — https://raw.githubusercontent.com/huggingface/peft/main/src/peft/tuners/lora/config.py
- FLoRA(arXiv 2409.05976): ΣB_kA_k = (B_0⊕…⊕B_K)(A_0⊕…⊕A_K) 스택 항등식으로 cross-term 노이즈 제거, 서버가 스택 어댑터를 재배포해 라운드당 통신 증가를 논문 스스로 인정, 스케일링 가중치 p_k는 제곱 방지를 위해 한쪽(A)에만 적용, 클라이언트는 매 라운드 로컬 어댑터 재초기화 — 설계안 A의 서술 전부 원문 재확인 — https://arxiv.org/html/2409.05976

# 함정 #4

## 채택 결론

기본 좌표 규약을 NORM_1000(분모 1000 고정) + 플레인 JSON `bbox_2d` 타깃으로 확정하고, 이 선언을 코드가 아니라 configs 데이터(CoordCfg)로 두되 합성 도형 카나리아 argmax 판별을 통합형 학습 착수의 하드 게이트로 삼는다(카나리아가 최종 판정자 — 문서보다 실측 우선). 저장 계층은 원본 픽셀 단일(모델 좌표는 어떤 파일에도 저장 금지), 변환은 학습 담당 소유 의존성 제로 리프 모듈 `vlm/coords.py`의 정변환·역변환 두 함수로만 통과시키며, ABS_RESIZED에 필요한 리사이즈 치수는 모듈이 계산하지 않고 프로세서 실호출 산출물(`image_grid_thw` × patch_size 복원값)을 인자로만 받는다 — 이것이 설계안 A의 "재계산 금지"와 B의 "리프 모듈" 요구를 동시에 만족시키는 해소책이다(smart_resize는 coords.py에 자체 구현도 import도 하지 않고, 정합 대조는 별도 파일럿 스크립트로 뺀다). 평가 담당은 같은 모듈을 import하고 C의 골든 픽스처를 재실행해 좌표 해석 일치를 기계적으로 보장하며, 채점기 자체는 bbox_px만 받는 좌표계 무지 상태를 유지한다.

# 함정 #4 처방 — VLM bbox 좌표계 (학습·연합 스펙 수록본)

## 0. 확정 사실 전제 (웹 검증 완료 — 상세 출처는 검증 사실 목록)

| 세대 | 규약 | 표기 | 확인 수준 |
|---|---|---|---|
| Qwen2-VL | 0~1000 정규화 | 특수 박스 토큰 | 양 설계안 일치 (비채택 경로, 직접 재검증 생략) |
| Qwen2.5-VL | **절대 픽셀 — 입력(=smart_resize 후) 이미지 기준** | JSON `bbox_2d` | **공식 1차 출처 확보** (기술보고서 + Qwen3-VL 공식 쿡북 교차) |
| Qwen3-VL | **0~1000 정규화 회귀, 분모 1000** | JSON `bbox_2d` | 공식 쿡북 코드로 확인. **999 분모는 주 규약 아님** |
| Qwen3.5 (4B) | **미확인** | 미확인 | 실존·네이티브 멀티모달·grounding 개선 확인. 규약 미기재 |

추가 확정: smart_resize의 factor는 세대별로 다르다(Qwen2.5-VL 28, Qwen3-VL 32) — **어떤 코드에도 factor를 하드코딩하지 않고 processor config 실물에서 읽는다.** `image_grid_thw`는 `[t=1, grid_h, grid_w]`이고 `grid_h = resized_height // patch_size`이므로 `resized_h = grid_h × patch_size`로 **정확 복원**된다(리사이즈 치수가 factor 배수라 나머지 없음).

## 1. 규약 선언 — configs 데이터화

- `configs/base.yaml`에 coord 블록 1회 선언 (5칸 공통 고정, 칸별 override 금지):
  - `convention: norm_1000` ← **확정 기본값.** 분모는 1000 고정(별도 denom 필드 없음)
  - `target_format: json_bbox2d`
  - `processor: {patch_size, merge_size, factor, min_pixels, max_pixels}` ← 채택 체크포인트 processor config 실물에서 읽어 고정. 런타임에 실제 프로세서 설정과 대조 assert
- **min_pixels/max_pixels·factor를 "5칸 공통 고정 8종" 중 전처리 항목에 편입한다.** ABS_RESIZED에서는 이 값이 좌표 정의 자체이고, NORM_1000이어도 시각 토큰화 동일성(공정성)을 위해 고정 필요
- coord 블록 해시를 5칸 전 run이 MLflow에 로깅해 동일 규약 사용을 증명
- 카나리아 게이트(4절)가 ABS_RESIZED로 판정하면 `convention` 값 1개만 바꾼다 — 코드 경로는 양쪽 다 상비

## 2. 모듈 `vlm/coords.py` — 학습 담당 소유, 의존성 제로 리프

- **import 허용: 표준 라이브러리 + numpy만.** torch/transformers/vlm 내 타 모듈 금지 — 리프 조건은 import 목록 검사 테스트로 강제. D의 `evaluation/`이 학습 스택 없이 import 가능
- **smart_resize는 이 모듈에 두지 않는다 — 자체 구현 금지, transformers import도 금지.** 리사이즈 치수는 항상 인자로 받는다. 근거: 소비자 분석 결과 오프라인 smart_resize가 필요한 지점이 없다 — 채점은 예측 레코드에 로깅된 resized_wh를 쓰고, gold는 원본 픽셀만 저장하며, 정합 대조는 별도 스크립트(transformers import 허용)가 담당
- API (시그니처는 CTO 게이트에서 D와 합의 후 동결. 변경은 의사결정로그 + C·D 양측 승인 + 골든 전체 재통과 3조건):
  - `class BoxConvention(str, Enum): NORM_1000 | ABS_RESIZED | ABS_ORIG` (ABS_ORIG는 항등 — 진단·카나리아 후보용)
  - `class TargetFormat(str, Enum): JSON_BBOX2D | QWEN2_BOX_TOKENS` — 좌표 스케일과 표기 형식은 **독립 축**
  - `@dataclass(frozen=True) class CoordCfg:` convention, patch_size, merge_size, factor, min_pixels, max_pixels. 생성 시 `factor == patch_size * merge_size` assert
  - `to_model_coords(bbox_px_xyxy, orig_wh, cfg, resized_wh=None) -> tuple[int,int,int,int]`
  - `to_orig_coords(bbox_model_xyxy, orig_wh, cfg, resized_wh=None) -> tuple[float,float,float,float]`
  - `resized_from_grid_thw(grid_thw, patch_size) -> (resized_w, resized_h)` — 축 순서 [t, h, w] 반영, 축 순서 단위 테스트 필수
- 동작 규칙:
  - `ABS_RESIZED`에서 `resized_wh=None` → 즉시 ValueError (조용한 기본값 금지)
  - bbox 비활성 데이터셋(`has_bbox=false`) 경로에서 호출되면 `CoordsDisabledError` raise (조용한 0 금지)
  - 역변환 출력은 `[0,W]×[0,H]` clamp + `x1<x2, y1<y2` 검사. 위반 박스는 무효 처리하고 건수 별도 보고 (재프롬프트 금지 준수)
  - 순수 함수, 상태 없음
- 변환 수식: `NORM_1000: m = round(px / orig_dim × 1000)`, 역 `px = m / 1000 × orig_dim` / `ABS_RESIZED: m = round(px × resized_dim / orig_dim)`, 역 `px = m × orig_dim / resized_dim` / `ABS_ORIG: 항등`
- `coords.py` 파일 sha256을 스냅샷 해시 목록에 편입 (논문 재현성 자산)

## 3. 데이터 흐름 — 원본 픽셀 단일 저장, 변환은 정확히 2지점

```
manifest / D4 jsonl : 원본 픽셀 xyxy + (W,H) 병기만. 모델 좌표 저장 금지
  ├─ 정변환 1지점 = 학습 collator:
  │   processor 호출 → image_grid_thw → resized_from_grid_thw → to_model_coords
  │   → TargetFormat 직렬화. 변환 결과 디스크 캐시 금지
  └─ 역변환 1지점 = 추론 스크립트:
      greedy 1회 생성 → json.loads + pydantic 파싱
      (실패 → parse_ok=false, 역변환 미진입)
      → to_orig_coords → clamp·유효성 → 공통 예측 스키마 bbox_px
```

- 채점기(평가 담당 소유)는 bbox_px만 받고 **좌표계를 전혀 모른다** — 단일 채점기 원칙의 좌표 버전
- 예측 레코드 메타: `convention`, `resized_wh`(grid_thw 유래), CoordCfg 해시, transformers 버전 — 사후 감사·재검증용
- **D4 페어 생성은 카나리아 게이트와 독립이다.** 페어는 원본 픽셀만 저장하므로 규약 미확정 상태에서도 생성 가능. 게이트가 막는 것은 통합형 **학습 착수**와 타깃 직렬화 동결뿐 (코퍼스 담당 일정 비커플링)

## 4. 카나리아 게이트 — 통합형 학습 착수 전 필수, 2단

**재시도 금지 원칙과의 관계 (명확화):** greedy 1회·재프롬프트 금지는 5칸 **평가 추론**에 적용되는 원칙이며 사전 점검을 금지하지 않는다. 카나리아도 이미지당 greedy 1회로 돌리되, 게이트 실패 시 원인 수정 후 게이트 재실행은 허용된다(실험 결과 채점이 아니므로). 카나리아 프로브 프롬프트는 본 실험 프롬프트와 별도 산출물이고, 본 실험 프롬프트 동결(한 글자 불변)은 카나리아와 무관하게 학습 착수 시점에 이뤄진다. 카나리아 프롬프트·판정 스크립트도 파일 고정 + 해시.

- **카나리아-1 (합성 도형, 규약 판별):** 로컬 생성 이미지 20장(흰 배경, 무작위 단색 사각형/원 — 정답 bbox를 생성 시점에 정확히 앎). 사전학습 체크포인트에 제로샷 grounding 질의 → 출력을 후보 규약 **{NORM_1000, ABS_RESIZED, ABS_ORIG}** 각각으로 역변환해 IoU 산출, **argmax 판별**
  - **후보 축퇴 방지 조건 (신설):** 원본↔리사이즈 치수가 한 축 이상 2배 이상 차이 나는 해상도를 반드시 포함(아니면 ABS_ORIG와 ABS_RESIZED가 구분 불가), 1000px 근방 해상도는 배제(NORM_1000과 ABS_RESIZED가 축퇴)
  - 999 분모는 후보에서 **제외** — IoU argmax로 1000과 판별 불가능(0.1% 차이)하고 공식 쿡북이 /1000 확정. 999 오용은 골든 픽스처(6절)가 잡는다
  - 게이트: `argmax 규약 == 선언 규약 AND argmax median IoU ≥ 0.5 AND 파싱 성공률 ≥ 0.9`. argmax 불일치 → 하드 실패, CoordCfg 수정 후 재실행. 전 후보 IoU < 0.5 → 판정 보류, 프롬프트/파싱 원인 분리 후 미해결 시 재검토 회부
- **카나리아-2 (실데이터 바닥선):** **학습 풀에서만** 결함 이미지 20장 층화 추출(글로벌 평가셋은 게이트 판단에도 투입 금지 — 격리 불변조건). 규약 판정용이 아니라 (a) 실험설계 3-5 제로샷 기준점 실측 연결, (b) 학습 중 감지의 바닥선. X선에서 IoU 0.0x여도 카나리아-1 통과면 규약은 맞고 도메인 갭 — 두 카나리아가 원인을 분리
- 운영: 결과 JSON(규약별 IoU 표, argmax, 판정, 모델·프로세서·프롬프트 해시)을 MLflow 기록. 학습 진입 스크립트는 통과 기록 부재·무효 시 시작 거부. CoordCfg·프로세서 설정·transformers 버전 중 하나라도 변경 시 게이트 무효화 → 재실행

## 5. 학습 전·중 감지 (좌표 버그는 loss에 안 보인다)

1. **골드 자기채점 (스텝 0 이전, 하드 게이트):** D4 타깃 직렬화 → 역파싱 → to_orig → manifest gold 대조. 기준: **전 박스 좌표 오차 ≤ 축당 양자화 한계(스케일의 1/2), 위반 0건.** (B 원안의 "평균 IoU ≥ 0.99"는 소형 결함에서 양자화만으로 거짓 실패 — 결정적 오차 한계로 교체. IoU는 보조 리포트만)
2. 첫 val 시점 IoU 히스토그램 MLflow 로깅 — median 0.0x 고착 + Class-Jaccard 정상 = 좌표계 사고의 전형 시그니처
3. 규약 판별 메트릭 상시 로깅: val 예측 좌표 max 분포, [0,1000] 범위 내 비율, 역변환 후 경계 밖 비율 (라운드당 스칼라 3개)
4. 연합 칸: 집계 직후 서버사이드 val에서 2·3 동일 산출, **파라미터 norm 로그와 교차 확인** — 집계 버그와 좌표 버그의 IoU 붕괴 증상 분리

## 6. 테스트 자산

- **라운드트립 속성 테스트:** hypothesis 무작위 500조합(시드 고정) + 고정 매트릭스 — 해상도 {1280×720, 640×640, 4032×3024(max_pixels 초과 경로), 1279×719(비배수), 224×224, 56×28, 2560×140, 140×2560(극단 종횡비 — x/y 스왑 최대 노출)} × 경계 박스 {전체, 원점 1px, 우하단 모서리, 좌변 접촉 세장형, 중앙 소형}. 기준 이원화: 최소변 ≥ 20px → IoU ≥ 0.99 / 미만 → 꼭짓점 오차 ≤ 축당 스케일 한계 + IoU > 0(소실 금지). 공통 불변: 경계 내, 순서 보존, x·y 축 독립, 이중 변환 검출(출력 범위 특성 assert)
- **골든 픽스처 (손계산 절대값, 확정 후 수정 금지):** 최소 6종 — NORM_1000 기본, **우측·하단 경계 근접 박스 포함(999 분모 오용은 여기서만 판별됨 — 예: 1280px 폭에서 x=1279 → /1000이면 999, /999면 998)**, ABS_RESIZED(resized_wh를 손계산 값으로 인자 주입 — 모듈이 계산하지 않으므로), 극단 종횡비(스왑), 음성 픽스처(xywh 오해석 값이 불일치임을 assert), max_pixels 초과 경로. 근거 주석 + 출처 URL을 테스트 파일에 기재
- **프로세서 정합 파일럿 스크립트** (coords.py 밖, transformers import 허용): 표본 전 이미지에서 transformers `smart_resize` 직접 호출 치수 vs `image_grid_thw` 복원 치수 전수 대조 — 불일치 0건. ABS_RESIZED 판정 시 좌표 정확성 직결, NORM_1000이면 전처리 동일성 감사용
- **리프 import 검사** + **D 채점기 테스트가 C의 골든 픽스처 파일을 import해 재실행** (가정 인터페이스, 게이트 합의) — 같은 픽스처 통과 = 같은 좌표 해석

## 7. RIAWELC 백업 — null 전파 규칙

- manifest `has_bbox: false` → coord 경로 비활성. 실수 호출은 `CoordsDisabledError`로 크게 실패
- 공통 예측 스키마 `bbox_px`는 nullable(가정 인터페이스). gold null 데이터셋에서 BBox-IoU·mAP 계열은 분모 제외 + 결과표 "N/A(위치 라벨 없음)" 표기 — **0으로 채우면 회복률 헤드라인이 오염된다**. 모델이 낸 bbox는 미채점 + 건수 카운트만 (낯선 데이터 평가는 공통 3클래스 축소 — 실험설계 3-6·8-4 정합)
- 라운드트립·골든 테스트는 백업 시나리오와 무관하게 상시 통과 유지

## 8. A·D 가정 인터페이스 (CTO 게이트에서 동결)

- **A(manifest):** bbox 원본 픽셀 xyxy 컬럼 + 이미지 width/height 컬럼 + `has_bbox` 플래그가 있다고 가정
- **D(공통 예측 스키마):** `bbox_px` nullable, 메타 필드(convention, resized_wh, coord_cfg_hash, transformers_version) 허용, 채점기는 bbox_px만 소비(좌표계 무지), D 테스트 스위트가 `vlm/coords.py` 골든 픽스처를 재실행한다고 가정

# 검증 방법 (구현 후)

1. **정적 스위트:** `pytest tests/test_coords.py` — 라운드트립 매트릭스(고정 픽스처 전수 + hypothesis 500조합, 시드 고정) + 골든 6종(우측 경계 박스로 999 오용 판별 포함) + 리프 import 검사 + CoordsDisabledError·ValueError 경로 + grid_thw 축 순서 테스트. 좌표 관련 코드 변경 시마다 실행
2. **게이트 동작 검증:** 카나리아 스크립트 1회 실행 → MLflow에 규약별 IoU 표·argmax·판정 기록 확인. **고의로 통과 기록을 지우고 학습 진입 스크립트가 시작을 거부하는지 1회 테스트.** CoordCfg 해시를 바꿔 게이트 무효화가 작동하는지도 1회 확인
3. **골드 자기채점 전량:** D4 페어 생성 완료 시 타깃 직렬화 → 역파싱 → to_orig → gold 대조를 전량 실행. 좌표 오차가 축당 양자화 한계(스케일 1/2)를 넘는 박스 0건이어야 학습 착수 허용. 위반 목록·IoU 분포 보조 리포트
4. **오라클 종단 주입 테스트:** gold bbox를 모델 출력 형식(TargetFormat)으로 직렬화한 가짜 생성문을 추론 파이프라인에 주입 → 파싱·역변환·공통 스키마 기록·채점까지 통과시켜 IoU = 1.0(양자화 한계 내) 확인 — 역변환 이중 적용·미적용을 잡는 유일한 종단 검사
5. **프로세서 정합 전수 대조 (파일럿):** 학습 풀 표본 전 이미지에서 transformers smart_resize 직접 호출 치수 vs processor 실행 후 image_grid_thw 복원 치수 비교 — 불일치 0건. 1건이라도 나오면 구현 중단·원인 규명
6. **파인튜닝 스모크:** 페어 500건 1 epoch 학습 후 학습 이미지 재추론 — BBox-IoU ≥ 0.5 궤도면 정상, ≤ 0.1이면 좌표계 불일치를 제1 용의자로 조사 (0.055 붕괴 사례의 재현 신호)
7. **학습 중 로깅 확인:** 첫 val 시점 IoU 히스토그램·규약 판별 메트릭 3종이 MLflow에 실제로 찍히는지 파일럿 1회 확인, median이 카나리아-2 바닥선 이상인지 대조
8. **감사 로그·재현성:** 예측 레코드 표본에서 convention·resized_wh·CoordCfg 해시·transformers 버전이 전부 기록되고 **5칸 동일**한지 스크립트 대조. `coords.py` sha256이 5칸 전 run에 동일 로깅되었는지 결과표 추출 스크립트에서 assert
9. **트랙 간:** D의 채점기 테스트가 C의 골든 픽스처 파일을 import해 통과하는지 — CTO 게이트 산출물로 D에 요구

## 실패 모드

- F1 규약 오인 (Qwen3.5가 NORM_1000이 아닌데 그렇게 선언, 또는 역) — 사전학습 grounding 폐기·IoU 0.938→0.055형 붕괴. 방어: 카나리아-1 argmax 하드 게이트
- F2 데이터 생성과 채점이 서로 다른 규약 — loss 정상·val IoU 고착. 방어: 골드 자기채점(스텝 0 이전, 좌표 오차 한계 위반 0건)
- F3 to_model·to_orig가 같은 방향으로 함께 틀림 — 라운드트립 통과·절대값 오류. 방어: 손계산 골든 픽스처
- F4 역변환 이중 적용 또는 미적용 — 좌표가 배율/역배율로 왜곡. 방어: 역변환 지점 1곳 강제 + 오라클 종단 주입 테스트 + 출력 범위 특성 assert
- F5 collator가 리사이즈 치수를 자체 재계산해 프로세서와 어긋남 — 전 샘플 계통 오차. 방어: 모듈에서 smart_resize 제거(치수는 grid_thw 복원값 인자만) + 파일럿 전수 대조
- F6 min/max_pixels·factor가 학습·추론·칸 간 상이 — ABS_RESIZED 좌표 기준 이동, NORM_1000이어도 전처리 공정성 훼손. 방어: configs 단일 선언 + 5칸 공통 고정 편입 + 런타임 프로세서 대조 assert + 예측 레코드 해시
- F7 x/y 스왑·xyxy↔xywh 혼동·grid_thw 축 순서 혼동 — 비정방 이미지에서만 붕괴. 방어: 극단 종횡비 픽스처 + 음성 픽스처 + 축 순서 단위 테스트
- F8 999 분모 오용 (쿡북 유틸 복붙 유입) — 우하단으로 갈수록 1~2px 계통 편향. 방어: 우측·하단 경계 근접 골든 픽스처 (카나리아로는 판별 불가)
- F9 모델 좌표를 D4 스냅샷·캐시에 저장 — 모델 교체 시 오염 잔존, 스냅샷 해시 불변 원칙 충돌. 방어: 저장 계층 원본 픽셀 단일 규칙 + 스냅샷 스키마 리뷰 체크리스트
- F10 transformers 버전 업그레이드로 프로세서 리사이즈 거동 변경 — 세션 간 좌표 기준 이동. 방어: 버전 lock + 게이트 무효화 조건 + 예측 레코드 버전 로깅 + 골든 재실행
- F11 D가 역변환을 재구현해 드리프트 — 트랙 간 채점 불일치, 단일 채점기 공정성 붕괴. 방어: 리프 모듈 단일 소스 + D의 골든 픽스처 재실행 + 리뷰 체크리스트(evaluation/ 내 스케일 곱셈+클리핑 패턴 금지)
- F12 집계 버그와 좌표 버그의 증상 혼동 (둘 다 연합 칸 IoU 붕괴) — 방어: 파라미터 norm 로그와 교차 확인으로 원인 분리
- F13 RIAWELC 백업 경로에서 bbox 지표가 0으로 기록 — 회복률·유지율 헤드라인 오염. 방어: null 전파 + N/A 표기 + CoordsDisabledError
- F14 카나리아 해상도 선정 실패로 후보 규약 축퇴 (리사이즈가 거의 안 일어나거나 ~1000px 해상도) — argmax 판별 무력화. 방어: 원본↔리사이즈 2배 이상 차이 해상도 필수 + 1000px 근방 배제 조건
- F15 생성 좌표가 이미지 밖/음수/순서 위반 — IoU 계산 오류. 방어: clamp + 유효성 검사 + 무효 박스 건수 별도 보고 (재프롬프트 없이)

## 논문 명시 문장 초안

- 학습 타깃의 bbox 좌표는 채택 VLM의 네이티브 규약을 따랐다. Qwen 계열은 세대별로 규약이 상이한데(Qwen2-VL: 0–1000 정규화, Qwen2.5-VL: 입력 이미지 절대 픽셀, Qwen3-VL: 0–1000 정규화 회귀), 채택 모델의 규약은 문서가 아니라 사전학습 체크포인트에 대한 합성 도형 제로샷 판별 실험(후보 규약별 역변환 IoU 비교)으로 확정하였다.
- 데이터 파일에는 원본 픽셀 좌표만 저장하고, 모델 좌표계로의 변환은 학습 데이터 조립 시 1회, 원본 좌표계로의 역변환은 추론 직후 1회만 수행하였으며, 두 변환은 sha256으로 고정된 단일 공유 모듈을 다섯 칸과 채점기가 동일하게 사용하였다.
- BBox-IoU는 모델 출력 좌표를 원본 이미지 좌표계로 역변환한 뒤 계산하였다. 선행 연구에서 좌표계 불일치 시 IoU가 0.938에서 0.055로 붕괴한 사례가 보고되어 있어, 좌표계 일치를 학습 착수 전 게이트로 검증하였다.
- 시각 전처리 파라미터(min_pixels/max_pixels 등 동적 해상도 설정)는 좌표 정의와 시각 토큰화에 직접 관여하므로 다섯 칸 공통 고정 항목에 포함하였다.
- 위치 라벨이 없는 데이터셋(RIAWELC)에 대한 평가에서 위치 계열 지표는 0이 아니라 N/A로 처리하여 회복률 산출에서 제외하였다.

  **기본값:** 채택 체크포인트 processor config 확정 직후. 그 전까지는 NORM_1000·극단 종횡비·음성 픽스처만으로 스위트 운용(ABS_RESIZED 픽스처는 자리만 예약)

## 기각한 설계 요소

- B의 CoordSpec denom 필드와 카나리아 후보의 999 변종 — 기각. Qwen3-VL 공식 2d_grounding 쿡북 코드가 /1000이고(직접 확인), 999는 일부 유틸에서만 보고된 비주류 경로(DeepWiki 경유). 결정적으로 999 vs 1000은 좌표 차이 0.1%라 IoU argmax 판별이 물리적으로 불가능해 카나리아 후보로 무의미하다. 분모는 1000 고정으로 확정하고, 999 오용 유입은 우측·하단 경계 근접 골든 픽스처가 잡는다
- B의 coords.py 내 smart_resize 자체 구현 — 기각. A의 '수식 사본은 라이브러리 반올림 분기 변경 시 조용히 낡는다'는 공격이 유효하다. 대체: 모듈은 리사이즈 치수를 계산하지 않고 프로세서 실호출 산출물(grid_thw 복원값)을 인자로만 받는다
- A의 '2순위 폴백 — coords.py 경로에서 transformers smart_resize를 직접 import' — 기각(리프 조건과 충돌). 소비자 분석 결과 오프라인 smart_resize가 필요한 지점이 없다: 채점은 예측 레코드에 로깅된 resized_wh를 쓰고, gold 생성은 원본 픽셀만 저장한다. 정합 대조 용도만 남으므로 coords.py 밖의 별도 파일럿 스크립트로 이동
- B의 resize_factor: int = 28 기본값 — 기각. factor는 세대별로 다름이 확인됨(Qwen2.5-VL 28, Qwen3-VL 32, qwen-vl-utils는 필수 인자). 기본값 금지, processor config 실물에서 읽고 factor == patch_size × merge_size assert
- B의 '카나리아 통과 전 D4 페어 생성 착수 금지' — 기각(과잉 커플링). 페어는 원본 픽셀만 저장하므로 좌표 규약과 독립적으로 생성 가능하다. 게이트 범위를 '통합형 학습 착수 + 타깃 직렬화 동결'로 축소해 코퍼스 담당 일정과 비커플링
- B의 골드 자기채점 기준 '전량 평균 IoU ≥ 0.99' — 기각. 소형 결함(기공 등 10px급)에서는 양자화 오차만으로 박스당 IoU가 0.6~0.8까지 내려가 거짓 실패한다. 대체: 전 박스 좌표 오차 ≤ 축당 양자화 한계(스케일 1/2) 위반 0건이라는 결정적 기준. IoU는 보조 리포트
- A·B 공통 기각 유지: qwen-vl-utils의 resized_height/resized_width 명시 주입 경로 — 값을 우리가 넣으면 또 하나의 진실 소스가 생긴다. 프로세서가 계산하고 우리는 읽는다
- common/ 최상위 디렉터리 신설 — 기각(B의 논거 채택). 트랙별 소유 경계가 모호해진다. vlm/coords.py 학습 담당 소유 + 리프 조건으로 D import 문제 해소
- A의 세부 사실 '현행 qwen-vl-utils는 patch 16 × merge 2 = 32가 관례' — 부분 기각(부정확). 직접 확인 결과 vision_process.py의 image_patch_size 기본값은 14(factor 28)이고 32는 Qwen3-VL 호출 시 값이다. 다만 '하드코딩 금지, config에서 읽어라'는 결론은 오히려 강화됨

## 웹 출처로 확인한 사실 / 미확인

- Qwen2.5-VL은 절대 좌표를 쓴다 — 공식 기술보고서 원문: "Qwen2.5-VL uses coordinate values based on the actual dimensions of the input images during training to represent bounding boxes and points" (https://arxiv.org/html/2502.13923v1). '입력 이미지 = smart_resize 후 이미지' 해석은 HF 모델 카드 discussion #13(커뮤니티, Qwen 팀 직접 답변은 없음: "relative to your resized image size if you are resizing", https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct/discussions/13)과 Qwen3-VL 공식 쿡북의 교차 진술로 뒷받침됨
- Qwen3-VL은 0~1000 정규화로 회귀 — 공식 쿡북(2d_grounding.ipynb) 명시 문구: "Qwen3-VL's default coordinate system has been changed from the absolute coordinates used in Qwen2.5-VL to relative coordinates ranging from 0 to 1000", 변환 코드는 `int(bbox_2d[0] / 1000 * width)` 즉 분모 1000 (https://raw.githubusercontent.com/QwenLM/Qwen3-VL/main/cookbooks/2d_grounding.ipynb). 이 문구는 동시에 Qwen2.5-VL 절대 좌표의 1차 교차 확인이기도 하다
- 999 분모는 일부 쿡북 유틸에서만 보고됨(DeepWiki: "some implementation utilities in the cookbooks use 999", https://deepwiki.com/QwenLM/Qwen3-VL/5.2-spatial-understanding-and-2d-grounding) — 주 grounding 쿡북은 /1000이므로 모델 규약이 아니라 유틸 비일관성으로 확정
- transformers smart_resize: 시그니처 `smart_resize(height, width, factor=28, min_pixels=56*56, max_pixels=14*14*4*1280)`, round→(max 초과 시 floor·min 미달 시 ceil) 3분기, 종횡비 > 200이면 ValueError, 프로세서는 factor=patch_size×merge_size(14×2=28)로 호출 (https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen2_vl/image_processing_qwen2_vl.py)
- image_grid_thw는 이미지당 [1, grid_h, grid_w]이고 grid_h = resized_height // patch_size, grid_w = resized_width // patch_size — 리사이즈 치수가 factor(=patch×merge) 배수이므로 resized_h = grid_h × patch_size로 나머지 없이 정확 복원 가능 (동일 transformers 소스에서 확인)
- 현행 qwen-vl-utils(QwenLM/Qwen3-VL 저장소): smart_resize의 factor는 기본값 없는 필수 인자, min/max_pixels 미지정 시 토큰 수 기준(IMAGE_MIN_TOKEN_NUM=4, IMAGE_MAX_TOKEN_NUM=16384 × factor²) 계산, fetch_image는 resized_height/width 키를 smart_resize에 재통과시켜 factor 배수로 스냅, SPATIAL_MERGE_SIZE=2·image_patch_size 기본 14 (https://raw.githubusercontent.com/QwenLM/Qwen3-VL/main/qwen-vl-utils/src/qwen_vl_utils/vision_process.py)
- 리사이즈 배수 factor는 세대별 상이: Qwen3-VL 32, Qwen2.5-VL 28 ("rounded to the nearest multiple of 32 (32 for Qwen3VL, 28 for Qwen2.5VL)" — vLLM 문서·검색 결과, https://docs.vllm.ai/en/v0.18.1/api/vllm/model_executor/models/qwen2_5_vl/ 외) — factor 하드코딩 금지 결론의 근거
- Qwen3.5는 실존: 2026-02-17 발표, 2026-03-02 0.8B/2B/4B/9B Apache 2.0 공개, early-fusion 네이티브 멀티모달, 공간 grounding에서 Qwen3-VL 대비 개선 주장 (https://www.alibabacloud.com/blog/qwen3-5-towards-native-multimodal-agents_602894, https://simonwillison.net/2026/Feb/17/qwen35/, https://huggingface.co/Qwen/Qwen3.5-4B). grounding 좌표 규약은 이들 자료에 미기재
- vLLM의 Qwen VL 계열 전처리는 HF 프로세서 경로를 사용해 원 리사이즈·정규화·패치 추출 거동을 보존한다고 서술됨 (vLLM 문서·검색 결과) — 단 grid_thw 수준의 세부 일치는 미검증
- 미확인: Qwen3.5 4B의 grounding 좌표 규약·타깃 표기 — 모델 카드·블로그 미기재. 카나리아-1 실측이 최종 판정 (문서와 실거동이 다를 수 있으므로 실측이 정본)
- 미확인: Qwen3.5 프로세서의 image_grid_thw 반환 여부·patch/merge 값 — 채택 시점 processor config 실물 확인 필요
- 미확인: 파인튜닝 시 transformers 프로세서/채팅 템플릿이 좌표를 자동 재조정하는지 — 공식 이슈(QwenLM/Qwen3-VL #1486)도 미답변 상태. 핀 버전 소스 직독 + 골드 자기채점이 방어선
- 미확인: vLLM 경로에서 resized 치수(grid_thw 상당 정보) 획득 방법 상세 — NORM_1000 확정 시 좌표 리스크 소멸, ABS_RESIZED 판정 시에만 구현 전 검증 필수
- 미확인: Qwen2-VL의 [0,1000) + 특수 박스 토큰 형식 — 양 설계안 진술 일치하고 비채택 경로(Qwen2-VL 후퇴 시에만 유효)라 직접 재검증 생략
