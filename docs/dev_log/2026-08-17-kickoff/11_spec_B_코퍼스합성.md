# 1. 계약 #3 확정안: `corpus/limits.csv`

## 1-1. 왜 이 파일이 가장 위험한가

판정 골격 생성기(B), RAG 청크 메타데이터(D), 채점기 판정 정합성 정답(D) 세 소비처가
전부 이 표에서 나온다. 적대 검증이 확인한 대로 위험은 두 층이다: ① 세 곳이 각자 표를
읽으면 어긋난 순간 판정 정합성 지표가 통째로 무의미해진다 ② CSV만 공유하고 **해석
코드를 각자 짜도** 같은 붕괴가 파생 계층에서 재현된다. 따라서 이 계약은 파일 하나 +
공식 로더 하나 + 공유 평가기 하나 + **D 소비용 파생 함수 3종**까지를 묶어서 얼린다 (§1-4).

## 1-2. 컬럼 전수 명세

계약 #3의 최소 9컬럼(`defect_code, thickness_min, thickness_max, quality_level,
limit_type, limit_value, unit, clause_id, source_doc`)은 전부 유지한다(널 허용 의미는
규칙별로 정의). 확장 컬럼은
전부 추가형이며 사유를 붙였다. 확정 후 컬럼 변경은 승인 대상이다.

**계약 변경 절차** (2026-08-21 실측 교훈). `inspection_method` 신설 때 통지 문서는 구현
36시간 전에 저장소에 올라갔고 D 스펙도 그 축을 반영했지만, **D의 픽스처 코드는 갱신되지
않아 필수 필드가 들어가는 순간 채점기 테스트 9건이 깨졌다.** 통지 시점이 아니라 **필수
필드 승격 시점**이 문제였다. 그래서 다음을 절차로 둔다.

1. 통지는 구현 커밋 **전에** 한다 (소비처 3곳을 명시: 골격 생성기·RAG 청크 메타·채점기
   정답 기준). 한 곳만 놓쳐도 그 소비처가 즉시 깨진다.
2. **필수(required) 필드로 승격하는 변경은 소비 담당의 반영 완료를 확인한 뒤 머지한다.**
   추가형이라도 `required`면 소비처 픽스처가 그 순간 실패한다. 추가형이라는 말이
   무해하다는 뜻은 아니다.
3. 유예가 필요하면 기본값을 둔 선택 필드로 먼저 넣고, 소비처 반영 후 필수로 올린다.

| V10 | 샘플링 실현성: 활성 행 전수에 대해 구간 내 최소 t 기준 유효 한계 L ≥ 0.1(그리드 10칸) 확인. 미달 행 목록을 보고하고 scope=excluded 여부를 판단한다. configs 교차 검증(t_sample_max > 활성 행 최대 thickness_min) 포함 (S1-8·S1-9) |
| V11 | 통과본 sha256 기록 — 이후 모든 산출물 provenance에 각인 |

추가로 **커버리지 리포트**: 재질 × 결함 4종 × 품질수준 격자의 공백 목록과 사유
분류(표준에 없음 / 미전사 / 유료 전용 / excluded)를 출력한다. 실존 조합 열거(§4)와
수량 보고(§7)의 근거 문서다.

## 1-3. 허용치 표현 규약: 전역, 행별 예외 없음

- **두께 구간은 반열림 `[min, max)`, max 공란 = +∞.** t = min이면 포함, t = max면 다음
  구간. 원문이 "8 초과 12 이하"류면 **CSV 입력 시점에 반열림으로 환산**하고 원문 표기는
  `limit_expr`·`note`에 보존한다. t=12가 [8,12)와 [12,25)에 걸리는 문제는 데이터가 아니라
  규약이 결정한다. (구간 개폐 컬럼 분리안은 불채택: 진입 시 정규화가 소요 자체를 없앤다)
- **유효 한계** L = const→`limit_value` / prop_t→`limit_factor`×basis / prop_t_cap→
  min(factor×basis, cap) / none_permitted→없음(결함 존재 = 불합격).
- **부등호**: 기본 `le`(경계값 합격, ISO 5817 표기 관례 "≤ 한계"). 원문이 "미만"이면
  `limit_op=lt`. 이 규약은 골격 생성·경계 샘플링·D 판정 정합성 재계산 세 곳에 동일 적용.
- **수치는 전부 Decimal, 0.01 단위 양자화(ROUND_HALF_UP) 후 비교.** 양자화 대상은
  크기·**두께**·한계·margin 전부다(두께 누락이 행 재선택 붕괴를 만든다, S2-3).
  float 직접 비교 금지. 텍스트로 왕복 가능한 고정 소수만이 "골격 = 생성문 = 채점 기준"
  삼자 일치를 보장한다.

금지 ② `corpus/derived/` 수기 수정 금지 ③ 판정·한계 산출을 `limit_eval` 밖에서 재구현

⑤ 다결함 이미지 verdict 합성을 `aggregate_verdicts` 밖에서 재구현 금지 (D 포함)
⑥ C가 통합·연합 `n_k`를 manifest에서 파생하는 것 금지: `counts.json`만 (§7-5).

**공유 평가기의 공통 모드 실패**: 생성과 채점이 같은 judge()를 쓰므로 평가기 버그는

3중 교차 검증한다: ① **골든 케이스 표**: 사람이 손으로 계산한 30건+(등호·경계 ±ε·
비율형·구간 경계·불허 포함)를 CSV로 두고 B·D의 CI가 각자 통과 (정답 소스가 코드가
아니라 사람) ② **뮤테이션 감도**: verdict 반전 오염본을 채점기에 투입해 정합성 지표가
실제로 붕괴함을 증명 ③ **전문가 표본 검토**(§6 3단계)의 시트에 부등식 계산란을 넣어
규칙 산출물을 사람이 재계산하는 유일한 지점으로 삼는다.

`corpus/derived/`는 `docs/개발규약.md`의 저장소 구조에 없는 신설 하위 디렉터리다(파생 전용 구역의

# 3. 문서 파싱 경로 (함정 구간 #7)

## 3-1. 문서 등록부와 라이선스 등급

`corpus/parse/sources.yaml`: 문서 1건 1엔트리, 파싱 착수 전 등록 필수. 미등록 문서
유래 행은 limits.csv 반입 금지. 필드: `doc_id`(전역 유일, limits.csv `source_doc`이 참조) /
`title` / `publisher` / `edition_year` / `url`(수기 전사는 열람 창구 명칭) / `access_date` /
`license_class` / `sha256`(파일 미보유 시 null + 사유) / `allowed_use` /
`canonical_priority`(정본 서열: 기본값 KR > IACS47 > KS 전사).

| license_class | 해당 문서 | 표 수치 추출 | 원문 텍스트 corpus·색인 반입 |
|---|---|---|---|
| OPEN | IACS Rec.47, KR 규정 PDF, 대한용접접합학회지(KCI), KIPRIS 특허 | 가능 | 가능 — 단 **콘텐츠 수준 스크린** 통과분만 (§3-6) |
| VIEW_ONLY | KS B 0845 등 e나라표준 열람본 | 가능 (수기 전사 한정) | 불가 — 재서술문만 |
| PAID | ISO 5817·10675·10042, AWS Handbook | **직접 추출 금지** | 금지. 수치는 OPEN/VIEW_ONLY 재수록 경유만, `restated_from`에 원 표준 기록 |
| CITED_FACT | ISO 6520-1 코드 번호·명칭 | 코드 체계로 사용 | 사실 정보라 코드·명칭만 |

**저작권 금지 대상의 정밀 정의** (자기모순 해소, D2-9): VIEW_ONLY·PAID에서 금지되는
것은 조판 이미지·화면 캡처·**문장 단위 원문 텍스트**다. 수치·조항번호·결함코드의
**구조화 전사 CSV는 사실 정보로서 허용**된다. 단 전사 CSV에 원문 문장 컬럼을 두지
않는다. OPEN 원본 PDF도 저장소에 커밋하지 않는다(재배포 조건 미확인): `raw/` 로컬
보관 + sha256·URL·access_date만 기록.

## 3-2. 경로 결정 트리 (분기 조건은 전부 판정 가능 기준)

```
[입구] PDF 파일 확보 가능?
 ├ 아니오 (VIEW_ONLY) ────────────────→ 경로 M: 수기 전사 (이중 입력 대조)
 ├ 아니오 (PAID) ─→ 직접 경로 없음. OPEN/VIEW_ONLY 재수록분만 반입
 └ 예 → 텍스트 레이어 검사 (pdfminer 추출 문자수/페이지 < 50자?)
     ├ 예 (스캔본) ─→ 표 문서: 경로 M / QA 원문: 폐기·대체 논문 선택
     └ 아니오 ─→ 경로 D: Docling → 표 단위 수용 판정 (§3-3)
         ├ 통과 ─→ accepted 승격
         └ 거부 ─→ 경로 P: pdfplumber (+수기 보정) → 동일 판정기 재통과
             ├ 통과 ─→ accepted 승격 (보정 셀 이력 기록)
             └ 재거부 ─→ 경로 M
```

- **OCR 미도입.** 허용치 수치의 OCR 오독(3→8, 0.2→0.7)은 침묵 오염이라 탐지가 어렵고,
  표 문서는 문서당 수십 행 규모라 수기 전사가 더 싸고 정확하다. 텍스트 레이어가 있는
  문서도 Docling OCR 옵션은 끈다.
- **강등은 단방향(D→P→M), 강등 단위는 표.** 한 표는 정확히 한 경로의 산출물.
- 초기 배정: IACS47→D / KR 규정→D(실패 시 P: HWP 변환 괘선 표는 P 튜닝 예산 선배정) /
  KS-ST·KS-AL→M / KCI 논문→D(표 추출 대상 아님, QA 원문 전용).
- e나라표준 열람 제약: 수기 전사가 기본 대체 절차. 열람 자체가 막히면 KR·IACS 대응
  조항으로 대체 + 커버리지 공백 보고, KS 인쇄본 소액 구매는 별도 판단 사항이다. 뷰어 스크래핑·
  화면 캡처 저장은 이용 조건 위반 소지로 금지.

## 3-3. 자동 추출과 수용 기준 (정량)

**Docling 설정·버전 고정**: `docling`·TableFormer 버전을 `uv.lock` 고정, 실행마다 버전·
모델 가중치 해시를 처리 이력에 기록. TableFormer accurate 모드, OCR off, 페이지 좌표
보존. **스냅샷 확정 전 동일 입력 전체 재실행 1회로 산출 sha256 일치 확인**: 불일치
원인 제거 전 확정 금지. 산출물: `{doc_id}.md`(제목 계층: D 조항 청킹 입력) +
표별 원시 CSV(**가공 없는 원시 추출**, fill·정규화 금지) + meta.json.

**TableExpectation** (`expectations/`, 표당 1회 사람이 육안 등록): **대상 표 단위 식별**
(페이지 + 앵커 셀): "문서당 표 수" 검사가 아니라 "기대 표가 전부 발견되는가"를 본다
(Docling의 목차·이력표 잡검출 오탐 제거, D1-10). 필드: 기대 열 수 / 수치 열 목록 /
앵커 셀 4개(모서리 3 + 중앙 1, 원문 값 사전 등록) / **기대 각주·비고 개수** /
**페이지 걸침 선언**(걸침 범위) / **품질수준 → 열 매핑**(언피벗이 코드 추론이 아니라
이 등록값을 읽는다, D2-6).

수용 판정은 **표 단위 전체 수용/거부** (셀 단위 부분 수용 금지: 부분 오염이 전체
오염보다 탐지 어렵다):

| 검사 | 거부 조건 |
|---|---|
| 기대 표 발견 | TableExpectation의 대상 표 미발견 |
| 구조 정합 | 래그드 행 존재, 헤더 행 검출 실패 |
| 헤더 매칭 | 기대 키워드 매칭 열 < 기대 열 수 |
| 수치 파싱률 | 수치 기대 셀 중 파싱 성공 < **98%** |
| 빈 셀 비율 | > **5%** (스팬 병합 해제 후 기준) |
| 페이지 병합 | 걸침 선언 없는 병합 시도, 열 수 불일치 |
| 앵커 대조 | 4셀 중 **1건이라도 불일치 → 즉시 거부** |
| 각주 검출 수 | 기대 각주·비고 개수와 불일치 → 거부 (마커 없는 비고 침묵 통과 차단, D1-6) |

통과 표도 무작위 10% 셀 사람 원문 대조 후 accepted 확정. **수용 시점에 산출 CSV
sha256을 처리 이력에 기록**: 이후 변경은 V0에서 걸린다.

## 3-4. 표 정규화와 변환 규칙 (경로 D·P·M 공통, accepted CSV에 단일 변환기)

| 병리 | 규칙 |
|---|---|
| 품질수준 매트릭스형 표 | wide→long **언피벗**. 열 매핑은 TableExpectation 등록값 사용. 1행 = (결함×구간×수준) 1조합 |
| 병합 셀 | 세로 fill-down → `filled_v`, **가로 스팬은 스팬 폭만큼 행 복제** → `filled_h` (균열 "불허" 3열 스팬 대응, D1-12). 원시 CSV에는 fill 금지, 변환 단계에서만 |
| 페이지 걸침 표 | 걸침 선언 + 열 수 일치 + 페이지 연속이면 병합. **반복 헤더 행은 시그니처 일치 시 데이터에서 제거하고 이력 기록**. 무헤더 연속 단편은 걸침 선언이 있으면 병합 허용 (D1-7) |
| 각주·단서 | 스캔 범위 = 데이터 셀 마커 + **표제목·컬럼 헤더 마커 + 표 하단·직후 문단의 비고/주기(마커 무관)**. 각주가 허용치를 바꾸는 행은 자동 반입 금지 → 수기 판정 큐 |
| 수식형 셀 ("0.2t, 최대 5") | `parse_limit_cell`이 limit_rule·factor·cap·**ratio_basis**(수식의 변수 문자 보존)로 도출. basis 식별 불가·파싱 불가는 오류가 아니라 **보류 값** 반환 → 수기 판정 큐 |
| 한국어 경계 어휘 | 사전: 이하·이내→le, 미만→lt, 이상·초과→방향 반전 규칙(거부조건문 "넘는 것은 불허" 포함), 조사 제거("3mm를"). **전 토큰 소진 원칙 — 문법이 소비하지 못한 잔여 토큰이 있으면 무조건 보류** (관대 파싱이 스펙 위반이 되도록, D1-3) |
| 괄호 표기 | 문법 기반: 괄호 내용이 순수 수량 + 비SI 단위이고 본문 값과 환산 일치할 때만 병기로 제거. 괄호 안에 최대/이하/한계 어휘 또는 SI 수량("0.2t(최대 5mm)")이면 **수식형 파서의 상한 절로 라우팅**. 판별 불능 → 보류 (D1-4) |
| 유니코드·표기 | NFC 정규화, 변환표 YAML 단일 파일(㎜→mm, ≦→≤, 전각→반각, Ø·φ→직경 …). **변환표 미등재 문자는 중단** — 조용한 통과 금지. `숫자,숫자` 인접 패턴은 소수점 콤마 후보로 자동 해석 없이 보류 (D1-14) |
| 두께 개구간 ("25 초과") | 반열림 규약으로 환산해 thickness_min/max에 기록, 원문은 limit_expr 보존. 매직 넘버(999) 금지 |
| 스코프 밖 결함 행 | 사상표 밖 defect_code(언더컷 등)는 오류가 아니라 `out_of_scope.csv`에 기록하고 반입만 제외 — 무기록 드롭 금지 (D1-11) |

**수기 판정 큐**: 보류 셀·각주 전개·V7/V9 위반의 해소는 전부
`manual_adjudications.jsonl`을 경유한다(원시 provenance, 셀·각주 원문, 결과 행들, 근거
한 줄, 판정자, 일자). **스냅샷 범위에 포함.** 왕복 대조(아래)는 수기 판정 유래 행을
원시 셀 대신 이 기록과 대조한다. 면제가 아니라 대조 대상 교체다 (D2-3). 미해소 큐
항목은 W2 데이터 확정 시점까지 판정 미완이면 해당 조합을 생성에서 제외하고 누락 보고.

**변환기 시그니처** (순수 함수):

```
normalize_cells(raw_table) -> table              # 유니코드·단위 정규화만
expand_spans(table, expectation) -> table        # 가로·세로 스팬 전개 + filled 마킹
unpivot_matrix(table, quality_col_map) -> records
parse_limit_cell(cell) -> LimitSpec | 보류
to_limits_rows(records, doc_meta, clause_map) -> [LimitsRow] + out_of_scope
emit_limits_csv(rows) -> sha256                  # 정렬·중복 검사 후 원자적 쓰기 + git commit 기록
```

**변환 검증**: G0(§1-2)이 전담한다. 왕복 대조는 각 행을 provenance(doc·table·row·
**source_col**)로 역참조해 accepted 원시값과 **셀 단위** 대조하며, 열 매핑은 순방향
코드가 아니라 TableExpectation 등록 매핑으로 역참조한다(파서 자기검증 한계 완화, D2-6).

변환기 단위 테스트: 부등식 어휘(이하/미만/초과·거부조건문 반전) / "0.2t(최대 5mm)" /
"0,2 t" 콤마 보류 / 전 토큰 소진 보류 / ratio_basis 보존("0.25s") / 스팬 전개와 보존성
(**스팬은 스팬 폭으로 계수**: 변환 전 수치 셀 수 = 변환 후 행 수) / 반복 헤더 제거 /
각주 스캔 3범위 / ㎜·전각 정규화와 미등재 문자 중단 / 개구간 환산 / V3·V9 검출.

## 3-5. 처리 이력 (`processing_log.jsonl`): 1행 = 표 1개 × 경로 시도 1회, 실패 시도 포함

| 필드 | 내용 |
|---|---|
| `doc_id`, `doc_sha256` | 등록부 참조. M 경로는 sha256 null + 열람 일시 |
| `table_id`, `source_pages` | 표 식별자, 페이지(걸침 시 범위) |
| `route`, `attempt` | D/P/M, 시도 차수 |
| `tool_version` | docling/pdfplumber 버전 + TableFormer 모델 해시 (M은 null) |
| `judgement` | 수용 여부, 검사별 수치(파싱률·빈 셀·앵커 n/4·각주 수), 실패 사유, **산출 CSV sha256** |
| `corrected_cells` | P 경로 수기 보정: 셀 좌표·전후 값 |
| `resolved_cells` | M 경로 diff 해소: 셀 좌표·A값·B값·확정값·확정자 (건수만 남기지 않는다, D2-7) |
| `transcriber`, `verifier` | M 경로 입력자·대조자 (동일인 금지), diff 건수 |
| `status`, `next_route`, `timestamp`, `output_path`, `notes` | 상태·강등 대상·일자·경로·특기 |

**경로 M 절차**: 전사자 A 입력 → B가 A 결과를 열람하지 않고 독립 재입력 → 셀 단위
diff → 불일치만 원문 재확인 확정, **A·B 최초 입력본은 불변 보존**(반복 입력분 별도
파일). 1인 체제 불가피 시 48시간 시차 본인 재입력 + 앵커 전수 재대조로 강등하고 이력에
명시. 수기 CSV도 수용 판정기의 구조·파싱률 검사를 동일하게 통과해야 한다.

문서별 최종 경로 요약과 논문 부록 "문서별 처리 경로 표"는 이 파일에서 스크립트로
생성한다. 손으로 옮겨 적지 않는다.

1. limits.csv의 임의 수치는 `rule_id → source_doc·page·table·row_label →
   processing_log(해시 결속) → raw/ 원본`으로 분 단위 역추적 가능해야 한다.

   VIEW_ONLY 문서의 조항을 색인에 세우는 실체는 **limits.csv 스냅샷에서 생성한 조항

3. OPEN 문서의 corpus·색인 반입에 **콘텐츠 수준 스크린**: 유료 표준 식별자 패턴 +

   (문서 단위 검사로는 못 보는 제3자 저작물 전재를 막는다).
4. 공개 QA 텍스트 4종(약 57,000행)은 배제 확정: 파싱 경로 진입 금지.

# 4. 판정 골격 생성기 (함정 구간 #6)

## 4-1. 허용치 형태 분류와 범위

F1 절대 스칼라(≤3mm) / F2 기준치수 비례(≤0.1t) / F3 비례+상한(≤min(0.2t, 5)) /
F4 불허 / F5 비율(%) / F6 기준 길이당·시야당 누적(100mm당 ≤25mm, KR 결함점수 합산).
**F6은 이 연구의 적용 범위 밖이다. 기능 미지원이 아니라 판정 단위가 다르다.**

> **판정 단위 불일치** (총괄 판정 근거, 논문 한계 절에 이 표현으로 싣는다): 누적형은
> **용접부(또는 촬영 시야) 단위** 판정인데 우리 데이터 단위는 **이미지 1장**이다. 중복
> 묶음 ID는 누수 방지용 군집이지 용접부 식별자가 아니며, 필름·용접부 ID의 존재 여부는
> A의 Q10에서 아직 미확인이다. 즉 누적 판정에 필요한 집계 단위를 데이터가 제공하지
> 못한다. 스케일 메타데이터가 확보되고 용접부 ID가 존재하면 승격 가능한 항목이다.

CSV에는 싣되 `scope=excluded`로 선언 배제하고 건수를 보고한다(한계 절: 누적형 판정
사례가 corpus에 없다).

**verdict의 의미론**: 골격의 verdict는 **인용 조항(제약) 기준 판정**이다. 같은 조합에
limit_type이 다른 복수 제약(낱개 지름 + 누적 비율)이 공존할 수 있으므로(V3 그룹 키
근거), 이미지 수준 최종 합부는 조립 단계(§4-6)에서 관측 결함·적용 가능 제약의 AND로
만든다. 이 정의는 D의 판정 정합성 지표("인용 조항의 허용치와 실측값 → 합부")와 정확히
일치한다.

## 4-2. 함수 분해와 시그니처

전 함수 순수(전역 상태·시각·I/O 없음, 로더 제외), 난수는 주입 rng만, 수치는 Decimal.

```
load_limits(path) -> LimitsTable                      # §1 G0 전체 수행
enumerate_combos(table) -> tuple[Combo, ...]          # scope=active·canonical만. 정렬 고정
applicable_row(table, defect_code, material, inspection_method, scheme, level, t) -> LimitRow
                                                      # [min,max) 규약. 정확히 1행, fallback 금지
effective_limit(row, basis_value: Decimal) -> Decimal | None   # 양자화 포함
judge(row, measured: Decimal | None) -> Judgment(verdict, margin)
                                                      # B·D 공용 단일 판정기. limit_op 반영
allocate_counts(combos, total=10_000, cap=40) -> dict[Combo, int]
sample_measurement(row, t, bucket, rng) -> Decimal    # 0.01 그리드 위 직접 추출
build_skeleton(row, measured, t, flags, sample_id) -> Skeleton
generate_corpus_skeletons(table, seed, total, cap) -> tuple[Skeleton, ...]   # (c) 경로
skeleton_from_label(table, label, scale, assumptions) -> Skeleton | Quarantined
                                                      # D4 경로. 난수 없음
aggregate_verdicts(verdicts) -> Verdict               # 다결함 보수 규칙 — D와 공유 (§1-4)
assemble_pair(image_id, skeletons) -> PairGold        # 이미지 단위 조립 (§4-6). 내부에서
                                                      # aggregate_verdicts 사용. 정상 이미지는
                                                      # skeletons=[] 로 같은 경로를 지난다
select_normal_images(manifest, ratio, seed) -> NormalSelection   # 정상 다운샘플 (§4-6-1)
audit_skeletons(skeletons, table) -> AuditReport      # G2 사후 감사
rows_for_clause / derive_chunk_meta / derive_gold_clauses      # 채점 담당 소비 계약 (§1-4)
```

**결정론**: 난수 스트림은 위치 기반 spawn이 아니라 조합 정체성 기반이다.
`SeedSequence((seed, stable_hash(defect|t_min|t_max|scheme|level|clause_id)))`. 표에 행을
추가·삭제해도 다른 조합의 난수열이 불변이다(위치 spawn은 정렬 인덱스가 밀리는 순간 전
조합이 흔들려 T21과 자기모순, S1-1). 컬렉션은 열거 전 사전순 정렬, dict 순회 의존 금지.
같은 (limits sha256, seed, configs, 코드 버전)이면 출력 jsonl sha256이 바이트 단위로 같아야 하고,
이 동일성 자체가 CI 테스트다.

**fail-closed의 적용 범위** (S1-5): **생성기 내부 불변식 위반**(자기 샘플링 수치의 범위
이탈, 평가 불능, 스키마 위반)은 코드 버그이므로 부분 산출 없이 전체 중단한다. 반면
**D4 외부 입력 이상**(퇴화 폴리곤→크기 0, 표 구간 밖 두께 등)은 코드 버그가 아니므로
사유 코드를 붙여 `quarantine/` jsonl로 격리 배출하고 건수·사유 분포를 G2 감사와 논문에
보고한다. 이상치 1건이 5만 건 생성을 중단시키지 않는다. (c) 경로는 입력이 자기
생성이므로 전체 중단 유지.

## 4-3. 실존 조합 열거와 수치 샘플링

- CSV에 행이 실존하는 (defect × material × 두께구간 × 수준) 중 active·canonical만 열거.
  외삽 금지: 표에 없는 조합의 골격이 1건이라도 나오면 감사 실패.
- **조합별 상한 40**: 총량을 조합 수로 균등 배분 후 min(배분, 40), 잔여는 정렬순
  라운드로빈. 상한 미달로 1만에 못 미치면 **상한을 올리지 않고 총량을 줄여 보고**한다.
- **버킷은 의도, verdict는 judge()의 계산 결과다.** 버킷에서 verdict를 역산하는 지름길
  금지, 둘의 일치는 G2에서 별도 검증.
- **그리드 직접 추출** (S1-2): 모든 버킷 구간을 0.01 그리드의 정수 인덱스 구간으로 먼저
  환산하고 그리드 위에서 균등 추출한다. 연속 샘플 후 반올림 방식은 금지: 양자화가 버킷
  소속을 바꾸는 경로 자체를 없앤다. **t도 0.01 그리드에서 직접 샘플링**하고, "골격에
  기록된 thickness_mm으로 applicable_row를 재실행하면 생성 시와 동일 행"을 불변식으로
  둔다(S2-3: 저장 t 반올림이 옆 구간 행을 잡으면 D 재계산이 다른 조항으로 붕괴).
- 버킷 구간 (L = 유효 한계): 합격 (0, 0.9L) / 불합격 (1.1L, 2.5L] / 경계 [0.9L, 1.1L].
  2.5L 상한은 configs.
- **경계 20% 내부 3분할 + 소규모 배분 최소 보장** (S1-3): n ≥ 3이면 =L 1건·하경계 1건·
  상경계 1건을 먼저 고정 배정하고 잔여를 40/40/20 비율(경계 내부 8/4/8)로 배분. 각 층
  합계 = n 불변식. n < 3이면 우선순위 =L → 상경계 → 하경계. 이 규칙이 없으면 조합당
  배분 12건에서 =L 표본이 round(0.48)=0건이 되어 "등호가 판정을 가르는 지점"을 모델이
  한 번도 못 본다. =L 외 경계 표본은 양자화 후에도 L과 최소 0.01 차이 보장.
- prop 계열은 t 먼저 샘플링(10%는 thickness_min 정확값·상한−0.01 근방에 배치해 행 선택
  로직 자체를 데이터에 노출) 후 L(t) 계산. +∞ 구간은 configs `t_sample_max`.
- **F4(불허)는 40/40/20 미적용, 전량 불합격.** 크기 범위는 configs
  `[f4_size_min, f4_size_max]` (스펙 외 상수 금지, S1-10). 무결함 "합격" 서술은 이
  생성기 범위 밖: D4 정상 이미지 다운샘플의 별도 템플릿 경로가 담당한다.
- 비율형(F5) 샘플 상한은 min(2.5L, 100%).

## 4-4. verdict·margin 산정

- 합격 ⇔ measured ≤ L (limit_op=le, 기본) / measured < L (lt). 근거·규약은 §1-3.
- **margin = L − measured** (양수 = 여유). **불변식 (margin ≥ 0) ⇔ 합격**은 limit_op=le
  기준이며 lt 행은 (margin > 0) ⇔ 합격: 생성기 assert이자 D 교차 검증 항목.
- F4: 결함 관측 = 불합격, margin = null. F5: 동일 judge() 함수, 단위만 percent.
- verdict는 enum {합격, 불합격} 2종 외 금지.

**골격 키 널러빌리티 매트릭스** (S2-8: D pydantic 검증과 수치 잠금 필수 출현 집합의
전제):

| limit_rule | size_mm | measured_value(%) | limit_value(=L) | margin | 수치 잠금 필수 출현 |
|---|---|---|---|---|---|
| const·prop_t·prop_t_cap (길이·직경) | 수치 | null | 수치 | 수치 | size, t, L, verdict |
| const (비율 F5) | **null** | 수치 | 수치 | 수치 | measured%, t, L, verdict |
| none_permitted (F4) | 수치 | null | **null** | **null** | size, defect_code, verdict |

## 4-5. 골격 JSON 스키마

최소 8키 `{defect_code, size_mm, thickness_mm, quality_level, clause_id, limit_value,
verdict, margin}` 유지 (널 의미는 위 매트릭스를 따른다. 최소 키의 의미가 바뀌므로 승인 대상이다).

| 확장 키 | 사유 |
|---|---|
| `material, quality_scheme` | 행 선택의 필수 축 (§1-2) |
| `limit_type, unit, limit_rule, limit_factor, limit_cap, ratio_basis, limit_op` | D가 부등식을 독립 재계산하는 데 필수. 수치 잠금 대상 |
| `measured_value, measured_unit` | 비율형 측정값. %를 size_mm에 넣는 단위 혼입을 스키마 수준 차단 |
| `sample_bucket` | 의도 vs 결과 사후 감사 (40/40/20 검증) |
| `source` ∈ {sampled, measured} | (c)/D4 경로 구분 |
| `sample_id` | (c): `{조합해시8}-{일련:03d}` / D4: `{image_id}-{defect_instance}` — 조합 인덱스 서식은 D4에서 오버플로하고 이미지 기반과 안 맞는다(S2-5) |
| `image_id, defect_instance_id` | D4·평가 gold의 이미지 단위 조립 조인 키 (S2-5) |
| `thickness_source, scale_source, quality_source, verdict_type` | 분기 플래그 (§4-7). **quality_source 포함** — D4의 품질수준 출처 기록 (S1-4) |
| `provenance` = {limits_sha256, generator_version, seed, configs_sha256} | 오염 역추적 경로 |

직렬화는 키 순서·수치 표기를 고정한다(스냅샷 sha256 안정성). 키 변경은 승인 대상이다.

## 4-6. D4 페어 경로: 공유·차이·조립

| | (c) 판정추론 1만 | D4 페어 ~4.6만 |
|---|---|---|
| size 출처 | 그리드 샘플링 | 폴리곤 실측 픽셀 × 스케일 → mm (0.01 양자화) |
| thickness / quality | 실존 구간·수준 샘플링 | 메타데이터 또는 **configs 가정값** |
| 난수 | 조합 정체성 시드 | **없음** — 매니페스트 동일이면 출력 동일 |
| 판정 | judge() | **동일 함수** — import 강제 |
| 이상 입력 | 전체 중단 (자기 생성) | quarantine 격리 + 건수 보고 |

- **D4의 품질수준** (S1-4): 라벨에 지정 수준이 없으므로 configs `d4_quality_level`
  (기본값 iso5817:C: 관례적 중간 수준) 1개로 고정하고 `quality_source=assumed` 기록.
  임의 선택도 하드코딩도 아닌 **설정 단일점**이다. 승인 항목.
- **기공 1:N 사상 해소** (S2-4): 사상표의 기공 → {2011, 2012} 중 **D4 경로는 2011(단일
  기공, 직경 한계)로 확정**: 폴리곤 단위 결함 관측과 정합한다. 2012(균일 분포 기공,
  비율 한계)는 분모(용접부 투영 면적)가 라벨에 없어 실측 불능이므로 **D4에서 선언적
  배제 + 건수 보고**, (c) 샘플링 경로에서만 생성. 이 결정을 사상표 YAML과 G0 V1
  (defect_code ∈ 사상표)로 상호 잠근다.
- **이미지 단위 조립 계약** `assemble_pair` (S2-5): 페어 gold = {image_id, defects[골격
  배열], verdict_image = **aggregate_verdicts(각 결함 verdict)**: 보수 규칙: 한 결함이라도
  불합격이면 불합격(채점기와 동일 함수 공유), cited_clauses = 정렬
  고정 합집합(중복 제거), margin은 이미지 수준에 두지 않고 defects[]별 유지}. D 공통
  예측 스키마와의 필드 동기화는 채점 담당과 교차 확정한다.
- 동일 (결함, t, 크기)를 두 경로로 넣어 judge 결과가 같음을 단위 테스트로 고정한다.

### 4-6-1. 정상 이미지 페어 경로 (~15,400건)

결함 0건 이미지의 페어는 골격 생성기의 판정 경로를 타지 않지만, **조립·검증·채점은
결함 페어와 같은 단일 경로**를 지나야 한다. 별도 코드 갈래를 만들지 않는다.

**① 선별**: `select_normal_images(manifest, ratio, seed)`:

- 입력: manifest(계약 #2)에서 `split=train` ∧ 결함 인스턴스 0건 이미지.
- 클라이언트별로 그 클라이언트의 **검증 통과 결함 페어 수 × 1/2** 를 시드 고정 무작위
  추출한다 (결함:정상 ≈ 2:1을 클라이언트 단위로 보장: 전역 비율만 맞추면 소규모 C3의
  비율이 틀어진다). 재질 층화는 클라이언트가 재질을 결정하므로 자동 성립.
- 산출: `corpus/generate/normal_selection.json` = {seed, ratio, manifest_snapshot,
  clients: {C1: [image_id…], …}}. **스냅샷(S4) 포함**: 선별 재현의 근거.
- 시점: 결함 페어 3단계 검증 완료 후 (비율의 분모가 "채택분"이기 때문).

**② 페어 레코드 스키마**: assemble_pair(image_id, skeletons=[]) 출력과 동일 형태:

```json
{"image_id": "...", "defects": [],
 "verdict": "합격",                  // aggregate_verdicts([]) = 합격
 "cited_clauses": [],               // 근거 조항 없음 — 인용할 허용치가 없다
 "verdict_type": "확정",            // 크기 비교가 없어 두께·스케일 가정과 무관
 "quality_level": "<d4_quality_level>",   // 문구용 (판정 기준 수준 표기)
 "source": "measured", "sample_id": "{image_id}-normal",
 "provenance": {...}}
```

D 채점 정합: 정상 이미지의 gold 인용 집합은 공집합이므로, 모델이 조항을 인용하면
무근거 인용 후보가 된다. 이 해석은 채점 명세와 교차 확인한다.

**③ 템플릿·표현 변주**: 정상 전용 템플릿 파일 분리(스냅샷 포함). 서술 원칙:
"검출 한계 내 특기할 결함 지시 없음 → 합격". 결함 명칭은 부정 문맥으로도 쓰지 않는다
("기공은 관찰되지 않았다" 금지): 부정 문맥 판별기를 만들지 않기 위한 안전 규약이다.

**④ 수치 잠금 (정상 변형)**: 허용 수치 집합 = {두께(가정 시 "가정 두께 N mm" 문구),
품질수준}. 그 외 수치 토큰 1개라도 출현 시 폐기. **결함 어휘 락**: 사상표(계약 #1)의
결함 명칭·ISO 코드 사전에 있는 토큰이 생성문에 출현하면 문맥 불문 폐기: 환각 결함이
정상 corpus에 들어가는 것을 차단한다. 사유 코드 `defect_hallucination` 추가.

**⑤ 3단계 검증**: 1단계: 스키마 강제(defects=[] ⇒ verdict=합격 ∧ cited_clauses=[]),
결함 어휘 락, 수치 화이트리스트. 2단계 Judge: 근거="라벨: 정상"으로 생성문이 결함
존재·판정 유보를 시사하는지 이진 판정. 3단계: 전문가 표본 층화의 자산 축에
`normal` 추가 (정상 페어도 2~3% 검토).

## 4-7. 실이미지 합부 모드: `verdict_mode` 소비 (v1.2 개정)

**실이미지(D4·평가) 경로는 A 소유의 `verdict_mode` 3값(`full | conditional | clause_only`)을
소비하며, 현재 `clause_only` 고정이다.** 가정 두께·스케일을 도입하지 않는다. 가정값으로
낸 합부는 데이터가 아니라 가정의 함수다 (결정 G). `conditional` 승격은 8/25 이후 A의
메타데이터 전수 확인(`probe_metadata.py`) 결과로만, 승격 시 가정값 본문 명시 + 민감도
병행 보고 조건.

- **경로별 적용 범위**: 결정 G는 "실이미지에 대한 판정"을 다룬다:
  - **(c) 샘플링 경로: 판정 포함 유지.** 두께·크기를 명시적으로 샘플링한 **합성 시나리오**
    이므로 실이미지에 대한 가정이 아니다. 대소 비교·판정 추론을 가르치는 것이 (c)의 존재
    이유다. (이 해석은 총괄 확인 요청 사항이다)
  - **D4·정상 페어: `verdict_mode`를 따른다.** `clause_only`에서는 골격이 결함 종류·위치·
    크기(px)·적용 조항·허용 기준 서술까지 생성하고 **합부 결론과 margin은 null**이다.
    판정문 템플릿도 clause_only 변형(합부 문장 없음)을 별도 파일로 둔다. `judge()` 호출
    자체가 생략되는 것이 아니라 **출력 게이트**가 모드를 따른다. 승격 시 재생성 없이
    같은 엔진으로 확장 가능해야 하기 때문이 아니라(스냅샷 재생성 금지·버전 증가가 원칙),
    엔진·테스트를 단일하게 유지하기 위해서다.
  - 정상 페어의 "특기할 결함 지시 없음" 서술은 검출 진술이므로 clause_only에서도 유지,
    합부 필드만 모드를 따른다. T34의 "defects=[] ⇒ verdict=합격" 검사는
    "defects=[] ⇒ verdict = (full 모드에서만) 합격, clause_only에서 null"로 개정한다.
- 출처 플래그는 유지한다: `thickness_source, scale_source, quality_source ∈ {metadata,
  assumed, n/a}` + `verdict_mode` 기록. clause_only에서는 전부 n/a가 정상값이다.
- **입력 패리티 조항** (S2-6, 유지: conditional 승격 시 발효): 평가·추론 시 질의/프롬프트의
  두께·스케일·수준은 **gold 골격에 내장된 값과 동일 소스**(스냅샷 시점 매니페스트 + 동일
  fallback 규칙)를 쓴다. 이후 확보된 메타데이터를 기확정 평가에 소급 적용하지 않는다.
  gold 레코드에 질의 재구성용 필드를 포함해 C·D가 골격과 무관한 경로로 두께를 읽을 수
  없게 한다. **C·채점 담당 소비 계약: 승인 대상.**
- D 파급 (결정 G 3항과 정합): clause_only에서 조항 검색 top-1/3·인용 일치율은 산출되고
  **판정 정합성만 N/A 보류**된다.

| T18 | 산출 조합 = 열거 결과 상호 포함 (외삽 0 + 결손 0) | 유령 조합·커버리지 결손 |
| T19 | 같은 (table, seed) 2회 → sha256 동일 / 시드 변경 → 상이 | 비결정론 |
| T20 | 행 순서 셔플 → 출력 불변 | 입력 순서 의존 |
| T21 | 무관 행 추가 → 기존 조합 출력 불변 (**정체성 시드 검증**) | 난수열 연쇄 오염 |
| T22 | 전 골격 verdict·margin judge() 재계산 일치, clause·L의 CSV 행 일치 | 조립 불일치·표 밖 수치 |
| T23 | JSON round-trip 동치, verdict enum 강제, NaN·inf 없음 | 직렬화 손실 |
| T24 | 동일 입력을 (c)·D4 경로로 → verdict·margin 동일 | 경로 판정 분기 — **핵심** |
| T25 | 픽셀→mm 기지값, scale=None → assumed·조건부 플래그 | 분기 누락 |
| T26 | (c) 생성 중 이상 주입 → 부분 산출 없이 전체 중단 | 조용한 결손 |
| T27 | 골든 케이스 30건+ (손계산) 전건 통과 | 공통 모드 실패 |
| T28 | verdict 반전 오염본 → G2 전건 검출 + D 정합성 붕괴 확인 | 지표 회로 미작동 |
| T29 | 전 골격 저장 t 재조회 → 생성 시와 동일 행·clause_id | 저장 t 행 재선택 붕괴 |
| T30 | assemble_pair: 다중 결함 AND, 인용 합집합 정렬·중복 제거 | 이미지 gold 조립 오류 |
| T31 | D4 퇴화 라벨·구간 밖 두께 → quarantine 배출, 생성 계속, 사유 기록 | 이상치 1건의 전체 중단 |
| T32 | 널러빌리티 매트릭스 준수 (rule별 null 키 검사) | 스키마 계약 위반 |
| T33 | aggregate_verdicts: 전 합격→합격 / 1건 불합격→불합격 / 빈 목록→합격 | 다결함 보수 규칙 붕괴 |
| T34 | 정상 페어 스키마 강제 + 결함 어휘 락 검출 (환각 결함 주입 → 폐기) | 정상 corpus 오염 |

# 5. LLM 표현 변주 + 수치 잠금

## 5-1. 원칙

LLM은 **문장 표현만** 만든다. 수치·조항·판정은 골격에 확정돼 있고, 출력에서 하나라도
달라지면 그 샘플은 죽는다. 재생성 없음.

## 5-2. 서빙·모델

> **v1.2 개정:** vLLM은 **로컬 sm_120에서 사용 불가 확정**이다 (vLLM의 torch
> 2.8.0 요구 ↔ sm_120의 2.11.0+cu128 요구가 공존 불가). 서빙 전제를 아래로 교체한다.

| 항목 | 내용 |
|---|---|
| 서빙 | 백엔드 추상화: 생성 스크립트는 `generate_fn(prompt, decode_cfg)` 인터페이스만 본다. **소표본 관통(§7-6): `transformers generate` 로컬** / **본 생성(3만): GPU 확보 후 백엔드 확정** — 클라우드 A40급(sm_86)이면 vLLM 재채택 가능, 로컬 16GB 지속이면 transformers 유지 + 규모를 통과율 실측치로 재산정 |
| 생성 모델 | 오픈 가중치 로컬. 소표본 파일럿(16GB): **Qwen2.5-7B-Instruct bf16** 기본값 (AWQ는 vLLM 전제였으므로 폐기). 본 생성: GPU 확정 후 32B급 |
| 상용 API | **금지.** 질의응답 한정 배치 API는 총괄 승인 사항, 현재 로컬 고정 |
| 디코딩 | **소표본 관통: greedy 고정** — 백엔드가 바뀌어도 출력이 동일해 파이프라인 검증이 백엔드 교체와 분리된다 (결정 I). **본 생성: temperature 0.7 / top_p 0.9 / seed** (표현 다양성 목적, 확정값은 `configs/corpus_gen.yaml`). greedy 통과율은 샘플링 통과율보다 높게 나올 수 있으므로, 본 생성 착수 시 **첫 1,000건을 스테이징 배치로 통과율 재실측** 후 오버샘플 계수(§7-2)를 보정한다. **시도 1회·실패 폐기**는 전 구간 동일 |
| 결정론 | 샘플별 시드(sample_id 유도) + greedy(파일럿)는 백엔드 불변 출력. 본 생성 샘플링은 재현 가능성을 높이되 **정본은 바이트 스냅샷** — 백엔드 배치 비결정성 때문에 완전 재현은 보증하지 않음을 명시 |

## 5-3. 프롬프트 계약

- 템플릿 파일 고정, 스냅샷 해시 포함. (c)는 관찰→분류→조회→대조→판정 5단 구조,
  D4는 별도 템플릿. 조건부 판정(assumed)이면 "가정 두께 N mm 기준" 문구 강제.
- 골격 필드를 표로 제시 + 제약: ① 수치 변경·**추가** 금지 ② 조항 번호·결함 코드 불변
  ③ 판정 결론 불변 ④ 지정 스키마 준수. 판정문의 등급 명칭은 원문 체계 그대로
  (quality_scheme 반영: IACS 행에 "품질수준 C"를 지어내지 않는다).
- 프롬프트 제약은 1차 방어다. 보증은 수치 잠금이 한다.

## 5-4. 수치 잠금 검증 (생성 직후 전수)

1. **추출**: 정규식으로 수치 토큰 전량(숫자+단위), ISO 코드, 조항 번호, 등급, 판정어.
2. **정규화**: ㎜→mm, 전각→반각, 콤마 제거, 후행 0 동치(2.0↔2), 조사 분리.
3. **화이트리스트 대조**: 허용 집합 = 골격의 {size 또는 measured%, thickness, L, margin,
   defect_code, clause_id, quality_level}. **필수 출현 집합은 §4-4 널러빌리티 매트릭스의
   rule별 정의를 따른다.** 허용 집합 밖 수치 토큰이 하나라도 있으면 폐기(환각 수치 차단),
   필수 값 결손도 폐기.
4. **판정어 대조**: 합격/불합격 ↔ 골격 verdict.

불일치 → 폐기, 사유 코드 기록: `missing_value | extra_value | changed_value |
verdict_flip | format_violation`. §6 1단계에서 전체 재실행된다(생성 스크립트 버그의
이중 안전망).

# 6. 3단계 검증

대상: (b) QA, (c) 판정추론, D4 페어. 각 단계는 전 단계 통과분에만. **실패분은 폐기,
재생성 금지, 통과율 기록.**

## 6-1. 1단계: 규칙 검사 (프로그램, 전수)

| 검사 | (c)·D4 | (b) QA |
|---|---|---|
| 스키마 | pydantic (골격 + 생성문 필드, 널러빌리티 매트릭스) | pydantic (질문/답/근거 구절 ID) |
| ISO 코드 | 사상표 집합 실존 | 해당 시 동일 |
| 조항 실존 | clause_id ∈ limits.csv (loader 경유) + 색인 등재 목록 | 인용 시 동일 |
| 부등식 재계산 | limit_eval로 verdict 재도출 일치 | — |
| 조합 실존 | (defect×material×구간×수준) 실존 + canonical | — |
| 수치 잠금 | §5-4 전체 재실행 | — |
| 근거 실존 | — | 근거 구절 ID가 parse 산출물에 실존 |
| 중복 | — | 질문 정규화 후 완전 일치 제거 |
| 길이 | max_seq_length 초과 폐기 (자르지 않는다) | 동일 |

## 6-2. 2단계: 조항 대조 (LLM Judge, 다른 계열, 1단계 통과분)

- Judge는 생성 모델과 **다른 계열**: 생성 Qwen → Judge Gemma 3 12B 기본값. vLLM 로컬.
- 입력: 생성문 + 근거((c)·D4는 인용 조항 재서술 + limits.csv 행 / (b)는 근거 구절 원문).
- 출력: **이진 pass/fail + 불일치 사유 한 줄.** 스키마 위반 출력은 fail. 1회 시도,
  재프롬프트 금지. Judge가 보는 것은 내용 일치다. 수치는 1단계가 이미 보증.

## 6-3. 3단계: 전문가 표본 검토 (2~3%)

- 층화: 자산 × defect_code × 등급 × verdict, 시드 고정. `note` 있는 행 유래 표본 우선
  포함(단서 조항은 기계 미해석: 사람 눈이 유일한 방어).
- 시트: `sample_id, asset, 판정적절성(Y/N), 오류유형(사실오류|조항부적합|표현오류|기타),
  부등식 재계산란(§1-4 공통 모드 방어 ③), 코멘트, 검토자, 일자`. 경로: 외부 도메인 전문가(협의 예정).
- 시스템적 오류(생성기 로직 결함) 판명 시: 표본 폐기로 끝나지 않는다. 상위 보고
  → 수정 → **새 버전 전량 재생성 + 스냅샷 버전 증가**. "실패분 재생성 금지"의 예외가
  아니라 결함 수정에 따른 버전 교체이며, 구버전 해시·사유가 의사결정로그에 남는다.

## 6-4. 통과율 기록

`corpus/validate/validation_report_{asset}_{version}.json`: 단계별
{n_in, n_pass, n_fail, fail_reasons{}, pass_rate} + quarantine 건수 + git commit +
limits·configs 스냅샷 해시. 논문 표는 이 JSON에서 스크립트로 추출: 손 전기 금지.

## 7-4. 평가 자산 격리 경계

## 7-5. `counts.json`: 클라이언트별 표본 수의 단일 소스

통합·연합 FedAvg의 가중치 `n_k`(클라이언트별 학습 표본 수)는 **manifest에서 파생할 수
없다**: 3단계 검증 폐기·quarantine·정상 다운샘플을 거치면 실제 학습 표본 수가 manifest
수치와 달라진다. C가 manifest 파생으로 가정하면 가중 평균이 조용히 틀어진다.

- 경로: `corpus/generate/counts.json`. **S4 스냅샷 대상.** 스키마 변경은 총괄 승인 사항.
- 생성 시점: 3단계 검증 완료·최종 채택 확정 직후, **채택 jsonl에서 스크립트로 기계
  산출**한다. 손 계산 금지.
- 스키마:

```json
{"asset": "d4_pairs", "version": "v1",
 "clients": {
   "C1": {"n_total": 0, "n_defect": 0, "n_normal": 0},
   "C2": {"n_total": 0, "n_defect": 0, "n_normal": 0},
   "C3": {"n_total": 0, "n_defect": 0, "n_normal": 0}},
 "discarded": {"stage0_numeric_lock": 0, "stage1_rule": 0, "stage2_judge": 0,
               "stage3_expert": 0, "quarantine": 0},
 "aux": {"b_qa_total": 0, "c_reasoning_total": 0},
 "limits_snapshot": "sha256:...", "manifest_snapshot": "sha256:...",
 "generated_by": {"git_commit": "...", "date": "..."}}
```

- **소비 규약**: C의 통합·연합 `n_k` = `clients[k].n_total`. C는 로드 시 counts.json이
  가리키는 스냅샷 해시를 대조하고, 불일치면 실행을 중단한다 (§8 규약과 동일).
- **정합 검증** (스냅샷 확정 조건): `clients` 합계 = 채택 jsonl 실제 행수 (기계 대조,
  T35), `n_defect + n_normal = n_total`, `discarded` 합계 = 생성량 − 채택량.
- `(b)·(c)`는 공통 자산(회사별 분할 아님)이라 `n_k`와 무관하며 `aux`에 통계로만 둔다.

## 7-6. 소표본 관통 시험: 500건 (본 생성의 선행 조건)

본 생성(3만)은 GPU 확보 후다. 그 전에 **파이프라인 전 구간을 실데이터로 1회 관통**시켜
통과율을 실측한다. 이 수치가 규모 확대(오버샘플 계수·축소 재산정)의 근거가 된다.

| 항목 | 내용 |
|---|---|
| 규모 | (c) 판정추론 400 + (b) QA 100 = 500건 (limits.csv v0 실존 조합 기준으로 조정 가능) |
| 생성 | transformers generate, **greedy 고정**, Qwen2.5-7B-Instruct bf16 (§5-2) |
| 관통 구간 | 골격 생성 → 표현 변주 → 수치 잠금(stage 0) → 규칙 검사(stage 1) → 타 계열 Judge(stage 2) → 표본 검토 시트 생성(stage 3 — 실제 전문가 검토는 외부 도메인 전문가(협의 예정) 경로 확보 후) |
| 산출 | `validation_report_pilot.json` — 단계별 통과율 + 폐기 사유 분포. **총괄 보고 대상** |
| 입력 | `limits.csv` **v0-pilot** — KR 부록 2-7 전사 초판. **파일럿 전용·미검수 표기, 스냅샷 비대상.** 본 CSV는 §3 본 파이프라인(수용 판정기·이중 검수)으로 별도 구축한다 |
| 해석 주의 | greedy 통과율은 본 생성 샘플링 통과율의 상한 추정일 수 있다 — §5-2 스테이징 배치로 보정 |

**난이도 구간별 폐기 분포.** 통과율 총계만 보면 안 보이는 값이 하나
있다. 경계 사례(허용치 ±10%)를 의도적으로 20% 넣는데 그 구간이 검증에서 더 많이 걸러지면
학습 데이터에 쉬운 것만 남는 **선택 편향**이 생긴다. 그래서 보고서에 두 가지를 함께 싣는다.

- `bucket_crosstab`: 버킷 × 단계 × 폐기 사유 교차표. 버킷은 `pass` / `fail` /
  경계 3층(`boundary_eq` 정확 일치, `boundary_low` 하경계, `boundary_high` 상경계).
- `selection_bias`: 생성 시점 버킷 점유율과 검증 통과 후 점유율을 나란히 두고 변화폭(%p)을
  낸다. 경계 구간 합계 변화폭을 별도 항목으로 뽑는다.

**이 점검은 (c) 판정추론에만 적용된다.** (b) QA에는 난이도 구간 개념이 없다. 버킷은
허용치 대비 수치 위치로 정의되는데 QA는 규정 구절에서 만든 질의응답이라 대조할 허용치가
없다. 따라서 (b)의 `bucket_crosstab`이 `n/a` 한 칸인 것이 정상이며, 보고서에도
`bucket_crosstab_note`로 그 사유를 남긴다.

경계 구간 폐기율이 유의하게 높으면 **재생성하지 않고 그 사실 자체를 보고한다**
(검증 실패분 재생성 금지 원칙, §6).

# 9. 선행 연구의 한계와 조항 정확도 축

WeldLLM의 `llm/src/datasets.py` 텍스트 어노테이션은 **150+ 템플릿 채우기**다. 논문은
"expert-level"이라 썼지만 실질이 다르다. 이 텍스트를 정답으로 삼는 텍스트 유사도 평가는
모델이 얼마나 잘 판정하는지가 아니라 **얼마나 템플릿을 잘 흉내내는지**를 잰다.

우리 합성 판정문도 골격 + 표현 변주라는 생성 방식은 유사하다. 차이는 **평가를 표현에
걸지 않는다**는 데 있다: ① 텍스트 유사도 채점 전면 배제: 필드 파싱과 조항 정확도로만
② 판정의 옳고 그름은 limits.csv라는 외부 기준으로 기계 재계산(판정 정합성): 템플릿이
어떻든 수치·조항·부등식이 맞아야 점수가 난다 ③ 인용 일치율·무근거 인용률이 "그럴듯한
문장 속 지어낸 인용"을 별도 정량화. 조항 정확도 축(신설)은 선행 연구 평가 한계에 대한
직접 응답이며, 논문 평가 절 서두에 이 논리를 명시한다.
