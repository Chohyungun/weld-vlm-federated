# R-적대 리뷰 — 트랙 B (11_spec_B_코퍼스합성.md)

리뷰어 E · 2026-08-17 · 기준 `15_리뷰루브릭_R적대.md` · 대상 커밋 f22a386 (main 머지본)

**요약: Critical 0 / Important 3 / Minor 3.** 자체 다관점 병렬 검증으로 적대 검토 31건을 선처리한
문서라 내부 결함은 이미 대부분 소진돼 있다 — 실제로 이번 리뷰의 지적 3건은 전부 **B 문서
바깥**, 즉 B가 새로 도입한 개념(quality_scheme, D4 페어 수, 정상 페어)이 C·D 스펙에 아직
반영되지 않은 교차 봉합선에서 나왔다. 허용치 표현 규약(반열림·Decimal 양자화·limit_op),
수치 잠금, 라이선스 4등급 처리, 3단계 검증의 예외 규정(시스템 오류 = 버전 교체)은 전부
불변조건과 정합한다.

## Important

### [Important] 11_spec_B:§4-3·§7-1 — D4의 1/3(~15,400건)인 정상 이미지 페어의 생성 경로가 "별도 템플릿 경로가 담당한다" 한 줄뿐, 명세가 없다

- **요약**: 결함 페어는 골격 생성기→표현 변주→수치 잠금→3단계 검증의 완전한 명세를
  갖는데, 정상 페어는 §4-3에 "무결함 '합격' 서술은 이 생성기 범위 밖 — D4 정상 이미지
  다운샘플의 별도 템플릿 경로가 담당"이라는 언급만 있고 그 경로의 스키마·템플릿·검증
  규칙(수치 잠금은 잠글 수치가 없다)·gold 형식(defects=[]에서 verdict·cited_clauses를
  무엇으로 두는가)이 어디에도 없다.
- **실패 시나리오**: 구현 단계에서 정상 페어 15,400건이 즉흥 템플릿으로 만들어진다 →
  검증 3단계의 적용 범위가 불명이라 통과율 보고에서 빠지거나, "결함 없음" 표현이 통제
  없이 단조로워져 통합형이 정상 판정을 표현 패턴으로 학습한다 — 학습 타깃의 1/3이 스펙
  밖 산출물인 채 스냅샷(S4)에 들어간다.
- **근거**: 실험설계 4-5(정상 다운샘플 2:1) / 11_spec_B §4-3·§7-1 / 계약 #4의
  `defects: []` 의미론(13_spec_D §2-1)
- **제안**: 정상 페어 경로를 §4-6에 정식 절로 승격한다 — 최소한 ① gold 형식(defects=[],
  verdict=합격, cited_clauses=[] 또는 "결함 없음" 근거 조항 인용 여부 — D와 교차 확정)
  ② 템플릿 다양성 규칙 ③ 검증 적용 범위(1단계 스키마 + 2단계 Judge는 적용, 수치 잠금은
  "수치 토큰 0개" 검사로 대체) ④ 다운샘플 추출 시드·클라이언트별 비율 규칙. 게이트
  승인 안건 2(D 교차 확정)에 여섯 번째 항목으로 추가하면 된다.

### [Important] 11_spec_B:§1-2(quality_scheme·grade_map.yaml) ↔ 13_spec_D:§5-3 — 스킴 이질성을 D의 검색 필터와 판정 정합성 행 선택이 아직 모른다

- **요약**: B는 적대 검증(S1-6/S2-2/D1-5)을 반영해 quality_level을 단일 B/C/D enum에서
  **스킴 스코프 값**(iacs: STD/LIM, none: ALL 등)으로 바꾸고 대응은 `grade_map.yaml`로
  옮겼다. 옳은 결정이다. 그러나 D 스펙의 메타 필터는 `quality_level ∈ chunk.quality_levels`
  **정확 매칭**이고(13_spec_D §5-3), 질의 키의 품질수준은 iso5817 계열 가정값(C)이다 —
  D는 grade_map의 존재 자체를 모른다.
- **실패 시나리오**: 질의 `{defect=2011, t=12, quality=C}` → IACS 유래 청크의
  `quality_levels=["STD"]`와 정확 매칭 실패 → 후보 0건 → "해당 조항 없음"·판정불가 대량
  발생 → 조항 top-1이 95% 기준선을 크게 미달하는데, D의 §9 진단 규칙("미달이면 색인 구축
  오류부터 의심")대로 색인을 뒤져도 원인이 안 나온다 — 원인은 색인이 아니라 **두 트랙
  사이의 등급 어휘 불일치**이기 때문이다. IACS Rec.47이 색인의 주력 문서라 발생 확률이
  높다.
- **근거**: 11_spec_B §1-2 #8·#9·부록 A(S1-6 처리) / 13_spec_D §5-2·§5-3 / docs/개발규약.md
  데이터 규칙 7(단일 소스 — 등급 어휘도 그 일부다)
- **제안**: 계약 #3 확정에 **grade_map 소비 규칙**을 포함한다: 검색 필터는
  `grade_map[scheme][질의 수준] ∋ chunk 수준` 매칭으로, 판정 정합성의 행 선택
  (`applicable_row`)도 같은 매핑을 경유하도록. B의 파생 함수 3종에 매핑 적용을 내장하면
  D가 grade_map을 직접 읽을 필요가 없어져 단일 소스 원칙에도 맞는다(권장).

### [Important] 11_spec_B:§7-1·§7-3 ↔ 12a(함정#3 §6) — 통합·연합 FedAvg 가중 n_k의 단일 소스가 계약에 없다

- **요약**: C는 n_k = "클라이언트별 D4 학습 페어 수, **manifest 파생**(client, pair 여부
  컬럼 가정)"으로 적었는데, manifest(계약 #2)에는 pair 여부 컬럼이 없고 **있을 수도 없다**
  — 어느 이미지가 페어가 되는지는 B의 다운샘플 추출(시드 고정)이 결정하므로 최종 페어
  수는 **B의 D4 스냅샷에서만 확정**된다. C의 fallback("파생 불가면 이미지 수로 임시
  대체")이 발동하면 정상 다운샘플 이후의 실제 페어 비율과 어긋난 가중이 논문에 실린다.
- **실패 시나리오**: C가 이미지 수 32k:16k:8k로 가중을 굳힘 → 실제 페어 수는 재질별 정상
  비율 차이(강재 44% vs 알루미늄 52%)와 다운샘플 규칙 때문에 다른 비율 → 논문의 "표본
  수 가중 FedAvg" 서술과 실측 n_k 기재가 불일치 — 수치 자체는 소폭이지만 재현·검증
  단계에서 반드시 걸리는 종류의 불일치다.
- **근거**: 12a 함정#3 §2·§6·열린질문 #8 / 11_spec_B §7-3(분할 상속, 재계산 금지)
- **제안**: D4 스냅샷(S4)에 **클라이언트별 채택 페어 수 요약(counts.json, SNAPSHOT 포함)**
  을 정식 산출물로 추가하고, C의 n_k는 이 파일만 읽도록 C·B 계약을 게이트에서 한 줄로
  닫아라. C 쪽 가정 문구("manifest 파생")의 정정도 함께.

## Minor

1. **[Minor] 가정값 3종의 config 이원화** — B는 `configs/corpus_gen.yaml`, D는
   `configs/base.yaml` evaluation 블록에 같은 가정값(t=12mm 등)을 따로 둔다. B의 입력
   패리티 조항(§4-7 — gold 레코드에 사용값 내장)이 위험의 절반을 이미 제거하므로 Minor로
   두지만, 나머지 절반(레코드 필드가 null일 때 D의 config 기본값 경로)은
   20_review_적대_D.md Important #5의 단일화 제안으로 닫아야 한다.
2. **[Minor] D4 페어 생성 대상에 val split 포함 여부 미명시** — §7-1 "학습 풀 ~56,000"은
   train+val을 포함한다. 페어에 split 필드가 실리므로(C 가정 7) C가 필터하면 되지만,
   "val 이미지도 페어를 생성하며 학습 투입 여부는 C의 split 필터 소관"인지 "train만
   생성"인지 한 줄로 명시한다 — 수량 개산(~46,000)의 분모가 달라진다.
3. **[Minor] F6(누적형)·2012(균일 기공) 배제의 한계 절 서술** — 스펙은 건수 보고까지
   설계했으나 논문 한계 절 문장은 E 소관이다. E가 한계 절 항목 목록에 편입한다(이 리뷰로
   인수).

## 지적하지 않은 것 (검토했음을 기록)

- **계약 #3의 3소비처 파생 구조**: 파일+로더+공유 평가기+파생 함수 3종까지 계약으로 묶은
  §1-4는 리뷰 배분에서 최우선 공격 지점으로 지목된 곳의 정답 형태다. 공유 평가기의
  공통 모드 실패까지 자인하고 3중 교차 검증(골든 케이스 표·뮤테이션 감도·전문가 재계산란)
  을 붙였다 — 지적할 것이 없다.
- **레드라인 스윕 통과**: 유료 표준 4등급 분리 + 콘텐츠 수준 스크린 + 원본 PDF 미커밋,
  상용 API 금지(배치 API는 총괄 승인 유보), Judge 타 계열(Gemma), 실패분 폐기·통과율
  기록, 평가 gold의 D 격리 구역 분리(§7-4). 위반 0건.
- **temperature 0.7 생성은 greedy 1회 원칙 위반이 아니다**: 해당 원칙은 5칸 평가 추론
  소관이고, corpus 생성은 "시도 1회·실패 폐기"로 등가 규율을 받는다는 §5-2의 해석이
  옳다. vLLM 배치 비결정성 때문에 "정본은 바이트 스냅샷"이라고 완전 재현 불가를 자인한
  것도 과잉 주장 금지의 모범이다.
- **함정 #6·#7 절차 준수**: 다관점 병렬 검증 12개 분업 단위, 지적 31건 전건 처리·기각 0건,
  critical 2건(S2-1·D2-1)이 전부 교차 계약 지점이었다는 사실 자체가 이번 리뷰 3건의
  방향(트랙 경계)을 예고한 셈이다.
