# R-적대 리뷰 루브릭

작성 2026-08-17 · 근거는 전부 `docs/개발규약.md`와 정본 문서, 검토 기록에 있다.
용도: A~D 스펙(이후 구현물)의 방법론·서술·과잉 주장 공격. 묻는 질문은 하나다 —
**"이대로 가면 논문 주장이 어디서 무너지는가."**

## 1. 판정 등급

| 등급 | 정의 | 처리 |
|---|---|---|
| **Critical** | 그대로 두면 ①논문의 주장이 성립하지 않거나 ②실험을 다시 돌려야 하거나 ③레드라인(docs/개발규약.md 불변조건 3절)을 위반한다. **셋 중 하나에 딱 걸려야 한다** | 해소 전 머지 금지 |
| **Important** | 방치하면 심사 공격 지점이 되거나 후속 재작업을 만들지만, 문서·설정 수정으로 흡수 가능하고 실험 재실행은 불필요 | 머지 가능, 해소 기한 명시 |
| **Minor** | 표현·일관성·스타일. 취향 문제는 전부 여기 이하 | 원저자 재량 |

등급 상향에는 **구체적 실패 시나리오가 필수**다. 시나리오를 못 쓰면 그 등급이 아니다.
Critical을 남발하면 검토가 멈춘다. ①~③에 걸리는지 자문하고, 애매하면 Important로 내리고
사유를 적는다.

## 3. 트랙별 특화 질문 — "여기부터 의심한다"

**A 데이터** ① 분할 절차에 순번이 있고 선분리가 1번인가 ② pHash 임계 8에 표본 100쌍 육안
점검이 붙어 있는가(함정 #8) ③ Dirichlet α=0.5가 C1·C2 **사이에만** 적용되는가 — C3 자연
분할을 침범하면 RQ3 서사 붕괴 ④ manifest 컬럼이 C·D 소비 요구(묶음 ID·sha256·client·split·
픽셀 bbox·크기·재질)를 다 싣는가, bbox는 원본 픽셀인가 ⑤ 라벨 문자열 하드코딩 없이
label_map.yaml import인가, RIAWELC 3클래스 사상이 별도 섹션인가

**B 코퍼스** ① 골격 생성기가 순수 함수 + 부등식 경계·조합 누락 단위테스트인가(함정 #6 —
틀리면 1만 건 오염) ② 경계 사례 20% 샘플링이 설계에 있는가 ③ 검증 모델이 생성 모델과
**다른 계열**이고, 실패분은 재생성 없이 폐기 + 통과율 기록인가 ④ 수치 잠금 검증(생성문
재추출 → 골격 대조)이 있는가 ⑤ 유료 표준 원문이 corpus·색인에 들어올 경로가 차단됐는가,
Docling 실패 문서의 처리 경로 목록이 있는가(함정 #7)

**C 학습·연합** ① patience가 epoch 수 이상으로 꺼졌고 last.pt 채점인가 ② BN 통계 포함
전체 평균 + 논문 명시 계획인가 — FedBN 불가 이유(글로벌 모델 1개 채점)를 인지하는가
(함정 #2) ③ LoRA는 행렬별 평균 + avg(B)·avg(A)≠avg(B·A) 명시인가(함정 #3) ④ VLM 학습
타깃이 **채택 모델 네이티브 좌표계**인가 — "0~1000 통일"이 되살아나면 IoU 0.938→0.055
붕괴(함정 #4) ⑤ Flower 주입과 Ultralytics 자체 저장·재개의 충돌을 커스텀 트레이너로
격리했는가(함정 #1), 통신량은 직렬화 바이트 실측 로깅인가

**D 평가·RAG** ① 채점기가 **하나**인가 — 칸별 채점 코드 분기가 보이면 즉시 지적 ② 스키마가
parse_ok=false(오답 처리, 재프롬프트 금지)를 내장하는가 ③ 검색이 메타 필터 1차·자연어 질의
생성 금지·top-k=3 고정·0건 시 "해당 조항 없음"인가 ④ 청크 메타데이터가 limits.csv **파생**인가
(C1과 동일 축) ⑤ 채점 IoU가 원본 좌표 역변환 후인가(함정 #4 공유), 평가 자산(D6) 격리가
구조적으로 보장되는가, 추적이 MLflow 로컬 한정인가

## 4. 과잉 주장 금지 목록 (발견 즉시 지적, 기본 Important — 수치 날조는 Critical)

1. "최초·유일" → "검색에서 확인되지 않았다" + 검색 로그 각주만 허용
2. WeldLLM 공표치를 결과와 **나란히 표에 넣거나 직접 비교** 서술 (참조점 원칙 위반)
3. 시뮬레이션 페더레이션을 실환경·실통신처럼 서술 (통신량은 "실측 크기 × 라운드" 산출임)
4. **검증 미도달을 검증 통과처럼** 서술. 실패와 미도달과 통과를 구분해 적는다
5. 통과율 숫자 없이 "검증했다" (합성 검증·전문가 검토 전부 해당)
6. 템플릿 생성물에 "expert-level" 류 수식 (선행 연구의 오류를 반복하는 것)
7. 1시드 결과에 ±sd·유의성 부여 / 통합형에 회복률 정의 적용 (유지율만 가능)
8. 스케일 메타데이터 미확인 상태에서 합부를 조건부 아닌 단정으로 서술
9. 자리표시자 자리에 실수치·예시 수치 기입 (없는 결과 날조 — **Critical ③**)
10. 결과 방향을 전제한 문장 골격 ("~상승했다" — 음수면 문장이 결과를 왜곡)

## 5. 보고 형식 (지적 1건 = 1블록, 근거 없는 등급 금지)

```
[등급] 파일:절 — 한 문장 요약
실패 시나리오: 이 입력/조건에서 → 이렇게 틀어진다 (구체적으로)
근거: docs/개발규약.md §_ / 실험설계 §_ / 구현설계 §_ (정확한 위치)
제안: 최소 수정안 (대안 없는 반대 금지)
```

리뷰 말미에 요약 1줄: `Critical N / Important N / Minor N — 머지 가부 의견`.

## 6. 리뷰어 금지 사항

- 스펙을 자기 취향으로 재작성 요구 금지. 지적은 "무너지는 지점"에 한정
- 대안 없는 반대 금지 — 제안 필드가 비면 그 지적은 내지 않는다
- 검토자는 코드를 직접 고치지 않는다. 지적과 제안까지만 한다
- 스펙 단계 산출물에 구현 완성도 잣대 적용 금지 — 스펙은 형식·계약·계획을 심사한다
- 근거 문서에 없는 규칙 발명 금지 — 인용 못 하면 지적이 아니라 의견이고, 의견은 Minor다

**잣대 조정 기록 (다음 리뷰어용).** Critical 0은 기준이 느슨해서가 아니다 — 대상이 이미
이미 두 차례 검토를 거친 문서고, Critical 정의 ①~③이 실제로 잡아내는지는 변형 시험으로
확인했다: T1에 실수치가 있었다면 ③(날조), 초록이 "90% 회복"을 단정했다면 ①(주장 불성립),
채점 표본 2,000건이 학습 유입됐다면 ③(격리 위반)으로 각각 걸린다. 경계 사례 판단 기준:
"방향 전제 문장"(#10)은 문구 수정으로 흡수되므로 Important — 실험 재실행이 필요 없으면
Critical로 올리지 않는다. 반대로 **자리표시자 위반은 문구 문제처럼 보여도 Critical**이다.
수치 날조는 발견 시점이 아니라 유입 시점부터 오염이기 때문이다.
