## 1. 검수 질문 4건에 대한 답

### 1-1. D가 C의 골든 픽스처를 재실행하는 경로가 실제로 성립하는가

**현재 문서로는 성립하지 않는다 (→ Important #1).** D 스펙 §3은 §5-1 판정 이전에 작성되어
정반대 구도(`evaluation/coords/` D 소유·C 소비, 역변환은 D 어댑터 단일 책임)를 전제한다.
문서 어디에도 "C의 픽스처를 재실행한다"는 절차가 없다 — D 자신의 픽스처(§3-3(d))만 있다.
판정 이후 필요한 경로는: C가 `vlm/coords.py` + 골든 픽스처(입력·기대값) + 실행 스크립트를
제공하고, D가 이를 **독립 재실행**해 좌표 해석 일치를 기계 검증하는 것이다. §5 권고에
리뷰어(C)가 제공을 확약하는 인터페이스를 적었다.

### 1-2. `coord_cfg_hash` 대조가 보장하는 것과 못 잡는 것

**보장:** 설정 동일성. CoordCfg(`coord_space`, min/max_pixels 등)의 직렬화 스냅샷이
D4 페어 생성 시점·5칸 추론 시점·채점 시점에 **같았다**는 증명. Q15(프로파일 override 금지)
위반과 칸 간 설정 드리프트를 잡는다.

**못 잡는 것 4종과 각각의 담당 그물:**

| 놓치는 실패 | 잡는 장치 |
|---|---|
| ① `coords.py` 구현 버그 (해시는 설정이지 코드가 아니다) | **골든 픽스처 독립 재실행**(1-1) — 이것이 해시가 못 하는 일의 정확한 보완이다 |
| ② 이미지별 런타임 파라미터 오류 (grid_thw 오전달·조인 오류) | D의 분포검사 D1·D3 + 시각 카나리 (§5-1이 "전부 살린다"고 판정한 그 장치들) |
| ③ 모델이 선언과 다른 공간을 출력 (사전학습 잔재) | C의 카나리아-1(학습 착수 하드 게이트) + `bbox_invalid` 비율 발행 게이트 |
| ④ transformers 버전 드리프트 (smart_resize 거동 변화) | D가 설계한 버전 스탬프 대조 — **유지 가치 있음**, 재배선 후에도 보존 권고 |

**권고:** 계약 #4 재보고에 `coord_cfg_hash`의 **입력 명세**를 포함한다 — CoordCfg 직렬화
+ `coords.py` 소스 sha256 + transformers 버전을 해시 입력에 넣으면 ①·④가 해시 대조
단계로 앞당겨진다. 무엇의 해시인지 계약에 없으면 C와 D가 서로 다른 것을 해싱한다.

### 1-3. 지표 13종이 5칸 전부에 정의되는가

**정의된다 — 전수 확인 결과 통과.** §4-1 명세표의 13종 전부가 5칸에 정의되거나 미정의를
명시 처리한다: 조항 검색 top-1/3은 분리형 전용 명기(통합형 `retrieved_clauses: null`),
mAP의 통합형 구조 비대칭은 §4-4가 상수 score + 각주 + BBox-IoU 주 지표 + conf≥0.25 대칭
보조 지표로 처방(conf 0.25는 C 스펙 Q4 기본값과 일치 확인), 통신량은 중앙·로컬 0 명시,
`parse_ok=false`의 지표별 처리 열이 13종 전부에 있다. `sep_local`의 모델 3개 문제도
`client` 필드 + 3사 단순 평균(§7) 규약으로 닫혀 있다.

**유일한 정의 공백이 Important #2(다결함 이미지의 조항 지표 구성)다.**

### 1-4. RIAWELC 축소본에서 사라지는 지표

**§4-10이 완전하게 명세했다 — 통과.** mAP·BBox-IoU 산출 불가(`N/A(위치 라벨 없음)`,
열 유지), Class-Jaccard는 단일라벨이라 정확도와 동치임을 각주 명기, 판정 정합성은 가정
크기 분포로 `(가정)` 표기, 비교 항목 5→4 축소 명시, `bbox_px: null`로 스키마·채점기 코드
불변. C 관점 확인 사항: C 스펙 §1-6(분류 3칸 전환)과 정합하며, coords 미호출·COCO 경로
미실행 규칙은 C의 null 전파 규칙과 맞물린다.

### [Important #2] §4-3·§5-3·§2-1 — 다결함 이미지에서 조항 지표 3종의 분모·구성 미정의

- **요약**: 검토 결정 F가 판정 정합성의 **재계산 규칙**(한 결함이라도 불합격이면
  불합격, B 골격 생성기와 규칙 공유)은 닫았다. 그러나 **검색·인용 지표의 다결함 구성**은
  여전히 비어 있다: §5-3 파이프라인의 질의 키가 단수형이고, `retrieved_clauses`(maxItems 3)·
  `cited_clauses`가 이미지당 단일 배열이다. 기공+슬래그 동시 이미지는 질의가 2건, 정답
  조항도 2건인데 — 검색 top-1의 분모가 이미지인지 (이미지×결함코드) 쌍인지, top-3 배열에
  어느 질의의 결과를 싣는지, 인용 일치율의 "정답 조항 포함"이 전 결함 조항의 포함인지
  하나라도 포함인지가 미정의다.
- **실패 시나리오**: 구현자가 첫 번째 결함만 질의하도록 구현 → RT 강재에서 기공(45%)이
  대부분 첫 결함이 되어 검색 top-1이 다수 클래스로 편중 산출 → 조항 top-1 95% 기준선
  통과가 **소수 클래스(슬래그·융합불량) 조항 검색 실패를 은폐**한다. 단일 채점기라 칸 간
  불공정은 아니지만, 조항 정확도 축(이 연구의 평가 기여)의 클래스 커버리지 주장이 약해진다.
- **제안**: 검색·인용을 **(이미지 × 결함코드) 쌍 단위**로 정의하고 레코드 구조를
  `defects[]` 항목별 `retrieved`/`cited`로 내리거나, 이미지 수준 유지 시 "전 결함 조항의
  합집합 포함 = 일치"의 보수 규칙 + 결함코드별 분해 보고를 명세할 것을 제안한다. 판정 정합성과 같은
  결로 **B 골격 생성기와 규칙을 공유**해야 한다(결정 F의 취지 연장).

### [Important #3] §8-3 — 라운드별 서버 evaluate가 "글로벌 평가셋" 기준으로 서술 — 정정된 정본 7-4와 불일치

- **요약**: §8-3 2행 "라운드 r의 글로벌 모델을 **글로벌 평가셋**으로 채점한 값을 step=r로
  남긴다"는 검토 결정 B·E로 정정된 구현설계 7-4("라운드별 곡선은 val — 학습 풀 10%,
  글로벌 평가셋은 최종 채점 1회")와 어긋난다. D 스펙이 정정 이전에 작성된 시차 문제다.
- **실패 시나리오**: D가 §8-3대로 MLflow 라운드 로깅을 구현하고 C가 정정본대로 val 기준
  evaluate를 구현하면, 라운드 CSV(`round, loss, macro_f1, ...`)의 macro_f1이 서로 다른
  집합 기준이 되어 그림·표 생성이 어긋나고, "평가셋 최종 1회 접근" 논문 문구가 MLflow
  기록과 모순돼 재현 검증(R-재현)에서 격리 주장이 거짓 판정된다.
- **제안**: §8-3을 "라운드 r의 글로벌 모델을 **val**로 채점(로깅 전용)"으로 정정하고,
  라운드 CSV 스키마에 `eval_set: "val"` 명시 컬럼(또는 파일명 규약)을 추가해 기준 집합을
  기계 판독 가능하게 한다. VLM 칸의 라운드 값은 val loss(생성 없음)임을 병기(C 스펙 §4-3).

### [Minor #1] §7 헤드라인 수치에 기준 지표 미명기

검토 총괄 결정 #1이 회복률·유지율의 기준 지표를 **Macro-F1로 사전 고정**했는데 §7의
산식 3종에는 지표명이 없다. "기준 지표 = Macro-F1, 타 지표 기준은 부록 병기" 한 줄을
§7에 추가할 것을 제안한다. 사후 선택 금지 원칙의 문서화 완결이다.

### [Minor #2] G6(limits.csv 조합 유일성)의 검증 주체 미지정

G6이 깨지면 §6-3 완화 규칙으로 넘어가는데, 유일성 위반을 **누가 언제 검사하는지**가 없다.
`build_gold_clauses.py`에 유일성 assert를 넣고 위반 시 빌드 실패 + B 판단 요청로 명시하면
"조용한 다대다"가 구조적으로 막힌다. (B 스펙 검수는 A 소관이므로 여기서는 D 쪽 소비
지점의 방어만 지적한다.)

| 채점 재현성 장치 | Hungarian 1:1(greedy 비결정성 제거 근거 타당) · `check-scorer` 비트 단위 일치 요구 · 정수화 단일 지점 — 재현 관점에서 모범적 |

**좋은 설계로 기록해 둘 것**: `판정불가`를 스키마 값으로 승격(환각을 스키마가 유도하지
않게), `retrieved`/`cited` 분리(검색 실패와 생성 실패의 분리), `truncated` 분리(능력 부족과
예산 부족의 분리), 오류 유형 분해(조항 오검색 vs 대소 비교 실패) — 전부 C가 5칸 출력을
만들 때 그대로 기대는 결정들이다.

## 4. 판정 요약

**Critical 0 / Important 3 / Minor 2.** 실험 재실행 요구 없음. Important 3건은 전부
검토 결정(F의 D 재보고 명령, B·E의 정본 정정)의 후속 반영이며, **#1·#3은 구현 착수 전

## 5. 규약 소유자로서 C가 제공을 확약하는 것 (D 재보고의 상대편 이행 사항)

1. **골든 픽스처 패키지**: `vlm/coords_fixtures/` — 입력(다양한 해상도·극단 종횡비·경계·
   28 비배수 원본) + 기대값 + 재실행 스크립트 + sha256. D는 import 없이도 스크립트 1회
   실행으로 좌표 해석 일치를 검증할 수 있다.

   C 내부 산출물로 수용(채점 입력에는 불포함).
