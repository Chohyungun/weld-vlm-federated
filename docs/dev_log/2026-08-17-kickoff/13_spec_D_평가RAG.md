## 0. 이 스펙이 지키는 한 문장

**채점기는 학습 결과가 나오기 전에 완성돼 있어야 한다.** 5칸의 출력을 하나의 스키마로
받아 하나의 채점기로 채점한다. 칸별 채점 코드가 갈라지는 순간 논문의 공정성 주장이
무너지므로, 이 스펙의 모든 결정은 "칸을 구분하는 코드 경로를 최대한 줄인다"는 기준으로 내렸다.

칸을 구분해도 되는 지점은 **딱 하나**, 원시 출력을 공통 스키마로 옮기는 어댑터(§2-4)뿐이다.
그 뒤로는 5칸이 완전히 같은 코드를 탄다.

## 1. 평가 자산 격리 규약

누출은 논문 철회 사유다. 코드 수준에서 강제한다.

| 자산 | 경로 | 규칙 |
|---|---|---|
| 글로벌 평가셋 이미지·라벨 | `manifest.csv`의 `split == "eval"` 행 | 학습 로더는 `split != "eval"` 필터를 **생성자에서 강제**한다. 필터 없는 로더 생성 자체를 막는다 |
| 정답 조항 목록 | `evaluation/gold/gold_clauses.csv` | `evaluation/` 아래에만 둔다. `corpus/`·`vlm/`·`detection/`은 이 경로를 import하지 않는다 |
| 판정문 채점용 gold 2,000건 | `evaluation/gold/gold_verdicts.jsonl` | 위와 동일 |
| 한국어 평가셋 599행 | 미보유·출처 추적 실패 | **계획에서 제외 확정.** 확보되더라도 학습 투입 금지 |

**자동 검사 2종** (CI 및 `make reproduce-check`에 포함):

1. **경로 격리 검사**: `corpus/`, `detection/`, `vlm/`, `fl/` 아래 소스에서 `evaluation/gold/`
   문자열이 등장하면 실패. grep 한 줄로 끝난다.
2. **누출 해시 검사**: 학습에 투입된 이미지 `image_id` 집합과 `split=="eval"` 집합의
   교집합이 비어 있는지 확인한다.
   - 입력은 **C의 정식 산출물**이어야 한다(E의 적대 리뷰 Important #4). 원안은
     `consumed_image_ids.txt`를 전제했는데 **C의 산출물 목록에 그 파일이 없었다.**
     계약 없는 전제는 "검사가 영구 skip인데 통과처럼 보이는" 상태를 만든다. 논문 철회
     사유급 방어선이 실제로는 한 번도 작동하지 않는다.
   - 확정 입력: **검출 칸은 C의 V11 산출물**(`data.yaml` 전개 결과 전수 grep),
     **VLM 칸은 D4 페어 로더의 필터 assert 로그**. 둘 다 칸·시드별로 남긴다.
   - **이 산출물이 없으면 검사를 통과로 표시하지 않고 `NOT_RUN`으로 표시**하고 게이트에
     보류한다. skip과 pass를 구분하지 못하는 검사는 검사가 아니다.
3. **평가 콜백 경로 검사** *(C의 R-재현 리뷰로 추가)*. 학습·연합 러너 **프로세스 전체**가
   `split=="eval"` 행을 로드한 적이 있는지 본다. 2번은 학습 데이터 로더만 검사하므로
   서버 evaluate 콜백 경로가 그 그물을 빠져나간다. 스냅샷 로더에 프로세스 단위 접근
   기록을 남기고, 러너 종료 시 eval 접근 건수가 0인지 확인한다.

### 1-1. 오해가 생기기 쉬운 지점: `limits.csv`는 격리 대상이 아니다

`corpus/limits.csv`는 **B의 합성 데이터 생성**과 **D의 판정 정합성 채점**에 동시에 쓰인다.
이는 누출이 아니라 `docs/개발규약.md`의 불변조건 1-7(허용치 CSV가 단일 소스)이 의도한 구조다. 허용치 표는
공개 규정에서 온 사실 정보이지 평가 정답 라벨이 아니다.

격리 대상은 **평가셋 이미지의 라벨**과 **어떤 이미지가 어떤 조항에 대응하는가**이지,
허용치 표 자체가 아니다. `gold_clauses.csv`도 `limits.csv`의 사영(projection)일 뿐 추가
정보가 없으므로, 격리의 실질은 `gold_verdicts.jsonl`(이미지 ↔ 정답 판정)에 걸린다.
이 논리를 논문 한 문장으로 명시한다.

## 2. 계약 #4: 공통 예측 JSON 스키마 (D 소유 · C 소비)

> **동결 상태. 최신 반영본이 최종이다.** 이후 변경은 총괄 승인 없이 불가하고,
> 변경 시 C에 통지한다. 확정까지의 변경 이력은 아래가 전부다.
>
> | 개정 | 근거 | 내용 |
> |---|---|---|
> | v1 → v1.1 | 좌표 규약 확정·§5-3 | 네이티브 좌표 필드(`coord_transform` 객체) **삭제**, `convention`·`coord_cfg_hash` 메타 추가, 원시 출력 계약의 좌표 필드를 `_px` 접미로 강제 |

> | v1.2 → **v1.3** | 검토 결정 ② (C의 R-재현 Imp #2) | `retrieved_clauses`(이미지 수준)를 **`defects[].retrieved`(결함별)** 로 내림. 조항 검색·인용 지표의 단위를 **(이미지 × 결함코드) 쌍**으로 확정 |

`schema.py`의 pydantic 모델이 **실행 가능한 정본**이고, 위 JSON Schema는 그 모델에서
`model_json_schema()`로 생성해 커밋한다. 두 곳을 손으로 맞추지 않는다. 어긋나는 순간
C가 보는 계약과 D가 채점하는 계약이 달라진다. 생성 일치 여부는 단위 테스트로 확인한다.

### 2-2. 설계 결정과 근거

| 결정 | 근거 |
|---|---|
| `additionalProperties: false` | 오타 필드가 조용히 무시되면 "채워 넣었다고 믿었는데 안 채워진" 사고가 난다. C가 필드를 추가하려면 계약 변경 절차를 밟게 만든다 |
| `verdict`에 `판정불가` 추가 | 검색 0건 시 "해당 조항 없음"을 출력하도록 프롬프트에 명시했는데(불변조건, 환각 방지) 스키마에 대응 값이 없으면 모델이 억지로 합격/불합격을 고른다. 환각을 스키마가 유도하는 꼴 |
| `retrieved`를 `cited_clauses`와 분리 | 조항 검색 정확도(검색기 성능)와 인용 일치율(생성 성능)은 다른 것을 잰다. 한 필드로 합치면 "검색은 맞았는데 인용을 틀린" 실패를 볼 수 없다 |
| `retrieved`는 **`defects[]` 항목별**, `cited_clauses`는 **이미지 수준** (검토 결정 ②) | 검색은 결함코드마다 질의가 따로 나가므로 쌍 단위가 자연스럽다. 반면 인용은 판정문 **하나**에서 나오며, 결함별로 인용을 쪼개 내라고 요구하면 통합형의 출력 형식을 바꿔야 한다. 5칸 공통 프롬프트 고정을 깨는 대가가 얻는 것보다 크다. **지표의 분모는 양쪽 다 (이미지 × 결함코드) 쌍**이고, 인용 판정만 이미지 수준 집합에 대해 수행한다 |
| `bbox_px`가 `null` 허용 | RIAWELC 확정 시나리오. 필드를 없애면 스키마가 갈라지고 채점기가 둘이 된다 |
| `score` `null` 허용 | 통합형에 가짜 1.0을 강제로 넣으면 mAP가 조용히 왜곡된다. null로 두고 §4-4에서 명시적으로 처리 |
| `size_px`를 항상 채움 | 스케일 부재 분기(G3)에서도 크기 비교의 상대적 근거가 남는다 |
| `raw_output_ref`로 본문 분리 | 12,600줄 jsonl에 생성문 전문을 넣으면 파일이 수백 MB가 되고 채점 반복이 느려진다 |
| `client` 필드 | `sep_local`은 모델이 3개다. RQ3(C3 편익)를 내려면 어느 클라이언트 모델의 출력인지 필요 |
| 네이티브 좌표 필드를 **두지 않고** `coord_space`·`coord_cfg_hash` 메타만 (확정 사항) | 역변환에는 프로세서 실호출 산출물이 필요하고 그 값은 추론 시점(C)에만 자연히 존재한다. 파라미터를 직렬화해 D로 넘기면 그 직렬화가 곧 새 실패 지점이 된다. **저장 계층은 원본 픽셀 단일**이고, D는 해시 대조와 픽스처 재실행으로 감사한다 |

### 2-3. C가 지켜야 할 원시 출력 계약 (가정 G7)

D는 C의 내부 구조에 관여하지 않는다. 다만 어댑터가 물 곳이 필요하므로 최소 형태만 정한다.

**분리형** 두 파일을 `image_id`로 조인한다.
```
outputs/{cell}/{seed}/detections.jsonl   {image_id, boxes:[{cls, xyxy_px, conf}], coord_space, coord_cfg_hash}
outputs/{cell}/{seed}/verdicts.jsonl     {image_id, retrieved:[clause_id], verdict, cited:[clause_id], raw_ref}
```

**통합형** 한 파일.
```
outputs/{cell}/{seed}/generations.jsonl  {image_id, text, bbox_px_parsed, coord_space, coord_cfg_hash, latency_ms}
```

`xyxy_px`·`bbox_px_parsed`는 **이미 원본 픽셀로 역변환된 값**이다(§3). 필드명에 `_px`를
강제하는 이유는 네이티브 좌표가 실수로 이 자리에 들어오는 것을 이름 층위에서 막기 위해서다.
`xyxy` 이외의 키(cxcywh 등)가 오면 어댑터는 보정하지 않고 즉시 실패한다.

`cls`는 원본 라벨이든 인덱스든 상관없다. 어댑터가 `label_map.yaml`로 ISO 코드에 사상한다.
**라벨 문자열을 어댑터에 하드코딩하지 않는다**(불변조건 1-8).

### 2-4. 어댑터: 칸을 구분해도 되는 유일한 지점

```
separated.py:  detections.jsonl + verdicts.jsonl --join(image_id)--> PredictionRecord
unified.py:    generations.jsonl --json.loads + pydantic--> PredictionRecord
```

- **분리형**은 이미 구조화되어 있으므로 `parse_ok`가 false가 되는 경우는 조인 실패
  (한쪽 파일에 image_id가 없음)뿐이다. 이때도 오답 처리한다.
- **통합형**은 생성 텍스트에서 JSON 블록을 추출해 `json.loads` → pydantic 검증.
  **추출은 관대하게, 검증은 엄격하게** 한다. 코드펜스(```json ... ```)와 선행/후행 산문은
  제거하되, 그 뒤의 필드 검증에서는 어떤 보정도 하지 않는다. 이유: 마크다운 코드펜스는
  모델의 습관이지 판정 능력의 결함이 아니므로 이것으로 오답을 만들면 측정하려던 것과
  다른 것을 재게 된다. 반대로 필드값 보정은 곧 채점기가 답을 고쳐주는 셈이 된다.
- 추출 규칙은 파일로 고정하고 5칸에 동일 적용한다. 규칙을 칸별로 바꾸는 것을 금지한다.

### 2-5. `parse_error` 열거값과 실패율 보고

| 값 | 의미 |
|---|---|
| `no_json` | 생성문에서 JSON 블록을 찾지 못함 |
| `json_decode` | 블록은 있으나 `json.loads` 실패 |
| `schema_violation` | 파싱은 되나 pydantic 검증 실패(필수 필드 누락, enum 위반) |
| `unknown_iso_code` | `label_map.yaml`에 없는 코드 |
| `bbox_invalid` | 좌표 4개가 아니거나 x1≥x2, 원본 이미지 범위를 크게 이탈(§3) |
| `join_missing` | 분리형에서 한쪽 파일에 레코드 없음 |
| `truncated` | max_tokens 도달로 생성이 잘림 |

**파싱 실패율은 칸별로 별도 보고하는 지표다**(구현설계 8-1). 결과표 8-6에 열을 추가한다.
통합형의 실패율이 높다면 그 자체가 RQ2의 답 중 하나이므로 숨기지 않는다.
`truncated`를 따로 두는 이유는 "능력 부족"과 "예산 부족"을 구분하기 위해서다. 전자는
결과이고 후자는 우리 설정의 결함이다.

### 2-6. 예측 파일 규약

```
outputs/predictions/{cell}_{seed}_{yymmdd}.jsonl
outputs/predictions/{cell}_{seed}_{yymmdd}.sha256
```

- 이미지 1장 = 1줄, `image_id` 기준 오름차순 정렬(diff 가능하게).
- **평가셋 전량**(12,600)에 대해 검출·위치 지표를, **층화 2,000 표본**에 대해 판정문·조항
  지표를 산출한다(구현설계 4-5).
- **표본의 진실 소스는 manifest의 `eval_subset` 컬럼 하나뿐이다** (확정 사항).
  `evaluation/gold/verdict_sample_ids.txt`는 **폐기**한다. 채점기는 `split=="eval" AND
  eval_subset` 조건으로 표본을 고르며, 자체 표본 파일을 만들지 않는다. 칸마다 다른 표본을
  쓰면 비교가 성립하지 않는데, 파일이 두 벌이면 그 사고가 언젠가 일어난다.
  - **층화는 재질 × 클래스 2축**이다. 원안의 3번째 축 "합부"는 **제거한다** 합부는 판정
    결과이지 분할 입력이 아니라서, 분할 확정 시점(8/25)에 존재하지 않는 정보다. A의 지적이
    옳았다.
  - 표본은 **분할 확정과 동시에** 뽑혀 manifest에 박힌다(A 소유). D는 읽기만 한다.
  - manifest가 읽기 전용으로 잠기므로 표본 고정은 manifest sha256으로 이미 보장된다.
    별도 sha256을 두지 않는다.
- 저널 단계 대비로 **이미지별 raw 예측을 반드시 보존한다**(의사결정로그 심사대비 1항.
  부트스트랩·McNemar에 필요).

## 3. 좌표계 규약 (지정 함정 구간 #4)

> **좌표 규약 확정 반영 (2026-08-17).** 이 절은 원래 D의 Q16안(네이티브 좌표 동봉 +
> D 어댑터가 역변환)으로 작성됐으나, 게이트에서 **C안이 채택**됐다. C가 규약과 변환을
> 소유하고 원본 픽셀만 제출하며, **D는 검증 소유자**가 된다. 판정 근거 셋: ①역변환에
> 필요한 프로세서 실호출 산출물은 추론 시점(C)에만 자연히 존재한다 ②D안은 분리형·통합형이
> 서로 다른 어댑터 경로를 타지만 C안은 5칸 한 경로다 ③D가 원한 책임 분리는 해시 대조 +
> 골든 픽스처 재실행으로 이미 확보된다.
>
> **D의 검증 장치는 전부 살린다**(게이트 명시). Q20·D1 정규화 잔재 검사·Q15는 승인됐고,
> Q15(프로파일 override 금지)는 **5칸 공통 고정 항목에 정식 편입**됐다. 아래 §3-3·§3-4·§3-5는
> 소유권 변경과 무관하게 그대로 유효하며, 실패 경로 표에서 소유권에 따라 달라지는 3행만
> 개정했다.
>
> 원 설계는 다관점 병렬 검증(3관점 설계 + 적대 검증 3 + 종합, 총 7개 분업 단위)으로 도출했고
> 적대 검증 3건 모두 반박에 실패했다. 채택되지 않은 것은 **소유권 배치 한 가지**이며,
> 붕괴 방지 장치·채점기 규율·COCO 규약은 그대로 계승된다.

**원칙 네 가지**(소유권 개정 후에도 불변).

① **단일 정본은 원본 픽셀 좌표다** GT, 공통 스키마 `bbox_px`, 모든 채점이 이 공간에서만
산다. **모델 좌표는 어떤 파일에도 저장하지 않는다.**
② **변환 코드는 한 곳에만 존재한다** C 소유 `vlm/coords.py`의 정변환·역변환 2함수.
D는 이 모듈을 **import할 뿐 재구현하지 않는다.**
③ **개별 레코드 좌표를 보정하지 않는다** 탐지만 하고, 예측 위반은 오답, GT 위반은 채점기
빌드 실패다.
④ **개별 오류는 오답이지만 계통 오류는 발행 중단이다** 배관 결함을 모델 성능으로
발표하면 측정하려던 것과 다른 것을 잰 셈이 된다.

### 3-1. 규약 정의 (C 소유 · D는 참조)

C가 확정한 규약을 D가 소비하는 형태로만 적는다. **정본은 C의 스펙 §4-4와 `12a_함정판정`이며,
아래는 채점 쪽 소비 계약이다.** 값이 어긋나면 C의 문서가 이긴다.

| 항목 | 값 | D에 대한 함의 |
|---|---|---|
| 기본 규약 | `NORM_1000` (분모 1000 고정) + 플레인 JSON `bbox_2d` 학습 타깃 | 채점기는 이 값을 **읽지도 않는다**. `coord_space`은 provenance 메타일 뿐 |
| 선언 위치 | 코드가 아니라 configs 데이터(`CoordCfg`) | Qwen3.5 규약이 미기재라 **값 교체로 흡수**된다. 스키마·채점기 코드 불변 (Q14 승인) |
| 대안 규약 | `ABS_RESIZED` | 이때 리사이즈 치수는 **재계산 금지**. 프로세서 실호출 산출물(`image_grid_thw` × patch_size)을 인자로만 받는다. D가 재계산해 대조하는 경로도 금지(같은 함정을 D 쪽에 복제하게 된다) |
| 저장 계층 | **원본 픽셀 단일** | 예측 JSON은 역변환 완료된 `bbox_px` + 메타(`coord_space`, `coord_cfg_hash`)만 (§2-1) |
| 판별 게이트 | 카나리아-1. 파인튜닝 전 제로샷 grounding 소표본 argmax 판별 | **통합형 학습 착수의 하드 게이트.** IoU 0.0x대면 규약 가정 오류 신호이며 학습을 차단한다. D는 이 게이트 통과 여부를 MLflow 태그로 확인한다 |
| RIAWELC 백업 | bbox 계열 전 경로 비활성(null 전파) | §3-5 그대로 |

`min/max_pixels`는 `base.yaml`에 공통 고정하고 **GPU 프로파일에서 override하지 않는다**
(Q15, 게이트 승인 → 5칸 공통 고정 항목에 정식 편입). 프로파일이 리사이즈 치수를 바꾸면
좌표 공간이 조용히 드리프트하고, 그 드리프트는 어떤 사후 검사로도 복원되지 않는다.

### 3-2. 소유·검증 분담: C는 규약 소유자, D는 검증 소유자

계약 #4에 이 분담을 명시한다.

| | C (규약 소유자) | D (검증 소유자) |
|---|---|---|
| 변환 코드 | `vlm/coords.py` 작성·유지. **의존성 제로 리프 모듈** | import만. 재구현 금지 |
| 역변환 수행 | 추론 직후 C가 수행, 원본 픽셀로 제출 | 수행하지 않음 |
| 골든 픽스처 | `vlm/coords_fixtures/` 패키지로 제공. 입력(다양한 해상도·극단 종횡비·경계·factor 비배수) + 기대값 + **재실행 스크립트** + sha256 (C가 R-재현 §5에서 제공 확약) | **독립 재실행**하고 결과를 채점 리포트에 첨부. import 없이 스크립트 1회 실행으로도 검증 가능 |
| `resized_wh` 실측·라이브러리 버전 | **C 내부 원시 로그에 기록** (D의 원 G8 설계 취지를 C가 자기 산출물로 수용) | 채점 입력에는 포함하지 않는다. 필요 시 감사용으로 조회 |
| 규약 판별 | 카나리아-1 실측 | 통과 여부를 게이트로 확인 |
| 사후 검증 | (해당 없음) | 해시 대조 · Q20 실측 봉인 · D1 분포 검사 · 오라클 카나리 · 시각 카나리 · 발행 게이트 (§3-3) |

**D가 실제로 하는 검증 5종.**

1. **골든 픽스처 독립 재실행**: C의 픽스처(입력 박스 ↔ 기대 왕복 결과)를 D의 테스트
   스위트에서 다시 돌린다. 왕복 IoU ≥0.99, 극단 종횡비·경계 픽스처 포함. `make
   reproduce-check`의 `check-coords`가 이것이다. **C의 CI 통과를 신뢰하지 않고 다시 돈다**.
   같은 코드를 두 번 돌리는 게 아니라, 픽스처를 고쳐서 통과시키는 경로를 막는 장치다.
2. **`coord_cfg_hash` 대조**: 5칸 예측 파일의 해시가 전부 같은지 확인한다. 다르면 채점기
   실패(§3-3 I2).
3. **Q20 실측 봉인**(게이트 승인). Ultralytics `Results.boxes.xyxy`가 원본 좌표라는 가정을
   표본 50장으로 실측 대조해 봉인한다. 가정하지 않고 잰다. 검증 스크립트는 저장소에 보존하고
   결과는 dev_log에 기록한다.
4. **D1 정규화 잔재 검사**(게이트 승인, 축별 95백분위 조건으로 정밀화). 누가 변환하든
   좌표계 사고를 잡는 마지막 그물이다. 즉시 중단이 아니라 발행 보류.
5. **오라클 카나리 + 시각 카나리**: §3-3 (b)(c).

**`coord_cfg_hash` 대조가 무엇을 보장하고 무엇을 못 잡는가** (트랙 C의 R-재현 리뷰가 물을
지점이므로 먼저 적는다).

**`coord_cfg_hash`의 입력 명세** (확정 사항 + C의 R-재현 §1-2 권고). **무엇의
해시인지 계약에 없으면 C와 D가 서로 다른 것을 해싱한다.** 입력은 셋이다.

```
coord_cfg_hash = sha256(
    CoordCfg 직렬화(coord_space, min_pixels, max_pixels, factor, …)
  + vlm/coords.py 소스 sha256
  + transformers 버전 문자열
)
```

`coords.py` 소스와 라이브러리 버전을 입력에 넣는 것이 핵심이다. 이렇게 하면 **구현 버그
유입과 버전 드리프트가 골든 픽스처·시각 카나리 단계까지 가기 전에 해시 대조에서 걸린다.**
좌표 규약은 프로세서의 `smart_resize`·`patch_size` 거동에 의존하므로, 버전이 올라가며
리사이즈 거동이 조용히 바뀌면 정확히 우리가 막으려던 붕괴가 재발한다.

**"버전마다 해시가 깨져 불편하다"는 반론은 기각한다. 깨지는 게 기능이다.** 5칸은 어차피
동일 스택에서 돌아야 하고(공통 고정 원칙), 조용히 다른 것이 최악이다.

**불일치 시 절차** (막다른 길이 아니라 정의된 경로가 있어야 실행이 죽지 않는다).

```
실행 시작 시 해시 불일치 → 중단
  → C의 카나리아-1(파인튜닝 전 제로짓 grounding argmax 판별) 재실행
      → 규약 동일 확인 → 새 해시로 재봉인하고 진행. 재봉인 사실·사유를 dev_log에 기록
      → 규약 상이 확인 → 계통 오류. 발행 보류, 학습 쪽에서 원인 수정 후 재추론
```

| 보장한다 | 못 잡는다 |
|---|---|
| 5칸이 같은 CoordCfg 값(coord_space, 분모, min/max_pixels)을 썼다 | CoordCfg 값 자체가 **모델의 실제 규약과 다른 경우**. 5칸이 사이좋게 같이 틀린다. 이건 카나리아-1과 D1·시각 카나리가 잡는다 |
| **`coords.py` 소스와 transformers 버전이 동일**(입력에 포함, 결정 H) | `coords.py`가 **같은 소스인데 산식 자체가 틀린 경우**. 해시는 동일성만 보므로 정확성은 골든 픽스처 재실행이 잡는다 |
| 어느 칸이 다른 설정으로 돌았는지 사후 식별 | 이미지별 파라미터 오적용(조인 오류). 해시는 파일 단위다. 분포 검사·시각 카나리가 잡는다 |

즉 해시 대조는 **설정 동일성**만 보장한다. 정확성은 픽스처가, 규약 가정은 카나리아가,
잔여 사고는 분포·시각 검사가 맡는 4중 구조다. 어느 하나로 나머지를 대신하지 않는다.

#### (b) 불변식 3층

- **레코드 층**(어댑터, pydantic). I1 범위·순서 검사, 위반 시 `parse_error="bbox_invalid"`
  오답. I2 `coord_cfg_hash`가 칸 간에 갈리거나 누락되면 **채점기 전체 즉시 실패**
  (크래시. 시스템 오류와 모델 오류를 섞지 않는다).
  I3 **왕복 폐쇄 검사는 순변환이 필요하므로 D가 자체 구현하지 않는다.** C의 골든 픽스처
  패키지(`vlm/coords_fixtures/`)를 **재실행 스크립트로 1회 실행**하거나, 리프 import가
  가능하면 `vlm/coords.py`의 순·역변환 짝을 import해 수행한다(왕복 IoU ≥0.99). 어느
  경로든 **D는 변환 산식을 갖지 않는다** 그것이 §3-2 분담의 요점이다.
- **파일 분포 층**(`score.py`, 지표 계산 전 자동). D1 정규화 잔재(축별 조건), D2 면적 비율
  이상, D3 붕괴 조기 검출(클래스 무시 최근접 IoU 중앙값 <0.1 이면서 parse_ok >80% → 좌표계
  문제일 확률이 압도적), D4 pad 잔재. **D1·D3은 즉시 중단이 아니라 발행 보류**
  (오탐 비용 최소화).
- **배관 층**(오라클 카나리). **§5-1 판정에 맞춰 주입 지점을 재정의했다.** 원안은 GT를
  네이티브 좌표로 순변환해 위장 주입하고 D 어댑터의 역변환을 통과시키는 설계였는데,
  역변환이 C로 갔으므로 그 경로가 D에 더는 없다. 재정의본은 2단이다.
  1. **좌표 해석 일치**: C의 골든 픽스처 재실행으로 검증한다(위 I3). 여기가 "변환이
     맞는가"를 본다.
  2. **채점 배관 종단 검사**: 학습 풀 고정 20장(4클래스 + 정상, **평가셋이 아니므로 격리
     위반 없음**)의 **GT를 원본 픽셀 그대로 예측 레코드로 위장**해 어댑터 → 스키마 검증 →
     COCO 변환 → 지표까지 통과시키고 **IoU = 1.0 / mAP@0.5 = 1.0**을 확인한다. 여기가
     "채점기가 맞는 답을 맞다고 하는가"를 본다. 매칭·COCO 변환·정수화·`image_id` 매핑의
     종단 검사이며 좌표 변환과는 다른 것을 잰다.
  - **1과 2는 중복이 아니라 보완이다.** 픽스처 재실행은 변환 산식을, 카나리는 채점 배관을
    검증한다. 어느 하나가 다른 하나를 대신하지 못한다.
  - **각 칸 본채점 시작 전 필수 통과, 실패 시 채점 시작 금지.** C의 원시 출력 계약(§2-3)에
    대한 실행 가능한 검증을 겸한다.

#### (c) 시각 카나리와 발행 게이트

- **시각 카나리(생략 불가)**: 각 칸 첫 완주 시 층화 표본 20장의 예측 vs GT 오버레이 PNG를
  채점 리포트에 자동 첨부하고, 사람 눈 1회 확인을 §10의 사람 작업 목록에 등재한다. 자동
  게이트가 놓치는 **IoU 0.1~0.6대 부분 붕괴 밴드**의 최종 방어선이다.
- **채점기 자기진단**: 매칭쌍 median IoU ≤0.1이면 `coord_suspect: true` 플래그. 실패가
  아니라 플래그인 이유는 **진짜 저성능을 채점기가 기각하면 안 되기 때문**이다. 판단은
  사람이 오버레이로 한다.
- **계통 오류 발행 게이트**(임계는 결과를 보기 전인 지금 고정한다). 칸별 `bbox_invalid`
  ≥20% / D1 발동 / D3 발동 / 카나리 실패 중 하나면 채점은 완주하되 **발표용 발행을 보류**하고
  진단 리포트와 함께 보류한다. 처방은 언제나 학습 쪽 원인 수정 후 재추론이지 채점기
  보정이 아니다. 발동·해소 이력은 MLflow 태그로 남긴다.

#### (d) 테스트 게이트 (머지 조건)

D가 실행하는 것만 적는다. 변환 코드의 CI는 C 소유이며, 아래는 **D가 독립적으로 다시 도는**
검사다.

1. **C의 골든 픽스처 독립 재실행**: 왕복 IoU ≥0.99. 극단 종횡비·경계 픽스처 포함. 픽스처가
   아래 케이스를 덮지 않으면 **D가 케이스를 추가해 C에 반송**한다: 정방형 무pad 대조군 /
   비정방 2종(1280×720·720×1280) / 0~1000 경계 박스 / 1px·5px 초소형 / **프로세서 factor
   비배수 원본**(1234×707, 축별 배율 검증). factor는 세대별로 다르므로(Qwen2.5-VL 28,
   Qwen3-VL 32. C가 소스로 확인) 숫자를 문서에 박지 않고 `CoordCfg`에서 읽는다.
2. **좌표계 교차 오적용 회귀 케이스**: 0.055 사고의 재현과 방어. 픽스처에 없으면 D가 추가한다.
3. **Q20 실측 봉인**: Ultralytics `Results.boxes.xyxy` 원본 좌표 가정을 표본 50장으로 대조
   (§3-2). 라이브러리 버전 업그레이드에 따른 침묵 변경을 차단한다.
4. **채점 시작 시 `coord_cfg_hash` 5칸 전수 대조 + manifest W/H 표본 200장 PIL 실측 대조.**

전부 `make reproduce-check`의 `check-coords`에 편입한다.

### 3-4. 채점기의 좌표 규율과 COCO 규약

**역변환은 C가 추론 직후에 끝낸다. D의 어댑터도, 채점기도 좌표를 변환하지 않는다.**

```
C: 추론 → vlm/coords.py 역변환 1회 → 원본 픽셀 bbox_px + 메타 제출
D: 어댑터(스키마 검증·조립, 변환 없음) → 단일 채점기(검증만) → IoU·mAP
```

- **D 쪽에 변환 코드가 존재하지 않는 것**이 이 배치의 안전장치다. 이중 변환·좌표계 분기가
  구조적으로 불가능해진다(실패 경로 표 #10).
- `coord_space`·`coord_cfg_hash`는 감사 추적용으로 보존하되 **계산에 쓰지 않는다.**
- **채점기 규율**: `score.py`·`metrics/`는 유한성·`x1<x2` 방어적 재검증만 한다. 채점기
  소스에 `letterbox`, `smart_resize`, `1000` 같은 좌표계 상수가 등장하면 코드 리뷰에서
  거부한다. `bbox_px`가 컨텍스트 없이 자명한 원본 픽셀이어야 저널 단계의 raw 예측 재사용
  (부트스트랩·McNemar)이 성립한다.
- **입력 검증 순서(변환 없이 받은 `bbox_px`에 적용).** 원칙은 *형식이 깨지면 레코드 실패, 의미가 틀리면 지표가 벌점*
  이며 **채점기의 좌표 수정을 금지**한다.

| 순서 | 상황 | 처리 |
|---|---|---|
| 1 | 원소 4개 아님 / 비수치 / NaN·inf (시나리오 무관 항상 적용) | `parse_ok=false`, `parse_error="bbox_invalid"` |
| 2 | `x1≥x2` 또는 `y1≥y2` | 동일 |
| 3 | 경계 이탈량 ≤1px | **경계 스냅**. 우리 연산의 수치 오차 처리로, 허용되는 유일한 좌표 수정. **스냅 직후 `x1<x2, y1<y2` 재검사, 퇴화하면 `bbox_invalid`로 승격.** 스냅·이탈 발생률은 카운터로 집계(높으면 좌표계 오류 신호) |
| 4 | 이미지와 교집합 = 0 (완전 이탈) | `bbox_invalid`. 생성 파탄이며 스키마 위반과 동급 |
| 5 | 부분 이탈 (교집합 >0) | **무수정 통과.** IoU·mAP를 무클리핑으로 계산해 이탈분이 자연 벌점이 되게 한다. 클램프는 IoU를 올리는 방향으로만 작동하므로 답을 고쳐주는 셈이다 (pycocotools도 박스 기하만으로 IoU를 계산하므로 두 지표가 일관된다) |

- **정수화 규칙(단일 지점)**: C가 역변환 내부를 float로 유지하고 제출 직전 `int(floor(v + 0.5))`로
  **최종 1회** 정수화한다(음수가 없으므로 round-half-away와 동치, 플랫폼 무관하게 결정적).
  D는 이후 어떤 반올림도 추가하지 않으며 COCO 변환 단계에도 없다. **채점 재현성이 서브픽셀
  정밀도보다 우선**한다. 이 규칙은 C가 지켜야 하는 계약 항목이므로 §2-3 원시 출력 계약에 건다.
- `bbox_invalid`(퇴화 포함) 레코드는 미검출 오답으로 계산하고, 발생률을 **파싱 실패율과
  분리해** 별도 보고한다. 이미지 전체를 버리지는 않는다(다른 결함 항목은 정상 채점).

**COCO 변환 규약** (`metrics/localization.py` 내부 표현, 5칸 공통):

| 항목 | 규약 |
|---|---|
| bbox | `[x1, y1, w, h]`, `w=x2−x1`, `h=y2−y1`. 좌상단 원점, **0-기준 연속 좌표**. Pascal VOC `+1` 규약 혼입 금지 |
| xyxy→xywh | `metrics/` 안의 단일 헬퍼 함수. 지표별 파일에서 직접 산술 금지 (좌표계 변환이 아니라 같은 공간의 표기 변환이므로 D 소유다) |
| `image_id` | manifest 문자열 오름차순 → 1..N 고정 매핑. 매핑 테이블을 채점 산출물로 저장 |
| `category_id` | `label_map.yaml`의 ISO 코드 명시 순서 → 1..4. 라벨 문자열 하드코딩 금지 |
| GT annotation | `iscrowd=0`, `area = w·h` (**bbox 면적이며 폴리곤 면적이 아님**. AP-s/m/l의 기준임을 각주) |
| score | 분리형 = 검출 conf, 통합형 = 1.0 상수(§4-4 각주) |
| eval 설정 | `iouType='bbox'`, maxDets·areaRng는 pycocotools 기본값. 커스텀 금지 |
| 결정론 | 상수 score 동률 시 정렬이 입력 순서에 의존 → `defects` 배열 순서 보존 + jsonl `image_id` 정렬로 재실행 비트 일치 보장 |

BBox-IoU는 COCO를 거치지 않고 같은 `bbox_px`에서 직접 Hungarian 매칭으로 계산한다(§4-6).
**두 지표가 같은 `bbox_px` 하나를 소스로 쓰는 것**이 단일 진실 원칙의 좌표판이다.

### 3-5. RIAWELC(위치 라벨 없음) 축소 경로

원칙 한 줄: **N/A는 GT가 결정하고, 오답은 예측이 결정한다.**

| GT bbox | 예측 `bbox_px` | 처리 |

## 4. 지표별 산출 명세

### 4-0. 공통 전제

- 입력은 예측 jsonl 1개 + `manifest.csv`(GT) + `gold_clauses.csv` + `limits.csv`.
- 모든 지표 함수는 **순수 함수**로 짠다: `(pred_records, gt_records, config) -> dict`.
  전역 상태·파일 IO를 함수 안에서 하지 않는다. 그래야 mock 픽스처로 지금 테스트할 수 있다.
- `parse_ok == false` 레코드의 처리를 **지표마다 명시**한다(아래 표의 마지막 열). "오답
  처리"의 의미가 지표마다 다르기 때문이다. recall에서는 미검출, precision에서는 분모 포함.
- 이미지 수준 클래스 집합은 `label_map.yaml`의 결함 4종(균열·기공·융합불량·슬래그혼입).
  **"정상"은 클래스가 아니라 "결함 4종 전부 음성"으로 표현한다.** 정상을 5번째 클래스로
  두면 Macro-F1에 다수 클래스가 하나 더 들어가 지표가 낙관적으로 부풀려진다.

| 13 | 통신량 | C의 라운드별 바이트 로그 | 라운드당 (업+다운) × 라운드 × 클라이언트 | pandas | 완전 | 해당 없음 |

### 4-2. Macro-F1을 주 지표로 두는 이유와 정의 고정

클래스 불균형이 크다(슬래그 1,140 : 기공 27,040). 전체 정확도만 보면 다수 클래스 뒤에
실패가 숨는다. **정의를 여기서 못박는다** 나중에 정의를 고르면 결과를 보고 지표를 고르는
셈이 된다.

- 단위: **이미지 수준 다중라벨**. 박스 단위가 아니다. 이유는 두 가지다. (a) 통합형은
  박스 개수를 신뢰할 수 없다(생성 모델이 같은 결함을 두 번 언급할 수 있다). (b) 현장의
  1차 관심사는 "이 사진에 균열이 있는가"이지 "균열이 몇 개인가"가 아니다.
- 중복 제거: 예측·GT 모두 이미지별로 클래스 집합(set)으로 축약한 뒤 비교한다.
- 평균: 결함 4종에 대한 **단순(unweighted) macro 평균**. 슬래그가 기공과 같은 무게를 갖게
  하는 것이 이 지표를 쓰는 이유다.

### 4-3. 판정 정합성: 이 트랙의 핵심 지표

**조항을 맞게 찾고도 결론을 틀릴 수 있다.** 이 지표는 그 실패를 잡는다. 규칙 기반 재계산이라
LLM 심판이 개입하지 않는다(불변조건: RQ2 결론을 LLM 판정에 의존하지 않는다).

```
이미지 1건에 대해:
 1) 결함 인스턴스마다 (그 결함코드에 대응하는 인용 조항, size) 짝을 만든다
    - B의 rows_for_clause(table, clause_id) 로 후보를 좁히고, 골격 내장 키
      (inspection_method, defect_code, material, quality_level, t) 로 applicable_row 선택
      ※ inspection_method 는 계약 #3 변경분(확정 사항). 이 축이 빠지면
        표면/내부 기공의 다른 허용치를 섞어 집고도 형식상 정상으로 보인다
    - 담당 조항이 인용에 없으면 그 결함은 '근거 없음'으로 별도 집계 (§4-3 분모 규칙)
 2) 짝마다 size를 limit_type에 맞춰 선택
    - limit_type == 길이   → size_basis == major_axis 값
    - limit_type == 직경   → size_basis == equiv_diameter 값
    - limit_type == 비율   → size / thickness_mm
 3) 결함별 recomputed = (측정값 <= limit_value) ? 합격 : 불합격
 4) 이미지 합성. B의 aggregate_verdicts(verdicts) 호출 (재구현 금지)
    **보수 규칙: 결함이 하나라도 불합격이면 이미지는 불합격**
    (전부 합격이어야 합격. 결함 0개면 합격)
 5) 정합 = (합성 결과 == record.verdict)

판정 정합성 = 정합 건수 / 판정 가능 건수
```

**다결함 합성 규칙은 보수 규칙 하나로 고정한다** (확정 사항). 근거는 두 가지다.
검사 실무에서 결함 하나가 기준을 넘으면 그 용접부는 불합격이고, 미검출이 오검출보다
위험하다는 이 연구의 전제와도 방향이 같다.

> **B의 골격 생성기와 같은 규칙을 공유한다** (계약 #3 부속 조항). B가 gold verdict를
> 만들 때 다른 합성 규칙을 쓰면 지표가 계통적으로 편향되고, 그 편향은 모델 실패로
> 오귀속된다. 규칙을 두 곳에 각각 구현하지 않고 **B의 순수 함수를 D가 import**하거나,
> 그것이 불가능하면 명세 문구를 계약 #3에 박고 양쪽 단위 테스트가 같은 케이스 표를
> 공유한다. 허용치 CSV가 단일 소스여야 하는 것과 같은 논리다. 표만 같고 규칙이 다르면
> 단일 소스가 아니다.

단위 테스트에 **다결함 3종**(전합격 / 혼합 / 전불합격)과 "담당 조항 미인용" 케이스를 넣는다.

**분모에서 빼는 경우와 그 처리**를 명시한다. 빼는 것을 숨기면 지표가 조용히 부풀려진다.

| 상황 | 처리 |
|---|---|
| `cited_clauses`가 비어 있음 | 분모 제외, **`판정 근거 없음` 비율**로 별도 보고 |
| 인용 조항이 `limits.csv`에 없음 | 분모 제외, 무근거 인용률(§4-5)로 계상 |
| `verdict == 판정불가`이고 검색 0건이 실제로 맞음 | **정합으로 계상**한다. "모르는 것을 모른다고 하는 것"은 정답이다 |
| `verdict == 판정불가`인데 조항이 실제로 존재 | 부정합 |
| `size_mm`이 null (스케일 부재) | §4-11 조건부 경로. 가정 스케일로 산출하고 지표명에 `(조건부)` 표기 |
| `limit_type == 비율`인데 `thickness_mm` null | 분모 제외, 별도 집계 |

오차 허용: 부등식 경계에서 부동소수 비교가 흔들리지 않도록 `limit_value`와의 비교에
**절대 허용오차 1e-6**을 둔다. 경계 사례가 corpus의 20%를 차지하므로(구현설계 4-3)
여기서 흔들리면 지표가 실제보다 나빠 보인다.

**오류 유형 분해를 반드시 함께 보고한다** 판정 정합성이 기준선(95%)에 미달할 때
"조항 오검색"인지 "대소 비교 실패"인지 구분되지 않으면 해석이 불가능하다.

| 유형 | 판별 |
|---|---|
| 조항 오검색 | 인용 조항 ≠ gold 조항, 그런데 인용 조항 기준으로는 verdict가 정합 |
| 대소 비교 실패 | 인용 조항 = gold 조항, 그런데 verdict가 부정합 |
| 이중 실패 | 둘 다 틀림 |

### 4-4. mAP의 구조적 비대칭: 숨기지 않고 명시한다

`score`가 통합형에 없다. pycocotools의 AP는 신뢰도 정렬로 PR 곡선을 그리므로, 통합형에
상수 score를 넣으면 곡선이 한 점으로 수렴해 AP가 **구조적으로** 불리해진다. 이는 통합형의
위치 정확도가 나빠서가 아니라 출력 형태가 달라서 생기는 차이다.

**처방:**

1. 통합형은 `score = 1.0` 고정으로 COCO 변환한다(pycocotools 요구사항).
2. **위치 정확도의 주 지표는 BBox-IoU로 둔다.** 두 구조에 대칭적이다.
3. mAP는 **분리형 3칸 간 비교**에 쓰고(RQ1의 검출 축), 통합형 값은 각주와 함께 참고치로
   싣는다. 각주 문구를 지금 고정한다: *"통합형은 생성 모델이라 검출 신뢰도가 없어 상수
   신뢰도로 산출했다. PR 곡선이 단일 점으로 축약되므로 분리형과 직접 비교할 수 없다."*
4. 보조로 **고정 신뢰도 임계에서의 대칭 지표**를 함께 낸다: 분리형 예측을 conf≥0.25로
   자른 뒤의 P/R/F1@IoU0.5. 이것이 두 구조를 같은 조건에 놓은 위치 비교다.

이 결정을 미루면 결과가 나온 뒤에 지표를 고르게 되고, 그것이 사후 합리화다.

### 4-5. 무근거 인용률: 2단 판정

```
1차 (자동): 인용 조항 ID가 색인(chunks.parquet)에 실존하는가
            → 미실존 = 무근거 확정 (환각 조항)
2차 (자동): 실존하지만 gold 조항 매핑과 무관한가
            → 결함코드·두께구간·품질수준 중 하나라도 어긋나면 무관으로 분류
3차 (사람): 2차에서 "결함코드는 맞고 두께구간만 인접"한 경계 사례만 표본 검수
```

무근거 인용률 = (1차 미실존 + 2차 무관) / 전체 인용 건수. 1차와 2차를 **분해해서 보고**한다.
없는 조항을 지어내는 것과 있는 조항을 잘못 고르는 것은 다른 실패다. 통합형이 생성문 안에서
인용을 지어내는 정도를 정량화하는 것이 이 지표의 목적이므로 전자가 더 중요한 신호다.

### 4-6. BBox-IoU 매칭 규칙

좌표계 처리는 §3에 있고, 여기서는 **어떤 박스를 어떤 박스와 짝지을지**만 정한다.

- 같은 `iso_code` 안에서만 매칭한다. 클래스가 틀리면 위치가 맞아도 매칭하지 않는다.
- 이미지별로 IoU 행렬을 만들고 **Hungarian 알고리즘**(`scipy.optimize.linear_sum_assignment`)으로
  1:1 최적 매칭. greedy를 쓰지 않는 이유는 결함이 밀집한 이미지에서 greedy가 순서에 따라
  다른 답을 내기 때문이다. 재현성이 깨진다.
- 매칭 임계 없음(IoU 0인 쌍도 매칭될 수 있음). 대신 **미매칭 GT는 IoU 0으로 분모에 포함**한다.
- 주 보고값: 전체 GT 박스 기준 평균 IoU(미매칭 0 포함).
  부 보고값: 매칭쌍만의 평균 IoU. 선행 연구(WeldLLM 0.953)와의 비교용. **어느 정의로
  산출했는지를 표에 반드시 병기한다.** 정의를 안 밝히면 0.9와 0.5가 같은 이름을 달게 된다.

### 4-7. Class-Jaccard

이미지별 `|pred ∩ gt| / |pred ∪ gt|`, 전체 이미지 평균. 둘 다 공집합(정상 이미지를 정상으로
예측)이면 J=1로 정의한다(0/0을 1로 둔다). 이 규약을 안 정하면 정상 이미지 비율(RT 강재 44%)이
지표를 통째로 좌우한다.

### 4-8. 조항 검색 top-1/top-3

분리형 전용. `defects[].retrieved`(검색기 원출력, 순서 유지)를 gold와 대조한다.
**검색은 구조화 lookup에 가까우므로 top-1이 95% 이상이 정상이다.** 미달 시 진단 순서는
§7에 고정했다(등급 어휘 정합성 → 색인 → 두께 구간).

**단위는 (이미지 × 결함코드) 쌍이다** (검토 결정 ②, C 제안 채택).

```
분모 = 모델이 실제로 질의를 던진 (image_id, iso_code) 쌍의 수
       = 예측 defects 를 iso_code 로 중복 제거한 것
분자 = 그 쌍의 gold 조항이 retrieved[0] (top-1) / retrieved[:3] (top-3) 에 있는 쌍의 수
```

이미지 단위로 재면 안 되는 이유가 있다. 이미지 하나에 결함이 여럿이면 질의도 여럿인데,
구현자가 **첫 결함만 질의하도록** 짜면 RT 강재에서 기공(45%)이 대부분 첫 결함이 되어
검색 top-1이 다수 클래스로 편중 산출된다. 그러면 **95% 기준선 통과가 슬래그·융합불량
조항 검색 실패를 은폐**한다. 조항 정확도 축은 이 연구의 평가 쪽 기여이므로, 커버리지를
숨기는 정의는 쓸 수 없다.

**결함코드별 분해를 반드시 함께 보고한다.** 전체 top-1 하나만 싣는 것을 금지한다.

주의: 검색 정확도는 **검출 결과가 맞다는 전제**에서만 의미가 있다. 검출이 틀린 결함코드로
질의하면 검색은 "질의에 맞는 조항"을 정확히 찾고도 gold와 어긋난다. 따라서 세 갈래로 낸다.

| 조건 | 의미 |
|---|---|
| 전체 기준 top-1 (쌍 단위) | 파이프라인 end-to-end 조항 정확도. **논문 표에 들어간다** |
| **검출 정답 조건부** top-1 (예측 결함코드 ∈ GT 결함코드인 쌍만) | 검색기 자체의 성능. 검색기 디버깅의 기준 |
| **GT 결함코드 커버리지** (GT에 있는데 예측에 없어 질의 자체가 없었던 쌍의 비율) | 미검출이 조항 지표의 분모에서 조용히 빠지는 양. 이 값을 안 내면 검출을 못 한 만큼 조항 정확도가 좋아 보인다 |

세 번째 줄이 중요하다. 쌍 단위 분모를 "질의한 쌍"으로 잡았으므로, **검출이 나쁠수록
분모가 줄어 top-1이 올라간다.** 커버리지를 병기해야 그 착시가 드러난다.

### 4-9. 인용 일치율

`cited_clauses`(최종 판정문이 인용한 것) ↔ gold. **두 구조 공통**이므로 RQ2의 핵심 비교
지표다. 통합형은 검색 없이 생성문 안에서 직접 인용하고, 분리형은 검색 결과를 인용한다.
이 비대칭이 판정 근거 신뢰도 비교의 대비축이므로 제거하지 않는다(실험설계 7장).

**단위는 검색과 같은 (이미지 × 결함코드) 쌍이다** (검토 결정 ②). 다만 인용 집합은
이미지 수준 `cited_clauses` 하나다. 결함별로 인용을 쪼개 내라고 요구하면 통합형의 출력
형식을 바꿔야 하고, 그건 5칸 공통 프롬프트 고정을 깨는 대가가 얻는 것보다 크다(§2-2).

```
분모 = GT 결함이 있는 (image_id, iso_code) 쌍
분자 = 그 쌍의 gold 조항이 이미지의 cited_clauses 에 포함된 쌍
```

- 주 보고: 위 쌍 단위 비율(재현 관점). **결함코드별 분해 병기.**
- 부 보고: 인용 정밀도(인용한 조항 중 그 이미지의 gold 조항 합집합에 속하는 비율).
  통합형이 조항을 많이 나열해 맞히는 것을 잡아낸다. 정밀도를 안 보면 "여러 개 인용하면
  이기는" 지표가 된다. 쌍 단위 분모와 이미지 단위 인용 집합을 섞어 쓰는 설계라 이 방어가
  더 필요하다.
- **B의 골격 생성기와 규칙을 공유한다**: gold verdict를 만들 때 어느 결함에 어느 조항이
  대응하는지의 매핑이 양쪽에서 같아야 한다. 판정 정합성(§4-3)과 같은 결이다.

### 4-10. RIAWELC 확정 시나리오: 지표 축소본

RIAWELC 로 전환하면 위치 라벨이 없다. 산출 불가 지표를 미리 확정해 두어야 그때 가서
급조하지 않는다. 주 데이터는 확보됐고, 이 절은 백업 경로를 위해 둔다.

| 지표 | RIAWELC 경로 |
|---|---|
| Macro-F1, 클래스별 P/R/F1, 혼동행렬 | **산출.** 4클래스 단일라벨 분류(패치 1장 = 1클래스)로 축약 |
| 결함 recall | **산출.** 정상을 제외한 3클래스 기준 |
| mAP@0.5 / 0.5:0.95 | **산출 불가.** 결과표에서 열을 지우지 말고 `N/A(위치 라벨 없음)`로 채운다 |
| BBox-IoU | **산출 불가.** 동일 |
| Class-Jaccard | **산출.** 단일라벨이므로 사실상 정확도와 같아지며, 그 사실을 각주로 밝힌다 |
| 조항 검색 top-1/3 | **산출.** 결함코드만 있으면 질의가 성립한다 |
| 인용 일치율 | **산출** |
| 판정 정합성 | **조건부 산출.** 227×227 패치라 실측 치수가 없다 → 가정 크기 분포를 부여하고 `(가정)` 표기. 이 경우 지표는 "모델이 주어진 수치로 부등식을 옳게 세우는가"만 잰다 |
| 무근거 인용률 | **산출** |
| latency·VRAM·통신량 | **산출** |

축소 시 **비교 항목이 다섯에서 넷으로 줄어든다**(위치 정확도 제외). 이를 논문에 명시한다.
스키마는 바뀌지 않는다. `bbox_px: null`로 흡수되며 채점기는 null을 만나면 해당 지표를
`N/A`로 반환한다. **코드가 안 바뀌는 것이 이 설계의 목표다.**

### 4-11. 스케일 메타데이터 부재 분기 (Critical 리스크)

`px_per_mm`이 없으면 mm 단위 부등식을 세울 수 없다.

**확정됐다.** D의 2값 플래그(`scale_available`)를 **폐기**하고,
**A의 `verdict_mode` 3값을 그대로 소비**한다. 진실 소스는 **스냅샷별
`data/{snapshot}/data_capabilities.yaml`** 이다(확정 사항. 전역 1파일은 낯선 데이터
검증에서 스냅샷 2개가 공존할 때 성립하지 않는다). D는 `configs/`에 이 플래그를 복제하지
않는다.

| `verdict_mode` | 의미 | D의 채점 동작 |
|---|---|---|
| `full` | 실측 두께·스케일 보유 (보유율 ≥0.95) | 판정 정합성 정상 산출 |
| `conditional` | 미보유이나 **가정값을 명시적으로 채택** | 가정값 기준 조건부 산출. 지표명에 `(조건부)` + 가정값 표 각주 + **가정값 ± 범위 민감도 병기** |
| `clause_only` | 미보유 + 가정값 미채택 | **판정 정합성 `N/A`.** 조항 검색 top-1/3·인용 일치율은 정상 산출 |

**현재는 `clause_only` 고정이다.** `conditional` 승격은 **데이터 실측 이후에만** 한다
(확정 사항). 근거는 총괄 판정을 그대로 옮긴다.

1. **가정값으로 낸 합부는 데이터가 아니라 우리 가정의 함수다.** "판정 정합성 95%"를 논문에
   쓰면 심사에서 "무엇에 대한 정합성인가"로 즉시 무너진다.
2. **지금 가정값을 박으면 실측 동기가 사라진다.** 두께·스케일 존재 여부는 현재 최대
   리스크이고 A의 `probe_metadata.py`가 8/25 이후 전수 확인한다. 그 전에 값을 넣으면
   확인이 흐지부지된다.
3. **평가 축이 통째로 사라지지 않는다.** 신설 조항 정확도 축 3지표 중 **판정 정합성 1개만
   보류**된다. mock 2벌이 `clause_only` + `assumptions: null`로 나와 판정 정합성이 `N/A`인
   것은 **정상 동작**이며, 채점기 결함이 아니다.
4. **승격 시 형식을 미리 고정한다.** 가정값을 논문 본문에 명시하고 **± 범위 민감도를 함께
   보고**한다. 조건부임을 감춘 채 단일 수치로 내지 않는다.

가정값이 실제로 쓰이게 되는 때(`conditional` 승격 시)를 대비한 키만 남긴다.

```yaml
# configs/base.yaml. conditional 승격 시에만 활성. 현재는 미사용.
evaluation:
  assumed_px_per_mm: null      # 승격 시 값을 넣고 논문 각주에 싣는다
  assumed_thickness_mm: null
  assumed_quality_level: null
  sensitivity_range: 0.2       # 승격 시 ±20% 민감도를 함께 산출
```
- 가정값은 **5칸 전부 동일**하다. 칸마다 다른 가정을 쓰면 비교가 무의미해진다.
- **가정값 3종은 B의 골격 생성기와 단일 소스로 묶는다** (E의 적대 리뷰 Important #5 → 가정
  인터페이스 **G14**). B는 같은 상황에서 가정값으로 D4 판정문과 gold verdict를 만들고
  (실험설계 4-4), D는 같은 가정값으로 판정 정합성을 재계산한다. 두 트랙이 다른 값을 쓰면
  **경계 사례 20%가 몰려 있는 허용치 근방에서 gold와 재계산이 조직적으로 갈리고**, 그
  미달이 "모델 실패"로 오귀속된다. `configs/base.yaml`의 이 블록을 B 골격 생성기와 D
  채점기가 **같은 키로 읽는 것**을 계약 #3 부속 조항으로 올린다. 값 변경은 스냅샷 재부여
  사유다.
- 세 경로 모두 채점 가능해야 하므로, 채점기는 `verdict_mode`를 읽어 분기하되 **지표 함수
  자체는 하나**다(mm 값을 만드는 어댑터만 다르다). **`clause_only`를 기본 경로로 놓고**
  나머지 12개 지표가 전부 나오는지를 mock으로 먼저 확인한다. A의 조치를 기다리지 않는다.

### 4-12. latency · VRAM · 통신량

| 항목 | 측정 조건 |
|---|---|
| latency | warmup 10회 후 **100장 median**, batch=1, 동일 GPU(로컬 RTX 5060 Ti 16GB), 동일 precision, **동일 추론 백엔드**. sm_120에서 vLLM이 torch 2.11+cu128과 공존 불가로 확정돼(검토) 평가 추론은 **`transformers generate` 폴백**을 쓴다. greedy 1회 원칙이라 **출력은 동일하고 처리량만 손해**이므로 재현성·결과는 무손실이다. 다만 latency 절대값은 백엔드에 종속되므로 결과표 각주에 백엔드를 명시한다. 분리형은 검출+검색+판정 end-to-end 합. 검색 latency를 빼면 분리형이 부당하게 유리해진다 |
| VRAM | `torch.cuda.max_memory_allocated()`. 프로세스 시작 시 reset. 분리형은 검출·판정부를 **동시 상주** 기준으로 잰다(현장 배포 형태) |
| 파라미터 수 | 학습 대상 파라미터와 전체 파라미터를 **둘 다** 보고(QLoRA는 두 값이 크게 다르다) |
| 통신량 | C가 라운드마다 남긴 직렬화 바이트 로그를 D가 집계. 중앙·로컬 칸은 0 |

측정 스크립트를 고정하고 5칸에 같은 스크립트를 돌린다. **median을 쓰는 이유**는 첫 배치
지연과 GC 스파이크가 평균을 흔들기 때문이다. p95도 함께 기록해 둔다.

## 5. RAG 색인·검색 설계

### 5-1. 성격 규정: 유사도 검색이 아니다

우리 검색은 **메타데이터 필터가 1차, 벡터 유사도는 보조**다. 질의는 구조화 키
`{결함 코드, 실측 치수, 모재 두께, 지정 품질 수준}`이며 자연어 질의를 생성하지 않는다.
자연어 질의를 만들면 (a) 재현성이 떨어지고 (b) 검색 실패의 원인이 질의 생성 탓인지 색인
탓인지 분리되지 않는다.

사실상 구조화 lookup이므로 **조항 top-1이 95% 이상 나와야 정상**이고, 미달이면 등급 어휘
정합성(§5-3)을 먼저 보고 그다음 색인 구축
오류를 먼저 의심한다.

> **명확히 해 둘 것:** dense 유사도 계산에는 질의 텍스트가 필요하다. 우리는 구조화 키를
> **결정론적 고정 템플릿**으로 직렬화해 쓴다(예: `결함코드=2011|두께=12.0mm|품질수준=C`).
> 이는 "자연어 질의 생성"(LLM이 문장을 만드는 것)이 아니다. 같은 키는 언제나 같은 문자열을
> 만들고, 템플릿은 파일로 고정해 스냅샷 해시에 포함한다.

### 5-2. 청크 스키마와 생성 경로

```json
{
  "chunk_id": "IACS47-3.2.1",
  "inspection_method": "RT",
  "doc": "IACS Rec.47",
  "clause_id": "3.2.1",
  "defect_codes": ["2011", "2012"],
  "thickness_min": 8, "thickness_max": 25,
  "quality_levels": ["B", "C"],
  "scope": "active",
  "text": "...조항 재서술 또는 무료 공개 원문..",
  "source_page": 14
}
```

**메타데이터는 계약 #3(`corpus/limits.csv`)에서 생성한다.** 두 곳이 어긋나면 판정 정합성이
통째로 무의미해지므로, 청크 메타를 손으로 채우는 경로를 금지한다.

```
corpus/limits.csv ─(B: derive_chunk_meta)→ corpus/derived/chunk_meta.jsonl ─┐
corpus/parse/*.md ─(조항 단위 청킹)────────────────────────────────────────┴→ chunks.parquet
```

**D는 `limits.csv`를 직접 읽지 않는다** (G5a, B 스펙 §1-4 금지 규칙 ④). `build_index.py`는
B의 `derive_chunk_meta(table)` 산출물 `corpus/derived/chunk_meta.jsonl`을 그대로 소비하고,
자체 pandas 순회로 메타를 만들지 않는다. 이유는 단순하다. D가 따로 순회하면 그 순간
소비처가 3곳이 아니라 **파생 규칙이 3벌**이 되고, 계약 #3의 위험 요인이 현실화된다.

B의 파생 규칙 중 D가 의존하는 것 셋을 명시해 둔다.

| 규칙 | 내용 | D에 대한 함의 |
|---|---|---|
| `clause_id` groupby, 집계는 합집합 | `defect_codes[]`·`quality_levels[]`가 조항 단위 합집합 | 필터는 `∈` 매칭이면 충분하다 |
| 두께 `[min 합집합, max 합집합)` 반구간, `+∞`는 null | 경계 두께에서 두 조항이 겹치지 않는다 | §5-3의 반구간 규약과 일치 |
| `scope=excluded` 행도 **포함**하되 플래그를 단다 | 검색은 되지만 채점에서는 제외 | 무근거 인용 1차 판정(§4-5)의 기준 집합이 유지된다. 채점 시 `scope != "active"` 청크가 인용되면 **별도 분류** |

- 청킹은 **조항 단위**. Docling의 제목 계층으로 경계를 잡는다. 고정 길이 분할 금지.
- `clause_id`가 `limits.csv`에 없는 조항(허용치 수치가 없는 서술 조항)도 색인에는 넣되
  `defect_codes`, `thickness_*`, `quality_levels`를 null로 둔다. **메타 필터에서 자동으로
  탈락**하므로 top-k를 오염시키지 않으면서, 무근거 인용률 1차 판정(색인 실존 여부)의
  기준 집합은 넓어진다.
- `limits.csv`에는 있는데 파싱 문서에 조항 본문이 없는 경우 → **빌드 실패**로 처리한다.
  경고로 넘기면 인용할 수 없는 정답 조항이 생기고, 조항 정확도의 상한이 조용히 내려간다.

### 5-3. 검색 절차

```
검출 결과 JSON
  → 질의 키 {inspection_method, defect_code, size_mm, thickness_mm, quality_level}
  → 1차 메타 필터 (pandas, 정확·범위 매칭)
       chunk.inspection_method == 질의 검사방식        ← 계약 #3 변경(확정 사항)
       AND defect_code ∈ chunk.defect_codes
       AND chunk.thickness_min <= thickness_mm < chunk.thickness_max
       AND grade_map[chunk.quality_scheme][질의 품질수준] ∋ chunk.quality_level
  → 후보 수에 따라 분기
       0건 → "해당 조항 없음" 반환, verdict=판정불가 (환각 방지, 프롬프트에 명시)
       1건 → 그것이 top-1, 검색 종료 (임베딩 호출 없음)
       2건+ → 결정론적 질의 문자열 임베딩 → 코사인 유사도 정렬 → top-3
  → 프롬프트 [검출 결과 + 조항 최대 3건] → LLM(배경지식 학습본, greedy 1회)
  → 판정문 JSON → 어댑터 → 공통 스키마
```

- **검사축(`inspection_method`)이 1차 필터의 첫 조건이다** (확정 사항). 같은 결함 코드라도 **표면 기공과 내부 기공은 허용치가 다르다.**
  축 없이 한 표에 섞이면 **검색이 잘못된 행을 집어도 형식상 정상으로 보이고, 판정 정합성이
  틀린 채로 높게 나온다** 지표 오류 중 최악의 형태다. 그래서 조건 순서에서 맨 앞에 둔다.
  - 질의의 검사방식은 manifest의 `modality` 컬럼(`RT`/`VT`)에서 온다. **주 실험은 RT
    한정**이므로 실질적으로 `RT` 고정이고, 동작이 바뀌지 않는다. 확장이지 재정의가 아니다.
  - VT 청크는 필터에서 자동 탈락하되 **색인에는 남긴다**. 빼면 그 조항이 영구 미검색이 되어
    무근거 인용 판정(§4-5 1차)의 기준 집합이 좁아진다.
  - 낯선 데이터 평가에서 VT로 확장할 때 이 축이 그대로 전환 손잡이가 된다.
- **등급 어휘는 스킴마다 다르다** (확정 사항). B가 `quality_level`을
  단일 `B/C/D` enum에서 **스킴 스코프 값**으로 바꿨다. IACS Rec.47은 `STD`/`LIM` 2단,
  KS는 류(類) 등급, 무등급 단일 한계 조항은 `ALL`이다. 질의 키의 품질수준은 iso5817 계열
  가정값(기본 `C`)이므로, **정확 매칭을 그대로 쓰면 IACS 유래 청크가 전부 탈락한다.**
  - 필터는 `grade_map[scheme][질의 수준] ∋ chunk 수준` 매핑을 **경유**한다.
    판정 정합성의 행 선택(`applicable_row`, §4-3)도 같은 매핑을 쓴다.
  - `configs/grade_map.yaml`은 **B 소유, D 소비**다. 가능하면 **B의 파생 함수에 매핑을
    내장해 D가 grade_map을 직접 읽지 않게** 한다(단일 소스 원칙). 그게 안 되면 D가 읽되
    해시를 MLflow 태그(`grade_map_sha256`)로 남긴다.
  - **미반영 시의 실패가 고약하다:** 후보 0건 → "해당 조항 없음" → `판정불가` 대량
    발생 → 조항 top-1이 95% 기준선을 크게 미달한다. 그런데 §7의 진단 규칙은 "미달이면
    색인 구축 오류부터 의심한다"이므로, **색인을 아무리 뒤져도 원인이 안 나온다.**
    원인은 색인이 아니라 두 트랙 사이의 등급 어휘 불일치이기 때문이다. IACS Rec.47이
    색인의 주력 문서라 발생 확률이 높다. → §7 진단 규칙에 "등급 어휘 정합성 먼저 확인"을
    앞세운다.
- **두께 구간 경계는 반구간 `[min, max)`로 고정**한다. 양끝 포함으로 두면 경계 두께에서
  두 조항이 동시에 걸려 top-1이 흔들린다. `limits.csv`가 이 규약을 따르는지 B와 맞춘다(G6).
  B의 V3(구간 무결성)이 `(material, defect_code, quality_scheme, quality_level, limit_type)`
  단위로 겹침·틈을 검사하므로, D는 그 검증을 신뢰하고 중복 구현하지 않는다.
- `top_k = 3` 고정. 5칸 공통.
- 검색 설정은 **칸별로 재학습하지 않는다.** 임베딩도 고정이고 RAG는 집계 대상이 아니다.

### 5-4. 임베딩 모델 선정: 벤치마크가 아니라 실측

```
1) gold_clauses.csv에서 질의 100건 추출 (결함코드×두께×품질수준 → 정답 chunk_id)
   - 실존 조합에서 층화 추출, 두께 경계 사례를 20% 포함시킨다
2) 후보별 top-1 / top-3 측정
   후보: BGE-M3 (MIT, dense+sparse, 한국어 상위) / KURE-v1 (BGE-M3 한국어 파인튜닝, dense 전용)
        / multilingual-e5-large / Qwen3-Embedding 소형
3) top-1 최고값 채택. 동률이면 라이선스가 명확하고 dense+sparse를 함께 주는 쪽(BGE-M3)
4) 채택 후 고정. 재학습·재선정 없음
```

**안전 기본값: BGE-M3.** 실측 전까지 이것으로 배관을 짠다. 임베딩 모델 교체는 파일 한 줄
설정 변경으로 끝나도록 인터페이스를 감춘다.

메타 필터가 1차이므로 dense는 후보가 2건 이상일 때만 개입한다. 즉 **임베딩 선택이 최종
성능에 미치는 영향은 제한적**이며, 이것이 이 결정에 시간을 많이 쓰지 않는 근거다.
dense 단독 top-1이 기준 미달일 때만 BM25 하이브리드를 추가한다(그때만 형태소 토큰화를
그 경로에 한정 적용).

### 5-5. 저장 형식: Chroma가 아니라 파일 3개

| 산출물 | 형식 | 이유 |
|---|---|---|
| 청크 메타 + 본문 | `rag/index/chunks.parquet` | pandas 필터가 1차 검색이므로 DataFrame이 자연스럽다 |
| 벡터 | `rag/index/vectors.npy` (float32, L2 정규화) | 청크 수백~수천이라 flat 전수 검색으로 충분 |
| 인덱스 | `rag/index/faiss_flat_ip.index` (IndexFlatIP) | 정규화 벡터에 내적 = 코사인 |
| 스냅샷 | `rag/SNAPSHOT.sha256` | 위 3개 + 프롬프트 파일 + 질의 템플릿 파일의 해시 |

**Chroma를 쓰지 않는 이유:** 메타데이터 필터가 내장이라 코드는 짧아지지만 내부 sqlite에
상태가 생겨 **스냅샷 sha256을 깔끔하게 고정하기 어렵다.** 불변조건 1-6(스냅샷 고정, 해시를
논문에 싣는다)이 우리 설계의 뼈대이므로, 파일 3개로 두는 쪽을 택한다. 청크가 수천 개
규모라 성능 이점도 없다.

**스냅샷 규약:** 색인 확정 후 `SNAPSHOT.sha256`을 부여하고 **재생성을 금지**한다. 재생성하면
검색 결과가 바뀌어 이미 돌린 칸과 재현이 어긋난다. 변경이 불가피하면 새 스냅샷 ID를 부여하고
영향받는 칸을 **전부 다시 돌린다.** 일부만 다시 돌리는 것을 금지한다.

### 5-6. 판정부 프롬프트 규약

- `rag/prompts/verdict_v1.txt` 한 파일에 고정. **5칸에서 한 글자도 다르면 안 된다**
  (불변조건 3-3). 파일 해시를 스냅샷에 포함하고 MLflow에 태그로 남긴다.
- 명시할 내용: 출력 JSON 스키마, "검색 결과가 0건이면 `해당 조항 없음`을 출력하고
  verdict를 `판정불가`로 할 것", "제시된 조항 외의 조항 번호를 만들어내지 말 것".
- greedy(temperature 0) 1회. **재시도·재프롬프트 없음.**
- 통합형에는 검색을 붙이지 않는 것이 기본이다. 여유가 있으면 검색 결과를 컨텍스트로 넣은
  보조 조건 1회를 부록에 추가한다(실험설계 7장). 이때도 프롬프트 파일을 별도 버전으로
  두고 본 실험 파일을 수정하지 않는다.

### 6-1. 스키마

| 컬럼 | 타입 | 설명 |
|---|---|---|
| **`inspection_method`** | str | **`RT` / `VT`**. 계약 #3 변경(확정 사항). **유일성 키의 첫 축**이다 |
| `defect_type_ko` | str | 원본 라벨 (균열/기공/융합불량/슬래그혼입) |
| `iso_code` | str | ISO 6520-1 코드 |
| `thickness_min` / `thickness_max` | float | 반구간 `[min, max)` |
| `quality_level` | str | B / C / D |
| `clause_id` | str | 조항 ID (= 색인의 `chunk_id`) |
| `source_doc` | str | 출처 문서명 |
| `limit_type` / `limit_value` / `unit` | str/float/str | `limits.csv`에서 승계 |
| `verified_by` | str | 확인자 |
| `verified_at` | date | 확인일 |
| `verify_note` | str | 이견·유보 사항 |

### 6-2. 생성과 확인 경로

```
corpus/limits.csv ──(B: derive_gold_clauses)──> corpus/derived/gold_clauses.csv
                                                             ↓
                              evaluation/gold/build_gold_clauses.py. 유일성 assert + 격리 복사
                                                             ↓
                                          전문가 확인은 **파생물이 아니라 원천(limits.csv)에**
                                                             ↓
                                     오류 발견 → B가 원천 수정 → 전체 재파생 → 재잠금 + sha256
```

**파생물을 직접 수정하지 않는다**(B 스펙 §1-4 금지 규칙 ②). 전문가가 조항 오류를 찾으면
`gold_clauses.csv`가 아니라 `limits.csv`를 고치고 전체를 다시 파생한다. 파생물을 손보면
그 순간 단일 소스가 깨지고, 다음 재파생에서 수정이 조용히 사라진다.

- **`build_gold_clauses.py`가 유일성을 assert한다** (C의 R-재현 Minor #2). G6(조합 유일성)이
  깨지면 §6-3 완화 규칙으로 넘어가는데, **누가 언제 검사하는지가 없으면 "조용한 다대다"가
  그대로 통과한다.**
  **`(inspection_method, defect_code, material, thickness 구간, quality_scheme, quality_level)`**
  키의 중복을 검사해 위반 시 **빌드 실패**로 처리하고 원천을 고친다. 경고로 넘기지 않는다.
  검사축이 키에 들어간 것이 계약 #3 변경의 핵심이다. 이 축이 없으면 표면·내부 기공 행이
  같은 키로 보여 "조용한 다대다"가 유일성 검사를 통과해 버린다.
- **손으로 새로 쓰지 않는다.** B의 `derive_gold_clauses`가 만든다. D는 유일성 검증과 격리 복사만 한다. 두 파일이
  어긋나면 판정 정합성(§4-3)이 자기 자신을 채점하는 꼴이 된다.
- 확인 경로: 외부 도메인 전문가(협의 예정) 경로(실험설계 4-5·8-3). **표본이 아니라 전량 확인**이다. 조합
  수가 수백 건 규모라 가능하고, 이 목록이 흔들리면 §4의 조항 지표 4종이 통째로 흔들린다.
- 방어 논리: **표준 원문의 조항 번호를 그대로 인용**한다. 우리가 조항을 재해석해 매핑하는
  것이 아니라 "표의 이 행이 이 조항에서 왔다"는 출처 추적만 한다. 해석이 개입하지 않으므로
  전문가 확인이 "맞는가"가 아니라 "출처가 맞는가"의 확인이 되어 부담이 낮다.
- 확인 전에도 D는 초안으로 채점 배관을 돌린다. **확인 완료 전 산출한 조항 지표는 예비값으로
  표시**하고 논문에 싣지 않는다.

### 6-3. 위험: 다대다 매핑

한 (결함코드, 두께, 품질수준) 조합에 조항이 여럿 대응하면 top-1 정확도의 정의가 무너진다.
G6에서 B에 유일성을 요구했다. 실제로 다대다가 나오면:

- **안전 기본값:** `clause_id`를 리스트로 두고, top-1은 "리스트 중 하나라도 맞으면 정답"으로
  완화한다. 인용 일치율도 같은 규칙. 완화했다는 사실을 표 각주에 명시한다.

## 7. 해석 기준선 (사전 합의 · 사후 합리화 방지)

**결과를 보기 전에 확정한다.** 이 표를 게이트에서 총괄이 승인하면 이후 변경 불가다.

| 항목 | 기준선 | 미달 시 조치 |
|---|---|---|
| **분리·중앙 Macro-F1** | **0.85 이상 = 파이프라인 정상** | 결과를 해석하기 전에 **라벨·분할 오류부터 점검.** 성능 튜닝을 먼저 하지 않는다 |
| **분리형 회복률** *(Macro-F1 기준)* | 90% 이상 강한 결과 / 80~90% 방어 가능 | 80% 미만이면 non-IID 심화 효과로 해석하고 **클라이언트별 분해**를 제시 |
| **통합형 유지율** *(Macro-F1 기준)* | 90% 이상이면 "통합형도 연합 가능" 주장 성립 | 미달은 그 자체가 RQ2의 답 |
| **조항 검색 top-1** | **95% 이상이 정상** | 미달 시 진단 순서 고정: ① **등급 어휘 정합성**(grade_map 경유 매칭이 실제로 걸리는가, §5-3) → ② 색인·메타데이터 구축 오류 → ③ 두께 구간 경계. **모델을 바꾸지 않는다.** ①을 앞에 둔 이유는 §5-3에 적었다 |
| **판정 정합성** | **95% 이상 기대** | 미달분은 §4-3의 오류 유형 분해(조항 오검색 vs 대소 비교 실패)로 보고 |
| **통합형 절대 성능** | 제로샷 대비 유의한 향상이 있으면 학습 효과 성립 | 분리형에 밀려도 그 자체가 RQ2의 답 |
| **RQ3 편익** | C3의 결함 recall이 로컬 대비 **+5%p 이상**이면 참여 편익 주장 성립 | 미달이면 "소규모·특수재 클라이언트에는 편익이 제한적"이 결과 |
| **파싱 실패율** | 통합형 5% 미만이면 정상 범위 | 초과 시 원인을 `parse_error` 분해로 보고. **재프롬프트로 낮추지 않는다** |
| **BBox-IoU** | 선행 연구 0.953은 다른 데이터·다른 정의라 목표치가 아니라 참조점 | **0.1 이하가 나오면 성능이 아니라 좌표계를 의심한다** (§3) |

헤드라인 수치 정의(변경 불가):

```
분리형 회복률 = (분리·연합 − 분리·로컬평균) / (분리·중앙 − 분리·로컬평균) × 100   (Macro-F1 기준)
통합형 유지율 = 통합·연합 / 통합·중앙 × 100                                      (Macro-F1 기준)
RQ3 편익      = C3의 분리·연합 성능 − C3의 분리·로컬 성능                        (결함 recall 기준)
```

**기준 지표를 결과보다 먼저 고정한다** (검토 결정 #1). 회복률·유지율은 **Macro-F1**로,
RQ3 편익은 **결함 recall**로 산출한다. 다른 지표로도 계산해 부록에 실을 수는 있으나,
헤드라인 숫자는 이 정의 하나다. 여러 지표로 계산해 놓고 좋은 것을 고르면 사후 합리화다.

분리·로컬평균은 **3사 단순 평균**이다(표본 수 가중이 아니다). 가중 평균을 쓰면 C3의 열세가
희석되어 RQ3의 대비가 약해진다. 3사 개별값도 함께 싣는다.

**미달이 곧 실패가 아니다.** 다섯 칸 비교가 성립하는 한, 어느 칸이 어디서 무너지는지가 결과다.

## 8. MLflow 로컬 배관

### 8-1. 저장소 구성

```
tracking/
  mlruns.db            # sqlite backend store
  artifacts/           # 파일 artifact store
```

```python
mlflow.set_tracking_uri("sqlite:///tracking/mlruns.db")
mlflow.set_experiment("weld-fl")   # artifact_location = tracking/artifacts
```

- **외부 클라우드 로깅 금지.** W&B를 쓰지 않는다. 기본이 클라우드 로깅인 도구는 비반출
  서사와 충돌한다(불변조건 2-3). `WANDB_*` 환경변수 존재 시 러너가 즉시 실패하도록 한다.
- `tracking/mlruns.db`와 `artifacts/`는 정션으로 본체와 공유되는 대형 산출물 폴더다.
  git에 커밋하지 않는다.

### 8-2. run 규약과 필수 로깅

run 이름: `{cell}_{seed}_{yymmdd}` (예: `sep_fed_s0_260910`)

| 종류 | 항목 |
|---|---|
| **params** | config YAML 전개값 전체(중첩은 `.`으로 평탄화), `R`, `E`, `N`, `top_k`, `gpu_profile` |
| **tags** | `git_commit`, `manifest_sha256`, `label_map_sha256`, `limits_sha256`, `grade_map_sha256`, `rag_snapshot_sha256`, `prompt_sha256`, `base_ckpt_sha256`, **`coords_sha256`**(C의 `vlm/coords.py` 모듈 해시), **`coord_cfg_hash`**, `verdict_mode` |
| **metrics** | §4의 전 지표. FL은 **round를 step으로** 로깅 |
| **artifacts** | config YAML 원본, 예측 jsonl, `metrics.json`, 학습 곡선, 혼동행렬 이미지, 라운드별 지표 CSV |

**`base_ckpt_sha256`·`coords_sha256`·`coord_cfg_hash`가 5칸에서 동일한지 검사하는 스크립트를 채점기에 붙인다.** 다섯 칸이
같은 출발점에서 시작했다는 것이 논문의 전제인데, 이를 사람이 확인하면 언젠가 놓친다.

`log_run.py`가 위 항목의 **누락을 즉시 실패로 처리**한다. 나중에 채우기로 하면 안 채워진다.

### 8-3. Flower 결합

> **정정 (2026-08-17, C의 R-재현 리뷰 결과).** 이 절은 원래 "라운드 r의 글로벌 모델을
> **글로벌 평가셋**으로 채점해 `step=r`로 로깅한다"였고, 구현설계 7-4를 그대로 승계한
> 서술이었다. C가 이것이 평가 자산 격리 원칙과 충돌한다고 지적했고 **그 지적이 옳다**.
> 라운드마다 평가셋 지표가 보이면 그것을 보고 학습을 끊고 싶어지고, 실제로 끊지 않더라도
> 심사에서 "학습 중 평가셋 지표를 봤는가"에 봤다고 답해야 한다. 그 순간 R×E=N 등가라는
> 공정성 주장의 방어선이 약해진다. 아래는 정정본이며, 구현설계 7-4 문구 정정도 게이트
> 안건으로 올린다.

- **서버 evaluate 콜백에서만 로깅한다.** 클라이언트 쪽은 로깅하지 않는다. 3개 클라이언트가
  같은 run에 동시에 쓰면 step이 뒤섞인다.
- **라운드별 곡선은 `val`로 낸다** (확정 사항).
  `val`은 **학습 풀의 10%, 묶음 단위·층화, 로깅 전용** 분할이며(A의 Q3에서 정의된 기존
  자산) **글로벌 평가셋이 아니다.** 라운드 r의 val 지표를 `step=r`로 남긴다.
- **글로벌 평가셋은 전 실험을 통틀어 최종 채점 1회만 접근한다.**
  지킬 불변식은 "접근 0회"가 아니라 **"평가셋이 학습·선택에 영향을 주지 않는다"** 이다.
  조기 종료를 금지하고 last를 채점하므로 라운드별 평가에는 선택압이 없지만, 문구를
  느슨하게 두면 심사에서 불필요하게 공격당한다. 그래서 두 집합을 분리해 둔다.
- **라운드 CSV에 기준 집합을 기계 판독 가능하게 박는다** (C의 R-재현 Important #3 제안
  채택): 컬럼 `eval_set`에 `"val"`을 명시한다. 사후 backfill로 평가셋 채점을 실을 때는
  `"eval_final"`로 구분한다. 문서로만 구분하면 언젠가 섞인다.
- **VLM 칸의 라운드 값은 val loss다**(생성 없음, C 스펙 §4-3). Macro-F1 열은 VLM 라운드
  행에서 비어 있으며, 이는 결측이 아니라 정의상 부재이므로 `N/A(생성 미수행)`로 채운다.
- 라운드별 지표 CSV의 지표 열은 **사후 채움(backfill) 열**이다. C의 서버는 라운드 중
  loss·norm·바이트만 보내고, 지표는 완주 후 D가 보존 체크포인트로 산출해 같은 run에
  `step=r`로 채운다. `log_run.py`의 "필수 항목 누락 시 즉시 실패" 정책이 **라운드 시점에
  지표를 요구해 러너를 매 라운드 실패시키지 않도록**, 필수 검사 시점을 run 종료로 둔다.
- **글로벌 평가셋 채점은 학습 완주 후 사후 1회**다. 라운드별 곡선이 필요하면 C가 보존한
  마일스톤 라운드 체크포인트(25/50/75/100%)를 D 채점기가 사후 평가해 점 4개로 그린다.
  곡선의 목적은 추세를 보이는 것이지 매 라운드를 감시하는 것이 아니다.
- VLM 칸은 라운드별 서버 평가 자체가 없다(C 스펙과 정합). loss·norm만 남기고 곡선은
  마일스톤 어댑터로 사후 산출한다.
- C의 Q7에 대한 D의 답: **수용**한다. 서버가 저장한 글로벌 raw state_dict
  (`sep_fed_global_r{r}_s{seed}.pt` + config + 해시 동반)를 D 채점기가 로드해 사후 평가하는
  규약으로 확정하고, §8-5 체크포인트 규칙의 FL 항목과 일치시킨다.
- 라운드별 지표 CSV(`round, loss, macro_f1, bytes_up, bytes_down`)를 MLflow와 **별도로도**
  남긴다. 그림 생성 스크립트가 MLflow API를 타지 않고 CSV를 직접 읽게 하기 위해서다.
- 집계 직전·직후 파라미터 norm을 라운드마다 로깅한다. 순서 뒤섞임·dtype 불일치를 잡는
  저비용 안전장치다(구현설계 10-3). D는 이 값을 소비만 하고 생성은 C가 한다.

### 8-4. 결과표 자동 생성

`evaluation/report/build_table.py`가 MLflow에서 지표를 뽑아 실험설계 8-6의 표를
markdown + CSV로 생성한다. **손으로 옮겨 적지 않는다.**

- 시드 3개가 있는 칸은 `평균 ± 표준편차`로 자동 조립.
- 값이 없는 칸은 빈칸이 아니라 `N/A(사유)`로 채운다. 빈칸은 "아직 안 돌렸다"와 "산출
  불가"를 구분하지 못한다.
- 각주(중앙집중 행의 "현실에서는 반출 불가", 통합형 mAP의 상수 신뢰도, 조건부 판정의
  가정값)를 **템플릿에 미리 넣어 둔다.** 사람이 각주를 기억해서 다는 구조를 만들지 않는다.

### 8-5. 체크포인트 규칙

| 항목 | 규칙 |
|---|---|
| 명명 | `{cell}_{stage}_{round\|epoch}_{seed}.pt` |
| 보존 | 로컬·중앙 칸은 **last만**. FL 칸은 최종 + 마일스톤(25/50/75%) 글로벌만 |
| 동반 저장 | 같은 폴더에 `config.yaml`, `metrics.json`, git commit hash |
| 공통 출발점 | 배경지식 학습 완료 병합본을 별도 디렉터리에 동결하고 해시 기록. 5칸이 전부 이 해시를 로깅 |
| 정리 | 마일스톤 외 자동 삭제 스크립트. **`last`는 절대 자동 삭제 대상에 넣지 않는다** |

`best.pt`를 채점하지 않는다. best 선택은 val 기준의 암묵적 조기 종료다. 채점기는 입력
체크포인트 파일명에 `best`가 포함되면 **경고가 아니라 실패**를 낸다.

## 9. `make reproduce-check`

새 환경에서 1회 실행해 재현성을 확인하는 단일 진입점. 논문 제출 전 필수 절차다.

```make
reproduce-check: check-isolation check-manifest check-scorer check-retrain
```

| 단계 | 내용 | 통과 기준 |
|---|---|---|
| `check-isolation` | §1의 경로 격리 검사 + 학습 소비 ID ↔ eval split 교집합 | 위반 0건 |
| `check-manifest` | manifest 재생성 후 sha256 대조 (A의 스크립트 호출) | 해시 완전 일치 |
| `check-snapshot` | corpus·페어·RAG 색인 sha256이 `SNAPSHOT.sha256`과 일치 | 완전 일치 |
| `check-scorer` | 보관된 예측 jsonl로 채점기 재실행 → `metrics.json` 대조 | **비트 단위 일치** (결정론적이어야 한다) |
| `check-retrain` | 분리·중앙 1시드 재학습 후 지표 대조 | Macro-F1 절대오차 **0.01 이내** |
| `check-schema` | `schema.py`에서 생성한 JSON Schema가 커밋본과 일치 | 완전 일치 |
| **`check-contract3-sync`** | **계약 #3의 3 소비처 동기화**. ① RAG 청크 메타(`chunk_meta.jsonl`) ② 정답 조항 목록(`gold_clauses.csv`) ③ 채점기 `applicable_row` 선택. 이 셋이 **같은 `limits.csv` 스냅샷 해시에서 파생됐고 축 집합(`inspection_method` 포함)이 동일한가** | 해시·축 집합 완전 일치 |
| `check-coords` | **C의 `vlm/coords.py` 골든 픽스처를 D가 독립 재실행** + Q20 실측 봉인 + `coord_cfg_hash`/`coords_sha256` 5칸 전수 대조 (§3-2·§3-3d). D는 변환을 재구현하지 않는다 | 전부 통과 |

- `check-scorer`가 **비트 단위 일치**를 요구하는 이유: 채점기에 비결정성이 들어가면
  (set 순회 순서, greedy 매칭, 부동소수 누적 순서) 그 순간 5칸 비교의 신뢰가 사라진다.
  Hungarian 매칭(§4-6)을 택한 것도 이 요구 때문이다.
- `check-retrain`의 0.01 허용치는 GPU 비결정성(cudnn atomics)을 감안한 값이다.
  `cudnn.deterministic=True`로도 완전 재현이 안 되는 연산이 있다.
- 각 단계는 **독립 실행 가능**해야 한다. 전체가 수 시간 걸리므로 실패한 단계만 다시 돌린다.

| Q13 | RIAWELC 로 전환할 경우 결과표 처리 | 열을 지우지 않고 `N/A(위치 라벨 없음)` 로 채움. 비교 항목 5→4 명시 (§4-10) | 백업 전환 시 | 논문 서술 |
| Q14~Q22 | 좌표 규약 관련 9건 | **§3-6 표 참조.** 검토에서 Q14·Q15·Q19·Q20 승인, **Q16 닫힘(C안 채택)**, Q17·Q18 기본값 유지, Q21·Q22 신규 | (해당 없음) | §3 |

**Q4와 Q12가 일정상 임계경로에 가깝다.** Q4는 색인 스냅샷을 얼리는 조건이라 학습 시작 전에
닫아야 하고, Q12는 최소 성립선(분리형 3칸 + 조항 정확도)의 마지막 관문이다. 나머지는
채점기 재실행으로 흡수되므로 늦게 닫혀도 비용이 작다. **이것이 채점기를 학습보다 먼저
만드는 실질적 이득이다.**
