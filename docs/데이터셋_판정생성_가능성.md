# 이미지 자료로 어떤 판정문을 만들 수 있는가

이 문서는 창원 AI허브 71761의 이미지·라벨만으로 결함을 찾아 설명하는 일과, 규격에 따라 합격 여부를 결정하는 일을 어디까지 할 수 있는지 구분한다. 2026-08-23 라벨 JSON 129,613개 전수 스캔(파싱 실패 0)과 원천 이미지 표본 확인을 근거로 한다. 후속 재질 해석은 [사전실험 보고](사전실험_보고.md)를 반영했다.

**확인된 자료만으로 실치수 기준 합부 판정 정답을 만들 수 없다.** 결함 종류와 픽셀 위치는 있지만 두께, 픽셀-mm 스케일, 적용 규격·등급, 전문가 합부 판정이 없다. 이 빈칸을 가정값으로 채운 문장은 합성 학습·평가 자료이며 실제 검사 정답과 구분해야 한다.

## 1. 자료가 제공하는 정보

| 정보 | 확인 결과 | 사용할 수 있는 범위 |
|---|---|---|
| 결함 종류 | `annotations[].case`, 전체 RT·VT에서 7종 표기 | 결함 유형 설명. RT 주 실험은 정상 포함 5클래스 |
| 위치 | 폴리곤 288,097개, 절대 픽셀 | 위치 학습·평가. 정상 폴리곤과 좌표 이상은 별도 처리 |
| 명목 재질 | `info.material`: ST/AL, 결측 0% | 데이터셋이 제공한 출처 구분. 실제 재질 확정에 사용하지 않음 |
| 상대 크기 | 폴리곤에서 면적·장축 길이 계산 가능 | px²·px 단위의 형상 설명 |
| 두께·실치수·픽셀-mm 스케일 | 라벨 필드 없음, 결측 100% | 실치수 기준 대조 불가 |
| 이음 형상·용접 자세·규격·등급 | 라벨 필드 없음, 결측 100% | 별도 확인 또는 명시적 가정 필요 |
| 합부·재작업 판정·판정자·판정일 | 라벨 필드 없음 | 실물 판정 정답 없음 |
| 조치 지침·자유 소견 | 라벨 필드 없음 | 규정 자료나 합성 과정의 별도 근거 필요 |

두께·스케일·촬영조건·환산 관련 어휘를 키와 문자열 값 양쪽에서 전수 검색했지만 일치 항목은 0건이었다. 문자열 필드도 파일명, 클래스·모달·재질 등 열거형뿐이었다. `image_data.information`과 `annotations[].case`는 검사 소견이 아닌 클래스 이름이다.

## 2. 필름에 보이는 글자를 활용할 수 있는가

파노라마 필름 표본에서는 두께, ASTM 재질규격, 촬영일, 현장·라인을 나타내는 납글자를 확인했다. 일부 표본에 ASTM A335 P11·A234 WP11 같은 강 계열 규격이 보였으며, 후속 확인에서는 명목 AL과 실제 재질이 일치한다고 단정할 수 없다는 문제가 드러났다. 현장 식별자나 원문 픽셀의 전사는 이 문서에 싣지 않는다.

라벨에 메타데이터 필드가 없다는 결과와 픽셀에 글자가 있다는 결과는 양립한다. 다만 글자가 남아 있는 이미지가 대부분 정상 파노라마라 결함 이미지의 누락 조건을 채우지 못한다.

| 이미지 구분(RT·VT 전체) | 파노라마 | 전체 | 비율 |
|---|---:|---:|---:|
| 결함 | 17 | 68,879 | 0.025% |
| 정상 | 48,679 | 60,734 | 80.2% |

결함 이미지는 대부분 1280×720 크롭이며 확인한 크롭 표본에는 납글자가 없었다. 연속 ID 묶음 12,956개 중 파노라마와 크롭이 함께 들어 있는 묶음은 10개(145장)뿐이다. 크롭끼리인 묶음 7,115개, 파노라마끼리인 묶음 3,079개도 확인했다. 이 구분만으로 모든 묶음의 성격을 확정하거나 크롭을 원판에 연결할 수는 없다.

확인한 필름 3장 중 2장에는 일부 글자 영역을 회색으로 가린 흔적이 있었다. 정상 파노라마 48,679장의 OCR을 검토할 수는 있지만, 결함 이미지로 값을 옮길 연결 키가 없고 마스킹도 일정하지 않다. 곡면 배관의 투영 영상에서 외경 등을 mm/pixel로 환산하려면 별도의 검증도 필요하다. OCR 추출을 실행·검증했다는 의미는 아니다.

## 3. 픽셀 크기와 실제 결함 크기의 차이

폴리곤 면적은 신발끈 공식으로 구할 수 있다. 아래는 확보 당시 RT 결함 폴리곤 실측 기록이며 단위는 모두 px²다. 재질 표기는 명목 구분이다.

| 구분 | 인스턴스 | 최소 | 중앙값 | 평균 | 최대 |
|---|---:|---:|---:|---:|---:|
| AL / 균열 | 517 | 1 | 5,999 | 7,624 | 43,816 |
| AL / 기공 | 6,953 | 34 | 1,172 | 4,615 | 1,339,802 |
| AL / 슬래그혼입 | 2,046 | 32 | 8,744 | 11,144 | 92,576 |
| AL / 융합불량 | 428 | 176 | 11,490 | 17,288 | 165,636 |
| ST / 균열 | 4,410 | 24 | 10,280 | 19,445 | 219,008 |
| ST / 기공 | 88,402 | 2 | 1,288 | 2,650 | 900,567 |
| ST / 슬래그혼입 | 2,288 | 12 | 8,592 | 12,296 | 213,412 |
| ST / 융합불량 | 4,019 | 16 | 19,168 | 27,582 | 336,264 |

ISO 5817·10675 등의 실치수 허용치와 대조하려면 촬영별 환산 정보가 필요하다. 같은 해상도도 동일한 물리적 스케일을 보장하지 않는다. 전체 자료의 해상도가 9,767종이라는 점까지 고려하면 임의의 공통 스케일을 넣을 근거가 없다. 동일 이미지 안의 상대 형상 비교에는 활용할 수 있지만, 이 표를 mm²나 합부 판정으로 바꾸지 않는다.

## 4. 정상 라벨을 합격 판정으로 읽지 않는 이유

폴더 클래스와 폴리곤을 전수 대조한 결과, 정상 폴더의 결함 폴리곤은 0건, 결함 폴더에서 정상 폴리곤만 있는 경우도 0건이었다. 양쪽 모두 폴리곤이 0개인 이미지는 없었고, `defect`와 `normal`이 한 이미지에 섞인 경우는 1건이었다. 나머지 129,612건은 폴더와 폴리곤의 정상·결함 구분이 일치했다.

이 결과는 라벨 내부의 일치에 관한 것이다. 규격·등급·합부 필드가 없으므로 `normal`을 허용치 이내 합격으로 해석할 근거가 없다. 마찬가지로 **결함이 있지만 합격인 사례의 수는 셀 수 없다.** 과거 문서의 0건 표현은 이 자료에 합부 정답이 없다는 뜻으로 한정해야 하며, 실제 현장 사례가 없다는 결론으로 사용하지 않는다.

## 5. 합성 자료와 평가의 범위

이미지에 직접 근거를 둘 수 있는 것은 결함 종류·픽셀 위치·명목 재질이다. 두께·실치수·규격·등급·합부·조치가 포함된 이미지-판정문 페어를 만들면 그 부분은 별도의 조건과 규칙으로 생성한 합성 정보다. 이미지를 보고 측정하거나 검사원이 판정한 정답처럼 기록하면 안 된다.

현재 자료에 맞는 이미지 과업은 후보 조항과 부족한 정보를 제시하는 `clause_only` 범위다. 조건을 명시한 텍스트에서 규칙을 적용하는 과업은 별도로 검토한다. 원문 허용치 대조, 합성 조건 표시, 사람의 정답 검토가 완료됐는지는 각각 확인해야 한다.

| 평가하려는 것 | 정답의 근거 | 해석상 제한 |
|---|---|---|
| 결함 종류·위치 | 원본 이미지 라벨 | 라벨 품질, 데이터 편향, 분할 중복 문제를 별도 검증해야 함 |
| 조항 검색 정확도·인용 일치율 | 작성한 정답 조항 목록 | 목록과 조건의 적합성을 사람에게 검증받아야 함 |
| 합성 조건에서의 판정 정합성 | 설정한 조건과 규칙 | 실제 검사 성능이 아닌 규칙 재현 정도 |
| 무근거 인용 여부 | 인용 대상이 색인에 존재하는지 | 조항의 존재 확인만으로 적용의 정확성을 보장하지 않음 |

과거 통합형·분리형 비교 설계에서도 두 방식이 같은 합성 규칙으로 학습·채점되면 규칙 재현 비교는 가능하지만 현장 판정 성능 검증으로 확대할 수 없었다. 현재 본실험 범위는 [실험설계](실험설계.md)를 따른다. 현재 검출기 사전실험의 점수 역시 규정 판정 성능을 나타내지 않는다.

규정 후보의 사용 조건과 추출 현황은 [corpus 후보 판정](corpus_후보_판정.md)에 있다. 정상 파노라마 OCR의 채택 여부, 사람 정답 검증, 판정 과업의 최종 표현은 미완료 사항으로 남긴다.
