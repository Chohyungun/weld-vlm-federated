# 데이터셋 등록부와 메타데이터 설계

데이터셋 등록부는 자료의 출처, 이용 조건, 라벨 구조, 입력 경로를 담는 JSON 문서다. 한 데이터셋을 한 파일로 설명하며, 이미지별 학습·평가 목록인 매니페스트와 역할을 나눈다. 등록부의 형식 검사를 통과해도 자료의 사실성이나 전문가 확인을 대신하지는 않는다.

이 문서는 필드 구성과 설계 원칙을 설명한다. 실행에 사용하는 라벨 사상표는 `configs/label_map.yaml`, 등록부의 필수 키와 값은 `data/registry/_schema/dataset_registry.schema.json`을 따른다. 실제 실험 입력은 잠긴 매니페스트로 식별한다. 이미지 62,308장의 분할 목록과 실험 범위는 [README](../README.md), 원천 자료의 측정값은 [데이터셋 현황](데이터셋_현황.md)과 [실물 구성](데이터셋_실물확보.md)을 참조한다.

## 등록부와 매니페스트의 역할

등록부는 어댑터에 필요한 데이터셋의 출처·구조·제약을 설명한다. `manifest.csv`는 이미지 1장당 1행, `annotations.csv`는 결함 1개당 1행을 담는다. 등록부를 고쳐도 이미 잠긴 매니페스트의 값은 바뀌지 않는다.

```
data/registry/datasets/<id>.json
  ├─ scripts/validate_registry.py       스키마·라벨·반출 제약 검사
  └─ scripts/build_registry_index.py    데이터셋별 문서를 index.json으로 집계

configs/label_map.yaml + data/ingest/<id>.py
  └─ manifest.csv / annotations.csv    원본 파일을 읽어 기계 생성
```

학습·평가·채점 코드는 등록부를 직접 읽지 않는다. `scripts/link_raw.py`는 수집 폴더를 `data/raw/`에 연결할 때 등록부를 이용하지만, 학습·평가 데이터를 읽는 경로와는 구별한다.

`sha256`, `phash_hex`, `group_id`, `group_size`, `strata_key`, `split`, `client`, `eval_subset`, `width_px`, `height_px`는 파일과 분할 절차로 계산한다. 좌표와 면적도 원본 라벨에서 유도한다. 같은 값을 수작업 JSON에 다시 적지 않는다.

### 규모 비교

아래는 인덱스 작성 단위를 비교한 설계 추산이다. 실제 분할 크기나 처리량을 측정한 결과가 아니다.

| 비교 항목 | 이미지 단위 | 데이터셋 단위 |
|---|---|---|
| 항목 수 | 62,998 (AI허브 RT만) | 15~20 (전 데이터셋·말뭉치·문서) |
| 1건 작성 | 10초 | 40~90분 |
| `index.json` 크기 | 8~28 MB | 약 80 KB |
| 오타 1건의 영향 | 이미지 1장 (수작업 대조 필요) | 데이터셋 전체 (검증 대상) |

데이터셋 수준의 선언은 사람이, 이미지 수준의 값은 어댑터가 만든다.

## 파일 배치

```
data/registry/
├── _schema/dataset_registry.schema.json
├── _TEMPLATE_image.json
├── _TEMPLATE_text_corpus.json
├── _TEMPLATE_document.json
├── datasets/
│   ├── riawelc.json
│   ├── lohi_weld.json
│   ├── aihub71761.json
│   ├── hf_<name>.json
│   └── std_<doc_id>.json
├── index.json
└── README.md
```

파일명은 `dataset_id + ".json"`이며 식별자 형식은 `^[a-z][a-z0-9_]{2,31}$`다. 파일명에 사람 이름을 넣지 않는다. 작성자 정보는 `authoring.owner`에 둔다. 집계 파일 `index.json`은 수작업으로 수정하지 않고 데이터셋별 파일에서 다시 만든다.

### 최상위 필드

| # | 키 | 필수 | 내용 |
|---|---|---|---|
| 1 | `$schema` | 필수 | `"../_schema/dataset_registry.schema.json"`. VS Code의 자동완성과 실시간 키 검사를 켠다. 추가 설치 없이 사용 가능 |
| 2 | `registry_schema_version` | 필수 | 정수. 현재 `1` |
| 3 | `dataset_id` | 필수 | 파일명과 일치. `kind=image`이고 `pipeline.eligible=true`면 라벨 사상표 `sources` 키·어댑터 `source` 상수와 3중 일치 |
| 4 | `kind` | 필수 | `image` \| `text_corpus` \| `document`. 이 값이 이하 필수 키 집합을 가른다 |
| 5 | `authoring` | 필수 | `owner` · `written_at` · `reviewer` · `reviewed_at` · `review_status`. 작성·독립 확인의 주체와 상태 |
| 6 | `provenance` | 필수 | 원천·출처. 발행처 · URL · 판본 · 접근조건 · 라이선스 · 인용의무 · 반출 제약 |
| 7 | `acquisition` | 필수 | 경로(수집 쪽). 어디에 받았는가, 어떤 상태인가 |
| 8 | `pipeline` | 필수 | 경로(파이프라인 쪽) + 투입 여부. `eligible` · `raw_subdir` · `dataset_subpath` · `adapter` |
| 9 | `constraints` | 필수 | 이용 조건의 값 표현. 클라우드 업로드·외부 API·상업 이용 가부. 검증기가 읽는 레드라인 필드 |
| 10 | `layout` | image | 파일 배치 규칙. 어댑터 `discover()`의 입력 명세 |
| 11 | `label_vocabulary` | image | 원본 라벨 어휘 전량 + L2 사상 제안 |
| 12 | `fields_declared` | image | 기준 스키마 10키의 보유 여부와 근거 |
| 13 | `counts_announced` | 필수 | 공지·실측 수량 + `basis` + `verified: false` |
| 14 | `samples` | 필수 | 이미지·클래스·조치 지침의 보유 여부와 실물 예시 ≤5건 |
| 15 | `probe_result` | . | 기계 실측 결과. 사람이 쓰지 않는다. 없으면 `null` |
| 16 | `open_items` · `notes` | . | 해소되지 않은 항목의 등급·확인 방법·주체·기한 / 자유 서술 |

`kind=text_corpus`와 `kind=document`는 이미지 전용 항목 대신 `text` 또는 `document` 블록을 갖는다. JSON Schema의 `if/then`으로 필수 필드를 구분하고, 객체에는 `additionalProperties: false`를 적용해 키 오타를 거부한다.

`samples.examples`는 실물 예시만 담으며 `maxItems: 5`로 제한한다. 전수 이미지 목록은 매니페스트에만 둔다.

## 매니페스트 필드 대응

표의 ‘사람’은 데이터셋의 이름·값 공간·원본 키 경로를 선언한다는 뜻이다. 개별 이미지의 값을 직접 입력한다는 뜻은 아니다. ‘어댑터’는 원본 바이트와 라벨을 읽어 계산하고, ‘후속’은 중복 제거와 분할 단계가 계산한다. ‘파생’은 다른 필드에서 유도한다.

### `manifest.csv` 30컬럼

분할 방법과 `eval_subset` 값은 필드의 설계 예시이며, 개별 실험의 표본 수는 해당 실행 설정에서 정한다.

이미지 규격은 파일 헤더에서 읽는다. RIAWELC은 24,407장 모두 227×227이며 공식 README의 224×224 기재와 다르다. 규격을 상수로 가정하면 3픽셀이 잘릴 수 있다.

`has_localization`은 `label_type != "classification"` 관계로 검사해야 한다. 등록부에 두 값을 따로 적지 않는다.

### `annotations.csv` 18컬럼

| 컬럼 | 값이 오는 곳 | 구분 |
|---|---|---|
| `ann_id` · `image_id` | `{image_id}#{seq}` / FK | [어댑터] |
| `src_label_raw` · `defect_type` · `iso_code` | 원본 라벨 + 라벨 사상표 | [어댑터] |
| `polygon_json` | 원본 좌표 그대로. 어떤 단계도 수정 금지 | [어댑터] · 키 경로만 [사람] (`fields_declared.coords.source_key`) |
| `bbox_x1_px` ~ `bbox_y2_px` | 폴리곤 min/max → floor/ceil → 경계 clip | [어댑터: convert] |
| `area_px` · `major_axis_px` · `minor_axis_px` · `equiv_diameter_px` | shapely / `cv2.minAreaRect` / √(4A/π) | [어댑터: convert] |
| `major_axis_mm` · `equiv_diameter_mm` | `px / px_per_mm`. 없으면 null. 가정값으로 채우지 않는다 | [어댑터: convert] |
| `geom_valid` · `geom_flags` | 좌표 이상 검사 | [어댑터] |

등록부가 지정하는 것은 좌표를 읽을 원본 키 경로다. 이미지별 좌표와 기하값은 어댑터가 계산한다. `polygon_json`은 원본 좌표를 유지하고, mm 환산에 필요한 스케일이 없으면 mm 값은 null로 남긴다.

### 매니페스트 밖의 메타데이터

| 등록부 키 | 왜 매니페스트 컬럼이 아닌가 | 실제 소비처 |
|---|---|---|
| `provenance.publisher` · `landing_url` · `edition` | 이미지 1장의 속성이 아니라 데이터셋의 속성. 62,998행에 반복하면 반복값이 어긋나는 순간 단일 기준이 깨진다 | 논문 데이터 가용성 절 |
| `provenance.license` · `citation_required` · `citations[]` | 파일 바이트에 없다. RIAWELC의 인용 의무 2편은 README에만 적혀 있다 | 논문 참고문헌. 사용 조건이지 재량이 아니다 |
| `provenance.export_restriction` | 법적 판단. 이미지 픽셀에 "국외 반출 금지"라는 정보가 없다 | 반출 제약 검사 |
| `acquisition.*` | 사람의 신청 행위 상태 + 머신 로컬 환경. 스냅샷 불변성과 수명이 다르다 | 입력 경로 대조, `link_raw.py` |
| `counts_announced` | 공지값은 실측의 대조군이다. 실측이 실측인지는 독립 기준과 대조해야 안다 | 공지값과 실측값 대조 |
| `samples.guidance_text` | 조치 지침 텍스트는 어느 데이터셋에도 없다. 만든다 | D4 페어 / corpus (c) 설계 입력 |
| `fields_declared.*.status` · `evidence` · `evidence_level` | 매니페스트 스키마에 이 상태를 표현할 컬럼이 없다. 등록부에서만 표현한다 | 입력 조건 검사, probe 대조 |
| `pipeline.eligible` · `exclusion_reason` | "등록부에 있다"와 "쓸 수 있다"는 다르다 | 실험 입력 범위와 제외 사유 |
| `text.*` / `document.*` | 이미지 축이 아니다 | 규정 코퍼스 `corpus/limits.csv`, D5 규정 색인 |

`notes`는 자유 서술이다. 라이선스·출처·경로 같은 구조화 정보를 `notes.str.contains(...)`로 읽는 방식에 의존하지 않는다. 이런 정보는 전용 필드에 둔다.

정상·결함 클래스는 `has_defect`, `defect_types`, `iso_codes`로 표현한다. 정상은 결함 유형이 아니다. 조치 지침은 원천 이미지 메타데이터의 일부가 아니며, 별도의 합성 코퍼스에 해당한다.


## 수작업으로 선언하는 정보

파일을 전수 스캔해도 알 수 없는 정보와 어댑터의 입력 규칙을 선언한다. 데이터셋당 약 40~50개 항목을 아홉 묶음으로 구분한다.

| # | 묶음 | 필드 | 왜 자동화할 수 없는가 |
|---|---|---|---|
| H1 | 신원 | `dataset_id` · `kind` · `authoring.owner` | `dataset_id`는 3중 일치의 기준점이다(파일명 = 라벨 사상표 `sources` 키 = 어댑터 `source` 상수). 기계는 "이 데이터셋을 무엇이라 부를지"를 정할 수 없고, 이름이 흔들리면 `image_id`(PK) 전체가 바뀐다 |
| H2 | 원천·출처 | `provenance.publisher` · `landing_url` · `edition.{label, retrieved_at}` · `access` | 파일 바이트에 없다. 같은 파일명·같은 개수여도 재배포판일 수 있다. 원천과 판본은 별도 출처 기록으로 식별한다 |
| H3 | 법적 의무 | `license.{name, url, spdx, commercial_use}` · `citation_required` · `citations[]` · `redistribution` | 법률 판단이다. Intel Research Use License의 이용 범위와 AI허브 성과 보고 의무는 약관으로 확인해야 한다. 기계는 LICENSE 파일 유무만 볼 수 있고, RIAWELC·LoHi-WELD에는 그 파일이 없다 |
| H4 | 보안 제약 | `provenance.export_restriction` · `constraints.{cloud_upload, external_api, commercial_use}` | H3의 값화. 보안 제약을 기계가 검사할 수 있는 값으로 표현한다. 사람이 안 적으면 검증기가 위반을 탐지할 근거가 없다 |
| H5 | 수집 경로 | `acquisition.{staging_uri, staging_subpath, storage_mode, access_state, obtained_at}` | 어디에 받았는지는 받은 사람만 안다. `storage_mode`(스트리밍 vs 로컬)는 Drive 클라이언트 설정이라 파일 목록으로 판별되지 않는다. 접근 허가의 상태는 파일 목록만으로 알 수 없다 |
| H6 | 파이프라인 경로 | `pipeline.{raw_subdir, dataset_subpath, eligible, adapter}` | `raw_subdir`가 `rel_path` 접두를 결정한다. 즉 매니페스트 스키마 컬럼 3번의 값을 사람이 정한다. `dataset_subpath`는 아카이브 내부 구조라 데이터셋마다 다르다 |
| H7 | 파일 배치 | `layout.{image_glob, class_dir_depth, label_mode, label_glob, pairing_rule}` | 어댑터 `discover()`가 무엇을 순회할지의 명세다. 자동 탐색으로 대체 가능해 보이지만 틀리면 조용히 이미지 일부를 빠뜨린다. `counts_announced` 대조가 이걸 잡으려면 사람이 먼저 규칙을 선언해야 한다 |
| H8 | 라벨 어휘 | `label_vocabulary.{label_field, labels[].raw, labels[].is_normal, labels[].proposed_l2}` | 의미론적 판단이다. RIAWELC의 `Difetto1`이 CR인지 LP인지는 데이터가 답하지 않는다. 라벨 의미는 문자열 빈도만으로 정할 수 없다. 기계는 문자열 빈도만 셀 수 있고, 라벨 사상표가 `unmapped_policy: fail`이므로 사람이 먼저 적어야 파이프라인이 돌기 시작한다 |
| H9 | 기준 스키마 선언 | `fields_declared` 10키 × `{status, source_key, evidence, evidence_level}` | 기계는 "없다"와 "아직 안 봤다"를 구분할 수 없다. 파일을 읽어 필드가 없으면 `absent`로 판정하겠지만, 그 판정을 하려면 파일을 다 읽어야 하고 접근 권한을 얻기 전에는 파일을 읽을 수 없다. 사람의 `unverified` 선언만이 이 공백을 정직하게 표시한다 |

공지값은 `counts_announced`에, 눈으로 확인한 예시는 `samples.examples[]`에 둔다. 파일에서 직접 측정한 수와 공지값을 같은 값으로 취급하지 않는다.

### `fields_declared`의 10개 키

키 집합을 고정해야 ‘항목 자체를 작성하지 않음’과 ‘자료에 없음’을 구분할 수 있다.

| 키 | 대응 매니페스트 스키마 위치 | 비고 |
|---|---|---|
| `modality` | manifest 7 | 값 공간 `RT`\|`VT`. 지원 모달리티와 대조 |
| `material` | manifest 8 | 값 공간 `ST`\|`AL`\|`UNK`. `UNK`는 결측이 아니라 "원본이 안 준다"는 값 |
| `label_type` | manifest 14 (→15 파생) | `polygon`\|`bbox`\|`classification` |
| `defect_label` | manifest 13 / ann 3 | 원본 결함 라벨이 어디에 있는가 |
| `normal_label` | manifest 9 (L1) | 정상을 어떻게 표기하는가 |
| `coords` | ann 6 / 7~10 | 좌표가 어디에 있는가 + 어느 좌표계인가 (정규화 vs 절대 픽셀) |
| `thickness_mm` | manifest 23·24 |  값이 아니라 키 경로만 |
| `px_per_mm` | manifest 25·26 | 동일 |
| `quality_level` | manifest 27 | ISO 5817 B/C/D |
| `group_key` | manifest 17 (E2 엣지) | 필름·용접부·촬영 묶음의 식별 근거를 `source`로 구별 |

### 등록부에 직접 적지 않는 값

| 금지 | 사유 |
|---|---|
| ISO 코드 (`"2011"`, `"100"`) 또는 한글 라벨을 `proposed_l2`에 | 라벨 사상표 L2가 단일 기준. 라벨 문자열을 별도로 하드코딩하지 않는다. `proposed_l2`는 L2 키(snake_case ASCII)여야 하고 한글은 `raw` 칸에 간다 |
| `thickness_mm` · `px_per_mm` · `quality_level`의 수치 | 등록부는 값을 읽을 키 경로만 받는다. 값을 적으면 probe 전수 확인의 동기가 사라진다 |
| `coverage` 에 수치 | 전수 측정값은 `probe_result`에만 둔다. 이 설계의 선언 블록에는 `null`만 허용한다 |
| `verdict_mode` · `assumptions` · `assumed_*` | 판정 범위와 가정값은 별도의 실행 설정으로 관리한다. 등록부에는 가정값을 적지 않는다 |
| `has_localization` | `label_type`에서 유도 |
| `sha256` · `phash_hex` · `group_id` · `strata_key` · `split` · `client` · `eval_subset` · `width_px` · `height_px` · `bbox_*` · `area_px` · `*_axis_px` · `equiv_diameter_*` | 전부 계산 결과. 스키마에 키 자체가 없고 `additionalProperties: false`가 침입을 막는다 |
| `counts_measured` 또는 `counts_announced.verified: true` | `verified` 승격은 어댑터 실측 스크립트만 할 수 있다 |
| 절대경로 (`<절대경로>`) | 논리 URI만 등록부에, 실제 경로는 `configs/paths.local.yaml`(비추적) |
| 이미지 1장당 항목 | `samples.examples` `maxItems: 5` |

## 필드 상태와 결측

등록부는 데이터셋이 어떤 필드를 제공하는지 설명한다. 매니페스트는 개별 행에 값이 있는지 표현한다. 두 층위의 결측은 다르다.

| 층위 | 결측의 뜻 | 판별 |
|---|---|---|
| 등록부 (수집 시점) | 이 데이터셋이 이 필드를 주는가 / 우리가 확인했는가 | 아래 `status` 6값 |
| 매니페스트 (파이프라인) | 이 행에 값이 있는가 | 매니페스트 스키마  N1/N2/N3 |


매니페스트의 N1·N2·N3는 각각 위치 라벨 없음, 정상 이미지, mm 환산 불가를 뜻한다. N2는 이미지의 속성이므로 등록부 상태값으로 쓰지 않는다. 정상 클래스가 존재하는지는 `label_vocabulary.labels[].is_normal`로 표시한다.

필드가 없다는 뜻과 아직 확인하지 않았다는 뜻을 단일 null 값으로 합치지 않는다. 필드별 객체의 `status`와 근거를 함께 쓴다. JSON literal null의 허용 여부는 필드별 스키마가 정한다.

### `status`의 여섯 값

| 값 | 뜻 | 필수 동반 필드 |
|---|---|---|
| `present` | 원본이 값을 준다 | `source_key` (모르면 `"unverified"` 허용) · `evidence` |
| `constant` | 원본은 침묵하지만 사람이 상수로 단언한다 | `constant_value` · `evidence` |
| `absent` | 확인했고 없다 | `evidence` · `evidence_level ∈ {file_inspected, publisher_doc}` |
| `out_of_contract` | 값은 있는데 매니페스트 스키마 값 공간에 담을 수 없다 | `observed_value` · `evidence` |
| `not_applicable` | 이 `kind`에 애초에 의미 없는 항목 | . |
| `unverified` | 아직 확인하지 않았다 (템플릿 기본값) | `how_to_verify` · `owner` · `due` |


페이지에는 필드의 존재가 설명되어 있어도 실제 키 경로를 모를 수 있다. 이 경우 `status: "present"`와 `source_key: "unverified"`를 함께 쓴다. 확인되지 않은 경로를 만들어 적지 않는다.

`out_of_contract`는 값이 없다는 뜻이 아니다. 값은 있지만 현재 파이프라인의 값 공간에 넣을 수 없다는 뜻이다. 예를 들어 RT·VT와 다른 가시광 또는 공정 모니터링 데이터는 모달리티 정의를 먼저 대조해야 한다.

RIAWELC의 재질은 `constant_value: "UNK"`로 표현한다. UNK는 원본에 재질 정보가 없다는 값이며, 층화의 재질 축이 상수가 된다. 픽셀-mm 스케일은 `absent`이고 mm 컬럼을 채울 수 없다. 묶음 식별 정보는 메타데이터 파일이 아니라 파일명에서 읽을 수 있으므로 `group_key.source`를 별도로 둔다.

### 파일 이름의 묶음 단서

```json
"group_key": {
  "status": "present",
  "source": "filename_pattern",
  "source_key": "^(?P<prefix>.+?)_\\[\\d+\\]\\[\\d+\\](?P<suffix>.*)\\.png$",
  "evidence": "<파일 목록과 패턴 대조 근거>",
  "evidence_level": "full_scan"
}
```

`source` 값은 `metadata_field`, `filename_pattern`, `absent`다. RIAWELC의 `RRT-101R_Img1_A80_S1_[12][8].png` 같은 파일 이름은 격자 위치를 담는다. ` - Copia` 접미가 붙은 파일도 30건 있어 접미를 제외하지 못하는 정규식으로는 묶음 일부가 흩어진다.

이름 접두사의 집계값은 509개이고, 접미를 함께 처리한 집계값은 479개다. 후자의 패턴은 24,407/24,407 파일 이름에 매칭된다. 이 수는 이름 처리 규칙에 따른 집계이며, 독립적인 원본 사진 수를 직접 측정했다는 뜻은 아니다. 엄격한 정규식의 별도 결과는 접두사 478개와 패턴 불일치 30건이다. 두 집계 방법을 혼동하지 않는다.

표본 8건에서 ` - Copia` 파일과 짝이 되는 원본을 찾지 못했다. 접미만으로 중복 사본이라고 단정할 수 없다. 파일명 묶음과 SHA256 중복 검사는 서로 다른 역할을 하며, pHash만으로 비겹침 타일 관계를 모두 잡을 수는 없다.

### 근거 수준

```
evidence_level : "none" | "publisher_doc" | "sample_inspected" | "full_scan"
```

| 값 | 뜻 |
|---|---|
| `none` | 아무것도 안 봤다 (`unverified` 전용) |
| `publisher_doc` | 데이터셋 페이지·README·논문에 그렇게 적혀 있다. 확정이 아니다 |
| `sample_inspected` | 실물 표본을 열어 확인했다 |
| `full_scan` | 전수 확인했다 |


`status`가 `present`, `constant`, `absent`, `out_of_contract`일 때 근거가 비어 있으면 실패 처리한다. `publisher_doc`은 배포처 설명이고, 파일의 측정 결과와 구별한다. 예를 들어 RIAWELC의 224×224 설명과 227×227 실측은 일치하지 않는다.

### 선언과 실측의 분리

`fields_declared`는 선언, `probe_result`는 기계 실측이다. `probe_metadata.py`는 선언을 덮어쓰지 않고 나란히 대조한다. 사람이 `meta.material`로 적었는데 실제 경로가 `images.0.meta.mat_cd`라면 그 차이를 보존한다.

아래는 필드 구조 예시다. 시간과 근거 자리표시자를 실제 값으로 채운 실행 결과가 아니다.

```json
"probe_result": {
  "_generated_by": "data/ingest/probe_metadata.py",
  "_generated_at": "<ISO 8601 timestamp>",
  "_do_not_hand_edit": true,
  "thickness_mm": {"status": "absent", "coverage": 0.0, "keys_scanned": 41, "candidates_matched": []},
  "material": {"status": "present", "source_key": "images.0.meta.mat_cd", "coverage": 1.0, "values_seen": ["ST", "AL"]}
}
```

`coverage`는 실측 블록에만 둔다. 사람이 쓰는 필드 선언에 실측 보유율을 임의로 채우지 않는다.


### 착수를 막는 상태와 실측으로 해소하는 상태

등록부 설계는 `unverified`를 B(차단)와 D(위임)로 나눈다. B 필드는 수집 경로·라벨·이용 조건처럼 입력 처리 전에 알아야 하는 항목이다. D 필드는 실제 파일을 읽는 단계에서 해소하되 스냅샷을 잠그기 전까지 남겨두지 않는다. 이 분류는 설계상의 요구와 검증기 구현 범위를 구별해서 읽어야 한다.

| 등급 | 필드 | 규칙 |
|---|---|---|
| B (차단) | `label_vocabulary.label_field` · `labels[]` · `layout.{image_glob, class_dir_depth, label_mode}` · `pipeline.{raw_subdir, dataset_subpath}` · `acquisition.storage_mode` · `provenance.{license.name, citation_required, export_restriction}` | `unverified`면 ingest 착수 금지. 법적 항목과 경로 항목은 모르는 상태로 진행하는 것 자체가 사고다 |
| D (위임) | `fields_declared`의 `thickness_mm` · `px_per_mm` · `quality_level` · `group_key` · `coords.source_key` · `license.commercial_use` · `edition.*` | ingest 착수는 허용. 스냅샷 잠금 시점에는 `unverified`가 0개여야 한다. probe 결과로 present/absent가 확정돼 있어야 한다 |

`license.commercial_use`는 논문·사업화 단계의 이용 범위와 관계된다. `unverified`가 허가를 뜻하지는 않는다. 반출 제약과 인용 의무는 별도의 착수 조건이다.

### 상태가 파이프라인에 미치는 영향

| `status` | `evidence_level` | probe `coverage` | manifest 23/25/27 | 24/26 (`*_source`) | `capabilities` | `verdict_mode` |
|---|---|---|---|---|---|---|
| `present` | `full_scan` | ≥ 0.95 | 값 | `metadata` | `true` | `absolute` 후보 → 별도 전환 조건 필요  |
| `present` | `full_scan` | < 0.95 | 있는 행만 값 | 행별 `metadata`/`none` | `false` | `clause_only`. 부분 보유는 전부-아니면-전무 |
| `present` | `publisher_doc` | 미실측 | null | `none` | `false` | `clause_only` |
| `constant` | . | . | 상수 | `metadata` | 상수 축 소거 | 층화에서 자동 퇴화 |
| `absent` | `file_inspected`/`publisher_doc` | . | null | `none` | `false` | `clause_only` (N3 경로, `MetricStatus.NO_SCALE`) |
| `out_of_contract` | . | . | . | . | . | ingest 차단. 지원 값 공간 확장 필요 |
| `not_applicable` | . | . | null | `none` | 계산 제외 | 결과표 `N/A` |
| `unverified` | . | . | . | . | . | `clause_only` 유지. B등급이면 착수 차단 |

`assumed`는 등록부에서 만들지 않는다. 조건부 판정의 가정값은 별도의 `data_capabilities.yaml`에서 명시해야 한다. 주 실험의 `clause_only` 범위를 실측 없이 `absolute`로 바꾸지 않는다.

`absent`와 `unverified`는 매니페스트의 `thickness_source="none"`만으로 구별되지 않는다. 그 구별은 등록부와 `data_capabilities.yaml`에 남는다. `metadata|assumed|none` 세 값에 데이터셋 수준의 조사 상태를 임의로 추가하지 않는다.

위치 라벨이 없는 N1을 좌표 0으로 채우면 위치 지표가 잘못 계산된다. 확인 전 상태를 값이 있다는 뜻으로 해석해도 잘못된 키의 숫자가 판정에 사용될 수 있다.

## 경로의 세 층

경로는 논리 URI, 머신 로컬 설정, 실물 대조로 구분한다. 공개 문서에는 자리표시자만 쓰고 개인 절대경로는 넣지 않는다.

| 층 | 내용 | git |
|---|---|---|
| 논리층 (등록부) | `acquisition.staging_uri` = `"gdrive:weld-fl-datasets/RIAWELC"`, `pipeline.raw_subdir` = `"riawelc"`, `pipeline.dataset_subpath` = `"dataset/DB - Copy"` | 추적 |
| 물리층 (머신 로컬) | `configs/paths.local.yaml`. `staging_root` · `raw_root` · `rel_base` · `mount_mode` | 비추적 (`.gitignore`의 `configs/*.local.yaml` 규칙) |
| 검증층 | `scripts/verify_landing.py`. 물리층이 논리층을 실제로 실현하는지 실측 | 추적 |


```yaml
# configs/paths.local.yaml — 버전 관리에서 제외
staging_root: "<수집 폴더>/weld-fl-datasets"
raw_root: "<저장소 루트>/data/raw"
rel_base: "<저장소 루트>"
mount_mode: junction
```

`rel_path`는 저장소 루트 기준의 POSIX 상대경로다. `ImageRecord._posix`는 역슬래시를 거부한다. 절대경로와 환경별 마운트 정보는 `configs/paths.local.yaml`에만 둔다.

### 아카이브 내부 경로

RIAWELC의 클래스 디렉터리는 `dataset/DB - Copy/{split}/{class}/*.png`다. 따라서 `raw_subdir`와 `dataset_subpath`를 분리하고, 클래스 디렉터리의 깊이를 지정한다.

```json
"pipeline": {"raw_subdir": "riawelc", "dataset_subpath": "dataset/DB - Copy"},
"layout": {"class_dir_depth": 2, "image_glob": "*.png", "label_mode": "dirname"}
```

`training/Difetto1/*.png`에서 클래스는 `Difetto1`이다. `training`을 클래스로 읽으면 라벨 사상이 실패한다. 저자 제공 분할은 독립적인 평가 분할을 대신하지 않는다.

`image_id = f"{source}:{rel_path}"`이므로 수집 폴더명이나 `rel_base`가 달라져도 식별자가 바뀔 수 있다. `data/raw/<source>/` 접두와 경로 왕복을 확인해야 한다. `--rel-base`를 환경 차이의 무조건적인 우회책으로 쓰지 않는다.

### 반출과 원본 보존

```
export_restriction == "no_overseas_transfer"
  AND staging_uri starts with "gdrive:"
  -> 실패

document.paywalled == true
  AND document.index_inclusion == true
  -> 실패
```

국외 반출을 금지한 자료는 해외 호스팅 저장소에 올리지 않는다. 유료 표준 전문도 코퍼스나 검색 색인에 넣지 않는다. 공개 접근이 가능하다는 이유만으로 재배포가 허용된다고 가정하지 않는다.

다운로드한 파일명과 폴더 구조는 식별자에 영향을 주므로 유지한다. 원본 아카이브는 복구와 바이트 대조를 위해 보존하고, 변환·리사이즈 결과는 원본 디렉터리 밖에 둔다.

### 대괄호 파일 이름

`RRT-101R_Img1_A80_S1_[12][8].png`를 glob 패턴으로 직접 넘기면 `[12]`가 문자 클래스로 해석된다. 원문 파일 이름과 다른 패턴이 되므로 결과가 0건일 수 있다. 실측 예시에서 같은 이름의 직접 glob은 0건, 해당 디렉터리의 `rglob("*.png")`는 4,962건이었다. 파일명 리터럴을 glob에 넣지 않는다.

## 검증 항목과 구현 범위

등록부 검증기는 `scripts/validate_registry.py`다. 다음 표는 설계상 검증 단계를 정리한 것이다. S3의 null 전면 금지와 S8의 B/D 세부분류까지 모두 구현됐다는 뜻은 아니다.

| 단계 | 검사 | 등급 |
|---|---|---|
| S0 바이트 | UTF-8 디코드 / BOM 없음 / 개행 LF / 스마트쿼트 없음 | 하드 실패 (자동 수정하지 않는다. 어느 파일 몇 행인지만 알려준다) |
| S1 파싱 | `json.load`. 트레일링 콤마·주석·NaN·Infinity 거부 | 하드 실패 + 행·열 |
| S2 스키마 | JSON Schema 2020-12. `additionalProperties:false`, enum, `format: date`, `kind`별 `if/then` | 하드 실패 + JSON Pointer |
| S3 `null` 금지 | 전 노드 재귀. JSON literal `null` 발견 시 실패 (`status` 객체만 허용) | 하드 실패 |
| S4 신원 정합 | `dataset_id == 파일명` / 전역 유일 / `owner`·`reviewer`가 enum / `reviewer != owner` | 하드 실패 |
| S5 계약 대조 | ① `proposed_l2` ∈ 라벨 사상표 L2 키 ② `modality`·`material`·`label_type`의 `constant_value`가 매니페스트 스키마 값 공간 ③ `pipeline.raw_subdir == dataset_id` ④ 금지 필드 부재(ISO 코드·두께 수치·sha256·bbox·`coverage`·절대경로) ⑤ `eligible=true`면 라벨 사상표 `sources`에 키 존재 | 하드 실패 |
| S6 레드라인 | ① `export_restriction=no_overseas_transfer` ∧ `staging_uri` 가 `gdrive:` → 실패 ② `paywalled` ∧ `index_inclusion` → 실패 ③ `access_state ∈ {pending_approval, restricted, unreachable}` → `eligible=false` 강제 | 하드 실패 |
| S7 근거 강제 | `status ∈ {present, constant, absent, out_of_contract}`인데 `evidence` 공란 → 실패. `absent`인데 `evidence_level=none` → 실패 | 하드 실패 |
| S8 등급 분류 | `unverified` B/D 등급 분류 · `out_of_contract` 목록 · `proposed_l2` 미사상 목록 | exit 1/2 |
| S9 리포트 | 데이터셋별 `unverified` 잔존 수 · `eligible` 수 · 독립 확인 대상 목록 | exit 0 + 표 |

구현 범위는 S0·S1·S2·S4·S5·S6·S7·S9이며, S8은 `unverified` 목록 출력까지다. S3의 null 전면 금지는 예시의 `probe_result: null`·`proposed_l2: null`과 충돌하므로 필드별 스키마로 제한한다. B/D 등급을 자동 분해하는 부분은 구현 범위에 포함되지 않는다.

라벨 사상은 `configs/label_map.yaml`을 직접 읽어 대조한다. `proposed_l2`에 한글 라벨이나 ISO 코드 대신 L2 키를 넣는 이유다. 객체 형식과 필수 키 검사는 내용이 옳다는 보증과 구별한다.

### 재현성

`index.json`은 UTF-8(BOM 없음), LF, `dataset_id` 오름차순, `indent=2`, `ensure_ascii=false`, 스키마 선언 순서의 키로 생성한다. 집계 파일끼리 충돌하면 수작업 병합 대신 원본 등록부에서 재생성한다.

등록부는 계속 갱신할 수 있지만 실험 스냅샷은 잠근 뒤 바꾸지 않는다. 등록부를 `SNAPSHOT.sha256`의 멤버로 섞지 않는다. 잠긴 매니페스트와 스냅샷 멤버 목록의 해시는 그대로 보존한다.

## 해석상의 주의

‘등록부에 있음’, ‘자료에 접근 가능함’, ‘실험에 투입 가능함’은 서로 다르다. `pipeline.eligible`와 `exclusion_reason`으로 투입 여부를 구분한다. 빈칸을 추측으로 채우지 않고 상태값과 근거로 표현한다.

공지 장수와 실측 장수가 다르면 파일을 더하거나 빼서 공지값에 맞추지 않는다. 선언과 실측을 나란히 보존한다. 라벨 사상과 좌표계, 묶음 규칙을 바꾸면 그 영향은 데이터 파이프라인에서 따로 확인해야 한다.

`defect_types`와 `iso_codes`를 각각 정렬한 값은 같은 위치끼리 대응하지 않을 수 있다. 예를 들어 `lack_of_penetration;porosity`와 `2011;402`는 위치별로 짝지을 수 없다. 코드 대응은 사상표로 조회한다.
