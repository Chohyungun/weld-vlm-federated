# 데이터 등록부와 이미지별 목록

데이터 등록부는 데이터셋의 출처·구조·제약을 설명한다. 이미지별 학습·평가 목록은 별도 파일인 매니페스트에 기록한다. 두 자료의 단위와 역할을 구분해야 같은 데이터를 서로 다른 방식으로 해석하는 일을 줄일 수 있다.

## 파일의 역할

| 파일 | 단위와 역할 |
|---|---|
| `data/registry/datasets/*.json` | 데이터셋별 출처·확보 상태·필드 제공 여부 |
| `data/registry/_schema/dataset_registry.schema.json` | 등록부의 허용 필드와 값 검사 |
| `configs/label_map.yaml` | 원본 라벨과 공통 결함 코드의 대응 |
| `manifest.csv` | 이미지별 출처·경로·크기·분할 등의 목록 |
| `annotations.csv` | 결함별 종류·위치 정보 |

등록부는 원자료 어댑터를 구현할 때 참고하는 자료다. 등록부의 설명을 고쳤다고 동결된 학습·평가 목록이 자동으로 바뀌어서는 안 된다. 이미지별 매니페스트와 주석은 변환 결과로 생성하고 검증한다.

## 결측과 근거

제공처가 기재한 정보와 실제 파일에서 확인한 정보를 나누어 기록한다. ‘없음’은 조사한 범위에서 제공되지 않는다는 뜻이고 ‘미확인’은 아직 확인하지 못했다는 뜻이다. 문서 설명과 실측이 다르면 어느 쪽을 확인했는지와 근거를 남긴다. 공백이나 임의의 0으로 모든 결측을 대체하지 않는다.

AI Hub RT 자료의 두께와 화소당 실치수처럼 없는 정보는 생성 과정에서 보충한 사실로 취급하지 않는다. 등록부의 형식 검사를 통과했더라도 물리적 의미나 전문가 판정의 타당성이 확인되는 것은 아니다.

## 경로와 변경

공개 등록부에는 개인 계정과 절대경로를 넣지 않는다. 환경별 자료 위치는 로컬 설정으로 관리하고 원자료의 상대 경로와 데이터셋 구분을 일관되게 사용한다. 스키마·라벨 매핑·변환 규칙이 바뀌면 새 산출의 버전과 해시를 남기며 기존 동결 실험에 소급 적용하지 않는다.

이 안내는 구현 스키마를 대체하지 않는다. 정확한 필드와 허용 값은 위 스키마 및 라벨 설정을 확인해야 한다. 과거의 전체 필드 표와 검토 기록은 원본 이력에 보존하고 현재 실행의 자료 구성은 [데이터 현황](데이터셋_현황.md)에 정리하였다.
