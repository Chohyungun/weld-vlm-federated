# 사전실험 결과와 본실험 준비

이 문서는 2026년 8월 9일 킥오프부터 9월 11일까지 한 일을 처음 보는 사람 기준으로 정리한다.
연구 배경과 질문은 [README](../README.md)와 [실험설계](실험설계.md), 결정의 근거는
[의사결정로그](의사결정로그.md)에 있다. 결과는 5절, 사전실험에서 찾은 문제를 본실험에 반영하는
방법은 6절에서 설명한다. 회의의 평가셋 질문은 [별도 답변](회의/2026-09-15_평가설계_질문과답변.md)에 정리했다.

9월 15일 검토에서 묶음 생성 방식, 매니페스트 동결일과 임계값 비교 설명을 정정했다.
실행 경과는 당시 기록이며 후속 설계·검증 상태는 [회의 자료](회의/2026-09-13_사전실험_검토와_본실험_설계.md)에서 함께 확인할 수 있다.

9월 17일 갱신: 대표 수치 채택(2026-09-16), 두 번째 구현 검산 통과(2026-09-17).
시드별 채점기 코드 버전 차이를 확인한 뒤 같은 코드로 재채점하고 입력·코드 출처와 신뢰구간을
검수했다. 9월 16일 앞선 보충에서 대표 채택 대기로 적었던 상태는 해소됐다. 기존 v1·v2 기록은
보존하며 5절에 v3 결과와 검산 범위를 적었다. 같은 평가 기록의 계산 검산을 평가셋·학습·추론의
타당성이나 현장 일반화 검증으로 확대하지 않는다.

저장소는 9월의 기존 정책 실행을 `main` 또는 본실험이라고 부른다. 여기서는 그 실행까지를
사전실험 검토에 포함하고, 발견한 문제를 반영할 실험은 후속 본실험으로 구분한다.

## 1. 한 장 요약

- 데이터 62,308장을 정리해 평가셋 12,461장을 먼저 떼고 나머지를 세 회사 역할(C1·C2·C3)로 나눴다.
- 분리형 세 학습 방식(로컬·중앙집중·연합)을 같은 기준 학습 표본의 epoch 순회 예산으로 세 번(시드 3개) 돌려 검출기 15개를 얻었다. 증강의 추가 표본 노출이나 최적화 경로까지 같다는 뜻은 아니다.
- v3 재채점에서도 세 시드 평균 mAP@50은 중앙집중 0.4946, 연합 0.2709, 로컬 평균 0.1973이었다.
  회복률 평균 24.8%와 평가 묶음 신뢰구간을 채택했다. 해석 조건은 5절에 적었다. 명목 AL 부분집합에서는 C3 로컬이 연합보다 높아 전체 결과와 순서가 달랐다.
- 시드 1의 이미지 수준 분류에서는 사진 번호만 쓰는 대조선이 검출기 다섯 모델보다 높았다.
  이 분류 축에는 대표 성과 숫자를 두지 않고 모델과 대조선의 결과를 함께 보고한다(5-2절).
- 별도 코드·연구 검토에서 구현과 해석에 관한 지적 15건이 나왔다. 그중 학습 데이터 순서가 라운드마다 반복되는 경로는 코드 분석과 CPU 재현으로 확인했다.
- 계속할 가치는 있다. 다만 지금 근거로는 데이터를 모으지 않는 조건에서 세 방식이 어떻게
  다른가를 살필 수 있다. 현장에 넣을 판정 시스템의 유효성은 아직 말할 수 없다.

## 2. 무엇을 비교하는가

용접 검사 사진을 회사 밖으로 옮기기 어려운 상황에서 세 학습 방식을 비교한다. 현재 실험은 공개
데이터셋을 C1·C2·C3라는 참여자 역할로 나눈 것이며 실제 세 회사의 현장 자료를 평가한 것은 아니다.

| 방식 | 데이터 | 뜻 |
|---|---|---|
| 로컬 | 자기 집단의 학습 자료만 | 각 참여자가 따로 학습하는 비교 기준 |
| 중앙집중 | 세 집단의 학습 자료를 합침 | 전체 학습 데이터를 이용하는 비교 기준 |
| 연합 | 데이터는 두고 모델 값만 교환 | 이 연구가 검증하려는 것 |

위치 찾기는 mAP@50으로 비교하고 대표 수치로 회복률을 채택했다. 로컬과 중앙집중의 차이를 연합이 얼마나 메웠는지를 백분율로 적는다.
회복률 = (연합 − 로컬 평균) ÷ (중앙집중 − 로컬 평균) × 100.
분모·신뢰구간 규칙과 출처 검수를 거쳐 9월 16일 채택했다. 적용 범위와 사후 규칙이라는 한계는 5절을 따른다.

AI 구성도 둘로 나눈다. 사진에서 결함을 찾는 검출기와 규정을 읽어 판정하는 언어 모델을 따로 두는 분리형,
하나의 시각언어 모델이 둘 다 하는 통합형이다. 표로 그리면 다섯 칸이 되고 이 연구는 그 다섯 칸을 비교한다.

표의 원문자 숫자는 기존 코드·설계에서 사용하는 조건 번호다. 시드나 실행 횟수가 아니다.

|        | 로컬 | 중앙집중 | 연합 |
|--------|------|---------|------|
| 통합형 | 제외 | ⑥ | ⑦ |
| 분리형 | ② | ③ | ④ |

정량 비교를 마친 학습 범위는 분리형 검출기 세 조건(②③④)이다. 시드마다 로컬 검출기 3개와
중앙집중·연합 검출기 각 1개를 얻어 총 15개를 채점했다. 분리형의 규정 판정부까지 검증을 마쳤다는
뜻은 아니다. 통합형 두 조건은 8월에 동작 확인용 파일럿을 실행했지만 수정 전 결과여서 성능 근거로 사용하지 않는다.

## 3. 어떻게 설계했나

### 3-1. 데이터

AI허브 용접 방사선 데이터 62,308장을 쓴다. 프로젝트의 데이터 취급 규약에 따라 이 이미지의 학습과
추론은 국내 장비에서만 한다. 원본은 읽기 전용이고 어떤 사진이 어느 묶음에 속하는지는 매니페스트 파일 하나가
정한다. 그 파일의 해시가 논문에 실린다.

| 구분 | 장수 | 비고 |
|---|---|---|
| 평가셋 | 12,461 | 결함 7,086 · 정상 5,375. 회사 분할보다 먼저 뗐고 어떤 학습에도 쓰지 않는다 |
| 학습 풀 | 49,847 | train 44,846 · val 5,001 |
| C1 (명목 ST) | 26,451 | C1·C2 사이는 디리클레 분포로 치우치게 나눴다 |
| C2 (명목 ST) | 16,253 | |
| C3 (명목 AL) | 7,143 | 데이터셋 라벨에 따른 출처 집단이며 실제 재질 차이로 해석하지 않는다 |

명목 AL의 판독 가능한 파노라마 표본에서는 강 계열 스펙을 확인했다. 결함 크롭의 재질은 확인하지 못했고
제공 기관의 라벨 정의도 확인 중이다. ST·AL 구분을 실제 강재·알루미늄 구분으로 단정할 근거는 없다.

같은 용접부를 연속으로 찍은 사진이 학습과 평가로 갈리면 점수가 부풀려진다. 이를 줄이려고 파일
내용 해시 일치, 라벨 숫자 ID의 연속 구간, 지각 해시 일치를 결합한 묶음 단위로 분할했다.
숫자 ID는 같은 검사 방식·명목 재질 안에서 1씩 이어지는 구간을 묶은 대용 기준이다. 실제 용접부나
연속 촬영 세션을 확인한 식별자는 아니다. ID 기반 묶음 안팎의 지각 해시 거리 분포가 잘 구분되지
않아 지각 해시는 거리 0인 경우에만 썼다. 실제 같은 용접부를 빠짐없이 식별하거나 누출을 모두
막았다는 뜻은 아니다.

이미지와 결함 라벨은 검출기의 학습·평가 자료다. 규정 코퍼스는 검색과 설명에 쓸 원문·구조화한
허용치 표·학습용 문답을 가리킨다. 이미지에 규정 설명을 연결한 페어는 통합형 학습에 사용하려는
자료다. 합성문에 넣은 두께·길이는 설정한 조건이지 이미지에서 측정한 값이 아니다. 현재 규정
자료는 파일럿 범위이며 원문 수치와 사람 정답 검증이 남아 있다.

### 3-2. 공정하게 비교하기 위한 규칙

세 방식의 점수를 나란히 놓기 위해 아래 조건을 고정했다. 다만 epoch 예산을 맞춘 것만으로
최적화 경로와 연산량까지 같아지지는 않는다.

- 학습량을 맞춘다. 연합은 라운드 50번 × 라운드당 2 epoch, 로컬과 중앙집중은 100 epoch. 곱이 같다.
- 조기 종료를 쓰지 않는다. 검증 점수가 좋은 시점을 고르는 것도 하지 않고 마지막 모델을 채점한다.
- 완료한 분리형 세 학습 조건의 검출기 다섯 모델에서 검출기(YOLO11s), 입력 크기(640), 배치(32), 최적화 설정을 고정한다. 통합형 두 칸은 다른 모델을 쓴다.
- 서로 다른 난수 시작값인 시드 3개로 반복해 결과의 변동을 본다.
- 다섯 칸의 출력을 같은 형식으로 바꾼 뒤 채점기 하나로 채점한다.

### 3-3. 사진을 보지 않는 규칙과 견준다

전처리 전 원자료에서 결함 사진은 전부 1280×720 크롭이고 정상 사진은 대부분 긴 파노라마였다.
이때 RT/ST 부분집합에서는 사진 크기만 보고도 결함 여부를 96.1% 맞혔다. 현재 동결본은 정상
파노라마를 타일로 잘라 크기를 맞췄지만 크롭·타일 출처의 차이는 남는다. 결함 종류도 사진 번호와 얽혀 있다.

그래서 화소를 한 번도 보지 않는 규칙을 따로 만들어 두고 모델이 그 규칙보다 나은지를 늘 함께 본다.
사진 번호를 512 구간으로 나눠 구간마다 학습·검증 풀(train+val)의 클래스 빈도를 점수로 쓰는 규칙이 주 대조선이다.
사진 번호가 실제 촬영 시간 순서와 같다고 확인된 것은 아니다. 모델이 이 규칙을 못 넘으면
그 점수만으로 사진을 배웠다고 말할 수 없다.

### 3-4. 작은 규모로 실행 경로를 점검했다

본실험 전에 작은 규모로 파이프라인을 끝까지 돌려 봤다. 통합형 두 칸(⑥⑦)도 8월 31일에 로컬 GPU
(16GB) 한 장으로 한 번 학습했다. 이 결과는 인용하지 않는다. 그 뒤 좌표 규약, 연합 가중치 단위,
학습률 스케줄을 바꿨고 ⑦에는 어댑터 집계 오류가 있었다. 이 실행에서는 파이프라인이 끝까지 돈다는 것을 확인했다.
성능 숫자는 성과로 삼지 않는다.

서버 하트비트 만료 두 종류로 분류했다. 하트비트가 오래 멈춘 근본 원인까지 확정한 것은 아니다.
수정 후 초기 라운드의 결과가 이전 실행과 바이트 단위로 같은지 확인했다. 이 검사는 해당 라운드에
한정되며 전체 학습 경로가 같다는 증명은 아니다.

## 5. 무엇이 나왔나

아래는 v3 재채점에서 확인한 세 시드 집계다. 검출기 15개의 mAP@50·mAP@50:95는
v1·v2·v3에서 모두 같았다. 출처·검수 상태까지 모든 파일이 같다는 뜻은 아니다.
mAP@50은 결함 종류와 예측 상자 위치의 일치를
평가하는 지표로, 사진을 몇 퍼센트 맞혔는지를 뜻하는 정확도와 다르다. 로컬 평균은 각 시드에서
공통 평가셋으로 채점한 로컬 C1·C2·C3 점수의 비가중 산술평균이다.

| 비교 | 공통 평가셋 12,461장의 세 시드 평균 mAP@50 |
|---|---:|
| 중앙집중 | 0.4946 |
| 연합 | 0.2709 |
| 로컬 평균 | 0.1973 |
| 로컬 C1 | 0.3595 |
| 중앙집중 − 연합(원시 격차) | 0.2237 |

시드별 회복률은 29.0%, 22.6%, 22.7%, 평균은 24.8%였다. 정확도가 24.8% 상승했다는 뜻이 아니다.
회복률의 평가 묶음 부트스트랩 95% 신뢰구간은 [20.9%, 29.3%]다. 학습 시드 3개를 고정하고
평가 묶음 1,245개를 2,000회 재표집한 구간이므로 학습 시드 변동이나 새 현장의 불확실성까지
포함하지 않는다. 신뢰구간에 관한 추가 판정 규칙은 세 시드 채점 뒤 등록했으며 사전등록이 아니다.
이 결과는 분리형 검출기 세 학습 방식과 동결된 혼합 평가셋에 한정된다.

공통 평가셋에서 연합은 C1 로컬보다 시드별 상대 감소율의 평균으로 24.6% 낮았다.
각 시드의 `100 × (연합 − C1 로컬) / C1 로컬`을 평균한 값이 −24.6%이며 %p가 아니다.
C1 고유 평가셋에서 측정한 참여자 편익도 아니다. 원시 격차와 C1 감소율의 신뢰구간은
별도로 산출하지 않았으므로 위 회복률 구간을 대신 붙이지 않는다.

같은 C3 모델의 공통 평가셋 점수는 0.0984로 연합 0.2709보다 낮았다. 명목 AL 부분집합 1,786장에서는
C3 로컬 0.4802, 연합 0.2267로 순서가 반대였다. 전체 혼합 자료와 출처별 자료에서 답이 달라졌으므로
모든 참여자에게 연합학습이 유리했다고 결론 내릴 수 없다. 원 수치와 계산식은
[당시 결과 근거](회의/2026-09-13_결과근거.json)에 보존했다.

최신 채점 원본은 `outputs/main_d/seed{1,2,3}/score_cells_v3.json`, 신뢰구간·집계 원본은
`outputs/main_d/seed3set/`의 `recovery_ci_v3.json`, `aggregate_v3.json`이다. 검수는
[v3 결과 기록](dev_log/2026-09-03-본실험/49_v3재채점_D.md),
[출처·결속·보존 검수](dev_log/2026-09-03-본실험/52_교차검수_D49_C.md),
[두 번째 구현 검산 검수](dev_log/2026-09-03-본실험/62_검산결과검수_A.md),
채택 시점은 [의사결정로그](의사결정로그.md)의 9월 16·17일 항목을 따른다.
두 번째 구현은 입력을 따로 읽는 경로에서도 15개 mAP@50과 회복률이 일치했다.
이는 같은 평가 기록·같은 정의의 계산 검산이다. 평가셋 구성, 학습·추론, 지표 선택의
타당성과 현장 일반화까지 검증한 것은 아니다.

다음 5-1~5-3은 첫 채점 당시의 시드 1 결과와 그 결과로 바꾼 보고 방식이다. 세 시드 평균과 구분해서 읽는다.

### 5-1. 시드 1의 위치 검출 결과

| 칸 | mAP@50 |
|---|---|
| 중앙집중 | 0.4926 |
| 연합 | 0.2820 |

사진 번호 구간별 중앙값 상자를 쓰는 위치 대조선은 이 축에서 0.0044다. 모델은 시험한 위치 대조선보다
성능이 높았다. 이 결과만으로 출처 편향이 해소됐거나 현장에 일반화된다고 볼 수는 없다.

### 5-2. 결함 종류 맞히기는 대표 숫자를 두지 않는다

| | 값 |
|---|---|
| 가장 좋은 칸(중앙집중) 이미지 수준 macro-AP | 0.8229 |
| 사진을 보지 않는 규칙 | 0.9582 |

검출기 다섯 모델이 전부 규칙에 진다. 이 데이터에서 결함 종류는 사진 번호와 강하게 얽혀 있어, 모델 점수가
높아도 사진을 배운 결과인지 순서를 배운 결과인지 가를 수 없다. 처음에는 분류 축에도 대표 숫자를 두려
했다가 이 비교를 본 뒤 철회했다. 곡선과 규칙 값을 나란히 싣는 것으로 보고 형식을 바꿨다.

### 5-3. 임계값 하나로 자르면 결론이 뒤집힌다

검출기는 상자마다 신뢰도를 내고 보통 0.25 같은 값으로 잘라 쓴다. 시드 1에서는 이 기준으로 다섯
모델 모두 자기 상자의 87.6~94.2%를 버렸다. 연합의 제외 비율이 가장 높았으며 남는 비율은 연합
5.84%, 로컬 C3 12.41%였다. 이 비율은 실제 결함의 누락률이 아니다. 임계값을 어디에 두느냐에 따라
연합이 로컬보다 낫기도 하고 못하기도 했다. 그래서 열네 개 값에서 곡선을 그리고 한 운용 임계값을
고르지 않는 mAP@50을 함께 보고한다. mAP도 출력 하한과 추론 설정에는 의존한다.
열네 개 값은 본실험 전인 9월 2일 코드에
고정됐지만 설정 파일의 공식 등록은 시드 1 채점 뒤인 9월 8일이었다. 값이 결과 뒤에 선택된 것은
아니지만 공식 사전등록으로 부르지는 않는다. 시드 2·3 채점 전에 등록을 마쳤다.

### 5-4. 별도 검토에서 찾은 것

9월 9일부터 개발 작업과 별도로 코드와 결과를 검토했다. 지적 15건 중 실험 해석에 직접 닿는 것 셋을 적는다.

- 연합은 라운드마다 학습 데이터를 같은 순서로 봤다. 학습 프레임워크가 데이터 로더의 난수를 상수로
  시드하는데 연합은 라운드마다 로더를 새로 만들기 때문이다. 해당 로더 구성을 모사한 CPU 실험에서
  100 epoch 동안 서로 다른 순서는 연합 2개, 중앙집중 100개였다. 실제 YOLO 실행의 모든 증강 경로를
  계측한 결과는 아니다. 이것이 결과에 어느 방향으로 얼마나 영향을 줬는지는
  아직 모른다. 세 시드는 기존 조건 그대로 돌렸고 순서를 바꾼 통제 실험은 따로 한다.
- 지름길이 원리적으로 통과할 수 없는 지표라고 판단했던 판별력 지표도 사진 번호 규칙에 진다
  (시드 1에서 규칙 0.6177, 가장 좋은 모델 0.5827). 그 판단을 철회했다.
- 검출기 다섯 모델에 같은 방향으로 실린 편향이니 모델끼리 비교는 성립한다는 논증은 서지 않는다. 편향의
  크기가 모델마다 다르면 순위가 바뀐다. 실제로 시드 1의 크롭 정상 사진의 오탐률이 모델별로 18.5%에서
  49.4%까지 달랐다.

나머지 지적(로그 형식, 재개 저장 훅, 검색 필터, 코퍼스 채택 조건 등)은 수정과 검수가 진행 중이다.

## 6. 본실험에 어떻게 쓰이는가

사전실험 수치를 다음 실험의 목표 점수로 삼기보다 비교에서 확인할 조건으로 옮긴다. 아래는
후속 설계 제안이며, 회의에서 모든 실행 조건을 확정했다는 뜻은 아니다.

| 사전실험에서 확인한 것 | 후속 본실험에 반영할 일 | 완료를 확인할 자료 |
|---|---|---|
| 전체·명목 AL 부분집합의 성능 순서가 다름 | 공통 평가와 참여자별 목표 평가를 분리 | 평가 이미지 목록·선정 근거, 동일 표본의 로컬·연합 점수 |
| 학습 순서 반복, 손실 변화, 과거 검증 로그 오류 | 저장 모델 진단과 수정 정책 비교를 구분 | 고정 입력의 진단 결과, 정책·학습량·마지막 모델 기록 |
| 사진 번호만 쓰는 분류 규칙이 모델보다 높음 | 같은 표본의 대조선과 출처별 결과 병기 | 표본 수·클래스 구성, 모델과 대조선의 결과 |
| 시드별 채점기 코드 버전이 다름 | v3 재채점·검산 완료. 후속 실행도 같은 출처 검사를 유지 | 코드·설정·입력 해시, v1·v2·v3 수치 대조와 검수 기록 |
| 두께·화소당 실치수와 규정 정답 검증 부족 | 이미지 근거 제시와 조건부 텍스트 과업 분리 | 원문 대조표, 독립 정답, 과업별 출력·채점 기준 |

C1·C2는 모두 명목 ST에 속한다. ST/AL로 나눠 평가한 것만으로 두 참여자의 개별 현장 성능을
확인했다고 할 수는 없다. 각 목표 평가 모집단을 정하지 못하면 그 항목의 참여자 편익은 미확인으로 남긴다.

### 6-1. 그대로 가져가는 것

- 데이터 분할, 매니페스트, 평가셋. 기존 벤치마크로 보존한다. 결과를 반복 확인했으므로 새 독립 평가 자료는 아니다.
- 학습·회계·채점 파이프라인. 기존 정책으로 세 시드를 끝까지 돌렸고 회계가 자동으로 검사된다. 재개 경로와 새 정책 패치는 별도 검수가 필요하다.
- 사진을 보지 않는 규칙과의 비교. 지표를 새로 들일 때마다 그 축에도 규칙 값을 함께 낸다.
- 보고 형식. 회복률은 시드별 값·평균·평가 묶음 신뢰구간·원시 격차를 함께 싣고 신뢰도 곡선과 단일 운용 임계값을 고르지 않는 mAP를 보고한다. mAP도 출력 하한과 추론 설정에는 의존한다. 기존 결과의 대표 수치 채택을 후속 실험의 자동 승인으로 쓰지는 않는다.

자료 수집·합성·설정 변경을 반복하는 실행은 탐색으로 기록한다. 최종 비교의 데이터와 설정을
정한 뒤에는 같은 버전으로 각 조건을 실행한다. 이후 자료나 정책을 바꾸면 새 실험으로 구분하고
이전 결과와 합치지 않는다.

### 6-2. 바뀐 것

- 주장 범위. 결함의 위치를 찾는 성능은 출처 대조와 학습 조건 검증을 전제로 비교한다. 결함 종류를 맞히는 점수만으로 이미지 학습의 효과를 주장하지 않는다.
- 통합형과 분리형의 비교는 두 완성 시스템의 비교로 한정한다. 두 구성은 시각 부분과 검색 유무가 달라
  구조 하나의 효과로 읽을 수 없다.
- 학습량이 같다는 말은 기준 학습 표본의 epoch 순회 예산이 같다는 뜻으로 좁힌다. mosaic 증강의 추가 표본 노출까지 같다는 뜻은 아니다.

### 6-3. 본실험 전에 넘어야 할 것

후속 비교를 시작하기 전에 아래 조건과 확인 방법을 정해야 한다.

1. 검출기 비교의 학습 조건을 맞춘다. 데이터 순서를 epoch마다 다시 섞는 통제 실험을 세 방식 모두에
   같은 정책으로 돌리고 기존 세 시드와 합치지 않고 따로 보고한다.
2. 해석을 견디는 평가를 정한다. 출처(크롭/타일)별 결과와 사진 번호 규칙 값을 같은 모집단에서 나란히
   싣고 출처 구성비를 바꿨을 때 결론이 얼마나 흔들리는지 미리 정한 시나리오로 본다.
3. 실제로 검증할 판정 과업을 고정한다. 현재 이미지 데이터에는 두께와 화소당 실치수가 없어 이미지와
   현재 라벨만으로 치수 기준 합부 판정을 확정할 수 없다. 두께 미상일 때는 후보 조항과 조건별 기준을
   제시하는 과업을 검토한다. 현재 검색기는 두께 없는 질의를 걸러내므로 과업 정의뿐 아니라 검색·평가
   경로도 바꿔야 한다. 사람이 만든 정답을 마련한 뒤에 정확도를 말한다.

통합형 두 조건을 진행하려면 규정 코퍼스의 범위와 원문 수치를 검수하고, 검증기 선택용 사람
라벨과 별도의 최종 평가 정답을 준비해야 한다. 계획한 100건은 합성문을 검사할 검증기 선택용이며
최종 정확도를 입증하는 표본 수가 아니다. 선택에 사용한 문장과 가까운 변형은 최종 평가에서 제외한다.
평가자에게 자동 판정과 표집층을 가리고 모집단 지표에는 표집 비율을 반영한다. GPU 시간도 별도 확인이 필요하다.

12.6~21.0 GPU-일은 한 시드의 12,461장에 분리형 판정부 5패스와 통합형 2패스를 적용하는 추론 추정치다.
학습 시간은 포함하지 않는다. 0.8B 모델 실측에 아직 측정하지 않은 4B 배율 ×3~5를 적용한 값이다.
`clause_only` 계획에서는 분리형 생성 추론을 생략하므로 통합형 2패스 추정치가 6.7~11.2 GPU-일이다.
실제 4B 속도와 학습 비용을 측정한 뒤 시드 수·층화 표본 규모·추가 GPU 확보 여부를 결정해야 한다.

## 7. 성공 가능성

계속할 가치는 있다. 다만 성공을 연합이 중앙집중을 넘는 것으로 정의하지 않는다. 어느 축에서 어느 회사가
얼마나 얻고 잃는지를 통제된 비교로 밝히려 한다. 회사별 편익은 공통 평가셋 점수와 구분해 해당
목표 모집단에서 평가해야 한다. 원하는 성능이 안 나와도 충분히 검증된 비교라면 연구 결과가 될 수 있다.
반대로 위 세 조건을 넘지 못한 채 좋은 점수만 더 쌓이면 판단은 달라지지 않는다.

기존 축소안은 분리형 세 조건과 조항 정확도 비교를 최소 보고 범위로 제시했다. 후속 검토안은 검출기 통제 비교를
우선하고 규정 과업과 통합형의 포함 여부를 별도로 확정하는 것이다. 코퍼스를 생성하거나 사람
라벨 100건을 모았다는 사실만으로 규정 과업을 완료 처리하지 않는다. 통합형 중앙집중만 마치면
그 범위만 비교하고, 통합형을 하나도 완료하지 못하면 구성 비교 질문은 미답으로 남긴다. 축소한
범위의 연구 질문과 보고 기준도 팀에서 확정해야 한다. 결과의 논문화나 게재를 보장하는 기준은 아니다.

현장에 넣을 판정 시스템의 유효성, 실측 치수 기반 합부 판정,
그리고 데이터 순서 문제가 결과에 준 영향의 방향은 지금 근거로 말할 수 없다.
